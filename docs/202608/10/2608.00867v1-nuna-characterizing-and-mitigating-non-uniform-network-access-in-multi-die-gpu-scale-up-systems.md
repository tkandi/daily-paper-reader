## 摘要
图形处理单元（GPU）架构的规模不断扩大，以满足日益增长的计算和内存需求。随着 GPU 尺寸增大，片内互连的传输延迟显著增加。以往研究主要优化片内的计算和内存局部性，但空间因素对 GPU 间通信的影响尚未得到充分研究。我们引入“非均匀网络访问”（NUNA）这一术语，描述多 GPU 系统中这一新兴的优化维度。我们特别关注机器学习推理中常见的对延迟敏感的集合通信。首先，我们强调了需要 NUNA 感知的路由（NAR），在大规模扩展网络拓扑中选择优化的、空间感知的 GPU 间路径。其次，我们引入 NUNA 感知的放置（NAP），将线程块和数据放置在 I/O 附近以优化 GPU 间流量。我们证明，仅 NAP 优化就能使集合通信速度比不考虑局部性的基线提高最多 1.5 倍。结合 NAP 与 NAR 后，集合通信速度比不考虑局部性的基线快最多 1.8 倍。这使机器学习推理中每个输出令牌的时间平均加快 7%（最高 28%）。

## Abstract
Graphics processing unit (GPU) architectures are growing in size to meet the increasing compute and memory requirements. As GPU sizes increase, intra-socket wire transfer delay increases significantly. While previous research has optimized for compute and memory locality within a socket, the spatial impact on inter-GPU communication has not been well-studied. We introduce the term non-uniform network access (NUNA) to describe this emerging optimization dimension in multi-GPU systems. We specifically focus on latency-sensitive collective communication, common in machine learning inference. First, we highlight the need for NUNA-aware routing (NAR), choosing optimized, spatially-aware inter-GPU paths in large scale-up network topologies. Second, we introduce NUNA-aware placement (NAP), placing threadblocks and data near I/O to optimize the inter-GPU traffic. We demonstrate that the NAP optimizations alone offer up to 1.5x collective speedups over a locality-unaware baseline. Combining NAP with NAR yields up to 1.8x faster collectives over the locality-unaware baseline. This leads to 7% mean (28% max) time per output token speedup in machine learning inference.

## 1. 论文的核心问题与整体含义

- **研究背景**：AI 模型规模急剧增长，现代 GPU 正通过先进封装技术（如 MCM、3D 芯片堆叠）将多个计算芯粒和 HBM 栈集成在一个封装内，形成物理尺寸越来越大的多芯粒 GPU。片内导线延迟随物理尺寸显著增加，从而导致缓存、内存访问呈现**非均匀性（NUMA / NUCA）**，但现有工作仅关注片内计算与内存的局部性。
- **核心问题**：对于大规模多 GPU 扩展系统（scale‑up），**片内延迟对 GPU 间通信的影响尚未被充分研究**，尤其是对延迟敏感的集合通信（如 All‑Gather、All‑Reduce、All‑to‑All）。计算单元（CU）→ 片内 I/O 端口 → 片外网络 → 远程 GPU 的端到端路径中，I/O 端口的选择以及 CU/数据的位置会带来显著的延迟差异。
- **整体含义**：作者将这种由于 I/O 端口位置差异引起的通信非均匀性定义为**非均匀网络访问（NUNA）**，作为继 NUMA 之后又一个重要的系统优化维度。该工作旨在**系统性地表征和缓解 NUNA 效应**，以提升多 GPU 系统中延迟敏感通信（特别是 ML 推理）的性能。

## 2. 方法论

论文提出两种互补的 NUNA 优化策略：NUNA 感知路由（NAR）和 NUNA 感知放置（NAP）。

### 2.1 NUNA 感知路由（NAR）

- **核心思想**：将延迟敏感的片间流量仅发送到距离当前 CU 更近的一组 I/O 端口（称为 NAR 域），而不是均匀散列到所有 I/O 端口，从而缩短片上传输路径，降低延迟与 NoC 拥塞。
- **技术细节**：
  - 将物理地址空间**静态分区**为多个段（segment），每段对应一种 NAR 粒度（granularity）。
  - 不同段使用不同的 I/O 端口子集（NAR 域）。例如粒度为 2 时，每个 NAR 域分配一半 I/O 端口。
  - 实现方式：修改 NoC flit 生成逻辑，根据地址高位选择对应段及 NAR 域；域内仍可负载均衡（不修改 NoC 本身）。
  - 页面分配时指定使用某种 NAR 粒度，虚拟‑物理地址映射自动触发对应路由。
  - 设计上与现有基线方案兼容，且仅对少量缓冲区（小型延迟敏感消息）采用 NAR，对带宽受限的大消息仍可使用原有全端口散列。

### 2.2 NUNA 感知放置（NAP）

- **核心思想**：不仅将线程块和内存页面放置在彼此附近（类似 NUMA），更要**将它们放置在物理上靠近 I/O 端口的 CU 和 HBM 栈上**，使本地访问和远程通信的片上路径都尽量短。
- **算法框架**（Algorithm 1）：
  - 输入：GPU 拓扑（CU、HBM、I/O 位置）、资源约束、NAR 最大粒度、通信调度计划 `W`（含线程块及其访问的 chunk 信息）。
  - **逻辑分配**（`logical_allocation`）：分析每个线程块访问的 chunk，将共享访问相同 chunk 的线程块归并到同一逻辑组，最终得到按规模降序排列的逻辑组列表。
  - **物理放置**（`physical_placement`）：
    - 对逻辑组以轮询方式分配 NAR 域（粗略负载均衡）。
    - 对于每个线程块和对应的 chunk，选择该 NAR 域中最靠近 I/O 端口且资源未超限的 CU 和 HBM 栈；优先使用 CU 最近的 HBM 栈。
    - 解耦资源跟踪，以支持 CU 的未完成请求容量和内存带宽‑延迟乘积的约束。
  - 输出：线程块‑CU 映射 `M_compute`，以及 chunk‑HBM 栈映射 `M_memory`。

- **实现假设**：利用现有 GPU 的 CU 亲和掩码（线程块调度）和驱动程序对 HBM 栈粒度的页面放置控制；NAR 地址段与 HBM 栈物理绑定，通过页面映射即可确定目标栈，无需改动地址翻译。

### 2.3 整体优化流程
- 编译器或性能剖析工具提取集合通信的每个线程块的数据访问模式。
- NAP 算法将线程块与 chunk 分组，并分配到特定 NAR 域。
- 调度器和内存驱动器通过掩码和物理地址放置执行映射。
- 集合通信执行时，利用 NAR 提供的低延迟片间路由和 NAP 优化的数据/计算位置，显著降低端到端延迟。

## 3. 实验设计

- **模拟基础设施**：基于 ASTRA‑sim 3.0 仿真器，支持 CU 级别线程块建模、256 B flit 粒度的 NoC 与 scale‑up 网络仿真，以及延迟模型（如内存访问固定 120 ns）。
- **目标系统**：
  - **片内**：4 计算芯粒 × 576 CU，16 个 HBM 栈，24×6 二维网格 NoC（X‑Y DOR 路由），合计 40 TB/s 内存带宽。
  - **片间**：单级 Clos 网络，144 个 I/O 端口（每芯粒 72），总带宽 7.2 TB/s；片间延迟 500 ns（参考真实设备比例调整）。
- **评测场景**：
  - **微基准测试**：All‑Gather、All‑Reduce、All‑to‑All 三种集合通信，数据量 100 kB ~ 1 GB，pod 规模 2 ~ 64 GPU。
  - **端到端 ML 推理**：12 种模型（Llama‑7B/70B/405B、GPT‑OSS 20B/120B、Mixtral 8×7B/8×22B、Qwen3 30B‑A3B/235B‑A22B、DeepSeek V3.2/V4 Flash/V4 Pro），采用最小 TTFT/TPOT 的 batch size 和并行化策略，使用 roofline 模型计算计算时间，通信时间来自仿真。
  - **真实硬件动机分析**：在 AMD Instinct™ MI210、MI355X、MI300X 上测量跨 GPU 原子加操作的远地存延迟，验证片内空间距离对远程通信延迟的影响。
- **对比方案**：
  - UA：完全无局部性感知的基线（线程块、内存 round‑robin，I/O 全散列）。
  - UA+NAR / NUMA+NAR / NAP+NAR：分别将 NAR 应用于不同放置策略。
  - NUMA：仅做到计算与内存靠近（类 NUMA），但路由与基线相同。
  - NAP：仅优化线程块与内存位置，路由仍为全散列。
  - NAP*：仅线程块放置靠近 I/O，内存维持 round‑robin。

## 6. 主要结论与发现

- **NUNA 效应确实存在且将随 GPU 规模增加而放大**：在 MI300X 上，远程通信延迟因 CU 和内存位置不同可出现约 5 倍的差异；预测下一代 GPU 的最差、平均情况延迟分别为最佳情况的 3 倍、2 倍。
- **NAR 单独可显著降低延迟**：UA+NAR 可使集合通信性能最高提升 35%。
- **NAP+NAR 联合优化效果最强**：相比 UA 基线，小型集合通信加速比可达 **1.8 倍**，且 NAP 与 NAR 需**结合使用**，单独 NAP 在高负载下可能因中片 NoC 拥塞而减速。
- **效果对消息大小敏感**：对于小消息（延迟敏感）收益最高，当消息增大导致片间网络带宽饱和时，NUNA 优化收益递减。
- **NAR 粒度需与线程块数量匹配**：充分的线程块数可支持更细粒度 NAR；线程块过少会导致 I/O 端口负载不均，反而降低性能。
- **端到端推理收益显著**：12 个模型的几何平均结果显示，prefill 的 TTFT 最高降低 11%，decode 的 TPOT 最高降低 **28%**，平均 TPOT 加速 7%；对应通信时间分别加速 1.32 倍（prefill）和 1.56 倍（decode）。
- **NUNA 优化具备一定的抗干扰能力**：在与 GEMM 内核共跑时，NAP+NAR 比 UA 能承受更高的片内 NoC 压力。

## 7. 优点

- **提出新概念**：首次将 I/O 端口位置引入多 GPU 通信性能分析，定义为 NUNA，开辟了新的系统优化维度。
- **方法简洁可行**：NAR 通过静态地址分区和轻量级硬件改动即可实现，NAP 利用已有的线程块调度与页面放置机制，工程实现难度可控。
- **算法系统性强**：联合考虑逻辑分组与资源约束的 NAP 算法，解耦访问模式与物理放置，兼具局部性与负载均衡。
- **实验充分**：从真实硬件测量到大规模仿真，覆盖微基准测试、消融实验和端到端多模型推理，证据链完整。
- **实用价值明确**：直接面向推理场景的延迟敏感集合通信，给出了具体的加速数字（最高 1.8× 通信加速、28% TPOT 加速），对工业界有一定指导意义。

## 8. 不足与局限

- **依赖静态的通信计划**：NAP 需要编译器或库提供精确的线程块访问模式，对于自动检测或动态变化的通信模式尚待扩展。
- **局限于单级 Clos 拓扑**：仅评估了该特定网络结构，对其他拓扑（如多层胖树、环面网络）的适用性未知。
- **未全面考虑资源竞争与动态适应性**：
  - NAR 的地址段大小需在启动时固定，缺乏动态调整能力。
  - 未深入讨论与更多不同内核（尤其是计算密集型负载）共享 I/O 和 NoC 时的资源调度策略。
- **页面粒度的限制**：存在分页冲突时采用先到先得的简单策略，可能导致部分 chunk 的放置并非最优。
- **仿真基于预估参数**：下一代 GPU 的参数基于行业趋势推导，并非真实硬件，性能加速绝对值可能有一定偏差。
- **主要针对小消息场景**：对带宽敏感的大消息（如大规模训练的梯度聚合）优化收益有限，方法适用范围相对聚焦。
- **未涉及能耗、冷却等现实约束**：仅关注延迟与加速比，未讨论优化对功耗或热分布的影响。
