## 摘要
现代GPU越来越多地将Tensor Core集成到执行流水线中。尽管在操作数供给从Ampere中基于寄存器的方式演进为Hopper和Blackwell中无冗余、基于内存的方式的推动下，聚合张量吞吐量持续增长，但针对现代AI工作负载高效编排完整张量计算流水线仍具挑战。我们指出根本瓶颈在于固定并行性和粗粒度调度，这两者都被现代AI工作负载所暴露，这些负载将多样化的非GEMM操作与GEMM交错执行。为高效编排张量计算，我们提出FIBER，一种扩展GPU SIMT（单指令多线程）模型的新架构。其基本执行实例——fiber——与私有寄存器所有权解耦，仅携带最小控制状态，同时通过共享视图访问SM的寄存器。这实现了动态并行扩展、细粒度寄存器级数据流调度，并为矩阵操作数供给提供了无冗余替代方案。我们扩展了ISA、微体系结构和编译器，以实现共享寄存器寻址、无冲突操作数投递以及基于fiber的程序映射。在典型的混合精度LLM服务场景下，FIBER在Ampere上实现了2.25倍端到端加速（原始FP16计算为1.15倍），在Hopper和Blackwell上分别达到1.8倍和2.09倍，内核级增益最高达2.49倍。

## Abstract
Modern GPUs increasingly integrate Tensor Cores into the execution pipeline. Although aggregate tensor throughput continues to grow, aided by an operand supply that has evolved from register-based in Ampere to redundancy-free, memory-based in Hopper and Blackwell, efficiently orchestrating the complete tensor compute pipeline for the modern AI workloads remains challenging. We identify the fundamental bottlenecks as fixed parallelism and coarse-grained scheduling, both of which are exposed by modern AI workloads that interleave diverse non-GEMM operations with GEMM. To orchestrate tensor computation efficiently, we propose FIBER, a new architecture that extends the GPU SIMT (single instruction, multiple thread) model. Its basic execution instance, the \emph{fiber}, is decoupled from private register ownership, carrying only minimal control state while accessing an SM's registers through a shared view. This enables dynamic parallelism scaling, fine-grained register-level dataflow scheduling, and offers a redundancy-free alternative for matrix operand supply. We extend the ISA, microarchitecture, and compiler to realize shared-register addressing, conflict-free operand delivery, and fiber-based program mapping. Under a typical mixed-precision LLM serving scenario, FIBER achieves a 2.25x end-to-end speedup on Ampere (1.15x for the original FP16 computation), with 1.8x and 2.09x on Hopper and Blackwell respectively, and kernel-level gains up to 2.49x.

## 1. 论文的核心问题与整体含义

- **研究背景**：现代 GPU 广泛集成 Tensor Core（TC）以加速矩阵乘法（GEMM），张量吞吐量持续增长。操作数供给方式从 Ampere 的私有寄存器冗余加载，演进到 Hopper/Blackwell 的共享/张量内存无冗余供给，解决了纯 GEMM 的 TC 利用瓶颈。
- **核心问题**：现代 AI 工作负载（如 LLM 中的注意力、FFN、混合精度内核）将 GEMM 与大量非 GEMM 操作（Softmax、RoPE、SiLU 等）交织执行。现有 SIMT 执行模型存在两个根本瓶颈：
  - **固定并行性（Static Parallelism）**：线程数量和寄存器预算在 kernel 启动时固定，无法适应不同计算阶段（内存密集、张量密集、向量密集）对并行度和寄存器占用的不同需求。
  - **粗粒度调度（Coarse-grained Scheduling）**：Hopper 之后以 warp-group 为粒度进行阶段式批量同步，缺少细粒度依赖跟踪，导致同步开销大、数据转发与复用受限。
- **整体含义**：为高效编排“GEMM + 非 GEMM”混合的张量计算流水线，需要重新思考执行实例与寄存器资源的绑定关系。FIBER 提出线程-寄存器解耦的执行模型，以更轻量的 fiber 取代传统线程，实现动态并行扩展、细粒度数据流调度和无冗余操作数供给。

## 2. 论文提出的方法论

FIBER 的核心思想是**将执行实例与其私有寄存器所有权解耦**，引入一种称为 **fiber** 的轻量并行执行单元。具体设计如下：

### 2.1 执行模型
- **fiber**：只携带最小控制状态（程序计数器 PC、标识符、控制标志），不拥有私有寄存器。同一 SM 上所有 fiber 通过共享视图访问统一寄存器文件。
- **weft**：以 lockstep 执行同一指令的 32 个 fiber 组成一个 weft，类比传统 warp，但具有共享寄存器语义。
- **关键效果**：fiber 数量不再受静态寄存器分配约束，调度器可在运行时动态缩放活动 fiber 数量；共享寄存器支持跨 fiber 的寄存器级数据流。

### 2.2 ISA 扩展
- **共享寄存器寻址**：利用 SASS 编码中 13 位未使用位扩展源操作数地址。每个源操作数增加 2 位高地址用于选择子分区（SP），1 位使能信号，4 位拼接原有地址，可寻址 2048 个 32-lane 向量寄存器。保持 32-lane 对齐，避免完全远程写，仅支持远程读 + 本地写。
- **动态并行指令 `SET_FIBER_NUM`**：软件指定期望 fiber 数，所有 fiber 同步后重新配置活动 weft 数量，实现运行时并行度缩放。
- **细粒度依赖指令 `DEPBAR`**：扩展为寄存器粒度跨 fiber 依赖跟踪，使用 **empty**（数据未就绪）和 **full**（数据正在被使用）两种状态。

### 2.3 微架构增强
- **选择器 + 交叉开关**：支持跨子分区寄存器读取，按 32-lane 对齐路由操作数。
- **读端口仲裁器（Read Port Arbiter）**：解决共享寄存器访问带来的跨 SP 读端口冲突，通过旋转优先级、占用位图和相同地址检测，保持固定延迟语义，仅引入少量停顿。
- **寄存器忙碌位图（Register Busy Bitmap）**：SM 内维护 2048×2 位寄存器状态（empty/full 组），实现跨 weft 的细粒度依赖跟踪。默认硬件自动更新：写目的寄存器在 issue 时设为 empty（未就绪），写回时清除；读源寄存器在 RF 读时设为 full（使用中），消费后清除。`DEPBAR` 可手动覆盖。

### 2.4 软件栈
- **CUDA-native 模式**：保持 SIMT 兼容，通过 `set_fiber_num` 生成与线程数相同的 fiber。
- **FIBER-native 模式**：使用 `__pool__` 声明共享寄存器张量，`set_busy_bit()` 操作寄存器忙碌位图，支持动态并行和寄存器级数据流。
- **编译器支持**：维护 2048 向量寄存器空闲列表，做活跃性分析；对 MMA 操作数放置进行优化以减少 bank 冲突；将远程写改写为本地写 + 远程读。

### 2.5 数据流示例
以 FlashAttention 为例，不同 weft 分别负责加载 K/V、计算 QK^T、Softmax、计算 PV 和 rescale。各阶段间通过共享寄存器直接传递中间数据（如注意力分数 s、概率 p），并通过 `set_busy_bit` 设置 empty/full 状态来协调生产者和消费者，避免粗粒度同步。

## 3. 实验设计

- **仿真平台**：使用 GTSim（tile-graph based cycle-level simulator）建模 Ampere、Hopper、Blackwell 三代 GPU 基线及 FIBER 架构。GTSim 对现代 GPU 工作负载的平均绝对百分比误差（MAPE）为 1.2–11.3%。
- **工作负载与场景**：
  - **基础 LLM 推理（prefill）**：QKV 投影、多头注意力（MHA）、输出投影、FFN（SiLU 激活、乘法门控）。配置来自 Llama 模型族（Lcontext=4096, dhead=128, dhidden=4096, dffn=11008）。
  - **混合精度（W4A16）GEMM**：AWQ（计算密集型反量化）、AQLM#（内存密集型码本反量化）。
  - **高效注意力变体**：MQA、GQA（每组 8 头）。
  - **解码与训练**：FlashDecoding（解码）、FlashAttention-2/3/4 backward（训练）。
- **对比方法**：
  - 基线：Ampere 上 FA2、Hopper 上 FA3、Blackwell 上 FA4；Hopper/Blackwell 启用 warp specialization、warp-group TC、异步流水线等最新特性。
  - 消融：逐步添加 +DP（动态并行）、+FS（细粒度调度）、+RS（寄存器共享）来量化各特性贡献。
  - 硬件开销对比：基于 TSMC 16nm 标准单元库综合，2.5GHz，并与 A100（7nm）比较面积、功耗、延迟。

## 6. 论文的主要结论与发现

- **FIBER 有效解决了固定并行性和粗粒度调度问题**：通过 fiber 解耦寄存器所有权，支持运行时动态调整并行度，并通过寄存器级依赖跟踪实现细粒度数据流调度。
- **显著加速混合精度 LLM 服务**：在 W4A16 混合精度场景下，FIBER 相对 Ampere 达到 **2.25x** 端到端加速（FP16 为 1.15x），相对 Hopper 和 Blackwell 分别为 **1.8x** 和 **2.09x**，内核级最高 **2.49x**。
- **注意力与训练负载收益明显**：前向注意力加速 1.4–1.57x，反向注意力 1.5–1.59x，混合精度 GEMM 最高 2.33x。
- **硬件开销极小**：新增单元总面积占 A100 的 0.069%，功耗占 0.39%，延迟最长 0.34ns（满足 2.5GHz 频率目标）。
- **消融结果**：动态并行（+DP）对几乎所有混合负载有效（最高 80% 提升）；细粒度调度（+FS）对同步密集负载（如投影）贡献最大；寄存器共享（+RS）进一步加速，尤其对操作交织严重的负载（如 MQA 提升 80%）。
- **无冗余操作数供给**：共享寄存器提供与 Hopper/Blackwell 内存供给同等的冗余消除，同时保持寄存器级低功耗数据复用。

## 7. 优点

- **架构创新**：提出 fiber 执行模型，将并行执行实例与寄存器所有权解耦，从根源上解决动态并行和细粒度数据流问题，同时保持 SIMT 兼容。
- **硬件改动轻量**：利用 SASS 未使用编码位实现共享寄存器寻址，新增单元面积/功耗开销均小于 1%，易于在现有 GPU 基础上实现。
- **细粒度依赖机制精巧**：empty/full 双状态位图 + 硬件自动维护 + `DEPBAR` 手动覆盖，兼顾安全性和灵活性。
- **实验设计全面**：覆盖三代 GPU、多种 LLM 工作负载（前向/反向/解码/混合精度/注意力变体），并通过消融实验清晰展示各特性贡献。
- **软件生态考虑**：提供 CUDA-native 和 FIBER-native 两种模式，渐进式迁移，降低编程负担。

## 8. 不足与局限

- **依赖模拟器评估**：所有性能结果来自 GTSim 模拟器，未在真实硬件（如 FPGA 原型或实际 GPU）上验证，存在模型误差和理想化假设的风险。
- **应用范围偏窄**：工作负载集中在 LLM 相关张量计算，缺少更通用的 HPC 或非 AI 负载验证，通用性有待进一步证明。
- **部分场景加速有限**：FlashDecoding 仅 1.12x，纯 GEMM 投影加速约 1.1x，说明 FIBER 对强计算受限或强内存受限负载收益不明显。
- **软件编译复杂度**：虽然提供了编译器支持，但 `__pool__` 共享寄存器管理、远程写改写、bank 冲突优化等可能增加编译器和程序员的复杂度，未做充分的编程效率评估。
- **共享寄存器冲突处理**：读端口仲裁器仅给出少量停顿的粗略分析，未讨论极端冲突模式下的性能退化；寄存器忙碌位图一致性广播的功耗/布线影响也未深入量化。
- **未来硬件扩展性**：论文提到 Blackwell tensor memory 可视为寄存器文件扩展，但 FIBER 如何在更大规模 TC 上继续扩展仍缺乏深入论证。
