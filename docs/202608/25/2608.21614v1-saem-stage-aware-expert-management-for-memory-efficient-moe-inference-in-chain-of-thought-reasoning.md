## 摘要
思维链（CoT）提示通过将复杂问题分解为中间步骤来提升大语言模型推理能力，但其顺序特性增加了解码延迟和内存占用。混合专家（MoE）模型通过稀疏专家激活来扩展容量，然而其全部专家权重往往超出 GPU 内存，并需要昂贵的 GPU-CPU 数据传输。现有运行时对所有 token 统一处理，忽略了 CoT 轨迹的一个关键结构特性：连续推理阶段展现出连贯且可预测的专家激活模式。忽视这种阶段级规律会导致缓存低效和不必要的数据移动。我们提出 SAEM，一种阶段感知的 MoE 推理运行时，它检测推理阶段边界并利用阶段级激活一致性来指导专家放置。SAEM 结合了阶段感知缓存、专家对齐的 token 重打包以及原位 CPU 执行，以减少数据传输和内核碎片化。在数学和科学推理工作负载上，在 GPU 内存受限条件下，SAEM 相较于最强的最新缓存与卸载基线实现了平均 1.33 倍的吞吐量提升；当校准数据与工作负载匹配时，提升可达 1.54 倍，证明了面向 CoT 推理的阶段感知、局部性驱动的 MoE 推理的有效性。

## Abstract
Chain-of-thought (CoT) prompting improves LLM reasoning by decomposing complex problems into intermediate steps, but its sequential nature increases decoding latency and memory usage. Mixture-of-Experts (MoE) models scale capacity through sparse expert activation, yet their full expert weights often exceed GPU memory and require costly GPU-CPU transfers. Existing runtimes treat all tokens uniformly, overlooking a key structural property of CoT traces: consecutive reasoning stages exhibit coherent and predictable expert activation patterns. Ignoring this stage-level regularity leads to inefficient caching and unnecessary data movement. We propose SAEM, a stage-aware MoE inference runtime that detects reasoning stage boundaries and exploits stage-level activation coherence to guide expert placement. SAEM combines stage-aware caching, expert-aligned token repacking, and in-situ CPU execution to reduce data transfer and kernel fragmentation. On mathematical and scientific reasoning workloads, SAEM achieves an average 1.33x throughput improvement over the strongest state-of-the-art caching and offloading baselines under constrained GPU memory, rising to 1.54x when calibration data matches the workload, demonstrating the effectiveness of stage-aware, locality-driven MoE inference for CoT reasoning.

  - 能否利用 CoT 推理中“阶段级”的专家激活规律，在 GPU 内存受限的条件下，减少不必要的数据搬运、降低缓存抖动和内核碎片，从而提升 MoE 推理吞吐？

## 2. 论文提出的方法论

### 2.1 核心思想

SAEM 观察到：CoT 轨迹由多个语义连贯的推理阶段组成，例如初始推导、探索不同解法、自我纠正、验证、最终结论等。不同阶段会稳定激活不同的专家子集，而在阶段内部，专家激活模式高度稳定。

基于此，SAEM 在**推理阶段边界**而非每个 token 上更新专家缓存策略，从而大幅减少 GPU–CPU 数据移动，同时保持较高的缓存命中率。

### 2.2 关键技术细节

#### （1）推理阶段边界检测

- **离线阶段：模型特定转换词集合构建**
  - 从通用 CoT 文本中收集候选转换词/短语（如 “Alternatively,” “Instead,” “On second thought,”）。
  - 使用校准数据集和模型 checkpoint，根据这些候选词对**相邻阶段专家激活一致性的贡献**（由时间一致性指标 \(TC_{seq}\) 衡量）进行裁剪，得到紧凑的、模型特定的转换集合 \(T_{model}\)。
  - 好处：避免运行时大规模语义解析或额外神经分类器，只保留高价值、低噪声的转换 cue。

- **在线阶段：滑动窗口 + 有限状态机匹配**
  - 对每个序列维护最近生成 token 的滑动窗口。
  - 使用有限状态机匹配窗口后缀是否命中 \(T_{model}\) 中的 cue。
  - 一旦命中，即触发阶段边界事件，结束当前阶段的激活统计收集，并开始为新阶段重新收集统计。

- **阶段边界处的激活模式聚合**
  - 当阶段边界被触发时，SAEM 汇总当前 stage 中所有 batch query 的逐层、逐专家激活频率。
  - 这些聚合统计用于指导下一阶段的专家放置，因为相邻阶段之间存在很强的专家激活一致性。

#### （2）阶段感知专家缓存管理

- **初始化**
  - 非 MoE 层（注意力、层归一化等）常驻 GPU。
  - MoE 专家权重按照用户设定的专家缓存比例（Expert Cache Ratio, ECR）在 GPU 上分配固定大小的缓存区域。
  - 可选用校准数据集得到的全局热专家集合进行预热。
  - 每层缓存槽位固定，避免动态分配带来的内存碎片。

- **动态专家放置**
  - 在每个阶段边界，对每层缓存内的专家按刚完成阶段的激活频率排序。
  - 将激活频率低的专家逐出 GPU 缓存，换成当前阶段高频但暂在 CPU 的专家。
  - 更新后清空当前激活日志，开始统计下一阶段。
  - 通过这种阶段级、逐层局部更新，避免 token 级专家迁移带来的调度开销，同时利用相邻阶段 >90% 的激活子集重叠来提高缓存命中率。

- **延迟隐藏预取**
  - 专家权重传输使用异步 DMA，与计算重叠。
  - 阶段边界被检测到后，预取调度器立即发出预取请求，使专家权重传输与当前阶段最后的解码步骤、下一阶段初始计算并行执行。
  - 使用 GPU event 机制协调异步传输完成信号，保证所需权重在需要时恰好可用。

#### （3）原位 CPU 专家执行

- **避免不必要的数据移动**
  - 当某个被路由到的专家不在 GPU 缓存、但在 CPU 内存中时，SAEM 会比较两条路径：将专家传输到 GPU 执行 vs. 直接在 CPU 上执行。
  - 对于仅分配少量 token 的专家，CPU 执行通常更快，因为 PCIe 传输延迟占主导。
  - 这样做还避免了将低频专家加载到 GPU 导致缓存污染。

- **混合 CPU–GPU 执行流水线**
  - 在 top-k 路由后，SAEM 将 token batch 按专家是否 GPU 常驻分为 GPU-bound 和 CPU-bound 两组。
