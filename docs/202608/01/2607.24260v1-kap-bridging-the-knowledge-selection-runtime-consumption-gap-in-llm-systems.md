## 摘要
现代大语言模型系统越来越依赖知识选择流程，这些流程会生成高价值的结构化先验，例如排序证据、图拓扑、多模态对齐以及置信度信号。然而，大语言模型的推理服务对此丰富的结构基本视而不见：一旦这些信号被序列化为提示，后端只能观察到扁平的token序列，在解码过程中被迫对整个键值状态进行密集且均匀的消耗。我们将这种架构上的错配称为知识选择-运行时消耗鸿沟：更丰富的上下文扩大了完整提示的键值足迹和解码时的内存流量，即使推理仅依赖于上下文的一小部分，也会增加延迟并降低吞吐量。为弥合此鸿沟，我们提出知识访问规划，这是一种范式转变的执行抽象，它将结构化的知识先验从被动的提示构建提示提升为一流的物理执行构件。KAP建立了一种通用的中间表示——运行时访问计划——它将结构化的知识信号编译为控制物理键值访问的规则，而不改变逻辑提示语义、模型权重或训练过程。通过此中间表示，KAP将大语言模型的服务从基于token感知的上下文消耗转变为计划驱动、知识感知的运行时消耗。我们以GraphSpec实例化KAP，这是一个将结构化知识选择与大语言模型服务后端连接起来的编译器-执行器实现。我们推导出计划引导执行的正向加速区域的相界模型。在4K-128K长上下文问答工作负载中，GraphSpec在保持答案质量与全上下文解码相当的同时，将物理键值消耗与提示长度解耦，在128K时提案时的键值访问降低至源键值状态的5.5%，从根本上改变了长上下文生成的扩展轨迹。

## Abstract
Modern LLM systems increasingly rely on knowledge-selection processes that produce high-value structured priors, such as ranked evidence, graph topology, multimodal alignment, and confidence signals. Yet LLM serving remains fundamentally oblivious to this rich structure: once such signals are serialized into a prompt, the backend observes only a flat token sequence, forcing dense and uniform consumption of the full key-value (KV) state during decoding. We term this architectural mismatch the Knowledge Selection-Runtime Consumption (KSRC) gap: richer contexts enlarge the full-prompt KV footprint and decode-time memory traffic, increasing latency and degrading throughput even when reasoning depends on only a small fraction of the context. To bridge the gap, we propose Knowledge Access Planning (KAP), a paradigm-shifting execution abstraction that elevates structured knowledge priors from passive prompt-construction hints into first-class physical execution artifacts. KAP establishes a universal intermediate representation (IR)-the runtime access plan-which compiles structured knowledge signals to govern physical KV access without altering logical prompt semantics, model weights, or training procedures. Through this IR, KAP shifts LLM serving from token-aware context consumption to plan-driven, knowledge-aware runtime consumption. We instantiate KAP with GraphSpec, a compiler-executor realization connecting structured knowledge selection to an LLM serving backend. We derive a phase-boundary model for the positive-speedup regime of plan-guided execution. Across 4K-128K long-context QA workloads, GraphSpec maintains answer quality comparable to full-context decoding while decoupling physical KV consumption from prompt length, reducing proposal-time KV access to 5.5% of source KV state at 128K, and fundamentally shifting the scaling trajectory of long-context generation.

### 1. 论文的核心问题与整体含义

现代大语言模型（LLM）系统在服务时，其上游的知识选择（如检索增强生成RAG中的排序、图遍历等）会产生高价值的结构化先验信息（例如：哪段证据更重要、图节点间的关联、置信度评分）。然而，当这些信息被序列化为一个扁平的提示词（Prompt）送入LLM后端时，其丰富的语义结构完全丢失了。后端只能看到一个无差别的token序列，并在解码时被迫无差别、均匀地访问和消耗整个上下文的键-值（KV）缓存状态。

这种架构上不匹配被本文定义为**知识选择-运行时消耗（KSRC）鸿沟**。其核心矛盾在于：知识选择阶段已经明确了“什么内容是重要的”，但运行时阶段却假设“所有内容都一样重要，都需要被消费”。这导致即便推理仅依赖于上下文的一小部分，物理计算和内存带宽开销仍随序列化上下文长度线性增长，造成了严重的浪费。

因此，本文提出了一种范式转变：将结构化的知识先验从被动的“提示词构建提示”提升为主动的“物理执行构件”，以实现**计划驱动、知识感知的运行时消耗**，从而弥合KSRC鸿沟，在大幅降低物理计算开销的同时保持生成质量。

### 2. 论文提出的方法论

论文的核心贡献是提出了**知识访问规划（KAP）**范式，并通过一个名为 **GraphSpec** 的系统进行实例化验证。KAP的核心思想并非直接压缩或修改提示词，而是建立一个“执行合同”来控制物理层面如何访问KV缓存。

**核心思想与关键技术细节：**

*   **通用中间表示（IR）：运行时访问计划**
    *   KAP的核心是一个被称为“运行时访问计划”的通用IR。这个IR是知识选择前端与LLM服务后端之间的桥梁。
    *   计划形式化定义为 `A = ( U, M, pos, ρ_access, ρ_verify )`，其中：
        *   `U`：**选定的知识单元**。即根据先验，哪些内容是预算内真正需要被访问的。
        *   `M`：**运行时对象映射**。将选定的知识单元（如文本片段）映射到底层的物理KV缓存页面和块表。
        *   `pos`：**逻辑位置**。严格保留选定内容在原始提示词中的位置，确保模型感知到的位置编码不受物理访问变化的影响。
        *   `ρ_access`：**运行时访问策略**。定义了在执行期间如何暴露选定的KV对象（本文的GraphSpec实例采用“选定KV提案”策略）。
        *   `ρ_verify`：**验证策略**。规定了如何对基于稀疏访问生成的输出进行验证或回退（本文的GraphSpec实例采用“全上下文验证”策略）。

*   **编译器-执行器架构**
    *   **KAP编译器**：接收来自知识选择前端（如Graph-RAG）的结构化先验和完整的逻辑提示词。其职责是执行算法流程，将这些先验编译成上述的运行时访问计划。具体步骤包括：证据文本与token跨度对齐、预算感知的语义选择、选定的token跨度解析到物理KV页面、构建块表和槽位映射、并最终物化出一个紧凑的“选定KV视图”。
    *   **KAP执行器**：在LLM服务后端解释并执行运行时访问计划。它按照计划中的策略，仅从物理内存中读取“选定KV视图”包含的KV状态用于提案生成，然后用完整的KV缓存对提案的token进行验证，只有验证通过的token才会被最终提交。

*   **GraphSpec实例的提案-验证机制**
    *   **选定KV提案**：作为执行器的一种具体实现策略，GraphSpec使用完整的基座模型，但在生成提案token时，其注意（Attention）机制仅暴露由计划编译出的、逻辑位置保留的紧凑KV视图。这大幅减少了每次解码步骤所需读取的KV缓存量。
    *   **全上下文验证**：提案生成的token不是最终结果。执行器会使用同一基座模型，但这次暴露完整的KV缓存，对候选token序列进行验证。本文采用了一种宽松的验证策略，即如果提案token在全上下文模型的Top-3候选词中，则被接受。

*   **相界分析模型**
    *   论文推导出一个成本模型，定义了计划引导执行能带来正向加速的条件。当计划导致的KV保留率（`s`）和提案接受率（`h`）满足特定不等式（`(h - s)KV > (1 - h)W_main`，其中 `W_main` 为模型权重读取成本）时，系统位于正向加速区。
    *   这个模型将前端知识选择的“质量”（影响`s`和`h`）与后端的“效率”联系了起来，为协同优化提供了理论指导。

### 6. 论文的主要结论与发现

1.  **成功解耦物理KV消耗**：GraphSpec实现了提案时的物理KV消耗与序列化上下文长度的解耦。在128K上下文中，它仅需访问源KV状态的5.5%，从根本上改变了长上下文服务的扩展轨迹。
2.  **质量无损的效率提升**：在4K-128K所有长度下，GraphSpec在答案通达率和平均相似度上都保持了与全上下文基线相当的水平，同时解码吞吐量提升了8%-19%。
3.  **运行时计划是关键桥梁**：消融实验证实，质量提升和效率提升的根源在于**运行时访问计划**，而非单纯的知识选择或提示词缩短。去掉计划，即使使用相同的证据也无法恢复质量。
4.  **理论与实证的吻合**：观察到的性能趋势与相界分析模型的理论预测一致：随着上下文增长，KV保留率`s`下降，接受率`h`维持高位，使得接受-保留边际（`h-s`）扩大，从而观测到更高的加速比。

### 7. 优点

*   **问题定义深刻**：精准识别并形式化了“KSRC鸿沟”这一在现有LLM系统中普遍存在但被忽视的架构错配问题。
*   **方法论简洁而强大**：KAP范式将问题从一个启发式的提示词工程问题提升为一个系统化的执行规划问题，其核心的“运行时访问计划”IR设计通用性强，分离了逻辑语义和物理执行，极具启发性。
*   **实例化与验证闭环**：GraphSpec作为KAP的一个干净、具体的实例，完整展示了从编译到执行的流程。**相界分析模型**为知识选择和运行时消耗的协同优化提供了量化的理论框架，使抽象概念落地为可度量的系统目标。
*   **实验论证力强**：通过精心设计的嵌套式上下文构建和“物理拼接”消融实验，干净地排除了混淆变量，有力地证明了KAP范式和GraphSpec实例化的独特价值。

### 8. 不足与局限

*   **生态局限性**：目前KAP仅通过GraphSpec这一个实例在单一模型（Qwen3-VL）、单一后端（vLLM）和单一任务类型（基于Graph-RAG的QA）上得到验证。其对其他类型知识先验、多模态输入、不同服务后端或Agent系统的普适性还有待更多实例化证明。
*   **仿真与部署差距**：相界模型是一个理想化的成本模型，未包含复杂的运行时开销（如调度、元数据构建等）。这些开销现实中可能侵蚀理论加速比。
*   **对前端的依赖性**：KAP的性能上限严重依赖于上游知识选择前端的质量。如果前端提供的先验信息信噪比低，编译出的计划也可能无效。
*   **提案-验证的效率瓶颈**：当前的提案-验证机制引入了一次额外的全模型验证前向传播，虽然保证了质量，但也构成了性能开销。在KV缓存相对小的时候（即短上下文），加速效果不明显。
*   **实现复杂性**：在vLLM这样的复杂系统中实现稳定的“选定KV访问路径”需要谨慎处理元数据、形状和内存分配，这可能会限制其在不同系统上的快速移植。
