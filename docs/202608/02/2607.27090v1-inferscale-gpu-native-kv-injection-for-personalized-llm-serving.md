## 摘要
大型语言模型越来越多地部署时需要持久的个性化上下文，例如累积的记忆档案或长对话历史，这些上下文在用户的多次请求间共享。现有的生产级记忆系统（如Mem0、MemGPT和Zep）会检索这些记忆的相关子集并将其注入提示中，迫使服务引擎重复预填充相同的内容。随着检索预算的增加，尽管底层的记忆在请求间被重用，但首token时间（TTFT）仍会上升。我们提出InferScale，一种GPU原生的LLM记忆系统，用可重用的KV状态替代重复的提示预填充。InferScale预先计算每个记忆事实的KV表示，将其与语义嵌入一同存储在GPU上，在服务时检索相关事实，并将其KV直接注入到vLLM的分页缓存中。为了在旋转位置嵌入下支持动态组装的记忆，我们引入了分块RoPE，它在旋转之前存储键，并在注入时应用其在服务时刻的位置。然而，独立编码记忆事实会丢失联合预填充时可用的跨事实上下文。我们通过上下文窗口编码来缓解这一问题，该方法将每个记忆事实与一小段之前的对话上下文一起编码，同时只缓存目标事实的KV。InferScale通过vLLM的KV连接器接口实现，无需引擎修改或模型微调。在LoCoMo上使用三个开源权重模型，随着检索预算的增加，InferScale保持TTFT几乎不变：在k=50时，TTFT减少了72-79%（3.6-4.8倍），在无需服务时重新计算的情况下，准确率达到60.3%，而Mem0为63.3%，并且在并发负载下的吞吐量提高了3.7-4.5倍。可重用的KV状态因此使得记忆条件下的服务延迟与检索上下文大小解耦，同时保持了应用质量。

## Abstract
Large language models are increasingly deployed with persistent personalized context, such as accumulated memory profiles or long conversation histories, that is shared across a user's many requests. Production memory systems (e.g., Mem0, MemGPT, and Zep) retrieve a relevant subset of this memory and inject it into the prompt, forcing the serving engine to repeatedly prefill the same content. As the retrieval budget grows, time-to-first-token (TTFT) increases even though the underlying memory is reused across requests.   We present InferScale, a GPU-native LLM memory system that replaces repeated prompt prefilling with reusable KV state. InferScale precomputes each memory fact's KV representation, stores it alongside a semantic embedding on the GPU, retrieves relevant facts at serving time, and injects their KV directly into vLLM's paged cache. To support dynamically assembled memories under rotary position embeddings, we introduce Chunked RoPE, which stores keys before rotation and applies their serving-time positions during injection. However, encoding memory facts independently omits the cross-fact context available during joint prefilling. We mitigate this with Context-Window Encoding, which encodes each memory fact together with a small window of preceding conversation context while caching only the target fact's KV.   InferScale is implemented through vLLM's KV-connector interface, requiring neither engine modifications nor model fine-tuning. Across three open-weight models on LoCoMo, InferScale keeps TTFT nearly constant as the retrieval budget increases: at k=50 it reduces TTFT by 72-79% (3.6-4.8x), achieves 60.3% accuracy versus 63.3% for Mem0 without serving-time recomputation, and delivers 3.7-4.5x the throughput under concurrent load. Reusable KV state thus decouples memory-conditioned serving latency from retrieved-context size while preserving application quality.

### 2. 方法论
- **核心思想**：将检索到的记忆事实从**提示注入**改为**KV注入**。即在离线阶段预先计算每个记忆事实的KV对（pre-RoPE键和原始值），在服务时检索相应事实，将其KV直接注入vLLM的分页KV缓存，模型只需预填充查询token。
- **关键技术细节**：
  - **分块RoPE**：为了支持同一事实在不同请求中被放置在不同位置，在编码时提前截获旋转编码前的键（\(k_{pre}=W_K h\)），注入时根据服务时刻的虚拟位置动态施加旋转，确保注意力分数与标准提示注入完全等价（定理6）。
  - **上下文窗口编码**：为了弥补独立编码事实造成的跨事实交互缺失，编码每个事实时引入其所属对话轮次的前\(w\)轮上下文进行前向传播，但最终仅保留目标事实的KV对（图3），使存储的KV包含消歧所需的上下文信息，同时仍可独立重用。
  - **系统实现**：作为vLLM的KV-Connector插件实现，无需修改引擎或微调模型。内存存储分为**GPU驻留的向量索引**（Jasper，用于语义检索）和**pre-RoPE KV存储**，两者通过shared `fact_id`关联。
- **理论支撑**：定理3证明，对于任意因果解码器Transformer，在给定位置注入预计算的KV对，查询位置的隐藏状态与提示注入完全一致。定理6证明分块RoPE可保证任意位置注入的注意力得分精确等价。上下文窗口编码理论保证存储的KV准确包含了窗口内上下文信息。

### 4. 资源与算力
- **硬件**：单张NVIDIA RTX PRO 6000 Blackwell Server Edition GPU，96GB GDDR7内存，PCIe 5.0 x16。

### 6. 主要结论与发现
- **延迟与预算解耦**：InferScale的TTFT几乎不随\(k\)增长。在\(k=50\)时，TTFT仅增加4%（Llama-3.1-8B），而Mem0增加106%，InferScale降低TTFT达72-79%（3.6-4.8倍）。
- **准确率恢复**：独立编码事实（\(w=0\)）在多事实情况下准确率下降，但上下文窗口编码（\(w \ge 20\)）可恢复至接近提示注入水平（整体准确率60.3% vs Mem0 63.3%），且在较小\(k\)下甚至超过Mem0。准确率差距主要集中在需要跨事实推理的**多跳问题**上。
- **吞吐量提升**：并发负载下吞吐量呈近线性扩展，100用户时达到Mem0的3.7-4.5倍，得益于预填充量大幅减少。
- **CPU卸载可行**：将KV存储卸载至主机DRAM并通过PCIe流式传输，仅增加极小的TTFT开销（~3ms），端到端延迟仍远低于Mem0，且吞吐量保持不变。

### 7. 优点
- **理论与实现并重**：提供了严格的等价性证明，并通过vLLM插件实现，无需侵入引擎或微调，实用性强。
- **巧妙解耦位置与内容**：分块RoPE允许记忆任意位置重放，上下文窗口编码兼顾了语义保真度和重用性，两个设计正交且互补。
- **全链路优化**：将检索索引和KV存储均置于GPU，最小化PCIe传输，仅预填充查询token，从系统层面彻底消除了重复预填充开销。
- **广泛的实验验证**：覆盖三种架构的模型和14B规模，多种消融和鲁棒性测试，结论可靠。

### 8. 不足与局限
- **跨事实交互缺失**：独立编码事实导致多跳推理问题上的准确率仍有明显损失，虽然窗口编码有所改善，但仍未达到联合预填充的上限。
- **GPU内存占用大**：单个对话的KV存储需1.8-4.8 GB，限制了GPU可同时服务的对话数量；尽管支持CPU卸载，但仍需权衡设备内存容量。
- **只读与离线构建**：当前系统假设记忆是静态只读的，不支持在线增量更新、删除或修订记忆事实，限制了在持续对话场景下的灵活性。
- **单GPU部署**：实验仅限于单张GPU，未探索多GPU、多节点场景下KV存储和检索索引的分片与路由问题。
- **预处理开销**：上下文窗口编码带来一次性离线计算开销，窗口较大时预处理时间可观。
