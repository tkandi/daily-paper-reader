## 摘要
现代 GPU 集群必须同时服务深度学习训练和离线大语言模型推理负载，然而现有调度器将这些负载视为孤立的资源消费者，采用刚性的静态分配。这导致大量 GPU 容量未被充分利用：训练作业保留整块设备尽管存在周期性空闲阶段，而离线推理任务过度配置 GPU 尽管需求呈突发模式。我们提出 ElastiCo，一个弹性共置框架，通过三种集成机制使训练和推理负载能够安全共享 GPU。首先，资源形状变换将每个作业暴露为一组可行的资源-性能配置。其次，弹性影子定价通过动态的每资源影子价格将由此产生的多资源分配问题分解为每个作业的配置选择子问题。第三，干扰感知共置使用基于硬件计数器和任务级特征训练的预测器来估计 GPU 共享下的成对性能下降。ElastiCo 实现为原生 Kubernetes 中间件，无需修改用户代码，在 64-GPU 测试平台上以及通过大规模轨迹驱动模拟（最高 512 GPU）进行评估，将平均 JCT 最多降低 2.94 倍，集群吞吐量提升 2.02 倍，并将 GPU 利用率从约 25% 提升至 46%。

## Abstract
Modern GPU clusters must simultaneously serve deep learning training and offline large language model inference workloads, yet existing schedulers treat these as isolated resource consumers with rigid, static allocations. This leaves substantial GPU capacity underutilized: training jobs reserve entire devices despite periodic idle phases, while offline inference tasks over-provision GPUs despite bursty demand patterns. We present ElastiCo, an elastic co-location framework that enables training and inference workloads to safely share GPUs through three integrated mechanisms. First, Resource Shape Transformation exposes each job as a family of feasible resource-performance configurations. Second, Elastic Shadow Pricing decomposes the resulting multi-resource allocation problem into per-job configuration selection subproblems via dynamic per-resource shadow prices. Third, Interference-Aware Co-location uses a predictor trained on hardware-counter and task-level features to estimate pairwise performance degradation under GPU sharing. Implemented as native Kubernetes middleware requiring no user-code modifications, ElastiCo is evaluated on a 64-GPU testbed and through large-scale trace-driven simulations (up to 512 GPUs), reducing the average JCT by up to 2.94x, increasing the cluster throughput by 2.02x, and increasing the GPU utilization from approximately 25% to 46%.

## 2. 论文提出的方法论

### 2.1 总体架构
ElastiCo 由四个模块构成，并由 **Phase-Aware Disaggregated Scheduling（PDS）** 闭环编排：

1. **Resource Shape Transformation（RST）** —— 暴露每个作业的可行配置空间。
2. **Elastic Shadow Pricing（ESP）** —— 通过影子价格分解多资源分配问题。
3. **Interference-Aware Co-location（IAC）** —— 预测 GPU 共享下的成对性能衰减。
4. **PDS** —— 队列感知容量预留、配置切换与抢占式迁移的统一调度循环。

### 2.2 RST：资源形状变换
- 为每个作业 \(j\) 定义配置集合 \(\mathcal{C}_j\)，每个配置 \(c\) 映射为资源–性能画像 \(p_j(c)=(R_j(c), T_j(c), L_j)\)：
  - \(R_j(c)\)：多维资源需求（GPU SM、显存、CPU、内存）。
  - \(T_j(c)\)：隔离环境下的吞吐。
  - \(L_j\)：最低性能目标。
- **训练作业配置旋钮**：激活重计算/检查点（activation checkpointing）、微批大小（micro-batch size）、自动混合精度（AMP）。
- **推理作业配置旋钮**：前缀缓存（prefix caching）、连续批处理（continuous batching）参数（最大批大小、最大序列长度）、`gpu_memory_utilization`（显存利用率上限）。
- 通过运行时采样生成画像，缺失配置用最近邻插值，在线实测后更新。

### 2.3 ESP：弹性影子定价
将联合配置选择与多资源分配形式化为整数规划：

\[
\max \sum_{j \in \mathcal{A}} \sum_{c \in \mathcal{C}_j} w_j \cdot T_j(c) \cdot x_j^c
\]
约束包括每作业唯一配置、资源容量约束、性能下限约束。

- **拉格朗日分解**：对资源容量约束引入影子价格向量 \(\lambda\)，将问题分解为每作业独立选择最优配置：
  \[
  c_j^* = \arg\max_c \left[ w_j T_j(c) - \sum_r \lambda_r R_j(c)[r] \right]
  \]
- **实际评分函数**：
  \[
  \text{Score}_j(c;\lambda^t)= \text{PerformanceCost}_j(c) + \sum_r \lambda_r^t R_j(c)[r] + \Gamma_j^{(m)}(c)
  \]
  其中 \(\Gamma_j^{(m)}(c)\) 包含切换代价和来自 IAC 的干扰惩罚。
- **价格更新**（投影次梯度）：
  \[
  \lambda_r^{t+1} = \max(0, \lambda_r^t + \eta_t (U_r - C_r))
  \]
  当某资源超售时其价格上升，引导作业选择更低资源需求配置。

### 2.4 IAC：干扰感知共置
- **特征工程**：36 维特征，包括每作业的硬件利用率（SM Active、SM Occupancy、DRAM Active、Framebuffer Used、Tensor Core Active）、任务级特征（负载类型、参数量、吞吐、批大小、检查点、精度、序列长度、前缀缓存率）以及成对交互特征（均值、共置类型、显存压力比、算力平衡比、内存强度差）。
- **预测模型**：三层全连接 DNN，输出 \(\hat{S}_{i|j}=T_i^{solo}/T_i^{colo}\)，约束 \(\hat{S}_{i|j}\ge 1\)。使用 log 空间 MSE 训练，batch norm 和 dropout。
- **自适应容忍阈值**：
  \[
  \tau_j(t) = \tau_j^{base} + \beta \left( \frac{U(t)}{U^{target}} - 1 \right)
  \]
  队列越长，容忍的干扰越大，但有上界。

### 2.5 PDS：调度循环
- 每个 epoch（默认 5s）计算有效容量 \( \mathbf{C}^{eff} = \mathbf{C} - \gamma \sum_{j \in \mathcal{Q}} R_j^{min} \)，为排队作业预留资源。
- ESP 影子价格迭代 → 每作业配置选择 → bin-packing 放置 → IAC 检查每对共置干扰 → 若违反阈值则更新惩罚项并重迭代，直到安全或达到最大轮数 \(M\)。
- 优先通过配置切换而非迁移来适应；迁移时采用框架原生 checkpoint。

### 2.6 实现要点
- **非侵入式 profiling**：TDOP 使用 `LD_PRELOAD` 拦截 CUDA API + NVIDIA DCGM 硬件计数器，不修改用户代码。
- **显存预算协调**：将调度器计算的显存预算映射为 vLLM 的 `gpu_memory_utilization`、PyTorch 的 `PYTORCH_CUDA_ALLOC_CONF` 等框架原生参数。

## 6. 论文的主要结论与发现

- **整体性能**（64-GPU）：
  - 平均 JCT 降至 Volcano 的 \(0.34\times\)（降低 \(2.94\times\)），较 Lucid 再降低约 \(1.35\times\)。
  - 集群吞吐量提升至 \(2.02\times\)。
  - GPU SM 利用率从 25% 提升至 46%（\(1.84\times\)）。
  - 所需额外 GPU 实例数减少 44%。
- **组件贡献**：
  - 禁用 RST 造成最大损失：JCT 增加 53%，吞吐下降 23%，显存利用率从 82.6% 降至 73.1%。
  - 禁用 ESP：吞吐下降 18%，说明全局协调对利用干扰异质性很关键。
  - 禁用 IAC：吞吐仅下降 8%，但会造成局部性能崩溃，表明 IAC 主要用于避免有害共置。
  - 禁用 PDS：JCT 增加 17%，吞吐降 11%，体现稳定编排的重要性。
- **干扰预测**：DNN 的 MAPE 为 7.6%，\(R^2=0.89\)，优于 XGBoost（9.4%）和线性回归（18.7%）。
- **可扩展性**：512 GPU 下仍保持 JCT 降低 \(2.44\times\)、吞吐提升 \(1.82\times\)，调度延迟 13.7 ms，远小于 5 s epoch。
- **系统开销**：64 GPU、30 活跃作业时每 epoch 调度延迟仅 4.2 ms；重配置过渡占 GPU 小时不足 0.3%。

## 7. 优点

- **联合优化视角**：将配置弹性、多资源分配和干扰感知统一建模，避免逐项优化导致的次优。
- **机制设计有理论支撑**：ESP 采用拉格朗日分解 + 影子价格，具有良好的可分解性和可扩展性。
- **干扰预测实用性强**：36 维特征覆盖硬件计数器和任务级信息，DNN 预测误差小于安全/有害共置之间的差异，足以支撑调度决策。
- **无需修改用户代码**：LD_PRELOAD 拦截 + DCGM 采样，对任意 PyTorch / vLLM / CUDA 应用具通用性。
- **工程实现完整**：显存预算协调到框架原生参数，支持 MPS 硬限制；配置切换优先于迁移，降低开销。
- **实验全面**：包含消融、案例、预测精度、可扩展性和系统开销，验证了各组件的独立贡献。
- **公开问题说明**：对 IAC 泛化、硬件同质性和规模局限有清醒认识。
