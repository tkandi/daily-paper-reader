## 摘要
随着大语言模型推理向多租户GPU集群迁移，合批处理提高了吞吐量，但模糊了每个租户的使用情况并限制了控制。要实现推理引擎的细粒度共享，需要一种实时、逐请求的归因原语，该原语既要足够准确，又要足够轻量以在调度循环内运行。我们提出LLMVisor，一个由Roofline模型引导的延迟归因模型，其通过与FLOPs和内存I/O流量成正比的特征，用简洁的分段线性形式刻画内存受限和计算受限阶段。LLMVisor将批处理延迟分解为可加和的逐请求份额，并在微秒级高效运行。我们在A100/H100 GPU上，在不同张量并行度和混合工作负载下对Llama 3.1-8B和Qwen 2.5-14B/32B进行评估。与基于token计数的基线相比，LLMVisor获得了近乎完美的R平方，在预填充阶段的p90和p99相对误差分别最多降低2.5倍和3.3倍，在解码阶段分别最多降低3.5倍和4.4倍，尽管存在批处理差异和序列差异。

## Abstract
As LLM inference shifts to multi-tenant GPU clusters, co-batching improves throughput but obscures per-tenant usage and limits control. Enabling fractional sharing of the inference engine requires a real-time, per-request attribution primitive that is accurate and light enough to run inside the scheduling loop. We present LLMVisor, a roofline-guided latency attribution model that captures the memory-bound and compute-bound phases via a concise piecewise-linear form over features proportional to FLOPs and memory I/O traffic. LLMVisor decomposes batch latency into additive, per-request shares and runs efficiently at microsecond scale. We evaluate LLMVisor across Llama 3.1-8B and Qwen 2.5-14B/32B on A100/H100 GPUs under varying tensor parallelism and workload mixes. Compared to a token-count baseline, LLMVisor attains near-perfect R-squared and reduces relative error by up to 2.5x and 3.3x at p90 and p99, respectively, for prefill, and by up to 3.5x and 4.4x for decode, despite batching variability and sequence divergence.

## 1. 论文的核心问题与整体含义

- **背景与动机**：大语言模型（LLM）推理正从独占 GPU 转向多租户、共享 GPU 集群。为了提高吞吐，服务提供商会将来自不同租户的异构请求合并为同一批次（co-batching），但这会掩盖每个租户实际的 GPU 使用情况，使得细粒度的资源分配、公平性控制、按量计费和 SLO 准入变得困难。
- **核心问题**：现有方案要么依赖专用 GPU 服务器（利用率低），要么依赖硬件分区（如 NVIDIA MIG，缺乏灵活性）。要在软件层面实现“推理引擎虚拟化”，让租户以分数形式共享 GPU 时间，缺少一个关键的 **实时、逐请求延迟归因原语**：它必须足够准确以指导调度，又必须足够轻量以运行在毫秒级调度循环中。
- **整体含义**：论文提出的 LLMVisor 填补了这一空白，通过将批次延迟分解为可加和的每请求延迟份额，使多租户 LLM 服务能够实现精细化的 GPU 时间配额控制、公平调度和透明的用量核算。

## 2. 论文提出的方法论

- **核心思想**：采用 **Roofline 引导的分段线性建模**。不直接手工计算 FLOPs 和内存字节并除以 GPU 峰值性能，而是构造一组与 FLOPs 和内存 I/O 流量成正比的请求级特征，再用短时间的 warm-up profiling 数据拟合系数。这样既保留可解释性，又提高精度并降低运行时开销。
- **关键公式**：批次延迟 \( T_B \) 建模为：
  \[
  T_B = \beta + a_1 \sum_i p_i + a_2 \sum_i c_i + a_3 \sum_i p_i^2 + a_4 \sum_i |B|
  \]
  其中：
  - \(p_i\)：当前步骤中请求 \(i\) 需要处理的 token 数（预填充阶段为全部 prompt token；解码阶段为 1）。
  - \(c_i\)：需要被注意力机制关注、且需要加载 KV cache 的上下文 token 数（预填充时为 0；解码阶段为此前的 prompt 长度）。
  - \(\sum_i p_i\) 反映 MLP 和因果注意力的计算量。
  - \(\sum_i c_i\) 反映 KV cache 内存流量。
  - \(\sum_i p_i^2\) 建模二次复杂度自注意力成本。
  - \(\sum_i |B|\) 刻画批量大小带来的利用率收益。
- **分段与参数拟合**：预填充和解码阶段分别对应不同的系数集，共 4 组参数（预填充 2 组、解码 2 组），通过普通最小二乘法（OLS）在 profiling 数据上拟合。
- **可加性归因**：由于 \(T_B\) 是每请求项之和的线性函数，因此可以自然地将批次延迟分解为闭式、可加和的每请求贡献 \(f(i|B)\)，并进一步聚合为每租户使用量 \(L_u = \sum_{i:u(i)=u} f(i|B)\)。
- **效率**：推理时只需对请求特征求和并乘系数，运行时间在微秒级，比 Random Forest 等 ML 预测器快 100 倍以上，适合嵌入调度循环。

## 7. 优点

- **可解释性强**：基于 Roofline 的分段线性形式，特征与 LLM 执行机制（计算、KV cache I/O、二次注意力、批量利用率）一一对应，易于理解和调试。
- **天然可加和**：批次延迟可直接分解为逐请求贡献，非常适合多租户公平性和计费场景，这是黑盒 ML 预测器无法提供的。
- **极其轻量**：运行时微秒级，远快于常见 ML 模型，可在高频调度循环中在线使用，不破坏合批处理效率。

- **针对性强**：明确针对多租户 LLM 服务中“合批掩盖资源使用”的实际痛点，应用价值清晰。
