## 摘要
面向大语言模型的强化学习（RL）正朝着多轮智能体工作负载发展，其中 rollout 任务会反复暂停以等待外部环境，在上下文不断增长的情况下恢复执行，并在高度可变的时间完成。在这一场景下，以训练吞吐量衡量的 RL 训练有效吞吐比原始 GPU 占用率更为重要：GPU 等待和重复的 prefill 重计算都是纯开销。我们提出 TideRL，一个具有连续任务批处理（CTB）、资源感知 Ref-Actor 流水线（RA²P）和弹性资源伸缩（ERS）的就绪感知弹性 RL 系统。CTB 保留有用的 rollout 状态，RA²P 根据就绪积压和到达间隔在解耦流式与共置聚合之间进行选择，ERS 利用相同的就绪信号在 rollout 与训练之间迁移 rank。在纯文本和多模态智能体工作负载上，TideRL 将 RL 训练有效吞吐相较同步基线提升高达 5.6 倍，相较异步基线提升超过 33%，同时达到相近的任务性能。它还将 KV 缓存命中率提升 1.58 倍，将每步训练时间最多减少 44.3%，并将总等待时间最多减少 77.6%。

## Abstract
Reinforcement learning (RL) for large language models is moving toward multi-turn agentic workloads, where rollout tasks repeatedly pause for external environments, resume with growing contexts, and finish at highly variable times. In this setting, RL training goodput, measured by training throughput, matters more than raw GPU occupancy: GPU waiting and repeated prefill recomputation are pure overhead. We present TideRL, a readiness-aware elastic RL system with Continuous Task Batching, Resource-Aware Ref-Actor Pipelining, and Elastic Resource Scaling. CTB preserves useful rollout state, $\textrm{RA}^2\textrm{P}$ selects between decoupled streaming and colocated aggregation from the ready backlog and arrival interval, and ERS moves ranks between rollout and training using the same readiness signals. Across text-only and multi-modal agentic workloads, TideRL improves RL training goodput by up to 5.6$\times$ over synchronous baselines and over 33% over asynchronous baselines, while reaching similar task performance. It also improves KV cache hit rate by 1.58$\times$, reduces per-step training time by up to 44.3%, and cuts total waiting time by up to 77.6%.

## 1. 论文的核心问题与整体含义

- **研究背景**：大语言模型正从单轮文本生成走向多轮智能体任务。在 agentic RL 中，rollout 会反复暂停等待外部环境、携带越来越长的上下文恢复执行，且不同任务完成时间差异极大。
- **核心问题**：现有 RL 系统在这种多轮、高并发、上下文长度剧烈变化的工作负载下，出现严重的 GPU 等待和重复 prefill 重计算，导致训练有效吞吐（goodput）低下。
- **整体含义**：论文提出，面向多轮 agentic RL 的目标不应只是提高 GPU 占用率，而应是提升“真正能推动模型更新”的训练吞吐。为此需要协同设计 rollout 内存管理、训练执行流水线和集群资源分配。

## 2. 论文提出的方法论

论文提出 **TideRL**，包括三个相互耦合的组件：

### 2.1 Continuous Task Batching（CTB）

- 将 rollout 调度从请求级别提升到任务级别。
- **Token-aware admission control**：将每个 DP rank 视为 token 预算池，根据探测到的首轮 token 用量决定是否接纳新任务，并约束环境并发、策略陈旧度和任务多样性。
- **Semantic-aware pausing/resuming**：当 rank 超预算时，按语义优先级抢占任务，优先级分数为：
  \[
  P(t)=\omega_1 \cdot I_{eval}+\omega_2 \cdot G_{completion}+\omega_3 \cdot I_{active}+\omega_4 \cdot L_{context}
  \]
  其中评估任务优先级最高，其次是 GRPO 组完成度、正在执行的任务、上下文长度。
- 恢复时优先恢复暂停任务并保持 worker affinity，以减少 KV cache 失效和前缀重算。

### 2.2 Resource-Aware Ref-Actor Pipelining（RA²P）

- 根据两个就绪信号选择 Ref-Actor 执行策略：
  - **RAS（Ready-at-Start）**：训练步开始时已经就绪的 micro-batch 数量。
  - **TPRM（Time Per Ready Micro-batch）**：训练步开始后，后续 micro-batch 到达的平均间隔。
- **Decoupled streaming mode**：当 RAS 大或 TPRM 短时，将 Ref 和 Actor 放在不同 GPU，通过将 loss 计算从 Actor forward 移到 backward，实现 Ref forward、Actor forward 和 Actor backward 重叠，避免模型换入换出。
- **Optimized colocated mode**：当 RAS 小或 TPRM 长时，将 Ref 和 Actor 共置在同一 GPU，通过“ready-batch aggregation”将多个就绪 micro-batch 聚合后一次 Ref 计算、一次 Actor 更新，减少模型切换次数；并通过 zero-copy shared memory 传输数据。
- 使用解析成本模型 \(C_{dec}\) 和 \(C_{col}\) 选择模式。

### 2.3 Elastic Resource Scaling（ERS）

- 动态在 Rollout 和 Trainer 之间迁移 GPU rank。
- 通过全局缓冲区的 **generation deficit** 和 **consumption deficit** 判断瓶颈：
  - Trainer 饥饿时：选择共置 RA²P，并把 Ref 专用 GPU 迁移给 Rollout。
  - Rollout 积压时：选择解耦 RA²P，并回收 Rollout rank 作为 Ref rank。
- 基于 on-policy RL 每次权重同步后 KV cache 自然失效的边界，将权重迁移隐藏在 `sync_params` 广播中，实现近零开销的角色切换。

## 7. 优点
