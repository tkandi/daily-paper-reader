## 摘要
混合专家（Mixture-of-Experts）模型在保持每个token激活计算量有界的同时增加了参数容量，但其架构演进无法仅通过模型发布的时间顺序列表来解释。本技术综述综合原始论文、官方技术报告和先前综述，沿着五个相互耦合的维度组织现代混合专家系统：专家粒度、专家拓扑、路由自由度、负载均衡范围和执行结构。我们将八个架构里程碑描述为一个依赖图，包含六条主线发展和两个正交分支，而不是将它们视为八个相继的世代。然后，我们通过四个控制平面分析各个系统：专家拓扑、路由、平衡和专家并行。这些平面规定了存在哪些专家、哪些专家处理每个token、如何控制总负载，以及如何将选定的计算映射到物理设备上。该框架将Top-k路由、共享专家、细粒度专家和动态专家组合等算法选择与token分发、设备放置、全对全通信及通信-计算重叠等系统问题联系起来。最后，我们进行了等预算预训练实验，给出了质量和系统指标，并提出了开放研究问题。主要趋势是从仅仅激活更多稀疏参数转向解耦语义路由、计算预算和物理执行。

## Abstract
Mixture-of-Experts models increase parameter capacity while keeping the computation activated by each token bounded, but their architectural evolution cannot be explained by a chronological list of model releases alone. This technical survey synthesizes primary papers, official technical reports, and prior surveys to organize modern Mixture-of-Experts systems along five coupled dimensions: expert granularity, expert topology, routing freedom, the scope of load balancing, and execution structure. We describe eight architectural milestones as a dependency graph with six mainline developments and two orthogonal branches, rather than as eight successive generations. We then analyze individual systems through four control planes: Expert Topology, Routing, Balance, and Expert Parallelism. These planes specify which experts exist, which experts process each token, how aggregate load is controlled, and how selected computation is mapped onto physical devices. The framework connects algorithmic choices such as Top-k routing, shared experts, fine-grained experts, and dynamic expert composition with systems concerns including token dispatch, device placement, all-to-all communication, and communication-computation overlap. We conclude with equal-budget pretraining experiments, quality and systems metrics, and open research questions. The main trend is a shift from merely activating more sparse parameters toward decoupling semantic routing, computational budgets, and physical execution.

## 2. 论文提出的方法论

论文不是提出某种新的 MoE 模型，而是提出一套分析和组织 MoE 系统的统一框架。

- **五个耦合维度**：
  - 专家粒度（expert granularity）
  - 专家拓扑（expert topology）
  - 路由自由度（routing freedom）
  - 负载均衡作用域（scope of load balancing）
  - 执行结构（execution structure）

- **四个控制平面**（用于剖析单个 MoE 系统内部工作机制）：
  - **Expert Topology（对象层）**：定义有哪些专家、它们多大、如何分组或共享。
  - **Routing（决策层）**：逐 token 决定选择哪些专家、激活多少专家。
  - **Balance（控制层）**：在 token 组/设备/节点等多尺度上观察负载，并通过辅助损失、bias、capacity 或 runtime placement 进行反馈控制。
  - **Expert Parallelism（执行层）**：将逻辑专家映射到物理设备，执行 dispatch、局部 GEMM 和 combine，处理 All-to-All 通信。

- **关键形式化表示**：
  - Token-choice MoE 的基本公式为：
    - 由 Router 计算专家亲和度 \(s_{i,t} = \phi(x_t,e_i)\)；
    - 选择 top-k 专家集合 \(\mathcal{K}_t\)；
    - 输出为 \(y_t = x_t + \sum_{i \in \mathcal{K}_t} g_{i,t} E_i(x_t)\)。
  - 四个控制层面的闭环关系可写作：
    - \(\mathcal{E} = T(\theta_{topo})\)；
    - \(\mathcal{K}_t = R(x_t,\mathcal{E};\theta_{route},b)\)；
    - \((b,\alpha,c) \leftarrow C(\{n_i\},\pi)\)；
    - \(y_t = EP(x_t,\mathcal{K}_t,\pi,\sigma)\)。

- **八个演进节点**（依赖图，而非线性代际）：
  1. Dense/Soft MoE：统计分工，所有专家参与计算。
  2. Sparse conditional computation：Top-k 建立容量杠杆，参数容量与单 token 计算量解耦。
  3. Transformer MoE 与 Expert Parallel：GShard、Switch 等解决集群级稳定训练。
  4. 开放权重 coarse-grained MoE：Mixtral 证明 decoder-only MoE 可产品化。
  5. Shared + fine-grained experts：DeepSeekMoE/V2、Qwen3 等实现细粒度知识组织和共享专家/设备限制路由。
  6. Ultra-sparse scaling：PEER、Kimi K2、gpt-oss 等探讨固定 active 参数下继续扩大专家池。
  7. 动态计算：zero experts、adaptive-k 使 token 的计算预算可变。
  8. 语义路由与物理执行解耦：ScMoE、MoHGE、GMoE、Head Parallel 等重构执行依赖、异构专家、跨层共享或结构化通信。

- **负载均衡关键技术细节**：
  - 经典 auxiliary loss：\(\mathcal{L}_{bal} = \alpha N \sum_{i=1}^{N} f_i P_i\)。
  - Auxiliary-Loss-Free（ALF）：使用非梯度 routing bias \(b_i\) 进行负载控制，避免直接干扰语言建模梯度。
  - Device/node/communication-aware balance：区分专家级、设备级、通信级均衡。
  - Runtime expert placement：在推理/服务阶段通过冗余部署和热点专家迁移来应对真实流量偏移。

- **专家并行与通信优化**：
  - MegaBlocks：dropless MoE，避免 token dropping。
  - Tutel：自适应并行和 pipeline 策略。
  - ScMoE、DualPipe、LongCat 等：通过执行依赖重排、token chunking、dense/MoE overlap 来隐藏通信。

## 6. 论文的主要结论与发现

- MoE 架构演进不是“专家越来越多”的单线扩张，而是五条路线的共同演化：
  - 专家从少量大模块变为细粒度、超稀疏和异构计算单元；
  - 拓扑从 layer-local routed experts 发展到 shared、cross-layer global/local 和 latent-head 结构；
  - Router 从简单 Top-k 逐步加入全局统计、bias 控制和动态计算预算；
  - Balance 从 sequence-wise 辅助损失走向 device/communication-aware、ALF 与 runtime placement；
  - 执行从串行 All-to-All 发展到 dropless kernels、topology-limited routing、ScMoE overlap 和结构化通信。
- 现代大规模 decoder MoE 的主流主干是：Token-choice Top-k + fine-grained experts + 可选 shared path + global/batch-wise balance 或 ALF + topology-limited routing + dropless kernels/communication overlap + runtime expert placement。
- ScMoE 之后不存在唯一的“下一代结构”，更可信的方向是四者组合：更自由的语义路由、显式的平均计算预算控制、拓扑感知或确定性通信、运行时 expert placement。
- 架构评估必须从单一 validation loss 扩展为质量、specialization、active budget、exposed communication 和尾延迟的联合分析。
