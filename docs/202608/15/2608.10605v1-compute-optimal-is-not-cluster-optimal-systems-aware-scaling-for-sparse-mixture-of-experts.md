## 摘要
在大规模预训练中，算法、架构和系统决策通常在彼此脱节的阶段做出。扩展律阶段选择架构和训练配方，在计算约束下优化损失，随后单独的系统阶段再针对硬件效率优化实现。在这项工作中，我们开发了 MOSAIC，将模型架构与系统协同设计形式化为一个优化问题。MOSAIC 将预测性扩展律与经过校准的性能模型相结合，该性能模型估计模型 FLOPs 利用率（MFU）、通信成本、内存占用以及最优并行布局。我们将该框架实例化用于稀疏混合专家（MoE）语言模型，其中专家数量、路由稀疏性及其他 MoE 层维度同时影响损失和系统效率。我们在文本数据上训练的稀疏 MoE 模型上拟合了扩展律，其扩展维度包括稀疏因子，即前向传播中每个 token 未激活的模型参数比例。我们工作中的扩展律扫描范围涵盖活跃参数从 1.04 亿到 27 亿，总模型规模达到 790 亿参数。我们表明，在校准的稀疏性范围内，不考虑效率的模型 FLOPs 预算不存在内部最优稀疏性。拟合的损失随模型更稀疏而单调下降，计算最优位于数据支持的上边界。相反，在集群系统约束下，如 MOSAIC 所捕捉的那样，MoE 模型的最优稀疏性才会出现。我们的结果主张前沿语言模型训练向统一的架构与系统协同设计转变。

## Abstract
In large-scale pretraining, the algorithm, architecture, and systems decisions are conventionally made in disconnected stages. A scaling law stage selects an architecture and training recipe, optimizing loss under compute constraints, and a separate systems stage then optimizes the implementation for hardware efficiency. In this work, we develop MOSAIC, which formulates model architecture and systems co-design as an optimization problem. MOSAIC couples a predictive scaling law with a calibrated performance model that estimates Model FLOPs Utilization (MFU), communication cost, memory footprint, and the best parallel layout. We instantiate the framework for sparse Mixture-of-Experts (MoE) language models, where expert count, routing sparsity, and other MoE layer dimensions affect both the loss and systems efficiency. We fit a scaling law on sparse MoE models trained on text data, whose scaling dimensions include the sparsity factor, which is the fraction of model parameters inactive per token in a forward pass. The scaling law sweeps in our work span active parameters from $104$ million to $2.7$ billion and total model sizes reaching $79$ billion parameters. We show that, within the calibrated sparsity range, an efficiency-agnostic model-FLOPs budget admits no interior optimal sparsity. The fitted loss decreases monotonically with sparser models and the compute optimum lies at the upper boundary of the data support. An optimal sparsity in MoE models instead emerges under the cluster's systems constraints, as captured by MOSAIC. Our results argue for a shift towards unified architecture and systems co-design for frontier language model training.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **问题**：在大规模预训练中，模型架构选择（扩展律阶段）与系统实现优化（系统工程阶段）通常被当作两个脱节的步骤。扩展律回答“在多少模型 FLOPs 预算下选多大模型、多少数据”，而系统阶段才考虑该架构在真实集群上的吞吐、内存、并行效率等。
- **核心矛盾**：两个架构在预测损失上可能相同，但在真实硬件上的训练吞吐可能相差数倍。即“模型 FLOPs 最优”的架构，不一定是在给定 GPU 小时预算下能最快达到最低损失的架构。
- **针对 MoE 的具体矛盾**：稀疏 MoE 模型的专家数量、稀疏性（sparsity）、专家细分度（expert split factor）等维度既影响损失（模型容量），又影响系统效率（专家 all-to-all 通信、内存占用、kernel 效率等），因此传统“模型 FLOPs 预算”无法充分反映这些因素的实际成本。
- **整体含义**：论文主张将“系统阶段”折叠进“扩展律阶段”，使单一联合优化同时决定模型架构、训练 token 预算与集群并行布局。其标题“Compute-Optimal Is Not Cluster-Optimal”即核心观点：模型 FLOPs 最优并不等于在固定集群和固定训练窗口下的最优。

## 2. 论文提出的方法论：MOSAIC 框架

- **MOSAIC**（Model Optimization via Systems-Aware TraIning Co-design）：将架构与系统协同设计形式化为一个**混合整数非线性规划（MINLP）**问题：
  - 决策变量：
    - 架构 \(Z\)（来自离散的稀疏 MoE 几何空间：层数、残差宽度、专家数 \(E\)、top-\(K\)、专家分裂因子 \(G\) 等）；
    - 训练 token 数 \(D\)；
    - 并行执行布局 \(P_\ell\)（TP / PP / EP / CP / DP、微批次大小、激活检查点策略等）。
  - 约束：模型的模型 FLOPs 需求不超过集群在训练窗口内可交付的模型 FLOPs。
  - 目标：最小化由扩展律预测的损失 \(L(Z,D)\)。

- **核心概念：可交付模型 FLOPs（deliverable model FLOPs）**：
  - 传统模型 FLOPs：\(C_{\text{model}}(Z,D)=6N_{\text{act}}(Z)D\)，其中 \(N_{\text{act}}\) 是活跃参数。
  - 可交付模型 FLOPs：\(C_{\text{deliverable}} = C_{\text{peak}}\times \text{MFU}(Z,P_\ell,B)\times \eta_{\text{good}}\)，其中 \(C_{\text{peak}}\) 是集群硬件上限（GPU 数 × 峰值算力 × 训练时间），MFU 是模型 FLOPs 利用率，\(\eta_{\text{good}}\) 是有效运行时间占比。
  - 关键性质：\(C_{\text{deliverable}}\) 依赖架构与其并行布局，不再是与架构无关的常量。

- **扩展律拟合（4 维）**：
  - 提出了一个考虑 \((N_{\text{tot}}, S, D, G)\) 的联合损失预测函数（论文公式 10）：
    \[
    L(N_{\text{tot}}, S, D, G)= aN_{\text{tot}}^{\alpha}+bD^{\beta}+\frac{c}{(1-S)^{\lambda}}+\frac{j}{(1-S)^{\delta}N_{\text{tot}}^{\gamma}G^{\eta}}+e.
    \]
  - 关键发现是专家分裂因子 \(G\) 的指数 \(\eta\approx 0.95\) 是**可识别的（identified）**，表明更细的专家划分在系统代价未计入时确实降低损失。

- **性能模型（Performance Model）**：
  - 采用算子级解析模型，结合实际硬件微基准测试（GEMM、grouped GEMM、attention、路由、通信、CPU dispatch 等）作为查找表。
  - 迭代时间 = block 计算时间 + pipeline bubble + 词汇表阶段不平衡 + 暴露的 DP/PP 通信时间 + 优化器步；再用唯一校准项 \(\chi_{\text{sys}}\) 修正跨节点 A2A 延迟和深 pipeline 的同步开销。
  - 可输出 MFU 和内存预测，并搜索给定设备数下的最优并行布局。

- **算法流程**：
  - 枚举几何阶梯（geometry ladder）上的离散架构 \((q,E,K,G)\)；
  - 对每个架构，在可行并行布局中选取 MFU 最大的布局；
  - 根据消元公式 \(D^\star(Z,P_\ell)=\frac{C_{\text{peak}}\cdot\text{MFU}^\star(Z)\cdot\eta_{\text{good}}}{6N_{\text{act}}(Z)}\) 解析地确定 token 预算（饱和约束）；
  - 最后用扩展律打分并排序。

## 6. 论文的主要结论与发现

- **模型 FLOPs 预算下无内部最优稀疏性**：在校准的稀疏范围内（\(S \le 0.981\)），拟合损失随稀疏度单调下降；在固定模型 FLOPs 预算下，最优稀疏度位于数据支持的上边界（\(S^\star=S_{\max}\)）。这意味着模型 FLOPs 本身无法决定有意义的稀疏度。
- **硬件预算引入内部最优稀疏性**：加入真实集群的 MFU、通信和内存限制后（否则最优配置可能不可行），出现了内部最优稀疏度。示例中，集群最优 \(S^\star\) 在 0.915–0.963 区间，且不与预算单调变化。
- **模型 FLOPs 最多的配置不是损失最低的配置**：在 32 节点 20 天预算下，MFU 最高的配置产生最多模型 FLOPs，但并非最优损失配置；专家分裂因子 \(G\) 与 MFU 之间的系统权衡改变了排序。例如 \(G=8\) 几何 MFU 低，\(G=2\) 几何模型 FLOPs 多，而最优选中 \(G=4\) 配置。
- **实际训练验证排序在硬件成本轴上反转**：在 8 节点 64 GPU 验证中，配置 ID 2（低 MFU 但高稀疏/细粒度专家）在模型 FLOPs 轴上领先，而 ID 1（高 MFU）在硬件成本轴上超过 ID 2。这直接验证了“效率感知的预算才能给出正确的架构排序”。
- **联合优化框架的可解性**：文中的 MINLP 可通过有限枚举，利用闭式消元 \(D^\star\) 和结构性质求解，避免了通用 MINLP 求解器的不可行性（MFU 与内存是实测查找表，不具有符号表达式）。

## 7. 优点

- **问题定位准确且具有实际意义**：直接挑战了扩展律研究、系统优化各自独立的问题，尤其对稀疏 MoE 这一架构与硬件冲突显著的场景。
- **统一框架设计清晰**：将扩展律与系统性能模型耦合，并保持架构变量、token 预算、并行布局三者作为联合决策变量，理论与实践价值较高。
- **扩展律维度设计合理**：将 \(G\)（专家分裂因子）作为独立维度加入联合项，对系统侧需求更敏感，且用 bootstrap 不确定性和可识别性分析突出了 \(G\) 与数据项的可信度。
- **性能模型相当实用且可复现**：基于微基准测试与少量校准项，MFU 预测 MAE 在 9–13% 之间，并列于开源仓库，有较好的可复现性。
- **验证兼具预测与实际**：不仅做了大量离线搜索，还用被选配置真实训练，观察其在模型 FLOPs 与硬件成本轴上的排序变化。
- **实验报告相对透明**：明确限制（如固定几何阶梯、Megatron-Core 栈、学习率规则等）和处理方式，对结论条件有较充分的说明。

## 8. 不足与局限

- **扩展律外推风险较大**：最终搜索的候选配置远超扩展律训练区间（约 150× FLOPs），实际验证的 run 也外推到约 15–20×，排序结论在这一区间的适用性不确定。
- **依赖固定的几何阶梯与训练栈**：所有结果都基于特定深度/宽度扩展阶梯和一方特定的 Megatron-Core 栈；文中也承认 \(G^\star\) 不呈现随预算变化的明显趋势可能源于具体系统的通信/调度开销。
- **实际训练验证规模有限**：仅在 8 节点 64 GPU 上验证 4 个配置，且训练时长受 GPU 小时预算限制，不能充分支撑小型搜索中所有排序反转结论。
- **学习率与架构/系统的交互未充分探索**：学习率由计算预算规则统一设定，可能对更细颗粒度专家、更高稀疏度配置不完全适用。
- **未传播扩展律系数不确定性**：尽管对系数做了 bootstrap，但未将这种不确定性传播到离散架构搜索，最优配置的鲁棒性未量化。
- **未系统报告扩展律数据采集的总 GPU 时数**：可算力信息存在缺失，不利于外部完整评估其训练开销。
- **部分维度覆盖有限**：\(G\) 只覆盖到 8，TPP（token-per-parameter ratio）有上限，未研究“过度训练”区域；稀疏性也未逼近 1，渐近爆炸项是形式强加的。
- **性能模型是“镜像当前栈”的近似**：模型未能计入新型通信/kernel 优化、host 侧数据管道停顿以及未来更激进的系统优化；换硬件或换训练栈需重新校准。
