## 摘要
对人工智能（AI）推理服务日益增长的需求要求可扩展的基础设施，然而集中式服务的成本随需求上升。我们提出了一种协作分布式推理系统，将专用基础设施与服务用户贡献的资源相结合。专用资源提供维持服务质量（QoS）的基线容量，而志愿资源吸收不断增长的需求，无需集中式基础设施按比例扩展。为了捕捉用户、资源、任务和策略之间的随机动态交互，我们开发了一种具有结构化时间分解的高维生成马尔可夫模型。该模型支持仿真，并为任务调度和 QoS 感知的资源分配优化提供基础。我们在不同用户规模、资源容量以及集中式和分布式调度策略下对系统进行了评估。仿真表明，随着用户群体增长，分布式调度变得越来越有优势，改善了请求完成情况和 P99 延迟，同时大幅减少了专用资源消耗。这些结果证明了用户辅助协作推理在基础设施高效自动伸缩方面的可行性。

## Abstract
Growing demand for artificial intelligence (AI) inference services requires scalable infrastructure, yet centralized serving costs rise with demand. We propose a collaborative distributed inference system combining dedicated infrastructure with resources contributed by service users. Dedicated resources provide baseline capacity for maintaining quality of service (QoS), while volunteered resources absorb increasing demand without proportional growth in centralized infrastructure. To capture stochastic and dynamic interactions among users, resources, tasks, and policies, we develop a high-dimensional generative Markov model with structured temporal factorization. The model supports simulation and provides a foundation for task scheduling and QoS-aware resource allocation optimization. We evaluate the system across user populations, resource capacities, and centralized and distributed scheduling policies. Simulations show that distributed scheduling becomes increasingly advantageous as the user population grows, improving request completion and P99 latency while substantially reducing dedicated resource consumption. These results demonstrate the feasibility of user-assisted collaborative inference for infrastructure-efficient autoscaling.

## 2. 论文提出的方法论

### 2.1 系统架构与核心思想

- 系统由一台专用服务器 \(v_0\)、若干用户节点 \(I\) 和节点集合 \(V=\{v_0\}\cup I\) 组成。
- 用户可同时：发出推理请求、贡献计算/带宽/存储资源执行子任务。
- 推理任务分为多种类型 \(k\in K\)，每个任务由若干子任务 \(p\in P_k\) 组成。
- 系统由两类策略控制：
  - **调度器策略 \(\pi\)**：服务器端决定子任务下发、执行、取消等。
  - **执行器策略 \(\varsigma\)**：节点端执行资源约束强制措施，如暂停、中止、恢复下载或执行。

### 2.2 高维生成马尔可夫模型

- 系统状态定义为元组：

\[
s_t = \langle o_t, q_t, a_t, x_t, y_t, c_t, d_t, u_t \rangle
\]

- 各状态变量含义与建模方法：

| 变量 | 含义 | 建模方式 |
|---|---|---|
| \(o_t, d^o_t\) | 用户在线状态与状态持续时长 | 在线时长用 Weibull 生存函数；离线时长用 log-normal 生存函数 |
| \(q_t, d^q_t\) | 用户当前请求类型与请求持续时长 | Pareto 生存函数建模思考时间与耐心时间；任务类型从分类分布采样 |
| \(a_t\) | 各节点分配给系统的资源量 | 对带宽、CPU、内存、存储等资源拟合 ARMA 模型；对用户资源条件化于在线状态 |
| \(x_t, d^x_t\) | 子任务数据就绪状态（empty/download/pause/ready） | 由调度器动作、执行器动作、持续时长和存储累积共同决定 |
| \(y_t, d^y_t\) | 子任务执行状态（idle/download/execution/upload/done） | 使用离散时间 hazard 模型建模阶段完成；服务器无 download/upload 阶段 |
| \(c_t\) | 资源消耗，分为数据准备消耗 \(c^x_t\) 与执行消耗 \(c^y_t\) | 基于 ARMA 模型，约束在分配资源范围内，并考虑批处理与带宽共享 |
| \(u_t\) | 联合动作，包括调度动作 \(u^{\pi}_t\) 与执行器动作 \(u^{\varsigma}_t\) | 两类策略分别生成，执行器动作优先级高于调度器 |

- 模型采用**稀疏时间分解**：各变量按用户、节点、任务类型、子任务等维度因子化，使高维模型在仿真、推断和策略学习中可计算。

### 2.3 调度策略

- **集中式调度器（Centralized）**：完全基线。所有执行在服务器进行，服务器预先存储全部子任务数据，不向用户节点分发。
- **均匀调度器（Uniform）**：机会主义地利用在线用户节点。对每个在线节点最多下载一个缺失子任务数据；将请求与可行节点随机均匀匹配。
- **亲和性调度器（Affinity）**：与均匀策略使用相同的下载/取消/完成逻辑，但分配执行时优先选择已经运行相同子任务的节点，以增大 batch size，提升批处理效率。

### 2.4 优化问题

- **问题 1：调度器优化**  
  固定执行器策略 \(\varsigma\)，优化调度器 \(\pi\)，最大化长期平均奖励：

\[
\max_{\pi} \liminf_{T\to\infty} \mathbb{E}\left[ \frac{1}{T} \sum_{t=1}^{T} r(s_t) \mid s_0, u^{\pi}_{0:t-1} \sim \pi \right]
\]

其中 \(r(s_t)\) 为请求延迟增量的负值。

- **问题 2：专用资源分配优化**  
  给定调度器 \(\pi\) 与执行器 \(\varsigma\)，确定满足目标 QoS 约束的最小专用服务器资源容量 \(a^\dagger\)：

\[
\min_{a^\dagger} \lVert a^\dagger \rVert_w
\]

约束为各任务类型请求延迟不超过阈值 \(\tau_k\) 的概率至少为 \(1-\epsilon_k\)。

- 本文未设计优化算法，仅形式化问题，并通过仿真比较固定调度策略。

## 6. 论文的主要结论与发现

- **集中式推理在大规模时饱和甚至退化**：集中式策略在用户少时表现良好；当用户数超过 1,000 后，完成数增长趋缓，取消数快速上升；仅靠提升服务器容量收益递减。
- **均匀分布式调度在大规模下显著优于集中式**：在 10,000 用户时，均匀策略在所有服务器容量下均获得更高请求完成量和更低 P99 延迟，且所需服务器容量更低。
- **亲和性调度效果不稳定**：亲和性在部分小规模或低服务器容量场景有优势，但在大规模用户下由于大 batch 造成延迟耦合、节点离开或资源中断导致多个子任务同时失败，整体表现不如均匀调度。
- **分布式策略大幅降低专用资源消耗**：两种分布式策略的 CPU、内存消耗均明显低于集中式，且未超过分配上限；大约 30×–50× 服务器容量即可有效补充志愿资源，继续增加收益有限。
- **用户侧子任务完成率受用户设备容量影响**：2× 容量用户节点完成率更高；均匀策略用户侧完成率约为 0.75–0.95。
- 总体结论：用户辅助协作推理在大规模用户场景下具有可行性，能够实现基础设施高效的 QoS 感知自动伸缩，并为未来基于模型优化调度与资源分配提供基础。
