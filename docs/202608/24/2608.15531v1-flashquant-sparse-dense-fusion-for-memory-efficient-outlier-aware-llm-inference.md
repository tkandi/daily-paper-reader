## 摘要
低比特量化降低了大语言模型（LLM）推理的内存占用和计算开销。然而，高幅值的离群值权重会引入显著的量化误差并降低模型精度。离群值感知量化通过将离群值保留在高精度而对其余权重进行量化来解决此问题，由此形成低比特稠密 GEMM 路径和高精度稀疏 SpMM 路径。现有实现将这两条路径放在单独的 GPU 内核中执行，尽管它们共享激活和输出，因而错失了算子内复用的机会，并产生了冗余的全局内存访问。这种低效在内存受限的解码工作负载中尤为明显。我们提出了 FlashQuant，一个用于离群值感知 W4A16 解码的内容共享执行框架。FlashQuant 将稠密 GEMM 和稀疏离群值 SpMM 路径融合到单个 GPU 内核中，从而在跨异构计算中实现激活块和输出块的片上复用。它引入了三项关键技术：稀疏-稠密分块，使离群值处理与稠密 GEMM 块对齐；Tile-COO 离群值编码，实现高效稀疏访问并减少共享内存 bank 冲突；以及流水线调度，使计算与数据移动重叠。实验表明，FlashQuant 降低了离群值处理开销，相比 cuBLAS BF16 实现了 2.74× 至 4.18× 的加速，相比最强的未融合离群值感知基线实现了最高 1.53× 的加速。

## Abstract
Low-bit quantization reduces the memory footprint and computational cost of large language model (LLM) inference. However, high-magnitude outlier weights can induce substantial quantization errors and degrade model accuracy. Outlier-aware quantization addresses this issue by retaining outliers in high precision while quantizing the remaining weights, resulting in a low-bit dense GEMM path and a high-precision sparse SpMM path. Existing implementations execute these paths in separate GPU kernels, despite their shared activations and outputs, thereby missing opportunities for intra-operator reuse and incurring redundant global-memory accesses. This inefficiency is particularly pronounced in memory-bound decoding workloads. We propose FlashQuant, a content-sharing execution framework for outlier-aware W4A16 decoding. FlashQuant fuses the dense GEMM and sparse outlier SpMM paths into a single GPU kernel, enabling on-chip reuse of activation and output tiles across heterogeneous computations. It introduces three key techniques: sparse-dense tiling, which aligns outlier processing with dense GEMM tiles; Tile-COO outlier encoding, which enables efficient sparse access and reduces shared-memory bank conflicts; and pipelined scheduling, which overlaps computation with data movement. Experiments show that FlashQuant reduces outlier-processing overhead, achieving $2.74\times - 4.18\times$ speedup over cuBLAS BF16 and up to $1.53\times$ speedup over the strongest unfused outlier-aware baseline.

## 1. 论文的核心问题与整体含义

- **研究背景**：大语言模型（LLM）推理面临高内存占用与高计算成本。权重低比特量化（如 INT4）是常用压缩手段，但高幅值离群值（outlier）权重在量化时会造成显著重构误差，损害模型精度。
- **现有方案**：离群值感知量化将少量离群值保留为高精度（如 BF16），其余权重量化为低比特。推理时因此形成两条计算路径：
  - 低比特稠密 GEMM（处理量化权重 \(W_Q\)）；
  - 高精度稀疏 SpMM（处理离群值 \(W_O\)）。
- **核心问题**：现有系统通常用两个独立的 GPU kernel 分别执行稠密 GEMM 和稀疏 SpMM。二者共享相同的激活矩阵与输出矩阵，但分离执行会重复加载激活、重复写回部分输出，产生冗余全局内存访问。在解码阶段（batch 小、内存受限）这一开销尤其严重，甚至少量离群值也能造成不成比例的延迟。
- **整体含义**：FlashQuant 旨在通过“内容共享融合”将两条路径合并到单个 GPU kernel 中，实现片上数据复用，减少冗余内存流量，从而提高离群值感知量化推理的内存效率与速度。

## 2. 论文提出的方法论

FlashQuant 是一个面向离群值感知 W4A16 解码的统一执行框架，其核心思想是将低比特稠密 GEMM 与高精度稀疏 SpMM 融合到单一 GPU kernel，共享激活与输出 tile。主要包含以下技术：

### 2.1 稀疏-稠密分块（Sparse-Dense Tiling）
- **CTA 级**：将 \(W_Q\) 与 \(W_O\) 按相同 tile 边界划分，每个 CTA 加载一次激活 tile，同时供 GEMM 和 SpMM 路径复用；部分结果在片上累加后再写回全局内存。采用 Stream-K 策略将总 MAC 迭代空间分配给持久 CTA，以平衡负载。
- **Warp 级**：稠密路径使用 Tensor Core MMA 指令，需要规则对齐的 fragment；稀疏路径使用 CUDA Core，因离群值位置不规则。稀疏 warp 被分配不相交的输出列集合，避免写冲突，同时根据非零分布平衡负载。必要时为稀疏路径分配额外 warp 以隐藏延迟。
- **Thread 级**：稠密激活矩阵在共享内存中使用 8 元素 swizzle 布局减少 bank 冲突；稀疏处理将输出列划分为多个 bucket，每个 bucket 由一组线程处理，每组线程按行取激活，以降低 bank 冲突。

### 2.2 Tile-COO 离群值编码
- 提出一种 tile 局部稀疏格式，满足四个要求：与 GEMM tile 边界对齐、支持向量化访问、兼容共享内存激活布局、支持不规则分布下的负载平衡。
- 结构包含三个数组：
  - `tile_indptr`：记录每个 tile 的起始偏移（uint32）；
  - `bucket_info`：记录每个 bucket 的起始偏移和非零个数（uint16）；
  - `packed_outliers`：将每 4 个离群值的行索引（uint8）、列索引（uint8）和值（BF16/FP16）打包成 uint4，便于并行解码。
- 存储成本低于 CSR：Tile-COO 为 \((N_{tile}+1)\times4 + N_B\times4 + nnz\times4\) 字节，CSR 为 \((K+1)\times4 + nnz\times12\) 字节，显著降低元数据开销。

### 2.3 稀疏重排序（Sparse Reordering）
- **列重排序**：将 tile 内列按非零数降序排序，用最小堆贪心分配到各 bucket，均衡各子 warp 的工作量。
- **元素重排序**：根据行索引计算 bank group（\(gid = \lfloor k/2 \rfloor \% 4\)），按 bucket 相关的循环顺序选取元素，错开不同子 warp 的 bank 访问，减少共享内存 bank 冲突。

### 2.4 流水线执行与离群值解码
- **流水线调度**：采用多阶段流水线与双缓冲，将数据从全局内存加载到共享内存、从共享内存到寄存器、反量化与离群值解码、Tensor Core / CUDA Core 计算等阶段重叠，隐藏内存延迟。
- **离群值解码**：每个线程根据 bucket_id 与 lane 确定激活地址；使用双缓冲预取下一个 packed outlier；解包出行索引、列索引和 4 个半精度值；应用预计算的 swizzle 掩码；执行 4 次展开的 FMA 累加，结果写回共享内存。

## 7. 优点

- **创新性强**：首次针对离群值感知量化提出内容共享融合，将稠密 GEMM 与稀疏 SpMM 合并到单一 kernel，针对性强。
- **系统设计完整**：从 tile 级调度（CTA/warp/thread）到专用稀疏格式（Tile-COO）再到流水线执行，形成完整的技术栈。
- **专门优化**：稀疏重排序（列平衡 + bank 冲突缓解）和预计算 swizzle 等细节显示出对 GPU 微架构的深入理解。
- **实验充分**：多 GPU 架构、多密度、多批量、消融和端到端评估，证据较全面。
- **存储效率**：Tile-COO 在元数据开销上优于 CSR，适合实际部署。

## 8. 不足与局限

- **精度范围有限**：仅支持 INT4 权重量化 + BF16 离群值，未扩展到 INT2 等更低比特（论文也指出未来工作）。
- **小批量性能下降**：批量大小小于 8 时会 pad 到 8，引入冗余计算，并行效率降低，这在单 token 解码（batch=1）场景下可能影响实际收益。
- **基线比较局限**：未与其他离群值感知量化推理系统（如 SqueezeLLM 等）直接对比，端到端实验只用了两个模型、一个离群值阈值（5%），缺乏更广泛的性能-精度权衡分析。

## 9. 结论与未来工作

FlashQuant 通过将离群值感知量化推理中的稠密 GEMM 与稀疏 SpMM 融合到单一 GPU kernel，解决了分离执行导致的激活重复加载与输出重复写回问题，显著降低了内存流量。在三种消费级 GPU 架构上的实验表明，该方法相比未融合基线取得了 1.03×–1.53× 的加速，且离群值密度越高、GPU 算力越强，优势越明显。Tile-COO 编码在保持低存储开销的同时支持高效并行解码，稀疏重排序进一步改善了负载平衡与 bank 冲突。该工作证明了内容共享融合在低比特量化推理中的有效性，并为后续扩展至更低比特、数据中心 GPU 及更广泛模型提供了清晰方向。
