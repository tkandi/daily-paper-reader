## 摘要
高性能 GPU 内核支撑着现代深度学习和科学计算。随着工作负载日益多样化以及 GPU 硬件快速演进，开发高效的自动化 GPU 内核生成与优化方法变得愈发重要。现有基于 LLM 的方法通常在固定的实现空间内进行优化，这限制了优化灵活性或搜索效率。我们提出 HIERA，一个用于 GPU 内核优化的分层搜索空间规划框架。HIERA 构建契约增强的任务规范，在 PyTorch 算子、CUDA 库和自定义 CUDA 内核之间选择合适的实现空间，并利用性能分析反馈和专家知识引导结构化的迭代优化。在 KernelBench 上跨多个不同工作负载级别和基础 LLM 的实验表明，HIERA 在整体实现有效性、样本效率和优化性能方面均优于现有的免训练方法，同时在不进行额外模型训练的情况下与基于训练的 CUDA-L1 保持竞争力。针对科学计算中一个专用 stencil 算子的案例研究进一步实现了相对 cuDNN 1.53 倍的加速，展示了该通用框架在标准机器学习工作负载之外的潜力。

## Abstract
High-performance GPU kernels underpin modern deep learning and scientific computing. As workloads become increasingly diverse and GPU hardware evolves rapidly, developing efficient methods for automated GPU kernel generation and optimization has become increasingly important. Existing LLM-based methods typically optimize within a fixed implementation space, limiting either optimization flexibility or search efficiency. We propose \textsc{HIERA}, a hierarchical search-space planning framework for GPU kernel optimization. \textsc{HIERA} constructs contract-augmented task specifications, selects an appropriate implementation space across PyTorch operators, CUDA libraries, and custom CUDA kernels, and uses profiling feedback and expert knowledge to guide structured iterative refinement. Experiments on KernelBench across multiple various workload levels and base LLMs show that \textsc{HIERA} delivers stronger overall implementation validity, sample efficiency, and optimization performance than existing training-free methods, while remaining competitive with the training-based CUDA-L1 without additional model training. A case study on a specialized stencil operator from scientific computing further achieves a \(1.53\times\) speedup over cuDNN, demonstrating the potentiality of the general framework beyond standard machine-learning workloads.

## 2. 论文提出的方法论

HIERA 由四个核心组件构成，整体流程如下：

### 2.1 契约增强的任务规范（Contract-Augmented Task Specification）

- 针对每个 KernelBench 任务，HIERA 固定与性能无关的模板文件：扩展包装器（`torch_demo.py`）、C++ 绑定源码（`cpp_source.cpp`）、正确性参考实现（`groundtruth.py`）。
- Level 2 和 Level 3 任务额外提供参数语义文件（`params_semantics.json`），描述参数角色、约束和依赖；Level 1 任务参数语义可从接口和参考实现推断。
- 模型**只生成**候选实现文件 `cuda_source.cu`，避免重复生成宿主端包装、数据准备、构建配置等固定内容，将生成预算集中在性能关键决策上。

### 2.2 跨粒度搜索空间规划（Cross-Granularity Search-Space Planning）

- 搜索空间决策代理（SSDA）在每轮规划时从三个嵌套实现空间中选择一个：
  1. **纯 CUDA**：仅允许自定义 CUDA 内核；
  2. **CUDA 库**：额外允许优化库（如 cuBLAS）；
  3. **CUDA 库 + PyTorch 算子**：进一步允许高层 PyTorch 算子。
- 该选择根据工作负载特征和当前候选的表现动态进行，避免简单算子过度使用高层抽象带来的 dispatch/物化开销，也避免复杂模型级工作负载在纯 CUDA 中重建大量中间数据流而浪费预算。

### 2.3 领域引导的优化方向剪枝（Domain-Guided Optimization-Direction Pruning）

- 在选定实现空间内部，SSDA 再从五个专家总结的优化方向中选择主要方向：
  - **C**：控制流与边界特化（减少分叉/冗余执行）
  - **P**：线程与 warp 级并行性（提升并行度）
  - **M**：内存事务效率（改善全局内存访问）
  - **R**：数据复用与数据移动流水线（提升片上复用、重叠计算与访存）
  - **T**：Tensor Core 与指令流水线利用率（充分利用计算指令）
- 对每个方向打分：  
  \( s_t = \text{SSDA}(\tau, g_t, x_t, F_t, E; R) = \{s_d^t\}_{d \in D} \)，其中 \( \tau \) 为任务规范，\( g_t \) 为当前实现空间，\( x_t \) 为当前候选，\( F_t \) 为 profiling 反馈，\( E \) 为专家知识，\( R \) 为评分 rubric。
- 选择得分最高的方向 \( d_t^* = \arg\max_{d \in D} s_d^t \)。
- 策略规划代理（SPA）将选定方向转化为具体、可执行的优化策略 \( \pi_t \)，限定在当前实现空间和方向对应的策略空间内。
- 优化代理（OA）根据策略生成下一轮候选内核集合。

### 2.4 反馈驱动的候选评估与迭代

- 每个候选与固定模板组合后依次经过：编译检查 → 正确性验证 → 性能评估 → NCU profiling（获取硬件级瓶颈指标）。
- 有效候选按实测性能排序，保留最强候选作为下一轮父本；所有中间决策和评估结果被记录，支持轨迹追踪与诊断。

## 3. 实验设计

### 3.1 基准测试与数据集

- **KernelBench**：共 250 个 PyTorch 工作负载，分三级：
  - Level 1：100 个算子级任务；
  - Level 2：100 个融合算子任务；
  - Level 3：50 个模型级工作负载。
- 所有方法使用相同的 PyTorch 参考实现和输入生成过程，在相同硬件与设置下评估同一任务集。

### 3.2 对比方法

- **免训练基线**：
  - KernelBench-Caesar：官方迭代生成与反馈细化流程。
  - CUDAForge：基于 Coder–Judge 的硬件反馈 CUDA 优化框架。
- **训练式基线**：
  - CUDA-L1：使用对比强化学习训练模型，结果不随基座 LLM 变化，仅报告一次。
- **基座 LLM**：DeepSeek-V3.2、Qwen3.6-Plus、Gemini-3.6-Flash。

### 3.3 具体实验设置

- **主比较**：三种方法均进行 3 轮优化，每轮生成 6 个候选，最大预算 \( B = 18 \) 候选/任务；统一温度 0.3、候选生成预算和评估设置。
- **有限预算评估**：分别报告 \( B \in \{1, 6, 12, 18\} \) 时的累计最佳性能，从同一生成轨迹中提取，不独立重跑。
- **实现空间比较**：在 90 个采样任务（每级 30 个）上比较 HIERA 与三种固定实现空间变体：纯 CUDA、CUDA 库、CUDA 库 + PyTorch。所有变体使用相同任务、契约规范、LLM（Qwen3.6-Plus）、方向规划、候选预算和评估协议。
- **消融实验**：
  - HIERA w/o Contract：去掉契约增强，要求模型生成所有支持文件；
  - HIERA w/o Planning：去掉分层规划代理，用固定优化提示直接细化候选。
- **案例研究**：科学计算中的 2D box stencil，半径 \( R=3 \)（7×7 邻域共 49 点），输入尺寸 10240×10240，重复 10240 次，FP64 精度。以 cuDNN 的 `cudnnConvolutionForward` 作为稠密参考（单通道 7×7 零填充互相关，pad=3, stride=1, FP64, IMPLICIT_PRECOMP_GEMM）。搜索 5 轮，每轮种群 10 个，总预算 50 次候选评估。

## 6. 论文的主要结论与发现

- **RQ1（与现有方法比较）**：  
  - HIERA 在所有预算点均取得最高的有效实现率（fast0）和加速率（fast1）；  
  - 在 \( B=1 \) 时 fast0 达 71.6%，fast1 达 32.4%，显著超过 KernelBench-Caesar 和 CUDAForge；  
  - 在 \( B=18 \) 时 fast0 92.4%，fast1 60.4%，同样领先；  
  - 在多数基座 LLM 和 level 组合上，HIERA 的 fast0、fast1、fast2 均为第一或并列第一；  
  - 无需训练即可在 Level 1 和 Level 2 平均指标上超过训练式 CUDA-L1。

- **RQ2（设计有效性）**：  
  - 固定实现空间比较显示：纯 CUDA 最大加速达 9.32× 但方差极大；CUDA 库 + PyTorch 稳定但最大加速仅 2.98×；HIERA 自适应选择实现空间，取得最高均值（1.42×）和中位数（1.15×），方差较 Pure CUDA 降低 23.4%。
  - 消融实验表明：  
    - **契约增强**主要影响实现有效性，去掉后 Level 2 和 Level 3 的 fast0 分别下降 73 和 60 个百分点；  
    - **分层规划**主要影响加速性能，去掉后 Level 2 的 fast1 从 62% 降至 6%，fast2 从 20% 降至 6%。

- **RQ3（案例研究）**：  
  - 在 2D box stencil 上，HIERA 在 5 轮搜索内将运行时间从 13.71 ms 降至 4.71 ms，相对 cuDNN 参考（7.23 ms）实现 1.53× 加速，证明框架可扩展至科学计算领域。

## 7. 优点

- **明确的实现空间选择**：显式将实现粒度作为优化决策，避免固定空间的局限性，兼顾灵活性与搜索效率。
- **契约增强设计**：固定非性能关键文件，只生成内核主体，显著减少无效生成，提高编译和正确性通过率。
- **专家知识驱动的方向剪枝**：基于五个可解释的优化方向组织搜索，使迭代过程有结构、可追溯。
- **实验全面且公平**：覆盖 KernelBench 三个 level、三种基座 LLM、多个预算点，与多个 baselines 对比，并包含实现空间比较和消融研究，变量控制严格。
- **通用框架潜力**：在科学计算 stencil 上取得优于 cuDNN 的结果，展示超越标准 ML 工作负载的适用性。

- **与训练式方法的比较深度不足**：仅与 CUDA-L1 比较，未涉及其他训练式方法；CUDA-L1 结果不随基座变化，比较时存在方法学差异。
- **
