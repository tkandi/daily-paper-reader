## 摘要
容器粒度调度使得容器内大量短暂的空闲时间片未被利用。在SLA约束下，重新分配容器过于重量级，难以利用这些细粒度机会；而算子级调度则需要实时推理依赖关系、内存安全以及集群范围的执行动态。本文提出SliceScheduler，一个面向多租户模型服务的动态算子级调度系统。其核心思想是暴露集群范围的算子执行状态，并支持对调度决策进行假设推演。SliceScheduler由四个关键组件组成。首先，我们引入全局映射图（GMG），一种统一抽象，用于刻画算子依赖、张量形状、资源映射和执行状态，从而提供具有明确资源语义的实时集群范围视图。其次，我们在GMG之上构建全局模拟器，以预测候选放置方案下算子级执行和内存演变。第三，我们设计了一个增量式、基于模拟的调度模块，该模块选择放置方案以利用碎片化空闲时间片，同时避免内存违规并保持SLA。最后，我们开发了一个算子执行器，在GPU上具体化调度决策，并协调计算与跨加速器传输。我们将SliceScheduler实现为PyTorch后端，并使用生产轨迹回放进行评估。实验结果表明，与现有方法相比，SliceScheduler将token吞吐量提高了1.10--2.29倍，同时将SLA违规率保持在9%以内。SliceScheduler表明，算子级调度是提高多租户LLM服务GPU利用率的一种实用且有效的方法。

## Abstract
Container-granularity scheduling leaves abundant short-lived idle slices within containers unexploited. Reallocating containers is too heavyweight to utilize such fine-grained opportunities under SLA constraints, and operator-level scheduling requires reasoning about dependencies, memory safety, and cluster-wide execution dynamics in real time.   In this paper, we present SliceScheduler, a dynamic operator-level scheduling system for multi-tenant model serving. The key idea is to expose cluster-wide operator execution state and enable what-if reasoning over scheduling decisions. SliceScheduler consists of four key components. First, we introduce the Global Mapping Graph (GMG), a unified abstraction that captures operator dependencies, tensor shapes, resource mappings, and execution states, providing a real-time, cluster-wide view with explicit resource semantics. Second, we build a global simulator on top of GMG to predict operator-level execution and memory evolution under candidate placements. Third, we design an incremental, simulation-based scheduling module that selects placements to exploit fragmented idle slices while avoiding memory violations and preserving SLA. Finally, we develop an operator executor that materializes scheduling decisions on GPUs and coordinates computation and cross-accelerator transfers. We implement SliceScheduler as a PyTorch backend and evaluate it using production trace replay. Experimental results show that SliceScheduler improves token throughput by 1.10--2.29$\times$ compared to existing approaches, while maintaining SLA violations within 9\%. SliceScheduler demonstrates that operator-level scheduling is a practical and effective approach to improving GPU utilization for multi-tenant LLM serving.

## 2. 论文提出的方法论

SliceScheduler 由四个核心组件构成：**Global Mapping Graph (GMG)、全局模拟器、调度模块、算子执行器**。

### 2.1 Global Mapping Graph (GMG)

- 提供统一的集群级算子视图，包括：  
  - **Shape DAG**：每个节点为算子，标注张量形状、执行状态（`unscheduled`、`issued`、`done`）；  
  - 边表示数据依赖；  
  - 算子节点映射到加速器集合（GPU）。  
- **动态执行生命周期**：  
  - 应用先注册图模板（graph template），再实例化图实例；  
  - 模板保留符号形状信息，实例化后通过形状推断得到每个算子的具体形状；  
  - 算子随执行在 `unscheduled → issued → done` 状态间迁移。  
- **调度元数据**：  
  - 每个算子模板维护在线更新算子估计器（estimator）；  
  - 全局时间戳记录加速器的 issued/done 时间；  
  - 输出张量形状用于估计执行时间、HBM 占用与传输延迟；  
  - checkpoint 元数据标识中间结果是否持久保留在 HBM。

### 2.2 全局模拟器（Global Simulator）

- **估计器设计**：  
  - **传输估计器**：线性模型 \( t = \alpha \cdot size + c \)；  
  - **算子估计器**：针对批量矩阵乘法等，使用形状乘积项（如 \( bmnk, bmk, bkn, bmn \)）的线性组合；  
  - 估计器根据运行时反馈在线更新，随样本增加越来越准确。  
- **模拟器构建**：  
  - 从 GMG 快照重建每个加速器队列、当前执行算子、HBM 占用；  
  - 根据算子依赖与 ready time 判断当前执行算子。  
- **事件驱动模拟**：  
  - 维护统一模拟时间线，每次选择最早完成的事件推进；  
  - 算子完成后触发后续 ready 算子；调用估计器预测完成时间；  
  - 支持 what-if 仿真：克隆 GMG，应用候选放置，构建模拟器，评估完成时间与内存安全性。

### 2.3 调度模块（Scheduling Module）

- **两个 frontier**：  
  - `scheduled frontier`：已 issued/done 但还有 unscheduled 后继的算子；  
  - `unscheduled frontier`：所有前驱均已 issued/done 或缺失的未调度算子。  
- **增量仿真调度算法**：  
  1. 检查 issued 算子数量是否超预算；  
  2. 从 `unscheduled frontier` 选择最高优先级算子；  
  3. 按依赖链收集一个小 batch（限制规模）；  
  4. 对预定义候选加速器分区，并行构建克隆 GMG + 模拟器；  
  5. 丢弃会导致 OOM 的候选，选择平均完成时间最短的放置。  
- **优先级与 SLA**：优先收集高优先级算子，低优先级算子在高负载下可能不被收集，从而隐式保护在线 SLA；同时通过仿真评估跨卡传输对完成时间的影响，兼顾数据局部性与负载均衡。

### 2.4 算子执行器（Operator Executor）

- **每加速器算子队列**：  
  - 按数据依赖而非提交顺序执行；  
  - 算子记录输入 ready 状态，输入全部 ready 后才可执行；  
  - 每队列最多同时执行一个算子。  
- **跨加速器传输仲裁**：  
  - 将一个跨卡传输分解为 `Intent`、`Recv`、`Send` 三个算子；  
  - 采用 Recv-before-Send 顺序，避免目标端缓冲分配失败导致的浪费；  
  - 维护通信图，事件驱动地选择无冲突的传输集合并行激活，避免死锁。

## 3. 实验设计

### 3.1 数据集与场景

### 3.3 对比方法（Baselines）

- `Static-Online`：4 个在线实例固定占用 4 对 GPU；  
- `Subset-Share`：在固定 4 GPU 子集上启动低优先级离线实例，基于优先级感知分享；  
- `Dual-Share`：在两个 4 GPU 子集上各启动一个离线实例，基于干扰感知分享；  
- `Full-Share`：在全部 8 卡上启动一个离线实例，固定范围共享。

### 3.4 评价指标

- 请求吞吐（requests/s）、token 吞吐（tokens/s）；

  - SliceScheduler 全局模拟器平均约 **176.8 operators/ms**，比 SimAI 快约 4 个数量级。  
- **扩展性结论**：  
  - 理论分析在现有参数下可扩展至约 64 GPU，适合中小规模集群。
