## 摘要
联邦微调使大语言模型能够在边缘设备上自适应，而无需集中私有数据，但实际部署必须同时应对硬件不稳定性和对抗性更新损坏。受热约束的客户端可能会降频、减慢本地训练或延迟同步聚合，而拜占庭客户端和通信层对手可能破坏用于形成全局模型的更新。为了应对这些挑战，我们提出 Thermo-FL，一个热感知联邦 LoRA 微调框架，将设备温度作为本地适配器训练和稀疏更新传输的主动控制信号。在客户端，Thermo-FL 根据设备升温或降温调整活跃 LoRA 层比例和传输更新密度，从而在热应力下减少工作负载。在服务器端，Thermo-FL 引入 TERRA，一种针对动态稀疏 LoRA 更新的鲁棒聚合流水线，结合了范数过滤、掩码感知方向验证、自适应活跃坐标裁剪和掩码感知聚合。我们使用大规模仿真器和基于 Jetson 的物理测试平台对 Thermo-FL 进行评估。在仿真器中，Thermo-FL 提高了对抗性稀疏聚合下的鲁棒性，并在干净和攻击设置下取得最强的 BoolQ 准确率，同时在 GSM8K 上保持竞争力。在物理原型中，Thermo-FL 稳定了设备温度，通过位图稀疏编码降低了压缩上传大小，并在符号翻转/缩放和中间人扰动下保持了 GSM8K 效用。这些结果表明，安全的边缘 LLM 自适应应联合考虑硬件行为、工作负载调节、稀疏通信和聚合鲁棒性。

## Abstract
Federated fine-tuning enables large language models to adapt on edge devices without centralizing private data, but practical deployments must address hardware instability and adversarial update corruption together. Thermally constrained clients may throttle, slow local training, or delay synchronous aggregation, while Byzantine clients and communication-layer adversaries can corrupt the updates used to form the global model. To address these challenges, we present Thermo-FL, a thermal-aware federated LoRA fine-tuning framework that uses device temperature as an active control signal for local adapter training and sparse update transmission. On the client side, Thermo-FL adjusts the active LoRA-layer fraction and transmitted update density as devices heat or cool, reducing workload under thermal stress. On the server side, Thermo-FL introduces TERRA, a robust aggregation pipeline for dynamically sparse LoRA updates that combines norm filtering, mask-aware directional validation, adaptive active-coordinate clipping, and mask-aware aggregation. We evaluate Thermo-FL using both a large-scale emulator and a Jetson-based physical testbed. In the emulator, Thermo-FL improves robustness under adversarial sparse aggregation and achieves the strongest BoolQ accuracy across clean and attack settings while remaining competitive on GSM8K. In the physical prototype, Thermo-FL stabilizes device temperature, reduces compressed upload size through bitmap sparse encoding, and preserves GSM8K utility under sign-flip/scale and MITM perturbations. These results show that secure edge LLM adaptation should jointly consider hardware behavior, workload regulation, sparse communication, and aggregation robustness.

## 1. 核心问题与整体含义

- **研究背景**：联邦微调可以让大语言模型（LLM）在边缘设备上利用本地数据自适应，同时避免集中私有数据。但与云端训练不同，边缘设备受功率、冷却、DVFS 节流等硬件条件制约，训练中容易发热、降频、变慢，从而拖慢同步联邦聚合。
- **核心问题**：实际边缘联邦微调必须同时处理两类相互耦合的威胁：
  - **硬件侧**：热约束客户端可能节流、延迟本地训练，形成“热墙”，导致同步聚合被最慢客户端拖累；
  - **安全侧**：内部拜占庭客户端或通信路径上的中间人（MITM）对手可能篡改模型更新，破坏全局模型。
- **整体含义**：已有工作通常把热管理、稀疏通信、鲁棒聚合分开处理，而本文主张：安全边缘 LLM 适应必须把**硬件行为、动态工作负载调节、稀疏通信和聚合鲁棒性**作为联合设计需求，而不是相互独立的外部约束。

## 2. 方法论

### 2.1 整体架构与控制回路

Thermo-FL 采用“客户端热自适应 + 服务器端鲁棒聚合”的闭环设计：

- 每轮服务器广播全局 LoRA 参数 \(W^{(t)}\)；
- 客户端测量本地温度 \(T_k^{(t)}\)，据此确定：
  - 活跃 LoRA 层比例 \(\kappa_k^{(t)}\)：控制本地反向传播工作量；
  - 稀疏传输保持比 \(\rho_k^{(t)}\)：控制上传坐标密度；
- 客户端完成本地训练后，对更新差做 top-k 稀疏化、编码并上传；
- 服务器对收到的动态稀疏更新执行 TERRA 聚合，得到全局更新差 \(\bar{\Delta}^{(t)}\)，更新全局 LoRA 参数。

### 2.2 客户端：热自适应 LoRA 训练

- 温度到活跃层比例 \(\kappa_k^{(t)}\) 采用三档离散策略：
  - \(T_k^{(t)} < T_{\text{low}}\)：\(\kappa = 1.0\)，训练全部 LoRA 层；
  - \(T_{\text{low}} \le T_k^{(t)} \le T_{\text{high}}\)：\(\kappa = \kappa_{\text{mid}}\)；
  - \(T_k^{(t)} > T_{\text{high}}\)：\(\kappa = \kappa_{\text{crit}}\)，只训练最后极少部分 LoRA 层。
- 通过层冻结掩码 \(M_k^{(t)}\) 限制更新：
  \[
  W_{k,\text{local}}^{(t)} = W^{(t)} - \eta M_k^{(t)} \nabla F_k(W^{(t)})
  \]
- 客户端随后构造更新差：
  \[
  \Delta_k^{(t)} = W_{k,\text{local}}^{(t)} - W^{(t)}
  \]

### 2.3 客户端：温度驱动的稀疏传输

- 保持比 \(\rho_k^{(t)}\) 随温度升高而下降：
  \[
  \rho_k^{(t)} = \text{clip}(b - \omega T_k^{(t)}, \rho_{\min}, \rho_{\max}), \quad \omega > 0
  \]
- 每个客户端保留 \(s_k^{(t)} = \lfloor \rho_k^{(t)} d \rfloor\) 个幅度最大的 LoRA 更新坐标，形成二值支持掩码 \(m_k^{(t)}\)；
- 上传时采用位图编码 + zlib 无损压缩，降低通信载荷。

### 2.4 服务器端：TERRA 鲁棒聚合流水线

TERRA 表示为四阶段复合算子：

\[
F_{\text{TERRA}} = F_{\text{agg}} \circ F_{\text{clip}} \circ F_{\text{dir}} \circ F_{\text{norm}}
\]

- **阶段 1：鲁棒范数过滤 \(F_{\text{norm}}\)**
  - 计算每个稀疏更新的 L2 范数 \(s_k^{(t)}\)；
  - 基于本轮范数中位数 \(m_s^{(t)}\) 和 MAD 设定自适应阈值；
  - 只保留：
    \[
    s_k^{(t)} \le m_s^{(t)} + \lambda_{\text{norm}} \text{MAD}^{(t)}
    \]
  - 目标：剔除过大幅度的缩放、模型替换等攻击。

- **阶段 2：掩码感知方向验证 \(F_{\text{dir}}\)**
  - 服务器维护历史参考方向：
    \[
    r^{(t)} = \beta r^{(t-1)} + (1-\beta)\bar{\Delta}^{(t-1)}
    \]
  - 仅在客户端实际传输的坐标上计算余弦相似度：
    \[
    c_k^{(t)} = \frac{\langle \tilde{\Delta}_k^{(t)}, m_k^{(t)} \odot r^{(t)} \rangle}{\|\tilde{\Delta}_k^{(t)}\|_2 \|m_k^{(t)} \odot r^{(t)}\|_2 + \varepsilon}
    \]
  - 只保留 \(c_k^{(t)} \ge \tau_{\text{dir}}\) 的更新，用于抑制方向相反的符号翻转攻击。

- **阶段 3：自适应活跃坐标裁剪 \(F_{\text{clip}}\)**
  - 从通过前两阶段的活跃坐标集合 \(C^{(t)}\) 中取分位数阈值 \(q_t = \text{Quantile}_q(C^{(t)})\)；
  - 对每个活跃坐标进行裁剪：
    \[
    \hat{\Delta}_{k,j}^{(t)} = m_{k,j}^{(t)}\, \text{clip}(\tilde{\Delta}_{k,j}^{(t)}, -q_t, q_t)
    \]
  - 目标：限制单坐标极端值，但仍保留稀疏支持结构。

- **阶段 4：掩码感知聚合 \(F_{\text{agg}}\)**
  - 对每个坐标只归一化在真正上传该坐标的客户端集合上：
    \[
    \bar{\Delta}_j^{(t)} = \frac{\sum_{k\in S_{\text{dir}}^{(t)}} w_k m_{k,j}^{(t)} \hat{\Delta}_{k,j}^{(t)}}{\sum_{k\in S_{\text{dir}}^{(t)}} w_k m_{k,j}^{(t)} + \varepsilon}
    \]
  - 关键设计：缺失坐标被当作“未上传”，而不是显式零值，避免稀疏支持操纵造成的聚合偏差。

### 2.5 鲁棒性分析思路

论文从设计层面证明了 TERRA 各阶段对攻击影响的有界约束：

- 范数阶段可拒绝高能量缩放/模型替换更新；
- 方向验证可拒绝符号翻转更新；
- 裁剪阶段使保留更新坐标级影响有界；
- 掩码感知聚合使对抗客户端在每坐标上的贡献受裁剪阈值和活跃聚合权重的联合约束。
- 附录给出抽象 TERRA 算子下的非凸收敛界，但强调这不是无条件任意攻击下的严格收敛证明，而是说明“若管线保持足够对齐和有界二阶矩，则接近标准随机联邦优化行为”。
