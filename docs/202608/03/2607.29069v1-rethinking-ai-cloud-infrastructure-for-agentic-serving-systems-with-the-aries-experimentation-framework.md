## 摘要
自主代理将重复推理与持久上下文和隔离工具执行相结合，对传统的大语言模型服务提出了挑战。我们推出了Aries，一个全栈实验框架，它将任务语义与执行配置分开，利用关联的系统遥测技术重建跨组件的代理轨迹，并通过一致的接口跨异构沙箱子系统暴露有状态工具执行。我们使用Aries在开放代理工具和基准上进行了可复现的实验。我们用来自商业平台的生产踪迹补充这些实验，将底层系统研究建立在观察到的生产行为之上。我们的结果显示：(1) 以令牌为中心的指标遗漏了非推理瓶颈，(2) 保留额外上下文虽然能带来精度提升但收益递减，同时降低了服务容量，(3) 工具沙箱在长时间空闲和短暂资源突增之间交替，而当前基于快照的状态管理使得积极挂起成本高昂。一项补充的安全分析进一步强调减少沙箱攻击面的必要性。随后我们讨论了为代理原生服务系统设计的愿景，该系统围绕轨迹级指标、自适应上下文管理、弹性沙箱资源管理以及最小化攻击面的沙箱而构建。

## Abstract
Autonomous agents challenge conventional LLM serving by coupling repeated inference with persistent context and sandboxed tool execution. We present Aries, a full-stack experimentation framework that separates task semantics from execution configurations, reconstructs cross-component agent trajectories with correlated system telemetry, and exposes stateful tool execution through a consistent interface across heterogeneous sandbox substrates. We use Aries to conduct reproducible experiments on open agent harnesses and benchmarks. We complement these experiments with production traces from a commercial platform, grounding low-level systems research in observed production behavior. Our results show that (1) token-centric metrics miss non-inference bottlenecks, (2) retaining additional context yields diminishing accuracy benefits while reducing serving capacity, and (3) tool sandboxes alternate between long idle periods and short resource bursts, while current snapshot-based state management makes aggressive suspension costly. A complementary security analysis further highlights the need to reduce the sandbox attack surface. We then discuss the vision for agent-native serving systems designed around trajectory-level metrics, adaptive context management, elastic sandbox resource management, and sandboxes with minimized attack surface.

### 1. 论文的核心问题与整体含义

*   **研究背景**：大语言模型正从单次问答的“提示应答器”进化为能自主调用工具、管理状态的多步**自主智能体**。智能体服务不再只是模型推理，而是一条包含模型调用、工具执行、上下文保持和调度逻辑的**持久化轨迹**。
*   **核心问题**：现有的云 AI 基础设施和评测体系存在严重的**测量断层**：
    *   以令牌为中心的指标（TTFT, TPOT）**掩盖了非推理瓶颈**（如工具执行和调度逻辑的延迟）。
    *   任务评测只看最终结果，**无法关联底层系统行为**对任务进度和资源开销的影响。
    *   任务语义与执行配置耦合，导致**难以进行受控、可复现的系统性对比**。
*   **整体含义**：为支撑智能体服务，云基础设施需要从“单次请求-响应”范式转向以**任务轨迹为第一观察对象**的协同设计，在轨迹层面同时考虑精度、容量和资源效率。

### 2. 论文提出的方法论

*   **核心思想**：提出 **Aries** 全栈实验框架，将**任务语义**与**执行配置**彻底分离，以**智能体轨迹**为第一等公民，重建带系统遥测信息的跨组件执行记录，从而揭示系统行为与任务进度之间的因果关系。
*   **关键技术细节**：
    *   **分离规范**：将工作负载定义（任务规范）与所选框架、模型后端、沙箱等技术栈（执行规范）解耦，通过加载器和适配器绑定，实现跨配置的受控比较。
    *   **跨组件轨迹重建**：在模型调用和工具边界间传播轨迹标识符，基于通用事件模式记录因果和顺序元数据，将各组件指标关联到统一轨迹上，实现延迟和瓶颈的阶段级归因。
    *   **有状态工具执行标准化**：通过沙箱适配器抽象环境设置、调用、状态连续性、结果收集和遥测钩子，使工具执行成为轨迹中可观测、可移植的阶段，支持不同沙箱技术（如 MicroVM、容器等）的公平对比。

### 3. 实验设计

*   **数据集与场景**：
    *   **生产踪迹**：使用某匿名商业平台 8 小时工作日的生产踪迹，包含 10 个 LLM 服务实例的请求长度，以及 100 个智能体沙箱每分钟的 CPU 和内存采样。
    *   **受控实验**：使用公开基准和工具。工具包括 **OpenHands, Hermes Agent, OpenClaw**；任务基准包括 **SWE-Bench Pro, Terminal-Bench 2, DeepResearch Bench**。
    *   每个基准采样 20 个任务（保证 50% 成功率），每个任务重复 5 次。主要采用 **Qwen3.6-35B-A3B-FP8** 模型，由 **SGLang** 在单节点（96 核 + 1×NVIDIA H100 94GB）上本地服务。
*   **对比方法**：
    *   对比不同智能体框架（OpenHands/Hermes/OpenClaw）的延迟分解和资源特征。
    *   **上下文预算扫描**：在 64K 至 256K 令牌窗口间扫描，分析任务成功率、压紧次数和溢出次数的变化。
    *   对比不同 **keepalive 超时**（0s 到 300s）下的 AWS Lambda MicroVM 成本结构（实例费 + 快照抓取/恢复费）。
    *   对比常规会话与智能体轨迹的上下文长度及并发容量。

### 4. 资源与算力

*   **推理硬件**：受控实验明确使用了 **1 个 NVIDIA H100 GPU（94 GB HBM）**，搭配 96 核 CPU 节点。框架本身仅为推理服务，**不涉及模型训练**，因此无训练时长或大规模 GPU 集群的需求。
*   **生产环境**：未披露具体集群算力规模，仅给出了服务实例数和沙箱数的宏观统计。

### 5. 实验数量与充分性

*   **实验组数**：组数较多，涵盖了生产踪迹分析、多框架、多基准、多上下文窗口扫描、不同 keepalive 策略的成本对比，以及安全趋势分析。

*   **充分性与公平性**：
    *   **充分性**：实验设计从宏观生产数据到微观受控剖析，链路完整。上下文窗口扫描揭示了非单调的精度-容量权衡，成本分析揭示了快照开销与闲置浪费的矛盾，论证较为充分。
    *   **公平性**：通过 Aries 框架解耦任务与执行配置，做到了跨工具的公平对比；同一任务重复 5 次增强了统计稳健性。但每个基准仅采样 20 个任务，且仅测试了一个模型（Qwen），实验广度仍有提升空间。

### 6. 论文的主要结论与发现

*   **Token 指标无法反映真实瓶颈**：端到端延迟中，调度逻辑和工具执行占比可达 13%–48%，工具调用的长尾延迟尤其严重，单纯优化 GPU 令牌生成无法解决智能体服务的核心延迟问题。
*   **上下文存在“精度—容量”临界点**：扩大上下文窗口虽能减少溢出、提升任务成功率，但收益存在任务依赖性阈值；超过该阈值后，KV 缓存压力导致并发容量下降 **4.4 倍**，排队延迟 \( p_{95} \) 达 7.9 秒，精度不再提高甚至退化。
*   **工具沙箱呈空闲-突发的弹性矛盾**：沙箱 80% 以上时间 CPU 空闲，但工具调用时资源需求突增。当前基于快照的“缩容至零”方案导致成本飙升（快照 C/R 使总成本达到持久基准的 4.9 倍），用户面临“为闲置付费”还是“为快照付费”的两难，理想系统可降低 3 倍成本。
*   **安全攻击面急需压缩**：AI 发现的 Linux 内核 CVE 数量在近期激增 3.5 倍，智能体自主利用漏洞能力快速增强，现有隔离机制不足以应对逐步增强的模型攻击能力，沙箱需最小化攻击面并采用纵深防御。

### 7. 优点

*   **轨迹级测量思想**：首次明确将“智能体轨迹”作为系统评测的第一等公民，填补了任务语义与系统执行之间的测量断层。
*   **框架设计解耦**：Aries 通过分离任务/执行规范、统一工具接口和跨组件遥测聚合，实现了对异构栈的**公平、可复现**系统研究。
*   **生产数据与受控实验结合**：既用生产踪迹验证宏观模式，又用公开工具和基准进行精细剖析，使结论同时具备真实性和可重现性。
*   **问题导向的系统视野**：不是单点优化，而是揭示了从指标、内存管理、资源弹性到安全的**全栈不适应**，并给出了层次化未来方向。

### 8. 不足与局限

*   **实验规模与模型单一性**：每个基准仅用 20 个任务，且仅测试了 Qwen3.6-35B 一种模型，结论的普适性待更多模型和更大规模任务集验证。
*   **生产成本与快照分析简化**：成本分析依赖 AWS Lambda 定价模型的重放，未考虑实际生产中的快照优化、预热池等可能缓解开销的技术，结论偏于理想“快照 C/R 原语”假设。
*   **安全分析间接性**：安全结论主要基于 CVE 趋势统计和间接代理攻击能力的推论，缺少在真实云隔离场景下对沙箱攻击面进行主动渗透测试的数据。
*   **部分概念化**：第 5 节提出的“轨迹捕捉指标”“自适应上下文控制平面”等未来方向仍停留在设计层面，缺乏原型实现或模拟验证其可行性。
*   **仅关注单节点服务**：并发容量和资源分析均基于单 H100 节点，未涉及跨节点、推理集群下的调度和状态迁移复杂性。
