## 摘要
大型语言模型（LLM）工作负载推动了多分区GPU的发展，将其作为扩展计算和内存容量的途径，但其非统一内存访问特性与跨分区通信可能加剧竞争并降低局部性，导致内核延迟欠佳。为此，我们分析了性能关键的LLM内核实现，涵盖权重投影、专家混合以及当前最先进推理引擎的注意力变体，以表征多分区GPU中的数据访问模式。首先，我们引入内存跟踪分析方法来获取工作组级别的数据访问与共享行为，随后利用周期级模拟器评估局部性对延迟的影响。借助这些工具，我们将LLM内核操作数分为三种工作组间共享模式（全局、部分或私有），并表明所需的优化策略因类别而异，从简单的逐工作组固定到子组感知协同调度。我们的发现凸显了在多分区GPU中对放置感知内核编程以及更智能的架构支持的需求，以优化工作和数据局部性。

## Abstract
Large language model (LLM) workloads motivate multi-partition GPUs as a path to scaling compute and memory capacity, but their non-uniform memory access characteristics and inter-partition communication can amplify contention and degrade locality, leading to suboptimal kernel latency. To address this, we analyze performance-critical LLM kernel implementations spanning weight projection, mixture-of-experts, and attention variants of state-of-the-art serving engines to present a characterization of data access patterns in multi-partition GPUs. First, we introduce memory trace analysis methodology to derive workgroup-level data access and sharing behavior, then evaluate the locality implications on latency using a cycle-level simulator. Using these tools, we categorize LLM kernel operands into three inter-workgroup sharing patterns (global, partial, or private) and show that the required optimization strategies differ across categories, from simple per-workgroup pinning to subgroup-aware co-scheduling. Our findings highlight the need for placement-aware kernel programming and smarter architectural support for work and data locality in multi-partition GPUs.

### 1. 论文的核心问题与整体含义
- **研究动机**：大语言模型（LLM）推理对计算和内存容量的需求急剧增长，促使 GPU 走向多分区（multi-partition）架构（如 AMD MI300X、NVIDIA B200）。这些芯片内部多个计算与内存域通过高速互联组成 NUMA（非统一内存访问）系统，跨分区访存会带来更高延迟和带宽争用。
- **核心问题**：当前 GPU 虚拟内存管理对程序员隐藏了物理分区拓扑，使得原本在单芯片上无问题的内核访问模式（如共享权重、激活、KV 缓存）无声无息地变成跨分区流量，导致性能下降。论文旨在系统地量化**现代 LLM 推理内核在多分区 GPU 中的 NUMA 成本**，并揭示内核优化和架构支持的方向。

### 2. 论文提出的方法论
- **整体思路**：通过真实内核执行的内存 trace 分析工作组（workgroup，即 thread block）级别的数据访问与共享行为，再利用周期级模拟器量化这些行为在多分区 NUMA 下的延迟影响。
- **关键技术细节**：
  - **内存 trace 采集**：使用 AMD Omniprobe 工具在 AMD Instinct MI300X 上收集内核执行的虚拟地址访问 trace，记录操作类型（读/写）、工作组坐标、通道地址等。
  - **trace 分析流水线**：
    - 过滤全局内存地址，提取单个内核分派的工作组 trace。
    - 检测**通道内步长**，识别连续访问模式。
    - 对每个 trace 条目（多通道地址列表）进行**多步长分段**，将地址序列按恒定步长切分为段。
    - 将步长一致的地址段合并为**字节区间**（chunk），形成每工作组、每操作类型的压缩内存足迹。
    - 进行**工作组间重用分析**：计算不同工作组读写区间集的字节级重叠量，从而判断操作数在工作组间的共享程度（0 重叠 → 私有，100%重叠 → 全局共享，部分重叠 → 部分共享）。
  - **分区局部性（Partition Locality）度量**：定义并推导局部性与数据放置、工作组调度策略的关系公式，分离出不变的内核行为与可控的策略因素。
  - **周期级模拟**：扩展 MGPUSIM 模拟器，加入 4 分区跨芯片互联延迟模型（32-cycle 单程，768 GB/s 带宽），并采用默认的 4 KB 轮询物理页交错和工作组轮询调度，量化跨分区通信造成的性能损失。

- **测试的内核与 benchmark**：
  - **权重投影**：Llama-2-7B 上投影（11008×4096），batch size 4，使用 TritonBLAS 后端。
  - **多头注意力解码（MHA decode）**：batch 4，KV 缓存长度 1024。
  - **分组查询注意力解码（GQA decode）**：Llama-3-8B（H_Q=32，H_KV=8，G=4），长度 1024。
  - **多头潜在注意力解码（MLA decode）**：DeepSeek-V2 风格的 MLA 维度，长度 1024，batch 4，包含双阶段（分块计算+对数求和指数归约）。

### 6. 论文的主要结论与发现
- **三种工作组间共享模式**：
  - **私有（WG‑Private）**：每个工作组访问不重叠的数据区域（如权重投影的输出 tile、MHA decode 的单个 Q/K/V 切片）。
  - **全局共享（Global Shared）**：所有工作组访问整个操作数（如投影中的激活向量）。
  - **部分共享（Partial Sharing）**：工作组分成子组，子组内共享一个切片（如 GQA 中同组查询头共享 K/V，MoE 中同专家工作组共享激活）。
- **NUMA 敏感性与优化空间极不均衡**：消除跨分区开销后，各内核可获得的理论加速比从 **1.09×（FA prefill）到 1.79×（GQA decode）** 不等，且不同类别所需优化策略迥异：
  - 私有操作数只需简单地将工作组数据页绑定到其执行分区（per-WG pinning）。
  - 部分共享操作数要求**子组感知的工作组协同调度**和对应的数据本地化。
  - 全局共享操作数要么接受 1/N 的局部性，要么接受 N 路内存复制。
- **架构与编程启示**：当前固定的 4 KB 页交错和轮询工作组调度严重损害局部性；需要放置感知的内核编程（如工作组映射顺序）以及更灵活的页粒度控制、工作组调度粒度支持（如 CPX 模式）。

### 7. 优点
- **方法论精细**：利用真实硬件 trace 和模拟器结合，分析粒度为工作组级，精确刻画共享量，并提出了通用的分区局部性公式。
- **覆盖面广**：涵盖了推理中计算密集（投影）、内存密集（解码注意力）和混合型算子（MoE），并触及 MLA 这种最新注意力变体，具有很强的代表性。
- **结论具有强指导性**：不仅报告数字，还按共享模式给出简明的优化策略分类，对内核开发者和架构设计者都提供了明确的参考。
- **实验设计公平**：通过理想情况对比，能干净地分离出 NUMA 通信延迟本身的影响，排除了其他实现因素的干扰。

### 8. 不足与局限
- **仅分析了优化上限，未实现任何优化方案**：论文仅展示了消除跨分区开销的理想加速，没有具体实现 WG pinning、协同调度等策略的实际性能，缺乏对可行性和其他开销（如内存复制、运行时迁移）的评估。
- **未与现有 NUMA 缓解方法对比**：尽管讨论了 CLAP、LADM、MGvm 等工作，但实验中没有将它们作为 baseline 进行比较，难以判断当前方法离实用还有多远。
- **模拟器与配置的简化**：4 KB 页交错和轮询工作组调度虽为默认，但实际系统可能采用更复杂的交错粒度或调度；模拟器参数如互连延迟来自先前的 MCM-GPU 工作，未必完全匹配 MI300X 真实特性。
- **模型与配置的局限性**：仅测试了特定模型（Llama-2, Llama-3, DeepSeek）和少数 batch size、序列长度，未涵盖更大的模型（如数百亿参数级的完整推理）或更极端的上下文长度，结论的普适性有待扩展。
- **缺少对动态场景的考量**：MoE 的路由动态性在表征中通过两种极端情况覆盖，但真实场景中路由模式复杂且随时间变化，论文未探讨动态重放置的开销。
