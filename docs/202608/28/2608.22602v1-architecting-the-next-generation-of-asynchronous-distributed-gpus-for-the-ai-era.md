## 摘要
机器学习工作负载的快速演进已从根本上改变了 GPU 硬件，推动架构朝着多芯片模块（Multi-Chip Module, MCM）拓扑、异步执行原语以及持久化的多阶段 kernel 行为发展。尽管如此，周期级仿真基础设施的发展却相对滞后，缺乏同时建模现代 GPU 物理非均匀性与最先进 AI 工作负载巨大规模的原生能力。为弥补这一空白，我们提出了一种周期级仿真框架，可精确建模包括 Ampere、Hopper 和 Blackwell 在内的现代 GPU 代际架构。该模拟器经过与真实硅芯片的严格验证，在 H100 GPU 上达到了 99% 的 Pearson 相关系数和 13.4% 的平均绝对周期误差。基于该基础设施，我们开展架构案例研究，以评估新兴设计方向，包括 chiplet 拓扑扩展、SRAM 容量与带宽提升，以及 GPU 间预取策略。

## Abstract
The rapid evolution of machine learning workloads has fundamentally transformed GPU hardware, driving architectures toward Multi-Chip Module (MCM) topologies, asynchronous execution primitives, and persistent, multi-phase kernel behaviors. Despite these shifts, cycle-level simulation infrastructure has lagged behind, lacking the native capability to model the physical non-uniformity of modern GPUs alongside the massive scale of state-of-the-art AI workloads. To bridge this gap, we present a cycle-level simulation framework designed to accurately model modern GPU generations, including Ampere, Hopper, and Blackwell. Rigorously validated against physical silicon, the simulator achieves a 99% Pearson correlation coefficient and a 13.4% mean absolute cycle error on the H100 GPU. Utilizing this infrastructure, we conduct architectural case studies to evaluate emerging design trajectories, including chiplet topology scaling, expanded SRAM capacity and bandwidth, and inter-GPU prefetching strategies.

# 2. 方法论：核心思想、关键技术细节

- **核心思想**
  - 在 Accel-Sim 1.x 的基础上大幅扩展，使其能够模拟现代 NVIDIA GPU 的真实执行行为，而不是仅做功能级或粗粒度建模。
  - 重点不是简单“提精度”，而是补齐 **现代 AI kernel 的结构性缺失建模**，例如：
    - 异步等待与 spinloop；
    - TMA 驱动的数据搬运；
    - warpgroup / cluster 级协作；
    - chiplet / uGPU 级别的内存非均匀性；
    - 多 GPU 远程内存和 NVLink 互连。

- **关键技术模块**
  - **异步执行建模**
    - 支持 Hopper / Blackwell 的 TMA、WGMMA、UTCMMA、mbarrier、warpgroup barrier 等。
    - 不再把 mbarrier spinloop 当作静态指令序列简单回放，而是**动态建模等待分支**，根据同步条件决定是否进入轮询/睡眠循环。
  - **Tracer 重构**
    - 基于 **TMA-enabled NVBit v1.8**。
    - 为支持 Tensor Descriptors、同步原语，增加了**动态寄存器值跟踪**。
    - 使用 **spinloop detection**：kernel 执行两遍，通过比较指令计数识别非确定性轮询段，并抽取 canonical loop。
    - 引入 **zstd 压缩 trace** 与 **page-based trace loading**，把持久 kernel 的内存占用从可能的数百 GB 降到约 4 GB 量级。
  - **多 GPU / 分布式建模**
    - 扩展 tracer 以支持 **NVLink-aware 多上下文 tracing**。
    - 通过 CUDA driver API 构建**每 GPU 虚拟地址映射**，区分 local / remote memory request。
    - 远程访问通过 **RDMA + interconnect model**（基于 BookSim）模拟，支持 ring、switch-based cluster、all-to-all 等拓扑。
    - 同时记录 CPU-GPU / GPU-GPU 的 kernel 依赖，构建 DAG。
  - **内存子系统建模**
    - 将单 GPU 内部逻辑划分为 **uGPU**，模拟 chiplet-like 的 L2/HBM 物理非均匀性。
    - 通过微基准反推出：
      - **LRC（L2 Request Coalescer）**是 per-GPC 结构；
      - 同 GPC 内可实现最多 **4:1 合并**；
      - 采用**local write-through + remote write-back** 的混合写策略；
      - 远程访问需经过本地 tag check，再跨 interconnect 访问远端 L2/HBM。
  - **GPUVision profiling 工具**
    - 不是模拟器，而是基于 **CUPTI** 的真实硬件 profiling 工具。
    - 能输出**cycle-level time series**，而不是 Nsight Compute 那种 kernel 级聚合值。
    - 用于与仿真结果做细粒度对齐和验证。

- **方法流程（文字版）**
  1. 用 NVBit/CUPTI 在真实 GPU 上采集 kernel 级和周期级行为；
  2. 对异步同步、TMA、warpgroup、multi-GPU 事件做专门 tracing；
  3. 在仿真器中按硬件机制动态重放，而非简单静态回放；
  4. 对 local/remote memory、L2 分区、NVLink 互连进行精细建模；
  5. 通过 H100/B200 实硅数据验证；
  6. 基于可信模型开展架构案例研究。

# 6. 主要结论与发现

- **仿真器可信度高**
  - Accel-Sim 2.0 在 H100 上达到约 **0.99 Pearson correlation**，**13.5% MAPE**；
  - 在 B200 上也有较高一致性，整体验证结果优于旧版本。
- **异步协调开销通常不是主瓶颈**
  - 在 TMA 驱动的 GEMM 中，mbarrier polling 的额外检查大多能被 warp scheduler 的空闲 issue slot 吸收；
  - 只有 polling 间隔过大时才会造成性能退化。
- **chiplet / 物理非均匀性会带来真实代价**
  - 对 graph analytics、CNN 等依赖空间局部性的任务，L2 复制导致**有效缓存容量下降**，引发更多 miss 和性能损失。
  - 但对 LLM 的某些阶段而言，这种影响较弱：
    - **prefill** 计算密集，能吸收 inter-chiplet latency；
    - **decode** 局部性本来就弱，对容量碎片化不敏感。
- **分布式预取有收益，但会受资源约束**
  - UVA + remote prefetch 能提升 EmbeddingBag 的性能和 NVLink 利用率；
  - 但 prefetch 过深会占用寄存器等片上资源，降低 occupancy，导致收益停滞。
- **静态资源分配会引入尾延迟**
  - 在 NCCL + GEMM 并发时，NCCL 占据一部分 SM，GEMM 静态切片分配会造成“尾部堆积”，形成明显的 tail effect。

# 7. 优点

- **对现代 GPU 的建模非常贴近现实**
  - 补上了 TMA、mbarrier、warpgroup、2-CTA、threadblock cluster 等关键机制。
- **真实硬件验证较充分**
  - 不只是模拟结果好看，还用 GPUVision 对真实 silicon 做了周期级对齐。
- **同时覆盖单芯片、多芯片、多 GPU**
  - 从 intra-SM 到 inter-GPU，层次完整。
- **方法上重视“动态时序”**
  - 不是只看总量统计，而是分析轮询、等待、尾延迟、访问时序等。
- **案例研究具有架构启发性**
  - 清晰回答了“带宽、容量、同步、预取到底谁更关键”的问题。
- **工具链实用性较强**
  - trace 压缩、分页加载、PyTorch hook、NVLink-aware tracing 等都面向真实研究可用性。

# 8. 不足与局限

- **生态偏 NVIDIA**
  - 主要围绕 Hopper / Blackwell / NVIDIA 软件栈展开，对 AMD、Intel 或自研加速器的适用性有限。
- **实验虽广，但仍偏 AI/HPC 主流场景**
  - 对更异构、更低层、更小众的 workload 覆盖不多。
- **部分结论依赖微基准推断**
  - 例如 L2 复制策略、local/remote 行为、写回策略等，虽有实验支撑，但仍受硬件黑盒影响。
- **对 LLM 的 tracing 采用“单 block 外推”**
  - 虽然作者验证了误差较小，但这仍是假设 transformer block 重复性足够强；对非规则模型可能不稳。
- **部分硬件计数器不稳定**
  - 论文自己提到某些 Nsight Compute counter 在新架构上不可靠，因此用替代指标推断，存在测量偏差风险。
- **存在少量工具链限制**
  - Blackwell 上 NVBit 的罕见 bug 导致少量 kernel 被剔除；
  - 说明这套基础设施仍受 instrumentation 生态约束。
- **案例研究包含假想设置**
  - 如“无穷带宽”“理想预取”“monolithic L2”并非现实系统，只能用于分析瓶颈上界与机制，不代表可直接落地。
