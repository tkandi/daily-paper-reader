## 摘要
现代深度学习工作负载越来越多地由异构计算图构成，这些图将计算密集型算子与内存密集型子图结合在一起。现有的深度学习编译器通常分别优化这些算子类别，形成了严格的融合边界，限制了跨算子优化和片上数据重用。我们观察到，下游内存密集型操作可以与计算密集型算子并发执行，从而使其执行隐藏在计算之后；然而，自动利用这一机会带来了新的编译挑战。本文提出ComFuse，一个自动化的GPU编译系统，采用新颖的算子融合策略，为包含计算密集型算子和依赖丰富的内存密集型逐元素归约子图的复杂图结构生成高性能内核。ComFuse进一步支持连续矩阵乘法（B2BGEMM）模式的融合，将其适用性扩展到更复杂的计算-内存交互模式。此外，它自动将高级张量子程序降低为优化的融合内核，减少对手工内核工程的需求。实验结果表明，ComFuse生成的融合内核在post-norm工作负载和各种复杂计算场景中均优于TorchInductor生成的内核，同时支持更灵活的融合模式。

## Abstract
Modern deep learning workloads increasingly comprise heterogeneous computation graphs that combine compute-intensive operators with memory-intensive subgraphs. Existing deep learning compilers typically optimize these operator classes separately, creating rigid fusion boundaries that limit cross-operator optimization and on-chip data reuse. We observe that downstream memory-intensive operations can execute concurrently with compute-intensive operators, allowing their execution to be hidden behind computation; however, automatically exploiting this opportunity poses new compilation challenges.   In this paper, we present ComFuse, an automated GPU compilation system that employs a novel operator fusion strategy to generate high-performance kernels for complex graph structures comprising compute-intensive operators and dependency-rich, memory-intensive elementwise-reduction subgraphs. ComFuse further supports the fusion of back-to-back GEMM (B2BGEMM) patterns, extending its applicability to more complex compute-memory interaction patterns. Additionally, it automatically lowers high-level tensor subprograms into optimized fused kernels, reducing the need for manual kernel engineering. Experimental results show that the fused kernels generated by ComFuse outperform those produced by TorchInductor across post-norm workloads and various complex computation scenarios, while supporting more flexible fusion patterns.

## 1. 论文的核心问题与整体含义

现代深度学习模型（如大语言模型、推荐系统）的计算图通常由**计算密集型算子**（如矩阵乘法 GEMM）与**内存密集型子图**（如逐元素运算、归约、归一化、激活函数）混合组成。  
现有编译器（如 XLA、TensorRT、TVM）倾向于将这两类算子**分开优化**，从而在计算密集型输出与下游内存密集型输入之间形成一条**刚性边界**：中间张量必须被写回全局内存（GMEM），再由后续算子重新加载。这一做法导致：

- **片上数据重用不足**：短暂存在于寄存器/共享内存中的中间结果被强制交换到片外，浪费带宽。
- **延迟隐藏缺失**：两类算子使用不同的硬件单元（Tensor Core vs. CUDA Core），原本可并发执行，但独立调度无法重叠。

论文的核心含义是：**打破计算‑内存之间的融合壁垒，让内存密集型子图与计算密集型内核在片上并发、流式执行，从而显著减少数据搬运并掩盖延迟。** 为此提出一个自动编译系统 ComFuse，能够在支持线程块簇（Thread Block Cluster）的新一代 GPU 上，对复杂的逐元素‑归约子图与 GEMM（甚至连续 GEMM）进行联合融合，生成高性能融合内核。

## 2. 方法论

### 2.1 Stage‑Stream 执行模型

针对“一个 GEMM + 一个包含多层归约的内存密集型子图”的场景，ComFuse 设计了**Stage‑Stream 执行模型**。其核心洞察是：  
当中间结果按二维瓦片（tile）划分时，大多数归约只沿一个逻辑维度进行，因此同步边界实际上被限制在**共享同一非归约索引的一组瓦片**内部，而不需要整个张量的全局材料化。

- **分阶段 DAG**  
  以归约操作作为阶段边界，将整个内存密集型子图切分为多个顺序执行的**有向无环图（DAG）**。每个 DAG 是一个“阶段”，阶段内执行局部逐元素运算和部分归约；阶段之间通过归约结果和旁路中间数据链接。

- **阶段内计算**  
  每个 DAG 分两个阶段执行：  
  **① 细粒度计算（compute phase）**：数据以碎片（Fragment，向量化指令处理的最大元素组）粒度在逐元素节点间流式传播；遇到归约节点时，先进行线程本地聚合。  
  **② 瓦片级归约（reduce phase）**：执行三级归约：
  - 线程束内归约（warp‑level shuffle）
  - 线程束组间归约（shared memory）
  - **跨 CTA 归约**：利用 **Thread Block Clusters** 的分布式共享内存（DSMEM） 进行对等全对全广播（少量 CTA）或主从聚合（大量 CTA），并借助 **TMA** 执行块数据搬移以降低指令开销。

- **阶段间链接**  
  当前阶段的终端归约节点在完成聚合后，将归约结果广播为与瓦片维度匹配的张量，并注入到下一阶段的入口占位节点，从而驱动后续 DAG 的计算。多个归约节点复用同一共享内存缓冲区，将片内存储复杂度由 O(L) 降为 O(1)。

- **流水线调度**  
  遵循 CUTLASS 的 MainLoop/Epilogue 分离思想，ComFuse 采用 **Ping‑Pong 流水线**：一个协作线程阵列（CTA）在处理当前瓦片的 GEMM 计算（MainLoop）的同时，对前一瓦片的 Epilogue 进行后处理，从而将内存密集型子图的计算延迟隐藏在 GEMM 之后。

### 2.2 B2BGEMM 融合

当存在两个连续的矩阵乘法（中间夹有内存密集型子图），即“背靠背 GEMM”（B2BGEMM）时，ComFuse 通过**集群协作调度**实现进一步融合。

- **数据流调度**：  
  第一层 GEMM 将中间结果瓦片 \(S_{\text{tile}}\) 保持在 CTA 的寄存器中，不经全局内存。同一线程块簇内沿收缩维度对齐的多个 CTA 共同持有中间矩阵的一段连续区域。  
  第二层 GEMM 将这些 CTA 的寄存器中间结果视为局部部分和，与各自预取的权重瓦片相乘得到部分累加结果，最后在写回全局内存时完成最终归约。从而彻底消除中间矩阵的全局内存材料化与重加载。

- **生产者‑消费者 warp 组**：  
  引擎复用同一套多级圆形共享内存缓冲，交替加载第一层所需的 \(X_{\text{tile}}, W_{1,\text{tile}}\) 和第二层所需的 \(W_{2,\text{tile}}\)，避免线性增长存储开销。消费者 warp 组被划分为四阶段流水线：`ML1 → Epi1 → ML2 → Epi2`，不同 warp 组错位执行以重叠多级计算。

### 2.3 自动编译系统实现

ComFuse 基于 CUTLASS 构建，引入新的 EVT 节点 `StreamReduction` 以表达流式归约语义。编译流程分为三步：  
1. **前端映射**：从 Python 子程序捕获符号图，提取计算密集型（MatMul）与内存密集型子图，转换为统一的中间表示 **Fusion Spec IR**（拓扑有序的节点列表）。  
2. **归约子图拆分**：递归地将 Fusion Spec IR 按归约节点拆分成嵌套的子 DAG，自然表达 LayerNorm、Softmax 等模式。  
3. **后端映射**：将 IR 结构性展开为 CUTLASS 的模板参数和运行时参数，生成可编译的 C++ 模板代码。整个过程是**数据驱动**的，避免硬编码模式匹配，天然支持新算子扩展。

## 6. 论文的主要结论与发现

1. **跨边界融合有效**：ComFuse 通过 Stage‑Stream 模型和 B2BGEMM 调度，成功将内存密集型 Epilogue 延迟隐藏在计算密集型 MatMul 之后，显著降低中间结果全局内存搬运。

5. **自动化与可扩展性**：不依赖固定图模式匹配，通过 IR 翻译生成内核，对新算子组合支持好，减少手工内核编写成本。

## 7. 优点

- **洞察深刻**：明确识别出计算‑内存两类算子的硬件互补性以及归约的局部同步特性，据此提出针对性设计。
- **技术新颖**：利用现代 GPU 的 Thread Block Cluster、DSMEM、TMA 等特性，实现了跨 CTA 的细粒度数据交换与协作，这是现有工作中较少使用的。
- **方案完备**：不仅解决单 GEMM 融合，还扩展到连续 GEMM（B2BGEMM），构成一套较完整的融合方案。

- **实验扎实**：覆盖典型负载，与两种主流基线对比，并分离残差时间分析，结论有说服力。

## 8. 不足与局限

- **硬件约束**：依赖较新的 GPU 架构（支持集群、DSMEM、TMA），对旧平台不兼容。
