## 摘要
现代大语言模型基础设施越来越多地将张量不仅作为计算数据，而且作为跨分布式组件共享的持久状态来管理。现有系统通过将特定任务的机制与执行引擎、网络或存储后端深度集成，来优化单个张量管理任务，例如模型权重加载、KV缓存管理和检查点同步。然而，这种专业化造成了孤立的竖井，阻碍了在不断演变的大语言模型工作负载中复用和组合张量管理策略。在本文中，我们将张量生命周期管理确定为大语言模型基础设施中缺失的抽象层，并提出了张量即服务（TaaS），将张量状态管理与计算逻辑解耦。我们设计并构建了TensorCast，一个分布式张量管理层，提供一等张量抽象、可编程生命周期原语，以及将张量管理策略与执行机制分离的运行时。这使得开发者可以使用TensorCast API编写张量管理程序，同时透明地利用分布式执行和数据移动。我们将TensorCast与vLLM和SGLang集成，并在多种张量生命周期工作负载下进行评估，包括模型权重具现化、权重同步、KV缓存管理和可编程请求路由。结果显示，TensorCast在与专用张量管理系统相比时实现了有竞争力的性能，同时支持新的跨组件优化策略。使用TensorCast实现的可编程策略在高并发多轮代理工作负载下，将中位首令牌时间（TTFT）提高了多达93.2%。

## Abstract
Modern LLM infrastructure increasingly manages tensors not only as computation data, but also as persistent states shared across distributed components. Existing systems optimize individual tensor management tasks, such as model weight loading, KV cache management, and checkpoint synchronization, by deeply integrating task-specific mechanisms with execution engines, networks, or storage backends. However, this specialization creates isolated silos that hinder the reuse and composition of tensor management strategies across evolving LLM workloads. In this paper, we identify tensor lifecycle management as a missing abstraction layer in LLM infrastructure and propose Tensor-as-a-Service (TaaS), which decouples tensor state management from computation logic. We design and build TensorCast, a distributed tensor management layer that provides first-class tensor abstractions, programmable lifecycle primitives, and a runtime that separates tensor management policies from execution mechanisms. This enables developers to write tensor management programs using TensorCast APIs while transparently leveraging distributed execution and data movement. We integrate TensorCast with vLLM and SGLang and evaluate it across diverse tensor lifecycle workloads, including model weight materialization, weight synchronization, KV cache management, and programmable request routing. Our results show that TensorCast achieves competitive performance with specialized tensor management systems while enabling new cross-component optimization policies. A programmable policy implemented with TensorCast improves median TTFT by up to 93.2% under highly concurrent multi-turn agent workloads.

### 2. 论文提出的方法论

论文的核心贡献是设计并实现了**TensorCast**，一个分布式张量管理层。其关键技术细节如下：

*   **核心思想：TaaS与策略-机制分离**
    *   **TaaS层**：将张量视为一等公民的、可编程的系统资源进行管理。它向上提供统一的API，向下屏蔽分布式的数据存储、移动和一致性细节。
    *   **策略与机制分离**：开发者通过Python API编写**张量管理策略**（Policy），而TensorCast运行时则负责在集群中透明地执行这些策略所对应的**机制**（Mechanism），无需修改底层执行引擎。

*   **编程抽象与API**
    TensorCast提供了四个核心编程抽象，映射了张量的生命周期原语：
    *   **`Artifact`（构件）**：张量状态的一等表示，将张量的身份、所有权和生命周期与其物理存储解耦。它像是一个逻辑句柄，指向分布式池中的张量。分为“系统所有”和“调用者租用”两种所有权模型。
    *   **`Operation`（操作）**：对张量生命周期进行操控的有限但可扩展的操作集合。分为两类：
        *   **Worker操作**：在TensorCast内部执行，如 `prefetch()`（在worker间传输副本）、`pin()`（固定副本位置）。
        *   **Instance操作**：与计算引擎交互，通过**实例适配器**（Instance Adaptor）执行，如 `publish()`（将引擎内KV缓存刷入TensorCast）、`hydrate()`（将TensorCast中KV缓存加载到引擎）、`transform_into()`（转换并填充模型权重到特定rank的显存）。
    *   **`Plan`（计划）**：用于组合多个分布式操作的抽象，构成一个有向无环图（DAG）。调用者通过 `plan.run()` 执行，运行时统一处理依赖调度、追踪、超时和幂等重试，但不提供事务性的ACID回滚。
    *   **`Signal`（信号）**：暴露运行时状态（如worker内存压力、实例负载），供开发者实现自适应管理策略。

*   **系统架构细节**
    *   **组件**：集群由**Worker节点**（负责存储和张量操作执行）、**Instance节点**（运行LLM推理/训练引擎）和**全局存储（GS）**（轻量级控制面元数据服务，不在数据路径上）组成。Worker通过角色（基本、网关、分片主节点）组合功能。
    *   **统一张量池**：
        *   **低基数张量**（如模型权重）：不可变、持久、访问不频繁，其副本位置通过GS集中管理，利用CUDA IPC或RDMA进行高效传输。
        *   **高基数张量**（如KV缓存）：动态、碎片化、频繁创建和复用。采用**分片（Sharding）和基于租约（Lease）的分布式所有权**机制，分片主节点通过HRW哈希算法确定，避免了GS成为元数据查询瓶颈。
    *   **分布式计划执行**：调用者向网关Worker提交计划，由其解析步骤依赖并分发到对应Worker或Instance上的本地计划执行器执行。数据面通过P2P RDMA或高性能TCP栈（mTCP）直接传输，绕过GS。
