## 摘要
大语言模型 (LLM) 推理日益依赖多 GPU 执行，然而现有的推理并行化策略需要逐层的 rank 间同步，使得端到端性能对工作负载不平衡非常敏感。我们提出了 DWDP（分布式权重数据并行），这是一种推理并行化策略，它在保持数据并行执行的同时，将 MoE 权重卸载到对等 GPU 上，并根据需要获取缺失的专家。通过消除集合式的 rank 间同步，DWDP 允许每个 GPU 独立运行。我们通过针对切分权重管理和异步远程权重预取的两项优化，进一步解决了该设计的实际开销。在 TensorRT-LLM 中实现并在 GB200 NVL72 上使用 DeepSeek-R1 进行评估，在 8K 输入序列长度和 1K 输出序列长度下，在 20-100 TPS/用户的服务范围内，DWDP 在相当的 TPS/用户水平下将端到端输出 TPS/GPU 提升了 8.8%。

## Abstract
Large language model (LLM) inference increasingly depends on multi-GPU execution, yet existing inference parallelization strategies require layer-wise inter-rank synchronization, making end-to-end performance sensitive to workload imbalance. We present DWDP (Distributed Weight Data Parallelism), an inference parallelization strategy that preserves data-parallel execution while offloading MoE weights across peer GPUs and fetching missing experts on demand. By removing collective inter-rank synchronization, DWDP allows each GPU to progress independently. We further address the practical overheads of this design with two optimizations for split-weight management and asynchronous remote-weight prefetch. Implemented in TensorRT-LLM and evaluated with DeepSeek-R1 on GB200 NVL72, DWDP improves end-to-end output TPS/GPU by 8.8% at comparable TPS/user in the 20-100 TPS/user serving range under 8K input sequence length and 1K output sequence length.

### 论文总结：DWDP（分布式权重数据并行）

#### 1. 核心问题与整体含义（研究动机和背景）
随着大语言模型（LLM）规模的增长，单 GPU 显存已无法容纳完整模型，推理必须依赖多 GPU 并行。现有的主流策略（如张量并行 TP、专家并行 EP）在每一层都需要进行跨 GPU 的集合通信（如 All-to-All 或 All-Reduce），这引入了**层级同步（Layer-wise Synchronization）**。
*   **痛点**：在实际生产环境中，由于请求长度不同、KV 缓存命中率差异以及 MoE 模型的路由倾斜，各 GPU 的负载极不均衡。同步机制导致“木桶效应”，即计算快的 GPU 必须等待最慢的 GPU，严重限制了端到端吞吐量。
*   **目标**：消除推理路径上的集体同步，使每个 GPU 能够独立、异步地推进推理进度。

#### 2. 论文提出的方法论
论文提出了 **DWDP (Distributed Weight Data Parallelism)**，其核心思想是将“数据并行”的独立性与“权重卸载”的灵活性相结合。
*   **核心思想**：每个 GPU 维持独立的数据并行执行流，不进行层间同步。MoE 层的专家权重被切分并分布存储在对等 GPU 组内。在计算当前层时，异步预取（Prefetch）下一层缺失的远程专家权重。
*   **关键技术细节**：
    *   **异步远程权重预取**：放弃 NCCL 集合通信，改用基于拷贝引擎（Copy Engine）的 `cudaMemcpyAsync` 进行点对点拉取，不占用 SM 计算资源。
    *   **切分权重管理（Split-Weight Management）**：针对本地和远程权重不在连续内存的问题，优化了 MoE GroupedGEMM 内核，使其支持 TensorList 输入，直接从多个缓冲区读取权重，消除了显存合并拷贝的开销。
    *   **时分复用（TDM）调度**：为解决多个 GPU 同时向同一源 GPU 请求权重导致的“多对一”通信竞争，将权重传输切分为固定大小的切片（Slice），并采用轮询（Round-robin）调度，利用硬件流水线掩盖延迟。
    *   **计算-通信重叠**：利用当前层的 MoE 计算和下一层的 Attention 计算窗口来掩盖权重预取的通信耗时。

#### 3. 实验设计
*   **模型与精度**：使用 **DeepSeek-R1** 模型。权重采用 NVFP4 量化，KV Cache 采用 FP8 精度。
*   **场景**：聚焦于**分离式推理（Disaggregated Serving）**架构中的 **Context Server（预填充阶段）**，因为该阶段计算量大，更容易掩盖预取开销。
*   **Benchmark（基准）**：对比了传统的 **DEP**（数据并行 + 专家并行）策略。
*   **数据集**：使用 Artificial Analysis 和 SemiAnalysis 数据集，模拟真实的推理负载（如输入序列 8K，输出 1K）。
*   **对比指标**：每秒处理 Token 数（TPS/GPU）、用户感知吞吐量（TPS/user）、首字延迟（TTFT）以及 Pareto 前沿分布。

#### 4. 资源与算力
*   **硬件平台**：NVIDIA **GB200 NVL72**。该平台通过第五代 NVLink 提供了极高的 GPU 间互联带宽（单 GPU 1.8 TB/s），这是 DWDP 能够有效运行的硬件基础。
*   **算力规模**：实验主要在 DWDP3（3 卡组）和 DWDP4（4 卡组）配置下进行。
*   **软件框架**：基于 NVIDIA **TensorRT-LLM** 实现。

论文进行了多维度的实验评估，具有较高的充分性和客观性：
*   **消融实验**：分别验证了“权重合并消除”和“通信竞争缓解”两项优化技术的增益。
*   **负载敏感度分析**：测试了不同输入序列长度（1K 到 32K）、不同负载不平衡度（标准差变化）对性能的影响。

#### 6. 主要结论与发现
*   **吞吐量提升**：在典型的 8K/1K 推理场景下，DWDP 在相同的用户吞吐量水平下，将单 GPU 的输出吞吐量（TPS/GPU）提升了 **8.8%**。
*   **抗失衡能力**：实验证明，工作负载越不平衡（ISL 标准差越大），DWDP 相对于传统同步策略的优势越明显。
*   **资源灵活性**：DWDP 支持非幂次方的 GPU 组配置（如 3 卡），允许更精细的资源分配，有助于在分离式推理中实现更好的速率匹配。
*   **硬件瓶颈发现**：发现限制异步预取性能的主要因素并非显存带宽，而是高负载下的**功耗诱导频率降频（Power-induced Frequency Throttling）**。

#### 7. 优点
*   **架构创新**：打破了 LLM 分布式推理必须逐层同步的思维定式，实现了真正的异步执行。
*   **实用性强**：针对 DeepSeek-R1 等超大规模 MoE 模型进行了深度优化，直接解决了当前工业界最关注的负载倾斜问题。
*   **软硬协同**：充分利用了 Blackwell 架构和 NVLink 5 的特性，并针对硬件底层的功耗和频率特性进行了细致的性能分析。

#### 8. 不足与局限
*   **硬件依赖性极高**：DWDP 极度依赖 NVLink 提供的超高带宽。在带宽较低的集群（如传统 PCIe 或低速以太网）上，预取开销可能无法被计算窗口掩盖。
*   **首字延迟（TTFT）风险**：在某些配置下，为了追求更高的吞吐量，DWDP 可能会导致 TTFT 增加（由于排队效应或预取等待），这在对延迟极度敏感的场景下需要权衡。
*   **适用阶段有限**：目前主要针对 Context 阶段（Prefill）有效。在 Decoding 阶段，由于计算量极小，计算窗口通常不足以掩盖权重预取的延迟。
