## 摘要
在大规模工业应用中，驱动推荐和排序的深度学习模型具有复杂多样的模型架构。这些模型由大型机器学习工程师团队持续开发和改良，使得手动优化不可行。因此，基于图的优化技术已成为提升性能的行业标准，其中PyTorch FX变换处于领先地位。这些变换通常依赖一组人工设计的模块级重写规则，而这些规则无法扩展到各种模型架构。为了解决这一局限性，我们引入了Optimus，这是一个在PyTorch 2.x (PT2) 机器学习编译器内构建的通用模型变换框架。Optimus通过一组简洁的预定义模式，应用高效的贪心搜索算法进行模式匹配和替换，同时保持模型语义。它被设计和实现为一个高度可定制和可扩展的框架，集成在PT2栈中。我们的评估表明，与基线相比，该框架可以在我们产业规模的推荐模型上实现高达63%的加速、6%的峰值内存降低，以及超过400秒的编译时间减少。Optimus已随PyTorch 2.x一同开源，作为一个可定制的模型变换层。

## Abstract
In large-scale industrial applications, deep learning models that power recommendation and ranking have complex and diverse model architectures. These models are continuously developed and refined by large teams of machine learning engineers, rendering manual optimization infeasible. Consequently, graph-based optimization techniques have become an industry standard for boosting performance, with PyTorch FX transformations leading the charge. These transformations typically rely on a set of human-engineered module-level rewrite rules which are not scalable to diverse model architectures. To address this limitation, we introduce Optimus, a general-purpose model transformation framework built in the PyTorch 2.x (PT2) machine learning compiler. With a concise set of predefined patterns, Optimus applies an efficient greedy search algorithm for pattern matching and replacement, while preserving model semantic. It is designed and implemented as a highly customizable and extensible framework integrated into the PT2 stack. Our evaluation shows that the framework can achieve up to 63% speedup, 6% peak memory reduction, and over 400 second compile time decrease for our industry-scale recommendation models compared to baselines. Optimus is open-sourced together with PyTorch 2.x as a customizable model transformation layer.

### 2. 论文提出的方法论
**核心思想**  
将复杂的图优化分解为**原子化的算子级重写模式**，通过预定义简洁的模式集和高效的贪心搜索，在 PyTorch 2.x 编译器的不同图中间表示（IR）上自动执行子图匹配与替换，同时保证语义不变。

**关键技术细节**  
- **图与规则表示**：  
  模型被编译为有向无环图（DAG），节点为操作符（如 `torch.split`、`aten.mm`），边表示张量流动。每一条变换规则定义为源模式 → 目标模式的符号表达式，例如消除 split‑concat 冗余：  
  `x -> split[1](item0, (item1(...))) -> cat[1](y) ⇒ x(y)`。

- **优化类型**：  
  - **横向优化（Horizontal）**：批量融合（batch fusion）将形状相同的无依赖张量堆叠后一次计算再拆解；组融合（group fusion）允许不同形状张量在同一次核启动中执行，减少核启动开销。  
  - **纵向优化（Vertical）**：针对连续操作形成的模式（如 split‑concat、GEMM 形状对齐 padding）消除冗余节点或重组计算图。

- **搜索与替换算法**：  
  - **横向优化算法**：从目标节点类型出发，反向 BFS 在图中查找匹配节点；按节点键（形状等元信息）分组候选；对每组独立子集进行融合变换。  
  - **纵向优化算法**：自锚点（输出节点）出发，递归比较子图结构与目标模式，匹配后执行替换；通过 `counter` 控制重复应用次数。  
  - 两种算法均采用启发式规则（如搜索深度、最小融合集合大小）平衡性能收益与编译开销；变换顺序（先横向后纵向）能消除横向融合引入的 stack/unbind 冗余。

- **语义保持**：  
  规则设计保证输入/输出张量不变；框架提供灵活开启/关闭控制、二分调试、运行时刻数值校验（对比变换前后输出），确保数值等价可控。

- **集成与扩展**：  
  作为 PyTorch 2.x 的插件式变换层，支持在 Torch‑IR、ATen‑IR、Inductor‑IR 上注册新模式，用户可自定义规则和参数（如 `min_fuse_set_size`、`max_depth`），实现高度可定制编译优化。

### 7. 优点
- **通用且高效**：算子级规则跨模型泛化，搜索复杂度远低于穷举或 equality saturation，生产环境中编译预算可控。
- **深度集成 PyTorch 2.x**：无缝接入 Dynamo → AOTAutograd → Inductor 流程，可利用现有框架能力，同时保持开发灵活性。
- **模块化与可扩展**：插件式注册新规则，用户可自定义搜索深度、融合规模等参数；支持 Torch‑IR、Aten‑IR 等多层 IR。
- **工业实用性验证充分**：在五个大型推荐模型、三种高端 GPU 上进行详尽的端到端评估，且已开源并部署于 Meta 内部生产系统。
- **诊断与调试完善**：提供 bisection 调试、数值校验机制，确保优化安全可回退。

### 8. 不足与局限
- **规则依赖人工设计**：模式库需要专家根据 GPU trace 分析和模型特点手动归纳，覆盖新计算范式（如 attention、新算子）时仍需投入工程分析。

- **实验范围偏重推荐系统**：所有工业评估均围绕 DLRM 变体，未展示在 Transformer、卷积网络等主流架构上的效果，结论泛化性待验证。
