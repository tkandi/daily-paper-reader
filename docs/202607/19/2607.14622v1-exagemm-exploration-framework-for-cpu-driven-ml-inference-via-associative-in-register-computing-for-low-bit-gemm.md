## 摘要
低比特GEMM对于高效的ML推理日益重要，然而极低比特的执行仍然不适合传统CPU。实际部署跨越碎片化的范围——从1/2/4比特权重到不同的激活精度——在固定的SIMD和寄存器文件预算下，它们的可行性、重用机会和支持成本各不相同，使得轻量级CPU支持选择成为一个首要的设计问题。我们提出了ExaGEMM，一个工作负载感知的协同设计和探索框架，通过寄存器驻留的LUT执行实现CPU原生的低比特GEMM。关键见解是，现有的SIMD数据通路已经涵盖了表生成和累积；唯一的新硬件是一个明确建模成本的寄存器内选择/馈送机制。ExaGEMM利用寄存器可行性、计算成本、存储器流量和硬件开销的分析模型，共同探索参数化内核和轻量级SIMD ISA支持，在仿真前剪枝了99.2%的候选空间。然后它确定非支配的支持点，并生成ISA规范、gem5补丁和GEMM内核以进行验证。在代表性的ML模型和CPU目标上，ExaGEMM相比纯软件基线实现了13.29倍的延迟改进，同时表明工作负载感知的前沿选择对于混合精度的LLM工作负载尤其重要。

## Abstract
Low-bit GEMM is increasingly central to efficient ML inference, yet very-low-bit execution remains a poor fit for conventional CPUs. Practical deployment spans fragmented regimes-from 1/2/4-bit weights to varying activation precision-whose feasibility, reuse opportunity, and support cost differ under fixed SIMD and register-file budgets, making lightweight CPU support selection a first-class design problem. We present ExaGEMM, a workload-aware codesign and exploration framework for CPU-native low-bit GEMM via register-resident LUT execution. The key insight is that existing SIMD datapaths already cover table generation and accumulation; the only new hardware is an in-register select/feed mechanism with explicitly modeled cost. ExaGEMM co-explores parameterized kernels and lightweight SIMD ISA support using analytical models of register feasibility, compute cost, memory traffic, and hardware overhead, pruning the candidate space by 99.2% before simulation. It then identifies non-dominated support points and generates ISA specs, gem5 patches, and GEMM kernels for validation. Across representative ML models and CPU targets, ExaGEMM improves latency by 13.29x over software-only baselines, while showing that workload-aware frontier selection is especially important for mixed-precision LLM workloads.

# ExaGEMM 论文总结

## 1. 研究的核心问题与背景
- **核心问题**：极低位宽通用矩阵乘法（GEMM）在传统 CPU 上执行效率低下，而实际部署中权重精度（1/2/4 比特）和激活精度（INT4/8/16）的组合呈现碎片化。单一固定内核或 ISA 扩展无法有效覆盖这种多样性，轻量级 CPU 支持点的选择成为一个首要的协同设计难题。
- **研究背景**：低比特 GEMM 通过量化减少内存流量和计算量，但表驱动 SIMD 方法虽然降低了算术成本，却将瓶颈转移到表构建和内存层次移动。已有方案要么仅提供软件 SIMD 内核（如 T‑MAC），要么只针对单一精度（如三元 LLM），均未解决跨多种量化体制的支持选择问题。ExaGEMM 旨在填补该空白：在有限的 SIMD 和寄存器文件预算下，系统地确定哪些轻量级硬件支持点值得实现。

## 2. 方法论概述
### 核心思想
- 复用现有 SIMD 数据通路完成表生成和累加，仅需新增一个轻量级的**寄存器内选择/馈送网络**，其成本随精度、打包粒度和分块形状变化，从而将硬件开销作为显式的可排序目标。

### 参数化执行空间
- 定义内核参数 `k = (e, b, r, c, u)`：
  - `e`：打包因子，决定一个表索引包含多少个低比特符号。
  - `b`：扇入，合并的分组数。
  - `r`：输出行分块。
  - `c`：输出列分块。
  - `u`：指令级合并因子，用于在调度层面合并多个 K 子块，降低输出加载/存储开销。
- 通过变化 `e, b, r, c` 控制表大小、选择网络复杂度和聚合工作量，从而适应不同精度和层形状。

### 分析探索流程
- **可行性检查**：分析寄存器需求（表寄存器、权重寄存器、输出寄存器）不得超过目标向量寄存器文件容量，且输出寄存器数量固定为 1。
- **成本模型**：
  - 计算逻辑指令数：表生成指令 `TBL` 和 GEMM 指令。
  - 内存流量模型：权重、激活和输出流量，输出流量因 `u` 而降低。
  - 算术/控制成本 `C_cmp` 综合 TBL、GEMM、聚合加法和控制开销。
  - 硬件开销 `H_sel` 仅与选择网络规模相关，通过 ASIC 合成进行校准。
  - 总分析执行成本 `C_exe = C_cmp + α_mem·B_mem`，其中 `α_mem` 为平台相关的内存流量惩罚系数。
- **层内核选择**：对于每个支持点和层，在可行候选中最小化 `C_exe`。
- **模型级支持前沿**：聚合所有层的执行成本和硬件开销，筛选出非支配的支持点集合，最终生成 ISA 规范、gem5 补丁和 GEMM 内核进行验证。

### 关键算法步骤
1. 针对量化模型和 CPU 参数，枚举候选支持点 σ。
2. 对每个层 ℓ 进行可行性剪枝并选择最优内核 k*。
3. 汇总模型级 `C_model` 和 `H_model`。
4. 提取帕累托前沿，生成实现制品。
