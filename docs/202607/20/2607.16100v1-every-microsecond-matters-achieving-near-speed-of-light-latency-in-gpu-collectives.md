## 摘要
GPU 集合通信通常针对带宽进行优化，然而许多新兴工作负载越来越受限于延迟。长上下文、解码密集型的大语言模型（LLM）推理就是一个典型例子，其中服务大型模型需要多个 GPU，而许多小型集合操作直接处于令牌生成的关键路径上。因此，即使是微秒级开销也会影响性能和成本。在本工作中，我们研究如何在扩展网络内接近 GPU 集合通信的硬件光速（Speed-of-Light，SoL）下界。我们提炼出接近最优设计的关键原则，包括无屏障同步以及对称内存和多播的高效利用。基于 NCCL 的设备端 API，我们开发了用于构建自定义集合内核的低延迟接口，并利用它们在 NCCL 中实现新的对称集合操作。微基准测试显示，中小消息的延迟显著降低，开销降至绝对 SoL 下界的 7% 以内。当集成到实际应用中时，这些内核改进了 LLM 推理中的令牌间延迟和吞吐量，并加速了 cuSOLVERMp，展示了对 AI 推理和传统 HPC 工作负载的双重效益。

## Abstract
GPU collective communication is typically optimized for bandwidth, yet many emerging workloads are increasingly limited by latency. Long-context decode-heavy large language model (LLM) inference is a prime example, where serving large models requires multiple GPUs, and many small collectives lie directly on the critical path of token generation. Therefore, even microsecond of overhead can impact performance and cost. In this work, we study how to approach the hardware Speed-of-Light (SoL) lower bound for GPU collectives within a scale-up network. We identify key principles for near-optimal designs, including barrier-free synchronization and efficient use of symmetric memory and multicast. Building on NCCL's device-side API, we develop low-latency interfaces for constructing custom collective kernels and use them to implement new symmetric collectives in NCCL. Microbenchmarks show substantial latency reductions for small and medium messages, reducing overhead to within 7% of the absolute SoL lower bound. When integrated into real applications, these kernels improve inter-token latency and throughput in LLM inference and accelerate cuSOLVERMp, demonstrating benefits for both AI inference and traditional HPC workloads.

### 2. 论文提出的方法论

*   **核心思想：消除全局内存屏障**
    识别出现有实现中跨GPU内存屏障是延迟的主要来源，并设计了一系列无屏障（Barrier-Free）同步技术来替代它。
*   **关键技术细节与算法流程**
    *   **低延迟同步机制**：
        *   **LL（Low Latency）**：将8字节的标志位与8字节数据打包，通过16字节原子写操作一同传输，接收方通过检查标志位判断数据就绪。绕过了单独的信号传输步骤，但会减半有效带宽。
        *   **哨兵（Sentinel）**：用特殊值（如`-NaN`）预初始化接收缓冲区，接收方轮询直到值改变即代表数据到达。相比LL，它保留了完整带宽，但需要排除哨兵值与有效数据冲突的可能性，且需要重置缓冲区。
    *   **双向通信与双缓冲**：
        为处理超出缓冲区大小、需要分块迭代的消息，采用双向通信模式。在此模式下，对于同一通信对，一次迭代中从对等方的接收操作，隐式地充当了下次迭代向该对等方发送数据的“许可”。结合双缓冲（轮换使用两个子缓冲区），有效防止了未消费数据被覆盖，从而在多轮迭代中消除了全局屏障的必要。
    *   **新型两阶段LL128原子AllReduce算法**：
        专为进一步提升可扩展性设计，利用NVLink的缓存行级原子加特性。
        1.  **ReduceScatter阶段**：线程组将其处理的128字节缓存行中的第一个元素（标志位）替换为`1`，然后对整个缓存行执行原子加操作，写入目标GPU的临时缓冲区。
        2.  **AllGather阶段**：当目标GPU轮询发现某缓存行第一个元素的值等于参与的GPU总数`N`时，即代表所有贡献已完成。随后将标志位移除，恢复数据并写入输出缓冲区。
        该算法显著节省了临时空间（仅需 `D/N`）和带宽（浪费约1.5%-3%），但限于加法和特定精度。
*   **低延迟API设计**
    基于上述技术，在NCCL设备端接口之上构建了一套实验性API，以`ncclLLBuffer`为核心抽象，封装了`send`, `recv`, `bcast`, `recvReduce`等线程级原语，简化了自定义无屏障集合内核的开发。
