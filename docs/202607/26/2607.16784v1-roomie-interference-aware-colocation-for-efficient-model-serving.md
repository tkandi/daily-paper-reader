## 摘要
随着DNN推理需求的增长，GPU容量日益被超额预订，迫使运营商在云端和边缘部署中将多个模型共置在同一设备上。共置是成功还是违反服务水平目标（SLO）取决于并发执行模型的内核的时间重叠——现有服务系统要么忽略这种效应，要么使用无法捕捉时间动态的聚合资源概况进行近似。本文提出了Roomie，一种模型服务编排架构，能够预测并避免共置DNN之间的内核级干扰。Roomie将离线内核分析与在线干扰预测解耦。它仅使用分析来提取每个内核的资源配置，并通过一种免疫于分析器引起的时间失真的基于占用率的分析模型来预测干扰。随后，一种成对贪心启发式算法在多项式时间内近似多模型干扰，而非指数时间，然后在线放置算法使用这些估计将每个传入模型分配给最小化预测减速的GPU。我们的实验评估在云级服务器集群和嵌入式边缘设备上将Roomie与最先进的解决方案进行了比较，结果表明Roomie将SLO违规（即推理延迟）减少了高达3倍，同时与现有方法相比，维持了相当、在许多情况下更优的有效吞吐量。

## Abstract
As demand for DNN inference grows, GPU capacity is increasingly oversubscribed, forcing operators to colocate multiple models on the same device in both cloud and edge deployments. Whether colocation succeeds or violates SLOs depends on the temporal overlap of kernels from concurrently executing models -- an effect that existing serving systems either ignore or approximate using aggregate resource profiles that fail to capture temporal dynamics. This paper presents Roomie, a model serving orchestration architecture that predicts and avoids kernel-level interference between colocated DNNs. Roomie decouples offline kernel profiling from online interference prediction. It uses profiling only to extract per-kernel resource configurations, and predicts interference with an occupancy-based analytical model immune to profiler-induced timing distortion. A pairwise greedy heuristic then approximates multi-model interference in polynomial rather than exponential time, and an online placement algorithm then uses these estimates to assign each incoming model to the GPU that minimizes predicted slowdown. Our experimental evaluation compares Roomie against state-of-the-art solutions across both cloud-grade server clusters and embedded edge devices, demonstrating that Roomie reduces SLO violations (i.e., inference latency) by up to 3x, while maintaining comparable, and in many cases superior, goodput relative to existing approaches.

### 1. 论文的核心问题与整体含义
- **背景**：随着深度学习模型推理需求的增长，GPU 资源越来越被超额预订，云端和边缘场景中普遍存在多模型共置（colocation）于同一 GPU 的现象。
- **核心问题**：多模型共置时，不同模型的内核（kernel）会在时间维度上重叠执行，引发严重的资源竞争与干扰，导致推理延迟显著增加，进而违反服务水平目标（SLO）。然而，现有的模型服务系统要么完全忽略这种内核级干扰，要么仅通过静态聚合的资源概况（如计算强度与访存强度）来近似，无法捕捉内核执行的时间动态，造成共置决策失败。
- **整体含义**：准确预测并避免内核级的时间重叠干扰，是提升共置效率、保障推理延迟 SLO 的关键。论文提出的 Roomie 正是一种通过离线剖析与在线预测相结合、以内核时间对齐为中心的干扰感知编排系统。

### 2. 方法论
Roomie 的核心思路是将内核干扰建模从昂贵的在线实测中解耦，并利用贪心策略应对组合爆炸。

- **离线剖析（解决剖析失真）**  
  使用 Nsight Compute 或 PyTorch Profiler 仅提取每内核的资源配置（寄存器用量、共享内存、线程块维度），而不依赖剖析器给出的执行时长（因为这些工具会引入 1.4×~2.7× 的时序膨胀）。性能预测通过基于占用率（occupancy）的分析模型完成。

- **占用率模型与干扰估计**  
  - 定义理论占用率：根据 SM 的寄存器、共享内存、线程束上限，计算每个内核在独占 GPU 时的最大占用率 \(o\)。  
  - 当多个内核同时调度且总资源需求超过容量时，重新计算调整后的占用率 \(\tilde o_k\)，并利用公式 \(\tilde d_k = d_k \cdot \frac{o_k}{\tilde o_k}\) 估算执行时间的膨胀。  
  - 考虑两阶段执行：短内核先结束，剩余内核恢复独占状态，进一步精炼延迟估计。  
  - 最终计算每个模型的性能下降 \(\mu_m = (\tilde T_m - T_m)/T_m\)，其中 \(\tilde T_m\) 为考虑所有重叠后的总执行时间。

- **成对贪心启发式（解决组合爆炸）**  
  为了评估 \(N\) 个模型共置时的干扰，不枚举所有内核起始点的笛卡尔积，而是仅考虑模型之间的两两配对 \( (m_i, m_j) \)，并用它们内核序列的采样对齐点（起始索引）进行模拟。对每个对齐点计算累计延迟，并取所有对齐点的中位数作为该模型对的延迟估计。再通过一个基于内核序列长度比的缩放因子 \(\gamma_{i,j}\) 对该延迟加权。最后累加所有其他模型对 \(m_i\) 的干扰，得到 \(m_i\) 的总延迟估计。该方法将复杂度从指数级降为多项式级。

- **在线放置算法**  
  当新模型到来时，针对每个候选 GPU 估算加入新模型后所有模型的平均性能下降 \(\bar \mu_g\)。设置一个可容忍的退化阈值 \(\lambda\)，选择满足 \(\bar \mu_g < \lambda\) 且平均下降最小的 GPU 作为部署目标；若无满足条件的 GPU，则推迟部署。

- **系统架构**  
  Roomie 由离线 Profiler（执行模型剖析、占用率计算、贪心干扰估计）和在线 Controller（包含调度器、负载均衡器、负载监控器）组成，使用 C++/Python 实现并通过 WebSocket 通信。推理引擎基于 PyTorch，每个模型运行在独立的 CUDA Stream 上。

### 3. 实验设计
- **数据集与工作负载**  
  - 真实负载：Twitter Trace 2020，使用泊松过程生成秒内到达，并用 Zipf 分布分配模型请求。  
  - 合成负载：基于高斯过程生成请求率，模型分配遵循 Zipf 分布（指数 1.8），以模拟非对称负载。

- **模型集合**  
  涵盖分类模型（如 AlexNet、GoogLeNet、ResNet152、EfficientNetV2 等）与目标检测模型（如 SSD、FasterRCNN、RetinaNet 等），部分大型模型仅用于云端集群。

- **对比基准**  
  - **INFaaS**：代表性的模型无关推理服务系统，仅依赖副本复制与自动缩放，无干扰感知。  
  - **Usher**：最先进的干扰感知共置系统，通过内核级资源分析将计算密集型与访存密集型模型配对，但忽略内核的时间重叠。

- **部署场景**  
  - 云端集群：12 块 Nvidia A100 GPU（3 台机器每台 4×A100，共 12 个 Docker 服务器）。  
  - 边缘集群：12 块 Nvidia Jetson AGX Xavier GPU（每块独立容器）。  
  - 控制节点与客户端节点分开。

- **评估指标**  
  SLO 违规率（主要）、有效吞吐量（goodput）、GPU 计算利用率、GPU 显存利用率、放置精度（与暴力搜索最优对比）、决策延迟。

### 6. 主要结论与发现
- Roomie 在所有场景下均显著降低了 SLO 违规率：云端降低 3×（相对 INFaaS）和 2×（相对 Usher）；边缘降低幅度更大（INFaaS >40% 违规时 Roomie 维持 ~10%）。
- 有效吞吐量在同等负载下保持可比，甚至在高负载下略高。
- 内核级时间重叠干扰才是共置决策的决定因素，而非单纯的资源使用量互补（Usher 的“计算+访存”配对策略常失效）。
- Roomie 的贪心算法在 ~90% 的随机化试验中达到与暴力搜索最优一致的放置结果。
- 决策延迟可控：即使 15 模型在 10 GPU 上，总决策延迟仍小于 1 秒。
- 增加批次大小并不能显著改善 SLO 违规，因为干扰的核心在于调度和内核重叠，而非单纯的资源利用率。

### 7. 优点
- **问题切入点精准**：以“内核执行的时间对齐”作为干扰的核心，区别于以往基于静态资源指纹的方法，理论解释力强。
- **方法优雅且实用**：通过剖析器仅提取结构参数并依赖分析模型进行预测，规避了剖析器自身引入的时长偏差，同时利用成对贪心将指数级搜索降为多项式。
- **系统实现完整**：端到端的在线服务系统，整合了剖析、干扰预测、放置决策与负载监控，能够在真实硬件上运行。
- **实验充分、对比公允**：同时覆盖云端大卡和边缘小卡，与当前最先进的 INFaaS 和 Usher 严格对比，并给出了放置精度和延迟的系统性评估。
- **效果显著**：在减少 SLO 违规方面提升显著，且决策开销低。

### 8. 不足与局限
- **模型覆盖范围有限**：主要针对传统 CNN 分类/检测模型，未包含大语言模型（LLM）等新兴架构。论文虽指出可扩展，但 LLM 的 KV-cache、token 级调度等特性会引入完全不同的干扰模式，现有方法无法直接迁移。
- **内核干扰模型简化**：调度策略假设了等分、优先级等经典方式，未考虑真实 GPU 调度器的复杂行为；核融合、算子优化等可能改变内核序列的实际重叠，影响预测精度。
- **未充分利用 MPS 等共享机制**：在部分平台（如 Jetson）MPS 不可用，但论文未探索如何将基于占用率的预测与 MPS 空间分区结合以进一步提升效率。
- **实验消融不足**：缺少对干扰预测中各组件（如中位数聚合、重叠缩放因子）的消融实验，难以评估各设计的相对贡献。
- **扩展性局限**：文中决策延迟评估显示，当模型数量较多且包含 SSD 等长序列模型时，决策时间可能达到数百毫秒，对超高频扩缩容场景可能有影响，但整体仍在可接受范围。
- **依赖剖析工具的可移植性**：不同 GPU 架构下剖析接口和资源参数可能变化，需针对每类硬件适配剖析器和分析模型。
