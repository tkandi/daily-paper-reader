## 摘要
现代大语言模型（LLM）及其代理应用正在拓宽服务负载的范围，上下文长度从几百个 token 到数十万个 token 不等。由于这些请求经常在同一服务窗口内交错出现，LLM 服务系统必须处理高度异构的混合长度负载。这种混合长度负载暴露了以 GPU 为中心的服务架构的根本低效性，这种架构的吞吐量依赖于大规模的、内存受限的批次。本文提出 NELSSA，一种将 GPU 与真实世界的近内存处理（PNM）加速器设备集成的 LLM 服务系统，以高效支持混合长度负载。NELSSA 采用基于长度的请求放置策略，将短上下文请求路由到 GPU，将长上下文请求路由到 PNM 层，并结合运行时迁移来适应动态上下文增长而无需重新计算。我们构建了 NELSSA 的端到端系统原型，在 PNM 上实现了设备级稀疏注意力，GPU 解码内核，以及一个主机端运行时，该运行时在支持 CXL 的基础设施上通过 RPC 和 RDMA 支持来协调调度和跨层内存移动。在混合长度 LLM 负载下，NELSSA 与仅 GPU 的基线相比，解码吞吐量提高了最多 5.5 倍（以 tokens/秒计），P99 延迟降低了最多 15 倍。我们的端到端原型和实验结果表明，由基于 CXL 的解耦实现的 GPU-PNM 集成服务，是一种有前景的系统范式，可用于构建可扩展且灵活的 LLM 基础设施，以支持不断演变的负载。

## Abstract
Modern LLMs and their agentic applications are broadening the range of serving workloads, spanning context lengths from a few hundred tokens to hundreds of thousands. As these requests frequently interleave within the same serving window, LLM serving systems must handle highly heterogeneous mixed-length workloads. Such mixed-length workloads expose fundamental inefficiencies in GPU-centric serving architectures, whose throughput depends on large, memory-constrained batches. In this paper, we present NELSSA, an LLM serving system that integrates GPUs with real-world Processing-near-Memory (PNM) accelerator devices to efficiently support mixed-length workloads. NELSSA employs length-based request placement to route short-context requests to GPUs and long-context requests to the PNM tier, incorporating runtime migration to accommodate dynamic context growth without recomputation. We prototype NELSSA as an end-to-end system, implementing device-level sparse attention on PNM, GPU decode kernels, and a host-side runtime that orchestrates scheduling and cross-tier memory movement over a CXL-enabled infrastructure with RPC and RDMA support. Across mixed-length LLM workloads, NELSSA improves decode throughput by up to 5.5x in tokens/sec and reduces P99 latency by up to 15x compared to GPU-only baselines. Our end-to-end prototype and experimental results suggest that integrated GPU-PNM serving, enabled by CXL-based disaggregation, is a promising system paradigm for scalable and flexible LLM infrastructures that support evolving workloads.

### 1. 论文的核心问题与整体含义

*   **研究背景**：现代大语言模型（LLM）服务正面临高度异构的**混合长度负载**。在实际应用中，短请求（几百个token）和长请求（高达数十万个token）在同一服务窗口中频繁交错出现。
*   **核心问题**：以GPU为中心的传统服务架构在处理此类混合负载时存在根本性的低效。
    *   **内存压力与批次坍缩（Batch Size Collapse）**：长请求的KV缓存会迅速消耗有限的GPU高带宽内存（HBM），导致调度器无法接纳新请求，强制将运行批次大小降低至1，从而严重损害吞吐量。
    *   **队头阻塞（Head-of-Line Blocking）**：由于长请求执行时间长，会导致队列中后续的短请求大量积压，引发尾部延迟（Tail Latency）急剧飙升。
*   **整体含义**：论文指出，问题根源在于**执行放置（Execution Placement）**，而非单纯的数据存储位置。即，对于内存密集型的长上下文解码注意力计算，GPU并非最优的执行场所。因此，需要一种能将长序列注意力计算卸载到专用内存计算单元的异构执行架构。

### 2. 论文提出的方法论

NELSSA 的核心思想是将GPU与近内存处理（PNM）加速器集成为一个异构系统，通过基于长度的请求放置策略，从系统层面解决混合长度负载的调度问题。其方法论包含三大机制：

*   **长度感知的混合路由 (Length-based Request Placement)**
    *   **核心思想**：短上下文请求路由至GPU执行（使用FlashAttention）；长上下文请求路由至PNM层，执行集群稀疏注意力（Clustered Sparse Attention）。
    *   **路由阈值推导（Threshold Derivation）**：系统并非采用启发式边界，而是根据硬件性能特性，通过等式推导出GPU密集注意力和PNM稀疏注意力的性能交叉点 `T_input`，低于该阈值的请求在GPU上更快，反之则在PNM上更优。
    *   **分批次混合路由（Split-Batch Hybrid Routing）**：在解码阶段，所有请求的QKV投影和MLP计算仍在GPU上全局批处理以保持计算效率，仅在注意力分支上进行分流。对长请求，GPU会执行一个本地窗口的注意力（处理sink和最近token），同时异步地将全局上下文的稀疏注意力的计算和结果聚合任务卸载到PNM节点。

*   **动态上下文增长的无缝运行时迁移 (Runtime Migration)**
    *   **问题**：初始为短的请求在解码过程中上下文可能急剧增长（如思维链推理），导致GPU内存耗尽。
    *   **迁移逻辑**：当一个请求的上下文长度超过 `T_input` 且GPU内存压力触发预判时，系统启动迁移。它优先选择上下文最长、最可能导致抢占的请求。
    *   **后台无缝切换**：迁移过程通过后台数据流异步进行，GPU将累积的历史KV缓存通过RDMA传输至PNM节点，同时不中断当前的 token 生成。传输完成后，请求的执行无缝切换至GPU+PNM的分布式模式，GPU立即释放其KV缓存内存。此为一劳永逸的**单向切换**，计算不会返回GPU。

*   **端到端GPU-PNM异构系统集成 (System Integration)**
    *   **架构设计**：采用预填充（Prefill）/解码（Decode）分离架构。预填充节点完成首次计算和KV缓存的K-means聚类；解码GPU节点执行短请求注意力和所有FFN，并管理长请求的路由；NELSSA节点包含多个PNM模块，负责存储分区KV缓存并执行稀疏注意力。
    *   **软件栈实现**：构建了完整的软件栈。控制路径使用gRPC/TCP进行会话管理和内存分配，性能关键的数据路径则使用RoCEv2 RDMA实现内核旁路、微秒级延迟的内存直传。PNM节点上的主机运行时负责命令分发和输出聚合。
    *   **多PNM可扩展性**：采用头维度划分（Head-wise Partitioning）策略在多PNM模块间分布KV缓存，实现负载均衡，并有效利用DDR5的 bank 级并行性来维持高带宽。
