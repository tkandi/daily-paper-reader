## 摘要
Apple Silicon SoC通过统一内存系统共享CPU、GPU和神经网络引擎，这提出了一个问题：是否可以通过跨单元拆分单个算子来加速Transformer推理。先前包括我们自己在内的尝试均告失败，或产生了精度受损的增益。我们找到了原因：MLX的惰性图调度器会在一个评估图内，当CPU流操作消费尚未物化的GPU结果时，序列化跨流工作；因此，使用物化输入时快1.38倍的行分块矩阵乘法，在惰性图内反而比仅用GPU慢0.66倍；而一个及时的物化边界可恢复并发性（1.34倍）。基于这一修正，我们实现了系统，为Transformer预填充构建了一个逐层、竞争感知的CPU+GPU行分块方案。在五种芯片和三代Apple Silicon上评估，并经社区复现，该分块方案将Llama风格解码器块的预填充加速了1.15–1.38倍，在全32块深度下保持不变，并在通过标准MLX-LM服务的真实Qwen2.5-7B检查点上，将首令牌时间缩短了1.18–1.25倍，输出令牌完全一致且解码吞吐不受影响。我们同样仔细地刻画了边界：解码无法受益，受共享带宽束缚，协同执行不能增加收益；精度匹配训练在所有五种芯片上损失了0.86–0.97倍；ANE调度开销使其无法在层粒度上参与；而在内存压力下，无回归的运行时门控会弄巧成拙，因为探测替代模式会逐出活动模式的工作集。代码、原始结果和生成记录已发布。

## Abstract
Apple-Silicon SoCs share CPU, GPU, and Neural Engine over one unified memory system, raising the question of whether transformer inference can be accelerated by splitting single operators across units. Prior attempts, including our own, failed or produced precision-confounded wins. We identify the cause: MLX's lazy-graph scheduler \emph{serializes} cross-stream work whenever a CPU-stream operation consumes an unmaterialized GPU result inside one evaluation graph, so a row-split matmul that runs \x{1.38} faster with materialized inputs runs \x{0.66} slower than GPU-only inside a lazy graph; an eager materialization boundary restores concurrency (\x{1.34}). \sys{} implements a per-layer, contention-aware CPU+GPU row split for transformer prefill built on this fix. Evaluated across five chips and three Apple-Silicon generations, community-replicated, the split accelerates Llama-shaped decoder-block prefill by \x{1.15}--\x{1.38}, unchanged at full 32-block depth, and reaches \x{1.18}--\x{1.25} faster time-to-first-token on a real Qwen2.5-7B checkpoint served through stock MLX-LM, with token-identical outputs and unchanged decode throughput. We characterize the boundaries equally carefully: decode cannot benefit, bound by shared bandwidth co-execution does not add; precision-matched training loses \x{0.86}--\x{0.97} on all five chips; ANE dispatch overhead excludes it at layer granularity; and a no-regression runtime gate becomes self-defeating under memory pressure, where probing an alternative mode evicts the active mode's working set. Code, raw results, and generation transcripts are released.

*   **研究动机**：Apple Silicon 芯片（如 M1/M2/M3/M4 系列）采用统一内存架构，CPU、GPU 和神经网络引擎（ANE）可物理共享内存。理论上，这为“单算子内部异构协同执行”（例如将矩阵乘法的行同时分配给 CPU 和 GPU）提供了零拷贝可能，有望加速大模型推理。然而，先前的相关尝试普遍失败，或仅得到因精度不匹配（如 FP16 vs FP32）导致的虚假加速。
*   **核心问题**：揭示在 Apple MLX 框架下，真正阻碍 CPU+GPU 协同执行的关键机制性障碍是什么，并在厘清该机制后，系统性地界定此方案的可行加速边界（何时有效、何时无效）。
*   **整体含义**：
    *   首次从调度器机制层面，探明 MLX 惰性图求值（lazy-graph evaluation）会**序列化跨流操作**——当 CPU 流消费尚未物理化（materialized）的 GPU 计算结果时，强制本可并行的任务变成串行，从而导致不升反降的性能。
    *   基于此发现，提出了 **FusionML**，一种仅针对 Transformer **预填充（Prefill）阶段**的、逐层行分割协同推理方案，并在五款不同代际芯片上验证了稳定加速。
    *   同时严格标定了该方案的**能力边界**：解码（Decode）受共享带宽限制无法加速；精度匹配训练在所有芯片上导致性能下降；ANE 因调度开销不适用于层细粒度；内存压力下进行运行时切换探针会严重偏估。
    *   最终，以务实方法实现了无损、易复现的端到端预填充加速（如7B模型首令牌缩短18-25%）。

### 2. 方法论：核心思想、关键技术与算法流程

*   **核心思想**：通过插入“即时物化边界（eager materialization boundary）”打破 MLX 惰性图调度引起的串行化，并结合“竞争感知（contention-aware）校准的静态行分割”，让 CPU（AMX）和 GPU（Metal）并在预填充阶段的线性层中同时工作。
*   **关键技术细节与流程**：
    1.  **机制发现与解决**（Figure 1 探针实验）：
        *   当对一个矩阵乘法进行行分割（一部分行在 `mx.cpu` 流上计算，另一部分在 `mx.gpu` 流上）时，若其输入直接在同一个 MLX 惰性求值图内依赖上游 GPU 算子的输出，MLX 调度器会**序列化**这两个流，导致分割版本比纯 GPU 版本还慢（`1.38× → 0.66×`）。
        *   解决方法：在每次分割并进入 MLX 图之前，对输入数据显式调用 `mx.eval()` 进行物理化，人为制造一个 eager 边界。该边界打破了 IPC 序列依赖，恢复了真实的并发执行（`0.66× → 1.34×`）。
    2.  **FusionML 设计**（Figure 2 逐层分割架构）：
        *   **作用范围**：仅用于 Transformer 解码器块的**预填充阶段**（Prefill），目标是加速长序列输入的“首次令牌时间（TTFT）”。
        *   **策略**：解码器块内的每一个线性层（Q/K/V 投影、W_o 输出投影、门控/上/下投影等），按行进行静态分割。
            *   前 **ρM** 行调度到 CPU 流（利用 AMX 矩阵协处理器）。
            *   剩余 **(1-ρ)M** 行调度到 GPU 流（Metal 计算）。
            *   计算完成后在结果张量上进行拼接（concat）。
            *   注意力计算、层归一化、逐元素激活等**保持原样在 GPU 上执行**。
            *   每个分割的线性层前**必须添加 eager 边界**。
    3.  **竞争感知的校准**：
        *   分割比例 **ρ** 不是由各自单独运行时的吞吐率（solo-throughput）决定。因为当 CPU 和 GPU**同时**运行时，会竞争共享的统一内存带宽，导致 GPU 本身吞吐下降。
        *   FusionML 针对每个具体的矩阵乘法形状，动态测量**实际并发运行**下一个小候选集 ρ ∈ {0, 0.10, ..., 0.50} 的性能，从而选出在竞争状况下真正最优的静态分割比例。
    4.  **无回归运行时门控**：
        *   实现一个简单但鲁棒的调度器，它视 {分割模式、MLX 编译基线、eager 基线} 为三种并行执行模式。
        *   通过一个短暂的**试跑阶段（probation）**选出最快模式；此后每调用第 10 次时**重新探测**其他模式，并结合指数滑动平均与滞后阈值（hysteresis）来决定是否切换。
        *   因为基线模式（stock execution）本身是门控的一个可选项，所以理论上该方法天然保证在“基线 - 微小探针开销”范围内不会出现性能倒退。

### 6. 论文的主要结论与发现

1.  **序列化机制是核心障碍**：Apple MLX 框架的惰性图调度内在属性会消除跨流协同执行的并行度。注入 eager 求值边界能无痛打破这一限制，成为开启真正并发的基础操作。
2.  **预填充加速为真实、跨代际稳定增益**：在五款芯片上，协同行分割将 Llama 几何形状的逐层预填充提速了 1.15–1.38 倍；在端到端 Qwen2.5-7B 模型上，将真实服务的首令牌时延（TTFT）降低了 1.18–1.25 倍。
3.  **解码天然不适用**：由于解码是带宽密集型且每个令牌需流动全部权重，在共享内存带宽下添加 CPU 算力无法提供任何加速，后续测得的保持中性解码吞吐也实证了此结论。
4.  **精度统一是受证前提**：任何混精度比较（如 FP16 协同 vs FP32 基线）均为伪优化，精度对齐后训练场景下协同执行在所有芯片上均失速（0.86-0.97×）。
5.  **ANE 及探测器在内存受限下失效**：ANE 因不可减免的高调度开销不适用于层级别切割；而内存紧张时，用于自动门控以探测最优模式的常规调度器自身会逐出工作集，导致既测不准也损失现有性能。
6.  **一个可落地且无损的方案**：FusionML 的无回归门控（因以基线为可能分支）和精准作用域（仅预填充）实现了对原有服务管线几乎零负面影响的实用加速。
