## 摘要
长上下文LLM训练存在一个序列打包无法解决的负载均衡问题。将样本打包到固定长度的token序列中可以平衡内存和线性成本算子，但主导的注意力成本与序列长度的平方和成比例。因此，从长尾语料库中提取的等长打包序列可能承载显著不同的注意力工作负载，从而产生数据并行拖后腿者和流水线气泡。现有方法要么在序列或微批次的粒度上进行平衡，其中一个异常值就能主导分配，要么将注意力分解到全局工作池中，该池的通信域随数据并行（DP）度增长。我们提出了Libra，它将大数定律（LLN）作为负载均衡的扩展原则进行实际操作：注意力均衡池不需要随DP度增长。Libra将打包序列及其上下文并行组分组为固定大小的序列池。随着DP向外扩展，Libra增加池的数量而不是扩大每个池，从而限制了每次注意力交换。方差缩减序列放置通过将具有互补注意力工作负载的序列放置在一起，以减少剩余的池间倾斜，从而对有限的长尾工作负载有效。在每个池内，分块注意力池化将序列头SH-Tiles分发到GPU上，而流水线运行时将tile交换与注意力重叠。Libra提供了一个即插即用的上下文并行注意力算子和一个可插拔的数据采样器，无需更改模型层、优化器或流水线调度。在使用256K和1M token工作负载的Qwen3-Turbo训练中，与Ulysses相比，Libra将端到端吞吐量提高了最多2.54倍，在微基准测试中，最差步骤拖后腿注意力加速比高达3.14倍。Libra已在生产中运行数十万GPU小时，处理从32K到1M token的任务，同时保持训练语义。

## Abstract
Long-context LLM training suffers from a load-balancing problem that sequence packing does not solve. Packing samples into fixed-token sequences balances memory and linear-cost operators, but the dominant attention cost scales with the sum of squared sequence lengths. Thus, equally sized packed sequences drawn from a long-tailed corpus can carry substantially different attention workloads, creating data-parallel stragglers and pipeline bubbles. Existing approaches either balance at the granularity of sequences or microbatches, where an outlier can dominate an assignment, or disaggregate attention over a global worker pool whose communication domain grows with the data-parallel (DP) degree.   We present Libra, which operationalizes the law of large numbers (LLN) as a scaling principle for load balancing: the attention-balancing pool need not grow with the DP degree. Libra groups packed sequences and their CP groups into fixed-size sequence pools. As DP scales out, Libra adds pools rather than enlarging each one, bounding every attention exchange. Variance-Reduced Sequence Placement makes this effective for finite, long-tailed workloads by co-locating sequences with complementary attention workloads to reduce residual inter-pool skew. Within each pool, Tiled Attention Pooling dispatches sequence-head SH-Tiles across GPUs, while a pipelined runtime overlaps tile exchange with attention.   Libra exposes a drop-in context-parallel attention operator and a pluggable data sampler, requiring no changes to model layers, optimizers, or pipeline schedules. On Qwen3-Turbo training with 256K- and 1M-token workloads, Libra improves end-to-end throughput by up to 2.54x over Ulysses, with up to 3.14x worst-step straggler-attention speedup in microbenchmarks. Libra has run for hundreds of thousands of GPU-hours in production on jobs spanning 32K to 1M tokens while preserving training semantics.

## 1. 核心问题与整体含义

- **背景**：现有方案要么在序列/微批次粒度平衡，异常值仍主导分配；要么将注意力分解到全局工作池，通信域随DP度增长，牺牲规模扩展性。

## 2. 方法论
- **核心思想**：注意力均衡池规模不必随DP度增长；随着DP向外扩展，只增加池数量而非池大小，从而限制注意力交换的通信范围。
- **关键技术细节**：
  - **方差缩减序列放置 (VRSP)**：
    - 以完整打包序列为单位，按注意力FLOPs（$\sum \ell^2$）从重到轻排序，采用最长处理时间优先（LPT）的贪心算法，将序列分配到负载最小的、尚未满的池（固定池大小$P$），以最小化池间总工作负载方差。
    - 仅重新排列序列在GA索引和DP副本间的映射，不改变样本多集。
  - **分块注意力池化 (TAP)**：
    - 将每条序列沿token方向和查询头方向切分为**SH-Tile**（一个序列块×一个头分片），成为可独立调度的注意力任务。
    - 使用**通信感知的贪心放置器**（算法2），在负载上限$C$内优先选择增量通信量最小的目标worker，以降低通信开销。
    - KV组（样本+头分片）支持跨tile复用，减少冗余传输。
  - **TAP流水线**：
    - 将分配的SH-Tile沿头维度等分为$M$个chunk（$M=4$）；每个chunk的FLOPs、通信量均等。
    - 采用异步非阻塞通信重叠：计算chunk $i$时预先发送chunk $i+1$的Q/K/V并返回chunk $i-1$的输出，隐藏通信。
- **即插即用架构**：提供一个`libra_attention` API取代原有CP注意力，无需修改模型层、优化器、流水线调度，配合可插拔的数据采样器。

## 6. 主要结论与发现
- **整体效果**：在Qwen3-Turbo 256K和1M训练中，Libra端到端吞吐相对于Ulysses提升分别达**1.79倍和2.54倍**；微基准最差步注意力加速比达**3.14倍**（256K）和**2.90倍**（1M）。

- **组件贡献**：VRSP显著降低池间不平衡（$P=8$时低于0.7%），TAP与流水线重叠结合有效控制通信开销，固定池大小$P=8$能在平衡与通信之间取得良好折中。

## 7. 优点
- **扩展性原则**：明确提出基于大数定律的“序列池规模不随DP增长”的负载均衡原则，具有理论支撑。
- **两级负载均衡**：结合全局池间重分配（VRSP）和池内细粒度tile调度（TAP），解决不同层次的倾斜。
- **通信优化**：通过通信感知tile放置和头轴均匀chunk流水线，有效隐藏传输开销，维持高速训练。
- **系统友好**：即插即用设计，完全不改变现有训练框架的核心组件，易于部署。
- **生产验证**：大规模GPU小时生产运行，保持训练语义（样本多集不变），证明了方法的鲁棒性。

## 8. 不足与局限
- **未涵盖稀疏/线性注意力**：仅针对稠密因果自注意力，对稀疏注意力变体的适用性尚不明确。
- **流水线重叠不完全**：首尾chunk通信不可隐藏，大池下残留通信成本可能仍显著。
- **VRSP依赖贪心启发式**：没有提供严格的最优化保证，但实际效果好。
- **跨PP阶段扩展**：池仅限定在一PP阶段内，跨PP的注意力解耦（如DistCA）需要更多协同设计，不适合当前流水线调度。
- **硬件假设**：实验结果基于NVLink + RoCE集群，其他互联结构下性能可能不同。
- **消融分析**：对VRSP与现有数据打包方法的复合效果未深入探讨。
