## 摘要
大语言模型通过扩展混合专家（MoE）参数实现卓越智能，但庞大的权重与动态计算阻碍了高效服务。现有实例级预填充-解码分离方法将不同阶段部署在独立的全模型副本上。随着 MoE 权重增长，每个实例可能跨越数十至数百个 GPU，导致资源分配日益粗放。预设的预填充与解码比例因此经常与需求不匹配，造成某一阶段资源过剩而另一阶段过载。预填充-解码协同部署避免了这种重复，但现有的绿色上下文方案按阶段划分每个 GPU 并在内核执行期间固定阶段资源。它们无法跟踪跨操作的资源变化或路由专家负载的逐层差异，从而引发队头阻塞或预留资源闲置。每个 GPU 都进行划分也使每个阶段获得的本地资源更少，迫使采用更宽的并行度和更多通信，并让预填充与解码流量在共享网络上相互干扰。我们提出 ExpertPlex，它在阶段之间共享庞大的 MoE 专家，同时分离轻量级注意力模块。专家共享消除了超过 95% 的重复模型权重并复用动态稀疏计算，而注意力分离则降低了注意力通信成本。ExpertPlex 进一步采用：(1) 自适应持久内核，以瓦片粒度调度动态专家计算，实现高效且隔离的执行；(2) 注意力发起的 MoE 通信，避免网络干扰并支持跨阶段通信-计算重叠；(3) 瓦片到集群模型，对这些机制进行优化以获得最大吞吐量。在 MiniMax-M2.7 和 GLM-5.1-FP8 上的服务实验表明，相比实例级预填充-解码分离，ExpertPlex 的吞吐量提升高达 2.01 倍，相比预填充-解码协同部署提升 1.66 倍。

## Abstract
LLMs scale Mixture-of-Experts (MoE) parameters for superior intelligence, but massive weights and dynamic computation impede efficient serving. Existing instance-level prefill-decode disaggregation isolates the phases on separate full-model replicas. As MoE weights grow, each instance may span tens to hundreds of GPUs, making resource allocation increasingly coarse. Configured prefill-to-decode ratios thus often mismatch demand, overprovisioning one phase while overloading the other. Prefill-decode colocation avoids this duplication, but existing Green Context solutions partition each GPU by phase and fix phase resources during a kernel. They cannot track resource changes across operations or layerwise variation in routed expert load, causing head-of-line blocking or idle reserved resources. Partitioning every GPU also leaves each phase with fewer local resources, forces wider parallelism and more communication, and lets prefill and decode traffic interfere on the shared network.   We present ExpertPlex, which shares massive MoE experts across phases while disaggregating lightweight attention modules. Expert sharing eliminates over 95\% duplicate model weights and multiplexes dynamically sparse computation, while attention disaggregation reduces attention communication cost. ExpertPlex further uses (1) adaptive persistent kernels to schedule dynamic expert computation at tile granularity for efficient, isolated execution; (2) attention-initiated MoE communication to avoid network interference and enable cross-phase communication-computation overlap; and (3) a tile-to-cluster model to optimize these mechanisms for maximum goodput. Experiments serving MiniMax-M2.7 and GLM-5.1-FP8 show that ExpertPlex improves goodput by up to 2.01$\times$ over instance-level prefill-decode disaggregation and 1.66$\times$ over prefill-decode colocation.

## 1. 论文的核心问题与整体含义

大型语言模型通过扩展混合专家（Mixture‑of‑Experts，MoE）参数来提升智能水平，但庞大的专家权重（如 DeepSeek‑V4‑Pro 中占 95 %）与逐 token 动态路由带来的稀疏计算严重阻碍了高效推理。当前两种主流服务方案均存在结构性缺陷：

- **实例级预填充‑解码分离（instance‑level PDD）**：将预填充和解码部署在各自独立的完整模型副本上，以消除阶段干扰。但 MoE 权重不断膨胀致使每个实例的 GPU 需求动辄数十至数百块，形成极粗粒度的部署单元。预设的预填充：解码资源比很难实时匹配实际负载，往往造成一个阶段资源闲置而另一阶段过载；同时，专家权重跨阶段重复存储，挤占了 KV 缓存空间，并扩大了故障爆炸半径。
- **预填充‑解码共置（colocation）**：如基于 Green Context 的方案，在每个 GPU 内按阶段静态划分流多处理器（SM），避免了权重重复。然而其资源分割固定且切换需 CPU 介入，无法跟踪 MoE 层间不同专家激活量的变化，导致队头阻塞（长预填充内核阻塞延迟敏感的解码）或资源气泡（为解码预留的 SM 被闲置）。GPU 分区还迫使单个阶段可用资源减少，不得不采用更宽的并行度，增加通信开销，并使两阶段流量在共享网络上相互干扰。

ExpertPlex 的总体含义是：**通过一种混合分离‑共置架构，在阶段间共享占绝对多数的 MoE 专家权重，同时将轻量注意力模块按阶段分离，并配以自适应持久内核、注意力发起的一侧通信和跨栈联合优化，在消除模型副本冗余的同时，实现细粒度的动态调度与通信/计算重叠，从而大幅提升服务吞吐量（goodput）**。

## 2. 论文提出的方法论

ExpertPlex 的核心思想是“**共享专家，分解注意力**”，并围绕该思想设计了三个主要技术：

- **混合架构（共享 MoE + 分离注意力）**  
  由于 MoE 权重占模型参数的 95 % 以上，而注意力权重不足 5 %，ExpertPlex 在每个节点上将部分 GPU 分配给预填充服务器和解码服务器（仅运行各自注意力模块），其余 GPU 作为 MoE 服务器（执行两阶段的专家计算）。该设计  
  - 消除了跨阶段的 MoE 权重重复，并复用动态稀疏的专家计算；  
  - 给每个阶段分配完整的注意力 GPU，避免分区导致并行度扩大和通信增加，同时消除跨阶段注意力网络干扰；  
  - 使资源匹配粒度更细，弹性伸缩更灵活。

- **自适应持久内核（Adaptive Persistent Kernel，APK）**  
  每个 MoE GPU 运行一个长期存在的内核，以**瓦片（tile）**为粒度调度两阶段任务。其关键特性：  
  - **有界抢占**：通过 GPU 内存层级（系统‑设备‑分布式共享内存‑共享内存‑warp 广播）逐级传播抢占信号，保证解码任务最长等待时间为一个瓦片执行时间加本地检查周期，与预填充序列总长度无关。  
  - **实时重分配**：当某阶段无就绪工作或解码负载变化时，APK 无需 CPU 干预或内核重启动，即可动态调整 SM 分配（如将闲置的 CTA 集群借给预填充）；  
  - **CUDA Graph 兼容**：所有调度在 GPU 上进行，保持持久执行，避免了短解码路径的启动和同步开销。  
  APK 同时支持空间复用（不同集群执行不同阶段）与时间复用（同一集群在瓦片边界切换），并根据实时解码专家负载按比例调整 SM 预算。

- **注意力发起的一侧 MoE 通信**  
  传统 MoE 通信为两侧协议，容易因调度不一致导致死锁，且预填充大流量会阻塞解码小包。ExpertPlex 改为：  
  - **分发**：注意力服务器在路由决定后，直接通过 NVLink/RDMA 写将 token 激活写入 MoE 服务器的最终缓冲区，并发布就绪信号；MoE 侧无需轮询。  
  - **合并**：MoE 服务器完成后发布完成信号，注意力侧通过一个轻量的 WaitDone 内核获取状态，再主动拉取结果。  
  - **层次化预填充路径**：尽可能让预填充的跨节点流量经过预填充注意力服务器中转，保留层级去重效果，并为解码保留直连路径；必要时利用 InfiniBand 虚拟通道优先级保护解码流量。  
  该设计去除了 MoE 侧的协调与轮询，避免了跨阶段死锁，并使一个阶段的通信能与另一个阶段的计算重叠。

- **跨栈放置优化器**  
  联合搜索注意力并行度、MoE 并行度、服务器布局、重叠策略及 APK 的解码 SM 预算。通过一个基于瓦片占用度的时延模型（将 MoE 计算时间建模为实际执行的瓦片数而非单纯的 token 数）快速评估候选配置，选择使 goodput \( G(\ell, q) = \min\left(\frac{B_p}{T_p}, \frac{B_d}{T_d \bar{O}}\right) \) 最大且满足两阶段 SLO 的布局。离线确定配置后，在线阶段 APK 根据实际解码专家负载动态调整 SM 配额。

## 6. 主要结论与发现

- 在所有测试场景下，ExpertPlex 均取得了最高的 goodput。**相较 SGLang‑PDD（实例级分离）最高提升 2.01 倍，相较 SGLang‑PDMux（Green Context 共置）最高提升 1.66 倍**，相较普通共置提升达 4.12 倍，相较 chunked prefill 提升达 5.65 倍。  
- APK 的瓦片级调度是唯一能在保护解码时延的同时保持预填充高吞吐的机制：解码仅增加 8 % 延迟，预填充仅减慢 1.12 倍，远优于其他共享方式（如 MPS、Green Context）。  
- 注意力发起的一侧通信在保持通信效率（与 DeepEP v1 相差约 5 %）的同时，完全去除了 MoE 侧的轮询与死锁风险，并使跨阶段通信‑计算重叠成为可能。  
- 瓦片级抢占间隔短至 2.2–25.3 μs，与序列长度无关，为 MoE 服务提供了比传统抢占方案更低的暂停与恢复代价。  

## 7. 优点

- **架构创新性强**：抓住 MoE 权重占比巨大的特点，提出“专家共享、注意分离”的混合架构，概念清晰且实用。  
- **高度协同的系统设计**：APK、一侧通信、跨栈优化器紧密配合，从瓦片调度、通信模式到集群级布局统一优化，而非孤立修补。  
- **细粒度且无外部干预**：APK 在 GPU 上实现瓦片级抢占与重分配，无需 CPU 介入、无需内核重启动、兼容 CUDA Graph，对短解码路径十分友好。  
- **通信‑计算重叠层次丰富**：不仅保留了批次内/批次间重叠，还实现了跨阶段重叠，充分利用 MoE 侧的闲置计算能力。  
- **实验扎实且透明**：在两个前沿 MoE 模型、两类负载、多种基线及大量消融下验证，实验设置公平，开销分析详细。

## 8. 不足与局限

- **适用范围**：本文仅针对 MoE LLM，其混合架构（共享 MoE、分离注意力）依赖 MoE 权重占绝大多数这一前提；对于稠密模型或注意力占比高的模型，优势可能急剧减弱。  
- **实现复杂度**：需要深度修改 GPU 内核（DeepGEMM）、通信库（DeepEP）及推理框架（SGLang），部署门槛较高。  
- **集群规模与模型覆盖**：多节点实验仅使用了 3 节点（24 块 H800），未验证在更大规模集群（如上百 GPU）下的扩展性和故障恢复能力；仅测试了两款模型，未涉及其他 MoE 类型（如 MoE 仅部分层）或多模态模型。  
- **APK 瓦片约束**：抢占粒度受限于 GEMM 瓦片尺寸，对某些非 GEMM 操作（如小算子）的抢占行为未详细讨论；同时瓦片调度增加的少量延迟在极低延迟场景下可能仍需权衡。  
- **负载假设**：在线 SM 重分配策略基于解码负载比例动态调整，但其有效性依赖于离线配置的“预期负载”，在负载剧烈且持续变化时的适应性未充分评估。
