## 摘要
大语言模型（LLM）可辅助GPU核函数生成，但其实际效能取决于生成代码能否被可靠地约束、验证、性能剖析与选择。本文面向MLSys 2026 FlashInfer AI核函数生成竞赛（基于NVIDIA Blackwell B200 GPU），提出了一套以评估框架为中心的系统，用于LLM驱动的GPU核函数优化。该系统将评估框架与基于性能剖析的优化控制器解耦：评估框架强制实施编译、正确性校验、官方对齐的计时与产物归档，而控制器则根据性能剖析器和工作负载证据生成有边界的候选生成决策。人类编写的技能描述封装了算子约束、参考实现、性能剖析流程与晋级规则，Codex与Claude Code智能体则在这些约束内生成候选核函数。在五个算子定义上，保留的官方对齐产物相比提供的FlashInfer基线取得了平均时延加速比，分别为1.62倍、18.05倍、29.68倍、1.12倍与13.70倍。智能体辅助核函数在所有评估定义上均优于全智能体生成的产物，表明专家提供的优化方向、高质量参考实现与工作负载上下文对于可靠的AI驱动核函数优化仍然至关重要。

## Abstract
Large language models (LLMs) can assist GPU kernel generation, but their practical effectiveness depends on whether generated code can be reliably constrained, validated, profiled, and selected. This paper presents a harness-centered system for LLM-driven GPU kernel optimization in the MLSys 2026 FlashInfer AI Kernel Generation Contest on NVIDIA Blackwell B200 GPUs. The system separates an evaluation harness from a profile-backed optimization controller: the harness enforces compilation, correctness, official-aligned timing, and artifact archival, while the controller turns profiler and workload evidence into bounded candidate-generation decisions. Human-authored skills capture operator constraints, references, profiling procedures, and promotion rules, while Codex and Claude Code agents generate candidate kernels inside those constraints. Across five operator definitions, the retained official-aligned artifacts achieved mean-latency speedups over supplied FlashInfer baselines of 1.62x, 18.05x, 29.68x, 1.12x, and 13.70x. The Agent-Assisted kernels outperform the Full-Agent artifacts across the evaluated definitions, indicating that expert-provided optimization directions, high-quality references, and workload context remain critical for reliable AI-driven kernel optimization.

# 方法论
## 整体架构：评估框架与优化控制器分离
*   **评估框架（Evaluation Harness）**：测量层，负责打包候选核函数、在目标环境编译、运行正确性校验、测量官方对齐的 B200 时延，并存储基准测试和剖面子产物。
*   **优化控制器（Optimization Controller）**：决策层，将 NCU 和 Torch Profiler 的剖面数据转化为可复用的状态，选择单一优化方向，监督停滞或退化，并将正/负面证据写入记忆。

## 技能封装与智能体协作
*   **技能（Skills）**：人类将专家优化实践编码为可复用的技能文件（SKILL.md），供 Codex 和 Claude Code 智能体调用。包含三层：
    *   通用 CUDA 技能：定义候选合约、评估、剖面与两阶段搜索。
    *   FlashInfer B200 技能：加入参考优先侦察、工作负载发现、配对闸门、B200/CUDA 13.2 战术和官方对齐评估。
    *   统一 CUDA 优化控制器技能：剖面状态抽取、方向选择、轨迹监督和知识库更新。
*   **智能体（Agents）**：GPT-5.3‑Codex 和 Claude Opus 4.6 作为编程智能体，在技能定义的边界内生成 CUDA、Triton 或 CuTe/CUTLASS 候选核函数，读取剖面反馈并提出路线变更，但不绕过测量闸门自主晋级。

## 闭环迭代与晋级决策
*   核心算法 **Agent‑Assisted Harness Loop**（Algorithm 1）流程：
    1.  初始化记忆和基线；
    2.  每一轮，控制器抽取出当前状态；
    3.  智能体基于状态生成一组候选；
    4.  对每个候选执行**代表闸门**（paired representative gate），通过编译和正确性则进行剖面；
    5.  选择最佳通过候选，进行**全工作负载扫测**（full sweep）；
    6.  仅当全分布时延改进且无正确性退化时，才**晋级**（promote），否则保留原基线；
    7.  所有剖面、决策指标归档为正向或负向轨迹记忆；
    8.  若出现停滞，由**人类干预**恢复搜索（切换模型、提供新参考、变更实现语言等）。

## 硬件感知语言选择与形状感知调度
*   根据剖面证据选取实现语言：**Triton** 用于快速特化（如 MoE），**CUDA C++** 用于底层内存与发射控制，**CuTe / CUTLASS** 用于显式张量核布局和 Blackwell 专用核（如 GDN prefill 的 chunked 路径）。
*   **形状感知调度**：从竞赛工作负载的 UUID 和 JSON 轴中推导形状区间（序列长度、批量大小、页面数等），仅当剖面和时延证明存在不同限制因素时，才引入形状专用路由（如 GDN decode 的小批量 Triton 路径、大批量 CuTe 路径）。
