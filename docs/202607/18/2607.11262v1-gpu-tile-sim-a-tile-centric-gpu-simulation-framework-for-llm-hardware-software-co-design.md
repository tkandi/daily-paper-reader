## 摘要
现代大语言模型（LLM）工作负载越来越依赖于通过软硬件协同设计优化的GPU内核。这些内核通过细粒度的依赖调度和计算-内存重叠实现高性能。因此，它们给现有的GPU性能模型带来了新的挑战。指令驱动的模拟器适应不断演进的架构成本高昂，而分析模型则过于粗略，无法捕捉内核的特性。我们提出GPU-Tile-Sim，一个面向LLM软硬件协同设计的以Tile为中心的GPU模拟框架。其关键洞察在于，现代LLM内核性能更少受单条指令延迟的影响，而更多受控于执行顺序和重叠的依赖结构。相应地，GTSim将内核执行表示为一个warp级的tile图，其节点捕捉tile级操作，边编码数据和排序约束。利用这种表示，我们设计了一个自动tile图前端和一个图驱动的模拟后端。我们在代表性的GEMM、注意力机制和端到端LLM推理工作负载上评估了GTSim。在A100和H100上，针对传统和高度优化的内核，GTSim实现了高性能建模精度（MAPE，平均绝对百分比误差，1.22%至8.71%）。我们进一步将GTSim扩展到Blackwell并进行了初步验证，展示了其在分析软件和架构设计选择方面的有效性。

## Abstract
Modern LLM (large language model) workloads increasingly rely on optimized GPU kernels through hardware-software co-design. These kernels achieve high-performance through fine-grained dependency scheduling and computation-memory overlap. As such, they incur new challenges on existing GPU performance models. Instruction-driven simulators are costly to adapt to evolving architectures, while analytical models are too coarse to capture kernels' characteristics. We propose GPU-Tile-Sim, a tile-centric GPU simulation framework for LLM hardware-software co-design. The key insight is that modern LLM kernel performance is governed less by individual instruction latency than by the dependency structure that controls execution order and overlap. Accordingly, GTSim represents kernel execution as a warp-level tile graph whose nodes capture tile-level operations and whose edges encode data and ordering constraints. Using this representation, we design an automatic tile-graph frontend and a graph-driven simulation backend. We evaluate GTSim on representative GEMM, attention, and end-to-end LLM inference workloads. On A100 and H100 across both conventional and highly optimized kernels, GTSim achieves high performance-modeling accuracy (MAPE, Mean Absolute Percentage Error, 1.22%--8.71%). We further extend GTSim to Blackwell with preliminary validation, and demonstrate its effectiveness in analyzing software and architectural design choices.

### 2. 论文提出的方法论

GTSim的核心思想是：**现代GPU内核的性能由数据移动、计算和同步之间的依赖和重叠方式决定，而非由单条指令延迟决定**。基于此，它采用以warp为中心的tile图作为统一的中间表示，并设计了自动前端和图形驱动后端。

-   **核心思想：Warp-Centric Tile Graph**
    -   **节点**：代表一个warp或合作warp组（Warpgroup）执行的tile级操作（如“MMA”、“TMA_Load”、“Epilogue”）。每个节点包含操作类型、执行单元和目标tile的元数据（形状、数据类型、内存层级、布局等）。
    -   **边**：编码节点间的依赖关系。
        -   **数据边**：显式的生产者-消费者数据流关系。
        -   **顺序边**：非数据依赖的排序约束，如维持同一warp的程序顺序、warp间的显式同步（信号/等待）、软件流水线中的缓冲区重用约束等。
    -   该图天然地统一表示了**内核融合**、**warp专业化**和**软件流水线**等关键编程技术，只需通过改变节点执行组和依赖边即可，无需修改抽象本身。

-   **关键技术细节：两阶段工作流**
    -   **自动图前端**：从TileLang DSL的编译器IR自动构建tile图。过程包括：
        1.  **上下文恢复**：从IR的warp断言、循环结构、同步原语中提取warp角色、循环作用域、流水线阶段等。
        2.  **事件提取**：识别IR中的基本操作（如tensor core指令、TMA传输）并映射为tile图节点。
        3.  **语义构建**：通过类似静态单赋值的方式从IR的操作数和目标中推断节点描述符；显式添加因程序顺序和同步原语产生的顺序边。
    -   **图驱动模拟后端**：直接执行构建好的tile图，而非模拟指令流。
        -   **硬件建模**：采用**面向吞吐量**的抽象，而非逐周期流水线。模型包括计算单元（Tensor/CUDA Core）的吞吐量和延迟、内存系统（缓存、DRAM）的带宽和延迟以及片上网络（NoC）的简化带宽队列模型。TMA操作被建模为以特定速率注入128B请求的批量传输。
        -   **运行时调度**：
            -   每个SM的子分区维护一个就绪队列。节点就绪的条件是其所有入边（数据和顺序依赖）均已满足。
            -   调度器根据“贪婪-再-最旧”或轮询策略从队列中选取就绪节点。
            -   为提高并发度，计算节点会被分解为多个**子操作**，以流水线宽度和持续吞吐量为限注入计算流水线，允许多个warp重叠执行。
            -   节点完成后释放其出边，激活后继节点。threadblock（TB）中所有节点完成后，TB退役。

-   **算法/流程**：整个后端模拟是一个事件驱动的循环，核心流程为：TB调度器分配SM -> 初始化就绪节点入队 -> 调度器在资源可用时发射节点 -> 节点在计算或内存流水线中分解为子操作执行 -> 节点完成后更新依赖计数器，激活后继节点 -> 所有节点完成，释放SM资源，调度新TB。
