## 摘要
推理上下文长度与强化学习后训练之间的差距日益扩大：推理系统正接近百万令牌的上下文窗口，而后训练工作负载通常停留在256K令牌或更少，且部署时依赖长度泛化。这一差距对AI智能体尤为重要，其观察、工具输出、文档及先前的决策会随着长轨迹不断累积。LongStraw是一种在固定GPU预算下实现百万令牌强化学习后训练的架构感知执行栈，通过分组相对策略优化（GRPO）实例化。它无需自动微分即可评估共享提示，仅保留后续令牌所需的模型特定状态，并一次重放短响应分支，以额外的重放时间为代价缩减实时训练图。我们在混合递归与全注意力的Qwen3.6-27B以及压缩注意力混合专家模型GLM-5.2上实现了该方法。在八块H20 GPU上，LongStraw在2.1M位置完成分组Qwen评分和响应反向传播，支持2组和8组；增加组大小仅增加0.21 GB的峰值内存分配，而单独的极限测试达到4.46M位置。在32块H20 GPU上，我们对GLM-5.2的全部78层验证了2.1M令牌提示的端到端LongStraw执行路径。这些实验建立了执行能力，而非完整的训练正确性，因为捕获的提示状态是分离的，且部分分布式前向传播与梯度合成路径尚不完整。

## Abstract
A growing gap separates inference context lengths from RL post-training: inference systems are approaching million-token contexts, while post-training workloads often remain at 256K tokens or below and rely on length generalization at deployment. The gap is especially important for AI agents, whose observations, tool outputs, documents, and prior decisions accumulate over long trajectories. LongStraw is an architecture-aware execution stack for million-token RL post-training under a fixed GPU budget, instantiated with Group Relative Policy Optimization (GRPO). It evaluates the shared prompt without autograd, retains only model-specific state needed by later tokens, and replays short response branches one at a time, reducing the live training graph at the cost of additional replay time. We implement it for the hybrid recurrent and full-attention Qwen3.6-27B and the compressed-attention mixture-of-experts GLM-5.2. On eight H20 GPUs, LongStraw completes grouped Qwen scoring and response backward at 2.1M positions for groups of 2 and 8; increasing the group size adds only 0.21 GB of peak allocated memory, while a separate stress test reaches 4.46M positions. On 32 H20 GPUs, we validate the end-to-end LongStraw execution path for a 2.1M-token prompt across all 78 layers of GLM-5.2. These experiments establish execution capacity rather than complete training correctness because the captured prompt state is detached and some distributed forward and gradient composition paths remain incomplete.

### 2. 论文提出的方法论

LongStraw的核心思想是**分离长提示和短响应的计算图，以牺牲重计算时间为代价，换取显著降低的GPU内存占用峰值**。其关键技术细节如下：

- **捕获一次，重放后缀**：
  - **提示捕获阶段**：在不启用自动微分（autograd）的模式下，对共享的百万级token长提示进行一次前向计算。此过程仅保留后续响应生成所需的架构特定状态（如注意力层的KV缓存、循环层的状态、MLA潜在页面），并立即释放所有中间激活值。该状态被标记为“分离”，意味着其本身的参数梯度在后续不会被计算。
  - **响应重放阶段**：基于冻结的提示状态，依次为GRPO组内的每个短响应分支构建自动微分计算图，执行前向和反向传播，并累积梯度。处理完一个分支后立即释放其计算图，再处理下一个。这使得动态计算图的大小仅与响应长度相关，而非\(P + R\)。

- **GRPO训练依赖图的修改**：该方法改变了GRPO更新中梯度的计算边界。传统方法中，损失函数对参数的梯度包含提示状态\(\nabla_\theta z_P(\theta)\)的贡献（公式3）。LongStraw存储的是`stopgrad(z_P(θ))`，因此梯度仅来自响应分支，这是一个重要的理论取舍。

- **架构感知的状态清单与物理所有权**：
  - **Qwen (密集+循环/全注意力)**：对于48个GDN循环层，保留固定大小的循环状态；对于16个全注意力层，保留并物理化地分片存储KV缓存页面，确保释放未拥有分片的内存。
  - **GLM (稀疏注意力+MoE)**：将MLA和DSA索引器键页面存储在CPU内存中。在响应重放时，一次仅将一个层的所需页面暂存到GPU，执行计算后释放。同时，采用完整的层级检查点策略，避免在MoE的专家路由和计算过程中保留大量中间激活。

- **并行布局与所有权**：该方法明确分离了上下文并行（CP，用于分割长序列）和专家并行（EP，用于分割MoE专家）。例如，在GLM的32张GPU配置中，CP32和EP32共用了相同的32个worker，但它们解决的是完全不同的存储和通信问题。

### 3. 实验设计

  - **GLM-5.2**：一个结合了MLA、DSA和MoE的稀疏模型，使用 Rank-8 LoRA 微调。

### 6. 论文的主要结论与发现

- **核心发现**：在固定GPU预算下，**状态（tensor）的物理生命周期和所有权归属**是决定长上下文RL后训练实用边界的决定性因素，而非计算稀疏性或单个注意力核的效率。
- **可行性证明**：证明了通过将提示从自动微分图中分离并序列化响应计算，可以在8块H20 GPU上为Qwen模型完成超200万token上下文的GRPO执行，峰值内存仅约97.5 GB，且增加组数几乎不影响峰值内存。
- **架构无关性**：该方法在密集和MoE两种迥异的模型架构（Qwen和GLM）上都得到了实现和验证，证明了其核心思想（分离提示状态，重放响应）的通用性。
- **资源瓶颈的转移**：揭示了稀疏注意力（DSA）和MoE并未消除长上下文训练的内存瓶颈，而是将其转移到了索引计算、专家路由和中间激活的延迟回收上。LongStraw通过在计算后立即释放这些资源来解决问题。

### 7. 优点

- **问题定义清晰，创新性实用**：瞄准了一个关键且现实的应用瓶颈，即算力受限下的长上下文RL训练，提出了结构化、非单一算子的系统级解决方案。
- **透明的自我评估体系**：独创的四级证据标准为系统类论文的验证提供了范式，其坦诚地宣告“未达成”的方面，极大地增加了研究的科学严谨性。
- **架构感知的深度**：对两种完全不同类型模型（Qwen的混合循环/注意力和GLM的MLA/DSA/MoE）的内部结构、内存占用和通信模式进行了深入的剖析，并据此定制了状态存储和重放策略。
- **递进式的工程论证**：GLM部分的七阶段进展描述，清晰地展示了如何将一个会导致OOM的巨大问题，逐步分解为可定位、可解决的资源约束问题，具有很强的教学和工程参考价值。

### 8. 不足与局限

- **分布式梯度合成不完整**：这是最核心的技术局限。Qwen路径缺少模型并行的K/V梯度同步，GLM路径跳过了跨上下文并行（CP）的非专家参数梯度归约，导致两者都无法保证产生一个“数学上正确”的分布式模型更新。
- **提示状态梯度缺失**：此方法理论上的根本局限在于分离了提示状态\(\bar{z}_P\)，导致其损失了一部分来自提示的参数梯度\(\frac{\partial \ell}{\partial z_P}\frac{\partial z_P}{\partial \theta}\)，无法与传统全图训练在数值上等价。
- **工作负载是执行探针，非真实训练**：实验全部使用合成token和奖励，未涉及真实的策略采样、奖励模型（Reward Model）和环境交互，因此结论仅限于执行可行性，不能等同于在真实任务上完成了一个有效的RL训练迭代。
- **基础模型配置与上下文脱节**：实验中使用的模型原生最大位置编码（Qwen为262K，GLM为1M）低于测试的上下文长度（超过2M），论文未提供在此规模下的任务评估，因此无法判断模型本身是否能有效利用如此长的上下文信息。
- **实验结果缺乏广泛性**：实验仅验证了有限的几个上下文长度和组大小锚点（如Qwen的 G=2, G=8），并未形成关于时间、内存与这些变量之间关系的完整、可泛化的性能模型或参考曲线。
