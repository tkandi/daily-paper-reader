## 摘要
大语言模型（LLM）在多节点上的训练或推理对 GPU 显存和互连带宽带来了巨大压力。Compute Express Link (CXL) 共享内存池通过实现跨节点内存共享，提供了一种可扩展的解决方案，能够减少过度配置并提高资源利用率。我们提出了 CCCL，这是一个集合通信库，它利用 CXL 共享内存池来支持跨节点 GPU 操作，而无需依赖传统的基于 RDMA 的网络。我们的设计解决了在使用 CXL 共享内存池进行集合通信时面临的同步、数据交织和通信并行化等挑战。通过在配备 TITAN-II CXL 交换机和六块美光（Micron）CZ120 内存卡的多节点环境下进行评估，我们证明了 CCCL 能够在主机间实现高效的集合操作，展示了 CXL 在可扩展、以内存为中心的 GPU 通信方面的潜力。评估结果表明，与基于 200 Gbps InfiniBand 的原始 RDMA 实现相比，CCCL 在 AllGather、Broadcast、Gather 和 Scatter 操作上分别实现了 1.34 倍、1.84 倍、1.94 倍和 1.04 倍的平均性能提升。此外，LLM 训练案例的评估显示，与 InfiniBand 相比，其速度提升了 1.11 倍，同时在硬件生产成本上节省了 2.75 倍。

## Abstract
Large language models (LLMs) training or inference across multiple nodes introduces significant pressure on GPU memory and interconnect bandwidth. The Compute Express Link (CXL) shared memory pool offers a scalable solution by enabling memory sharing across nodes, reducing over-provisioning and improving resource utilization. We propose \name, a collective communication library, leveraging the CXL shared memory pool to support cross-node GPU operations without relying on traditional RDMA-based networking. Our design addresses the challenges on synchronization, data interleaving, and communication parallelization faced by using the CXL shared memory pool for collective communications. Evaluating on multiple nodes with a TITAN-II CXL switch and six Micron CZ120 memory cards, we show that \name achieves highly efficient collective operations across hosts, demonstrating CXL's potential for scalable, memory-centric GPU communication. Our evaluation demonstrates that \name achieves average performance improvements of 1.34$\times$ for AllGather, 1.84$\times$ for Broadcast, 1.94$\times$ for Gather, and 1.04$\times$ for Scatter, compared to the original RDMA-based implementation over 200 Gbps InfiniBand. \textcolor{dong}{In addition, the evaluation with a case of LLM training shows 1.11$\times$ speedup compared with the InfiniBand while saving production cost by $2.75\times$ in hardware.}

### CCCL：基于 CXL 内存池的跨节点 GPU 集合通信论文总结

#### 1. 核心问题与整体含义（研究动机和背景）
随着大语言模型（LLM）规模的爆炸式增长，分布式训练和推理对 GPU 间的集合通信（如 AllReduce, AllGather）提出了极高要求。目前主流方案依赖 NVIDIA NCCL 库配合 InfiniBand（IB）或 RoCE 等 RDMA 网络技术。然而，这些技术面临**基础设施成本高昂、软件栈复杂以及显存扩展性受限**等挑战。
本文提出了 **CCCL**，这是首个利用 **CXL（Compute Express Link）共享内存池**实现跨节点 GPU 集合通信的库。其核心动机是将 CXL 内存池视为一种高性能互连织物，利用其直接的负载/存储（Load/Store）语义简化数据交换，从而替代或增强传统的 RDMA 网络。

#### 2. 方法论：核心思想与关键技术
CCCL 的核心思想是将集合通信转化为对共享 CXL 内存池的读写操作，并针对 CXL 硬件特性解决了三大挑战：
*   **带宽聚合（软件级交织）：** 针对 CXL 内存池缺乏硬件级缓存行交织的问题，CCCL 设计了软件控制的数据放置策略。通过公式计算 `device_index`（目标设备）和 `device_location`（内存偏移），将不同 Rank 的数据均匀分布在多个 CXL 设备上，避免访问热点。
*   **异步与重叠（Fine-grained Chunking）：** 为了打破“先写后读”的严格串行限制，CCCL 将大块数据切分为细粒度的分片（Chunks），并为每个 Rank 创建独立的 `writeStream` 和 `readStream`。这使得生产者 Rank 在写入后续分片时，消费者 Rank 可以并行读取已就绪的前序分片。
*   **轻量级锁机制（Doorbell 机制）：** 针对跨节点同步难题，CCCL 在 CXL 内存中预分配了“门铃”缓冲区。通过简单的索引计算实现信号量同步：生产者完成写入后将状态置为 `READY` 并刷新缓存；消费者通过轮询和缓存行刷新（CLFLUSH）确保观察到最新数据，避免了昂贵的传统分布式锁开销。

*   **扩展性测试：** 由于硬件限制，作者通过**仿真模拟**了 6 节点和 12 节点的扩展性表现。

#### 6. 主要结论与发现
*   **性能超越 IB：** 在 200 Gbps IB 环境下，CCCL 在 AllGather 上平均提升 1.34x，Broadcast 提升 1.84x，Gather 提升 1.94x。
*   **LLM 训练增益：** 在 Llama-3-8B 训练中，CCCL 相比 IB 实现了 **1.11x 的端到端加速**。
*   **成本优势巨大：** 相比 IB 方案，CXL 方案在提供更高性能的同时，硬件生产成本降低了 **2.75x**（主要得益于 CXL 交换机相比 IB 交换机的价格优势）。
*   **带宽利用：** 软件交织策略能有效聚合多个 CXL 设备的带宽，克服了单设备 PCIe 带宽的限制。

#### 7. 优点
*   **架构创新：** 首次将 CXL 共享内存池应用于 GPU 集合通信，开辟了除 RDMA 之外的新路径。
*   **软硬结合：** 针对 CXL 2.0/3.0 硬件尚不完善的现状（如缺乏硬件一致性），通过软件手段（Doorbell + CLFLUSH）巧妙解决了同步问题。
*   **高性价比：** 证明了在数据中心内部，CXL 可以作为一种更廉价且性能更优的互连替代方案。

#### 8. 不足与局限
*   **节点规模受限：** 物理实验仅在 3 个节点上完成，虽然有仿真支持，但在超大规模集群（如千卡/万卡）中的竞争冲突和延迟表现尚待验证。
*   **AllReduce 优化空间：** 在 AllReduce 操作中，由于无法像 IB 环形算法那样复用中间结果，CCCL 在超大消息下的优势不明显（仅 1.05x）。
*   **硬件依赖：** 依赖特定的 CXL 2.0/3.0 交换机和设备，目前这些硬件的普及率远低于 InfiniBand。
*   **缓存一致性开销：** 依赖手动刷新缓存行来保证可见性，这在某些高频小包通信场景下可能引入额外开销。
