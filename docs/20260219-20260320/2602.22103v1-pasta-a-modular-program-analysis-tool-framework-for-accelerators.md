## 摘要
现代计算系统中硬件加速器日益增长的复杂性和多样性，要求具备灵活且低开销的程序分析工具。我们提出了 PASTA，一个低开销且模块化的面向加速器的程序分析工具框架。PASTA 对底层分析 API 和多种深度学习框架进行了抽象，为用户提供了一个统一的接口，用于捕获和分析多个层级的运行时事件。其可扩展的设计使研究人员和从业者能够以极低的开销快速构建自定义工具原型。我们通过开发多个分析工具展示了 PASTA 的实用性，包括深度学习工作负载特征分析工具和 UVM 优化工具。通过在单 GPU 和多 GPU 场景下对 NVIDIA 和 AMD GPU 上的主流深度学习工作负载进行广泛评估，我们证明了 PASTA 的广泛适用性。在 NVIDIA GPU 上，我们进一步展示了 PASTA 能够提供详细的性能洞察，且开销显著降低，得益于其 GPU 加速后端，其速度比传统分析工具快高达 1.3*10^4 倍。PASTA 在易用性、可扩展性和效率之间取得了实际的平衡，使其非常适合现代基于加速器的计算环境。

## Abstract
The increasing complexity and diversity of hardware accelerators in modern computing systems demand flexible, low-overhead program analysis tools. We present PASTA, a low-overhead and modular Program AnalysiS Tool Framework for Accelerators. PASTA abstracts over low-level profiling APIs and diverse deep learning frameworks, offering users a unified interface to capture and analyze runtime events at multiple levels. Its extensible design enables researchers and practitioners to rapidly prototype custom tools with minimal overhead. We demonstrate the utility of PASTA by developing several analysis tools, including a deep learning workload characterization tool and a UVM optimization tool. Through extensive evaluation on mainstream deep learning workloads tested on NVIDIA and AMD GPUs under both single- and multi-GPU scenarios, we demonstrate PASTA's broad applicability. On NVIDIA GPUs, we further show that PASTA provides detailed performance insights with significantly lower overhead, up to 1.3*10^4 faster than conventional analysis tools, thanks to its GPU-accelerated backend. PASTA strikes a practical balance between usability, extensibility, and efficiency, making it well-suited for modern accelerator-based computing environments.

随着摩尔定律接近物理极限，GPU、TPU 等硬件加速器成为计算引擎的核心。然而，加速器的高并发性和与 CPU 的异步交互使得性能分析变得极其复杂。
*   **现有工具局限性**：厂商提供的工具（如 NVIDIA Nsight, AMD ROCm Profiler）通常灵活性差、扩展性不足，且难以关联深度学习（DL）框架（如 PyTorch, TensorFlow）的高层语义（如张量分配、算子边界）。
*   **分析开销巨大**：传统的细粒度分析工具（如内存追踪）往往导致程序运行速度下降数千倍，严重阻碍了大规模负载的调试。
*   **PASTA 的目标**：提供一个低开销、模块化、跨厂商（支持 NVIDIA 和 AMD）的框架，能够同时捕获底层硬件事件和高层 DL 框架事件，并支持快速原型化自定义分析工具。

#### 2. 方法论：核心思想与关键技术
PASTA 采用三层模块化架构，核心思想是将分析逻辑从 CPU 卸载到 GPU，实现“原位分析”。
*   **PASTA 事件处理器（Event Handler）**：抽象了不同厂商的底层 API（如 NVIDIA Compute Sanitizer, NVBit, AMD ROCprofiler-SDK）和 DL 框架回调，提供统一的事件接口（如内核启动、内存拷贝、张量分配）。
*   **PASTA 事件处理引擎（Event Processor）**：
    *   **GPU 加速分析**：这是其低开销的关键。传统工具将追踪数据传回 CPU 处理，而 PASTA 利用 GPU 线程并发处理生成的追踪数据，避免了频繁的 CPU-GPU 通信和 CPU 端的处理瓶颈。
    *   **标准化接口**：将异构的运行时信息转化为统一格式，分发给上层工具。
*   **PASTA 工具集（Tool Collection）**：提供模板供用户开发自定义工具。
*   **关键功能**：
    *   **跨层调用栈追踪**：能够同时关联 Python 代码行、C++ 库调用和底层 CUDA/HIP 内核。
    *   **范围特定分析**：支持通过 Python 注解（`pasta.start/stop`）或环境变量指定分析特定的内核范围或模型层。

#### 6. 主要结论与发现
*   **极致性能**：在 NVIDIA GPU 上，PASTA 的分析速度比传统 CPU 驱动的分析工具快 **941 倍至 13,000 倍**。

*   **跨平台一致性**：证明了 PASTA 能在 NVIDIA 和 AMD GPU 上提供一致的分析体验，并揭示了两者在算子融合和内存管理上的细微差异。

#### 7. 优点
*   **模块化与可扩展性**：用户只需重写少量函数即可开发新工具，无需深入了解底层驱动 API。
*   **极低开销**：通过 GPU 驻留分析模型，解决了细粒度分析工具无法用于大规模实际负载的痛点。
*   **全栈可见性**：打通了从 Python 业务逻辑到硬件指令执行的黑盒，对系统研究人员极具价值。
*   **开源友好**：完全开源并提供详细文档。

#### 8. 不足与局限
*   **硬件依赖**：虽然支持 NVIDIA 和 AMD，但仍依赖于厂商提供的底层插桩 API（如 Sanitizer API），如果硬件厂商不开放这些接口，PASTA 将难以适配。
*   **内存占用**：虽然分析开销低，但 PASTA 自身仍需占用少量 GPU 显存（约 4MB）用于存储分析元数据，在极端显存受限的情况下可能存在微小干扰。
*   **算力平台覆盖**：目前尚未提及对 Intel GPU (oneAPI) 或华为昇腾等其他国产加速器的支持情况。
