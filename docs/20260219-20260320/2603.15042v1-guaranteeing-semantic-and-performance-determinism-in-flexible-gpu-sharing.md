## 摘要
GPU 共享对于最大化现代数据中心的硬件利用率至关重要。然而，现有方法面临着明显的权衡：粗粒度的时间复用会导致交互式服务的尾延迟剧增，而细粒度的空间分区通常需要侵入性的内核修改，从而损害了行为等效性。我们提出了 DetShare，这是一种优先考虑确定性和透明度的新型 GPU 共享系统。DetShare 确保了语义确定性（未修改的内核产生相同的结果）和性能确定性（可预测的尾延迟），同时保持了完全的透明度（零代码修改）。DetShare 引入了 GPU 协程（GPU coroutines），这是一种将逻辑执行上下文与物理 GPU 资源解耦的新抽象。这种解耦通过轻量级的上下文迁移实现了灵活、细粒度的资源分配。我们的评估表明，与时间共享相比，DetShare 将训练吞吐量提高了高达 79.2%。在混部场景下，它的表现优于最先进的基准方案，在不损失吞吐量的情况下将 P99 尾延迟降低了 15.1%。此外，通过感知负载的放置和我们的 TPOT-First 调度策略，DetShare 相比默认策略将平均推理延迟降低了 69.1%，并将每个输出 Token 的时间（TPOT）SLO 违规减少了 21.2%。

## Abstract
GPU sharing is critical for maximizing hardware utilization in modern data centers. However, existing approaches present a stark trade-off: coarse-grained temporal multiplexing incurs severe tail-latency spikes for interactive services, while fine-grained spatial partitioning often necessitates invasive kernel modifications that compromise behavioral equivalence.   We present DetShare, a novel GPU sharing system that prioritizes determinism and transparency. DetShare ensures semantic determinism (unmodified kernels yield identical results) and performance determinism (predictable tail latency), all while maintaining complete transparency (zero code modification). DetShare introduces GPU coroutines, a new abstraction that decouples logical execution contexts from physical GPU resources. This decoupling enables flexible, fine-grained resource allocation via lightweight context migration.   Our evaluation demonstrates that DetShare improves training throughput by up to 79.2% compared to temporal sharing. In co-location scenarios, it outperforms state-of-the-art baselines, reducing P99 tail latency by 15.1% without compromising throughput. Furthermore, through workload-aware placement and our TPOT-First scheduling policy, DetShare decreases average inference latency by 69.1% and reduces Time-Per-Output-Token (TPOT) SLO violations by 21.2% relative to default policies.

### 1. 核心问题与研究动机
*   **核心问题**：现代数据中心 GPU 利用率普遍较低（通常低于 30%），但现有的 GPU 共享技术存在严重的权衡：
    *   **时间分片（Temporal Sharing）**：虽然隔离性好，但在任务切换时会产生巨大的尾延迟，且无法利用显存带宽受限阶段的空闲算力。
    *   **空间划分（Spatial Sharing）**：虽然利用率高，但现有方案（如 LithOS）往往需要修改内核代码（Kernel Atomization），这会导致**语义非确定性**（由于浮点数加法不满足结合律或 Batch Size 改变导致的数值偏差）和高昂的**工程成本**（需手动重写内核）。
*   **研究动机**：在不修改任何用户代码（透明性）的前提下，同时保证**语义确定性**（计算结果与独占时一致）和**性能确定性**（满足 SLO 尾延迟要求）。

### 2. 方法论：GPU 协程（GPU Coroutines）
DetShare 的核心思想是**逻辑执行上下文与物理资源的彻底解耦**。
*   **关键抽象**：引入 **GPU 协程**，将其分为：
    *   **虚拟上下文 (vCtx)**：面向应用，封装逻辑执行状态，对用户透明。
    *   **物理上下文 (pCtx)**：面向硬件，具有固定的 SM（流处理器）配额。
*   **关键技术细节**：
    *   **动态绑定与迁移**：系统维护一个预先配置好的 pCtx 池（不同 SM 比例）。当调度器检测到高优先级任务或资源碎片时，通过“迁移即让步（migrate-to-yield）”机制，将 vCtx 重新绑定到不同的 pCtx，而无需修改内核参数。
    *   **常驻控制内核 (RCK)**：在每个 pCtx 中注入一个极轻量级的单线程内核，作为设备端的信号处理器，实现低延迟的协作式抢占。
    *   **状态管理优化**：为了降低迁移开销，采用了**细粒度工作集追踪**、**基于内省的输入分析**和**按需延迟复制（Lazy Copying）**，仅迁移必要的内存页面。
    *   **可扩展调度框架**：支持插件化策略，如 **SLO-Aware**（针对混合负载）和 **TPOT-First**（针对 LLM 推理，优先保证 Token 生成速度）。

*   **完全透明**：无需修改内核代码或模型架构，通过 `LD_PRELOAD` 拦截 API 即可运行，极大地降低了部署门槛。

### 8. 不足与局限
*   **硬件依赖**：该系统高度依赖 NVIDIA 的特定硬件特性（如 Green Contexts 和 MPS），在 AMD 或其他国产算力芯片上的可移植性尚未验证。

*   **显存限制**：虽然实现了算力（SM）的动态划分，但对于显存容量的动态硬隔离（非地址空间隔离）提及较少，在显存极度紧张时可能触发 OOM 风险。
