## 摘要
为了经济高效地部署大型混合专家（MoE）模型，基于卸载的单 GPU 异构推理至关重要。虽然卸载冷专家的 GPU-CPU 架构受限于主机内存带宽，但新兴的 GPU-NDP 架构利用 DIMM-NDP 来卸载非热点专家。然而，非热点专家并非同质的内存受限群体：存在一个显著的温专家子集，它们受到高 GPU I/O 延迟的严重影响，但能够使 NDP 计算吞吐量达到饱和，从而暴露了关键的计算缺口。我们提出了 TriMoE，这是一种新型的 GPU-CPU-NDP 架构，通过协同利用支持 AMX 的 CPU，将热、温、冷专家精确映射到其最佳计算单元，从而填补了这一缺口。我们还引入了一种瓶颈感知的专家调度策略和一种预测驱动的动态重布局/重平衡方案。实验表明，TriMoE 相比现有最先进的解决方案实现了高达 2.83 倍的加速。

## Abstract
To deploy large Mixture-of-Experts (MoE) models cost-effectively, offloading-based single-GPU heterogeneous inference is crucial. While GPU-CPU architectures that offload cold experts are constrained by host memory bandwidth, emerging GPU-NDP architectures utilize DIMM-NDP to offload non-hot experts. However, non-hot experts are not a homogeneous memory-bound group: a significant subset of warm experts exists is severely penalized by high GPU I/O latency yet can saturate NDP compute throughput, exposing a critical compute gap. We present TriMoE, a novel GPU-CPU-NDP architecture that fills this gap by synergistically leveraging AMX-enabled CPU to precisely map hot, warm, and cold experts onto their optimal compute units. We further introduce a bottleneck-aware expert scheduling policy and a prediction-driven dynamic relayout/rebalancing scheme. Experiments demonstrate that TriMoE achieves up to 2.83x speedup over state-of-the-art solutions.

### TriMoE 论文深度总结

#### 1. 论文的核心问题与整体含义（研究动机和背景）
随着混合专家模型（MoE）规模的剧增（如 DeepSeek-V2），单 GPU 显存已无法容纳全部参数，因此“卸载（Offloading）”技术成为低成本推理的关键。
*   **研究动机**：现有的卸载方案主要分为 GPU-CPU（受限于主机内存带宽）和 GPU-NDP（近数据处理，受限于 NDP 的计算能力）。
*   **核心发现**：作者发现非热点专家并非同质。除了极少数“热专家”和长尾的“冷专家”外，存在约 30% 的**“温专家（Warm Experts）”**。
*   **痛点**：温专家如果放在 GPU，由于 Token 数量不足以掩盖 PCIe 传输延迟，会导致 GPU 频繁停顿；如果放在 NDP，则会迅速耗尽其有限的计算资源。这种“计算缺口”导致现有二元划分方案（GPU-NDP）效率低下。

#### 2. 论文提出的方法论：TriMoE 架构
TriMoE 提出了**GPU-CPU-NDP 三级异构架构**，核心思想是将专家按活跃度精准匹配到最合适的计算单元：
*   **三级映射策略**：
    *   **热专家（Hot）**：驻留在 GPU HBM 中，利用其峰值吞吐量。
    *   **温专家（Warm）**：映射到支持 **AMX（高级矩阵扩展）** 的 CPU 上。利用 CPU 直接访问内存的特性绕过 PCIe 瓶颈，并利用 AMX 提供的数十 TFLOPS 算力填补计算缺口。
    *   **冷专家（Cold）**：卸载到 **DIMM-NDP**。利用内存条内部极高的聚合带宽处理内存受限的任务。
*   **关键技术细节**：
    *   **瓶颈感知调度（Bottleneck-Aware Scheduling）**：基于成本模型（考虑计算耗时、PCIe 传输、DRAM 访问冲突等），先进行贪心初始分配，再通过迭代精细化调整，最小化全局完成时间（Makespan）。
    *   **预测驱动的动态重布局与重平衡**：引入轻量级指数移动平均（EMA）预测器，预测专家负载。利用 **DIMM-Link**（一种主机无关的内存间传输总线）在后台异步执行数据重布局（条带化 vs 本地化）和冷专家迁移，解决 NDP 负载不均问题。

*   **实验规模**：涵盖了三种主流超大规模 MoE 模型，测试了 256 到 768 的不同 Batch Size。

*   **性能提升**：TriMoE 在解码阶段相比最强基准实现了 **2.12–2.83 倍** 的加速，端到端吞吐量提升了 **2.09–2.78 倍**。

#### 7. 优点
*   **视角独特**：首次识别并形式化了 MoE 推理中的“温专家”类别，指出了现有二元卸载模型的局限。
*   **架构创新**：巧妙地将现代 CPU 的 AMX 加速能力引入 MoE 推理链路，而非仅仅将其视为内存控制器。
*   **软硬协同**：结合了硬件层面的 DIMM-Link 和软件层面的预测调度算法，系统性地解决了数据布局冲突。

#### 8. 不足与局限
*   **硬件依赖性**：TriMoE 依赖于 DIMM-NDP 和 DIMM-Link 等非标准硬件扩展，目前这些硬件多处于模拟或原型阶段，大规模商业化部署存在门槛。
