## 摘要
参数高效微调（PEFT）被广泛应用于数据中心大语言模型（LLM）定制化微调 API 的后端。服务提供商通常为每个 PEFT 任务部署独立的实例，这导致了显著的资源低效，包括：（1）小规模 PEFT 原生算子导致的 GPU 利用率不足，以及（2）并行执行中通信延迟和数据依赖导致的设备停顿。为解决这些问题，本文提出了 MuxTune，一个能够实现多个 PEFT 任务资源高效并发执行的微调系统。其核心思想是以时空复用的方式在独立任务间共享主干网络，以提高利用率并减少停顿。基于通过统一 PEFT 表示实现的灵活、模块化主干网络共享，MuxTune 提出了包含任务、算子和数据级优化的分层协同调度方案。具体而言，它通过空间和时间复用的混合方式融合任务，并以两层混合并行模式编排多任务算子的执行。此外，MuxTune 采用基于块的数据对齐来减少任务间的无效 token。实验结果表明，与三种最先进的基准方案相比，MuxTune 实现了高达 2.33 倍的吞吐量提升和 5.29 倍的内存占用降低。

## Abstract
Parameter-Efficient Fine-Tuning (PEFT) is widely applied as the backend of fine-tuning APIs for large language model (LLM) customization in datacenters. Service providers deploy separate instances for individual PEFT tasks, giving rise to prominent resource inefficiencies, including (1) GPU underutilization from small-scale, PEFT-native operators and (2) device stalls from communication delays and data dependencies in parallelized execution. To address these issues, this paper presents MuxTune, a fine-tuning system that enables resource-efficient concurrent execution of multiple PEFT tasks. The key idea is to multiplex the backbone across independent tasks in a spatial-temporal manner for improved utilization and reduced stalls. Building on flexible, modularized backbone sharing via unified PEFT representations, MuxTune proposes hierarchical co-scheduling scheme with task, operator, and data-level optimizations. Specifically, it fuses tasks through a hybrid of spatial and temporal multiplexing, and orchestrates multi-task operator execution in two-tiered hybrid parallelism. Additionally, MuxTune employs chunk-based data alignment to mitigate inter-task ineffective tokens. Experimental results demonstrate that MuxTune achieves up to $2.33\times$ higher throughput and $5.29\times$ memory reduction compared to three state-of-the-art baselines.

### 1. 核心问题与整体含义（研究动机和背景）
随着大语言模型（LLM）定制化需求的激增，云服务商通过 API 提供参数高效微调（PEFT，如 LoRA）服务。然而，现有的 PEFT 框架在多租户数据中心面临严重的资源低效问题：
*   **GPU 利用率低**：PEFT 算子（如 LoRA 的低秩投影）规模极小，难以填满现代 GPU（如 H100）的计算能力；且微调任务通常 batch size 较小、序列较短。
*   **设备停顿（Stalls）**：在模型并行执行时，通信延迟和算子间的数据依赖导致严重的流水线气泡（Bubbles），且 PEFT 缺少权重梯度计算，无法直接复用传统的“零气泡”调度技术。
*   **内存浪费**：为每个任务部署独立实例会导致主干网络（Backbone）参数的冗余存储。

**MuxTune** 的核心目标是通过**时空主干网络复用（Spatial-Temporal Backbone Multiplexing）**，在单一主干网络上高效并发执行多个独立的 PEFT 任务。

### 2. 方法论：核心思想与关键技术
MuxTune 提出了一个分层协同调度框架，主要包含以下四个关键技术：

*   **模块化主干网络共享（Modularized Backbone Sharing）**：
    *   将 PEFT 抽象为四个子模块：BaseOp（主干算子）、Adapter（适配器）、Dispatch（分发规则）和 Aggregate（聚合规则）。
    *   通过动态钩子（Hook）机制实现适配器与主干网络的解耦，支持任务在运行时动态加入或退出，无需重新初始化模型。
*   **任务融合（Task Fusion）与混合任务（hTask）抽象**：
    *   **核心思想**：在空间维度（Batching）提升利用率，在时间维度（Interleaving）隐藏停顿。
    *   **算法**：利用动态规划（DP）算法，根据任务的 Token 数量、算子延迟和内存约束，将多个任务划分为若干个“混合任务（hTask）”。hTask 内部任务空间合并，hTask 之间时间交错执行。
*   **算子编排（Operator Orchestration）**：
    *   **两层调度**：在流水线并行（Inter-stage）层面，通过结构化模板交错执行不同 hTask 的微批次；在张量并行（Intra-stage）层面，采用基于优先级的子图调度算法，实现计算与通信的深度重叠。
*   **块级数据对齐（Chunk-based Data Alignment）**：
    *   针对多任务序列长度不一的问题，先进行任务内打包（Packing），再将长序列切分为固定大小的块（Chunk）。这种方式既减少了任务间的无效填充（Padding），又通过 KV Cache 复用保证了计算效率。

*   **实用性**：非侵入式设计，支持动态任务挂载，非常适合云服务商的微调 API 场景。

### 8. 不足与局限
*   **主干网络同质化假设**：MuxTune 要求复用的任务必须基于相同的主干网络（如都是 LLaMA-7B）。如果用户需求高度碎片化（涉及大量不同基座模型），复用效率会下降。
*   **调度算法开销**：虽然 DP 算法在任务数较少时很快，但如果单实例挂载的任务数量达到极大规模，调度计算可能成为瓶颈。
*   **Padding 依然存在**：虽然块级对齐减少了 Padding，但在块内部若序列长度不整除，仍会有少量无效计算。
