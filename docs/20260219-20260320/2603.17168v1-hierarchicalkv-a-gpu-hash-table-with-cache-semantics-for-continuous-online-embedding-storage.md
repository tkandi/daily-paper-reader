## 摘要
传统的 GPU 哈希表会保留每一个插入的键——这种“字典假设”在嵌入表规模经常超过单 GPU 容量的情况下，会浪费稀缺的高带宽内存（HBM）。我们通过引入缓存语义挑战了这一假设，将基于策略的驱逐（eviction）视为一等操作。我们提出了 HierarchicalKV (HKV)，这是首个通用的 GPU 哈希表库，其在满容量下的正常运行契约遵循缓存语义：每个满桶的 upsert（更新或插入）操作通过就地驱逐或拒绝准入来解决，而非通过重新哈希（rehashing）或因容量不足而报错。HKV 协同设计了四种核心机制：缓存行对齐桶、内联分数驱动的 upsert、基于分数的动态双桶选择以及三组并发，并利用分层键值分离技术实现了超越 HBM 的容量扩展。在 NVIDIA H100 NVL GPU 上，HKV 实现了高达每秒 39 亿个键值对（B-KV/s）的查找吞吐量，且在 0.50-1.00 的负载因子范围内表现稳定（波动小于 5%）；其查找吞吐量比 WarpCore（在 lambda=0.50 时最强的字典语义 GPU 基准）高出 1.4 倍，比基于间接寻址的 GPU 基准高出 2.6 至 9.4 倍。自 2022 年 10 月开源发布以来，HKV 已被集成到多个开源推荐框架中。

## Abstract
Traditional GPU hash tables preserve every inserted key -- a dictionary assumption that wastes scarce High Bandwidth Memory (HBM) when embedding tables routinely exceed single-GPU capacity. We challenge this assumption with cache semantics, where policy-driven eviction is a first-class operation. We introduce HierarchicalKV (HKV), the first general-purpose GPU hash table library whose normal full-capacity operating contract is cache-semantic: each full-bucket upsert (update-or-insert) is resolved in place by eviction or admission rejection rather than by rehashing or capacity-induced failure. HKV co-designs four core mechanisms -- cache-line-aligned buckets, in-line score-driven upsert, score-based dynamic dual-bucket selection, and triple-group concurrency -- and uses tiered key-value separation as a scaling enabler beyond HBM. On an NVIDIA H100 NVL GPU, HKV achieves up to 3.9 billion key-value pairs per second (B-KV/s) find throughput, stable across load factors 0.50-1.00 (<5% variation), and delivers 1.4x higher find throughput than WarpCore (the strongest dictionary-semantic GPU baseline at lambda=0.50) and up to 2.6-9.4x over indirection-based GPU baselines. Since its open-source release in October 2022, HKV has been integrated into multiple open-source recommendation frameworks.

*   **核心问题**：传统的 GPU 哈希表遵循“字典语义”（Dictionary Semantics），即必须保留所有插入的键。但在现代推荐系统（RecSys）中，嵌入表（Embedding Tables）规模巨大，经常超过单张 GPU 的显存（HBM）容量。
*   **研究动机**：
    *   **容量瓶颈**：当负载因子（Load Factor, $\lambda$）接近 1.0 时，传统哈希表的探测链变长，性能急剧下降，最终必须重新哈希（Rehash）或报错，这在持续在线训练场景下不可接受。
    *   **语义错位**：嵌入表访问通常遵循幂律分布，更适合建模为“缓存”而非“字典”。
    *   **设计空白**：现有的 GPU 哈希表缺乏内置的、高性能的逐出（Eviction）机制。

### 2. 方法论：HierarchicalKV (HKV)
HKV 的核心思想是将**缓存语义**作为一等公民，通过四种协同设计的机制实现满容量下的高性能运行：

*   **缓存行对齐桶（Cache-line-aligned Buckets）**：
    *   将每个桶的大小固定为 128 个槽位，每个槽位存储 1 字节的摘要（Digest）。
    *   128 字节正好对应 NVIDIA GPU 的一个 L1 缓存行。通过一次内存事务即可加载整个桶的摘要，实现“确定性未命中”检测，避免了变长探测。
*   **内联分数驱动的 Upsert（In-line Score-driven Upsert）**：
    *   将分数比较、准入控制和 CAS（比较并交换）提交直接融合在插入路径中。
    *   当桶满时，直接在桶内寻找最小分数项进行就地替换，无需额外的逐出数据结构或复杂的后台管理。
*   **基于分数的动态双桶选择（Score-based Dynamic Dual-bucket Selection）**：
    *   扩展了“两人选一”（Power-of-two-choices）范式。在负载较低时选择空闲桶；在负载达到 1.0 时，比较两个候选桶的最小分数，逐出分数更低的那一项，从而显著提升高价值条目的保留率。
*   **三组并发控制（Triple-group Concurrency）**：
    *   将操作分为：读取者（Reader）、更新者（Updater，仅改值）和插入者（Inserter，涉及结构变更）。
    *   通过 CPU-GPU 双层锁协调，允许读取和更新并发执行，仅在发生结构性变更（如逐出）时才需要排他性访问。
*   **分层键值分离（Tiered KV Separation）**：
    *   键、摘要和分数保留在 HBM 中，而大尺寸的嵌入向量（Value）可以溢出到主机内存（HMEM），通过位置寻址避免存储指针。
