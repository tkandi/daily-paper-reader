# SARAM: Sparse Adapter Allocation with Reuse and Merging for Lifelong Robot Learning 

SeongJun Jeong 1, Chungwoo Lee 1, Gi-Cheon Kang 2∗, and Byoung-Tak Zhang 1∗

Abstract — Lifelong robot learning requires acquiring new tasks sequentially without forgetting earlier ones. With large pre-trained vision-language-action (VLA) backbones, adapter-based methods e ff ectively mitigate this challenge. However, their task-specific adapters and selection modules accumulate with the task stream, creating a scalability challenge in on-disk storage and deployment cost under fixed onboard resource budgets. We propose SARAM, a lifelong learning framework that limits storage growth while keeping GPU memory and per-step inference cost independent of the task stream length. For each new task, SARAM reuses frozen adapters from previous tasks and introduces new adapters only at sparsely selected layers, with a duplication penalty encouraging them to capture information not already represented by the adapter library. At deployment, a compact signature derived from backbone activation statistics identifies the task once per episode, and the corresponding task update is merged into the backbone, leaving only the backbone in the control loop. Across four LIBERO suites, SARAM matches or exceeds adapter-based baselines while adding up to 4.5× less on-disk state per task. GPU memory usage and control frequency remain comparable to those of the backbone as the task stream grows. Experiments on a real UR5 arm with a di ff erent backbone further demonstrate retention throughout a sequential task stream. 

I. INTRODUCTION Robots deployed in real environments need to learn new tasks continually [1], yet onboard hardware imposes fixed budgets on storage, memory, and compute. Learning tasks sequentially causes catastrophic forgetting [2], [3], where acquiring a new task degrades performance on previously learned ones. Existing approaches address this through re-play, regularization, or architectural isolation, which re-quire storing past demonstrations, provide weaker protection against forgetting, or leave progressively less free capacity for new tasks, respectively [4]–[7]. With large pre-trained vision-language-action (VLA) backbones [8]–[10], recent methods [11]–[13] increasingly adopt lightweight adapters such as LoRA [14]. The backbone remains frozen, while each task learns its own adapters, which are then frozen so that later training cannot overwrite them. By freezing the back-bone and task-specific adapters, these methods e ff ectively preserve previously learned tasks.

However, task-specific adapters must be selected at de-ployment, and the oracle task ID is typically unavailable. In-stead, the robot receives the current observation and language instruction, from which the appropriate task-specific adapter must be identified. Recent methods [12], [13] dynamically select task-specific adapters from the current input during execution. By design, the adapters and selection modules therefore remain active in the control loop, increasing GPU memory and per-step computation as tasks accumulate. As illustrated in Fig. 1, this accumulation appears along two axes. During training, task-specific adapters, selection modules, and associated state accumulate on disk as new tasks are learned. At deployment, the adapters and selection modules must remain available on the GPU and are used throughout the control loop. Both axes therefore grow with the task stream, conflicting with the fixed resource budgets of onboard robot hardware. Can a VLA policy learn new tasks continually while keeping its deployment cost independent of the task stream and limiting task-dependent storage growth? 

To address this, we propose SARAM, a lifelong robot learning method that addresses the two axes at their respec-tive stages: storage as tasks accumulate, and deployment cost at execution. During learning, each new task first reuses a linear combination of frozen LoRA adapters from previous tasks, then adds new adapters only at layers selected under a sparsity penalty. A duplication penalty discourages the new adapters from reproducing what the reused library already arXiv:2610.24804v1 [cs.RO] 17 Oct 2026 expresses. The newly allocated adapters and combination coe ffi cients are frozen after training, so later tasks cannot overwrite previously learned parameters. Because every per-task update stays linear in the weights, it can later be folded into the backbone rather than evaluated as a separate module. SARAM then removes task selection from the control loop. After each task is learned, the demonstrations are passed through the adapter-free backbone and its layer-wise activation statistics are summarized into a compact task signature. These frozen-backbone statistics provide task-dependent signatures without requiring a learned selection module. At deployment, the initial observation and instruc-tion are summarized in the same way, matched against the stored signatures, and the selected update is merged into the backbone before execution. The episode therefore runs on a single backbone, with no task-specific adapter or selection module inside the control loop, keeping GPU memory and per-step inference cost at the backbone’s level regardless of the number of learned tasks. We evaluate SARAM on four LIBERO suites against adapter-based methods [12], [13] and standard continual learning baselines. SARAM attains the highest final success rate and AUC on all four suites while requiring up to 4 .5×

less on-disk state per task than adapter-based baselines. At deployment, SARAM remains at the backbone’s level in both GPU memory and control frequency: after ten tasks it runs at 15.2 Hz with 748 MB of GPU memory, identical to the backbone alone. By contrast, CLARE and DMPEL grow to 922 MB and 829 MB of GPU memory and slow to 10.1 Hz and 5.0 Hz after ten tasks, respectively. On a seven-task real-robot stream with a di ff erent VLA backbone, SARAM ends the stream at the same success rate it reached when each task was learned, showing that the method transfers to a physical robot and a di ff erent backbone architecture. We summarize our contributions as follows:  

> •

We propose SARAM, an adapter-based lifelong robot learning method that limits per-task storage through adapter reuse, sparse allocation, and compact task sig-natures in place of learned selection modules.  

> •

At deployment, task signatures move selection outside the control loop, and the corresponding task update is merged into the backbone to keep GPU memory and per-step inference cost independent of the number of learned tasks.  

> •

On four LIBERO suites, SARAM attains the highest final success rate and AUC while requiring up to 4 .5×

less on-disk state per task, and real-robot experiments with a di ff erent VLA backbone demonstrate applicabil-ity beyond simulation. II. RELATED WORK 

Lifelong Robot Learning. Lifelong robot learning [1], [15] studies how robots can learn new tasks sequentially while retaining those learned before. A central challenge, shared with continual learning in general [3], is catastrophic for-getting [6], where learning new tasks degrades performance on earlier ones. Existing approaches address this problem through replay, regularization, or architectural isolation. Re-play methods retain past demonstrations for later training [4], which incurs storage overhead and can be undesirable when past demonstrations cannot be retained. Regularization meth-ods such as EWC [6] avoid storing past data but often provide weaker protection against forgetting. Architectural-isolation methods such as PackNet [7] protect previous tasks by re-serving separate capacity, but the available capacity becomes increasingly constrained as more tasks are learned. In robot manipulation, LIBERO [1] provides a standard benchmark for evaluating sequential task learning and retention. 

Adapter-Based Lifelong Robot Learning. With the emer-gence of large pretrained VLA policies [8]–[10], [16], [17], recent work has increasingly adopted lightweight adapters for task-specific adaptation while keeping the backbone frozen [11]–[13]. After each task is learned, its adapter is frozen, preventing later training from overwriting previously learned task parameters. This provides strong retention, but requires maintaining additional task-specific parameters as the task stream grows. When the oracle task ID is unavail-able, CLARE [12] and DMPEL [13] dynamically select or combine task-specific modules from the current input using learned discriminators and a router, respectively. These input-dependent mechanisms remain active during control, causing task-specific storage and deployment cost to grow with the task stream. 

Resource-E ffi cient Continual Learning. Recent work be-yond robotics has explored reducing the parameter growth of adapter-based continual learning. Some approaches compress task-specific adapters into a shared low-rank representation or merge multiple task updates into a shared model [18]– [20]. These methods reduce parameter growth, but typi-cally update shared parameters that also represent previously learned tasks. Their evaluation settings typically do not con-sider task selection from observations and instructions at de-ployment. In contrast, SARAM keeps previously learned task parameters frozen, reuses past adapters through combination coe ffi cients, and adds new adapters only at layers retained by sparse allocation. It further replaces learned selection modules with task signatures and merges the corresponding task update into the VLA backbone before execution, so only the backbone runs during control. III. B. Overview 

SARAM addresses the two growth axes at their respec-tive stages: disk storage during learning, and GPU cost at deployment. Each new task first reuses the frozen adapters of past tasks (Sec. III-D). A sparse adapter allocation then adds new capacity only at layers selected under a sparsity penalty (Sec. III-E), and a duplication penalty keeps that capacity from re-expressing what the reused adapters already provide (Sec. III-F). At deployment, every per-task update is linear in the weights, and the task is selected once per episode from frozen-backbone activation statistics (Sec. III-G). The selected update can therefore be added directly to the backbone weights, and the episode runs on a single backbone (Sec. III-H), holding GPU memory and per-step inference cost at the backbone’s own level.

A. Simulation Experimental Setup 

Benchmark and protocol. We evaluate on the four LIBERO suites [1]: Long, Goal, Spatial, and Object, each a stream of T =10 tasks learned sequentially. Following the LIBERO protocol, each task is probed with rollout episodes at regular intervals during training, and the best checkpoint is deployed as the task’s final policy. Every method runs three seeds un-der a shared schedule: 10k training steps per task, 20-episode probes every 800 steps, and 40 episodes for each retention evaluation. For SARAM, the 10k-step budget includes all three phases. Retention evaluations use each method’s own task selection without the oracle task ID.

Baselines. We consider sequential adaptation baselines that overwrite previously learned parameters: SeqFFT, which fine-tunes the whole model for each new task, and SeqLoRA, which fine-tunes a single LoRA adapter across tasks. We also consider EWC [6], which regularizes parameters important to previous tasks, PackNet [7], which freezes the most important weights after each task and learns the next within the remaining free capacity, and ER [4], which retains past demonstrations and trains each new task on an even mix of old and new data. We further include two adapter-based methods: CLARE [12], which trains task-specific adapters with per-task discriminators for selection, and DMPEL [13], which builds an expert library with a router fine-tuned by expert-coe ffi cient replay. SHARE [18] represents resource-effi cient continual learning methods that compress all tasks into a single adapter over a shared low-rank basis. We include it to examine whether such methods, developed beyond robotics, transfer to lifelong robot learning. 

Implementation. All methods share one pre-trained VLA backbone: a DiT-based flow-matching policy [24] pretrained on LIBERO-90 [1], with a DINOv2 vision encoder [25], a CLIP text encoder [26], and an action head predicting 16-step chunks of which 8 are executed. SARAM uses rank-8 LoRA adapters and one setting on every suite: sparsity-penalty weight of ξ=2 with an 800-step allocation phase and gates initialized from N(0 , 1) once per stream, duplication-penalty weight λ=0.3, and a coe ffi cient pre-fit that stops when the loss plateaus. Task signatures keep the top-2 eigenpairs per observation-side layer. Our implementation builds on the o ffi cial CLARE code [12], which provides the shared backbone and the SeqFFT, SeqLoRA, EWC, ER, and PackNet baselines. DMPEL [13] and SHARE [18] are adapted from their o ffi cial code with only the backbone replaced. All baselines are reproduced under the protocol and metrics above. All experiments run on a single NVIDIA A100 (80 GB) GPU per task stream.

D. Ablations and Analysis 

Component ablations. Table II examines each component of SARAM on LIBERO-Long. Without coe ffi cient pre-fit, we skip Phase 1 and train the combination coe ffi cients only with the new adapters in Phase 3. This lowers FWT and AUC, suggesting that fitting reuse first helps isolate the residual for new adapters. In random allocation per task , we keep the same number of adapters as SARAM but randomly allocate their locations for each task. This causes the largest AUC drop and substantially higher variation across seeds. In fixed random allocation , one randomly sampled layer set is shared by all tasks, recovering much of this loss and suggesting that shared adapter locations facilitate library reuse. In fixed first-task allocation , the gate-selected layers of the first task are reused throughout the stream. Its lower AUC and higher variation than the full method indicate that task-specific gate fitting provides additional gains. Without library reuse, we set c(t)=0, preventing new tasks from using adapters learned for previous tasks. The resulting drop in FWT and AUC shows that the frozen library provides useful capacity under the same sparse allocation budget. Finally, without the duplication penalty, we set λ=0 during Phase 3. This lowers mean FWT and AUC and substantially increases variation across seeds, indicating that the penalty improves both performance and stability. 

Where adapters are allocated. Figure 4 shows the layers that survive gate-based allocation on LIBERO-Long for each task and seed. Within each seed, tasks share many allocated layers under the common gate initialization, while task-specific gradients lead to di ff erences at a few locations, and no two tasks end with an identical layer set. Across seeds, the selected layers overlap little despite similar performance, suggesting that multiple sparse placements can be e ff ective. Together with Table II, these results show that shared adapter locations facilitate library reuse, while fitting the gates for each task provides additional gains and stability. 

Eff ect of ξ and λ. Table III examines how the sparsity-penalty weight ξ and duplication-penalty weight λ aff ect performance and storage. Signatures are built from the remaining episodes with the original instructions, and each held-out first observation is queried with either the original instruction or an unseen paraphrase. A mild paraphrase changes only the action verbs, e.g., “pick up the ketchup and place it in the basket” becomes “grab the ketchup and put it in the basket.” A strong paraphrase restructures the sentence while preserving objects, attributes, and relations, e.g., “point to the yellow cup” becomes “reach toward the cup that is yellow.” Recognition remains accurate under mild paraphrases on all suites and the real-robot stream, and errors appear only under strong paraphrasing. These results show that task recognition is not tied to the exact surface form of the instruction. 

E. Real-Robot Experiments 

Real-robot setup. We evaluate on a UR5 robot with a Robotiq 2F-85 gripper, an external camera, and a wrist cam-era. The robot learns the seven tasks in Fig. 5 sequentially. Each task has about 50 teleoperated demonstrations and is evaluated with 10 rollouts. We use π0 [9] as the backbone with rank-8 LoRA candidates on its linear layers and ξ=40, which keeps a similar fraction of layers per task as on LIBERO; other settings follow the simulation setup. We compare against SeqLoRA, ER, and per-task LoRA policies selected with the oracle task ID as a reference. 

Real-robot results. Table IV and Fig. 6 show the results over the seven-task stream. SeqLoRA retains only the last task, and ER, despite replaying past demonstrations, loses most earlier tasks as the stream grows. SARAM learns tasks close to the per-task reference and keeps them: its final success equals its success at learning time, with per-task di ff erences within one episode. Task selection is correct on every held-out episode, including the same-scene die and cup tasks (Table V). V. CONCLUSION We presented SARAM, a lifelong robot learning method for VLA policies that limits storage growth during learning and removes task-specific computation from the control loop. Each new task reuses the frozen adapters of past tasks, adds new adapters only at layers selected by a sparsity penalty, and trains them under a duplication penalty. At deployment, a task signature built from frozen-backbone activations selects the task once per episode without the oracle task ID or a learned selection module, and the selected update is merged into the backbone so that only the backbone runs in the control loop. On four LIBERO suites, SARAM attains the highest SR final and AUC of all compared methods while adding up to 4 .5× less on-disk state per task than adapter-based baselines, and its GPU memory and control frequency stay at the backbone’s level while the adapter-based baselines slow down by up to 3 ×. On a seven-task real-robot stream with a di ff erent backbone, it learns and retains all seven tasks throughout the stream. References
