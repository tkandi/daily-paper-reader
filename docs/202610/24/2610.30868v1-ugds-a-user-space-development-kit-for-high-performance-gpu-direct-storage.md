## 摘要
数据密集型 GPU 应用日益依赖 NVMe SSD 来扩展 GPU 内存。NVIDIA GPU Direct Storage（GDS）通过 PCIe 点对点 DMA 实现 SSD 与 GPU 之间的直接数据传输，消除了主机端暂存。然而，GDS 仍存在三个关键局限性：（1）其控制路径针对每个 I/O 请求都要经过内核，从而引入软件开销；（2）其流有序路径即使在工作负载仅需要批次级顺序时，仍施加严格的全序约束；（3）其闭源的用户态引擎不利于故障诊断和自定义调度。我们提出 uGDS（https://github.com/ScaleX-IO/uGDS），这是一个开源的用户态 GPU 直接存储库，基于四项原则构建：用户态控制、跨厂商统一抽象、面向工作负载的调度，以及端到端透明性。主机 CPU 在用户态管理整个 NVMe 命令生命周期，而数据载荷通过 PCIe P2P DMA 传输，不占用 GPU 计算资源。一个最小化的内核模块（ugds_drv.ko）仅用于一次性的特权设置。uGDS 在同步流量和批处理流量之间划分硬件队列，保证 DMA 安全的缓冲区生命周期，并在 NVIDIA CUDA 和 AMD HIP 平台上提供与 cuFile 兼容的同步、批处理和流有序 API，以及轮询或中断完成机制。在搭载 A100 GPU 和 Samsung 990 PRO SSD 的平台上评估表明，对于 8 KiB 和 4 KiB 请求、批大小为 128 的场景，uGDS 的批量读取带宽最高可达 GDS 的 12.12 倍，批量写入带宽最高可达其 30.69 倍；在双线程条件下，4 KiB 同步写入延迟降低了 84.1%。其流有序路径在单个流上可持续达到 5.49 GiB/s，而 GDS 在该场景下仅能保持其同步带宽的 40.8%。在 LMCache 中，uGDS 将中位首个词元时间（TTFT）最高降低 62.7%，并将服务有效吞吐量提升至 2.63 倍。在 AMD 平台上，uGDS 的同步写入带宽最高可达 hipFile 的 1.19 倍。

## Abstract
Data-intensive GPU applications increasingly rely on NVMe SSDs to extend GPU memory. NVIDIA GPU Direct Storage (GDS) enables direct SSD-GPU transfers via PCIe peer-to-peer DMA, eliminating host staging. However, GDS retains three key limitations: (1) its control path traverses the kernel for every I/O request, introducing software overhead; (2) its stream-ordered path imposes strict total ordering even when workloads only require batch-level ordering; and (3) its closed-source user-space engine hinders diagnosis and custom scheduling.   We present uGDS, https://github.com/ScaleX-IO/uGDS, an open-source user-space GPU Direct Storage library built on four principles: user-space control, unified cross-vendor abstraction, workload-aware scheduling, and end-to-end transparency. The host CPU manages the entire NVMe command lifecycle in user space, while payloads move via PCIe P2P DMA without consuming GPU compute. A minimal kernel module (ugds_drv.ko) is used only for one-time privileged setup. uGDS partitions hardware queues between synchronous and batch traffic, enforces DMA-safe buffer lifetimes, and provides cuFile-compatible synchronous, batched, and stream-ordered APIs with polling or interrupt completion on both NVIDIA CUDA and AMD HIP.   Evaluated on an A100 with a Samsung 990 PRO, uGDS achieves up to 12.12x GDS's batch-read bandwidth and 30.69x its batch-write bandwidth (8- and 4-KiB requests, batch size 128), and reduces 4-KiB synchronous write latency by 84.1% with two threads. Its stream-ordered path sustains 5.49 GiB/s on a single stream, where GDS retains only 40.8% of its synchronous bandwidth. In LMCache, uGDS reduces median time-to-first-token (TTFT) by up to 62.7% and raises serving goodput by 2.63x. On AMD, uGDS achieves up to 1.19x hipFile's synchronous-write bandwidth.
