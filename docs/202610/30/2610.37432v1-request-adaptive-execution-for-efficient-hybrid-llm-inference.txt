Abstract 

Hybrid large language models (LLMs) have emerged as a promising way to combine the modeling capability of the Attention mechanism with the efficiency of state space mod-els (SSMs). However, most existing hybrid LLMs still inherit a static design philosophy: once the Attention-to-SSM lay-out is chosen, every request must follow the same hybrid execution. This one-layout-fits-all design is inefficient for real-world serving workloads, where different requests rely on contextual information in different ways. This paper presents Flex, a serving system that co-designs the model architecture and runtime for request-adaptive hy-brid LLM inference. Its model architecture pairs Attention and SSM layers within each block and uses prefill-oriented gating to select a request-specific layout that remains fixed throughout decoding. Its serving runtime preserves batch-ing efficiency under divergent layer choices through selec-tive batching and enables correct prefix reuse through hybrid-aware context caching. Experiments on six datasets show that Flex achieves a better quality-efficiency trade-off than existing static hybrid baselines. System-level evaluation fur-ther shows that Flex improves the serving throughput by up to 3.87× over baselines while substantially reducing in-ference latency. 

Keywords: Large language models, State space models, Ef-ficient serving 

1 Introduction

Most deployed LLMs are based on the Transformer architecture, where the attention mech-anism provides strong global-context modeling but incurs quadratic computation and growing KV-cache memory dur-ing inference [43, 50, 56]. To reduce this cost, state space models (SSMs), such as Mamba [9, 16], have been introduced as efficient sequence modeling primitives. As a result, a static Attention-to-SSM layout can either overuse Attention for simple re-quests, wasting computation, or underuse Attention for context-sensitive requests, sacrificing output quality. 

Key Idea. Our key idea is to make the hybrid LLM request-adaptive: rather than fixing the Attention-to-SSM layout, the model selects an appropriate hybrid layout for each in-coming request. As illustrated in Figure 1(b), different re-quests can activate different Attention and SSM layers ac-cording to their context-modeling demands. We realize this idea through algorithm-system co-design in Flex, an infer-ence system that integrates a request-adaptive hybrid model with runtime optimizations for efficient serving. The hybrid model consists of multiple adaptive hybrid blocks, each con-taining a lightweight gate, paired Attention and SSM branches, and shared components such as the FFN. For each request, the gates select one branch per block, forming a request-specific execution layout that balances modeling capability and inference cost. A key design choice is the gating granularity. A natural token-level gating design would allow each token to inde-pendently choose whether to execute the Attention or SSM layer in each hybrid block. However, this design is ill-suited for autoregressive decoding, where newly generated tokens rely on the cached results of previous tokens, i.e., Atten-tion KVs and SSM states, to avoid recomputation. If tokens from the same request choose different layers within the same block, later tokens may not be able to directly reuse the Attention KVs or SSM states produced by earlier tokens, forcing the runtime to recompute previous tokens under the new layer choice. Flex therefore adopts prefill-oriented gat-ing mechanism (§4): during prefill, the gate uses all input tokens to make one request-level Attention and SSM choice for each hybrid block, and these choices are fixed through-out decoding. This allows the Attention KVs or SSM states built by previously generated tokens to be reused consis-tently. At the system level, request-adaptive layouts introduce two challenges: requests within the same batch may select different branches, and requests sharing a textual prefix may require incompatible layer-wise caches. The serving runtime in Flex addresses these challenges through the following two designs to preserve batching efficiency and ensure cor-rect context reuse. 

Selective Batching Engine. To maintain high inference throughput, Flex must efficiently batch multiple requests for parallel execution. However, requests in the same batch may select different branches at each hybrid block, which breaks the traditional batching assumption of conventional serving engines, where all requests in a batch follow the same operator sequence [12, 21, 32]. A naive solution would either serialize or execute block computations separately. The former loses parallelism, while the latter fragments the original batch and prevents request-independent operations, such as normalization and FFN computation, from being ex-ecuted as a single compact batch [55]. Flex addresses this with selective batching engine (§5). The key idea is to keep branch-independent operations on the original packed batch, and split requests only for the branch-dependent Attention and SSM computation. At each block, it partitions requests into compact Attention and SSM sub-batches, executes them with their corresponding ker-nels, and then merges outputs back into the original batch layout. Since two branches may have different execution costs, Flex further applies load-aware branch coordination by assigning more resources to heavier branch, reducing synchronization stalls before merging. 

Hybrid-Aware Context Caching. Real-world LLM serv-ing workloads often contain repeated long prefixes, such as system prompts, document contexts, and multi-turn conver-sation histories. Recomputing these prefixes for every re-quest wastes substantial prefill computation, especially in long-context scenarios. Context caching [19, 41, 45] addresses this issue by identifying matched textual prefixes and reusing their previously generated caches. Existing techniques typ-ically assume that a matched textual prefix uniquely deter-mines all reusable caches. However, this assumption no longer holds for Flex: even when two requests share the same pre-fix, they may select different Attention and SSM layers across hybrid blocks, producing different layer-wise caches. More-over, conventional cache eviction operates at the context level, where evicting a prefix removes all layer-wise caches associated with it. This coarse-grained eviction is inefficient for request-adaptive hybrid execution, because only a subset of layer caches under a matched context may be frequently reused. Evicting the whole context can reduce future cache hit ratios, while retaining it may keep many rarely used layer caches in memory. To address these limitations, Flex introduces the hybrid-aware context caching (§6). Its core mechanism, a two-level radix tree structure, decouples textual-prefix matching from layer-wise cache matching. After identifying a shared tex-tual prefix, it further determines which layer-wise caches are compatible with the current hybrid layout. 2.2 Motivation 

The quality-efficiency trade-off of a hybrid LLM is largely determined by its Attention-to-SSM layouts . Existing hybrid LLMs determine this configuration based on empirical stud-ies and keep it static during model serving. For example, Jamba [22] periodically inserts Attention layers into an SSM-dominated backbone, while Nemotron-H [3] fixes a prede-fined distribution of Attention and SSM layers. Once con-structed, all requests are forced to execute the same lay-out, regardless of their input characteristics or contextual requirements. We find that such static layouts are insuffi-cient for diverse inference workloads: different tasks, and even different requests from the same task, can prefer dif-ferent uses of Attention and SSM computation.

4 Prefill-Oriented Gating 

This section presents the prefill-oriented gating mechanism of Flex. The goal is to enable request-adaptive Attention and SSM layer selection while preserving efficient autore-gressive decoding. 

4.1 Gating Design 

A natural way to enable dynamic hybrid execution is to make layer choices for each token. However, such token-level gating is ill-suited for autoregressive hybrid LLM serv-ing. During decoding, each newly generated token relies on the Attention KV caches or SSM state caches produced by previous tokens to avoid redundant computation. If differ-ent tokens from the same request choose different layers within the same block, later tokens may no longer be able to directly reuse the caches produced by earlier tokens. As a result, the runtime must recompute previous tokens under the new layer choice, introducing substantial overhead and complicating decoding. To avoid these problems, Flex adopts a coarse-grained prefill-oriented gating mechanism in the request-adaptive hybrid model. As shown in Figure 6, this mechanism has two key properties. First, the gate is evaluated only during prefill, where each hybrid block makes one request-level choice between the Attention layer and the SSM layer based on all input tokens. Second, the selected layer choices are fixed after prefill and directly reused throughout decoding, so generated tokens do not trigger additional gating deci-sions. This design is reasonable for both system efficiency and hybrid adaptation. From the system perspective, prefill-oriented gating preserves a consistent computation throughout model inference and newly generated tokens can directly reuse the Attention KV caches or SSM state caches produced by pre-vious tokens, avoiding the recomputation overhead. From the model perspective, the input tokens processed during prefill already encode the key characteristics of the request, such as task type, context length, and dependency require-ments [30, 52]. Our experimental results further show that such prefill information is sufficient to guide the Attention and SSM layer choices for the whole request, enabling the hybrid model to adapt its computation without repeatedly invoking the gate during decoding. In each hybrid block, the gate first aggregates the pre-fill hidden states into a compact request representation, and then feeds it into a lightweight gate network to obtain the probabilities of selecting the Attention and SSM layers. We use top-1 gating and activate the layer with the larger proba-bility. The formal definition of the gating process is provided in the supplementary manuscript.

5 Selective Batching Engine 

This section introduces the design of selective batching en-gine in Flex, which supports efficient batching processing of the proposed request-adaptive hybrid model. 

5.1 Split-and-Merge Execution 

Given the request-adaptive layer choices produced by dy-namic hybrid execution, the key question is how to exe-cute a mixed batch without sacrificing normal batching ef-ficiency. Flex addresses this through a split-and-merge ex-ecution mechanism. As shown in Figure 7, the input tokens from different requests are first packed into a single batch tensor. For example, 𝑥 𝑗 𝑖 denotes the 𝑗 -th token of request 𝑖 ,and the two requests in the figure form a packed tensor with shape [6, 𝐻 ] . Flex keeps this packed layout for shared op-erations, such as gate network and FFN computation, and splits the batch only before the layer-specific Attention or SSM computation. Requests selecting the Attention layer are compacted into an Attention sub-batch, while requests selecting the SSM layer are compacted into an SSM sub-batch. The two sub-batches are then executed by their cor-responding kernels. Afterward, Flex merges their outputs back into the original packed batch layout, so subsequent shared operations can still be processed as a regular batch. 5.2 Load-Aware Branch Coordination 

Although selective batching enables the Attention and SSM layers to run independently, simply launching them on nor-mal CUDA streams is insufficient. The two branches have different execution characteristics: the Attention branch is sensitive to context length and KV access, while the SSM branch is mainly dominated by recurrent state updates. More-over, the number of tokens assigned to each branch changes across blocks and batches. As a result, one branch may fin-ish earlier than the other, forcing the merge operation to wait for the slower branch. To reduce this synchronization stall, Flex adopts load-aware branch coordination. The key idea is to estimate the relative workload of the Attention and SSM branches and assign more SM resources to the heavier branch. Guided by the computation complexity in Table 1, Flex uses light-weight profiled cost models to predict branch execution costs from simple runtime features, including the number of re-quests in each branch, input lengths during prefill, and cur-rent KV-cache lengths during decoding. Since branch coor-dination only requires relative costs, the predictor does not need exact latency estimation. In our implementation, its prediction error is within 6.32% for the Attention branch and 5.18% for the SSM branch. The profiling is a one-time effort for each model-GPU pair and can be completed effi-ciently. Detailed cost models are provided in the supplemen-tary manuscript. 6 Hybrid-Aware Context Caching 

This section presents the hybrid-aware context caching mech-anism in Flex, which enables correct prefix reuse when the same textual context may produce different layer-wise At-tention KV and SSM state caches. 

6.1 Context Caching Mechanism 

Context caching is widely used to improve LLM serving ef-ficiency by reusing previously computed caches (e.g., Atten-tion KVs and SSM states) for repeated prefixes [19, 41, 45]. For example, RadixAttention [51] organizes historical con-texts with a radix tree, where each node represents a textual prefix. When a new request arrives, the runtime searches the radix tree to find the longest matched prefix, reuses the caches associated with the matched prefix, and computes only the unmatched suffix. However, conventional RadixAt-tention cannot be directly applied to Flex. Its key assump-tion is that a matched textual prefix uniquely determines all layer-wise caches that can be reused. This assumption holds for static models because the layer type at each po-sition is fixed by the model architecture. For example, in an Attention-only model, each layer always produces a KV cache, while in an SSM-only model, each layer always pro-duces an SSM cache. In Flex, requests sharing a textual prefix may select differ-ent layer layouts depending on their full contexts. As shown in Figure 8, the incoming request matches the cached pre-fix “You are a helpful assistant.”, but requires Attention KV caches at the third and fourth blocks, where the cached en-tries are SSM states. Conventional methods treat the matched entry as a whole: it is either reused or rejected. Reusing the cached states despite the layout mismatch can introduce in-consistent intermediate representations and degrade infer-ence quality. Alternatively, rejecting the incompatible entry results in a cache miss and requires recomputing the shared prefix, losing the opportunity to exploit the textual overlap. To support correct and efficient context reuse under dy-namic hybrid execution, Flex implements hybrid-aware con-text caching using a two-level radix-tree structure. The outer-context radix tree indexes textual prefixes, while an inner-cache radix tree attached to each context node organizes layer-selection paths and their associated Attention KV caches and SSM states. Cache lookup proceeds in two steps. First, Flex locates the longest matching textual prefix in the outer-context radix tree. It then examines the inner-cache radix tree of the matched node and its ancestors to identify com-patible cache paths. Compatibility requires matching the se-quence of layer choices from the first block through the block being reused. Among these candidates, Flex selects the prefix and cache path with the lowest estimated recom-putation cost, considering both prefix length and the num-ber of reusable leading blocks. As illustrated in Figure 9, the inner-cache radix tree asso-ciated with CTX1 contains multiple execution paths. These paths share caches for the first two blocks, then branch ac-cording to the branch choices at the third and fourth blocks. For cache, Flex retains input hidden states and terminal SSM states, reconstructing Attention KV caches on demand. For an incoming request matching CTX1, Flex follows the inner-tree path consistent with its branch-selection history and reuses the corresponding caches. At the first route mis-match, the cached hidden states remain valid because all preceding branch choices match. Flex uses these states to recompute the prefix at that block and all subsequent blocks, then extends the inner-cache radix tree with the newly com-puted caches while retaining existing branches. This orga-nization supports partial cache reuse and preserves alterna-tive execution paths for future requests sharing same textual prefix.

6.2 Priority-based Eviction Policy 

Hybrid-aware context caching enables correct cache reuse under dynamic hybrid execution, but also increases the num-ber of cache entries. With a fixed layer layout, conventional RadixAttention associates each textual prefix with one set of layer-wise caches. In Flex, the same context node can maintain multiple cache paths corresponding to different Attention and SSM choices. Evicting an entire context node therefore discards all these paths, potentially removing fre-quently reused caches together with rarely accessed ones. Flex instead performs eviction at the granularity of indi-vidual layer-wise cache entries. Under GPU memory pres-sure, it evicts entries from the inner-cache radix trees. An outer-context node is removed only when all its associated caches have been evicted and the node is no longer needed to represent shared textual prefixes. To determine which en-tries to retain, Flex assigns each cache 𝑐 a retention priority: 

𝑃(𝑐) = 𝐻 (𝑐) ⋅ 𝑅(𝑐) 𝑀(𝑐) ⋅ 𝐷(𝑐), (5) where 𝐻 (𝑐) is its recent access frequency, 𝑅(𝑐) is the recom-putation cost saved by reusing it, 𝑀(𝑐) is its memory foot-print, and 𝐷(𝑐) is a depth factor that favors caches at earlier blocks. Flex evicts entries with the lowest priority first. This policy favors caches that provide greater expected compu-tation savings per unit of memory. The depth factor further prioritizes early-layer caches, which can form shared ances-tors of multiple execution paths in an inner-cache radix tree. 

7 Implementation 

We implement a prototype of Flex with approximately 6.5K lines of code using Python, PyTorch, HuggingFace Trans-formers, and CUDA/C++. The construction and fine-tuning of the request-adaptive hybrid model are implemented in PyTorch, while the serving runtime extends a vLLM-style execution loop with selective batching and hybrid-aware context caching. It caches layer hidden states and terminal SSM states, supporting Attention KV reconstruction and re-computation from the first mismatched layer. For concur-rent Attention and SSM execution, Flex uses NVIDIA Green-Context to partition SM resources and launches the two sub-batches on separate CUDA streams. It also adopts a unified paging-based memory manager for heterogeneous Atten-tion KV caches and SSM caches, following Jenga [47]. The runtime currently uses a conventional continuous batching scheduler [44], and is compatible with other scheduling poli-cies such as chunked prefill, prefill-decode disaggregation, and latency-aware scheduling [1, 12, 27, 30, 53]. Detailed im-plementation is provided in the supplementary manuscript.

8.2 Overall Model Performance Quality-efficiency trade-off. Table 2 compares Flex with homogeneous and static hybrid LLMs across three model scales. Overall, Flex achieves the best results on 13 out of 18 quality metrics while maintaining competitive computa-tion cost. At the small scale, Flex obtains the best results on ARC-Easy, TruthfulQA, and PubMed, and remains close to the best baseline on ARC-Challenge and CNN/DailyMail. At the medium scale, it consistently outperforms all baselines on all six datasets. At the large scale, it achieves the best results on reasoning and QA tasks, while remaining com-petitive on summarization tasks. More importantly, Flex achieves these quality gains with substantially lower esti-mated TFLOPs/token: compared with Attention-only Llama models, it reduces computation cost by 40.5%, 33.2%, and 67.2% at the three evaluated scales, respectively. Compared with Nemotron-H, it reduces TFLOPs/token by 28.4%, 28.9%, and 58.7%. Although Mamba and some static hybrid models can be cheaper in certain settings, their quality is often less stable across tasks. These results show that request-adaptive Attention and SSM selection provides a better quality-efficiency trade-off than static hybrid layouts. We further analyze eval-uation results across different tasks. 

Reasoning tasks. On ARC-Easy and ARC-Challenge, Flex performs particularly well at medium and large scales. For example, at the medium scale, Flex achieves 77.8% accuracy on ARC-Easy and 57.7% on ARC-Challenge, outperforming all static hybrid baselines. At the large scale, it further im-proves the results to 85.6% and 85.1%, respectively. These results suggest that reasoning tasks benefit from selectively activating Attention in important layers, while still using efficient SSM computation elsewhere. Static hybrid models improve over pure SSM models, but their static attention placement cannot adapt to the varying dependency patterns of different requests. 

QA tasks. On PIQA and TruthfulQA, Flex also shows strong performance. At the medium scale, it achieves 83.1% on PIQA and 68.9% on TruthfulQA, outperforming all baselines. At the large scale, it reaches 85.3% on PIQA and 75.2% on Truth-fulQA. These results indicate that QA workloads do not al-ways require Attention in every layer, but still need Atten-tion in selected layers to preserve factual and contextual signals. Flex captures this behavior by adapting the Atten-tion and SSM choices to each request instead of relying on a static hybrid layout. 

Summarization tasks. Summarization workloads have a stronger dependence on global context modeling. Attention-heavy models such as Llama remain competitive, especially at the large scale. Nevertheless, Flex achieves the best sum-marization results at the medium scale, reaching 23.4 ROUGE-L on CNN/DailyMail and 21.5 ROUGE-L on PubMed. At the small scale, it also achieves the best PubMed score and re-mains close to the best CNN/DailyMail result. These results show that summarization benefits from more frequent At-tention activation, but does not require all layers to be At-tention layers. Flex can allocate Attention to the layers and requests that need global context, while using SSM layers elsewhere to reduce computation. 

Routing Effectiveness. We compare three routing strate-gies using the same fine-tuned checkpoint at each model scale. We collect candidate layouts from adaptive routing on held-out validation data and evaluate each as a fixed lay-out under matched inference-cost budgets. Within this can-didate set, Global Optimal (G-Optimal) selects one layout that maximizes the macro-average of normalized validation scores across datasets, while Dataset Optimal (D-Optimal) selects the best layout separately for each dataset. Both strate-gies keep their selected layouts fixed during evaluation, whereas Adaptive selects a layout for each request. As shown in Ta-ble 3, our adaptive method outperforms both static strate-gies across all 18 model-dataset combinations. Compared with D-Optimal, it achieves average gains of 4.86 percentage points in accuracy and 2.55 points in ROUGE-L. Although D-Optimal consistently improves over G-Optimal, its remain-ing gap to Adaptive demonstrates the benefit of adapting layer choices to individual requests within the same dataset.

9 Related Work 

Hybrid LLMs. Recent works reduce the cost of long-context LLM inference by replacing part of the attention computa-tion with efficient sequence modeling modules [10, 28, 33]. SSM-based models, such as Mamba [16] and Mamba-2 [9] maintain compact recurrent states instead of full Attention KV caches. Hybrid LLMs further combine Attention and SSM layers to balance global-context modeling and inference ef-ficiency, with representative examples including Jamba [22], 

> 12

Zamba [14], Hymba [11], Mamba-in-Llama [38], and Nemotron-H [3]. While prior hybrid LLMs demonstrate the promise of Attention and SSM hybridization, they rely on static layouts, whereas Flex enables request-adaptive Attention and SSM layer selection within the same model. 

Efficient batching. Efficient batching is central to high-throughput LLM serving. Orca [44] introduces iteration-level scheduling, while vLLM [21] improves batching capacity with PagedAttention. SGLang [51] supports structured LLM pro-gram execution, and systems such as Sarathi-Serve [1], Split-wise [27], DistServe [53], LoongServe [39], NanoFlow [55], and MuxWise [4] optimize prefill/decode scheduling or GPU resource coordination. Unlike these systems, Flex supports batches with divergent Attention and SSM layer choices and preserves efficiency through selective hybrid batching. 

Context caching. Context caching reduces redundant pre-fill computation by reusing caches for repeated prefixes [19, 41, 42, 45, 48]. SGLang [51] proposes RadixAttention for prefix-based cache reuse, and works such as Parrot [24], CacheBlend [41], and Mooncake [29] exploit reuse opportunities in structured, RAG, multi-turn, or disaggregated serving scenarios. Unlike prior techniques that bind each matched prefix to a single reusable cache, Flex uses the two-level radix tree to dis-tinguish different layer-wise Attention KV and SSM state caches for the same textual prefix. 

10 Conclusion 

This paper presents Flex, an inference system that combines a request-adaptive hybrid model with an optimized serving runtime through algorithm-system co-design. The model uses prefill-oriented gating to select Attention or SSM branches for each request and keeps the resulting layout fixed through-out decoding. The runtime integrates selective batching and hybrid-aware context caching to support efficient mixed-branch execution and correct prefix reuse. Experiments show that the hybrid model achieves a better quality-efficiency trade-off than static hybrid baselines, while the runtime im-proves serving throughput and reduces inference latency.
