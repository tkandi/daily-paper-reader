# ABSTRACT 

Agentic AI drives significant productivity gains across diverse domains, but concurrent long-context prefills from multiple agents can saturate GPU compute resources. Although CPUs offer a viable alternative, existing CPU attention kernels fall short in adapting to multi-tier cache hierarchies and lack effective thread scheduling. To address this, we introduce CACPU, a high-performance attention kernel featuring tiered cache blocking and an in-kernel task dispatching mechanism designed for causal full-sequence prefilling. CACPU achieves up to a 2.01× speedup over PyTorch SDPA, FlexAttention, and SGLang attention kernels. Integrated into SGLang, it reduces Time to First Token (TTFT) of Llama-3.1-8B by up to 1.74× while preserving model accuracy. 

# 1 INTRODUCTION 

Several recent efforts have explored CPU-based accelera-tion for large language models (LLMs). Gupta et al. (2026) adapt FlashAttention to scalable vector architectures, so that the kernel scales from short to long vectors on RISC-V CPU. Na et al. (2025) exploit CPU memory and compu-tation alongside GPU resources, while Shen et al. (2023) improve CPU LLM inference through INT4 weight-only quantization and an optimized runtime. At the framework level SGLang and vLLM have introduced CPU-specific ker-nels (Li, 2026) and scheduler optimizations (Li, 2025). In this work, we specifically target causal attention mecha-nisms to accelerate the LLM serving pipelines, which will benefit agentic AI workloads on CPU architectures. Agentic AI workloads require large language models (LLMs) to process extremely long contexts, which include intermediate reasoning steps (Wei et al., 2022) and tool call outputs (Schick et al., 2023). Building upon recent ad-vancements in GPU attention kernels (Dao et al., 2022; Dao, 2024; Shah et al., 2024; Zadouri et al., 2026), we propose an optimized CPU attention kernel tailored specifically for the prefill phase to accelerate long-context processing in LLM serving frameworks. We introduce two core mechanisms: Two-Level Cache-Aware Scheduling and L3-Chunk-Scoped Cost-Prioritized Scheduling. The former minimizes redun-dant DRAM reads by partitioning sequences according to cache hierarchy budgets, while the latter addresses core workload imbalance through dynamic cost-based task dis-patch from a shared task queue. # 2 RELATED WORK 

As the attention mechanism constitutes the primary com-putational backbone of Large Language Models (LLMs), extensive research has focused on its optimization to fully utilize GPU capabilities. A typical example is FlashAt-tention (FA). Beginning with FA1 (Dao et al., 2022) and FA2 (Dao, 2024), the primary goal was to minimize redun-dant data transfers between high-bandwidth memory (HBM) and on-chip SRAM. With the advent of dedicated Tensor Cores, FA3 (Shah et al., 2024) extended this concept by overlapping General Matrix Multiplication (GEMM) with Softmax operations through asynchronous execution and warp specialization. Most recently, FA4 (Zadouri et al., 2026) co-designs the algorithm with the kernel pipeline to address the asymmetric hardware scaling of Blackwell-class systems. These methods yield exact outputs while signifi-cantly reducing latency. 

2.1 Long Context Scenarios 

Specialized attention mechanisms have also been developed to tackle long-context scenarios efficiently. Local (sliding-window) attention reduces attention complexity to process long documents (Beltagy et al., 2020); a related work also shows that biasing attention toward local image regions can also mitigate hallucination in vision-language models (An et al., 2025). Infini-Attention (Munkhdalai et al., 2024) extends this concept by incorporating a compressed mem-ory module to support streaming over unbounded context lengths with memory constraints, while Xiao et al. (2024) retain only a fixed window together with the initial attention sinks. Other approaches focus on distributed compute effi-ciency: RingAttention with Blockwise Transformers (Liu et al., 2024) overlaps peer-to-peer (P2P) Key/Value com-munication with computation in a logical ring network. To address the inherent workload imbalance in causal attention, Striped Attention (Brandon et al., 2023) redistribute blocks across accelerators to increase hardware utilization. 

2.2 Serving Frameworks 

To satisfy the demands of high-throughput LLM serving sys-tems, several framework-specific attention primitives have emerged. vLLM introduced PagedAttention (Kwon et al., 2023), which applies virtual memory paging principles to dynamically manage KV cache allocations. Conversely, SGLang adapts a RadixTree structure to efficiently manage and reuse shared prefix KV caches (Zheng et al., 2024). FlashInfer (Ye et al., 2025) unifies these different KV cache layouts under a single hardware-optimized kernel abstrac-tion. 

2.3 Offloading Workloads to CPU 

Recent work actively leverages CPU resources to mitigate the massive computational demands of LLM serving. Flex-Gen (Sheng et al., 2023) offloads attention-score compu-tation to the CPU when the KV cache resides in CPU memory, while FastDecode (He & Zhai, 2024) extends this approach by executing KV-cache-bound attention across aggregated cross-node CPU compute and memory band-width. For online serving, NEO (Jiang et al., 2025) overlaps CPU attention with GPU computation, transmitting only compact activations rather than large KV caches. Other approaches partition a single attention operation across de-vices: HGCA (Deng et al., 2025) splits dense and sparse attention between the CPU and GPU before merging them, while HybridGen (Lin et al., 2026) parallelizes attention logits using a feedback-driven dynamic scheduler. 

2.4 Variants of Attention Mechanisms on CPUs 

Several efforts focus on optimizing CPU-native atten-tion performance through either structural redesign or ap-proximate computation. For architectural modifications, NOSA (Huang et al., 2025) applies trainable sparse atten-tion to bound KV cache transmission. For approximation methods, IceFormer (Mao et al., 2024) approximates atten-tion using top-k candidate keys selected by nearest-neighbor search, while MagicPIG (Chen et al., 2025) samples keys and reweights them according to their sampling probabili-ties. Alternatively, NoMAD-Attention (Zhang et al., 2024) approximates matrix multiplication by turning multiply-add operations into in-register SIMD lookups, IntAtten-tion (Zhong et al., 2025) numerically approximates softmax by clipping and using lookup tables with integer normaliza-tion. SparAMX (AbouElhamayed et al., 2025) prunes low-magnitude KV values to accelerate GEMMs using hardware-accelerated Intel AMX kernels. 

2.5 Our Work 

While these pioneering approaches highlight promising re-search directions, many require model retraining, model architecture redesigns, or active framework adaptations. These introduce difficulties to adopt in existing agentic AI workloads. In contrast, this work aims to deliver immediate and practical performance gains for existing LLM serving systems. Specifically, we introduce a self-contained atten-tion kernel that preserves output quality while seamlessly integrating into mainstream frameworks such as PyTorch and SGLang. By maintaining full compatibility with pre-trained LLMs, our design substantially improves end-to-end prefill throughput in modern production environments. 3.2 Two-Level Cache-Aware Scheduling 

Unlike GPU shared memory, CPU L2 and L3 caches are filled by hardware according to the order of memory accesses. Data access must be carefully scheduled to preserve locality. Dedicated loop structures are hence intro-duced to exploit the cache hierarchy of the CPU, without changing the arithmetic of the kernel. At the entry point of the kernel, we compute the working sets analytically from the CPU cache capacities. This proposed schedul-ing can be divided into 2 main parts: L3 cache and L2 cache. 

L3 Cache: For short and medium length sequences, the shared cache (L3) is not a bottleneck as the key and value tensors fit entirely in L3. As the sequence grows, this stops holding. Beyond a certain sequence length, K and V blocks are evicted before the next query block reuses them, forcing repeated reads from DRAM. This results in redundant DRAM-to-L3 traffic, which is why the L3 capacity has to enter the algorithm design rather than being left to the hardware. We restructure the loop nest so that the K and V tensors brought into L3 are fully reused before they can be evicted. We group Q heads whose K and V tensors fit within a fixed fraction of L3. An outer loop is added in order to walk the groups one at a time. If a single head’s K and V already exceed the budget, we will further split the sequence as well. We parallelize the threads on the same group. Since every core on a socket shares one L3 cache, a block of K or V tensors that any thread pulls in is immediately available to all the other cores. As a result, unnecessary L3 cache eviction can be avoided, and the performance of the algorithm can be improved. Figure 1 shows the packing of K and V tensors. 

L2 Cache: Once the L3-resident chunk has eliminated DRAM refetch, we move one level down. Under the natural ordering, where each q-block sweeps the entire chunk, every KV step ( j) is re-fetched from L3 once per q-block. This increases the latency of the kernel. In order to address this, we invert the two innermost loops: the loop over KV steps becomes the outer loop, while the loop over a group of G consecutive q-blocks becomes the inner loop. So a packed KV step ( j) is loaded into L2 once and reused by G q -blocks before it is evicted. Rather than manually tuning G for different CPUs, we con-servatively size it from the L2 capacity. We split the group’s resident set into two terms: shared ( U ) and per-q-block (Qb).

3.3 L3-Chunk-Scoped Cost-Prioritized Scheduling The load-imbalance problem: The two-level cache-aware scheduling scheme described in the previous section estab-lishes a specific loop hierarchy, where the KV step serves as the outer loop and the query block ( q-block) as the inner loop. Consequently, the query group ( q-blocks) forms the natural unit of parallelism. In self-attention, contiguous partitioning works effectively as all threads execute identical workloads. This does not hold in causal attention. Since causal attention applies a lower-triangular mask, threads handling q-groups from ear-lier sequence positions skip fully masked regions and finish quickly. FlashAttention-4 LPT Scheduling and Its CPU Limits: 

FlashAttention-4 (Zadouri et al., 2026) addresses work im-balance via LPT scheduling (Graham, 1969), assuming identical processors and monotonic tile execution costs in causal attention. Although effective for GPUs, these as-sumptions do not hold on modern CPUs with heterogeneous execution units and complex cache hierarchies. We adapt and build upon the LPT heuristic to address imbalanced workloads on modern CPUs.

# 5 CONCLUSION 

In this work, we introduce CPU-centric optimizations to FlashAttention by incorporating cache-aware and cost-prioritized scheduling mechanisms. With an aim to mini-mize redundant DRAM reads, the algorithm first partitions long-sequence Key and Value tensors into chunks that fit within the L3 cache. At the L2 cache level, query-blocks are grouped to maximize reuse of the K and V subblocks residing in L2, significantly improving latency. To validate correctness, we verified the numerical differences at the single-kernel level using cosine similarity against reference outputs. We also evaluated the kernel within multi-layer models using the MMLU and RULER benchmarks, con-firming that model accuracy and system robustness are fully preserved in end-to-end scenarios. Extensive evaluations have been conducted to demonstrate the efficiency of the proposed kernel. In microbenchmarks, our implementation consistently outperformed standard baselines, which are PyTorch SDPA, SGLang’s attention ker-nel, and PyTorch FlexAttention, by up to a 2.01 × speedup on long sequences. End-to-end evaluation using SGLang as the serving framework demonstrated corresponding im-provements in Time-to-First-Token (TTFT) across multiple models (Llama-3.1-8B, Qwen3-8B, and Mistral-7B-v0.3), revealing the kernel’s effectiveness in accelerating the LLM prefill phase. Furthermore, comparative analysis against vLLM’s framework-level attention scheduler paired with its optimized kernel shows that integrating scheduling di-rectly inside the kernel achieved performance gains, while maintaining framework portability without requiring custom framework modifications. Finally, the experimental results confirm the contributions of both proposed mechanisms. Cache-aware scheduling improves L3 cache hit rates and reduces DRAM read volume, while cost-prioritized schedul-ing delivers up to a 1.44 × speedup on a heterogeneous CPU architecture. Both optimizations interact to substantially improve latency performance. While the current algorithm effectively covers common sce-narios, there are certain limitations. The current algorithm assumes standard causal attention. Modified attention pat-terns, such as attention sinks or custom sparsity masks, change the computational cost model used for load balanc-ing and the memory access patterns. These can degrade the L2 and L3 cache locality. However, the underlying concepts are flexible. The scheduling criteria can be extended to ac-commodate prefill variants, custom masking patterns, and also decode. As the attention mechanisms evolve to support emerging LLM serving and agentic AI workloads, we will continue to improve this algorithm to support non-standard masking structures and variants of attention based on the principles proposed. B.1 Hardware Infrastructure 

To evaluate both the execution performance and numerical accuracy of the proposed algorithm, we conduct experi-ments across two distinct CPU architectures: • Enterprise Platform: We use Intel Xeon 6767P (Xeon 6767P) as it supports Intel Advanced Matrix Exten-sions (AMX) and AVX-512 instruction sets, which enable fused and overlapped execution of GEMM and Softmax operators. It also features a large L3 cache (336MB). • Client Platform: Intel Core Ultra 7 265K (265K) is used as it is a hybrid processor architecture (comprising P-cores and E-cores), which supports AVX2 and is equipped with a relatively small 30 MB L3 cache. B.3 Input and Benchmarks 

All benchmarks are evaluated using Brain Floating Point 16 (bf16 ), one primary numerical precision used in modern Large Language Model (LLM) inference. Inputs are format-ted as 4D tensors with dimensions [B, H, S, D ]. The ker-nel microbenchmarks evaluate full-sequence causal prefill, where the query and key/value tensors have equal sequence lengths. Most experiments use a batch size of 1 to isolate single-sequence kernel performance and examine its scaling with sequence length. We also evaluate across representative Multi-Head Attention (MHA, 32:32) and Grouped-Query Attention (GQA, 32:8) configurations. Sequence lengths ( S)range from 4,096 (4K) to 131,072 (128K) tokens, with head dimensions ( D) set to 128 or 192. If not specified, the input shape will be [1,32, S,128] with GQA 32:8 as this is the typical shape for models. For performance benchmarking, we adopted the following execution scheme: experiments on sequence lengths from 4K to 32K were measured over 20 iterations, while sequences of 64K and 128K were evaluated over 10 and 5 iterations respectively. The average latency across iterations is reported. 

B.4 Kernels 

We implement the proposed algorithm using the Py-Torch Codegen mechanism. The custom kernel is au-thored as a C++ template, which is similar to the cur-rent existing CPU FlexAttention, under PyTorch Code-gen. This allows PyTorch to serve as a unified bench-marking runtime. We selected the mainstream atten-tion kernel implementations in SGLang, vLLM and Py-Torch as our primary baselines, as they represent the cur-rent state of the art for LLM serving. The kernels ex-tracted from SGLang and vLLM are built as custom op-erators and bound via the PyTorch TORCH LIBRARY mechanism. The standard baselines, which are the torch.nn.functional.scaled dot product attention (SDPA) and torch.nn.attention.flex attention, are executed directly through the native PyTorch APIs without modification.
