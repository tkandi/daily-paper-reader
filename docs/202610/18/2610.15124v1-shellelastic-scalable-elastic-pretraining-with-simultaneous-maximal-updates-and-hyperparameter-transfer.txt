ABSTRACT
Foundation models need to support diverse inference budgets, yet training a sepa-
rate model for each budget duplicates pretraining effort. Elastic models train sev-
eral nested sub-networks inside one weight-shared supernet, but existing recipes
face three obstacles: variable per-step workloads that hinder distributed scaling,
limited hyperparameter (HP) transfer across model sizes, and no guarantee that
all sub-networks are maximally updated at once. We present SHELLELASTIC,
an elastic transformer that organizes hidden dimensions into a dense core and
successive shells, so that every hidden matrix is block lower triangular. One full-
width forward pass contains every sub-network’s exact hidden states as prefixes,
so joint training keeps a fixed computation graph and costs about as much per
step as training the widest sub-network alone. We further introduce µ-ELASTIC,
an extension of maximal update parameterization (µP) to SHELLELASTIC and
other elastic architectures. Its scaling rules provably keep all sub-networks of a
supernet maximally updated simultaneously (µ-Internal), and keep doing so when
the supernet is widened or given more shells; sweeps confirm that HPs tuned on
a small non-elastic proxy stay near-optimal for elastic families and larger super-
nets (µ-Transfer). A single SHELLELASTIC run produces sub-networks that out-
perform MatFormer and fully elastic baselines at matched parameter counts, and
approach separately trained models that together take several times the steps.

INTRODUCTION
Foundation models need to support different compute budgets for different tasks and deployment
platforms. Elastic training answers this need by optimizing several nested sub-networks inside one
shared parameter set: slimmable networks and Once-for-All established the idea for vision mod-
els (Yu et al., 2018; Cai et al., 2020), MatFormer nests the FFN width of a transformer and underlies
released on-device models (Devvrit et al., 2024; Gemma Team, 2025), and Flextron and Nemotron
Elastic make pretrained LLMs elastic by post-training (Cai et al., 2024; Taghibakhshi et al., 2025).
Three problems remain when the elastic training recipe is carried into foundation-model pretraining.
Scalability. Standard recipes sample one or a few sub-networks per step (Devvrit et al., 2024; Yu &
Huang, 2019), so the computation graph, the parameter access pattern and the workload change from
step to step; under parameter sharding this variability complicates activation memory, recomputation
and distributed scheduling, the very machinery that large-scale pretraining depends on. Training all
sub-networks at every step fixes the workload but needs a forward and backward pass per sub-
network, so the cost grows with the family size and erodes the saving that motivates elastic training.

Transferability. Hyperparameters (HPs) tuned at one model size need not remain effective at another,
and repeating the search over learning rate, initialization scale and weight decay at every target
scale cancels the compute that elastic training saves. Maximal update parameterization transfers
HPs across widths for independently trained models (Yang et al., 2021); elastic models add two
questions: can HPs tuned on a non-elastic proxy serve an entire elastic family, and can those tuned
on a smaller elastic family serve a larger one? We refer to these two forms of transfer as µ-Transfer
for elastic models and seek one scaling rule that delivers both under parameter sharing.
Simultaneous maximal updates. Existing elastic training recipes do not generally ensure maximal
updates for all sub-networks simultaneously.1 Without width-dependent scaling, HPs that yield
well-scaled feature updates in one sub-network make updates vanish or blow up in another, and
re-tuning one global value only trades one width against another, so some widths stay mis-scaled.
The requirement is therefore a shared parameterization that keeps every width maximally updated
simultaneously despite parameter sharing; we call this property µ-Internal for elastic models.
We address the first problem with a new architecture, SHELLELASTIC, and the other two with µ-
ELASTIC. SHELLELASTIC (Figure 1) partitions the residual stream into a dense core followed
by ordered shells, each a multiple of a base width g, and each supported sub-network is the core
plus a prefix of the shells. Every hidden matrix is block lower triangular: a shell reads the core,
the earlier shells and itself, but never a later shell. Trunk normalization acts within each group,
attention heads align with the group boundaries, and every supported width has its own readout. One
full-width forward pass therefore contains the exact hidden states of every sub-network as prefixes
(Proposition 1), and the per-step compute stays close to that of a single full-width pass however
many sub-networks are trained, so every step has a fixed workload, as in non-elastic training.
µ-ELASTIC (Figure 2) extends maximal update parameterization (µP) (Yang et al., 2021) to elastic
models with two factors: a µ-Transfer factor m = g/d0 that carries HPs from a non-elastic proxy of
width d0 to base width g, and a µ-Internal factor for the different widths inside one shared model.
Every group reads the same input coordinates in every sub-network that contains it, so we set its
initialization, learning rate and weight decay from this fan-in, while each readout uses its own input
width (Table 1). This keeps every group maximally updated in all sub-networks at once (Theorem 1),
which uniform scaling across groups cannot do in general (Proposition 2). The same two factors
apply to MatFormer and to fully elastic models (Appendix D).
Our main contributions are summarized as follows:
★Scalable elastic architecture. We propose SHELLELASTIC, an elastic transformer whose
single full-width forward pass yields the exact hidden states of every sub-network as pre-
fixes, so every step has a fixed workload rather than a varying one.
★µ-ELASTIC parameterization. We introduce µ-ELASTIC, which transfers HPs from a
non-elastic proxy to an elastic model and from smaller to larger elastic models (µ-Transfer),
and keeps all sub-networks of a supernet maximally updated at once (µ-Internal).
★Theoretical and empirical validation. We prove that µ-ELASTIC keeps all sub-networks
maximally updated at both levels of transfer; sweeps confirm that transferred HPs stay near-
optimal and that µ-ELASTIC beats the standard parameterization on every elastic family.
★Comprehensive ablation studies. We search architectures at equal parameters and ablate
sub-network selection, loss weights, normalization scope, readout design, in-place distil-
lation, sub-network ensembles and stage-residual gradient scaling for elastic pretraining.

HP transfer and µ-parameterization. Tuning HPs such as the learning rate and initialization is
expensive at scale, and under the standard parameterization (Sohl-Dickstein et al., 2020) their optima
drift with width, so a small model cannot stand in for a large one (Yang et al., 2021). Scaling HPs
with model size removes this drift, so values tuned on a small proxy transfer zero-shot (Yang et al.,
2021; Dey et al., 2026). Building on infinite-width theory (Jacot et al., 2018; Mei et al., 2018), Yang
& Hu (2021) identified µP, a parameterization that gives every layer maximal Θ(1) feature updates
as width grows, and Yang et al. (2021) turned it into a transfer rule for initialization, learning rate
and multipliers. CompleteP extends the rule across depth for pre-norm transformers (Yang et al.,
2024; Bordelon et al., 2024; Dey et al., 2026), and Mlodozeniec et al. (2026) add batch size and
token budget. Everett et al. (2024) derive per-layer learning-rate exponents across parameterizations
and optimizers, including Adam, and find that HP transfer is not limited to µP; Table 1 follows
their scaling rules. These rules assume separately trained models, where each tensor has one fan-in;
µ-ELASTIC extends them to the shared tensors of an elastic supernet.

In the SHELLELASTIC architecture, all sub-networks reuse hidden-state prefixes from one full-width
trunk pass; µ-ELASTIC, a parameterization based on each weight’s active input width, enables reuse
of base optimization settings across model sizes.

µ-ELASTIC for other elastic architectures.
µ-ELASTIC carries over to other elastic architec-

For a chosen width s ∈S, we retain the embedding prefix, the core and shells up to
s, and the matching terminal norm and readout, keeping the forward multipliers of Table 1. By
Proposition 1, the extracted model reproduces its supernet logits exactly and runs as a standalone
transformer of width sg without further training.

EXPERIMENTS
After describing the setup (Section 4.1), we evaluate the sub-networks of one SHELLELASTIC run
against parameter-matched MatFormer, fully elastic and separately trained models, and µ-ELASTIC
against SP on every elastic family (Section 4.2). We then compare SHELLELASTIC with StairFormer
and run an architecture search at equal parameters and width count (Section 4.3); finally, we ablate
the training and design choices to derive practical guidance for elastic pretraining (Section 4.4).
4.1
EXPERIMENTAL DETAILS
Models.
Our primary model is a SHELLELASTIC supernet with base width g = 128 and supported
set S = {4, 5, 6, 7, 8}: a 512-dimensional core followed by four 128-dimensional shells, giving five
sub-networks of widths 512 to 1024. We report main results at three scales, with sub-networks of
about 119M–285M, 375M–906M and 675M–1.69B parameters (SHELLELASTIC widths 512–1024,
1024–2048 and 1024–2048, respectively). All models are 32-layer transformers with gated attention
and SwiGLU FFNs. Tables 7 and 8 in Appendix E list all configurations.

ery sub-network, the latter on held-out C4 text (Raffel et al., 2020; Dodge et al., 2021). Following

Baselines.
We compare SHELLELASTIC against five baselines, each providing networks of five
sizes: Low, Medium, High, Extra and Max. (i) MatFormer (Devvrit et al., 2024) nests only the
FFN hidden width. (ii) Fully elastic, a transformer adaptation of slimmable networks (Yu et al.,
2018), nests the residual, attention and FFN widths by slicing shared dense matrices. (iii) Stair-
Former (Trost et al., 2026) shares the prefix structure of SHELLELASTIC but uses equal-width
groups and normalizes over cumulative prefixes. (iv) Standalone trains five separate models, each
on the full budget, and thus takes 5× the steps of one elastic run. (v) Sampled standalone, the stan-
dalone baseline of MatFormer, trains the five Standalone models within the steps of one elastic run.
MatFormer, the fully elastic model and sampled standalone sample one sub-network uniformly at
random per step, whereas StairFormer and SHELLELASTIC train all sub-networks in one full-width
pass at every step. In the main results, all baselines match the SHELLELASTIC sub-networks
in parameter count to within 3% (Table 10). Appendix E details the baselines’ architecture and
training, and Appendix D gives their parameterization.
Hyperparameters.
All models are trained with AdamW. Unless otherwise specified, they use
the base learning rate η0 = 2 × 10−3, initialization scale σ0 = 3.3 × 10−3 and weight decay
λ0 = 0.01, with µ-ELASTIC for the elastic models and µP for the non-elastic ones, both with
d0 = 128. SHELLELASTIC has m = 1 and trains all five widths at every step with loss weights
(1, 1, 1, 1, 4) (Equation 8). Main results at the 119M–285M and 375M–906M scales are averaged
over three runs with the same seed; compute limits the 675M–1.69B scale to one run. Ablations
vary only the setting under study; Table 9 in Appendix E lists the remaining HPs and the hardware.

4.3
ARCHITECTURE COMPARISON AND SEARCH
Comparison with StairFormer.
StairFormer (Trost et al., 2026) nests sub-networks as prefixes
of one forward pass; it uses equal-width groups, cumulative prefix normalization and one shared
readout. Here it has g = 208 and S = {1, 2, 3, 4, 5} in our notation, whereas SHELLELASTIC has
a 512-wide core and four 128-wide shells (S = {4, 5, 6, 7, 8}), group-local normalization and per-
width readouts. Like SHELLELASTIC, it trains all sub-networks at every step; we give it the same
µ-ELASTIC and HPs (Section 4.1). Its narrower sub-networks are much smaller (32.6M to 200.4M);
only its Max matches SHELLELASTIC in size. At the parameter count of each SHELLELASTIC sub-
network, its validation loss is 0.055 to 0.083 nats higher (Figure 4a; curves in Figure 17), and even
its Max, with 1.5× the parameters, is 0.001 nats above the High of SHELLELASTIC. At Max,
SHELLELASTIC also leads in average 5-shot accuracy, 36.9 against 35.7 (Figure 4b and Table 29).
Architecture search at equal parameters and width count.
Since S fixes both the extractable
widths and the parameter count (a hidden matrix keeps B(S) = P
k(sk −sk−1)sk of its M 2 blocks
of size g × g), we ask where extra width should go when B and the number of supported widths are
fixed. At B = 42 with five supported widths, each candidate set has four groups of width g and one
of width 4g and differs only in where this wide group sits (block masks in Figure 18); at B = 39
with six, the wide group has width 3g (Appendix I.2). We train every supported width at every step
and compare the sets at each width they share with equal parameter counts (Figure 4c). The core is
the best place for the wide group: the core placement has the lowest loss, or is within 0.006 nats of
it, at every shared width, whereas a shell placement makes the first width containing the wide group
0.025 to 0.052 nats worse. This motivates the wide core and thin shells of SHELLELASTIC.

Selected sub-networks per step.
Besides training all five sub-networks at every step (All, the
default), we test three rules for Aτ in Equation 8: Sandwich (Low and Max plus one other), Max +
random (Max plus one other) and Random (one sub-network, as in MatFormer), drawing the random
ones uniformly at random. The loss of each sub-network follows how often it is trained: Sandwich
and Max + random match All at Max but are up to 0.024 and 0.086 nats worse at those they select
less often, and Random is worse at every sub-network, by 0.095 nats at Max. All gives the lowest
mean loss, 0.012 to 0.059 nats below the others, and the highest mean 5-shot accuracy.
In-place distillation.
Elastic recipes often distill the narrower sub-networks from the widest
one (Yu & Huang, 2019). We add to the losses of Low to Extra a KL divergence toward the output
distribution of Max (forward KL with weights 0.1 to 1; reverse and symmetric KL with weight 0.5).
This lowers the loss of Low by up to 0.034 nats and the mean loss by up to 0.010 nats, the largest
gain of any ablation, but raises that of Max by up to 0.008 nats, improves the mean 5-shot accuracy
by at most 0.1 points and makes a step 2.2 to 2.6 times as long, so we do not use it.
Ensembles of the sub-networks.
One trunk pass yields the output distributions ps of all five sub-
networks, which may err on different tokens, so a per-token ensemble P

predictor at little extra cost, or replace it as a stronger teacher (details in Appendix J).

semble, whose weights minimize the loss. We also train a router, an MLP that maps the last-layer

nats while the other sub-networks, now barely trained, lose up to 0.365 nats (Figure 5c).

Stage-residual gradient scaling.
Since the readout is linear (Equation 6), the logits of width sk
are a sum of k terms, one from the last-layer coordinates of each of its groups, so the supernet can be
viewed as a sequence of stages: the core gives a base prediction and each shell adds a correction, as
in residual learning (He et al., 2016). To make each shell learn this correction, we keep the forward
pass but, in the backward pass, scale by γ the gradient that each sub-network’s loss sends to the
trunk through the narrower sub-network it contains; the gradient through its own shell is unchanged
(details in Appendix J). Thus γ = 1 is the usual joint training of Equation 8, while with γ = 0
each loss reaches the trunk only through its own shell, which therefore learns only to correct the
prediction of the narrower sub-network. A γ of 0.3 to 0.8 lowers the loss of Low by up to 0.028
nats but raises those of Extra and Max by up to 0.012 nats, leaving the mean loss within 0.002
nats, whereas γ = 0 raises the mean loss by 0.047 nats, as the last-layer features of the narrower
groups no longer adapt to the wider losses; we keep γ = 1. The stage view still points to a property
that MatFormer and fully elastic models lack: since no group reads a later one and every group is
normalized on its own, a new shell can be appended to a trained supernet and trained as a new stage
with all trained weights frozen, so every trained sub-network keeps its exact outputs.

CONCLUSION
In SHELLELASTIC, one full-width pass gives the exact hidden states of every sub-network, so joint
training costs about as much as the widest one alone. With µ-ELASTIC and proxy-tuned HPs, one
run yields maximally updated sub-networks that beat MatFormer and fully elastic models at matched

Comparison with other elastic architectures.
MatFormer keeps the model width, attention, nor-
malization, embedding and readout at full width and nests only the FFN hidden width. A fully elastic
model slices dense matrices along both axes and normalizes over the active width. In both cases,
channel mixing is dense, so the hidden states of a narrow sub-network are not contained in those of

which is exactly what lets the supported prefixes share a single trunk pass (Proposition 1).

B.2
PROOF OF PROPOSITION 1
Proof. We show that every operation of a layer is prefix-preserving (Steps 1–4) and then compose
the operations over the L layers (Step 5).
Step 1: projections. The query, key, value, gate and output projections of attention and the up, gate
and down projections of the FFN are structured linear maps. Lemma 1 therefore applies to each of
them, with gin = gout = g for the attention projections, (gin, gout) = (g, eg) for the FFN up and
gate projections, and (eg, g) for the FFN down projection.
Step 2: group-local normalization. By Equation 3, N(x)Gk = Nk(xGk) uses only the coordinates
and gains of Gk, so the first sg outputs depend only on the first sg inputs, and Ps◦Nt = Ns◦Ps. The
same holds for any finer partition and for a cumulative prefix norm, whose statistics for a coordinate
use all coordinates up to the end of its group or of its block of g coordinates (Equation 25); for any
of the first sg coordinates, that end is at most sg. A norm over the full active width does not preserve
prefixes, because adding a group changes the statistics of the earlier coordinates.

B.3
NUMERICAL VERIFICATION AND SCOPE
Numerical verification.
We instantiated the full trained configuration on the meta device to check
module selection and shapes, and ran a reduced two-layer model on CPU with the same architecture
switches, comparing one shared trunk pass against five separate evaluations of the same nested
weights. The logits and the weighted cross-entropy agreed exactly; the largest absolute difference
between the two sets of parameter gradients was 1.68×10−8, and every trainable parameter received
a gradient. The check replaces the fused SwiGLU and cross-entropy kernels of the GPU path with
reference expressions, so it supports the implementation of Proposition 1, not its throughput.
Scope of the statement.
The proposition assumes the dense-FFN graph of Section 3.1, a fixed
supported set S and prefix-preserving normalization. Beyond these assumptions:
• dropout needs matched masks for an equality test;
• data-dependent routing or width-specific trunk modules need a separate argument;
• Equation 2 fixes the logical dependencies and not a storage layout or a kernel: every im-
plementation of that map has the prefix property.

Activation checkpointing.
The runs of Table 11 train with activation checkpointing on every other
transformer block (16 of 32), whose forward pass is recomputed during the backward pass. Training
latency therefore includes this recomputation (on H100 GPUs, the Standalone models train 14–
19% faster without it), and peak training memory keeps only the inputs of the checkpointed blocks
(without checkpointing, Standalone needs 1.9× the memory); inference latency is a plain forward
pass and is unaffected.
Sampled standalone.
Sampled standalone trains the same five models as Standalone, one per step,
so its per-tier latency and memory are those of Standalone: in its training runs, the logged latencies
agree within 2%, and the 2.2–2.6 GB of extra memory it logged comes from our implementation
keeping the four inactive models’ weights and optimizer states on the GPU, which offloading them
would remove.
Observations.
Two observations emerge:
• The shared trunk is the saving of the architecture. One training step of SHELLELASTIC
updates all five tiers, whereas updating every tier once takes five steps with MatFormer and
the fully elastic model (one per tier) and one step of each model with Standalone.
• Fused kernels lower the per-tier cost. At equal parameters, all methods need about the
same effective FLOPs per tier, so the lower per-tier latency and memory of SHELLELASTIC
in Table 11 come from our fused implementation: Triton kernels compute the RMSNorms
of every transformer block, including the query and key normalizations, and read the
queries and keys directly from the output of the QKV projection without copying them.

World knowledge.
Exam-style and science questions that probe academic knowledge.
• MMLU (Hendrycks et al., 2020) (14,042 items, four-choice): exam-style questions from
57 subjects across the sciences, humanities and social sciences.
• ARC-Easy and ARC-Challenge (Clark et al., 2018) (2,376 and 1,172 items, four-choice):
grade-school science questions; the Challenge subset holds the questions that retrieval and
co-occurrence methods answer incorrectly.
Symbolic problem solving.
Arithmetic reasoning with a generated answer.
• SVAMP (Patel et al., 2021) (300 problems, free-response): short arithmetic word problems
with numerical answers; the model generates a derivation followed by the answer, which is
scored by exact match.
Commonsense reasoning.
Everyday causal and physical knowledge.
• COPA (Gordon et al., 2012) (100 items, two-choice): choose the more plausible cause or
effect of a premise.
• PIQA (Bisk et al., 2020) (1,838 items, two-choice): choose the more sensible solution to a
physical task.
Language understanding.
Narrative coherence, coreference and the use of broad context.
• HellaSwag (Zellers et al., 2019) (10,042 items, four-choice): choose the most plausible
continuation of a partial narrative.

• WinoGrande (Sakaguchi et al., 2021) (1,267 items, two-choice): fill a blank with one of
two candidates so that the sentence is coherent.
• LAMBADA (Paperno et al., 2016) (5,153 passages): predict the final word of a passage
that requires broad discourse context.
Reading comprehension.
Questions answered from a given passage or argument.
• BoolQ (Clark et al., 2019) (3,270 items, yes/no): answer a binary question about a short
passage.
• AGIEval LSAT-RC, LSAT-LR and SAT-EN (Zhong et al., 2024) (268, 510 and 206 items,
four-choice): LSAT reading-comprehension and logical-reasoning questions and SAT En-
glish questions.

ARCHITECTURE COMPARISON AND SEARCH
This appendix complements Section 4.3: Appendix I.1 gives the per-task results and training curves
of StairFormer, and Appendix I.2 details the architecture search at equal parameters and width count.
I.1
COMPARISON WITH STAIRFORMER
StairFormer (Trost et al., 2026) nests sub-networks as prefixes of one forward pass with equal-width
groups, S = {1, . . . , M} in our notation; it normalizes over cumulative prefixes (Equation 25)
and shares one terminal-norm gain and one readout across sub-networks. Our StairFormer base-
line has five 208-wide groups (g = 208, S = {1, 2, 3, 4, 5}) with dhead = 104, so that each
group holds two complete heads, and an FFN hidden width of 236 per group (e ≈1.13, against
e = 1 for SHELLELASTIC), so that its Max matches that of SHELLELASTIC in parameters. Like
SHELLELASTIC, it trains all sub-networks at every step; we give it the data, steps, HPs and loss
weights of Section 4.1, and µ-ELASTIC with m = 208/128 = 1.625 (Appendix D). Table 29 gives
its per-task results at every tier, and Figure 17 its training curves next to the methods of Table 2 other
than sampled standalone. Two observations emerge:
• Only Max is parameter-matched. StairFormer’s Max and that of SHELLELASTIC both
have 279.6M parameters, but at Tiers 1–4, StairFormer’s sub-networks are 14–73% smaller
(32.6–200.4M against 118.8–233.1M), so these pairs compare sub-networks of different
sizes; Figure 4 compares the validation loss and average 5-shot accuracy against parameter
count.
• At Max, SHELLELASTIC is better on most tasks. At the matched size, SHELLELASTIC
is better on 9 of the 13 tasks and worse on 4 (MMLU, SVAMP, WinoGrande and LSAT-
RC).

• Four ensembles of a trained supernet: uniform weights, πs = 1/5; confidence weights,

that assigns the target the highest probability.
• Learned router: a two-layer MLP (1024 →256 →5, SiLU) maps the last-layer hidden

five logits into the per-token weights πs; its output layer is initialized to zero, so the weights
start uniform. It is trained jointly with the supernet, whose loss becomes the π-weighted
sum of the five losses at every token plus 0.01 times their unweighted mean, which keeps
every sub-network trained.

• Separately trained models ensemble well. Averaging the Max of two supernets trained with

• Low gives the largest share of the gain. With Low and Max alone, the oracle is already

Every width has its own readout and terminal norm, which only its own loss trains, so for γ > 0
Adam, being invariant to the gradient scale, still trains them in full; the scaling only reduces the
gradient that these coordinates pass on to the trunk. The forward pass is unchanged, and γ = 1 is

losses still train the narrower groups inside the trunk.
Observation: A γ between 0.3 and 0.8 lowers the loss of Low by up to 0.028 nats but raises those
of Extra and Max by up to 0.012 nats and leaves the mean loss within 0.002 nats. With γ = 0, Low
is 0.003 nats lower, but the wider widths lose more, from 0.036 nats at Medium to 0.071 at Extra
and Max, and the mean loss rises by 0.047 nats, as the last-layer features of the narrower groups no
longer adapt to the losses of the wider widths. We therefore keep γ = 1.
Outlook: Although γ < 1 does not lower the mean loss here, the stage view matches a property that
SHELLELASTIC has but MatFormer and fully elastic models lack: it can grow after training. Since
no group reads a later one (Equation 2) and every group is normalized on its own (Equation 3), a
new shell GK+1 can be appended to a trained supernet and trained as a new stage, for example on
downstream data, while all trained weights stay frozen, so every trained sub-network keeps its exact
outputs. MatFormer and fully elastic models cannot grow this way: new FFN units of MatFormer
write into the hidden states that its trained layers read, and new channels of a fully elastic model
change the inputs of every trained weight in the wider sub-network, so their trained weights would
operate on inputs they were not trained on.
