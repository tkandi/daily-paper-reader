# NOMAI : Scalable Federated Learning with Private Weights 

## Yiyi Sun ∗ Mushtari Sadia ∗ Amrita Roy Chowdhury ∗∗University of Michigan, Ann Arbor 

## Abstract 

The twin goals of privacy-preserving federated learning (FL) – harnessing distributed data while protecting the parties who contribute it–demands three properties: model privacy, data privacy, and integrity. Achieving all three in a realistic deployment–with a single coordinator and millions of users– remains an open challenge that prior work has yet to fully resolve. We present N OMAI , the first scalable MPC-based FL system to provide all three guarantees simultaneously. NOMAI operates under an honest-majority assumption in the semi-honest model, with an extension to the malicious-with-abort setting. At its core, N OMAI combines a multi-committee MPC architecture with packed Shamir secret sharing, enabling SIMD-style secure computation that scales far beyond what monolithic n-party protocols can support. We further intro-duce ML-aware optimizations and new cryptographic primi-tives that substantially reduce per-user overhead. Our evalua-tion shows N OMAI is practically deployable at unprecedented scale: it reduces per-user computation to just <350 ms (semi-honest) and <700 ms (malicious) for per iteration of training MNIST, achieving three orders-of-magnitude improvements over prior work while seamlessly supporting populations of over 10 6 users. This demonstrates, for the first time, that MPC-based FL can meet the scale demands of real-world systems without compromising on privacy or integrity. 

## 1 Introduction 

Federated learning (FL) is a distributed training paradigm in which a massive number of users collaboratively train a global model without ever centralizing their raw data. FL is widely deployed, from Google’s next-word prediction across Android devices [32] to Apple’s on-device intelligence across iPhones [6]. Yet this is not without serious security vulnerabil-ities. FL involves two parties with competing incentives–users and a coordinating server. Users aim to keep their local data private; in many deployments, this data captures highly sensi-tive behavior that must never be exposed to the server or other participants. The server, typically a commercial organization, seeks to protect its proprietary model weights as intellectual property and to prevent leakage of sensitive training dynamics. The distributed nature of FL further expands the attack sur-face. Malicious users can inject poisoned or malformed data to degrade global model performance [10, 11, 22, 33, 39], or embed backdoors that are only triggered at test time [7,16,59]. Beyond security, any practical solution must satisfy two constraints that are crucial in real-world deployments. First, it must operate in a single-server setting, with one persis-tent entity responsible for orchestrating training, distributing model updates, and aggregating results. Such a setting may use lightweight user helpers, but it cannot rely on more non-colluding servers. This reflects real-world FL deployments; in-troducing multiple servers would alter the deployment model and incur substantial infrastructure overhead. Second, the so-lution must scale to millions of users . The power of FL comes precisely from broad participation and any approach that fails to scale to this regime undermines the core promise of FL. 

Related work. Prior work falls into two camps. Scalable single-server approaches primarily focus on either data pri-vacy and integrity [8, 36, 37, 48, 49, 56], but assume model weights are revealed in the clear to users. The only prior work that attempts to address both data and weight privacy in the single-server setting is POSEIDON [50]. However, it falls short in several ways. First, it does not provide data integrity. Second, it operates in a semi-honest threat model. Finally, it relies on homomorphic encryption-based computation, which significantly limits scalability, as we empirically verify in Sec. 8.2. The other line of work considers secure training protocols that achieve all three security guarantees but as-sume multiple non-colluding servers. In the context of FL, this effectively transforms the problem into outsourced com-putation, where users delegate their data to a set of servers. Additionally, scalability remains a major bottleneck in this setting as well, as verified in our experiments. Achieving all three remains an open challenge that prior work has yet to fully resolve. We close this gap.

## 3 Problem Setting 

We consider a standard cross-device FL setting with N users and a single coordinating server. Each user ui holds a private data point xi2. The server is untrusted and aims to train a global model M over the joint dataset X = {xi}i∈[N] without directly accessing user data. Training proceeds over multiple rounds. In each round, the server maintains the current param-eters of M and obtains the aggregate gradient G = ∑i∈[N] gi,where gi is the gradient computed from user ui’s local data. The server then uses G to update the model for the next round. 

## 3.1 Security Goals 

• Data Privacy (User’s Goal). For every honest user, no other user should learn any information about its raw pri-vate data xi. The server learns only the final aggregate G

and nothing beyond what is revealed by this aggregate. 

• Weight Privacy (Server’s Goal). The model parameters held by the server should remain hidden from the users. 

• Data Integrity (Server’s Goal) 3. The server seeks to en-sure that individual user gradients are well-formed. To this end, it enforces a validation predicate Valid (·) that defines a syntax for the gradients. A gradient g is considered valid if and only if Valid (g) = 1. For example, per-gradient checks such as norm bounds are natural instances of Valid (·).

Reflecting these goals, we consider a corrupted server and as-sume that an η fraction of users may be adversarial, under both semi-honest and malicious-with-abort threat models [21].

## 3.2 Design Goals 

• Single-coordinating server deployment. NOMAI should preserve the standard FL deployment model, in which a single server coordinates and orchestrates training. Lightweight MPC helpers are permitted, but the system must not require additional non-colluding servers. 

• No user pre-processing. A common way to speed up MPC is a data-independent pre-processing phase that generates randomness (e.g., Beaver triples), via multiple rounds of interaction. In cross-device FL, however, users are inter-mittently available. Since requiring such pre-processing introduces significant coordination challenges, in N OMAI ,users should participate only in the online phase. We still allow independent local pre-computation by users. 

• Low computation cost for users. Users are resource-constrained devices (e.g., edge devices). Therefore, N O-

MAI aims to ensure all user-side operations are efficient. 

## 4 Technical Overview 

We present the key technical ideas underlying N OMAI , orga-nized around the design goals above. 

Single Coordinator Deployment. Ensuring gradient privacy re-quires performing gradient computation under MPC, i.e., each training round is a secure computation. Prior work [12, 41] typically assumes multiple non-colluding servers, which con-flicts with our single coordinating server setting. A naive alternative is an (N + 1)-party protocol among all users and the server, but this is prohibitively expensive at scale. NOMAI overcomes this via two ideas. First, instead of a sin-gle N-party protocol, users are partitioned into c disjoint com-mittees of size n ≪ N. Committees are constructed to bound corruption, using an efficient procedure with Ω(c) work per user. Each user’s data is assigned to one committee, yielding disjoint data shards of size N/c. Within each committee, data is secret-shared and an MPC protocol is run independently to compute a local gradient aggregate. This reduces the cost 3from a N-party to a n-party computation, with c committees running in parallel. Second, we use packed Shamir secret sharing to encode l values per share, enabling SIMD-style computation and a further l-fold speedup within each commit-tee. Together, these yield an overall speedup of roughly Nc·l .Each committee produces a partial aggregate, which are then securely combined into the final global aggregate revealed only to the server (Fig. 1). 

Eliminating pre-processing. Secure ML training typically re-lies on pre-processing to generate data-independent random-ness: correlated randomness (e.g., Beaver triples) for multi-plications and random masks for non-linear operations such as truncation. N OMAI eliminates both through careful proto-col design. For multiplications, appropriate parameters allow Shamir secret sharing to perform local share-wise multipli-cation followed by degree reduction, requiring no correlated randomness. For non-linear operations such as truncation, which typically require bit decomposition and additional ran-domness, N OMAI avoids this overhead by operating over Mersenne primes (2 b − 1) for efficient modular arithmetic and bit operations, and leveraging users to supply randomness efficiently under PSS .

Computational Efficiency. While Shamir sharing supports lo-cal multiplication, each multiplication doubles the polynomial degree, requiring degree reduction to continue computation. Naive interpolation costs O(n2), while FFT-based methods achieve O(n log n) but require FFT-friendly primes. Since NOMAI uses Mersenne primes for efficient truncation, these optimizations are unavailable, making degree reduction a cen-tral bottleneck. We address this with techniques that reduce both the number and cost of these operations. 

Efficient Linear Layers. Our first set of techniques targets the dominant source of multiplications in training–linear layers which involve different types of matrix operations. N OMAI 

reduces this cost through two key ideas. First, we adopt Winograd convolution for convolutional layers, a transformation that reduces the number of multipli-cations by converting convolution into a sequence of small linear transforms and element-wise products. To the best of our knowledge, this is the first use of Winograd-style tech-niques in secure ML training. However, a direct application of Winograd is not well-suited to PSS . To address this, our second key idea is to design novel packing strategies that retain Winograd’s compu-tational advantages while remaining compatible with packed representations. By carefully aligning data layout with com-putation, N OMAI maximizes parallelism while minimizing non-scalar multiplications and hence the number of expensive degree–reduction steps. Similarly, we design new packing strategies for fully connected layers as well. To the best of our knowledge, we are the first ones to design packing strategies tailored to Shamir secret sharing for secure ML training.

Efficient Degree Reduction Protocol. A central bottleneck in Shamir-based MPC is degree reduction: each secret–secret multiplication produces a degree-2 d sharing that must be re-duced to degree d before further computation. In PSS , this cost is amplified by frequent reshaping and repacking across layers. Existing approaches either rely on FFT-based interpo-lation, incompatible with Mersenne primes, or incur overhead from explicit unpacking and repacking. N OMAI addresses this with an efficient degree-reduction protocol. 

Efficient Malicious Security. Standard approaches to ma-licious security under Shamir secret sharing, such as Reed-Solomon decoding and verifiable secret sharing, incur sig-nificant computational overhead. While straightforward to integrate into our protocol, their cost becomes prohibitive at the scale of practical FL. N OMAI achieves a significantly more efficient design via two new ideas that exploit unique properties of the FL setting. First, we make a crucial observa-tion about the FL threat model: in addition to being malicious in the traditional sense of cryptographic protocols, malicious 4users in FL can corrupt the final aggregate by directly sub-mitting malformed or poisoned data. Hence, as discussed in Sec. 3.1, ensuring data integrity –that all gradients satisfy a prescribed validity condition–is a central server goal. This means that simply performing the gradient computation fol-lowed by a secure aggregation with malicious security is not 

sufficient; explicit well-formedness checks on each gradient are required regardless. N OMAI turns this observation into an efficiency gain: since well-formedness must be checked anyway, we execute the expensive gradient computation using a cheap semi-honest protocol and enforce malicious security 

only at the validity check. This dramatically reduces cost, as the heaviest part of the computation–gradient computation– runs in the cheaper semi-honest model. Second, we design a novel maliciously secure aggregation protocol that combines 

only well-formed gradients into the final aggregate, ensuring that any malicious behavior is detected unless the adversary restricts itself to manipulations that pass the validity check. Together, these two ideas deliver strong practical security at a fraction of the cost of a fully malicious protocol. 

## 5 Protocol Details 

In this section, we present the core building blocks underly-ing N OMAI . We introduce them in isolation, as they are of independent interest for secure training with Shamir secret sharing, and compose them into a full end-to-end FL system in the next section. We begin in the semi-honest setting; the extension to the malicious setting is deferred to Sec. 6.4. Due to space constraints, we present only the constructions here and defer ideal functionalities and security proofs to App. D. 

## 5.1 Efficient Linear Layers 

Linear layers dominate the computational cost in ML training, as they involve a large number of multiplications and, con-sequently, frequent degree-reduction steps. Hence, we begin by reducing the number of multiplications while remaining compatible with PSS .

5.1.1 Convolutional Layers 

For convolutional layers, we reduce this cost using two ideas. First, we adopt Winograd convolution, which expresses convo-lution as linear transforms and entry-wise products, reducing the cost of an m × m output block with an r × r kernel from 

m2r2 multiplications to T 2, where T = m + r − 1. Concretely, it rewrites the computation as

Thus, the only non-linear step is the transformed-domain entry-wise product U ⊙V .Second, we amplify these savings by tailoring the pack-ing to the structure of Winograd. A natural approach is to pack different coordinates of the same tile into one sharing. However, this is inefficient under PSS , since local multipli-cation by a public constant requires the same constant in all slots, while Winograd applies different coefficients from A, B,or G to different coordinates. Handling slot-dependent con-stants would require secret-share the public coefficients and perform a full secret–secret multiplication, introducing addi-tional degree-reduction round and entirely wasting the benefit of those coefficients being public. Our idea therefore is to pack the same coordinate across many tiles into one sharing. Each transform coefficient is then uniform across all slots, so the Winograd transforms become local operations. To the best of our knowledge, this is the first use of Winograd-style techniques in secure ML training. For clarity, we first describe the protocol for a single input channel and output channel. ## 5.4 Truncation 

We use Mersenne-prime fields ( p = 2b − 1) for efficient trun-cation. First, truncation reduces to bit shifts with a simple MSB-based correction. Second, they provide single-bit slack, allowing values up to 2 b−1 without overflow. This lets us amortize truncation across multiple multiplications rather than after each step, which we later exploit (Sec. 6.2). We build on the truncation protocol of Liu et al. [35], which assumes preprocessed randomness: a mask r, its truncated value r′, and MSB rmsb . Given x, the protocol opens c = x + r,truncates c, and corrects using r and the wraparound term 

cmsb (1 − rmsb ). However, their design targets standard Shamir sharing; we extend it to PSS , where truncation must apply independently to each packed slot without cross-slot interfer-ence. This requires redesigning the randomness generation and correction step. We also avoid explicit preprocessing (Sec. 6.1) and compare with Liu et al. in App. F.2.5.

## 6 NOMAI Description 

We present the design of N OMAI and show how the building blocks from the previous section compose into an end-to-end FL training protocol. The system has three phases: data shar-ing , training , and aggregation (Fig. 1). We first describe the semi-honest protocol, then extend it to the malicious setting. 

Notations. Let C = {C1, · · · , Cc} denote c disjoint committees, each of size n with at most t corrupt members, chosen from 

N users with corruption rate η.

Setup. This one-time phase occurs when users register. As in prior work [37, 49], we assume a public key infrastructure (PKI) [20]. Each user communicates with the server over a private authenticated channel, while user-to-user messages are relayed through the server and encrypted under the recipient’s public key. Each user ui is assigned a unique identifier i ∈ [N].

## 6.1 Data Sharing Phase 

For each training iteration, N OMAI begins with a data sharing phase that secret-shares each user’s data across committees. We use the t-linear sharing optimization [29] to reduce the communication cost of distributing shares. Here, two chal-lenges arise: first, users must share their data blindly, without knowing the recipients. Under the static corruption model, where the adversary fixes corrupted parties in advance, com-mittee assignment must therefore occur after data sharing; otherwise, the adversary could corrupt an entire committee and compromise privacy. Second, some of our packing strate-gies (Sec. 5.1) require combining data from l users into a single vector for efficient computation. ## 6.2 Training Phase 

After data sharing, each committee holds PSS of its assigned inputs, arranged for the first layer. During training, commit-tees independently compute gradients for their users under 

> PSS

, enabling full parallelism with all computation local to each committee. At each iteration, the server distributes PSS

6.2.1 Forward Pass 

Each committee evaluates the model layer by layer on its packed input sharings. Linear layers use the packing-aware protocols from Sec. 5.1. Convolutional layers use the packed Winograd layout, while fully connected layers use the diago-nal representation and chunking strategy from Sec. 5.1.2 

PolyRelu. For non-linear layers, N OMAI replaces ReLU with a low-degree polynomial approximation, PolyReLU. To bal-ance accuracy and efficiency, N OMAI incorporates several ML-aware optimizations: (i) He initialization to preserve variance and prevent vanishing or exploding gradients, (ii) quantization-aware polynomial approximation [19] for nu-merically stable coefficients, and (iii) an activation regular-ization term that penalizes inputs outside the regime where PolyReLU closely matches ReLU [19]. 

Inter-layer Connections. Different layers require different packing layouts. Convolutional layers pack the same Wino-grad coordinate across tiles, while fully connected layers use diagonal chunks. Even between convolutional layers, layouts do not align: Winograd outputs are non-overlapping m × m

tiles, whereas the next layer expects overlapping T × T in-puts. Thus, transitions such as Conv-to-Conv and Conv-to-FC require repacking. Since these are public linear transforma-tions over slots, N OMAI folds them into the degree-reduction step (Sec. 5.3), incurring no extra interaction cost. 

Choosing the cleanup path. After a secret-secret multipli-cation, N OMAI may require three cleanup operations: degree reduction, truncation, and repacking. Degree reduction re-stores a degree-2 d sharing to degree d, truncation restores the fixed-point scale, and repacking adjusts the slot layout when the next computation expects a different packing. These operations have different urgency: degree reduction is manda-tory before the next secret-secret multiplication, otherwise the degree would exceed 2 d and the committee could no longer reconstruct the polynomial; repacking is needed only at lay-out boundaries; and truncation, while required for fixed-point correctness, can be delayed for a bounded number of mul-tiplications. This is because N OMAI operates over a 61-bit Mersenne field with a much smaller fractional scale (e.g., 16 bits), allowing several multiplications before truncation as long as range analysis rules out modular wraparound. Delaying truncation has two benefits: it reduces accu-mulated rounding error, and, when no repacking is needed, exposes a cost tradeoff between ΠPack DegRed and ΠPack Trunc -DegRed .The former incurs higher communication but lower online computation, while the latter reduces communication at the cost of higher online computation. N OMAI therefore selects the cleanup protocol based on both layout requirements and whether truncation is due.

6.2.2 Backward Pass 

The backward pass mirrors the forward pass. Given the secret-shared loss gradient, each committee propagates gradients in reverse order using the same packing-aware primitives. For PolyReLU, N OMAI computes derivatives using powers of the activation input already cached during the forward pass. For convolutional layers, gradients w.r.t. inputs and kernels are evaluated using the same packed Winograd strategy. For FC layers, the input-gradient has the same structure as the forward pass: if C = W B , then ∆B = W T ∆C, which is computed using the same chunked lower-diagonal representation by swapping operands. However, the weight-gradient ∆W = ∆CB T differs since both ∆C and B are in lower-diagonal form, so their en-tries are not aligned for coordinate-wise products. To avoid an extra communication round for repacking, N OMAI keeps ∆C

in lower-diagonal form and uses rotated copies of B, generated during forward-pass degree-reduction and repacking. This in-creases computation but preserves the communication-round structure of the forward protocol. 

## 6.3 Aggregation Phase 

At the end of training, each committee holds packed shares of its local gradient aggregates, and the goal is to combine these 10 into a global aggregate. A transfer of shares across committees is unsafe, since an adversary corrupting parties in multiple committees could accumulate more than t shares of the same polynomial and violate privacy. To avoid this, we exploit that the last operation in training is a multiplication and skip the last degree-reduction step, leaving all shares at degree 2 d.However, such polynomial formed by multiplying two degree-

d sharing polynomials is not distributed as a fresh random packed sharing and does not provide the privacy guarantee against up to 2 t shares. Before transferring the aggregate across committees, we therefore add a fresh random degree-2d zero-sharing that preserves the encoded aggregate while re-randomizing it. A PSS of degree 2 d hides the l secrets against up to 2 t + l − 1 shares, so even if an adversary obtains 

t shares from both the source and receiving committees, it sees only 2 t shares. This enables a simple aggregation protocol: for each committee Ci, party Pi, j sends its degree-2 d share to the corresponding party P1, j in a designated primary committee 

C1, which locally sums all received shares. As a result, C1

obtains a degree-2 d sharing of the global aggregate, which is then jointly reconstructed and decoded to produce the final gradient for the server. 

## 6.4 Extension to Malicious Threat Model 

Under a malicious threat model, privacy follows from the threshold property of PSS , while correctness requires ad-ditional well-studied checks [29–31]. However, N OMAI 

achieves a more efficient design by exploiting an observa-tion specific to FL. Beyond protocol deviations, malicious users can corrupt the aggregate by submitting malformed data. Thus, to ensure data integrity , each gradient must satisfy a validity condition. Maliciously secure aggregation alone is therefore insufficient; explicit per-gradient well-formedness checks are required. NOMAI turns this requirement into an efficiency gain. Since validation is necessary anyway, we perform the expensive gra-dient computation in the more efficient semi-honest model and enforce malicious security only during validation and aggregation. This reduces overhead by running the domi-nant computation in the cheaper semi-honest setting. This slightly relaxes the threat model, as discussed below. Finally, we handle a malicious server distributing inconsistent model parameters with a simple weight-consistency check.

6.4.2 Gradient Validation and Aggregation 

A malicious user may corrupt the model by submitting an invalid gradient, so each committee validates individual gra-dients before aggregation. Following prior work [36, 49], we model validity as a predicate Valid (·) over gradient vectors, such as a norm bound. In the malicious setting, per-user gra-dients are retained through the backward pass. At its end, the committee holds degree-d PSS whose slots jointly encode individual gradient coordinates. It converts each PSS into per-slot degree-t Shamir sharings and groups them by user to obtain a shared gradient vector gu. The committee then securely evaluates Valid (gu), obtaining a validity bit bu. We implement norm-bound validation using secure comparison, such as bit decomposition [35], and DIK-based multiplica-tion [17]. The committee accepts only gradients with bu = 1and computes gagg = ∑u:bu=1 gu. Full validation and consis-tency checks appear in App. B.2. The local aggregates are then combined across committees. Each committee raises its aggregate to degree 2 t by adding a fresh degree-2 t zero-sharing [29, 30] and sends the shares to the primary committee, which verifies consistency with a degree-2 t Shamir sharing before aggregation. Discussion. In N OMAI , a malicious user can exhibit two be-haviors: (i) Input manipulation: supplying malformed data, yielding an invalid gradient. (ii) Protocol deviation: deviating during execution to perturb other users’ gradients. Under full malicious security, both are addressed directly: protocol safe-guards prevent (ii), while validation filters malformed inputs in (i). Under our relaxed approach, (ii) is not eliminated, but its effect is restricted. This is justified since correctness is defined by the validation predicate: a gradient is accepted iff 

Valid (g) = 1. Thus, any adversarial perturbation goes unde-tected only if the resulting gradient remains valid, aligning with the server’s acceptance criterion. The server can further limit such influence in two ways. First, it keeps the parameters of Valid (·) private (e.g., the threshold ρ in |g|2 < ρ), forcing adversaries to perturb blindly. Second, it monitors rejection rates: if the observed rate exceeds the estimated corruption rate η, this signals protocol deviations beyond malformed inputs, and the server aborts.

(i) Scaling with Number of Users N. Fig. 4 shows that N O-

## 9 Conclusion 

We presented N OMAI , the first scalable FL system to achieve data privacy, weight privacy, and integrity in the single-server setting. Our design introduces new cryptographic and ML-aware techniques for efficient secure training. 13 Ethical Considerations 

This paper studies privacy preserving federated learning using MPC to jointly achieve data privacy, model privacy, and in-tegrity in a single server setting. Federated learning involves sensitive user data and proprietary model parameters, so we consider the ethical implications of both our system design and its potential deployment. 

Stakeholders. Stakeholders include end users whose private data is used for training, service providers deploying federated learning systems, organizations relying on trained models, practitioners implementing such systems, and the broader research community. 

Principles. We consider the Menlo Report principles of Beneficence, Respect for Persons, Justice, and Respect for Law and Public Interest. 

Potential harms. A primary concern is misuse. Even if train-ing is privacy preserving, the resulting model may be used in harmful or unethical applications. Second, the system’s guarantees depend on the stated threat model, including the honest majority assumption within committees and the mali-cious with abort setting; deploying the system outside these assumptions could lead to overestimated privacy or integrity guarantees. Third, while our protocol enforces well formed gradients, it does not ensure that the trained model is unbiased, fair, or safe for downstream use. Another concern is dual use. Techniques that enable scal-able privacy preserving training could be adopted in settings where users may not fully understand or consent to how their data contributes to model training, even if the protocol itself preserves confidentiality. 

Mitigations. We mitigate these risks through clear design and transparency. First, all user data remains secret shared and is never revealed to the server or other users. Second, model weights are protected from disclosure to users, preserv-ing provider confidentiality. Third, integrity checks ensure that malformed or adversarial updates are detected within the defined threat model. We explicitly state all assumptions and limitations, includ-ing the threat model and deployment constraints. Our eval-uation uses only standard public datasets and does not in-volve human subjects, private user data, live deployments, or vulnerability disclosure. We do not release sensitive data or operational system details. 

Decision. We believe it is ethical to proceed and publish be-cause this work advances practical mechanisms for protecting both user data and model confidentiality in federated learning. The system reduces reliance on weaker or ad hoc privacy ap-proaches, while making all assumptions explicit. Publication enables scrutiny, informed adoption, and responsible deploy-ment.

## A.2 Discussion 

A large body of prior work [35, 40, 41, 56] optimizes exact non-linear layer computation in secure ML. These techniques are complementary and can be integrated into our framework. However, they typically incur multiple rounds of interaction and substantial correlated randomness, making them less suit-able for our massively distributed setting where communica-tion dominates. Instead, we adopt polynomial approximations for non-linearities, which are more amenable to efficient packed com-putation. To preserve accuracy, we incorporate ML-aware optimizations that stabilize training under polynomial acti-vations (see Sec. 6.2), and empirically observe competitive performance with PolyReLU-style approximations. Our de-sign does not preclude exact non-linear protocols, which can be substituted if desired. Our core contributions, particularly for linear layers and system-level optimizations, are orthogo-nal to this choice.

Let D denote the desired dropout tolerance. For a fixed cor-ruption threshold t and packing factor l, let d = t + l − 1 and 

n = 2d + 1. In the semi-honest setting, tolerating up to D

unavailable members requires at least 2 d + 1 + D commit-tee members. In the malicious-with-abort setting, we instead require 2 d + 1 + 2D, where the additional D members are used to handle malicious cross-committee transfers under different dropout patterns, as described below. In concrete pa-rameter selection, increasing the committee size may change the value of t required to satisfy the target committee-safety bound. We therefore choose t and the committee size jointly, using the corresponding size requirement above while main-taining the desired bound on the probability that a committee contains more than t corrupted members. All input shares, model-weight shares, and user-supplied randomness are dis-tributed to every member of the provisioned committee. Local linear operations and share-wise multiplications require no modification; only interactive subprotocols require additional mechanisms. In truncation and degree-reduction Algs. 8 and 10, the masked value opened in Step 3 is shared using a degree-2d polynomial. Hence, any 2 d + 1 available shares uniquely determine the opened value, and each party can interpolate from any 2 d + 1 shares it receives. Increasing the committee size to 2 d + 1 + D therefore tolerates up to D erasures. Degree reduction and repacking in Algs. 11 and 9 require an additional mechanism because every receiver must apply the degree-reduction map using the same set of 2 d + 1 shares. A public ordering is fixed over all members of each commit-tee. The protocol initially selects the first n parties in this ordering as the sender set. Since all user-to-user communica-tion is relayed by the server, the server can wait for complete message bundles from the current sender set before relaying. After a timeout, each missing sender is replaced, in order, by the next available member on the list. Because changing the sender set changes the interpolation coefficients used by the degree-reduction map, all parties in the updated sender set recompute and resend their messages. A member once identified as unavailable remains excluded from subsequent sender sets. Since at most D parties are unavailable, at most 

D sender replacements are required. Cross-committee operations, such as weight consistency and cross-committee gradient aggregation, require additional care because corresponding positions in different committees may experience different dropout patterns. Thus, the number of aligned live positions may fall below the required threshold even when each committee individually has enough active parties. In the semi-honest setting, provisioning n + D mem-bers suffices. For each source committee Ck and each active party P1, j in the primary committee C1, party Pk, j directly sends fk(α j) to P1, j. If Pk, j is unavailable, the current set of live senders in Ck privately restores only the missing evalua-tion fk(α j) using fresh user-provided correlated randomness. Thus, every active party in the primary committee obtains its share, allowing cross-committee values to be aggregated locally at corresponding evaluation points. Since public or-dering and dropout budget are shared across the committee execution, parties already identified as unavailable remain excluded, and at most D such restorations are required per source committee. In the malicious-with-abort setting, we instead provision 

n + 2D members and use the same direct-transfer and share-restoration procedure. In gradient aggregation, at most t di-rectly transferred source positions, D restored positions, and 

t primary-committee positions can be adversarially affected, for a total of 2 t + D positions. The primary committee has at least n + D active parties. Therefore, the corresponding degree-2 t Reed–Solomon code has minimum distance at least 

(n + D) − 2t = 2l − 1 + D. Under the requirement t < l, we have 2 t + D < 2l − 1 + D, so an incorrect contribution cannot form a distinct valid degree-2 t codeword. A source gradient contribution is therefore either rejected or accepted as the cor-rect aggregate, except with probability bounded by the sound-ness error of the consistency check. For weight consistency, the primary committee first verifies that the transferred eval-uations form a valid degree-(d + t) sharing and then applies the existing weight equality check. Thus, even if a malicious transfer or restoration produces a different valid sharing, the sharing is harmless if it encodes the same packed weights and is rejected otherwise, except with probability bounded by the soundness error of these checks. Corrupted committee members may withhold messages or send malformed ones, while a corrupted server may selec-tively delay or suppress messages or relay inconsistent shares to different receivers. These deviations may cause a party to be treated as unavailable, produce inconsistent sharings, per-turb subsequent computation, or force an abort, all of which are permitted by our model. Our dropout mechanism does not correct malformed shares. Any resulting share inconsis-tency is detected by subsequent consistency checks, while a deviation that still produces a well-formed gradient remains subject to the validation predicate described in Sec. 6.4.2.

Random Projection. The inclusion of the high-dimensional 4096-input layer significantly increases model size; in the malicious setting, this directly impacts both runtime and com-munication, as the gradient validation step is costly. To miti-gate this overhead, we apply random projection [3] to reduce the dimensionality of updates by projecting to d′ = 10 ,000 prior to aggregation. F.2.2 Parameter Design Space 

A configuration of N OMAI is determined by the number of committees c, packing factor l, corruption threshold t, and the resulting committee size 

n = 2(t + l − 1) + 1.

Given N users and corruption rate β, we choose the smallest 

t such that the probability that any committee contains more than t corrupted members is at most 10 −12 . Specifically, for every candidate (c, l), we require 

c · Pr [X > t] ≤ 10 −12 , X ∼ Hypergeom (N, ⌊βN⌋, n) ,

with β = 0.01, together with the feasibility condition cn ≤ N.For malicious security, we additionally require t < l. Thus, once (c, l) is fixed, t and n are determined by the security requirement rather than tuned independently. The two main tuning parameters, c and l, affect different parts of the protocol. Increasing c reduces the number of users assigned to each committee,

which generally reduces user-dependent training and valida-tion work per committee member. At the same time, more committees increase cross-committee aggregation overhead and, in the malicious setting, the cost of checking that all committees received consistent model weights. Moreover, changing c may change the minimum safe threshold t and therefore the committee size n. Consequently, increasing the number of committees is beneficial only while the reduction in per-committee workload outweighs these additional costs. The packing factor l creates a similar tradeoff. A larger l

places more values in each packed sharing and can therefore reduce the number of packed objects that must be processed. For example, an FC layer with input dimension a uses ⌈a/l⌉

packed chunks, while a convolution with K Winograd tiles uses ⌈K/l⌉ tile groups. However, increasing l also increases the sharing degree d = t + l − 1 and hence typically increases the committee size n = 2d + 1. Interactive operations such as degree reduction, truncation, and repacking therefore be-come more expensive. The resulting tradeoff depends on the exact architecture and packing layout, so neither a larger nor a smaller l is universally optimal. We therefore search over candidate (c, l) pairs directly. For each pair, we first determine the minimum safe t, discard infeasible configurations, and then evaluate the resulting per-machine computation and sent communication. In N OMAI , the dom-inant cost is the semi-honest secure training computation, whose per-committee-member workload is determined pri-marily by the model architecture and committee parameters, being independent of the total user population N. Increasing 

N affects only the additional malicious-security mechanisms, mainly through the number of committees that must be coordi-nated and checked. Therefore, only a relatively small portion of the per-machine cost grows with the user population. In contrast, F LAMINGO requires each decryptor to process user-dependent recovery material, giving its per-decryptor work-load an approximately linear dependence on N. W ILLOW 

distributes verification across multiple verifiers, reducing the workload of an individual verifier, but its per-machine ver-ification cost still grows with N under the scalable verifier configuration. Thus, N OMAI achieves favorable per-machine scalability even though it protects much more of the training process than either secure-aggregation baseline. For communication, we compare the upload of an ordinary user that do not serve as protocol helpers. A N OMAI user distributes packed shares of its private input across the com-mittee so that both training data and model computation can remain protected inside MPC.
