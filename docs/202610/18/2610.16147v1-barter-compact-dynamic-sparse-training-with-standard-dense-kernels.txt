ABSTRACT
Dynamic sparse training (DST) aims to reduce training costs while maintaining
accuracy. Existing DST methods mask out parameters but keep matrix dimensions
unchanged. Training speedups therefore depend on specialized support, such as
sparse kernels. We introduce BARTER, a structured DST framework that reduces
training cost using standard dense kernels by keeping training tensors physically
compact while dynamically reallocating capacity across layers.
Unlike exist-
ing works that require computing gradients for all parameters, BARTER instead
uses statistics collected only from active units during ordinary backpropagation to
prune and clone attention heads and feed-forward channels under separate fixed
global budgets. At each topology update, it resizes the affected parameter tensors
and remaps their optimizer states, so subsequent training steps operate directly
on the compact model. Training and fine-tuning experiments with Transformer-
based vision models on two image classification benchmarks at densities from 0.1
to 0.7 show competitive Top-1 accuracy relative to full-tensor DST baselines. On
an NVIDIA L40, BARTER achieves speedups of up to 6.29× in measured train-
ing segments and reduces peak allocated GPU memory by up to 81.3% relative to
these implementations. An iPhone 13 Pro Max training benchmark additionally
shows a 2.78× speedup over the full-tensor DST baseline.

Training neural networks requires substantial
computation and memory, while deployment
imposes limits on model size and inference
cost. Pruning reduces deployment costs by re-
moving redundant weights (Han et al., 2015)
or structural units (Li et al., 2016), but train-
ing a dense model before pruning still incurs
the full training cost. Dynamic sparse training
(DST) (Mocanu et al., 2018; Dettmers & Zettle-
moyer, 2019; Evci et al., 2020) aims to reduce
this training cost while maintaining accuracy. It
trains a sparse network from initialization un-
der a limited active-parameter budget. The ini-
tial topology may not make the best use of this
budget, so DST periodically prunes and grows
connections to revise its capacity allocation as
it learns.
However, fewer active parameters do not nec-
essarily mean cheaper training. Existing DST
methods mask out parameters but keep matrix
dimensions unchanged (Evci et al., 2020; Chen
et al., 2021; Lasby et al., 2024). Standard dense kernels still process the full-size tensors. Sparse
kernels can skip computations on inactive weights to accelerate training, but require implementa-

tions tailored to the sparsity format and execution backend (Nikdan et al., 2023; Hu et al., 2024;
Mozaffari et al., 2025). This limits which platforms can benefit from these speedups.
To achieve reductions in computation with standard dense kernels, a logical approach is to remove
inactive structural units and train on a smaller tensor consisting only of active units. However, it is
not possible to do so using existing approaches because they require using the gradients of inactive
candidates to guide growth (Evci et al., 2020; Chen et al., 2021; Lasby et al., 2024); once these units
are physically removed, ordinary backpropagation no longer provides those gradients.
Our Approach. We propose BARTER, a structured DST framework that prunes and grows struc-
tural units directly on compact tensors using standard dense kernels (Figure 1). Under fixed global
Budgets, BARTER uses only Active-unit statistics to Reallocate capacity during Training. It main-
tains compact dense Execution by Resizing the affected tensors. In our Transformer implementation,
attention heads and feed-forward network (FFN) channels have separate budgets, and training uses
compact tensors from the first optimization step. At each update, BARTER uses these statistics to
prune a unit from a donor layer and clone an active unit within the receiving layer. The clone starts
from a feature the model has already learned, and the parent’s outgoing weights are split between
the two units. We resize the affected parameters and remap their optimizer states so training can
continue on the compact model. The final model can be deployed without further pruning.
Our contributions are summarized as follows:
• We introduce BARTER, a structured DST framework that reallocates capacity under fixed
global budgets while keeping training tensors physically compact. Unlike existing DST
implementations that rely on specialized sparse kernels for acceleration, BARTER achieves
training speedups using standard dense kernels and produces a compact model for deploy-
ment.
• We develop a reallocation mechanism that selects units for pruning and cloning. Unlike
prior growth rules that rely on gradients of inactive candidates, it uses only active-unit
statistics. Tensor resizing and optimizer-state remapping allow training to continue directly
on the compact model after each structural update.
• We conduct training and fine-tuning experiments with two Transformer architectures on
two image classification benchmarks, comparing against five state-of-the-art DST methods
and a dense reference. Under standard dense-kernel execution, BARTER maintains com-
petitive classification performance while achieving speedups of up to 6.29× in measured
GPU training segments and reducing peak allocated GPU memory by up to 81.3% relative
to these DST methods. A smartphone training benchmark shows a 2.78× speedup over
RigL.

RELATED WORK
Unstructured dynamic sparse training.
Unstructured DST learns sparse connectivity along-
side network weights under limited connection budgets (Bellec et al., 2017; Mocanu et al.,
2018). SET (Mocanu et al., 2018) combines magnitude-based pruning with random growth, while
RigL (Evci et al., 2020) selects new connections using gradient magnitudes. CHTs (Zhang et al.,
2026) uses topology-based link prediction to guide regrowth. Beyond the selection of individual con-
nections, dynamic sparse reparameterization redistributes a fixed nonzero parameter budget across
layers (Mostafa & Wang, 2019), and in-time over-parameterization relates training performance to
the exploration of sparse configurations over time (Liu et al., 2021). These methods adapt connec-
tivity at the level of individual weights. BARTER changes the granularity of reallocation to complete
attention heads and FFN channels, physically adjusting the corresponding tensor dimensions as ca-
pacity moves across layers.
Structured dynamic sparse training.
Structured DST introduces constraints on the units or con-
nectivity patterns being updated. S2ViTE (Chen et al., 2021) prunes and grows attention heads and
FFN channels; Chase (Yin et al., 2023) combines channel pruning with weight-level redistribution;
and SRigL (Lasby et al., 2024) maintains constant fan-in connectivity with neuron ablation. Their
growth rules use gradients of inactive candidate weights or units (Chen et al., 2021; Yin et al., 2023;
Lasby et al., 2024), which ordinary backpropagation through a physically compact active model

Sparse execution for training.
MEST (Yuan et al., 2021) combines memory-economic sparse
training with compiler-level optimizations for mobile execution. DSB (Jiang et al., 2022) organizes
changing connectivity into shuffled blocks for efficient sparse computation, while DynaDiag (Tyagi
et al., 2025) maintains diagonal sparsity and accelerates training with custom CUDA kernels. For
large output spaces, HASTE (Ullah et al., 2026) pairs group-shared fixed fan-in patterns with custom
CUDA kernels. Transformer pre-training has also benefited from optimized forward and backward
kernels for 2:4 sparsity (Hu et al., 2024), while CHTs24 (Lyu et al., 2026) studies dynamic con-
nectivity updates under transposable 2:4 constraints. These approaches tailor execution to particular
sparsity patterns and backends. BARTER follows a different route: it reduces layer dimensions
during training and executes the resulting compact tensors with standard dense kernels.

METHODOLOGY
BARTER adapts the allocation of attention heads and feed-forward channels across layers while
training a physically compact model. Figure 2 provides an overview of the framework. We first
define the compact model and its capacity budgets (Section 3.1), then describe how statistics from
active units guide cross-layer reallocation (Section 3.2). We next present the prune-and-clone oper-
ation (Section 3.3) and explain how the affected parameters and optimizer states are resized so that
training can continue with standard dense kernels (Section 3.4).

3.2
ACTIVE-ONLY CAPACITY REALLOCATION
Active-unit scoring.
We use activations and their gradients from ordinary training to decide where
to remove and add capacity. For attention heads, we collect the head outputs before the output
projection; for FFN channels, we collect the hidden activations after GELU.
For an active unit i in layer ℓ, let aℓ,i,b,j denote its activation for sample b at output coordinate j.
Here, b indexes samples in the current minibatch. For an FFN channel, j runs over token posi-
tions; for an attention head, it runs over token positions and features within the head. Let L be the
minibatch loss and gℓ,i,b,j = ∂L/∂aℓ,i,b,j the gradient with respect to that activation.

activation-gradient products over all output coordinates within each sample, taking the absolute

Unit removal and cloning.
Using the selections from Section 3.2, BARTER removes the donor
unit (ℓd, id) and creates a unit of the same type in receiving layer r by cloning its selected parent
ip. We remove an attention head’s query, key, and value parameter blocks, including their biases

3.4
PHYSICAL RESIZING AND CONTINUED TRAINING
Physical resizing.
At each topology update, we rebuild the affected tensors from the retained and
newly created parameter slices defined in Section 3.3. We use matching unit indices across the
associated tensors. For an FFN with cℓactive channels and embedding dimension d, the input and
output weight matrices have sizes cℓ× d and d × cℓ, respectively. Attention projections are resized
by complete head blocks. Both modules retain their input and output dimensions as their internal
widths change. Removed units leave no zero-filled slots, and subsequent forward and backward
passes operate directly on the resized tensors with standard dense kernels.
Optimizer-state remapping.
We resize the optimizer states using the same unit indices as the pa-
rameters. For Adam, we retain the first- and second-moment estimates of unaffected parameter slices
and remove those belonging to the pruned unit. Both estimates are set to zero for the parameters of
the cloned parent and its new copy, while the Adam step counters remain unchanged.
Training schedule.
Pruning decisions can benefit from training beyond initialization (Frankle
et al., 2020). We therefore train the initial compact model and accumulate active-unit scores be-
fore the first capacity transfer. Let T denote the total number of training steps, and let tstart and tend
define the reallocation window. We set the total numbers of head and FFN-channel transfer attempts,
KH and KC, in proportion to their initial active counts H and C, respectively. For each unit type,
we spread these attempts approximately uniformly across the window. Training between updates
lets the model adapt to its current structure and refresh the importance estimates used for the next
decision (Chen et al., 2021). At each scheduled update, we attempt one transfer of the corresponding
unit type after the optimizer step, keeping the change small to limit disruption to training (Yin et al.,
2023).
We stop collecting scores for each unit type after its last scheduled update. After tend, we fix the
layer widths and continue optimizing the weights until step T, as sparse connectivity can stabilize
earlier than the weights (Mostafa & Wang, 2019). Appendix C.5 examines how increasing the
number of capacity transfers affects classification performance and incremental update cost.

RESULTS AND DISCUSSION
We evaluate BARTER against dense and sparse baselines on two image classification benchmarks,
comparing classification performance, training cost, and final model size.
Datasets and models.
Our from-scratch experiments use a seven-layer CCT (Hassani et al., 2021)
on CIFAR-100 (Krizhevsky & Hinton, 2009) and a nine-layer ViT (Dosovitskiy, 2020) on Tiny-
ImageNet (Le et al., 2015). CCT uses 32 × 32 inputs, while ViT uses 64 × 64 inputs and the
small-model configuration of Gani et al. (2022). We also fine-tune the Tiny-ImageNet-trained ViT
on CIFAR-100 with images resized to 64 × 64. We reserve 10% of each official training set for
validation. Final evaluation uses the CIFAR-100 test set and the labeled Tiny-ImageNet validation
set.
Baselines.
We compare BARTER with Dense, the unstructured DST methods SET (Mocanu et al.,
2018), SNFS (Dettmers & Zettlemoyer, 2019), and RigL (Evci et al., 2020), and the structured
DST methods SRigL (Lasby et al., 2024) and S2ViTE (Chen et al., 2021).We use the official im-
plementations of the DST baselines, adapted to our model configurations. Sparse models use target
densities ρ ∈{0.1, 0.3, 0.5, 0.7}. Initial capacity allocation and baseline settings are described in
Appendices B.1 and B.3.

Training settings.
In the fixed-step comparisons, methods share the data split, augmentation, and
optimization settings within each task and seed. GPU training uses FP32 and Adam (Kingma & Ba,
2014) with decoupled weight decay (Loshchilov & Hutter, 2017). CCT is trained for 200 epochs.
ViT training and standard fine-tuning each run for 100 epochs, with three shuffled passes through the
training set per epoch. For BARTER, we set the score EMA decay to 0.99 and reallocate capacity
between 10% and 40% of the training steps. Detailed training settings and checkpoint-selection
rules are provided in Appendix B.2.
Evaluation.
We select checkpoints by validation Top-1 accuracy and report Top-1 accuracy and
macro-F1 as mean ± sample standard deviation across three random seeds. For training efficiency,
we report measured training time for epoch-length segments, estimated per-step time, and peak allo-
cated GPU memory. We also report estimated training FLOPs, counting each multiply-accumulate
operation as two FLOPs, and the physical parameter counts of the exported models. Measurement
and counting protocols are provided in Appendix D.
4.1
CLASSIFICATION PERFORMANCE
Table 1 shows that BARTER ranks first or second among sparse methods in both Top-1 accuracy
and macro-F1 at densities of 0.3, 0.5, and 0.7 on CIFAR-100 and Tiny-ImageNet. At ρ = 0.5, it
achieves the highest mean Top-1 accuracy and macro-F1 among sparse methods on both tasks,
with Top-1 accuracies of 72.85% and 52.77%, respectively.
Even at ρ = 0.1, BARTER physically removes approximately 90% of the original attention
heads and FFN channels, while the baselines in our experiments retain full-size training tensors.
Despite this reduction, its Top-1 accuracy is only 0.88 and 1.57 percentage points below RigL, the
best-performing sparse baseline at this density, on CIFAR-100 and Tiny-ImageNet, respectively.

CONCLUSION
We presented BARTER, a structured DST framework that reallocates capacity under fixed global
budgets using active-unit statistics while maintaining compact dense execution. Experiments show
competitive accuracy, lower peak allocated GPU memory, and speedups in GPU and smartphone
training benchmarks. Matched-compute fine-tuning further improves accuracy at low densities,
surpassing the strongest sparse baseline. The resulting models require no additional pruning for
deployment.
Broader Impact and Future Work. BARTER supports resource-efficient training without special-
ized sparse kernels. Future work will explore more effective capacity allocation and extend compact
training to environments with changing resource constraints.

A
ALGORITHM AND IMPLEMENTATION DETAILS
A.1
COMPLETE TRAINING ALGORITHM
Algorithm 1 summarizes training. Density ρ applies to the attention and FFN weight matrices; em-
beddings, normalization layers, and the classifier remain outside the pruning pool. Table 3 lists
the integer head and channel budgets. We distribute each budget as evenly as possible across lay-
ers, assign remainders randomly, and randomly select the retained units within each layer. Their
parameters form the initial compact model.
Selection and scheduling.
We use the selection rules in Section 3.2, with EMA decay β = 0.99.
A receiving layer must contain an active unit and remain below its full-density width. Donors come
from other layers, with at least one FFN channel retained per layer. Reallocation takes place between
0.1T and 0.4T, after optimizer updates. FFN proposals are evenly spaced over this window; head
proposals use interval midpoints. Clone parents and their copies are excluded from donor selection
for two typical FFN proposal intervals or one head interval. Score collection stops after each unit
type’s final scheduled proposal.
Reallocation budget.
For the main experiments, we use a limited number of whole-unit transfers
to evaluate whether capacity reallocation can improve classification performance in compact models.
We scale the scheduled head and FFN-channel transfer counts with their active-unit budgets using
reference ratios of 2/34 and 60/1067, respectively, corresponding to the CCT configuration at ρ =
0.3. Counts are rounded to the nearest integer, with at least one transfer scheduled for each feasible
unit type. All scheduled transfers were completed in these runs. Table 3 reports the executed transfer
counts alongside the global budgets and initial per-layer counts. ViT uses the same reference settings
for training from scratch and fine-tuning.
Whole-unit transfers can change a substantial fraction of an individual layer’s capacity. At ρ = 0.1,
CCT and ViT initially contain only one or two heads per layer, so one head represents 50% or
100% of a layer’s initial head count. FFN channels allow finer adjustments, with 20 to 142 channel
transfers per run in the main-experiment settings. Appendix C.5 examines how increasing these
transfer counts affects classification performance and estimated incremental topology-update cost.

B.2
TRAINING SETTINGS
Optimization.
Table 5 summarizes the training settings. All methods use label-smoothed cross-
entropy and Adam with explicitly implemented decoupled weight decay, applied after the Adam
update for CCT and before it for ViT training and fine-tuning. Decay includes biases and normal-
ization parameters, and is restricted to active entries in masked implementations. Learning rates use
linear warmup followed by cosine decay (Loshchilov & Hutter, 2016). All tasks use FP32 without
automatic mixed precision; ViT training and fine-tuning also disable TF32.
One CCT epoch traverses the training set once. ViT training and fine-tuning use three shuffled passes
per epoch, dropping the final incomplete minibatch; their 100-epoch schedules therefore correspond
to approximately 300 data passes. Evaluation uses batch size 256. Embedding, FFN, and projection
dropout are zero, while stochastic-depth rates increase linearly across layers.
Data augmentation.
All tasks use random cropping with four-pixel padding and horizontal flip-
ping. CCT additionally uses RandAugment (Cubuk et al., 2020) with two operations and magnitude
9, together with Mixup (Zhang et al., 2017). ViT training and fine-tuning use ImageNet AutoAug-
ment (Cubuk et al., 2019) and random erasing with probability 0.25. When batch mixing is enabled,
ViT chooses Mixup or CutMix (Yun et al., 2019) with equal probability. Fine-tuning retains the
source model’s Tiny-ImageNet normalization.
Fine-tuning protocol.
For each seed, all methods start from the same validation-selected dense
Tiny-ImageNet checkpoint, with a newly initialized classifier and optimizer. Sparse methods inherit
pretrained weights at their selected positions. After the initial 100 epochs, BARTER at ρ = 0.1 and
0.3 continues from the endpoint checkpoint with its topology fixed and score collection disabled.
Adam moments and step counters are retained, while a separate warmup/cosine schedule restarts
over the remaining compute budget using the same learning-rate settings. Training stops at the
baselines’ cumulative forward-plus-backward MAC budget, allowing a final partial epoch. The
counting protocol is given in Appendix D.2.

D
EFFICIENCY MEASUREMENT PROTOCOL
D.1
GPU TIMING AND MEMORY
We benchmark the validation-selected checkpoints using their stored tensor shapes. For each method
and density, we replay one epoch of its training schedule: 351 steps with batch size 128 for CCT,
and 1,054 steps with batch size 256 for ViT. These segments process 44,928 and 269,824 images,
respectively; a ViT epoch follows the three-pass convention used in training. The replays use the
schedules at epoch 50 for CCT and epoch 25 for ViT.
After warmup, we synchronize the GPU and time the full training segment, synchronizing again
before stopping the timer. The interval includes data loading, device transfer, augmentation, forward
and backward passes, optimizer steps, score collection, and scheduled topology updates. We reset
the peak-memory counter after warmup and record the maximum GPU memory allocated during the
same interval.
We estimate average step time separately.
Ordinary training steps are grouped by their score-
collection settings, and collection or topology-update windows are timed as separate segments. We
weight these timings by their frequency in the training schedule; an update window uses the nearest
measured window of the same type. Measurements are aggregated within each seed before report-
ing the mean and sample standard deviation across seeds. Speedups are ratios of the reported mean
times.
Incremental topology-update cost.
For the study in Appendix C.5, we benchmark topology-
update windows and ordinary training steps using GPU-resident batches. We subtract the cost of an
equal number of ordinary steps with matching score-collection settings from each update window
and weight the differences over the training schedule. The ordinary-step reference includes the
corresponding score collection and EMA updates. We report the resulting increment averaged over
all 105,400 optimizer steps in milliseconds per step and accumulated over the 100-epoch schedule
in seconds.

TRAINING FLOPS AND EXPORTED PARAMETER COUNTS
Both compute measures count only convolution and matrix-multiplication MACs, with two FLOPs
per MAC.
Training from scratch.
Let Mfwd denote forward MACs per image, calculated from the tensor
shapes executed during training. We approximate the backward cost as twice the forward cost and
report estimated training FLOPs per image as
bFtrain = 6Mfwd.

Fine-tuning.
We derive forward and backward MAC counts separately from operator shapes ob-
served during training, reusing counts for identical shapes and execution settings. We accumulate
these counts over all completed training steps to obtain Mtrain and report cumulative training FLOPs
as Ftotal = 2Mtrain. The matched-compute experiments use this cumulative budget.
Exported parameter counts.
We report all parameters physically stored in the exported models,
in millions. Parameter counts use validation-selected checkpoints; Static’s counts in Table 15 use its
final checkpoint. S2ViTE removes inactive units during export, whereas Static and BARTER already
store compact tensors. Dense, SET, SNFS, RigL, and SRigL retain full-size tensors in the evaluated
exports.
D.3
ON-DEVICE MEASUREMENT
We run a native Swift implementation of CCT on an iPhone 13 Pro Max with iOS 18.7.8, using
MPSGraph on the Metal GPU in a Release build. Training uses FP32 and an effective batch size of
128, formed by accumulating gradients over 32 microbatches of four images each. For each method,
