## 摘要
新兴的数据流加速器为机器学习工作负载提供了卓越的能效和吞吐量，但在性能分析方面对开发者而言仍基本不透明。与可通过插桩框架实现细粒度内省的 CPU 和 GPU 不同，数据流硬件几乎不暴露任何信息。这种透明度的缺失限制了编译器工程师、系统设计人员和应用开发者对加速器行为进行分析、调优或调试的能力。本文提出 DFIT（DataFlow Accelerator Instrumentation Tool，数据流加速器插桩工具），这是一个专为数据流架构设计的插桩框架。DFIT 利用语义化程序表示，直接在图中间表示（IR）和后端降级阶段对操作、区域及编译器变换进行插桩。DFIT 捕获能够反映计算真实数据流的高层次、具有语义意义的数据，并可将这些数据导出用于可视化和分析。我们的方法展示了如何将插桩泛化到传统硬件之外，以支持异构架构，并且无需修改工具逻辑即可实现可移植性。通过揭开数据流执行的黑箱，DFIT 为面向 AI 加速器的新型性能分析工具奠定了基础。它为异构系统中可复现、具备架构感知能力的内省提供了切实可行的路径，弥合了编译器设计、运行时调度与硬件实现之间长期存在的可见性鸿沟。在 Cerebras、SambaNova 和 TPU 上的评估表明，在不同插桩模式下，其实际开销为 3.53%–13.62%，并具有稳健的跨平台可移植性。

## Abstract
Emerging dataflow accelerators offer exceptional energy efficiency and throughput for machine learning workloads, yet remain largely opaque to developers for performance analysis. Unlike CPUs and GPUs, where instrumentation frameworks enable fine-grained introspection, dataflow hardware exposes little information. This lack of transparency limits the ability of compiler engineers, system designers, and application developers to analyze, tune, or debug accelerator behavior.   In this paper, we introduce DFIT (DataFlow Accelerator Instrumentation Tool), an instrumentation framework designed specifically for dataflow architectures. DFIT directly instruments operations, regions, and compiler transformations at the graph IR and backend-lowering stages using semantic program representation. DFIT captures high-level, semantically meaningful data that reflect the true dataflow of computation. These data can be exported for visualization and analysis. Our approach demonstrates how instrumentation can be generalized beyond traditional hardware to support heterogeneous architectures, providing portability without modifying tool logic.   By opening the black box of dataflow execution, DFIT establishes a foundation for new classes of performance analysis tools for AI accelerators. It provides a practical path toward reproducible, architecture-aware introspection across heterogeneous systems, bridging the long-standing visibility gap between compiler design, runtime scheduling, and hardware realization. Evaluation across Cerebras, SambaNova, and TPU shows practical overhead of 3.53%-13.62% across instrumentation modes with robust cross-platform portability.
