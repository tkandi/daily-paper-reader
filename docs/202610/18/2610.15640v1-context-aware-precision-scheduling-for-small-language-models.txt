# Context-Aware Precision Scheduling for Small Language Models 

Mukund Athmaram 1,2∗ Manoj Rao 1 Liang Ma 11 Advanced Micro Devices Inc. (AMD) 2 Cornell University 

## Abstract 

Small language models (SLMs) used as on-device agents must balance accuracy and latency as their context grows. Mixed precision helps manage this tradeoff by assigning different precisions to weight tensors according to their size and sensitivity. However, these choices depend on the operating conditions, so a configuration selected for a short context may no longer provide the best tradeoff at a longer one. We calibrate a timing model from measurements at different precisions and context lengths, and combine it with tensor sensitivities to choose configurations under a latency or accuracy budget. We argue that fewer bits do not always mean faster execution, so our predictor estimates latency from calibrated execution costs rather than weight bytes alone. Under a latency budget, reading the larger key–value (KV) cache leaves less time for weight operations, leading the allocator to select lower precisions. This gives a schedule of tensor changes that can be prepared before execution. Our runtime follows the schedule while retaining the session’s KV cache. We evaluate executed schedules on a laptop GPU, including a longer-context schedule with three weight formats and a tool-use benchmark measuring full response time and correctness. Under an accuracy budget, measured error from a quantized KV cache determines the budget left for weights. The allocator can raise or lower weight precision as this estimate changes. These experiments show where context-aware precision helps and where accuracy recovery remains limited. 

## 1 Introduction 

Small language models can run on-device as tool-using agents [Belcak et al., 2025], where memory and bandwidth are limited. Each turn adds instructions, tool outputs, and messages, changing the work required for later responses. A fixed precision configuration must serve both short and long contexts. We ask how to choose that configuration as the session grows. Mixed-precision schemes assign different bit-widths to weight tensors because tensors differ in their sensitivity to quantization and their size. We combine an estimate of each tensor’s timing effect with measurements of its accuracy impact to choose a configuration under a budget. We measure accuracy impact offline through a Kullback–Leibler (KL) divergence test that quantizes one tensor at a time. For speed impact, a simple approach is to use bytes as a proxy. This is a natural assumption: for example, storing weights in four bits rather than eight roughly halves their storage, so it makes sense to assume that this also makes execution faster. However, storage alone does not account for the compute and conversion work of each format’s kernels. Section 2 shows a measured case where Q8 is faster than Q4 and evaluates latency prediction on new mixed-precision configurations. We then use these timing costs to choose precisions as context grows. Context growth introduces two different scheduling questions. Under a latency budget, reading a larger KV cache leaves less time for weight operations. We can predict this change, allocate precision

## 2 Predicting latency of mixed-precision configurations 

Lower precision reduces weight traffic, but computation and conversion also take time. Under the roofline view [Williams et al., 2009], matrix multiplication can be limited by compute or weight loading. Prefill reuses weights across several token rows, while single-token decode offers less reuse. A lower-bit format can therefore be slower if its compute or conversion costs outweigh the memory saving. ## 7 Related work and discussion 

Mixed-precision allocation. Sensitivity and hardware costs guide precision choices in HAWQ/HAQ [Dong et al., 2019, Wang et al., 2019], dMX/MxMoE [Franco et al., 2026, Duanmu et al., 2025], and LLM-PQ [Zhao et al., 2024]. Kong et al. [2026] use forward-only KL sensitivity in hybrid state-space/Transformer models. 

Precision scheduling. PMPD [Chen et al., 2025] reduces average bit-width under a quality constraint with static and prompt-adaptive decoding schedules. MorphServe [Su et al., 2026] swaps quantized layers as serving load changes, preserving attention state. QAQ [Li et al., 2025] learns to choose precision for each query and loads the required weights on demand. We precompute which tensors to change and when under a context-dependent time budget. 

KV compression. KIVI [Liu et al., 2024] and KVQuant [Hooper et al., 2025] compress the cache itself. We use measured cache error to set the weight-error budget. Raising weight precision can improve predictions but leaves stored cache entries unchanged (Section 5). 

Scope and future work. We test one laptop GPU, and using a different device or software stack requires new timing calibration. Agent turns start from the same conversation context; full sessions would also reveal how earlier actions affect later requests. Loading tensors before each switch and releasing unused copies could reduce memory use, provided transfers fit the latency budget. 

## 8 Conclusion 

Our calibrated predictor estimates the latency of mixed-precision configurations and captures execu-tion costs that weight bytes alone can miss. It provides a way to compare precision choices before running each configuration. Combining context-dependent timing with tensor sensitivities gives a precision schedule that can be prepared in advance and executed while retaining the KV cache. Our experiments show improved latency–fidelity tradeoffs and faster tool-use responses at matching correctness, alongside the limits of recovering cache error through weight precision.
