## 摘要
NVIDIA Grace--Blackwell 系统在编程层面使 CPU--GPU 内存日益统一，但统一的地址可寻址性并不意味着内存系统是均一的。GB200 上的 CUDA 托管分配可由 GPU 本地 HBM 提供服务，也可经由主机/系统内存访问，还可按需迁移、预取、在 GPU 访问后复用，或在容量压力下被驱逐并重新加载。问题在于，这些状态共用同一编程接口，却会调用不同的硬件路径和运行时机制，因此以单一的“统一内存带宽”数值加以描述具有误导性。本文对 NVIDIA GB200 上的 CUDA 统一内存开展了一项放置控制微基准测试研究，并以 GH200 作为 Grace--Hopper 基线、以 GB10/DGX Spark 作为验证平台。我们的方法区分了本地 HBM 访问、主机/系统内存访问、显式数据移动、托管内存首次触及、预取、复用、对访问模式的敏感性、超额订阅以及 CPU--GPU 交接；随后利用经测量校准的模型，概括计算、访问、迁移、驱逐、同步和交接的成本。在 GB200 上，1~GB 的 STREAM 风格三元组操作从本地 HBM 可达到 3963~GB/s，而经由主机映射的 CPU/系统内存时为 304~GB/s；对于 256~MB 的流式内核，冷启动的、由 CPU 初始化的托管内存可达到 14.1~GB/s，而托管内存预取和复用分别可达到 4606~GB/s 和 4504~GB/s。在容量边界以下，经预取和复用的托管内存带宽均保持在 4.6~TB/s 以上；但在达到 CUDA 可见内存容量的 125\% 时，二者分别降至 968~GB/s 和 1214~GB/s。这表明，必须从放置、访问历史、局部性、复用和容量压力等维度来理解 Grace--Blackwell 统一内存。

## Abstract
NVIDIA Grace--Blackwell systems make CPU--GPU memory increasingly unified at the programming level, but unified addressability does not make the memory system uniform. A CUDA managed allocation on GB200 may be served from GPU-local HBM, accessed through host/system memory, demand-migrated, prefetched, reused after GPU access, or evicted and reloaded under capacity pressure. The problem is that these states share a programming interface while exercising different hardware paths and runtime mechanisms, making a single ``Unified Memory bandwidth'' number misleading.   This paper presents a placement-controlled microbenchmark study of CUDA Unified Memory on NVIDIA GB200, using GH200 as a Grace--Hopper baseline and GB10/DGX Spark as a validation platform. Our methodology separates local HBM access, host/system-memory access, explicit movement, managed first touch, prefetch, reuse, access-pattern sensitivity, oversubscription, and CPU--GPU handoff, then summarizes the observations with a measurement-calibrated model of compute, access, migration, eviction, synchronization, and handoff costs. On GB200, a 1~GB STREAM-style triad reaches 3963~GB/s from local HBM but 304~GB/s through host-mapped CPU/system memory; for a 256~MB streaming kernel, cold CPU-initialized managed memory reaches 14.1~GB/s, while managed prefetch and reuse reach 4606~GB/s and 4504~GB/s. Below the capacity boundary, prefetched and reused managed memory remain above 4.6~TB/s, but at 125\% of CUDA-visible memory they fall to 968~GB/s and 1214~GB/s, showing that Grace--Blackwell unified memory must be understood through placement, access history, locality, reuse, and capacity pressure.
