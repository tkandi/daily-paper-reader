# ML Engineering Agents – A Data Management Perspective 

Arnab Phani, Elias Strauss, Tim Schuster, and Sebastian Schelter BIFOLD & TU Berlin, Germany 

{arnab.phani, elias.strauss, tim.schuster}@tu-berlin.de ,

schelter@tu-berlin.de 

Abstract 

Machine learning engineering (MLE) agents are emerging as a new paradigm for automating end-to-end ML pipeline development. Using large language models for code generation and predictive performance as a machine-gradable feedback signal, these agents iteratively synthesize, execute, and refine pipeline code. Yet current systems are largely evaluated on pre-built, single-table benchmarks that abstract away key data management challenges. This tutorial introduces the foundations of MLE agents and highlights research opportunities for the database community. We cover how agents combine program synthesis with iterative and evolutionary optimization, and discuss open challenges in efficient pipeline execution, data discovery and augmentation over heterogeneous sources, reliability and debugging, as well as fairness and compliance. We connect these challenges to existing data management techniques and conclude with a hands-on session using contemporary MLE agents. 

Keywords: machine learning pipelines, LLM-based program optimization, machine learning engineering agents, code synthesis 

# 1 Topic of the Proposed Tutorial 

Machine learning (ML) on tabular data is central to data science research and practice [50]. In real-world applications, data comes from heterogeneous sources such as data lakes, warehouses, logs, and external APIs, and must be joined, cleaned, augmented [1, 9, 15], and encoded before it can be used by predictive models. 

Machine learning pipelines. This preparation is implemented through end-to-end ML pipelines [37]. Such pipelines span data integration, prediction, debugging, and postprocess-ing [5, 21, 38], combine code from many libraries [39], and can be expensive to execute in production [52]. Developing them is therefore tedious and error-prone, requiring substantial engineering and domain expertise as well as repeated revisions to improve predictive perfor-mance. Accordingly, recent industry surveys identify data quality and pipeline consistency as major obstacles to deploying ML-based applications [2]. 

The rise of machine learning engineering agents. Large language models (LLMs) are reshaping data-centric software development through advances in code synthesis and program understanding. A key driver is their ability to optimize programs for machine-gradable problems [53], where a cheap, well-defined feedback metric can guide iterative improvement. This paradigm has for example enabled advances in scientific and algorithmic discovery (exemplified by Google’s AlphaEvolve [31]), workload-specific database engine synthesis [23, 51], and kernel optimization for emerging AI accelerators [55]. 1arXiv:2610.16919v1 [cs.DB] 12 Oct 2026 ML pipelines are a natural fit for this paradigm because their predictive performance provides a direct optimization objective, making pipeline generation machine-gradable. This has led to the emergence of machine learning engineering (MLE) agents , which aim to automate the generation of tabular prediction pipelines from natural-language task descriptions. These agents use LLMs in iterative loops to generate and refine pipeline code, treating pipeline construction as a program optimization problem. They typically combine LLM-based code generation with evolutionary search methods, such as Monte-Carlo tree search [4] or MAP-Elites [29], using validation performance as the fitness signal. Representative systems include AIDE [19], Amazon’s MLZero [12], Google’s MLE-Star [30], and MLEvolve [11]. Several conceptually extend earlier work from the data management community [13, 14, 25, 27, 45, 46]. However, current agents are primarily evaluated on simplified benchmarks such as MLE-bench, which is based on pre-built datasets derived from Kaggle competitions [7, 48] and thereby ignores key data management challenges. 

Data management challenges for MLE agents. (Semi-)autonomous agents are emerging as a new “class of users” of data systems. In response, the data management community is beginning to redesign systems to be “agent-first” [26, 28], with work spanning agentic text-to-SQL [16], semantic query processing [57], data science [22], and deep research [43]. We argue that MLE agents should likewise become a focus of the community, as they introduce a distinct set of data management challenges. 

Systems and infrastructure. MLE agents repeatedly generate, execute, and evaluate a large number of candidate pipelines, making pipeline search itself a dynamic workload. This shifts the optimization scope from individual pipeline executions to the entire search process, creating opportunities for shared execution, reuse of intermediates [34, 35], cross-pipeline scheduling, and resource management across CPUs, GPUs, and distributed backends [20, 36]. Existing work on efficient ML systems [3, 33, 47] provides a natural foundation, but must be extended to workloads in which pipeline structure, code, data access patterns, resource requirements continuously evolve. Further challenges include cost- and energy-aware execution [24], adaptive placement and parallelization [56], multi-tenant resource sharing across agents [6, 17], and tighter agent-system co-design. Finally, the LLM inference layer itself presents opportunities, such as tailored inference configuration, model selection, and reuse of key-value caches across agents [40]. 

Data discovery and preparation. Current MLE agents are largely evaluated on Kaggle-like tasks with a single pre-built input table, and therefore lack the ability to discover and prepare useful data from heterogeneous sources [54] with complex schemas [8]. Real-world agents must instead operate over data warehouses and lakes, discovering relevant datasets, integrating them, and identifying useful augmentations. This requires integrating efficient data augmentation and discovery techniques [9, 18, 49] into the agentic search process. 

Reliability. MLE agents also face substantial reliability challenges: they often generate non-runnable or semantically incorrect pipelines [32] or fail to filter and clean their input data appropriately. Addressing this requires techniques for detecting and repairing faulty code [10], preventing common errors such as train-test leakage [44], and data debugging methods [21] to identify data issues such as mislabeled training examples. 

Fairness and compliance. By automating pipeline development from raw data and natural-language instructions, MLE agents could make ML accessible to non-technical domain experts. In sensitive or regulated domains, however, this abstraction creates a responsibility gap: users may lack visibility into choices that affect correctness, robustness, fairness, and regulatory compliance [41, 42]. Open questions include how to evaluate these properties systematically and how to design agents that allow non-technical users to understand and control consequential compliance decisions. 2Covered technical questions. In summary, we address the following technical questions: 

• What are machine learning engineering agents, and how do they combine LLM-based code synthesis with evolutionary optimization to generate end-to-end ML pipelines? 

• What data management challenges arise for MLE agents in runtime systems, data discovery and augmentation, reliability, as well as fairness and compliance? 

• How can data management research contribute to addressing these challenges and improving MLE agents? 

# 2 Duration, Format and Anticipated Number of Participants 

The proposed tutorial is new and has not been offered previously. 

Duration and expected number of participants. We propose a 1.5-hour tutorial and expect approximately 20–40 participants. The tutorial assumes only a basic understanding of machine learning and Python. 

Format. The tutorial consists of a 60-minute presentation followed by a 30-minute hands-on session. The presentation will combine prepared slides with interactive question answering, while the hands-on session will allow participants to explore MLE agents on their own laptops. The tutorial is structured as follows: 

Presentation (60min). In the first 30 minutes, we introduce the core architecture of MLE agents and explain how they combine LLM-based code generation with iterative and evolutionary search to optimize end-to-end ML pipelines. We survey representative systems and benchmarks. In the second 30 minutes, we discuss open data management research questions that arise when MLE agents move beyond simplified benchmarks to real-world data environments. 

Hands-on tutorial (30min). Participants will experiment with several MLE agents using prepared Google Colab notebooks and observe how they generate, execute, and iteratively improve ML pipelines. The exercises will require minimal setup; participants will only need to bring a laptop and provide their own LLM API key where required.
