Abstract 

Mixture-of-Experts (MoE) models reduce com-putation by routing each token to a small set of experts, but each selected expert is still used at a fixed precision. We present DPA-MoE , a run-time precision control framework that makes routed experts any-precision. DPA-MoE en-codes expert feed-forward weights as prefix-decodable chunks using SharedScale AnyBCQ, profiles per-expert reconstruction residuals of-fline, and allocates chunks at inference time us-ing live router gate scores. This post-routing al-location lets a single encoded MoE checkpoint operate at multiple effective weight-memory budgets without retraining or re-encoding. Ex-periments on four MoE models spanning dif-ferent scales, routing widths, and shared-expert configurations show that DPA-MoE consis-tently improves reconstruction fidelity over uni-form chunk allocation and yields a better over-all weight-size–quality frontier, with modest steady-state throughput overhead in our proto-type. 

1 Introduction 

Large language models are used across increas-ingly diverse workloads, including interactive assis-tants, coding tools, document summarization, and retrieval-augmented question answering. These workloads vary in their latency, throughput, mem-ory, and quality requirements, creating a need for multiple operating points from the same model. However, a conventional fixed-precision check-point exposes only one point on this resource– quality curve. Releasing or storing a separate quan-tized checkpoint for each operating point increases storage and deployment complexity. An attractive alternative is an any-precision model: a single en-coded artifact whose effective weight size can be

The need is sharpest for local inference, where the binding constraints change while the model is resident: memory shifts as other applications come and go and a user may want speed now and accuracy next. Adapting a fixed-precision check-point means swapping in a separately quantized artifact, which requires re-encoding or fetching an-other multi-gigabyte file; an any-precision artifact instead moves along the size–quality curve in place. Mixture-of-Experts (MoE) models route each token to a small subset of experts rather than ap-plying the full feed-forward parameter set (Shazeer et al., 2017; Lepikhin et al., 2021; Fedus et al., 2022; Du et al., 2022; Jiang et al., 2024; Dai et al., 2024; Muennighoff et al., 2025). This increases total capacity while keeping per-token computation small. However, MoE only controls which experts are activated: once selected, an expert is still evalu-ated at a fixed precision. Since expert FFN weights dominate modern MoE parameter counts (about arXiv:2610.21378v1 [cs.CL] 15 Oct 2026 95% in Qwen3-30B-A3B (Qwen Team, 2025)), the number of weight bits read inside each selected expert remains an important control point. This paper makes selected experts any-precision. As shown in Figure 1, MoE chooses which experts are activated, while DPA-MoE chooses how much 

of each selected expert is used by assigning a vari-able number of precision chunks (Section 3.1) per routed activation. Throughout, precision means this chunk count k rather than a numeric bit-width: an expert at precision k is one reconstructed from its first k chunks. Smaller chunk budgets give lighter but less accurate reconstructions; larger bud-gets recover higher fidelity. This lets a single MoE checkpoint trace a fine-grained weight-size–quality frontier without retraining or maintaining multiple quantized variants. A uniform any-precision MoE assigns the same chunk count to every activated expert, ignoring router-provided structure. Existing methods ad-dress memory and quality through post-training quantization (Frantar and Alistarh, 2024; Duanmu et al., 2025) or runtime adaptation using cache state, device constraints, or long-horizon activation statis-tics (Tang et al., 2024; Wang et al., 2025a; Chu et al., 2025). DPA-MoE instead combines offline quantization residuals with live gate scores, since experts differ both in current-token importance and reconstruction sensitivity. We present DPA-MoE , a dynamic precision al-location framework for any-precision MoE mod-els. DPA-MoE encodes expert FFN weights with SharedScale AnyBCQ, a prefix-decodable repre-sentation built on AnyBCQ (Park et al., 2026), profiles reconstruction residuals for each expert and chunk count, and combines those residuals with live router gate scores at inference time. The pretrained router and expert identities re-main unchanged; DPA-MoE only controls how much precision each selected expert receives. It is not an end-to-end serving system, but a precision-allocation primitive complementary to systems such as DeepSpeed-MoE, HOBBIT, and D2MoE (Rajbhandari et al., 2022; Tang et al., 2024; Wang et al., 2025a). On Qwen3-30B-A3B, DeepSeekMoE-16B-Chat, OLMoE-1B-7B-0125, and Qwen1.5-MoE-A2.7B (Qwen Team, 2025; Dai et al., 2024; Muennighoff et al., 2025; Qwen Team, 2024), DPA-MoE con-sistently reduces KL divergence relative to uni-form chunk allocation and yields a better overall weight-size–quality frontier, with modest steady-state throughput overhead in our prototype. Sparse routing chooses the experts; DPA-MoE chooses how much of each selected expert to use. Our contributions are: • We formulate any-precision MoE , where sparse routing selects experts and a separate precision controller adjusts how many weight bits are read from each selected expert. • We introduce SharedScale AnyBCQ, a prefix-decodable expert encoding built on Any-BCQ (Park et al., 2026) that lets a single MoE checkpoint expose multiple effective weight-memory budgets without retraining or re-encoding. • We propose a two-stage allocation framework that combines offline residual profiling with live router gate scores to allocate precision chunks across routed expert activations. • We show that DPA-MoE improves the weight-size–quality frontier over uniform chunk al-location, while incurring modest steady-state throughput overhead in a lightweight proto-type. 

2 Related Work 

Static Quantization. Post-training quantization reduces LLM memory footprint by compress-ing weights offline. General LLM post-training quantization methods include LLM.int8 (Dettmers et al., 2022), ZeroQuant (Yao et al., 2022), SmoothQuant (Xiao et al., 2023), GPTQ (Frantar et al., 2023), and AWQ (Lin et al., 2024). MoE-specific methods extend this to expert weights, ei-ther uniformly (Frantar and Alistarh, 2024) or with mixed precision assigned per expert based on sen-sitivity and activation frequency (Duanmu et al., 2025). While mixed-precision methods acknowl-edge that experts differ in importance, the alloca-tion is fixed before deployment and remains con-stant regardless of the current input. 

Input-Adaptive Precision Methods. Recent work has begun to adapt expert precision beyond static assignment. Tang et al. (2024) serve cache-miss experts at lower precision, but the decision is binary and driven by cache state rather than token-level routing confidence. Chu et al. (2025) main-tain a high-precision resident set based on long-horizon router traces, but rely on aggregate statis-tics that cannot reflect the importance of the current token to each expert. Wang et al. (2025a) insert a per-expert bit-width gate downstream of the un-modified router, but require training an additional adapter and bind precision to a learned policy rather than exposing it as a separable runtime variable. 

Progressive and Multi-Precision Encodings. Acomplementary line of work encodes weights such that multiple precisions are accessible without re-encoding. Yu et al. (2021) introduce neural net-works whose precision can be changed at runtime, Park et al. (2024) show that a single quantized model can support multiple bit-widths, Wang et al. (2025b) provide fine-grained model size control through stacked residual quantization, and Park et al. (2026) advance this through progressive bit-planes with negligible switching overhead. These encodings provide the representational substrate for runtime precision control, but do not specify how that control should be exercised across experts. 

Positioning. Appendix D compares these meth-ods on five axes: training-free, router left un-changed, token-aware, fine-grained budgets reach-able, and no re-fetch on a precision upgrade. The closest is D 2MoE, whose nested Matryoshka quan-tization reuses already-loaded bits as our prefix-decodable encoding does, but it exposes only dis-crete tiers and needs a trained per-expert network to choose bit-widths. DPA-MoE is, to our knowledge, the only method that is simultaneously training-free, token-aware, and fine-grained in k while leav-ing the router untouched. 

3 Background and Problem Formulation 

3.1 Precision Chunks 

DPA-MoE stores each expert weight tensor as an ordered sequence of chunks . A chunk is a single binary bitplane together with its per-group scale; a per-group offset is shared across chunks. Using the first k chunks appends bitplanes to a prefix that is already valid, so raising k never invalidates what has been read; kmin and kmax denote the smallest and largest supported chunk counts. Section 4.1 gives the reconstruction (Equation 1) and the en-coding procedure. A chunk is thus the granularity at which expert precision can be spent.

3.3 Problem Statement 

Uniform precision is structurally mismatched with MoE routing. For a given token, the router does not activate experts equally: it assigns different gate scores to different selected experts, indicat-ing that their contributions to the layer output are not symmetric. Across layers and experts, the re-construction error introduced by using a shorter precision prefix also varies. Nevertheless, a uni-form precision policy reads the same number of weight bits from every selected expert. This wastes budget in two ways. First, low-contribution experts can receive the same precision as high-contribution experts. Second, experts that are already easy to reconstruct can receive the same precision as experts whose output is more sensitive to missing chunks. As a result, uniform precision can spend memory and bandwidth on expert ac-tivations with small marginal value while under-serving the activations where additional precision matters most. The problem addressed in this paper is therefore not to change the MoE router, retrain the model, or design a new serving scheduler. It is to remove this uniform-precision assumption inside the experts selected by the existing router, so that a single en-coded MoE checkpoint can expose multiple weight-size–quality operating points more efficiently.

4.2 Two-Stage Framework 

The encoding described in Section 4.1 converts ex-pert precision into a runtime-controllable variable. The central question then becomes: given a fixed per-dispatch budget, how should chunks be allo-cated across active experts to best preserve output quality? A uniform allocation—assigning the same chunk count to every expert—ignores two sources of heterogeneity: the intrinsic quantization error of each expert, which varies across experts inde-pendently of routing, and the router’s gate scores, which reflect each expert’s relevance to the current token. We propose a two-stage framework that keeps these two sources strictly separate.

5 Experimental Setup 

5.1 Models 

We evaluate on four open-weight MoE language models, chosen to vary in scale, routing width, and shared-expert configuration: Qwen3-30B-A3B (Qwen Team, 2025), 8 of 128 experts, no shared ex-perts; DeepSeekMoE-16B-Chat (Dai et al., 2024), 6 of 64 routed experts plus 2 shared; OLMoE-1B-7B-0125 (Muennighoff et al., 2025), 8 of 64, no shared experts; and Qwen1.5-MoE-A2.7B (Qwen Team, 2024), 4 of 60 routed experts plus 4 shared. The first two carry the full evaluation suite includ-ing inference speed; the latter two are evaluated on KL divergence and downstream accuracy. 

5.2 Baselines 

We compare DPA against two baselines. As static quantization references, we include Q2_K, Q5_K_M, and Q8_0 GGUF quantizations of all four models, representing fixed operating points at approximately 2-, 5-, and 8-bit compression. For Qwen3-30B-A3B and DeepSeekMoE-16B-Chat we use published GGUF artifacts (Unsloth AI, 2025; Mradermacher, 2024); the OLMoE-1B-7B-0125 and Qwen1.5-MoE-A2.7B artifacts are converted locally from the base checkpoints with llama.cpp. As a dynamic baseline, Uniform k

serves all experts at a fixed chunk count k ∈{2, . . . , 8}, using the same encoding as DPA but without gate-aware allocation. 

5.3 Evaluation 

We evaluate reconstruction quality via mean KL divergence (KLD) between the quantized and full-precision output distributions, measured on 10 sequences of 4,096 tokens sampled from the WikiText-2 test set (Merity et al., 2017) with a fixed random seed. For downstream task performance, we report accuracy on four benchmarks: ARC-Challenge (Clark et al., 2018), ARC-Easy (Clark et al., 2018), WinoGrande (Sakaguchi et al., 2021), and PIQA (Bisk et al., 2020). We additionally re-port the macro-average across all four tasks as a single summary metric. 

5.4 Inference Evaluation Setup 

We evaluate inference throughput and latency un-der a controlled execution setting designed to com-pare the cost of materializing and computing dif-ferent amounts of expert weight. All methods use the same model, implementation, and execution path; the only difference is the chunk allocation assigned to activated experts. In the Full-Memory setting used for the speed measurements, all en-coded expert chunks are resident in GPU memory, so the measurement isolates precision allocation and variable-chunk execution rather than SSD, host-cache, or expert-offloading effects. We compare DPA against Uniform-k at matched average chunk budgets ¯k ∈ {3, 4, 5, 6, 7}.Uniform-k materializes the same number of chunks for every activated expert, while DPA redistributes the same total chunk budget according to gate-weighted residual costs. Thus, the comparison iso-lates the runtime and quality effect of non-uniform expert precision allocation under the same effective weight-memory budget. We report generation throughput (TPS) and time-to-first-token (TTFT) averaged over 100 sequences from each of WikiText-2 (Merity et al., 2017), C4-en (Raffel et al., 2020), and the Korean split of mC4 (Xue et al., 2021). 6 Results 

6.1 Reconstruction Quality 

We adopt mean KL divergence (KLD) between the quantized and full-precision output distributions as our primary reconstruction metric. Unlike perplex-ity, KLD directly quantifies how much quantization distorts the model’s predicted distribution at every token, providing a sensitive and task-agnostic mea-sure of fidelity that captures both mode shifts and tail deformations in the output. Figure 4 plots mean KLD against effective model weight for DPA and all baselines. On both models, the DPA curve lies consistently below the Uniform k curve across the full compression range, confirming that gate-aware allocation re-duces output distortion at every matched memory budget. The gain is most pronounced in the mid-compression regime, where DPA reduces KLD by up to 4.5× relative to Uniform k at matched size (DeepSeekMoE-16B-Chat, ¯k=4 ), and recov-ers equivalent fidelity at 2–4 GB less memory across both models. Non-integer operating points (e.g., ¯k=2 .5) smoothly interpolate between inte-ger anchors, enabling fine-grained memory–fidelity trade-offs that static quantization cannot provide. 

6.2 Downstream Task Performance 

Figure 5 reports macro-average accuracy across ARC-Challenge, ARC-Easy, WinoGrande, and PIQA as a function of effective model weight; per-task breakdowns are provided in Appendix C. DPA consistently outperforms Uniform k at matched memory budgets on both models, with the largest gains at aggressive compression where uniform allocation is most wasteful. The accuracy improvements mirror the KLD reductions reported in Section 6.1, confirming that reduced output dis-tortion translates to measurable downstream gains.

7 Discussion 

What does DPA-MoE show? DPA-MoE shows that, after the router selects the active experts, there is still a meaningful precision-allocation problem. Uniform-k assigns the same chunk count to ev-ery routed expert, but routed experts differ in two ways: their gate scores indicate different impor-tance for the current token, and their residual pro-files indicate different quantization sensitivity at each chunk count. DPA combines these two signals into a gate-weighted residual objective, allowing the same chunk budget to be used more effectively without modifying the pretrained router or train-ing an additional policy. The consistent improve-ments over Uniform-k suggest that expert precision should be treated as a runtime allocation variable rather than a fixed property of the encoded check-point. 

How should the runtime results be interpreted? 

DPA-MoE improves the weight-size–quality fron-tier, but it is not a free speedup at a fixed bud-get: at matched ¯k, per-dispatch allocation and non-uniform chunk materialization lower steady-state TPS and raise TTFT in our prototype. The bene-fit is clearer at matched quality, since DPA often reaches a larger Uniform-k budget’s quality with fewer chunks, recovering part of that overhead at a smaller effective weight size. Its value is thus a better set of weight-size–quality operating points from one encoded model, not higher throughput at every fixed budget. 

Where is DPA-MoE the right tool? For batched prefill A is the union of all tokens’ selected experts, so the O(n2¯kk range ) allocator cost of Section 4.3 grows with batch size while its benefit shrinks: inference turns compute-bound and each expert is reused across more tokens. DPA-MoE there-fore suits memory-constrained, small-to-moderate batches — single-stream decoding, local serving — and a deployment should fall back to Uniform-k

past the batch size where allocation stops paying for itself, a threshold set by the target device rather than by the method. 

Scope and extensions. SharedScale AnyBCQ is one prefix-stable encoding substrate for this frame-work, not the only possible choice. The allocation method can be applied to other progressive encod-ings as long as their precision units can be treated as allocatable chunks with measurable residual pro-files. Likewise, DPA-MoE exposes a runtime pre-cision interface that could be used by higher-level policies such as phase-aware decoding, adaptive quality control, or speculative decoding. This paper focuses on the core allocation problem; optimized runtime integration and downstream system com-position are left as directions for future work. 

8 Conclusion 

We presented DPA-MoE, a runtime precision con-trol framework for any-precision MoE inference. Standard MoE routing determines which experts are activated for each token, but leaves the selected experts at a fixed precision. DPA-MoE adds a post-routing precision allocation step: given the experts selected by the pretrained router and a fixed chunk budget, it decides how many precision chunks each routed expert activation should receive. To support this formulation, we introduced SharedScale AnyBCQ, a prefix-stable expert en-coding that lets a single MoE checkpoint expose multiple effective weight-memory budgets without retraining or re-encoding. We then combined of-fline residual profiling with live router gate scores to allocate chunks according to gate-weighted re-construction costs. Experiments on four MoE models show that this allocation consistently improves reconstruction fi-delity over uniform chunk allocation and yields a better overall weight-size–quality frontier. Run-time measurements further show that these gains come with modest steady-state throughput over-head in our current prototype. Overall, DPA-MoE suggests that expert preci-sion can be treated as a runtime allocation variable rather than a fixed property of a deployed check-point. By allowing a single encoded MoE check-point to trace a fine-grained weight-size–quality frontier at runtime, DPA-MoE establishes expert precision as a first-class inference-time variable— one that downstream systems, adaptive controllers, and deployment pipelines can optimize directly without maintaining separate model variants. 

9 Limitations 

DPA-MoE optimizes the weight-size–quality fron-tier of a single encoded MoE checkpoint, but effec-tive weight size is a proxy, not a complete latency model. Actual serving performance also depends on kernel fusion, batching, dispatch overhead, and hardware-specific scheduling, none of which are modeled here. Our runtime is a lightweight prototype built on top of llama.cpp (Gerganov et al., 2023). The al-locator and variable chunk materialization are not fully fused with expert dispatch kernels, and no custom scheduler is used. The observed TTFT overhead and modest TPS reduction should there-fore be interpreted as prototype costs rather than intrinsic costs of the method. The allocation objective is a surrogate for down-stream quality. DPA uses live router gate scores as a lightweight proxy for expert importance and offline residuals to estimate quality loss, but gate scores are imperfect and the objective ignores cross-expert residual interactions. Residual estimates are computed from finite calibration data and can con-tain small precision inversions, which we address via monotone projection. The dynamic program is therefore optimal for the projected surrogate, not necessarily for the true downstream loss. Finally, our empirical scope covers four open-weight MoE models and a focused set of bench-marks, chosen to isolate the effect of non-uniform chunk allocation against a uniform baseline. They differ in scale, routing width, and shared-expert configuration, but we do not claim exhaustive gen-erality across all MoE architectures, routing de-signs, hardware backends, or task domains. DPA-MoE also requires access to router gate scores, which may not be available in closed-weight de-ployments.

A Storage Overhead: AnyBCQ vs. SharedScale AnyBCQ 

To support any-precision inference across the full 2–8 bit range at runtime, both AnyBCQ and Shared-Scale AnyBCQ must store all bitplanes and their associated scale parameters simultaneously. Al-though the two encodings require the same eight bitplanes, they differ substantially in how many scale sets must be retained. In AnyBCQ, scales are jointly re-optimized at every precision tier, so each tier maintains its own independent scale set. D Comparison with Dynamic Expert-Precision Methods 

Table 5 expands the positioning discussion in the Related Work section into a per-axis comparison. MxMoE assigns mixed precision per expert, but the allocation is fixed before deployment, is inde-pendent of the current input, and does not support runtime switching. HOBBIT selects a substitute precision for cache-miss experts only; the mecha-nism is gated by cache state rather than by the gate score, and it does not apply to cache-hit experts. DynaExq promotes and demotes experts between high- and low-precision resident sets using long-horizon expert hotness estimated from router traces, so it relies on aggregate statistics rather than each expert’s importance to the current token. D 2MoE uses a nested Matryoshka quantization in which higher bit-widths encapsulate lower ones, so up-grading precision reuses already-loaded bits — a property it shares with our prefix-decodable design. It nonetheless supports only discrete tiers, offers no non-integer interpolation, and requires training a separate per-expert plug-in network to decide bit-width. DPA-MoE is, to our knowledge, the only method that is simultaneously training-free, token-aware, and fine-grained in k while leaving the router untouched. We do not report a head-to-head empirical com-parison against these methods. D 2MoE is the clos-est in capability, but we are not aware of a pub-lic implementation, and its per-expert plug-in net-works would have to be trained before any com-parison could be run. The main comparison in the paper is therefore against Uniform-k, and the sig-nal ablation of Section 6.5 isolates the contribution of each allocation signal in place of a cross-method baseline.
