## 摘要
数据流是深度学习（DL）框架执行的基础，涵盖自动微分和算子融合优化。涉及数据流的缺陷可能导致结果错误或出现非预期行为。现有测试方法主要通过算子拓扑表示模型，忽略了运行时张量值、属性以及算子输入需求。因此，即使这些差异会影响框架行为，它们也无法区分拓扑结构相似的模型中的不同数据流。我们提出张量流图（Tensor Flow Graph，TFG），以捕获运行时张量状态和算子输入需求。其节点表示算子及其输入需求，边则记录张量值和属性。在 TFG 的基础上，我们提出了以数据流为基础的变异测试方法 FlowMuT。该方法将变异表示为受约束的子图替换，其中变异算子源自已有工作以及对可变数据流对象的分析。在每一轮中，FlowMuT 为种子模型构建 TFG，将变异算子与 TFG 中的位置配对，并利用数据流约束过滤非法候选项。它采用 LinUCB 根据覆盖率和影响选择候选项，执行变异体，更新选择反馈，并将每个被接受的变异体作为下一轮的种子。我们使用来自多种应用场景的代表性模型，在 PyTorch 和 MindSpore 上评估了 FlowMuT。对于所有基线方法均未发现的情形，FlowMuT 共提交了 55 份缺陷报告；开发者确认了其中 41 份报告，并修复了其中 7 份报告所描述的缺陷。与最强基线相比，FlowMuT 的数据流多样性提高了 43.4%；其合法变异体比例达到 96.7%，而不使用约束时仅为 86.4%。这些结果表明，从数据流视角开展测试具有可行性和有效性。

## Abstract
Data flow underlies deep learning (DL) framework execution, including automatic differentiation and operator-fusion optimization. Bugs involving data flow can cause incorrect results or unexpected behavior. Existing testing methods represent models primarily by operator topology, omitting runtime tensor values and properties and operator input requirements. They therefore cannot distinguish data flows in models with similar topologies, even when these differences affect framework behavior. We introduce the Tensor Flow Graph (TFG) to capture runtime tensor states and operator input requirements. Its nodes represent operators and their input requirements, while its edges record tensor values and properties. Building on the TFG, we propose FlowMuT, a mutation-based testing method grounded in data flow. Mutations are represented as constrained subgraph replacements, with mutation operators derived from prior work and an analysis of mutable data flow objects. In each round, FlowMuT builds a TFG for the seed model, pairs mutation operators with TFG sites, and filters illegal candidates using data flow constraints. It uses LinUCB to select a candidate based on coverage and impact, executes the mutant, updates selection feedback, and uses each accepted mutant as the next seed. We evaluate FlowMuT on PyTorch and MindSpore using representative models from diverse application scenarios. FlowMuT submitted 55 bug reports for cases missed by all baseline methods; developers confirmed 41 reports and fixed the bugs described in 7 reports. FlowMuT achieves 43.4% higher data flow diversity than the strongest baseline and a legal mutant rate of 96.7%, compared with 86.4% without constraints. These results show that testing from a data flow perspective is practical and effective.
