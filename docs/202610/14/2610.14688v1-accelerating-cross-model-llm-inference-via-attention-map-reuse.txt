XUPENG MIAO ∗, Peking University, China LLM-augmented data workflows often involve multiple heterogeneous models operating over substantial shared context, such as schemas, tool specifications, interaction history, and intermediate results. Although prefix caching can reduce prefilling overhead, existing approaches are largely limited to reuse within the same model because KV states are tightly coupled to model-specific architectures. We present MapFlow, a system for efficient heterogeneous LLM serving via cross-model attention map reuse. Instead of reusing KV states, MapFlow reuses attention maps, which capture token dependency patterns and are more transferable across models. To enable efficient and accurate reuse, we combine partial recomputation with lightweight linear translation across layers and heads. To make attention reuse practical for long contexts, we further introduce block-level sparse compression and a fused retrieval kernel. Experiments show that MapFlow reduces prefilling latency and improves end-to-end serving efficiency while preserving generation quality across heterogeneous model pairs and multi-turn routing workloads. These results suggest that attention maps provide an effective reusable state for heterogeneous LLM serving, especially in prefix-heavy data workflows. 1 Introduction 

Large language models (LLMs) are increasingly becoming a core building block of modern data systems. Recent studies [11, 14, 17, 24, 67, 68, 79, 80, 87] have explored using LLMs for database interaction and symbolic memory, query optimization and tuning, data preprocessing, and entity matching, suggesting that LLMs are no longer merely front-end interfaces but active components in data management pipelines. In these settings, LLM execution is rarely a single prompt-response step. Instead, requests are embedded in multi-stage workflows that repeatedly expose models

to long, structured contexts, including database schemas, system constraints, tool specifications, prior interaction history, and intermediate results. As these contexts accumulate across turns and operators, repeatedly processing the same prefix becomes a major bottleneck for interactive latency and system throughput [24, 45, 47, 57, 68]. When multiple requests share the same prompt prefix and are served by the same model, cached Key-Value (KV) tensors can be reused to avoid redundant prefilling and reduce Time-to-First-Token (TTFT), as demonstrated by recent LLM serving systems such as vLLM [33] and SGLang [84]. However, this assumption does not hold in many LLM-augmented data systems, where a single data workflow often involves multiple heterogeneous LLMs or agents. To balance quality, cost, and response time, these systems assign different subtasks to different models, such as using a stronger model for planning or semantic interpretation and smaller models for refinement, formatting, or summarization. Such heterogeneous execution appears naturally in routing-based assistants, cascaded inference, and multi-agent workflows [27, 51, 64]. Although these executions frequently share substantial prompt prefixes, existing prefix caching mechanisms are largely restricted to 

identical model instances . Once execution moves across models, even identical database-centric context must be recomputed from scratch, leading to high latency and poor reuse. This problem is particularly acute in data management workloads. Compared with open-ended chat, many database-facing prompts are highly structured and persist across multiple requests. A text-to-SQL or database assistant may repeatedly prepend the same schema and system instructions; a tuning assistant may repeatedly condition on workload summaries and engine constraints; and an agentic analytics pipeline may pass along tool traces, metadata, and prior reasoning results [74]. These workloads therefore create a distinctive combination of prefix-heavy execution and cross-model transitions. From a data systems perspective, this is not merely a serving inefficiency; it is a missed opportunity for intermediate state reuse across operators in heterogeneous LLM pipelines. A straightforward idea is to reuse cached KV states across models. Prior work on cross-model or multi-model execution has explored routing, blending, multiplexing, and state reuse, but KV tensors remain tightly coupled to model-specific hidden representations, dimensions, structures, and param-eters [12, 16, 40, 46, 56, 73, 86]. This coupling makes them difficult to translate across heterogeneous architectures without incurring either substantial accuracy loss or nontrivial adaptation overhead. As a result, existing approaches struggle to achieve the accuracy-efficiency trade-off required by online systems. This limitation suggests a broader question: what form of intermediate state can be reused across heterogeneous LLMs while remaining efficient enough for real-time execution? 

In this paper, we answer this question with MapFlow, an efficient heterogeneous LLM serving system based on cross-model attention map reuse. Our key insight is that, while KV states are model-specific latent representations, attention maps encode token-to-token dependency structure in Transformer models . For models that share the same tokenizer and process the same context, these dependency patterns can exhibit stronger structural similarity across models than KV tensors do. This makes attention maps a more suitable reusable state for heterogeneous execution. Based on this observation, MapFlow transfers attention maps from a sender model to a receiver model, uses lightweight linear translation to bridge differences in layers and heads, and combines this with partial recomputation to preserve semantic fidelity. Turning this idea into a practical runtime raises two systems challenges. First, raw attention maps have quadratic size in context length, making naive caching prohibitively expensive. Second, even if cached, directly reconstructing dense receiver-side attention would introduce excessive memory traffic and runtime overhead. MapFlow addresses these challenges through a co-designed system runtime. It applies a hardware-friendly block-level top-𝑝 sparse compression scheme to store attention maps in a compact block-sparse layout, and uses a fused retrieval kernel that combines attention translation and value aggregation without materializing dense intermediate tensors.

The system further organizes cached sparse blocks with prefix-hash-based indexing and overlaps retrieval with partial recomputation, enabling efficient online reuse within modern serving stacks. We evaluate our system across heterogeneous model pairs and multi-turn workloads. Our results show that MapFlow reduces TTFT by 15%–20% while maintaining generation quality, and improves end-to-end throughput by up to 25% under the same latency target. We further show that its benefits are especially pronounced in long-context, multi-turn settings, where repeated workflow-level context amplifies the cost of standard prefilling. These results suggest that cross-model attention reuse can serve as an effective execution primitive for LLM-augmented data systems. Our paper makes four main contributions: 

• We identify cross-model prefix reuse as a fundamental bottleneck in LLM-augmented data workflows, where long structured contexts are repeatedly processed across heterogeneous models. 

• We propose attention maps as a reusable intermediate execution state for heterogeneous LLM serving, avoiding the tight architectural coupling of KV-cache-based reuse. 

• We design MapFlow, a practical LLM serving system that combines partial recomputation, lightweight attention-map translation, sparse block-level compression, and fused online retrieval. 

• We demonstrate through extensive experiments that MapFlow improves latency and through-put for heterogeneous multi-model execution, making it a promising systems substrate for prefix-heavy LLM data workflows.

2.2 Inference Phases: Prefill and Decode 

As shown in Figure 1B, LLM inference is distinctively characterized by two sequential phases: Prefill 

and Decode .

Prefill Phase: This phase processes the input prompt in parallel and serves two primary purposes: (1) computing and storing the Key-Value (KV) cache for all input tokens to accelerate subsequent generation; (2) generating the first output token. This phase is typically compute-bound due to the highly parallelizable matrix multiplications ( 𝑂 (𝐿 2) complexity for attention). The latency of this phase is referred to as Time-to-First-Token (TTFT). 

Decode Phase: Following prefill, the model generates tokens auto-regressively, one by one. In each step, the model attends to all previous tokens (prompt + generated). This phase is typically 

memory-bound , dominated by the cost of loading model weights and KV caches from memory. 

2.3 Prefix Caching 

Due to the quadratic computational complexity of the attention mechanism, the prefill phase remains a major bottleneck for processing long prompts. Prefix caching [33, 84] mitigates this by retaining the KV cache of frequently reused prefixes (e.g., system prompts or few-shot examples). When a new request shares a prefix with a cached entry, the serving engine retrieves the pre-computed KV tensors, bypassing redundant computation. However, traditional prefix caching strictly requires identical model architectures and weights, severely limiting its applicability in heterogeneous environments. 

2.4 Multi-LLM Systems 

In production environments, a “one-size-fits-all” model strategy is often inefficient. Multi-LLM systems [2, 4, 20, 21, 26, 35, 38, 43, 44, 53, 69, 85] leverage the distinct capabilities and cost-efficiency profiles of heterogeneous models to optimize performance. As a typical example shown in Figure 2, the multi-LLM router system [7, 10, 51] has a router that will analyze the complexity of an incoming query and direct it to the most appropriate model (e.g., sending simple queries to smaller, faster models and complex reasoning tasks to larger models). Crucially, in multi-LLM system workflows, identical prompt prefixes are often processed by different models (query 1 and answer 1 in Figure 2). This redundancy highlights the critical need for a cross-model prefix caching mechanism.

2.6 Cross-model Communication 

The conventional approach for inter-model communication relies on transmitting raw token se-quences, requiring the receiving model to perform a full prefill computation. While straightforward, this method incurs significant computational overhead during the prefill phase, as the context length expands rapidly over multiple rounds of interaction. To alleviate this bottleneck, recent studies leverage the intermediate KV cache, rather than raw text, as the cross-model communication medium. These techniques generally fall into two paradigms: selective partial recomputation and learned cache adaptation. As an example of the partial recomputation paradigm, Droidspeak [40] isolates critical trans-former layers via profiling, selectively recomputing the KV cache only at these layers while reusing the cached tensors for the rest. Similarly, CacheBlend [73] identifies tokens exhibiting significant KV state deviation between the source and target models, recomputing the KV cache exclusively for these divergent tokens. Conversely, under the learned adaptation paradigm, C2C [16] fuses the KV cache from both sender and receiver, generating a composite cache that encapsulates context from both. But it doesn’t eliminate receiver prefill since it requires both models to compute the KV cache. KVCOMM [75] and Q-KVComm [32] communicate or compress KV caches among homogeneous agents whose inputs contain related content under diverging prefixes. Addressing

3.2 Challenges in Cross-Model Reuse 

Multi-LLM systems typically contain heterogeneous models with varying architectures (e.g., dif-ferent layer counts, head counts and head dimensions). This heterogeneity renders naive reuse approaches, such as Droidspeak and CacheBlend, ineffective, as they are tailored strictly for homo-geneous models. To enable KV cache reuse across heterogeneous architectures, recent works have introduced learning-based approaches that employ neural networks to project KV states between models. However, these methods primarily prioritize generation quality over system efficiency. The com-putational overhead introduced by complex adapters often negates the latency benefits of reuse, failing to achieve the optimal accuracy-efficiency trade-off required by online serving systems. The fundamental limitation of these approaches lies in the nature of the reused state. KV caches are tightly coupled with model weights and hidden dimensions. Even models fine-tuned from the same base checkpoint can exhibit drastically different KV distributions for identical prompts, let alone fully heterogeneous pairs. Consequently, translating KV caches requires complex non-linear transformations to maintain accuracy, making efficient reuse intrinsically difficult.

5 MapFlow System Design 

To efficiently reuse the attention map across different models, we must address two primary challenges. The first is mitigating memory bloat: the memory complexity of the attention map scales quadratically with the context length, making it infeasible to fully materialize it during both the training phase and runtime storage. The second challenge lies in computation: given the attention map collected from the sender, we need to efficiently apply it with transformation weights to the receiver’s value vectors without incurring prohibitive inference overhead. We design MapFlow to overcome these bottlenecks in three steps, as shown in Figure 6. First, to reduce the memory footprint of the generated attention maps, MapFlow employs an Attention State Compressor to compress and store the attention map in a block-wise format. Second, to manage the compressed attention map cache and minimize memory fragmentation, MapFlow implements a Block Manager that organizes the cache by maintaining a prefix-hash-based indexing system for efficient retrieval. Third, to efficiently reuse the block-sparse attention map, MapFlow performs Attention Retrieval by utilizing a custom GPU kernel which fuses the reconstruction of the receiver’s attention map (using the cached sender’s map and transformation weights) with the matrix multiplication of the receiver’s value vectors, directly producing the attention output without intermediate dense materialization.

5.2 Attention State Compressor 

MapFlow utilizes Sparse Compression mechanism that filters the attention map before it is cached. Empirical profiling of attention distributions across extended sequence lengths reveals a heavy-tail phenomenon, as extensively studied in previous works [5, 34, 61]. This implies that retaining only the tokens necessary to satisfy a cumulative probability 𝑝 requires only a small fraction of the memory compared to full dense materialization, with minimal impact on generation quality. Guided by this insight, MapFlow systematically compresses the attention map by exploiting this inherent sparsity. Details about memory footprint analysis can be found at Section 7.5. Instead of applying token-level sparsity, which leads to irregular memory access patterns, MapFlow adopts a hardware-friendly block-level sparsity approach which partitions the attention map into 2D blocks (e.g., 64 × 64 tokens). As shown in Algorithm 1, the process avoids full dense matrix materialization by splitting the compression into two primary stages:

Stage 1: Block-Level Top-𝑝 Filtering. For each query block and key block pair, we efficiently compute an aggregated block-level importance score via LogSumExp reductions ( block_row_lse ). Using these block-level statistics, we calculate the sum probabilities for each block ( block_sumprob )and apply a Top-𝑝 filtering strategy. For each blocks in a row, we sort the target key blocks by their aggregated scores in descending order and retain only the subset of blocks required to reach a cumulative probability threshold 𝑝 . This yields a binary mask indicating which blocks are to be kept. 

Stage 2: Sparse Extraction. Once the block-sparsity mask is determined, we extract the BSR metadata, including compressed row indices ( crow ), column indices ( col ), and non-zero offsets (nnz_offsets ) which map the logical coordinates of each retained block within the [num_blocks_q ,

This two-stage compression packs the attention map into a BSR layout ultimately, drastically reducing the memory footprint and network transmission payload and aligning with memory constraints and layout of the downstream fused kernel. Note that, compression can be performed once after the sender produces the attention map, without blocking the sender’s critical path. And the compressed map can be reused by multiple receivers. 

5.3 Block Manager 

MapFlow organizes the attention map cache in a block-wise structure to bound memory consump-tion, analogous to how vLLM manages the KV cache in paged blocks[33]. However, a fundamental distinction complicates our design: whereas KV caches maintain uniform shape across layers and sequence positions, block-sparse attention maps exhibit highly dynamic shapes. Specifically, the attention context length varies across different sequence positions due to the causal masking, while the number of retained attention blocks fluctuates across different layers depending on the local sparsity patterns. This variability makes dynamic memory management more challenging. 

Block Structure and Indexing. To accommodate these irregular shapes, we partition the attention map into blocks along the sequence dimension. For each token span (contiguous token segment), we compute a prefix hash that incorporates the content of the span and all preceding context. This hash serves as a unique identifier for cache retrieval. We maintain, for each layer of the sender model, a list of block indices corresponding to the non-zero columns of the attention map for that token span. This sparse indexing allows MapFlow to store only the attended positions rather than the full quadratic attention matrix. 

Cache Storage. During the caching phase, after the sender model computes the attention map, it identifies the retained column indices for each token span (as determined by the sparsifying strategy in Section 5.2). The sender transmits these indices along with their prefix hashes to the MapFlow cache server. The server maintains a hash table mapping each prefix hash to its corresponding block indices across all layers, enabling efficient lookup during retrieval. 

Cache Retrieval and Overlap. During online serving, the receiver model identifies the prefix hashes of the context it wishes to reuse. It transmits these hashes to the cache server, which returns the corresponding block indices for cache hits. The server then streams the hit blocks to the receiver’s GPU memory. This retrieval process is fully overlapped with the receiver’s partial recomputation phase described in Section 4, ensuring that the attention map blocks are available

5.4 Attention Retrieval with Fused Kernel 

To retrieve sender’s attention map and transform into receiver’s, a naive implementation would follow a two-stage pipeline: (1) materialize a dense receiver attention map 𝐴 𝑅 ∈ R𝐿 ×𝐿 ×𝑛 by transforming the sender map 𝐴 𝑆 ∈ R𝐿 ×𝐿 ×𝑚 with weights 𝑊 ∈ R𝑚 ×𝑛 , and (2) multiply 𝐴 𝑅 with the receiver values 𝑉 𝑅 to produce the output. However, even though 𝐴 𝑆 is stored in a block-sparse format, the head transformation induced by 𝑊 densifies attention across heads. Consequently, explicitly materializing 𝐴 𝑅 requires O( 𝑛𝐿 2) memory and is infeasible for long contexts. To overcome this memory bottleneck, MapFlow employs a custom fused GPU kernel (Algo-rithm 2) that reconstructs the receiver’s attention and computes the output on the fly, without allocating global memory for intermediate dense states. The attention retrieval engine organizes the sparse 𝐴 𝑆 logically into a shape of [𝐿 𝐵 , 𝐿 𝐵 , 𝑚, 𝐵, 𝐵 ], where 𝐿 𝐵 is the number of blocks along the sequence dimension and 𝐵 is the block size. Within the BSR layout, the column array (denoted as col in Algorithm 2) stores the non-zero indices of a flattened 2D logical grid of size [𝐿 𝐵 , 𝑚 ].Because this flattening process strictly packs the 𝑚 sender heads for a single sequence position contiguous in memory before advancing to the next sequence position, a 1D compressed column

6 Implementation 

We implement the MapFlow inference server in 5K lines of code in Python, comprising three main modules: the sender, the receiver, and the cache server. We integrated our sender and re-ceiver modules into vLLM [33]. We wrote a fused retrieval kernel using Triton [62], supporting features including PagedAttention [33], Chunked Prefill [1] and Variable Length Sequences Packing. Currently we store the compressed attention map in GPU memory for fast retrieval due to the large size of attention maps and limited bandwidth of PCIe. In order to reduce interference when multiple processes access the shared GPU resources, we launch the NVIDIA MPS server [50] to create a unified CUDA context for all processes and only reserve a little fraction of GPU SMs for cache server to operate inside receiver’s GPU memory without interrupting the receiver’s main workflow. Inter-module tensor communication leverages CUDA Inter-Process Communication (IPC) [49], which allows tensors to be accessed across process boundaries by passing hardware memory handles over TCP connections, eliminating the need for explicit data copies through the CPU. A naive IPC approach would invoke cudaIpcOpenMemHandle for each tensor transfer, incurring significant overhead from repeated CUDA handle operations. To mitigate this, MapFlow pre-allocates a large, fixed-size memory buffer in GPU memory and registers it for IPC during server initialization. The buffer handle is shared once across processes via TCP. Subsequently, modules write tensors to pre-negotiated offsets within this buffer and signal availability through lightweight metadata messages. This design amortizes the cost of handle creation and avoids per-transfer CUDA API overhead. The cache server performs attention map reconstruction and compression entirely on the GPU. Since compression is applied once during the caching phase, the computational cost is independent of the number of receivers. This allows MapFlow to scale efficiently to serve multiple receiver instances without recomputing or recompressing the cached attention maps. Our current implementation follows prior works [22, 37, 86] on multi-model multiplexing serving that assume a co-located deployment to isolate the computational benefit of attention-map reuse, but the method itself does not require models to reside on the same GPU. 7 Experiments 7.1 Setup 

Models: We conduct our evaluation of MapFlow using two distinct model families: Qwen3 [54], Ministral3 [39]. To analyze performance across different scales, we select three model sizes and form two pairs for each family: Qwen3 (1.7B, 8B, and 14B), Ministral3 (3B, 8B, and 14B). 

Hardware Configuration: All experiments are conducted on virtual machines with 8 × NVIDIA A800 (80GB) GPUs. 

Datasets: We evaluate MapFlow on three diverse datasets (top-𝑝 = 0.7 by default), including HotpotQA [72] , LMSYS [83], ShareGPT4 [9], and Multi-News [15]. For each dataset, we utilize a split of approximately 10,000 examples for training and validation, and 1,000 examples for testing. Following conventions [3, 41, 73], we assess generation quality using task-specific metrics: F1 scores for Question-Answering tasks, and ROUGE-L for conversation and summarization tasks. 

Baselines: We compare MapFlow against state-of-the-art methods that also optimize the trade-off between generation quality and latency. Specifically, we select: 

• Full Prefill: The receiver model prefills the text of the context with vLLM [33], representing the highest computation overhead but the best quality. 

• KV Cache Reuse: We extend CacheBlend’s [73] algorithm to determine the fraction of tokens to recompute for cross model KV cache reuse based on the difference between the recomputed KV cache and sender model’s original KV cache. In addition, we adopt a reverse layer mapping strategy since now sender has more layers than receiver, which is different from CacheBlend’s setting. 

• Sparse Prefill: We also compare with FlexPrefill [34] and MInference [28] which reduce computation costs using sparse attention patterns instead of full attention. 

• Attention Map Reuse: We compare with IAM [82] and implement it ourselves since its repository is empty, following its suggested 50% layer-mapping setting. We did not compare with prior works with strong application constraints, like DroidSpeak using selective recomputation and necessitating embedding tensor transfers at transition layers, which is infeasible for heterogeneous model pairs with differing hidden dimensions (i.e., different shape of embedding tensors).

7.4 End-to-End Throughput Improvement on Multi-turn Conversation 

To see the impact of MapFlow on improving the throughput of an online LLM serving system with multi-model routing, we simulate the routing traces. Instead of deploying a specific learned router, we adopt the noise-injection methodology introduced in [10][25] to emulate prediction uncertainty. Specifically, we first evaluate the ground-truth scores of both the large and small models. We then inject zero-centered Gaussian noise into these true values to simulate the imperfect predictions of a practical router. Finally, we apply a threshold-based policy: the query is routed to the large model only if its noisy score exceeds that of the small model by a pre-defined threshold 𝜏 , thereby achieving a controllable trade-off between quality and cost. For each multi-turn conversation dataset trajectory, we carefully pair each single turn with request arrival times to simulate the real-world scenario of an online system. We then run our model with optimal top-𝑝 (which achieves the best performance with sufficient quality as a raw small model) and compare it with full prefill on routing. As shown in Figure 8, we compare the TTFT of the receiver model under various arrival rates on the LMSYS [83] and ShareGPT4 [9] dataset. MapFlow achieves lower P90 TTFT across all arrival rates, and achieves at most 25% higher throughput (QPS) under same P90 TTFT constraint across different model pairs.

7.8 Single-Workflow Latency for Three Models 

We evaluate MapFlow on a representative three-model agentic workflow [55, 65, 76], where a request is sequentially processed by Ministral3-14B, 8B, and 3B for planning, refinement, and summarization. Both receiver models reuse the attention map produced by the 14B sender. We group trajectories by context length and let each model decode a fixed number of tokens. The 14B model uses two-way tensor parallelism, while the 8B and 3B models are co-located on one GPU to directly share the block pool. As shown in Figure 11, MapFlow consistently reduces end-to-end latency, saving 0.48–0.73 seconds per round and achieving up to 5.4% speedup. This demonstrates that sender-side compression can be amortized across multiple downstream receivers. This experiment demonstrates that attention-map reuse provides a measurable end-to-end benefit in an agentic workflow, rather than representing the maximum acceleration achievable by MapFlow. Because MapFlow accelerates prefill but not decode, its workflow-level benefit is naturally bounded when decoding dominates the overall latency. It is therefore particularly suitable for TTFT-sensitive, routing-heavy, and long-context workflows, where repeated prefill constitutes a substantial fraction of execution time. For example, with a 20K-token context and 256 decoded tokens across the large, medium, and small models, prefilling the two downstream models accounts for approximately 23.4% of the end-to-end latency. MapFlow accelerates these prefill stages by approximately 1 .28 ×, resulting in the observed 5.4% end-to-end speedup. 

8 Related Work 

LLM-augmented Data Systems. Integrating Large Language Models (LLMs) into data manage-ment has shifted from basic natural language interfaces toward autonomous, agentic databases. Recent research explores LLM-driven database tuning and query optimization (e.g., 𝜆 -Tune [18], LL-MOpt [74], LLM-QO [60], LlamaTune [31], GENO [58]), where generative models replace heuristic planners to directly infer execution plans and synthesize configurations. Furthermore, frameworks increasingly leverage LLMs for complex data integration, cleaning, and entity resolution (e.g., Jelly-fish [77], PromptEM [66], Seed [8]). At the orchestration level, frameworks like BridgeScope [68] and ChatDB [24] securely modularize operations, enabling agents to execute ACID-compliant transactions without exposing raw data. Crucially, these LLM-augmented pipelines frequently process highly redundant prefixes—such as exhaustive database schemas, system constraints, and multi-turn instructions. Dispatching these shared contexts across heterogeneous models incurs pro-hibitive prefill computational costs, which directly motivate our approach for efficient cross-model state reuse mechanisms.

Multi-Model Serving and Management. To optimize the cost-latency-accuracy tradeoff in production environments, algorithms for multi-model serving frequently employ LLM routing and cascade inference (e.g., RouteLLM [51], CascadeLLM [29], and LLM-Blender [27]). At the system level, serving infrastructures have evolved across three paradigms. For identical model instances, high-throughput frameworks like vLLM [33] and SGLang [84] utilize prefix caching to minimize redundant prefill computation. Expanding beyond a single base model, multi-adapter serving architectures—such as Punica [6] and S-LoRA [56] enable the concurrent execution of thousands of fine-tuned task variants by sharing the base model’s weights. Furthermore, as application workflows increasingly demand entirely distinct architectures, multi-tenant heterogeneous frameworks like AlpaServe [37], MuxServe [86], and Llumnix [59] have been developed to spatially and temporally multiplex completely different models across shared GPU clusters. All these heterogeneous serving frameworks remain unoptimized for shared prefix prompts. 

KV Cache Management. Foundational research has tackled KV Cache memory fragmentation by adapting OS-level virtualization techniques: PagedAttention enables non-contiguous memory allocation, while frameworks like SGLang [84] and PromptCache [19] leverage Radix Trees to facilitate prefix-aware KV cache sharing among requests directed to the same model. Concurrently, to bound cache growth during long-context generation, a proliferation of cache compression and eviction algorithms (e.g., StreamingLLM [70], H2O [81], SnapKV [36], PQCache [78]) dynamically prune non-essential tokens by preserving only critical attention sinks or high-activation states. Despite these advancements, existing paradigms remain bound to rigid KV tensors, making them orthogonal to the attention-map-based design of MapFlow. 

9 Limitations and Future Work 

While MapFlow establishes attention maps as a practical reusable state for cross-model prefix caching, our current design choices prioritize structural compatibility and online serving efficiency. We briefly discuss their implications and promising directions for future work. 

Applicability beyond shared tokenization. MapFlow is currently most effective when the sender and receiver share the same tokenizer and process the same canonicalized input context. This assumption holds for many realistic multi-model deployments, especially within a model family. Taking the Llama 3 family as an example, Meta has officially released at least 15 publicly available text-model checkpoints across Llama 3, 3.1, 3.2, and 3.3 1 that share the same underlying tokenizer vocabulary, while HuggingFace hosts hundreds of additional community-developed vari-ants. There still remains many challenges to consider settings with mismatched tokenizers, prompt canonicalization pipelines, or more divergent architectures. Extending MapFlow to these broader scenarios will likely require additional alignment mechanisms, such as token-level correspondence recovery or intermediate semantic anchoring. Exploring such alignment strategies is an important direction for broadening the scope of cross-model attention reuse. 

Compact representations for reusable attention state. Our current system adopts block-level Top-𝑝 compression to make attention-map caching practical for long contexts. Although this design substantially reduces the cost of storing dense attention, reusable attention states can still occupy nontrivial memory under long-context, high-reuse workloads. This suggests an opportunity for richer compression schemes that preserve the transferability of attention structure while further reducing storage overhead. Examples include quantized sparse attention, low-rank or hybrid sparse–low-rank representations, and mechanisms that allow one sender-layer cache

10 Conclusion 

In this paper, we address the prefill latency bottleneck in multi-LLM systems caused by redundant prompt processing across heterogeneous models. We propose MapFlow, a novel heterogeneous LLM serving system that allows different LLMs to share semantic attention maps for prefix reuse. To enable efficient cross-model sharing, we utilize a lightweight linear adapter alongside a block-level Top-𝑝 sparse compression technique and a custom fused kernel to prevent memory bloat. Extensive evaluations demonstrate that MapFlow achieves a 15% to 20% reduction in Time-to-First-Token and up to a 25% increase in end-to-end throughput for multi-turn routing , all while maintaining generation quality. Ultimately, MapFlow provides a scalable, memory-efficient solution that significantly accelerates serving times for complex multi-model workflows.
