Abstract 

Temporal graph neural networks (TGNNs) achieve superior performance in many dynamic graph learning tasks. These models use node state vectors (i.e., memories) to capture and record graph changes (i.e., events), and then exploit these memories to assist prediction. However, this memory-centric design makes multi-GPU training challenging be-cause predictions for later events often depend on memory updates from earlier events. To maintain model quality, ex-isting multi-GPU TGNN training schemes strictly preserve all event dependencies, which limits parallelism and causes expensive cross-GPU memory synchronization. In this work, we observe that many of these dependencies can be handled more flexibly without harming training quality. Specifically, (a) dependencies in TGNN training have high locality in both time and graph topology, (b) the short-range dependencies missed within a large batch can often be recovered cheaply, and (c) many memory updates are not immediately needed. Based on these observations, we propose DepBloom to ac-celerate multi-GPU TGNN training with three techniques: (1) temporally bounded spatial partitioning to reduce unnec-essary cross-GPU synchronization and improve parallelism; (2) intra-batch memory refinement to recover missing short-range temporal dependencies inside enlarged batches; and

1 Introduction 

Dynamic graphs are widespread across various applications such as social networks [20], recommendation systems [38], traffic forecasting [24], and financial risk analysis [45]. Com-pared with static graphs, dynamic graphs involve changing nodes and edges, which makes representation learning sub-stantially more challenging [2, 17, 21, 32]. Temporal Graph Neural Networks (TGNNs) have emerged as an effective ap-proach for learning on dynamic graphs and have achieved state-of-the-art performance on a range of dynamic graph tasks [4, 8, 9, 19, 21, 27, 30, 32, 33, 35, 39, 42, 44, 46, 48, 50, 55]. TGNNs model a dynamic graph as a time-ordered sequence of events , where each event records a graph change, such as adding a node or an edge. A key feature of these mod-els is that each node maintains a time-evolving state vector,

often called node memory [7, 9, 10, 13, 26, 54], which is up-dated when relevant events occur around it. As dynamic graphs continue to grow in scale to billions or even trillions of events [22, 23, 54], efficient multi-GPU training of TGNNs is crucial for practical deployment. However, TGNN training is fundamentally bottlenecked by its unique memory update mechanism. Ideally, TGNNs follow a strict chronological execution order, updating node memories whenever they become relevant to an event [21, 33, 35, 42]. In TGNN training, however, events are grouped into batches , where each batch reads memories from earlier batches for computing and writes back updated memories for later batches [10, 21, 26, 32, 33, 35, 42, 54, 55]. As a re-sult, unlike conventional deep learning workloads, where batches are largely independent, TGNN batches are linked by strict cross-batch memory dependencies, leading to two major challenges in scaling multi-GPU TGNN training. First, temporal dependency forces a trade-off between par-allelism and training quality. Larger batches improve hardware utilization, but they delay memory updates and ignore dependencies among events within the same batch. Existing single-GPU TGNN systems, such as ETC and Cas-cade [10, 13], improve efficiency by enlarging batches along a chronological event stream while controlling information loss. However, simply enlarging batches remains insufficient to expose scalable parallelism across GPUs, while the re-sulting irregular workloads can further cause load imbal-ance and pipeline bubbles in multi-GPU execution. Second, multi-GPU scalability is limited by expensive cross-GPU memory synchronization. Existing systems [7, 26] either synchronize updated memory states across GPUs at the end of each batch or ignore such synchronization al-together. As a result, they either incur substantial commu-nication overhead and prolonged pipeline stalls, or suffer noticeable training-quality degradation. Table 1 summarizes how representative prior methods, together with our design, address these two core challenges. As the table shows, prior methods partially improve one challenge or the other, but remain insufficient for scalable multi-GPU TGNN training. Nevertheless, we find that many dependencies can be handled more flexibly without harming training quality. In particular, we make three observations: First, dependen-cies in TGNN training are often local in both time and graph topology . This locality is hard to utilize with only one-dimensional partitioning. Temporal-only partitioning breaks topological dependencies while spatial-only partition-ing degrades training quality over long horizons. Second, the short-range temporal dependencies missed inside a large batch can often be recovered cheaply . Specifically, stale node memories in a large batch can be recovered based on earlier events within the same batch, enabling higher par-allelism while maintaining training quality. Third, memory updates are not equally urgent for subsequent compu-tation . Only a small subset of updated node memories is immediately required by the next dependent batch. There-fore, uniformly synchronizing all updates places unneces-sary work on the critical path and prolongs execution stalls. Together, these observations suggest that scalable TGNN training could preserve only critical dependencies while re-laxing or restructuring the rest to improve parallelism and reduce synchronization. Based on these insights, we propose DepBloom, an ef-ficient framework for scalable multi-GPU TGNN training with three key techniques. First, temporally bounded spatial partitioning divides the event stream into serial temporal windows and organizes each window into topology-aware parallel sub-chains, reducing unnecessary cross-GPU syn-chronization among sub-chains while preserving critical de-pendencies among windows. Second, intra-batch memory re-finement recovers missing short-range temporal information inside enlarged batches, enabling higher parallelism without sacrificing training quality. Third, critical-path optimization for multi-GPU pipeline execution prioritizes urgent memory updates and removes non-critical updates and operations from the critical path, thereby improving pipeline execu-tion efficiency and enhancing system scalability. Experimen-tal results across diverse benchmarks show that DepBloom achieves an average speedup of 2.84 × and up to 5.16 × over baselines, while maintaining comparable or better model quality. We summarize our contributions as follows: 

• We identify the excessive preservation of event dependen-cies in existing multi-GPU TGNN training frameworks as a major limitation of parallelism and scalability, and recognize the potential of handling these dependencies more flexibly without harming training quality. 

• We propose DepBloom, a multi-GPU TGNN training frame-work that combines temporally bounded spatial partition-ing, intra-batch memory refinement, and critical-path op-timization to increase parallelism and reduce cross-GPU synchronization costs. 

• We evaluate DepBloom on representative TGNN models and dynamic graph datasets, and show that it substan-tially outperforms prior multi-GPU TGNN training sys-tems while maintaining comparable or better accuracy.

2.1 Temporal GNN Learning on Dynamic Graphs Dynamic Graphs . Dynamic graphs model systems whose nodes and edges evolve over time. They are commonly rep-resented as either discrete-time dynamic graphs (DTDGs), modeled as a sequence of graph snapshots, or continuous-time dynamic graphs (CTDGs), modeled as a chronologically ordered stream of timestamped events. DTDGs can often be viewed as a coarser discretization of CTDG event streams, where events are grouped into time windows to form snap-shots [9, 10, 54]. Recent work [1, 7, 10, 15, 26, 32, 52, 54] increasingly favors CTDGs because they preserve exact in-teraction timing and better capture fine-grained temporal dynamics. 2.2 Multi-GPU Training for TGNNs 

To enable multi-GPU TGNN training, prior work has ex-plored four representative paradigms [26, 55], as shown in Figure 2. Batch parallelism [53–55] executes adjacent batches concurrently on different GPUs, which improves throughput but causes stale memories by weakening inter-batch dependencies. Epoch parallelism [55] overlaps dif-ferent training epochs across GPUs, but later epochs may process the same samples before earlier model updates are fully incorporated. Memory parallelism [55] reduces syn-chronization by keeping multiple copies of node memory across GPUs, but this increases memory overhead and dis-rupts memory evolution across the entire training event stream. These three paradigms improve hardware utilization by relaxing the original dependency order of TGNN training. In contrast, pipeline parallelism [26] preserves depen-dency order while still exposing concurrency. It decomposes each batch into dependent stages, such as node memory up-date and node embedding, and overlaps different batches across GPUs. Once one batch finishes its memory update, the next GPU can start the following batch, while the current GPU continues the later stages of the current batch. Because it improves concurrency without violating the original up-date order, pipeline parallelism is the most suitable paradigm for TGNN training [26], and we focus on it in this work.

3 Motivation and Opportunity 

3.1 Bottlenecks in Multi-GPU TGNN Training 

Although recent pipeline-based systems can preserve tem-poral dependencies [26], they still scale poorly. To quantify this limitation, we profile PipeTGL [26], a state-of-the-art multi-GPU TGNN training system, on WIKI-TALK [22] us-ing 2 to 8 NVIDIA RTX 4090 GPUs. As shown in Figure 3, adding more GPUs does not consistently reduce end-to-end latency. Although total latency decreases from 2 to 6 GPUs, the scaling quickly saturates, and 8 GPUs even underperform 6 GPUs. Challenge 2: Multi-GPU scalability is limited by ex-pensive cross-GPU memory synchronization. The sec-ond challenge is that cross-GPU memory synchronization is both expensive and increasingly inefficient at scale. In multi-GPU TGNN training, a batch cannot proceed until the required memory update has been produced by the previous GPU and transferred to the current one. As a result, each synchronization point incurs not only waiting time but also explicit communication overhead. As the number of GPUs increases, this overhead becomes harder to hide and increas-ingly dominates execution. This effect is clearly reflected in Figure 3. Although the computation stages continue to shrink as more GPUs are added, the synchronization latency rises from 4.70 s on 2 GPUs to 13.85 s on 8 GPUs, and be-comes 2.92 × higher than that on 4 GPUs. Meanwhile, its share of total runtime increases sharply from 12.3% to 53.1%. These results show that cross-GPU memory synchronization becomes a dominant bottleneck as the system scales.

In summary, multi-GPU TGNN training scales poorly be-cause (1) execution on each GPU repeatedly stalls due to memory updates across small batches, and (2) those stalls are too expensive to be effectively hidden by pipelining. This naturally raises the following question: can we reduce (i) the frequency of memory updates and (ii) the cost of each memory synchronization without hurting training quality? 

3.2 Rethinking Dependencies in Multi-GPU TGNN Training 

By revisiting dependency handling in TGNN training, we find that current execution strategies are often overly con-servative, leaving substantial room to improve parallelism and reduce overhead. Specifically, we make three key obser-vations that motivate our design. Our first observation is that dependencies in TGNN training are often local in both time and graph topology, so effective partitioning must jointly consider both. Partitioning is a nat-ural way to reduce cross-GPU communication [12, 36, 47]: If a training sequence can be decomposed into multiple largely independent units, which we call sub-chains , these units can execute in parallel. This preserves sequential dependencies within each sub-chain while reducing synchronization across sub-chains. Limits of temporal partitioning. Existing approaches, such as memory parallelism [55], partition the input sequence only along the temporal dimension and ignore graph topol-ogy. As a result, strongly coupled events, which share the same source nodes, are often assigned to different sub-chains, which breaks dependencies across sub-chains. To quantify this effect, we apply (i) sequential partitioning by dividing events chronologically [55] and (ii) topology-aware parti-tioning using a minimum-cut solver [18] on the first 150,000 events on REDDIT and 300,000 events on WIKI_TALK , and then measure the fraction of dependencies broken across sub-chains. Limits of spatial partitioning. Directly applying spatial partitioning to the full dynamic graph, as is often done for static GNNs [3, 7, 51], is too aggressive for TGNN training because it ignores temporal locality and allows omitted cross-chain dependencies to accumulate over long horizons. To evaluate this effect, we use the same setup as in Figure 5(a), vary the temporal window length before partitioning, and train TGN [32] on the resulting partitioned graphs. As shown in Figure 5(b), when we directly partition the whole graph, the cross-chain event ratio increases from 5.98% to 11.19% ,and training loss rises by 70.7% . 4.1 Overview 

Based on the above observations, we propose DepBloom, an efficient framework for multi-GPU TGNN training. Dep-Bloom integrates three complementary techniques to im-prove scalability and efficiency. As illustrated in Figure 8, DepBloom improves multi-GPU TGNN training from top to bottom. First, Temporally Bounded Spatial Partition-ing divides the training event sequence into serial temporal windows and further partitions each window into topology-aware sub-chains, exposing parallelism while minimizing cross-chain synchronization. Next, Intra-Batch Memory Refinement enables efficient large-batch execution within each sub-chain by compensating for missing short-range temporal dependencies caused by stale updates, thereby in-creasing parallelism without sacrificing training quality. Fi-nally, Critical-Path Optimization for Multi-GPU Pipeline Execution prioritizes urgent memory updates and removes deferrable operations from the critical path, thereby reducing synchronization cost and shortening execution stalls. 4.3 Intra-batch Memory Refinement 

Motivated by Observation 2 , we propose Intra-Batch Mem-ory Refinement , as illustrated in Figure 10(c). Compared with small-batch execution in Figure 10(a), which preserves fre-quent memory updates but incurs frequent synchronization and pipeline stalls, and large-batch execution in Figure 10(b), which improves efficiency but uses overly stale node mem-ories, our design combines the strengths of both. It retains the efficiency of large-batch execution while keeping node memories nearly as fresh as if the batch had been processed as several small batches with intermediate memory updates. 

Micro-batch Split. Instead of treating a large batch as an indivisible unit, we divide it into an ordered sequence of micro-batches, 𝐵 𝑡 = {M 1, M2, . . . , M𝐾 }, where each micro-batch M𝑘 contains the same number of events as the original small-batch baseline, and the micro-batches remain ordered by event timestamp. In this way, the large batch retains the temporal structure of several small batches, while still preserving the lower synchronization frequency of large-batch execution. 

Parallel Memory Refinement. To avoid sequential up-dates between micro-batches, which cause frequent stalls and synchronizations, we allow micro-batches to execute in parallel and use a lightweight refinement module to ap-proximate the effect of the omitted intermediate updates. Specifically, when processing micro-batch M𝑖 , we first apply the standard memory update using the available but stale node memories at the beginning of the large batch, and then refine that memory using the most recent events from preced-ing micro-batches M1, . . . , M𝑖 −1. Priority-aware memory-update decoupling. Recalling 

Observation 3 , only a small subset of memory updates is immediately required by the next dependent batch, while many others are consumed later or not revisited in the near term. To avoid unnecessary waiting cost, we split the updates produced by each batch into two groups: urgent updates and 

non-urgent updates. Then we handle their execution differ-ently, as illustrated in Figure 11: Urgent updates are those immediately needed by the next dependent batch, so they are updated and transferred first via GPU–GPU communication (e.g., NVLink). This allows the downstream GPU to resume execution as soon as the required memory state becomes available. In contrast, non-urgent updates are removed from the critical path. They are handled separately without block-ing the execution of the next batch on remote GPUs, and the resulting memory will first be written back to the CPU and then loaded onto remote GPUs on demand. This design preserves correctness for dependency-critical updates while significantly reducing the amount of communication that lies on the critical path. 

Critical-path precomputation and overlap. Beyond memory transfer itself, multi-GPU TGNN execution also incurs repeated overhead in preparing memory accesses. Specifically, before a batch can fetch the required node mem-ories, the system often performs preprocessing steps such as node-index deduplication, sorting, remapping, request construction, and buffer packing [55], because the required memories may reside in different locations, such as CPU memory or GPU memory on different devices. Although each step is lightweight in isolation, repeatedly performing them on the critical path adds noticeable delay and further prolongs pipeline stalls. However, much of this preprocessing depends only on information that is already known before execution begins. In particular, once the event sequence, neighbor sampling results, and partition assignments are determined, the set of accessed nodes and the corresponding memory-access patterns are also fixed. This means that many metadata struc-tures, such as accessed-node lists, index remapping tables, communication offsets, and data movement plans, can be pre-pared in advance rather than rebuilt repeatedly at runtime and stalled by node memory synchronizations. Therefore, we move this preprocessing work off the criti-cal path by precomputing it before receiving updated node memories from the previous batch, hiding its overhead be-hind the memory-update critical path. Specifically, while a GPU waits for updated memory from the previous batch or fetches the node features needed by the current batch, DepBloom concurrently prepares the metadata needed for fu-ture batches. In our implementation, we also explore Python 3.13’s free-threading mode to implement such thread-level parallelism more easily, allowing I/O data preparation to run concurrently with latency-sensitive training stages.

5.6 Overhead Analysis 

DepBloom introduces two additional overhead sources: pre-processing for temporally bounded spatial partitioning and computation for intra-batch memory refinement. As shown in Figure 18, these overheads take only a small fraction of to-tal training time across all evaluated datasets and models. On average, preprocessing accounts for 0.61% of DepBloom’s end-to-end training time, while memory refinement accounts for 3.78% ; the remaining 95.61% is spent on normal training execution. Compared with the baseline training time, the added preprocessing and refinement costs are smaller, ac-counting for only 0.19% and 1.42% on average, respectively. The low preprocessing overhead arises because temporal window construction and topology-aware spatial partition-ing run before training and are reused during execution. Re-finement overhead is slightly higher because it runs during training. However, refinement enables larger batches while preserving short-range temporal information, amortizing its cost through higher parallelism and fewer synchronizations. 0%

6 Related Work 

Although prior systems accelerate GNN training [7, 28, 43, 47], they do not directly address multi-GPU TGNN training, whose core challenge comes from temporal dependencies across events. Earlier dynamic-graph studies largely focused on discrete-time dynamic graphs (DTDGs), which model graph evolution as snapshots [5, 6, 11, 14, 34, 40]. More re-cent TGNNs increasingly adopt continuous-time dynamic graphs (CTDGs), which model graph evolution as chrono-logically ordered event streams and thereby better preserve fine-grained temporal dynamics, but this also introduces event-level training dependencies that make snapshot-based DTDG optimizations difficult to transfer directly [10, 13, 21, 26, 32, 39, 42, 46, 54, 55]. Prior CTDG-focused work improves training efficiency through both algorithmic and systems-level techniques [10, 13, 37, 54]. TGL [54] provides a general framework for CTDG training, while ETC [13] improves efficiency through dy-namic batching and Cascade [10] enlarges batches by ex-ploiting spatial and temporal independence. PRISM [16] mit-igates intra-batch memory staleness through multi-version memory and refinement. Other studies further reduce over-heads by optimizing memory access, data movement, and runtime execution [13, 25, 37, 49]. These methods are de-signed mainly for single-GPU execution. When extended to multi-GPU training, they do not address how batches should be organized across GPUs to expose parallelism, often leading to workload imbalance and low GPU utilization. In multi-GPU and distributed settings, GNNFlow [53] improves graph storage and data movement, while DistTGL [55] and PipeTGL [26] optimize parallel execution over a fixed chrono-logical batch sequence. Nevertheless, these methods either preserve event dependencies too conservatively or relax them too aggressively, and still struggle to jointly optimize training efficiency and model quality. 

7 Conclusion 

We present DepBloom, a scalable multi-GPU framework for TGNN training. Instead of synchronizing all dependen-cies across small batches, DepBloom combines temporally bounded spatial partitioning, intra-batch memory refine-ment, and critical-path optimization to reduce unnecessary synchronization, recover missing short-range temporal infor-mation, and shorten memory-synchronization stalls. Across representative TGNN models and dynamic graph datasets, DepBloom achieves 2.84 × average speedup and up to 5.16 ×

speedup over state-of-the-art baselines while maintaining comparable or better model quality.
