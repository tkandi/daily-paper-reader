## 摘要
现代向量搜索系统将载荷向量保存在云对象存储中，仅将紧凑的路由索引置于高速本地存储上，通常采用基于聚类的近似最近邻（ANN）索引。该设计沿袭了一个现有系统尚未解决的问题：在对象存储上，小型 Range-GET 请求的延迟主要由每次请求的固定开销决定，且按请求次数计费。现有读取器要么对每个被探测的簇发起一次请求，要么使用人工调优的间隙或跨度阈值合并相邻范围；这些阈值无法迁移到不同的数据集或查询工作负载。我们将把被探测簇的字节区间分组成对象存储请求的问题，形式化为一个全局的逐查询优化问题，并提出 WaRP——一种能够高效求解该问题的工作负载感知请求规划器。给定已排序的字节区间、每个查询的请求数量上限，以及在目标服务配置下单个查询可并发执行的对象存储请求数估计，WaRP 搜索一种合并方案，在满足请求数量限制的同时，最小化一种考虑并发性的延迟代理目标。借助优化的动态规划和自适应前沿搜索，WaRP 返回的方案与最优解的差距在 $(1{+}ε)$ 倍以内；即使在测试中要求最高的设置下，其逐查询规划开销也低于 $10$ ms。一个轻量级的离线重排序步骤可在不改变 ANN 搜索语义的前提下，进一步提升请求的可合并性。我们在 Lance 的 I/O 调度器中实现了 WaRP，并在 AWS S3 上进行了评估。我们在七个数据集上构建了 IVFPQ 索引，其中包括百万向量规模达到 1 亿的 SIFT100M 和 DEEP100M。相较于 Lance，在保持其召回率不变的情况下，WaRP + Reorder 将 QPS 提升了 $1.09--3.48\times$，并将 GET 请求数量减少了 $2.12--5.19\times$。

## Abstract
Modern vector search systems keep payload vectors in cloud object storage and only a compact routing index on fast local storage, typically using cluster-based ANN indexes. This design inherits a problem existing systems do not address. On object storage, small Range-GETs have latency dominated by fixed per-request overhead and are billed per request. Existing readers either issue one request per probed cluster, or coalesce adjacent ranges with hand-tuned gap or span thresholds that do not transfer across datasets or query workloads.   We formulate the grouping of probed-cluster byte intervals into object-store requests as a global per-query optimization problem and present WaRP, a workload-aware request planner that solves it efficiently. Given the sorted byte intervals, a limit on the number of requests per query, and an estimate of how many object-store requests from one query can proceed concurrently under the target serving configuration, WaRP searches for a merge plan that minimizes a concurrency-aware latency surrogate while satisfying the request limit. Using an optimized dynamic program and adaptive frontier search, WaRP returns a plan within $(1{+}ε)$ of the optimum, with per-query planning overhead under $10$ms even in the most demanding tested settings. A lightweight offline reordering pass further improves request mergeability without changing the semantics of ANN search.   We implement WaRP inside Lance's I/O scheduler and evaluate it on AWS S3. We build IVFPQ indexes on seven datasets, including SIFT100M and DEEP100M at the 100M-vector scale. WaRP + Reorder improves QPS by $1.09--3.48\times$ and reduces GETs by $2.12--5.19\times$ relative to Lance, while preserving Lance's recall.
