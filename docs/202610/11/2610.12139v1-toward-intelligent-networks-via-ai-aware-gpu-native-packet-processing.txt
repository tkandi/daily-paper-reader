## ABSTRACT 

The integration of inline Artificial Intelligence (AI) models into critical network infrastructure is fundamentally bottlenecked by the high latency and synchronization overhead of CPU-mediated packet processing. While legacy GPU offload and recent CPU-bypass frameworks attempt to bridge this gap, they remain trapped in proprietary ecosystems or still rely on the host CPU and coarse-grained batching to coordinate stateful telemetry and AI pipeline execution. In this paper, we propose AGP, a novel framework that promotes the GPU from a passive accelerator to a primary data-path controller, answering what changes architecturally when the GPU autonomously owns the complete packet-to-inference pipeline. By enabling GPU-native packet processing, contention-free in-GPU stateful aggregation, and a persistent mega-kernel for continuous AI inference, AGP removes the CPU from the critical path. Our eval-uation demonstrates that native in-GPU packet processing sustains line-rate throughput while being over 6 .1× more power-efficient. Furthermore, our integrated Intrusion Detection System (IDS) stress test eliminates the legacy CPU-GPU synchronization tax, reducing end-to-end latency by 7 .9× (up to 35 × p99) and accelerating whole-system inference throughput by 9 .3× using only ∼2% of the GPU’s thread capacity.

## 1 INTRODUCTION 

Despite rapid integration of inline Artificial Intelligence (AI) into critical network infrastructure for applications such as teleme-try [15, 16, 35, 40], infrastructure provisioning [4, 39], and intrusion detection systems [19, 25, 26], the deployment of these systems re-mains constrained by a legacy architectural paradigm: treating the GPU strictly as a passive, host-dependent coprocessor. Over the past two decades, both classic GPU packet-processing frameworks [11, 14, 17, 18, 37] and modern AI-integrated network systems have treated packet processing and GPU execution as two isolated pipelines [8, 9, 19, 25]. Whether packets are polled by kernel-bypass drivers [36] or filtered by in-kernel fast paths [12 ? ], data and control still traverse a slow, host-mediated bridge: features are collected in the data plane, coordinated by CPUs, and pushed across PCIe in batches to amortize launch overheads. This twisted path introduces prohibitive latency, power overhead, and poor performance. To address the inefficiency of this CPU-mediated bridge, the networking community has recently embraced CPU-bypass frame-works. Technologies such as GPUDirect RDMA [27] and NVIDIA GPUNetIO [31] allow the Network Interface Card (NIC) to write directly to GPU memory and offload basic queue interactions. How-ever, we argue that these I/O-layer optimizations create an illusion 

of GPU autonomy: they stop at packet delivery and leave state management and inference scheduling on the host. Closing this gap within the GPU exposes three technical chal-lenges that prior work leaves open. (C1) Owning NIC queues on an open stack. DPDK poll-mode drivers [36] assume queues reside in host memory, and legacy GPU frameworks [11, 17] inherit this model by polling from the CPU. While DPDK’s gpudev library [7] places packet payloads in GPU memory, the CPU still polls the queues and relays packet addresses to the GPU through a commu-nication list. GPUNetIO [31] moves packet reception onto the GPU, but only through a closed stack tied to recent NICs [29, 30], so the queue layout cannot be co-designed with the state and inference stages that follow. (C2) Updating shared telemetry state under SIMT. Prior GPU packet processors are stateless per batch [11, 17], while stateful telemetry is typically maintained on CPUs or switch ASICs [19, 26], so features must be copied and reshaped into tensors before inference. However, moving this state onto the GPU intro-duces a new challenge: traffic bursts make many threads within a warp update the same flow, forcing their atomic operations to serialize, and heterogeneous headers cause threads to diverge dur-ing parsing. (C3) Triggering inference without the host. While CUDA Graphs [10] and recent mega-kernels [6] reduce launch overhead, they still rely on the host to launch batches or dispatch requests. Together, these limitations raise a fundamental architec-tural question: what changes when the GPU is promoted from a passive I/O target to the autonomous owner of the entire network data path, and what new capabilities does this unlock? 

To answer this question, we argue for a fundamental shift in how accelerators are deployed: to unlock low-latency, AI-driven networking, the GPU must transition from a host-dependent copro-cessor into an autonomous execution domain. We therefore propose an AI-aware GPU-native Packet processing framework (AGP) ,which elevates the GPU into a fully autonomous network endpoint for inline AI inference. Specifically, instead of relying on a host CPU or proprietary NIC firmware, AGP enables CUDA cores to autonomously manage low-level Work/Completion Queue Entries arXiv:2610.12139v1 [cs.NI] 8 Oct 2026 (WQEs/CQEs) in VRAM by extending the open DPDK stack [36]. To bridge the gap between raw byte streams and AI tensors, AGP extracts and aggregates features in place as packets arrive, pro-ducing GPU-resident tensors that inference consumes without an intermediate copy. Moreover, packet I/O, feature extraction, and multi-layer model inference are fused into a persistent mega-kernel with device-side manager-worker scheduling, eliminating host ker-nel launches and batch-wait delays. We developed an AGP prototype that implements a state-of-the-art Intrusion Detection System (IDS) [19] as a demanding end-to-end stress test requiring line-rate ingestion, high-concurrency state updates, and continuous AI inference. Our benchmarks re-veal that autonomous in-GPU packet processing delivers line-rate performance comparable to 16 dedicated polling cores, while be-ing over 6.1 × more power-efficient. Furthermore, we achieve 9.3 ×

higher inference throughput than CPU-bypass frameworks using only ∼2% of the GPU’s thread capacity. These results answer our opening question. When the GPU owns the data path, (i) the unit of scheduling shrinks from a host-launched batch to a single tensor event, removing batch-wait latency; (ii) state lives where inference runs, removing the byte-to-tensor copy; and (iii) the CPU leaves the fast path entirely, freeing all host cores. This GPU efficiency as a network endpoint therefore unlocks new opportunities: 1) multi-tenant GPU service offloading and 2) a unified compiler for co-located network functions. We summarize the key contributions of this work as follows: 

• Open GPU-Resident NIC Queues: We extend open DPDK to place NIC rings in VRAM and poll them from a persistent CUDA kernel, following the GPUNetIO model but without its proprietary stack or NIC-generation limits. 

• Eliminating the Byte-to-Tensor Transformation Over-head: AGP embeds hardware-aligned stateful structures (e.g., probabilistic sketches) into the ingestion path, updated in place via warp-cooperative register reductions to avoid global atomic serialization. 

• Device-Side Mega-Kernel AI Scheduling: We replace host-driven, batched multi-kernel launches with a persistent mega-kernel and on-device manager-worker queues, trigger-ing inference continuously in on-chip memory as individual tensors mature, eliminating CPU-GPU synchronization. 

• End-to-End Validation and Co-Location Headroom: We validate the AGP prototype on a 100 Gbps testbed and a state-ful IDS stress test, demonstrating GPU data-path ownership frees all host CPU cores and over 70% of GPU SMs for co-located applications.

Limitations of Host-Orchestrated Architecture. Historically, both software data planes and early GPU packet-processing frame-works rely on CPU orchestration. In software data planes (e.g., DPDK [8, 9, 22, 25, 36]), the CPU constantly polls the NIC Work/-Completion Queue Entries (WQEs/CQEs), parses packet headers, and batches data for the GPU. Pioneering GPU packet-processing systems [11, 14, 17, 18, 37] offloaded compute-heavy tasks to the GPU, but still relied on the host CPU to poll the NIC and accumu-late massive packet batches in host DRAM before copying them across PCIe. Even with programmable switches [2, 3] where ASICs aggregate telemetry at line rate, the CPU must still retrieve, nor-malize, and push features across PCIe [19, 26, 33]. Across all these paradigms, the CPU bears the burden of preparing the data and scheduling the AI inference via standard frameworks (e.g., Tensor-Flow, PyTorch). This host-driven scheduling introduces a severe synchronization cost, as standard deep learning frameworks oper-ate by launching a sequence of dozens of discrete micro-kernels (e.g., convolution, ReLU, pooling) with a context-switching overhead of 5 to 10 microseconds per-kernel [5, 20]. This repeated movement of control and data across the PCIe bus introduces high latency that can quickly dominate the end-to-end inference pipeline. Addition-ally, the recent persistent mega-kernels (e.g., Mirage [6]) that fuse model layers on the GPU still rely on the host CPU to feed requests and lack native network I/O support. 

Limitations of Proprietary CPU-Bypass Frameworks. To miti-gate host-coordination overhead, the industry has shifted toward CPU-bypass frameworks (e.g., DOCA [32], GPUNetIO [31]) and SmartNIC [28] architectures. While these technologies successfully allow the NIC to write packets directly to GPU memory and offload tasks like doorbell ringing, they stop at the raw I/O boundary and leave three fundamental deployment gaps. First, the data delivery path operates as a closed, proprietary black box, restricted to the newest hardware generations (e.g., ConnectX-7 [29] and newer [30]) and completely precluding deep architectural customization across diverse NICs. Second, despite bypassing the CPU for raw packet delivery, the end-to-end AI pipeline remains bound to host orches-tration. Once data arrives in GPU memory, the CPU must still wake up to manage stateless buffers, track stateful telemetry, and ex-plicitly launch the subsequent CUDA kernels for inference. This host-device coupling reintroduces the exact scheduling and batch-wait latency that direct I/O was intended to eliminate. Third, these frameworks fail to bridge the semantic and microarchitectural mis-match between network traffic and AI execution, leaving data in VRAM as raw, asynchronous byte streams. ## 3 THE AGP DESIGN: A UNIFIED VISION 

To address the persistent CPU bottleneck of AI-integrated packet processing, AGP packages a closed-loop GPU execution environ-ment into a reusable framework that owns the entire fast path. 

## 3.1 Overview 

Figure 1 illustrates the end-to-end execution flow of AGP’s bifur-cated control-data plane architecture. AGP isolates all line-rate data processing within the GPU while restricting the CPU to asynchro-nous supervision off the critical path. During initialization, the CPU negotiates direct NIC-to-GPU memory access, allocates DMA rings (WQE/CQE) in GPU VRAM, and launches the persistent CUDA kernel driving the data plane. Thereafter, the CPU merely monitors system health, can hot-swap model weights into VRAM without stalling the pipeline, and enforces slow-path policy updates (e.g., routing or logging) upon receiving asynchronous control signals from the GPU. The GPU, on the other hand, functions as an autonomous, closed-loop execution environment. Within the CUDA cores, a persis-tent I/O management stage continuously polls the DMA rings, directly ingesting packets and refreshing completion entries for the NIC. This raw byte stream is immediately passed to line-rate pars-ing, where parsing stages extract network telemetry and update hardware-accelerated stateful structures to maintain a live repre-sentation of traffic behavior. As flow features mature, dedicated CUDA warps normalize and reshape the data into multidimensional tensors. Rather than relying on a host-side AI framework, execution is managed by a persistent mega-kernel. This kernel autonomously orchestrates the deep learning pipeline, synchronizing data hand-offs and managing the underlying hardware resources. Specifically, it can dispatch the heavy, mixed-precision matrix multiplications (GEMM) [23, 24] to the Tensor Cores for AI inference, while also leveraging them to execute tensor-mapped payload inspection (DPI) for complex pattern matching. By keeping the entire workflow from raw packet reception to final inference bound within device mem-ory, AGP enables line-rate, stateful inline AI inference with zero host scheduling. 

## 3.2 Handing NIC Control to GPU 

True autonomy requires decoupling the control path from the CPU. DPDK’s Poll Mode Driver dedicates a full core to each polled queue, so line-rate deployments often consume dozens of cores for I/O alone, making telemetry aggregation, preprocessing, and AI orches-tration on this host-centric control plane prohibitively resource-intensive. 

GPU-Native I/O Management (WQEs/CQEs). While the vendor-specific GPU networking frameworks (e.g., DOCA GPUNetIO) par-tially move network control onto the GPU, they remain propri-etary and are maintained for specific hardware generations (e.g., ConnectX-7 [29] and beyond), limiting extensibility and making it difficult to build systems. Upstream DPDK, to the best of our knowl-edge, stops at GPU-resident payloads [7]. AGP removes both limits by placing the rings themselves in VRAM using standard DPDK abstractions. Instead of placing NIC receive and transmit queues in host memory, AGP allocates these queues directly in GPU VRAM. During initialization, the host allocates queue memory in VRAM and establishes DMA mappings via I/O Virtual Addresses (IOVAs), allowing the NIC to issue transactions directly to GPU queues. Once mapped, the CPU is completely removed from the critical packet-processing path. Incoming descriptors and packet payloads are subsequently transferred directly into VRAM through PCIe peer-to-peer (P2P) DMA using the registered IOVA mappings. The persistent CUDA kernel then monitors queue state locally within GPU memory, enabling packet reception, queue management, and scheduling decisions to proceed without CPU intervention. 

Enforcing DMA Memory Visibility. Unlike host memory, GPU memory lacks the cache-coherence assumptions of DPDK designs, which can lead to race conditions in which kernels observe queue updates before packet data becomes visible. AGP resolves this with cache-aware polling and device-wide synchronization: a polling thread accepts a CQE only after re-reading its ownership field following __threadfence_system() , and advances the consumer index only once the payload is observed, ensuring DMA updates are globally visible before processing begins. 

Two Polling Modes for Line-rate Ingestion. With memory con-sistency enforced across device queues and DMA visibility, AGP exposes two execution modes for different semantic workloads. In the flow-level mode, AGP leverages the NIC’s Receive Side Scaling (RSS) to distribute incoming traffic across multiple receive queues in VRAM. Then, each GPU warp is assigned to a specific queue, enabling massively parallel polling without contention. This ex-ecution model is particularly well-suited for workloads such as flow-level telemetry, traffic classification, and stateful feature ex-traction, allowing throughput to scale with the number of available GPU warps and streaming multiprocessors. In the sequence-level mode, AGP handles workloads that require strict packet ordering or operate on a single logical stream. All packets arrive in a shared VRAM-resident ring buffer in NIC arrival order, and multiple warps cooperatively claim descriptors via light-weight atomic operations that preserve this order. Downstream kernels thus operate on temporally consistent streams, allowing sequence-dependent tasks such as inter-arrival time analysis, pro-tocol state tracking, and AI inference over packet sequences to run without additional reordering or buffering. ## 3.3 GPU-Native Stateful Telemetry 

Once packets are ingested into VRAM, AGP bridges the semantic gap between unstructured network byte streams and the rigidly formatted multidimensional tensors required for AI inference. Repli-cating the CPU’s branch-intensive parsing and flow tracking on a parallel accelerator introduces severe microarchitectural friction: protocol parsing induces warp divergence, while concurrent state updates cause atomic contention. AGP therefore bifurcates teleme-try construction by workload semantics, ensuring feature extrac-tion uses strictly warp-aligned, divergence-minimizing memory operations. 

Stateless Packet-Level Parsing. For workloads without histor-ical context (e.g., payload signature matching [38] or per-packet classification [13]), each packet is processed independently. In this execution path, threads within a warp perform inline feature ex-traction and feed the AI mega-kernel directly. Because there is no shared state across packets, this pipeline operates entirely lock-free, avoiding synchronization overhead and maximizing raw packet-processing throughput. 

Stateful Flow-Level Aggregation. In contrast, flow-level teleme-try requires shared state (e.g., connection counters, inter-arrival times, or sketch-based statistics). Because network traffic arrives in bursts, multiple threads within a warp frequently attempt to update overlapping flow identifiers simultaneously. Naively issuing global atomic operations (e.g., atomicAdd ) to update shared hash tables leads to severe memory serialization. AGP eliminates this con-tention through a two-tiered, GPU-native memory hierarchy. First, inter-ring contention is eliminated via Receive Side Scaling (RSS), which deterministically hashes all packets of a given flow to the same VRAM receive ring. Second, intra-ring contention is resolved by replacing global atomic updates with warp-cooperative reduc-tions. Using hardware shuffle primitives (e.g., __shfl_down_sync() ), threads aggregate per-flow statistics locally in high-speed registers before committing a single, coalesced update to memory. 

Optimized Device Memory Layout. To minimize atomic pres-sure, AGP replaces pointer-heavy CPU data structures (e.g., linked lists) with flat, contiguous GPU arrays for all ring-local state. This ensures writes to global memory are coalesced, maximizing VRAM bandwidth utilization. 

## 3.4 The Autonomous AI Model Inference 

True data-path autonomy requires executing stateful downstream compute, such as multi-layer neural inference, directly on the GPU without host scheduling. In conventional frameworks (e.g., Tensor-Flow, PyTorch), decomposing models into dozens of CPU-launched micro-kernels introduces severe per-kernel synchronization over-head. Recent work [6] mitigates this with persistent mega-kernels for Large Language Model (LLM) inference, but the approach does not transfer directly to the network environment. First, in LLM serving, the CPU still feeds requests and collects out-puts, whereas in-network processing already lives entirely within the GPU; the challenge is thus integrating inference into a high-throughput packet pipeline without additional memory movement or synchronization. Second, existing mega-kernel designs are spe-cialized for transformers and do not extend naturally to the light-weight convolutional models common in networking tasks. AGP therefore requires an execution model that tightly couples packet processing with inference while remaining flexible across model architectures. 

Fused Single-Block Execution. For lightweight models, AGP by-passes inter-layer scheduling via aggressive kernel fusion. The en-tire inference pipeline executes within a single CUDA thread block. By keeping all intermediate activations strictly on-chip (e.g., shared memory/L1) and using local synchronization ( __syncthreads() ), this eliminates global memory traffic and launch overhead. 

Device-Side Scheduling and Execution Queues. For multi-stage models that exceed the register and shared memory limits of a sin-gle streaming multiprocessor (SM), AGP introduces a hierarchical, device-side scheduling engine. Instead of a monolithic block, exe-cution is dynamically coordinated across multiple worker blocks. Once the telemetry pipeline finalizes the stateful features, the data is pushed into a VRAM-resident inference queue. A dedicated set of manager warps continuously monitors this queue. When a teleme-try tensor is ready, these managers handle final preprocessing (e.g., precision casting or dimensionality reduction) and dynamically dis-patch the data to idle worker blocks assigned to compute specific model layers. As worker blocks complete their assigned task (e.g., convolution, activation), they publish their execution state through lock-free, GPU-resident synchronization flags. The manager threads track this state graph in real time, resolving layer dependencies and triggering subsequent layers. This closed-loop scheduling ensures that even complex, multi-stage inferences progress layer-by-layer entirely within the device, maintaining line-rate throughput with-out host intervention, as shown in Figure 2.

## 5 DISCUSSION & OPPORTUNITIES 

Practical Implications. Our prototype’s residual throughput gap at 64-byte packets stems from a sub-optimal PCIe topology that forces P2P traffic through the CPU root complex. Platforms where the NIC and GPU share a PCIe switch, or are integrated on one device, should close this gap. In our prototype, we targeted the mlx5 driver; porting to other NIC families is left as future work. 

GPU as a Multi-Tenant Network Endpoint. Beyond IDS, because AGP’s entire pipeline fits in a small, persistent slice of SMs, that slice can serve as a network front-end for the rest of the GPU. Remote users stream compute requests over the NIC, and on-device manager warps authenticate, parse, and dispatch them to tenant kernels on the remaining SMs without host OS intervention. This requires GPU-native control: with a host in the loop, every request pays the same launch and batch-wait latency we measured for the baselines. Similarly, it can be extended to inline semantic request routing for distributed AI serving, and telemetry and congestion control co-located with primary training jobs. 

A Unified AI-Network Compiler. While AGP demonstrates the benefits of autonomous GPU networking, developing fused GPU kernels and hardware-aware memory layouts remains complex and error-prone. A promising future direction is a unified compiler that bridges networking and AI, replacing today’s fragmented toolchain (e.g., DPDK, CUDA, and PyTorch). Such a compiler could jointly compile packet processing and AI model graphs into optimized GPU kernels and memory layouts, enabling programmable, stateful AI data planes with minimal developer effort. 

## 6 CONCLUSION 

In this paper, we introduced AGP, a GPU-native framework for autonomous packet processing that decouples the network data path from the host CPU. By leveraging an in-GPU execution en-vironment and a fused mega-kernel pipeline, AGP provides a uni-fied AI-native execution environment with zero host intervention, achieving line-rate packet processing with 6 .1× lower marginal power consumption than CPU/DPDK and accelerating network AI inference by 9 .3× over host-scheduled bypass baselines, providing a foundation for next-generation intelligent network infrastructure. More broadly, once the GPU owns the data path, per-flow sched-uling, in-place state, and a host-free fast path follow, making the GPU a first-class network endpoint. ACKNOWLEDGMENTS
