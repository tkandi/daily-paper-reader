Abstract —Supporting edge Artificial Intelligence (AI) infer-ence as a network service is challenging because current mobile systems can transport tensors but do not expose or understand the inference context that gives those tensors operational mean-ing. Prior studies have addressed this gap through dynamic partitioning, collaborative inference, and split pipelines; how-ever, these solutions remain application-bound, network-blind, or context-free. This work proposes Inference on Demand (IoD), an inference-on-demand abstraction that exposes split inference through a CAMARA-like Application Program Interface (API) and carries a split-aware tensor context in-band across the 5G user plane path. We evaluate the IoD on a programmable user plane function (UPF)-based testbed using a partitionable visual AI workload, showing that adaptive split selection can operate as a network-facing service while avoiding the rigid cost profile of static configurations. Including our findings, split inference becomes more than offloading when the service intent, runtime partitioning, and tensor transport are made visible to the mobile data plane. This opens a path toward network-native AI services, in which programmable telco infrastructure coordinates computation, context, and connectivity for user-facing applications. 

I. INTRODUCTION 

Modern applications increasingly require networks to per-form more than just packet delivery [1]. Real-time Artificial Intelligence (AI), immersive sensing, and safety-critical visual analytics depend on latency, compute placement, and context that are not fully captured by best-effort connectivity alone [1], [2]. This gap has motivated open telco infrastructure initiatives, such as the GSMA Open Gateway and CAMARA, which expose network capabilities through common Application Pro-gramming Interfaces (APIs) and make operator infrastructure programmable for developers [3], [4], [5]. At the same time, the growth of 5th Generation Mobile Network (5G) traffic and edge-native workloads has made softwarized mobile cores, programmable user planes, and AI-assisted service control practical enablers for turning connectivity into a common

programmable substrate for user-facing, context-aware appli-cations [2]. However, this broader role for the network is not available for edge inference today [6], [7]. The problem is that split inference is still mostly treated as an application-offloading technique, rather than as a programmable network service [8], [9], [10]. Existing studies have explored dynamic partition-ing, but often outside the mobile user plane; collaborative inference, but without a telco service abstraction; and split-computing pipelines, but without inference-specific in-band context [11], [12]. The network can carry tensors, but it does not yet understand the inference session to which they belong. We propose Inference-on-Demand (IoD), which turns split inference into a network-facing service primitive: the applica-tion requests an inference envelope, the User Equipment (UE) adapts the split point at runtime, and the user plane carries the inference context with the tensor fragments, making the mobile network an active substrate for adaptive AI execution rather than a passive transport path [2]. To address this gap, we designed and evaluated IoD, a CAMARA-inspired service interface and user-plane mecha-nism that exposes adaptive split inference as a programmable network service. Rather than treating the mobile network as a passive path for tensor fragments, the IoD lets the application negotiate an inference envelope, enables the UE to adapt the split point at runtime, and binds activation traffic to inference-session context through in-band metadata carried in the GPRS Tunnelling Protocol User Plane (GTP-U)/Segment Routing over IPv6 (SRv6) packet stack. The contributions are threefold: (i) an application-facing abstraction for requesting and control-ling split-inference sessions; (ii) a data-plane mechanism that transports inference-specific context together with activation fragments; (iii) and an experimental validation over a 5G user plane path showing how this service primitive can support adaptive AI execution inside the mobile network. The remainder of this work is organized as follows. Sec-tion II reviews related work. Section III presents the proposed method. Section III-A describes the experimental testbed. Section IV discusses the results. Section V concludes the paper. arXiv:2610.15062v1 [cs.AI] 10 Oct 2026 II. RELATED WORK 

Recent work has mainly advanced split inference as an optimization problem over computation, communication, and service constraints. Several studies adapt the split point or layer placement to improve latency, energy, throughput, or Service-Level Agreement (SLA) compliance in Mobile Edge Computing (MEC) systems: [13] and [14] target runtime par-titioning and placement of Large Foundation Models (LFMs), while [15], [16], [17], [18], [19], [20], and [21] optimize collaborative Deep Neural Network (DNN) inference across mobile devices, edge servers, or Device-to-Device (D2D) settings. Related learning-oriented works, such as [22], [23], and [24], extend this direction toward Extended Reality (XR), satellite edge computing, and vehicular 6G systems, showing that adaptive partitioning is increasingly treated as a runtime control problem rather than a static model-design choice. A second line of work moves closer to the network infras-tructure itself. [11] proposes 5G architectural enhancements for split-computing service pipelines using Computing-Aware Traffic Steering (CATS), Segment Routing over IPv6 (SRv6), and Mobile User Plane (MUP), whereas [25] studies functional split of in-network Deep Learning (DL) across enhanced User Plane Functions (UPFs). These works show that split Artificial Intelligence (AI) is no longer only an application-layer con-cern. However, they do not expose inference as a CAMARA-style telco Network Application Programming Interface (API), nor do they carry inference-specific split metadata in-band with the user-plane tensor traffic.

III. PROPOSED METHOD 

Figure 1 shows the core idea of our approach: if telco networks are to host new services, their capabilities must be exposed as programmable network APIs, not only as connectivity pipes. IoD follows this direction by exposing edge inference as a CAMARA-style [4] service. The split point k is the service knob: smaller k protects the UE but pushes larger tensors into the user plane, whereas larger k spends more local computing resources but sends fewer bytes to the Multi-access Edge Computing (MEC). For catastrophic scenarios, where device and network conditions change over time, fixing k in advance is excessively rigid. The service intent defines the admissible split range, thresholds, and quan-tization mode; the UE then selects kt = πI (st) from its local execution and recent transmission state. Unlike a fixed split, IoD does not replace the model or reconfigure the MEC service at each frame: it only changes where the current inference is partitioned. The UE transmits encoded activation tensors rather than raw frames, with compact metadata for split identification, shape, type, and reassembly. This makes the abstraction relevant to privacy-sensitive visual applications, where reducing the exposure of raw images in the user plane is part of the service requirement. In our approach we build a CAMARA-like [4] IoD API. The API does not micromanage every frame; it opens the telco infrastructure to a new class of services by negotiating an inference envelope. As shown in Listing 1, the application requests a model, an admissible range of split points, and a quantization policy. The network grants a service session with a MEC target and a data-plane metadata schema. The concrete split point kt is then selected at runtime by the UE, inside the admitted range, and carried in-band with the activation tensor.

The User Plane Function (UPF) is the user-plane anchor between the radio-side path and the MEC-side service. In our architecture, the UE sends activation fragments through the N3 interface using GPRS Tunnelling Protocol (GTP)-U encapsulation toward the UPF. Inside the GTP-U payload, the packet carries an Internet Protocol version 6 (IPv6) and Segment Routing Extension Header (SRH) stack with a split-inference TLV and the raw activation fragment. The relevant packet structure is according to Eq. 1:  

> Ethernet /IP /UDP 2152 /GTP -U(TEID) /IPv6 /SRH+TLV /payload .(1)

The TLV carries the selected split point k, the tensor data type, fragment offset, total number of fragments, scaling information for quantized tensors, and tensor shape. Therefore, the split decision travels in-band with the data plane packet, while Packet Forwarding Control Protocol (PFCP) remains responsible for session-level state and TEID installation. In our implementation, the pipeline receives N3 packets, parses the outer headers, matches the session by TEID through the Packet Detection Rule (PDR) state, and performs GTP-U decapsulation. The split-inference handling is placed imme-diately after decapsulation, when the inner IPv6/SRH packet becomes visible to the data-plane pipeline. At this point, the UPF can parse the split TLV, account the traffic by TEID and split point, and forward the resulting payload toward the MEC through the N6 side. The UPF only exposes the inner packet after GTP-U decapsulation, reads the in-band metadata, and keeps the inference traffic observable and forwardable inside the mobile user plane. At the MEC, TLV metadata drives fragment reassembly, tail selection, and inference completion. The same parti-tionable model therefore admits several runtime operating points: later splits save user-plane bytes, earlier splits save UE compute. IoD ties these choices across three planes: the CAMARA-like API defines the intent, the UE selects kt, and the UPF carries and observes the activation traffic toward the MEC.

IV. RESULTS AND DISCUSSION 

A. Dataset and Neural Network Training 

We use FLAME 2 ( Fire detection and modeLing: Aerial Multi-spectral imagE dataset ) as the visual workload for the split-inference service [29]. FLAME 2 is originally a Unmanned Aerial Vehicle (UAV) video dataset, containing raw RGB/IR video pairs and labeled frame pairs derived from those videos; in this work, we use the 254p RGB frames and the binary Fire/NoFire task. The split model is derived from a ResNet18 backbone pre-trained on ImageNet, with the final fully connected layer re-placed by a two-class classifier. Frames are resized to 224 ×224 

and normalized with ImageNet statistics; training uses random horizontal flips, small rotations, and color jitter. To reduce temporal leakage between adjacent video frames, samples are grouped into temporal blocks of 1000 consecutive frames before the train/validation/test split. B. Inference-on-Demand Split Adaptation 

We carried out experiments in order to evaluate our approach. We aim to answer whether IoD can operate as a dynamic split-selection mechanism under changing user-plane load. Our results show whether IoD can recover a useful operating region without selecting k a priori, react to increasing contention, and keep the UPF load below bytes-heavy static configurations. Figure 4 shows the compute–bytes operating frontier. The static baselines follow the expected trade-off: shallow splits reduce UE-side head inference time but transmit more bytes, whereas deeper splits reduce transmitted bytes at the cost of more UE-side computation. The IoD operating point lies near the middle of this frontier, at approximately 4.0 ms of UE head inference and 1302 KB per frame. This is close to the region represented by k=3 , but it is reached without configuring a fixed split in advance. Overall, the results support the feasibility of IoD as an online adaptation mechanism for split inference over a mobile user-plane path. The method recovers a balanced operating region without prior split selection, reacts to increasing con-tention by shifting toward protection, and keeps UPF load below bytes-heavy static baselines. V. CONCLUDING REMARKS 

This work addressed the gap between edge inference as an application-side offloading mechanism and edge inference as a programmable telco service. The results show that the IoD can adapt the split point at runtime, keep tensor transport observable in the 5G user plane, and reduce the pressure imposed by bytes-heavy static configurations. This finding suggests that mobile networks can support AI execution not only by providing connectivity but also by exposing service intent and carrying inference context along the data path. Future work will extend IoD toward tighter CAMARA API integration, policy-driven split selection, and larger multi-tenant MEC deployments. Overall, the IoD reframes split inference as a network-native service primitive for adaptive AI over a programmable mobile infrastructure. ACKNOWLEDGMENT
