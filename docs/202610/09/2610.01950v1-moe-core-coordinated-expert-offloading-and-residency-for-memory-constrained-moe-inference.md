## 摘要
稀疏专家激活降低了 MoE 模型的计算量，但专家权重可能超出有限的设备内存。卸载使得在紧凑型 AI 设备上进行推理成为可能，但也使主机到设备的数据传输暴露于推理路径中。我们提出 MoE-CORE，这是一个面向内存受限 MoE 推理、协同管理专家卸载与驻留的系统。在预填充阶段，它在交替缓冲区中暂存完整的专家层。在解码阶段，它结合了非均匀的逐层缓存容量、领域信息驱动的初始化、基于路由历史的替换策略以及跨层预取。其主要配置精确执行路由器选中的专家；一条可选的基于分数的替代路径则用于处理符合条件的低分未命中。主要对比中，MoE-CORE 和 vLLM Prefetch 的输出长度上限分别设为 1K 和 128 个 token。在每个模型的五项工作负载上，对于 DeepSeek-V4-Flash-W4A8，MoE-CORE 的平均每输出 token 时间（TPOT）为 38.0–44.8 ms，而所评估的 vLLM Prefetch 配置为 1268.9–1269.1 ms；对于 GLM-5.2-W4A8C8，相应数值分别为 206.6–220.5 ms 和 5941.5–5941.8 ms。在 84 GB NPU 内存上限下，表现最佳的 DeepSeek GSM8K 配置采用近似专家替代和深度为 2 的多 token 预测（MTP），实现了 21.5 ms 的 TPOT。这些结果表明，在设备内存约束下，协同的专家驻留与传输调度具有有效性。代码见此处。

## Abstract
Sparse expert activation reduces MoE models' computation, yet expert weights can exceed limited device memory. Offloading makes inference feasible on a compact AI appliance but exposes host-to-device transfers to the inference path. We present MoE-CORE, a system that coordinates expert offloading and residency for memory-constrained MoE inference. It stages complete expert layers in alternating buffers during prefill. During decode, it combines nonuniform layer-wise cache capacity, domain-informed initialization, routing-history-aware replacement, and cross-layer prefetching. The main configuration executes router-selected experts exactly; an optional score-based substitution path handles eligible low-score misses. The main comparison uses 1K- and 128-token output caps for MoE-CORE and vLLM Prefetch, respectively. Across five workloads per model, MoE-CORE records a mean time per output token (TPOT) of 38.0-44.8 ms versus 1268.9-1269.1 ms for the evaluated vLLM Prefetch configuration on DeepSeek-V4-Flash-W4A8; the corresponding values on GLM-5.2-W4A8C8 are 206.6-220.5 and 5941.5-5941.8 ms. Under an 84-GB NPU-memory cap, the best measured DeepSeek GSM8K configuration achieves a TPOT of 21.5 ms with approximate expert substitution and multi-token prediction (MTP) at depth 2.
