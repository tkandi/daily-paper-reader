## ABSTRACT 

This paper presents AgentDP , which aims to deploy pre-trained AI models on heterogeneous embedded devices by fully automating model optimization and adaptation (O&A) with Large Language Model (LLM) agents. AgentDP not only significantly reduces human effort via automation but also enhances model inference efficacy by integrating LLMs with device-specific domain knowledge. To deliver a robust automation framework, AgentDP develops novel solutions to address three key technical challenges: 1) To help users elicit clear requirements, we propose a user requirement standardiza-tion module; 2) To mitigate the execution environment mismatch be-tween AI models and heterogeneous embedded devices, we design an operator-aware model partition paradigm that enables different parts of the model to be efficiently executed on distinct inference engines. 3) To avoid re-searching optimization hyperparameters for new tasks, we propose a configuration reuse module that heuristi-cally retrieves previous hyperparameter configurations for efficient reuse. Extensive experiments demonstrate that by fully automating the entire O&A process, AgentDP reduces entire model adaptation time by up to 80% compared with manual O&A while achieving higher task accuracy (more than 13% on average) than the base-lines. Additionally, a comprehensive user study also exhibits the robust generalizability of AgentDP in adapting to different user requirements for heterogeneous embedded devices.

## 1 INTRODUCTION 

Embedded AI has emerged as a transformative paradigm, enabling the deployment of AI models directly on embedded devices such as Jetson Nano. Embedded AI facilitates real-time onboard data processing of various sensors ( e.g., camera, microphone) and en-ables low-latency decision-making [53, 55]. In addition, embedded AI ensures privacy and security by keeping sensitive data on local devices [54]. To develop an embedded AI application, developers can down-load a pre-trained model from open-source platforms ( e.g., Hugging Face) and deploy the model on target embedded devices. These models, extensively trained on high-end servers using large-scale datasets ( e.g., ImageNet [20]), can achieve high performance in var-ious sensing tasks. In practice, however, most open-source models cannot be directly deployed on embedded devices for two main reasons. First, these models often contain a large number of pa-rameters 1, making them hard to fit into resource-constrained em-bedded devices [54]. Second, these models are primarily available in PyTorch [49] format, which may not be supported by embed-ded devices with heterogeneous execution environments and di-verse dependencies. To tackle these practical challenges, devel-opers need to perform multiple iterations of model optimization and adaptation, as illustrated in Fig. 1 (left). To tailor models for resource-constrained devices, developers adopt various optimiza-tion techniques with tunable hyperparameters ( e.g., pruning rate, quantization level, etc .) to compress the models. To facilitate the portability of the compressed models across heterogeneous environ-ments, developers also need to translate the compressed models into platform-independent portable models , which can be deployed and executed on embedded devices via cross-platform inference engines (e.g., ONNX Runtime [1]). Finally, developers can iteratively adapt the portable models to meet runtime performance requirements given the resource constraints of embedded devices 2.

Nevertheless, such an iterative O&A process is cumbersome, error-prone, and inefficient. 1) Large Search Space : Manually defining and adjusting the search space for numerous tunable hy-perparameters is time-consuming even when assisted by automated search frameworks [67]. For example, model pruning can be im-plemented with either channel-level or filter-level pruning with varying pruning ratios [37]. Worse still, highly specialized exper-tise is required to identify an appropriate search space for each hyperparameter. 2) Heterogeneous Target Devices : Heteroge-neous embedded devices have diverse execution environments, making the selection and installation of an appropriate inference engine with various dependencies challenging. For instance, Ten-sorRT [46] is optimized for Jetson Nano, whereas ONNX Runtime suits Raspberry Pis [15] better. Mastering and manually config-uring these device-specific frameworks demands substantial time and domain expertise [51]. 3) Laborious Iterative Refinement :Optimizing an AI model for high performance given the resource constraints of a target device typically necessitates multiple rounds of trial-and-error iterations, which is time-consuming even for ex-perienced experts let alone novice developers. This motivates the following research question: Can we automate the O&A process and democratize the AI models that are readily open-sourced yet inaccessible for embedded AI applications? 

To fill this gap, our key insight is to employ LLM agents to fully automate the entire O&A process. The recent advancement of LLMs (e.g., GPT-4 [14]) has demonstrated exceptional language compre-hension and task automation capabilities. Embedded with extensive world knowledge, LLMs can effectively accomplish complex tasks (e.g., program synthesis [56, 59, 60], IoT data interpretation [64], 

etc .) in response to user requirements. Furthermore, by integrat-ing LLMs with various third-party tools ( e.g., web search tools, knowledge databases), we can empower LLM agents to facilitate task automation via enriched domain knowledge. To this end, we propose AgentDP , a multi-agent-assisted model O&A system for heterogeneous embedded AI applications. As shown in Fig. 1 (right), 

AgentDP leverages multiple collaborative agents to automatically execute the iterative O&A process. Nevertheless, several technical challenges need to be addressed to deliver a functional and practical system: 1) Vague User Re-quirements. Due to complex and numerous model evaluation metrics, developers typically struggle to clearly and comprehen-sively articulate their requirements in a single attempt. Moreover, these requirements are often expressed in natural language with irregular structures, leading to misinterpretation of user require-ments and real intents. To tackle this challenge, we propose a user requirement standardization (URS) module that guides users to elicit their requirements following the Tree-of-Thought [68] approach tailored for the URS module. 2) Model-Engine Mismatch. Though portable models are platform-independent, they may not be fully compatible with a single inference engine due to mismatched execu-tion environments. For example, some AI models may use the Mod 

operator during inference, which is not supported by the TensorRT engine [10]. Developers have to either wait for engine updates or use an inefficient fallback solution ( e.g., CPU). To address this challenge, we propose an operator-aware model partition module that allows different parts of a model to be executed using distinct engines. In addition, we design a cross-engine inference pipeline to schedule the partitioned model for efficient inference. 3) Exhausted Hyperparameter Search. If AgentDP performed model O&A from scratch for all new tasks, the O&A process would become extremely time-consuming due to the large hyperparameter search spaces. To mitigate this problem, we reuse hyperparameter configurations of previous models with similar resource profiles. Specifically, we model the hyperparameter tuning process as a finite state machine (FSM) and construct a graph database for similarity-based hyperpa-rameter configuration retrieval. We fully implement and evaluate AgentDP on three heteroge-neous embedded devices across various embedded AI applications, including image recognition, speech sentiment analysis, and vision-language understanding. We compare AgentDP with two types of baselines: a SOTA LLM agent tailored for programming tasks and human developers. We invite 15 users as human baselines and evenly divide them into three groups based on their development experience and expertise. Extensive experiments demonstrate that 

AgentDP can reduce the time required for the O&A process by up to 61% compared to manual execution by experts, significantly im-proving the model O&A efficiency and reducing the human effort. Moreover, the portable models optimized by AgentDP outperform baselines in terms of both task accuracy ( > 13% on average) and resource consumption ( < 14% on average). Last but not least, by allowing users to freely express their requirements, our user studies demonstrate high generalizability (users rated overall satisfaction at over 4.8 out of 5) of AgentDP in handling dis-tinct requirements for adapting various open-source models to heterogeneous embedded devices. 

In summary, we make the following contributions: 

• To our best, AgentDP is the first system to fully automate the model O&A process (from open-source model optimization to embedded AI application deployment), offering an end-to-end solution via multi-collaborative LLM agents. 

• AgentDP develops three novel technical modules for enhanced efficiency and robustness: a user requirement standardization mod-ule for iterative user requirement elicitation, an operator-aware model partition module with a cross-engine inference pipeline to mitigate mismatch between models and inference engines, and a 

configuration reuse module for efficient model optimization. 

• Comprehensive evaluation validates the effectiveness and effi-ciency of AgentDP , demonstrating that AgentDP can significantly reduce the time required and enhance the performance for opti-mizing and adapting open-source models for embedded devices.

For example, if the tar-get device operates on battery power, hyperparameters that can minimize energy consumption may be prioritized. 

Model Adaptation. To facilitate model portability, developers translate optimized models into portable models, which can be deployed on the embedded device via a cross-platform inference engine. Nonetheless, manually configuring model execution envi-ronments poses three key challenges: 1) Empirically following tra-ditional configuration practices ( e.g., directly deploying a PyTorch model on a server installed with commonly used environments) often fails due to hardware incompatibilities, dependency conflicts, and obsolete packages for embedded devices. For instance, some Jetson Nano boards may only support earlier and tailored versions of Ubuntu and Python environments [5]. 2) Embedded devices of-ten exhibit varying affinities for different inference engines. For example, TensorRT is optimized for inference latency on Jetson Nano, whereas ONNX Runtime may be more suitable for Raspberry Pis. Similarly, different inference engines support distinct sets of op-erators based on their diverse architectures. In Fig. 2, we see that none of the representative inference engines can fully support all operators of a Mask RCNN model [23] as an example. This indicates that it is impractical to rely on a single inference engine for various embedded AI models on target devices. Moreover, it implies that models are typically executed in the less efficient fallback mode (i.e., CPU) in practice. 

Multiple Iterations. The O&A process typically undergoes multi-ple trial-and-error iterations by experts to optimize the model per-formance to meet user requirements. Such a labor-intensive process underscores the need for an automated system to enhance efficiency and reduce human effort.

## 2.3 Agent Meets O&A 

As discussed in § 2.1, manually executing the O&A process demands highly specialized domain expertise and substantial human effort, even for experienced developers. Therefore, we propose AgentDP 

that fully automates the O&A process by orchestrating multiple tool-enabled agents, offering unique advantages over manual model op-timization and adaptation. 1) Efficiency Enhancement. AgentDP 

achieves enhanced development efficiency, as it presents end-to-end full automation (from hyperparameter tuning and execution envi-ronment configuration to model deployment) with minimal human intervention. 2) Reliability Enhancement. AgentDP improves the reliability of O&A automation. Armed with information retrieval tools, AgentDP can complement agents with domain knowledge needed in the O&A process. AgentDP also helps users elicit their requirements to avoid misunderstanding user intents.

## 4 SYSTEM DESIGN 4.1 User Interface Agent (UIA) 

The heterogeneity of AI models and embedded devices makes it difficult even for experienced developers to clearly and comprehen-sively articulate their requirements using natural language ( e.g., "The model should achieve an acceptable accuracy on the device"). This poses significant challenges for LLM agents to accurately in-terpret the requirements and verify whether they are ultimately fulfilled (§ 6.6.1). To tackle this problem, we employ UIA to serve as the user interface to help users iteratively elicit clear and structured requirements. As shown in Fig. 5, UIA contains two main modules, 

i.e., system profiling and user requirement standardization (URS). 

4.1.1 System Profiling . To provide users with a concise overview of the specified model and the target device, this module presents the resource consumption information of the model and the hard-ware capabilities of the target device. 

Model Profiling. Given the name of a large model as user input, UIA first invokes the web search tool to download its parameters from open-source platforms ( e.g., Hugging Face). UIA then gener-ates a script to deploy the model on a powerful server and perform inference tasks. The resource consumption information ( i.e., model size, GPU memory usage, and RAM usage) is recorded and format-ted as the model profile. 

Device Profiling. Given the name of a target embedded device (e.g., Jetson Nano) for model deployment, UIA invokes the web search tool to retrieve detailed specs of the device from its official website. Then, we utilize few-shot prompts [17] to instruct UIA to process and format the retrieved contents into a structured device profile, including key specifications such as CPU, GPU, RAM, disk storage, connectivity, I/O ports, and operating system. The constructed system profiles are further processed by the next user requirement standardization module. 

4.1.2 User Requirement Standardization (URS) . Although us-ing JSON or fill-in-the-blank UIs to capture clear user requirements appears promising, these methods often fail to accommodate the fluid and non-deterministic nature of user requirements. ## 4.2 Hyperparameter Tuning Agent (HTA) 

Given the system profiles and the standardized user requirements from UIA, HTA tailors models for resource-constrained devices by tuning various hyperparameters for optimization. However, deter-mining appropriate search spaces for various hyperparameters and selecting optimal sets requires highly specialized domain expertise (§ 2.1). To tackle this issue, we meticulously design several ToT prompts and explicitly instruct HTA to comprehensively analyze the system profiles and resource requirements. Finally, HTA synthesizes a script that translates the original model into multiple optimized portable mod-els by applying the identified hyperparameter sets. The portable models are then sent to MAA for model adaptation. 

Remarks. Hyperparameter filtering and appropriate search space determination leverage LLMs’ extensive world knowledge, enhanc-ing the reliability and efficiency of model optimization. Notably, more advanced hyperparameter searching algorithms ( e.g., BOHB [22]) can also be further integrated orthogonally in the script syn-thesized by HTA for enhanced model optimization performance. 

## 4.3 Model Adaptation Agent (MAA) 

To cater to heterogeneous embedded AI environments, we need to adapt portable models to the target device via various inference engines. However, the operators used by portable models may not be fully supported by a single inference engine (§ 2.1). Existing solutions either rely on fallback environments ( e.g., CPU) for model execution or continuously develop new cross-platform frameworks to support additional operators, both of which are inefficient and cumbersome. To tackle this problem, we propose MMA (Fig. 9), which features an operator-aware model partition module that di-vides the portable model into multiple partitions, each compatible with a different inference engine. Accordingly, MMA also employs a cross-engine inference pipeline to arrange the model partitions and perform inference tasks on the target device by switching between different engines.

Nonetheless, the op-erator set supported by a single inference engine may not cover all the operators used in a portable model. For example, TensorRT does not support the Mod operator while ONNX Runtime does [10, 11]. To address this problem, we propose the OAMP module to split a portable model into multiple parts, ensuring that each partition can be executed on different but compatible inference engines. Specif-ically, our OAMP module contains two key stages: the operator availability check and the greedy partitioning algorithm .The operator availability check analyzes the operators used by the portable model and those supported by distinct inference engines. Specifically, AgentDP first instructs MAA to synthesize a tailored script that analyzes the DAG of the portable model and produces a list of the operators used. Next, MAA is prompted to generate a list of inference engines compatible with the target de-vice. For each engine, MAA invokes the web search tool to retrieve a detailed list of supported operators. In addition, MAA estimates the inference latency of each operator across all supported engines. The greedy partition algorithm aims to minimize the total inference latency while preserving operators’ dependency consis-tency. Specifically, for each operator used by the portable model, three cases are considered: 1) If the operator is supported by mul-tiple inference engines, it is assigned to the one with the lowest latency ( e.g., TensorRT for Jetson Nano). 2) If the operator is sup-ported by only one engine, it is directly assigned to that engine. 3) If the operator is not supported by any available engine, it is assigned to a fallback execution environment ( e.g., CPU). Further-more, considering the overhead incurred when transferring data and control signal between different engines, i.e., context switch-ing [66], we introduce an additional condition. When assigning an engine different from the one used for the previous operator, we calculate the sum of the context-switching time and the inference latency using the new engine. If the computed time exceeds the inference time using the previous engine, the current operator is assigned to the previous engine; otherwise, it is assigned to the new engine. After such a greedy approach, MAA generates a list of model partitions with their corresponding inference engines. This method ensures that the model partitioning process is both efficient and adaptive to the heterogeneous capabilities of different inference engines in embedded environments while minimizing the performance penalties caused by context switching. 4.3.2 Cross-Engine Inference Pipeline (CEIP) . To minimize context switching overhead and ensure efficient data flow between model partitions during inference, we propose the CEIP module to implement a pipelined inference paradigm across multiple engines, as illustrated in Fig. 10(b). Specifically, MAA first loads each model partition onto its assigned inference engine, ensuring that memory and data alignment are consistent across different execution envi-ronments. Inference is then performed sequentially or concurrently, depending on the dependency structure of the portable model’s DAG. Data transfer between partitions is optimized using shared memory and direct memory access (DMA) to minimize context switching time. Additionally, before context switching, CEIP pre-fetches the input of the next partition while the current partition is still executing. This design effectively exploits the strengths of different inference engines ( e.g., TensorRT’s GPU acceleration) to maximize inference efficiency and reduce execution latency. 

4.3.3 Model Evaluation . With the model partitions and the in-ference pipeline, the target device performs inference on its local data and monitors the real-time performance, which is then sent to MAA. For each portable model’s monitoring results, MAA judges whether all performance requirements are satisfied. If they are met, the hyperparameter configuration is delivered to CRA and the monitoring results are presented to the user. Till now, a single round of the model O&A process is completed. The user can either select a preferred configuration for model deploy-ment or choose to continue optimizing the model, in which case 

AgentDP will initiate a new round and repeat the automated O&A process until the user is satisfied with the final deployment result. 

Remarks. As the supported operators evolve with version updates and iterations of different inference engines, all the scripts and algorithms need to be automatically and dynamically implemented by MAA through our meticulously designed prompts to deal with heterogeneous embedded AI environments. The OAMP and CEIP modules fully exploit the extensive world knowledge and the pro-gram synthesis capabilities of LLM agents, enhancing the reliabil-ity and efficiency of model inference on embedded devices. Note that more advanced and efficient model inference strategies ( e.g., prefetching [31] and virtual memory [32]) can also be orthogonally integrated for enhanced efficiency.

## 5 EXPERIMENT SETUP 5.1 Implementation 

Hardware. We implement and deploy AgentDP on an edge server and deploy various models on three embedded devices: a Raspberry Pi, a Jetson Nano, and an embedded mini PC. The edge server and the embedded devices are connected via a router within a local area network. Table 1 shows the hardware configurations of the devices. 

Software. We develop AgentDP with 2,683 lines of Python code. We use LangChain [18] to construct LLM agents. Tavily [8] and Fire-crawl [4] are selected as the web search tools. We choose Chroma [3] as the vector database for storing system profiles and use Neo4j [6] as the graph database to store FSMs for efficient hyperparameter reuse. We implement a communication interface for AgentDP to support remote access and control of target devices. We also build a Python executor within a sandbox [44]. GPT-4o [28] serves as the backend LLM of AgentDP and text-embedding-ada-002 [7] is used for embedding. We integrate the Optuna package [16] with 

AgentDP for HTA to find multiple optimal hyperparameter sets. For embedded AI models, we use PyTorch [49] framework to run the original model and translate it into ONNX [2] as the portable model. We implement our cross-engine inference pipeline considering the following inference engines: ONNX Runtime [1], TensorRT [46], OpenVINO [9], TVM [19], and MLIR [34]. Reflexion [61] is used to ensure the correctness of intermediate outputs. 

## 5.2 Embedded AI Applications & Datasets 

Based on the input data modality, model architecture, and device het-erogeneity, we select three representative embedded AI applications: image recognition (visual), speech sentiment analysis (audio), and visual-language understanding (multimodal). 1) Image Recogni-tion (IR) on embedded devices enable real-time processing and analysis of visual data in areas such as autonomous driving [25] and healthcare [47]. We select a pre-trained CNN -based ResNet-152 [24] model and instruct AgentDP to deploy it on a Raspberry Pi . We evaluate the deployed model on a subset of the ImageNet dataset [20], containing 100,000 RGB images in 1,000 classes. 2) 

Speech Sentiment Analysis (SSA) on audio data involves analyz-ing speech patterns and pitch to determine the emotional tone of spoken content, enabling smart voice assistants, customer service interactions, etc . We select the fine-tuned CNN+Transformer -based Whisper model 3 and deploy it on a Jetson Nano . We evaluate the deployed model using the TESS [50] dataset that has 2,800 audio samples of seven types of emotions. 3) Vision-Language Under-standing (VLU) leverages Vision-Language Models (VLMs) to inter-pret and describe general images ( e.g., logical diagrams and formula recognition), enabling applications such as visually impaired assis-tant [72]. We select the pre-trained multimodal Transformer -based DeepSeek-VL-1.3b [42] as the VLM model and prompt AgentDP 

to deploy it on an embedded mini PC with 12 GB of GPU mem-ory. We evaluate the deployed model on the MMMU benchmark [70], containing 11.5K meticulously collected image understanding questions covering six core disciplines, i.e., art & design, business, science, medicine & healthcare, humanities, and technology & en-gineering. Note that the fine-tuned Whisper model and the VLM use certain operators ( e.g., LayerNormalization , FusedConv ) that are not fully supported by any single inference engine.

## 6.2 Baselines 

To the best of our knowledge, no existing system in litera-ture can automatically execute the O&A process for heteroge-neous embedded devices [57]. We select the best representative baselines, including: 1) Original Models (O.) , i.e., ResNet-152, the fine-tuned Whisper, and DeepSeek-VL-1.3b. 2) MapCoder [30], a SOTA multi-agent system tailored for complex programming tasks. We invite 15 developers and evenly divide them into three groups based on their self-assessed development experience and expertise. User Group 1 (U1) are ex-perts with extensive experience in deploying open-source models on various embedded devices. On the contrary, we analyze the model optimization code generated by 

AgentDP and find that it even adopts a pruning method tailored for Transformer-based models [35]. 3) Although MapCoder completes the O&A process in a comparable amount of time to AgentDP , it de-livers lower performance even than semi-experts while consuming more resources. This is because MapCoder is a general program-ming agent without specialized domain knowledge in embedded AI and thereby cannot effectively handle specific O&A tasks. 4) 

AgentDP takes significantly less time (17 hours) to finish the O&A process, whereas U2 and U3 take about 60 hours and 80 hours, respectively. The underlying reasons are twofold. During model optimization, AgentDP efficiently reuses previous hyperparameters to narrow down search spaces and accelerate model optimization while U2 and U3 rely primarily on brute-force search. During model adaptation, U2 and U3 repeatedly fail to deploy the optimized model due to mismatched operators and Jetson Nano’s complex inference environment. As a result, they resort to executing the model on the CPU, leading to much lower inference speed and throughput. In contrast, AgentDP partitions the model using our OAMP module and selectively switches between different engines via our CEIP module for efficient model inference. These results further showcase that AgentDP can efficiently perform model optimization even for complex models while accommodating heterogeneous embedded AI environments with enhanced reliability.

## 6.6 Ablation Study 

We conduct ablation studies to evaluate the impact of the technical modules in AgentDP . For demonstration purposes, we use image recognition as an example, though similar phenomena are also observed in the other two applications. 

6.6.1 User Requirement Standardization . We directly input the raw user requirements into AgentDP to execute the model O&A process. As shown in Fig. 16(a), without our URS module, the de-ployed embedded model not only exhibits a significant classification accuracy drop (around 10%) but also requires considerably more time to find a valid hyperparameter configuration. Further analy-sis of the source code generated by AgentDP reveals that natural-language-described user requirements make it more difficult for HTA to interpret and verify each requirement. As a result, HTA creates fuzzy search spaces for hyperparameter tuning, resulting in prolonged optimization time. This underscores the importance of our URS module in helping AgentDP gain a clear and comprehensive understanding of user requirements so that they can be effectively processed and verified. 

6.6.2 Configuration Reuse Agent. We first remove CRA by searching hyperparameters from scratch without reusing historical hyperparameters and then record the total time used for model optimization. As shown in Fig. 16(b), removing CRA dramatically increases the time required for model optimization (even exceeding expert users U1), while providing only a minor improvement in task accuracy and RAM usage. This implies that by reusing retrieved previ-ous configurations for hyperparameter tuning, CRA enables AgentDP to reduce the model optimization time by up to 74% without searching from scratch as system utilization increases.

## 7 DISCUSSION 

Error Handling in Multi-Agent Systems. In LLM agent systems, a common challenge is the generation of incorrect intermediate results during multi-step reasoning. These errors can propagate and lead to incorrect final outputs, significantly impacting the reliability of the agent. To address this, AgentDP incorporates Reflexion [61] that enables agents to reflect on failed attempts and iteratively improve. Moreover, to further enhance the robustness of AgentDP in helping agents detect and recover from mistakes during multi-step reasoning, we plan to orthogonally integrate more advanced techniques (e.g., ReAct [69]) as part of our future work. 

Decoupled HTA and MAA. HTA primarily focuses on reducing the resource consumption of large models via hyperparameter tun-ing, ensuring that embedded devices can accommodate them. The real-time performance ( e.g., inference latency), however, is only recorded during model deployment on embedded devices. Thus, in multiple rounds of O&A optimization, HTA can only adjust hy-perparameters for further optimization based on MAA’s feedback and present users with all applicable hyperparameter configura-tions that fully satisfy their requirements. To further enhance the efficiency in such an iterative process, we can orthogonally inte-grate real-time performance prediction models [71] with AgentDP 

to narrow down the search space during hyperparameter tuning. 

## 8 RELATED WORK 

Model Deployment on Embedded Devices. Most pre-trained models cannot be directly deployed on embedded devices due to limited resources and heterogeneous execution environments [48]. Existing works [33, 39] on model deployment to embedded devices focus on optimizing deep learning models for limited compute, memory, and energy budgets. However, hyperparameter tuning often requires multiple iterations of trial-and-error, resulting in substantial human effort even with SOTA hyperparameter tun-ing frameworks [16]. On the other hand, while numerous model deployment frameworks [1] exist, they are not tailored for hetero-geneous embedded environments. Developers need to first generate portable models and deploy them on device-specific inference en-gines ( e.g., ONNX Runtime [1]). Mastering such highly specialized knowledge poses huge challenges even for experienced experts. To deal with such heterogeneous environments, existing solutions either rely on fallback environments ( e.g., CPU) for model execu-tion or continuously develop new cross-platform frameworks ( e.g., ExecuTorch [21]), both of which are inefficient and cumbersome. In addition, although container techniques ( e.g., Docker [45]) can package dependencies to ease software portability, they often fail to support heterogeneous hardware architectures in embedded AI scenarios. To address these issues, instead of requiring develop-ers to manually configure the model optimization and adaptation processes, AgentDP fully automates the whole O&A process with enriched domain knowledge, significantly reducing human effort with enhanced reliability. 

LLM Agents. LLM agents [59] automate complex tasks by integrat-ing LLMs with various third-party tools ( e.g., web search engines). These agents can be applied to various applications, such as pro-gram synthesis [43, 56] and smart assistants [65]. Furthermore, some studies [26, 30] construct multiple agents to collaboratively accomplish complex tasks, allowing specialized agents to work together and adapt to dynamic environments efficiently. For ex-ample, MapCoder [30] solves competitive programming tasks via four agents that handle different development stages. Unlike Code LLMs like MapCoder, which are designed to synthesize general programs, AgentDP builds an automation chain to optimize and adapt open-source models for heterogeneous embedded devices, addressing unique technical challenges ( e.g., model-engine mis-match) and significantly reducing human effort with enhanced model performance. 

## 9 CONCLUSION 

This paper presents AgentDP , a multi-agent automatic model opti-mization and adaptation (O&A) system for heterogeneous embed-ded AI applications. Armed with four specialized agents to address three distinct technical challenges, AgentDP significantly enhances the O&A efficiency with enhanced model performance. User stud-ies demonstrate AgentDP ’s high generalizability in adapting vari-ous open-source models to heterogeneous embedded devices with distinct user requirements. We believe AgentDP can unlock the potential to drive the practical deployment of open-source AI mod-els across diverse and distributed embedded devices in real-world everyday applications.
