Abstract Looped language models increase computational depth by repeatedly applying shared layers, offering a way to improve model quality without adding parameters. However, sequential dependencies between loop iterations increase autoregressive decoding latency. We introduce Dual-Slot ,an architecture that reorganizes serial looped computation into parallel latent and prediction slots. Rather than waiting for the current token’s latent computation to finish, the prediction slot combines the previous token’s deep latent state with the current representation, while the latent slot produces a state for the next decoding step. This shifts the latent dependency across adjacent tokens, replacing two sequential module invocations with a single paired invocation while preserving standard autoregressive generation. To preserve token-level parallelism during training, we use a small number of Jacobi iterations to refine latent states across the sequence in parallel. Experiments on Qwen-style dense and MoE models show consistent improvements in language modeling and downstream performance. On the 1B dense model, Dual-Slot reduces Pile validation perplexity from 7.25 to 7.00 and improves average five-shot accuracy across nine task configurations by 2.26 percentage points. After supervised fine-tuning, it improves zero-shot GSM8K accuracy by 5.83 and 3.49 percentage points for the 1B dense and A0.6B MoE models, respectively, while maintaining near-vanilla decoding latency. 

1. Introduction 

Increasing the computation applied to each token offers a way to improve language model quality without increasing model size. Looped language models implement this idea by repeatedly applying shared layers, increasing effective computational depth through parameter reuse (Dehghani et al., 2018; Giannou et al., 2023; Geiping et al., 2026). However, parameter sharing does not eliminate the cost of repeated computation: successive loop iterations remain sequentially dependent and can make autoregressive decoding several times slower than a vanilla Transformer with the same parameter count. The challenge is therefore to benefit from recurrent computation without paying for multiple serial loop invocations at every decoding step. To address this bottleneck, we introduce Dual-Slot , an architecture that reorganizes serial looped computation into parallel latent and prediction slots. Rather than waiting for the current token’s latent computation to finish, the prediction slot combines the previous token’s already-computed latent state with the current representation. Meanwhile, the latent slot processes the current representation to produce a state for the next decoding step. This shifts the latent dependency across adjacent tokens, replacing two sequential module invocations with a single paired invocation while preserving standard autoregressive generation. 2. Related Work 

Looped language models. Parameter sharing allows a Transformer to reuse the same layers, in-creasing computation depth without adding parameters. Early work applies shared layers recurrently across depth (Dehghani et al., 2018). Later studies use repeated shared modules to improve language modeling and reasoning (Giannou et al., 2023; Yang et al., 2024), while recurrent-depth models increase computation within the latent space (Geiping et al., 2026). Some methods reuse intermediate latent representations by feeding continuous outputs back into the model (Zeng et al., 2026) or refining the current hidden state as a latent thought (Zeng et al., 2025). However, these computations remain sequential, so decoding latency grows with the number of loops.

Efficient looped inference. Several methods reduce this cost through adaptive computation. Some determine whether to continue from the current state (Banino et al., 2021), while token-level methods allocate different amounts of computation to different tokens (Li et al., 2026). Dynamic routing and separate KV caches can support variable loop depths (Yu et al., 2026), but they introduce irregular execution and complicate batching, scheduling, and cache management. Other methods stagger computation across adjacent decoding steps (Cutler et al., 2025), execute loop stages from different tokens in one model invocation (Wu et al., 2025), or use a parameter-shared parallel prediction stream (Langford et al., 2026). However, their information flow remains tied to a predefined stage schedule. During autoregressive decoding, the previous token’s latent state is available before the current step (Fan et al., 2020; Tang and Lu, 2026; Cai et al., 2026; Huang et al., 2026) and can support prediction while the current latent state is computed. Dual-Slot uses this property to compute a latent slot and a prediction slot in one shared-module invocation, with Jacobi iteration preserving token-level parallelism during training. 

3. Method 

Looped language models allocate additional computation to each token by repeatedly applying a shared module. Consider a two-loop computation and let 𝐹 denote the looped module. Omitting the causal context for notational simplicity, the computation can be written schematically as: Loop 1: ℎ𝑡 = 𝐹 (𝑥 𝑡 ); Loop 2: 𝑦 𝑡 = 𝐹 (ℎ𝑡 ). (1) Here, 𝑥 𝑡 is the representation of token 𝑡 entering the looped module, ℎ𝑡 is an intermediate latent representation, and 𝑦 𝑡 is used to predict token 𝑡 + 1. In this conventional formulation, Loop 2 depends on the output of Loop 1 and therefore cannot begin until Loop 1 has finished. More generally, 𝐿 loops require 𝐿 sequential applications of 𝐹 along the autoregressive decoding path. To address the decoding latency introduced by serial looping, we propose Dual-Slot, which introduces a latent slot and a prediction slot for each token. Neither slot requires the other’s final output at the current step, allowing the two slots to advance through the shared module in parallel. We first describe this decoding procedure and its parallel training rule while treating 𝐹 as an abstract looped module. We then instantiate 𝐹 as a partial loop over the middle layers of a Transformer in subsection 3.3.

3.1. Dual-Slot Parallel Decoding 

At decoding step 𝑡 , we define the two slot inputs as: Latent slot: 𝑥 𝑡 ; Prediction slot: e𝑥 𝑡 = Mix (𝑥 𝑡 , ℎ 𝑡 −1) = 𝑥 𝑡 + ℎ𝑡 −1, (2) where 𝑥 𝑡 is the current representation and ℎ𝑡 −1 is the preceding token’s latent-slot output. The carried history is set to zero at sequence boundaries. The two slots share token 𝑡 ’s position ID and are ordered causally, with the latent slot first. Given the attention key–value cache KV <𝑡 from preceding steps, we evaluate them together: 

(ℎ𝑡 , 𝑦 𝑡 ) = 𝐹 ([ 𝑥 𝑡 , e𝑥 𝑡 ]; KV <𝑡 ) . (3) Here, ℎ𝑡 is retained for the next decoding step, while 𝑦 𝑡 is used to predict token 𝑡 + 1. During autoregressive decoding, ℎ𝑡 −1 is already available from the preceding step, so both slot inputs are known before invoking 𝐹 and the two slots can be processed in parallel. 

3.2. Parallel Training via Jacobi Iteration 

Sequential decoding naturally provides ℎ𝑡 −1 before token 𝑡 is processed. Teacher-forced pretraining, however, processes all tokens in a sequence simultaneously, before their latent-slot outputs are available. Naively reproducing the decoding procedure would create a left-to-right chain ℎ1 → ℎ2 →· · · → ℎ𝑇 and remove the token-level parallelism of Transformer training. To preserve token-level parallelism while approximating the latent states induced by sequential inference, we use Jacobi iteration to refine all positions in parallel for a small number of rounds (Saad, 2003).

3.3. Partial-Loop Implementation 

In practice, to balance model performance and computational cost, we apply Dual-Slot in a partial-loop form rather than looping the entire model. Only a contiguous set of middle Transformer layers is looped. The complete model can therefore be viewed as three components: a Prefix, a Loop Core, and a Suffix. For each token, the Prefix is evaluated once to produce the loop input: 

𝑥 𝑡 = Prefix (Embed (token 𝑡 )) . (9) The Loop Core serves as 𝐹 in Equation 3–Equation 6: only these middle layers operate on the paired latent and prediction slots. We then discard the latent stream and pass only the prediction output through the Suffix and the language modeling head: logits 𝑡 = LMHead (Suffix ( 𝑦 𝑡 )) . (10) Thus, token encoding in the Prefix and prediction decoding in the Suffix are performed once, while recurrent latent computation is confined to an intermediate representation space.

We evaluate the 1B dense and A0.6B MoE models on Pile validation (Gao et al., 2020), WikiText-2 (Merity et al., 2016), LAMBADA-OpenAI, and LAMBADA-Standard (Paperno et al., 2016), using word-level perplexity for WikiText-2. As shown in Figure 2, Dual-Slot consistently improves language modeling performance over Vanilla across all four benchmarks, achieving lower perplexity for both dense and MoE models. 

4.1.2. Downstream Performance 

We evaluate the 1B dense and A0.6B MoE models on nine downstream task configurations: LAMBADA-OpenAI, LAMBADA-Standard (Paperno et al., 2016), PIQA (Bisk et al., 2020), WinoGrande (Sak-aguchi et al., 2021), SciQ (Welbl et al., 2017), HellaSwag (Zellers et al., 2019), ARC-Easy, ARC-Challenge (Clark et al., 2018), and RACE-high (Lai et al., 2017). Table 1 reports zero-shot and five-shot accuracy, together with the unweighted average over all nine configurations. In zero-shot evaluation, Dual-Slot improves average accuracy from 55.83% to 57.10% for the 1B dense model and from 56.26% to 57.41% for the A0.6B MoE model, corresponding to gains of 1.27 and 1.15 percentage points, respectively. The gains also hold in the five-shot setting, where average accuracy increases 2.26 and 1.48 percentage points. Although individual task gains vary, Dual-Slot consistently improves aggregate downstream performance across both model families and shot settings.

We study the scaling behavior of Dual-Slot using dense models with 150M, 300M, 600M, and 1B parameters, and MoE models with A0.15B, A0.3B, and A0.6B active parameters, with tpp200 (token-per-parameter). 5. Ablation Studies 

We conduct all ablations on the 600M dense model trained for 120B tokens. We examine three design choices: how to construct the prediction-slot input, where to place the loop core, and whether to use fixed or random 𝐾 during training. 

5.1. Prediction-Slot Fusion 

We compare four prediction-slot fusion methods: direct addition (Raw Add), postmerge RMS matching, gated addition, and gated addition with postmerge RMS matching. RMS matching rescales the merged representation to match the RMS of 𝑥 𝑡 , while the learnable gate controls the contribution of ℎ𝑡 −1

before addition. As shown in Table 5, RMS matching increases validation loss both with (w/) and without (w/o) gating. Gated addition improves over Raw Add by only 0.001. We therefore retain Raw Add as our default for its simplicity and parameter-free formulation.

6. Conclusion 

We introduced Dual-Slot, an architecture that reorganizes serial looped computation into parallel latent and prediction slots. By carrying latent states across adjacent tokens, the two slots advance through shared layers in a single paired invocation while preserving standard autoregressive generation. A small number of Jacobi iterations preserves token-level parallelism during training, while randomizing  

> 𝐾

∈ { 2, 3} encourages more stable predictions and hidden-state refinement beyond the iteration counts used during training. The experiment results highlight cross-token latent-state reuse as a practical way to improve language model quality while avoiding the within-token serial loop dependency of conventional looped models.

Layer indices in this paper start at zero, whereas the implementation indexes the core’s starting layer from one.
