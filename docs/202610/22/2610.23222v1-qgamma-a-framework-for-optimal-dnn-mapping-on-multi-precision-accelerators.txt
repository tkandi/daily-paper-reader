Abstract. This work describes qGAMMA, a flexible framework for ex-ploring and optimizing the mapping of mixed-precision Deep Neural Net-work (DNN) models onto general-purpose spatial accelerators that sup-port a range of fixed- and floating-point precisions. qGAMMA navigates the design space using a domain-specific genetic algorithm and an an-alytical performance model based on hardware synthesis results. The framework identifies the optimal mapping and accelerator configuration that minimizes target metrics. Extensive evaluations across DNN work-loads show that qGAMMA offers valuable insights for designing mixed-precision applications, enabling better trade-offs between performance, energy efficiency, and resource utilization. 

Keywords: DNN accelerators · Optimization · Mapping. 

# 1 Introduction 

As DNNs become increasingly computationally demanding, efficient hardware accelerators have become essential, particularly for resource-constrained plat-forms. Recent research has focused on low- and mixed-precision computation to reduce storage and computational overhead in DNN accelerators. By process-ing each DNN layer with a different precision, these approaches offer greater flexibility in balancing efficiency and accuracy [11, 13, 16]. However, optimizing and fine-tuning the execution of mixed-precision DNN models on accelerators equipped with multiple precision pipelines (integer and/or floating point) intro-duces significant complexities largely unaddressed in system-level optimization. This work introduces qGAMMA, a framework designed to optimize the map-ping of mixed-precision DNN models onto accelerators that support multiple precision pipelines. Specifically, qGAMMA enables designers to explore trade-offs between mapping strategies, parallelization, and precision, offering valuable insights into leveraging mixed-precision computations for optimal performance.

# 2 Background and related work 

The 2D CNN 3 algorithm consists of six nested loops (or seven when consider-ing batching) of Multiply-Accumulate (MAC) operations. These loops can be ordered, tiled, and scheduled to optimize the algorithm execution on an acceler-ator. This configuration, known as dataflow , directly influences resource utiliza-tion, energy efficiency, and data reuse [10]. Dataflow is defined by (i) computation order , affecting temporal and spatial reuse, (ii) parallelism and unrolling , deter-mining data movement patterns, and (iii) tiling strategy , which dictates memory usage and bandwidth requirements [9]. State-of-the-art tools like MAESTRO [10] and Timeloop [12] adopt the dataflow concept to evaluate CNN performance on spatial accelerators. In MAESTRO, a 2D convolution and its dataflow model (Figure 1) are structured using key directives: TemporalMap() , which dictates data distribution over time within a processing element (PE), SpatialMap() , which indicates spatial distribution data across multiple PEs for parallel execution, and Cluster() , which groups PEs or subclusters for multidimensional spatial distribution. These tools analyze dataflow descriptions and accelerator configurations, using analytical models to estimate arithmetic unit activity, memory usage, communication overhead, and data reuse efficiency. Execution latency is dictated by the slowest component, while energy consumption is estimated using activity counts and component-specific energy costs. GAMMA [9] supports the exploration of per-layer dataflows optimized for specific hardware accelerators. As shown in Figure 4a, GAMMA encodes dataflow characteristics as gene pairs—one for each of the six CNN dimensions (see Fig-ure 1a) and an additional pair for spatial parallelization-and use a domain-specific genetic algorithm to search for an optimal CNN layer mappings min-imizing latency and/or energy consumption. # 3 Accelerator architecture template 

Figure 2 presents the spatial architecture template used in this work, which consists of PEs with local (L1) and global shared (L2) scratchpad buffers, main memory, and a Network-on-Chip (NoC) interconnecting all components. The PEs can be arranged into multiple hierarchical clusters. To improve data transfer efficiency, the accelerator utilizes double buffering. To support mixed-precision computations, each PE in our model features a configurable functional unit based on state-of-the-art designs [1, 11] and capable of performing computations in different precisions. Following [11], we consider separate pipelines for integer fixed-point and floating-point operations, allowing 5

Functional units have 32-bit input/output ports and support FP32, FP16, FP8, and FP4 floating-point operations [2, 13], as well as INT32, INT16, INT8, INT4, and INT2 fixed-point computations [7, 11]. At FP32 or INT32 precision, the functional unit performs a single MAC operation. For lower precisions Q, the 32-bit lane is partitioned into P = 32 /Q operands and the func-tional unit executes a P

Given the high parallelism of the targeted algorithms, threads are scheduled to minimize data dependencies, ideally achieving one instruction per cycle [7]. During design-space exploration, accelerator components are instantiated au-tomatically with precision-specific configurations, including accumulator width, adder trees, and output packing. 

# 4 qGAMMA 

As shown in Figure 3, qGAMMA takes as input a mixed-precision DNN model, an objective metric (energy, latency, or energy-delay product (EDP)), and a gen-eral description of accelerator resources (such as the number of PEs, memory levels, maximum memory sizes, maximum NoC bandwidth, and supported pre-cisions). By leveraging the search based on a genetic algorithm and the dataflow encoding used in GAMMA [9], qGAMMA explores a range of possible dataflows and architectural configurations—such as the number of components in each hardware cluster and buffer utilization across memory levels— to identify the characteristics that minimize the chosen metric. 4.1 Enhanced dataflow model 

We enhanced the GAMMA framework to support mixed-precision DNN mod-els. In addition to specifying the dimensions of each DNN layer, hardware con-straints, and the objective metric, qGAMMA allows users to define the precision of weights and activations for each layer. This information is then used to gener-ate the architectural model of the pipeline and the corresponding dataflow model used in the exploration.

To support the functional unit’s architectural model, we extended GAMMA’s original 2-level genome (one genome level for each cluster level shown in Figure2) by introducing an additional level of parallelism, accounting for the cluster used to model the low-precision pipeline. Figure 4a illustrates the encoding of the 3-level genome: The first block (L3-mapper) defines the dataflow between PE clusters, the second block (L2-mapper) represents the dataflow within each PE cluster, and the third block (L1-mapper) models the dataflow for the multi-precision pipeline. As in GAMMA, within each block, the last six pairs of genes encode a DNN layer dimension and its corresponding tile size, ordered according to the computation sequence in the dataflow. The first pair of genes in each mapper specifies the parallelized dimension. Their associated value is constrained by the corresponding tile size of the chosen parallelizing dimension and by the number of available elements on which the parallelization is performed (clusters, PEs, multipliers). The 3-level genome is used exclusively for configurations involving low-precision computations, while FP32 and INT32 computations continue to use the original 2-level genome. The inner cluster size is dictated by the lowest precision used in the DNN computations. In contrast, the sizes of higher-level clusters are dy-namically selected during exploration based on the model’s overall performance. qGAMMA’s genetic algorithm follows the same fundamental steps as the original framework [9]. It begins by generating a random initial population of samples (dataflows), then evolves the genome through crossover between two high-performing parent genomes. Additionally, with a certain probability, it ap-plies random mutations to the parallel dimensions and tile sizes specified in the genome. Once a population is selected, the genomes are decoded into dataflow descriptions and evaluated using a hardware performance estimation tool. This tool assesses the objective function while ensuring compliance with hardware constraints. The next generation of samples is then selected based on their fit-ness, as determined by the chosen objective metric. 

4.3 Heuristic optimization 

Introducing a three-level genome significantly expands the search space com-pared to a two-level genome (size of O(10 33 ) for a ResNet18 [9]). To prune the search space, we define a combination of three heuristics: 

– Heuristic 1: Since accelerator architectures typically consist of a power-of-two number of processing units, we restrict the number of PEs per cluster to 8 L. Fiorin et al. 

powers of two. An exception is made for the inner cluster, where the number of low-precision multipliers determines the number of PEs; 

– Heuristic 2: The 3-level genome enables parallelization across three dimen-sions, one for each cluster level, prioritizing dimensions with more elements, as they are more likely to benefit from parallelization. The outer cluster randomly selects the parallel dimension from the three largest dataflow di-mensions. At the next cluster level, the selection is narrowed to the two largest dimensions. No restrictions are imposed on the inner cluster, as the parallelization over the K dimension is already constrained; 

– Heuristic 3: We explore power-of-two values for the K and C dimensions during genome generation since these values typically correspond to the most common configurations in DNN layers. 

4.4 Performance estimation tool 

Leveraging MAESTRO [10], we designed an analytical estimation tool sup-porting multi-precision pipelines and incorporating the changes introduced in qGAMMA. We modified the original dataflow description used as input to the estimation tool to include the desired computation precision for each DNN layer. To reflect the architectural features of the PEs introduced in Section 3, we devel-oped a new activity-based energy model that accounts for the implementation of low-precision MACs, packed accesses to memory buffers, and NoC transfers. More details on the energy model are provided in Section 5. 

# 5 Experimental evaluation 

5.1 Experimental setup Hardware accelerator model Our experiments focus on a hardware acceler-ator consisting of 16 PEs, each with a maximum of 512 bytes of L1 scratchpad memory, and a global L2 scratchpad memory of up to 512 Kbytes. Energy, per-formance, and area values for the functional unit components were extracted from implementation results published in [7,11,13]. The on-chip interconnection network is modeled based on implementation results from [3]. Energy and area values for the memory elements were obtained using CACTI-D [15]. All val-ues were scaled to 22-nm technology. In our results, we did not include energy consumption for main memory, as the exploration framework discards design solutions requiring main memory access for storing temporary results, resulting in the same main memory energy profile across all valid solutions. 

DNN models We evaluated three DNN models of different complexity: a Mo-bileNetV1 [5], a ResNetV1 [4], and a mixed-precision variant of ResNet18 [16], which employs a combination of INT8 and INT4 precisions for weights and ac-tivations. In [16], the selection of layers to be quantized in INT4 is formulated as an ILP problem aiming at minimizing the DNN’s sensitivity to perturbations 9

caused by the lower precision while adhering to constraints on latency, comput-ing capacity, and model size. The resulting mixed-precision DNN model is then fine-tuned, achieving an accuracy close to the FP32 baseline (-1.5%) and a uni-form INT8 ResNet18 (-1.6%). The precision assigned to each layer is shown in Figure 5a. 

Optimization setup We focused on single-objective optimization, targeting either latency, activity-based energy, or EDP. We applied qGAMMA in two opti-mization approaches. In the first approach, we performed per-layer optimization, allowing a unique clustering strategy for each DNN layer. We ran qGAMMA for 1000 generations with a population of 150 individuals, using INT32 and FP32 precisions (requiring a 2-level mapper). For lower-precision configurations (re-quiring a 3-level mapper), we increased the population to 300 individuals due to the larger search space. In the second approach, we used a single clustering applied to all layers, re-flecting the fact that clustering is a hardware configuration fixed at runtime. We first ran the per-layer optimization as in the first approach, then conducted a second phase where qGAMMA was run for 1000 generations to select a sin-gle clustering based on the configuration most frequently used across layers in the first phase. To improve optimization efficiency, we implemented an early-stopping policy that halts the process if the best solution does not change after 150 generations. 

5.2 Experimental Results 

A direct comparison of qGAMMA with state-of-the-art mapping and exploration tools is not feasible, as none of the existing frameworks support both mixed-precision DNN modeling and multi-precision accelerators. However, this section presents experimental results that highlight qGAMMA’s capabilities, in compar-ison, when suitable, to the original search algorithm and modeling features of GAMMA [9]. 

Heuristics validation - ResNet18 [16] The proposed heuristics aim to prune the search space and eliminate inefficient dataflow. To demonstrate their effec-tiveness, we optimized the mixed-precision ResNet18 for minimum latency. We ran qGAMMA with a population of 300 individuals for 1000 generations, applying an early-stop condition at 150 generations. Figure 5a compares the latency of the ResNet18 when using the heuristics implemented in qGAMMA, and without them (original GAMMA search algorithm). The latency results are nearly identical in both cases, with a modest 4% reduction when heuristics are applied. However, the heuristics significantly reduced the number of generations required to reach the early-stop condition and decreased overall execution time by about 31% when considering the 150 early-stop generations (Figure 5b), and by 51% without them (results not shown). While slightly increasing the search time, the early-stop condition is essential for ensuring the convergence of the search algorithm. 10 L. Fiorin et al.

# 6 Conclusions 

In this work, we introduced qGAMMA, a versatile framework for optimizing the mapping of mixed-precision DNN models on accelerators with multi-precision support. Alongside qGAMMA, we proposed an accelerator architecture tem-plate that models cutting-edge multi-precision designs. Through extensive evalu-ation across diverse DNN inference workloads, we demonstrated that qGAMMA equips designers with valuable insights for optimizing mixed-precision applica-tions. By integrating efficient techniques for rapid DNN accuracy estimation across different models and precision levels, qGAMMA serves as a powerful tool for comprehensive DNN accelerator optimization, enabling faster and more ef-fective design-space exploration. 14 L.
