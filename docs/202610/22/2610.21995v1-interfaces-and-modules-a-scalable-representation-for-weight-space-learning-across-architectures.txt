# ABSTRACT 

Weight-space learning across architectures requires representations that respect parameter symmetries and scale to large networks. Existing equivariant tensor en-coders require architecture-specific symmetry specifications, while neuron graphs make global attention costly. We introduce a typed graph organized around shared coordinate-permutation actions. Its nodes, called interfaces , represent coordinate spaces whose bound tensor axes must be permuted jointly; operation occurrences, called modules , form typed hyperedges. A compiler derives this graph from sup-ported PyTorch models, with exact recovery of the permutation factors defined by its constraints. The Universal Weight Encoder (UWE) combines local equivariant updates to parameter features with global attention over invariant interface sum-maries. The small number of interfaces makes global attention practical, and a single encoder processes different supported architectures. UWE is competitive with architecture-specific state-of-the-art methods on established benchmarks. On a new zoo of 1,200 transformers spanning 100 architectures, it outperforms the evaluated baselines at ranking networks within unseen architectures, including architectures larger than those used for training, while using substantially less memory. 

# 1 INTRODUCTION 

Weight-space learning treats trained neural networks as data: predicting performance from parameters, editing implicit neural representations, and generating weights and adapters (Unterthiner et al., 2020; Navon et al., 2023; Zhou et al., 2023a; Karimi Mahabadi et al., 2021; Ruiz et al., 2024). Public model hubs motivate extending these methods across networks that differ in width, depth, operations and training history (Falk et al., 2025). Their representations must also account for parameter symmetries: hidden-unit permutations, and in suitable architectures continuous rescalings and changes of basis, can preserve the represented function (Hecht-Nielsen, 1990; Chen et al., 1993; Neyshabur et al., 2015; Putterman et al., 2024). Here we focus on coordinate permutations. We seek a representation that respects these symmetries, supports modern architectural components, transfers across architectures, and remains compact enough for global attention. It should also be derived from the network’s implementation. Existing representations meet only some of these requirements. Equivariant weight-space networks act directly on weight tensors, using an architecture-specific construction or a supplied permutation specification (Navon et al., 2023; Zhou et al., 2023a; 2024; Tran et al., 2025). Neural graph methods instead represent neurons as nodes and weights as edge features, allowing one encoder to process different architectures (Kofinas et al., 2024; Lim et al., 2024). However, extending these repre-sentations to combinations of residual connections, normalization, attention and low-rank adapters requires careful treatment of their parameter dependencies. The required symmetry specifications or graph encodings are typically supplied by hand, and their correctness is not automatic: the attention representation of Kofinas et al. The size of neural graphs creates a further constraint. Local message passing requires successive hops to connect distant operations, while fully connected attention is quadratic in the number of neuron nodes. Methods that tokenize windows of weights offer another route to scale, but do not enforce permutation equivariance (Sch¨ urholt et al., 2024; Falk et al., 2025). We therefore need objects that preserve the shared permutation actions of the network while being substantially fewer than its neurons. Appendix A reviews related work in more detail. These requirements suggest separating operations from the coordinate spaces they act on. In an MLP, permuting a hidden layer requires the same relabelling of the preceding weight matrix’s outputs and the following matrix’s inputs. A residual addition can impose this agreement across several activation tensors. The shared coordinate space is therefore a natural object for the representation: it identifies which parameter axes must be relabelled together. We call such a space an interface . Each permutation-bearing interface carries one shared coordinate permutation, while distinct interfaces may be permuted independently. We represent the network as a typed graph whose nodes are interfaces and whose hyperedges are operation occurrences, called modules .Our main contributions are this interface–module graph and the Universal Weight Encoder (UWE), an equivariant encoder that operates on it across architectures. Shared permutation bindings already appear in alignment specifications (Ainsworth et al., 2023) and in specifications used to construct equivariant layers (Zhou et al., 2024). We use these bindings to define the graph’s nodes and the objects over which the encoder communicates. UWE alternates local equivariant updates to parameter features with global attention over invariant interface summaries (Section 3). The graphs are compact: a ResNet-18 has twelve permutation-bearing interfaces, and an 85M-parameter transformer has 301, compared with about 84,000 neuron nodes. Global attention over these interfaces is therefore affordable. To automate graph construction, a compiler traces a supported PyTorch model and infers interfaces and parameter-axis bindings from operator constraints. Recovery is exact within its constraint language, and the recovered relabellings preserve the network’s function (Section 4). Models assembled from supported operations, layouts and sharing patterns require no new architecture-specific specification. Figure 1 illustrates the pipeline. Evaluating transfer across architectures requires benchmarks that vary both architecture and scale. Common weight-space benchmarks focus on small networks from a single architecture or a narrow family, leaving transfer to larger, unseen architectures poorly tested. We therefore introduce a trans-former zoo with architecture-level splits and loss profiles across class groups and image corruptions. These profiles distinguish networks with similar aggregate performance but different patterns of error. UWE is competitive on standard weight-space benchmarks and outperforms the tested baselines on the new zoo, with stronger transfer to larger held-out architectures and lower memory use (Section 5). Separate scaling experiments establish computational feasibility on larger networks, including full training steps on ViT-L/16 and GPT-2 Medium on a single 80 GB GPU (Section 5.4).

Objects sharing a coordinate-permutation action map to one interface. Operations whose inputs and outputs share an interface become self-loops. The compiler (Section 4) constructs these graphs for the encoder (Section 3). An interface I ∈ I is a coordinate space of width nI . It is permutation-bearing if the compiler’s constraints permit arbitrary coordinate permutations, and fixed if they permit only the identity. Fixed interfaces arise, for example, from input/output layers or fixed positional encodings. Interfaces carry no arbitrary identity or depth labels. A module o ∈ O is an operation occurrence with a type, hyperparameter descriptor and network depth. Several modules may reference shared parameters. Parameter-free operations, such as activations, additions and concatenations, are weightless modules retained for their constraints on relabellings. A binding associates a module axis with an interface under a role , such as input, output, query-output or scale-and-shift, from a fixed vocabulary of about a dozen entries (Appendix H.6). Each bound axis has one binding; several axes may bind to the same interface. The representation is thus a typed hypergraph: modules are typed hyperedges, and bindings are their role-labelled incidences. 2.2 PARAMETERS 

A parameter tensor with two channel axes bound to I and J forms a rectangular block of cells

Modules reference one or more units, such as a linear layer’s weight and bias; several occurrences may share a unit. An axis spanning several interfaces, as when reading a concatenation, is partitioned into one unit per interface. Theorem 2.2 (Function preservation) . For every model accepted by the compiler under its supported operation, layout, state-action and alias rules: (a) Every coordinate relabelling in Γ, applied consistently through the bindings, leaves the network’s function unchanged for every admissible value of the represented state. (b) Every supported module exchange in E, applied to all affected modules, interfaces and stored-state blocks, leaves the network’s function unchanged. Consequently, every transformation in G preserves the network’s function. 

Part (a) follows by composing the supported operations’ equivariance, enforcing fixed-state and alias constraints (Appendix H.7); part (b) follows from the supported exchange rules. Composition extends these actions to G. Numerical tests separately check their implementation on compiled models. 

Remark 2.3 (Exactness and completeness) . Γ is exact relative to the compiler’s constraints: it contains precisely the coordinate relabellings satisfying them (Theorem F.1, Appendix F.5). Soundness establishes function preservation, not the converse. # 3 THE ENCODER 

The representation does not prescribe one encoder, but it fixes what any encoder over it must respect. We state the design at that level, keeping it as close to a standard transformer as the graph allows; the architecture used in our experiments is specified in full in Appendix G.1. 

State. A rectangular unit u bound to interfaces I, J carries Eu ∈ RnI ×nJ ×dE ; a diagonal unit, such as a bias tensor, carries Eu ∈ RnI ×dE . Each cell encodes one scalar or a vector of folded parameters. Interface I carries HI ∈ RnI ×dH , one vector per coordinate. Each weightless module o carries 

uo ∈ RdH , and g learned global tokens G ∈ Rg×dH support invariant readouts. Cells can greatly outnumber interface coordinates, so we use narrower cell features, dE < d H , to reduce memory use. 

Layer. Each encoder layer applies four passes (Figure 3). • Interface pass. Coordinate states are pooled into invariant interface summaries. Local messages connect interfaces sharing a module, conditioned on its type and binding roles. Global atten-tion operates on the summaries and optional global tokens. Updates are broadcast to interface coordinates. • Delivery: interfaces to modules. Each unit gathers its bound interface states, adds receiving-role embeddings, and projects them into row and column contributions to its cells. • Module pass. Shared maps update cells from their features and pooled row and column features, following equivariant weight-space layers (Navon et al., 2023; Zhou et al., 2023a; 2024). Weightless modules receive a feed-forward update. This is the analogue of the per-token feed-forward block in a conventional transformer. • Emission: modules to interfaces. Each unit pools its cells into one message per bound interface coordinate, with sending-role embeddings. Each coordinate averages incoming messages from its bound units and weightless modules. Codes. Learned embeddings identify parameter kinds, operation types and binding roles. Numerical descriptors record attributes such as stride and normalization ϵ; sinusoidal features encode module depth, ordered binding positions and offsets within folded tensors. These codes condition the lift and local messages and are shared across architectures (Appendix G.1). 

Lift. Scalar weights are encoded with a fixed multi-octave sine–cosine basis (Tancik et al., 2020; Vaswani et al., 2017), optionally including the raw value, without rescaling. A cell contains one scalar or a folded vector, such as kernel elements or a normalization pair, with codes for their kinds and offsets. The parameter layout retains every entry, while the fixed-width cell encoding may compress folded vectors. Module codes are added to cell features. 

Fixed coordinates. For every fixed interface, the lift adds projected sinusoidal coordinate encodings to its bound cell axes. This includes input and output interfaces and residual streams fixed by externally supplied positional encodings. Learned positional embeddings are parameters that permute jointly with the residual stream; permutable axes receive no coordinate encoding. 

Aggregation, normalization, and batching. Pooling uses shared maps and means (Zaheer et al., 2017); LayerNorm acts only along the feature dimension. Different architectures are batched as disjoint unions, with attention and readouts separate for each network. Matching graphs and metadata permit batching along a shared batch dimension. Encoder maps are shared across modules and architectures.

# 4 THE COMPILER 

The compiler constructs the graph of Section 2 from a supported PyTorch model and example inputs. It traces the model in evaluation mode and resolves coordinate axes from tensor shapes, dtypes and operator rules, without inspecting numerical parameter values. External input and output coordinates are fixed. Rules for parameters, buffers and shared storage specify their permitted transformations; unsupported cases are rejected. 6Each operation imposes constraints on coordinate permutations. A glue requires corresponding coordinate blocks to use the same permutation: activations and normalization glue their input and output axes, addition glues its inputs to its output, and attention glues query and key coordinates within each head. A split requires permutations to preserve a block boundary, such as an input boundary in coordinate-axis concatenation or a head boundary in attention. A linear layer imposes no input–output glue. The compiler propagates splits through glues until no new split is introduced. This procedure terminates and is independent of processing order. It then partitions each axis at the split positions and identifies the resulting intervals whose permutations must agree. Each equivalence class defines an interface, which is fixed if any member belongs to a fixed axis. Parameters and buffers are partitioned into units and bound to these interfaces. The permutations satisfying the emitted constraints are exactly Γ. Supported head permutations generate the additional exchanges E. Function preservation follows from the operator rules under their stated assumptions. An independent checker verifies the interface derivation against the emitted constraints; numerical tests separately check the implementation. Appendix F gives the compiler pipeline and interval solver in Algorithms 1 and 2. Appendix H.6 lists the supported operations and their interface bindings.

# 6 LIMITATIONS 

(i) The compiler’s guarantees hold within its rule set and constraint language, which exclude continu-ous changes of basis. (ii) Unsupported constructs, including arbitrary attention masks, cross-attention, rotary embeddings, recurrence and tensor sharing without a supported alias rule, are rejected. (iii) Compressing the parameters bound to each cell into a fixed-width feature can lose information, particularly for large convolutional kernels. (iv) Execution requires many small kernels, making deep targets substantially slower per step than neural graph baselines. Designing encoders that use modern hardware more efficiently while respecting the representation’s symmetries remains future work. (v) The zoo covers one transformer family, one dataset and one task; transfer across model families and tasks remains untested. (vi) Resource measurements use random weights and establish computational feasibility, not predictive quality. 

# 7 DISCUSSION 

Organizing weight-space learning around shared permutation actions gives a common representation for networks with different architectures. Interfaces record which parameter axes must be relabelled together, and modules describe the operations connecting them. This structure serves two purposes: it specifies the permutation action and provides a small graph for global communication. UWE combines attention over interface summaries with local equivariant updates to parameter features. The compiler derives the required bindings from operator constraints, allowing the same representation and encoder to handle new combinations covered by its rules. The connection between symmetry, architecture transfer and computational cost therefore follows from the choice of what the graph represents. The held-out-architecture results provide evidence that computations shared at this level can learn useful predictors across changes in transformer architecture. The resource measurements establish feasibility on substantially larger networks; predictive quality at that scale remains to be tested. More broadly, a shared representation makes transfer possible, but does not ensure that the learned features will remain useful across model families or tasks. Training across several families and testing unseen combinations of supported operations would help establish how far interface-based learning extends beyond variation within a transformer family. 9AI USE STATEMENT

# A RELATED WORK 

Weight-space learning treats neural-network parameters as inputs to learned models. Han et al. (2026b) survey weight-space geometry, representation learning and weight generation, together with their applications and benchmarks. 

Parameter-space symmetries. Hidden-unit permutations preserve the functions represented by feedforward networks (Hecht-Nielsen, 1990; Chen et al., 1993). Further symmetries depend on the activation, architecture and parameter values (Godfrey et al., 2022; Grigsby et al., 2023). Zhao et al. (2025) review these symmetries and their applications. Permutation alignment is used to merge independently trained networks (Ainsworth et al., 2023). ScaleGMN incorporates both permutation and activation-dependent scaling symmetries into graph metanetworks (Kalogeropoulos et al., 2024). 

Equivariant tensor models. DWSNets construct permutation-equivariant layers for MLP weight spaces (Navon et al., 2023). Neural functionals process MLP and CNN parameters through equivariant tensor operations (Zhou et al., 2023a), while neural functional transformers introduce attention-based weight-space processing (Zhou et al., 2023b). Universal neural functionals automate equivariant layer construction for collections of tensors with specified permutation actions (Zhou et al., 2024). Their weight-space specification assigns shared permutation identifiers to tensor axes, describing which axes must transform jointly. 

Graph metanetworks. Kofinas et al. (2024) represent neurons as nodes and weights as edge features, and process the resulting graphs with message passing or relational transformers. Lim et al. (2024) construct parameter graphs for diverse neural architectures, including architectural features such as residual connections, normalization and parameter sharing. They relate metanetwork equivariance to automorphisms of the represented computation. Message passing communicates along graph edges, whereas relational transformers permit global interactions between nodes. Invariant pooling provides network-level representations; standard pooling constructions are studied by Zaheer et al. (2017). 

Transformer and adapter symmetries. Transformer-NFN studies the symmetries of multi-head attention and constructs polynomial weight-space layers equivariant to attention-head permutations and continuous query/key and value basis changes (Tran et al., 2025). LoRA adapters have a related factorization ambiguity: invertible transformations of the rank coordinates can preserve the induced weight update. W2T uses QR and SVD preprocessing to address this ambiguity, followed by rank-level and position-level transformers (Han et al., 2026a). 

Large and heterogeneous model collections. SANE processes windows of weight tokens to learn representations of larger networks and generate network parameters (Sch¨ urholt et al., 2024). Falk et al. (2025) learn model representations from heterogeneous networks collected from public model hubs, extending weight-space learning beyond purpose-built model zoos. These settings introduce variation in architecture, training data and parameter count. 

Expressivity. Dayan et al. (2026) establish expressivity equivalences between several permutation-equivariant weight-space architectures. They derive universality results under assumptions on the input weights and characterize settings where those results fail. Their analysis distinguishes 13 PW1, b 1 W2 P W 1, P b 1 W2P ⊤

This appendix collects the symmetries a weight-space representation has to take a position on, and states which of them Γ (Definition 2.1) contains. # F THE COMPILER 

The compiler constructs the representation of Section 2 from a supported PyTorch model and example inputs. It traces the model in evaluation mode and uses tensor shapes, dtypes, operation attributes and parameter-sharing information to infer interfaces and parameter bindings. This inference does not depend on numerical parameter values. Parameters and buffers are subsequently assigned to the corresponding units. The compiler recovers the permutation group defined by its constraints. Function preservation additionally depends on the supported operator, layout and parameter-sharing rules. F.1 OVERVIEW 

Coordinate axes. The compiler records the computational graph and identifies the feature or channel dimension of each relevant tensor. We call this its coordinate axis . Linear layers specify the final feature dimension; convolutions specify the channel dimension. Layout operations, such as transposes, relate coordinate axes across tensors. Axis constraints propagate in both directions through the graph. 

Permutation constraints. Each operation imposes constraints on its input and output permutations. A linear layer without parameter sharing allows independent input and output permutations, with corresponding permutations of its weights and bias. Elementwise addition requires the same permu-tation on both inputs and the output. Concatenation along the coordinate axis requires the output permutation to preserve the input blocks and agree with each input permutation within its block. 23 Figure 6: Interface inference for concatenation and addition. Concatenation splits c at position 2; addition propagates this split to s and h3. The resulting atoms form two interfaces with permutation group S2 × S3. Colors indicate their bindings to rows of W3 and columns of Wo. Input and output coordinates remain fixed. The compiler represents these requirements using three constraints: a glue equates permutations on two coordinate intervals; a split prevents permutations across a boundary; and a fixed axis permits only the identity. 

Interface inference. The compiler propagates splits through glues until no new split is introduced. It then partitions each coordinate axis into intervals between consecutive split positions, called atoms .Atoms identified by glues form equivalence classes. Each class defines an interface with one shared permutation. If any atom belongs to a fixed axis, the entire class is fixed. 

Example. Let h1, h 2, h 3 be the outputs of three linear layers with dimensions 2, 3 and 5, respec-tively: 

hi = Wix + bi, i = 1 , 2, 3,c = concat( h1, h 2), s = c + h3, y = Wos + bo.

The layers do not share parameters, and batch dimensions are omitted. Concatenation introduces a split at position 2 of c. Addition propagates this split to h3 and s. Their first two coordinates share an interface with h1; their remaining three share an interface with h2. The two interfaces admit independent permutations, giving S2 × S3. The input and output coordinates remain fixed. The same partition splits the rows of W3 and the columns of Wo into the corresponding units. See Figure 6 for a schematic illustration. 

Parameter bindings and head permutations. The inferred interfaces determine the permutations of parameters and buffers. Binding rules specify the affected tensor dimensions and slices, including constraints from parameter sharing. Attention-head permutations are handled separately: a head permutation must also permute the corresponding query, key and value projections and the matching blocks of the output projection. Axis inference. Operator rules specify coordinate-axis positions, and layout rules propagate these positions in both directions. Conflicting assignments are rejected. Supported reshapes preserve the coordinate axis without combining it with another non-singleton dimension. If propagation permits several positions for an unassigned tensor, the implementation selects the lowest index. Components without an assigned axis are initialized at tensor dimension 1, using zero-based indexing, and propagation resumes. Tensors for which this assignment is unavailable or inconsistent are rejected. The exactness theorem is conditional on the resulting axis assignment.

Verification. The factor checker verifies each split derivation, inclusion of all initial positions and closure under every glue. It independently computes the connected components of the atom-matching graph and checks the reported interface members, widths and fixed flags. It uses graph connectivity rather than the solver’s union–find implementation. The check establishes correctness relative to the supplied constraints; correctness of the operator rules requires the separate soundness arguments. The head-permutation checker verifies the declared permutations against the supported attention rules and parameter bindings. The parameter and buffer coverage check compares entry counts. H.1 EQUIVARIANCE OF THE ENCODER 

Every encoder stage respects the coordinate action of Γ. Shared pointwise maps and feature nor-malization commute with coordinate permutations. Pooling removes the action on the reduced axis and preserves it on the retained axes; gathering and scattering follow the bindings. Linear transbinding contracts matching coordinate axes and therefore obeys the same transformation law. Fixed-coordinate labels occur only where the action is the identity. Optional observation features must transform with their interface coordinates. Supported module exchanges carry states between the corresponding interfaces, modules and units. These exchanges preserve the codes, layouts and typed bindings used by the encoder. Local aggrega-tion follows the exchanged incidences, while global attention follows the permutation of interface summaries because it has no interface-position encoding. Global-token outputs remain unchanged. Thus the encoder respects the combined action G = Γ ⋊ E.The network-level readouts pool over coordinates and interfaces and are therefore invariant. The per-parameter readout applies a shared decoder to each cell and its scalar codes, so its outputs transform with the represented parameters. These properties do not imply that the encoder distinguishes all states in distinct G-orbits. For Theorem 2.2(b), the implemented exchanges move complete attention heads: their query, key and value parameters, including biases, move together with the corresponding output-projection blocks. In evaluation mode, this merely reorders the sum of projected head outputs and leaves the layer’s output unchanged. The same argument applies to the supported GPT-2 causal attention rule, whose mask is shared across heads. H.2 FEATURE PROVIDERS
