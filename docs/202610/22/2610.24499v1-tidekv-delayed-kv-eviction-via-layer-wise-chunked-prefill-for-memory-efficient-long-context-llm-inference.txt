A B S T R A C T 

Long-context large language model (LLM) inference is important for modern intelligent applications but remains constrained by peak memory during prompt prefill. Existing KV cache compression reduces decoding memory but typically requires full-prompt prefill to preserve global context, retaining a high construction peak. Online chunk-level eviction lowers memory earlier but selects before each layer has observed the complete prompt, potentially degrading cache construction and decoding. We present TideKV, an on-GPU cache-construction architecture using layer-major delayed eviction. TideKV processes all prompt chunks within each Transformer layer, retains full-prompt KV only for the active layer, and evicts at layer end. This schedule preserves full-prompt-aware selection while reducing activation and temporary memory. Experiments across multiple computing platforms show that TideKV preserves the inference quality and final cache size of the evaluated compression methods. At 64K on A100, it reduces the construction-time transient footprint by 83.89%. On RTX 4090, it increases time to first token by only 1.06% at 64K and enables 128K prefill. TideKV also completes 128K on Jetson, whereas matched post-prefill compression runs out of memory on both resource-constrained platforms. These results show that delayed layer-end eviction substantially expands feasible context lengths without sacrificing cache utility. 

## 1. Introduction 

Recent advances in large language models (LLMs) have extended supported context windows to 128K tokens and beyond [1–3], enabled in part by positional-encoding exten-sions such as rotary embeddings [4–6]. This expansion is also driven by applications that require sustained reasoning over long horizons, including retrieval-augmented genera-tion [7], multi-turn autonomous agents [8], long-form code synthesis [9], and extended document comprehension. Such applications routinely require tens of thousands of input tokens in a single inference session and have motivated dedicated long-context benchmarks [10, 11]. At the same time, due to requirements related to data privacy, communi-cation latency, and regulatory compliance, the deployment of LLMs is undergoing a structural shift from centralized cloud infrastructure to edge computing platforms [12–14], such as mobile robots, embodied intelligent systems [15, 16], and in-vehicle autonomous driving modules [17]. However, resource-constrained edge accelerators oper-ate under fixed and often severely limited device mem-ory, creating a fundamental tension with the memory de-mands of long-context inference. During inference, memory is consumed by multiple concurrent components: the key– value (KV) cache accumulating per-layer attention states, the full-sequence hidden-state tensor propagated through Trans-former blocks [18], intermediate MLP activation tensors,

As input sequence length increases, each of these components grows corre-spondingly, with the KV cache scaling linearly with both sequence length and layer count [19]. The aggregate mem-ory pressure renders long-context inference on resource-constrained edge devices increasingly infeasible without systematic memory management. The memory pressure is most acute during the prefill phase, when the entire input prompt must be processed to construct the initial KV cache before decoding begins [20]. For a representative Trans-former model such as Llama-3.1-8B [1], a single 128K-token prompt generates approximately 16 GiB of uncom-pressed KV cache. During prefill, hidden states and tem-porary activations coexist in device memory with the KV cache [21]. The cumulative footprint routinely exceeds the physical memory capacity of edge accelerators, resulting in out-of-memory (OOM) errors that render the service unavailable. Therefore, to enable long-context reasoning on resource-constrained devices, it is necessary not only to control the final KV cache retained during decoding but also to limit the peak memory consumption during the construction of the KV cache. Existing KV cache compression approaches fall into two paradigms, each exposing a distinct limitation under tight memory budgets, as illustrated in Figure 1. Post-prefill selectors such as SnapKV [22] score and compress each layer’s cache after processing the complete prompt at that layer. ## 2. Related work 

In this section, we review the relevant research in the following three aspects: 

2.1. KV-cache selection and compression 

KV-cache compression methods differ in which entries they retain and when they make eviction decisions. Heavy-hitter eviction keeps tokens with high accumulated attention together with recent tokens [24, 25]; StreamingLLM retains a few initial attention-sink tokens plus a sliding window so that a bounded cache supports streaming beyond the nominal context [26]; SnapKV predicts from a prompt-final observation window which positions generation will attend to and compresses per head [22]; and FastGen profiles the per-head attention structure to choose a per-head com-pression policy [27]. A parallel line refines the granularity of the budget: PyramidKV allocates a pyramidal per-layer budget [28]; Ada-KV distributes budget across heads [29]; CAKE casts eviction as adaptive layer-preference budgeting with time-varying token importance [30]; ChunkKV retains semantic chunks rather than isolated tokens [31]. In contrast, query-aware methods load only the KV pages required by the query during the decoding phase [32]. Beyond hard eviction, several methods modify or complement it: KeepKV merges KV entries to limit output perturbation [33]; KVzip targets query-agnostic caches reusable across queries [34]; a recent direction reconstructs KV on demand from a stored residual stream [35]; and, orthogonally to eviction, low-bit quanti-zation compresses each retained entry rather than removing it [36]. Surveys catalog these directions [37]. Post-prefill selectors preserve full-prompt visibility with a compact retained cache; layer- and head-adaptive alloca-tion also informs TideKV’s adaptive variants. Their bot-tleneck is cache construction. Even if layer-wise eviction confines uncompressed KV to one layer, whole-prompt exe-cution still produces full-sequence hidden states and MLP activations, driving the prefill peak (Section 2.3). Thus, constructing a compact cache can exceed device memory (Fig. 1a). TideKV retains the selector and changes compres-sion scheduling to reduce this construction peak. 

2.2. Chunked construction with online eviction 

Online construction processes prompts in chunks and evicts before full-prompt observation (Fig. 1c). InfiniPot dis-tills history as the cache fills, processing later input against compressed history under a fixed budget [38]; KeyDiff uses key similarity for FlashAttention-compatible eviction under a fixed cache budget [23]; EpiCache clusters conversational history into episodes with layer-budgeted eviction and high-lights the peak cost of full-context prefill [39]. Related de-signs use look-once multimodal eviction [40] and trained re-taining heads [41]. Early eviction lowers construction peaks, but later tokens see compressed history and may lose entries relevant to subsequent context. TideKV delays eviction until each layer finishes, preserving uncompressed causal history during prompt encoding and full-prompt visibility for selec-tion. 

2.3. Prefill peak-memory reduction and KV offloading 

A third group of methods targets peak prefill memory by reducing intermediate MLP activations, which can dom-inate the memory footprint [42] (Fig. 1b). Chunked prefill splits the prompt into segments processed sequentially. For prompt length 𝑆 and chunk size 𝐶 , chunking reduces the corresponding temporary activation term to approximately 

𝐶 ∕𝑆 of its full-sequence size, while introducing kernel-launch and latency overheads [43–45]; MST partitions the MLP and LM-head inputs into mini-sequences during train-ing [46], and MOM brings mini-sequence MLP processing to inference while offloading the full KV cache to CPU [42]; PyramidInfer instead computes fewer KV entries in deeper layers during prefill [47]. Offloading-centric systems keep the full KV but relocate it: HeadInfer fetches KV head-group by head-group between CPU and GPU so that an entire layer’s KV never co-resides on the GPU, at a substantial decode-speed cost [48]; FlexGen aggregates GPU, CPU, and disk memory to run inference under tight GPU budgets [49]. Collectively, these methods reduce the peak load during the prefill phase but either retain the uncompressed decoding cache or incur the cost of data transfer between the GPU and CPU. TideKV reduces peak memory usage through chunk-inner execution while keeping execution on the GPU and generating a compressed decoding cache. The approaches differ in prompt visibility and memory use during construction. Post-prefill selectors preserve full-prompt visibility but mainly reduce retained KV; online eviction also lowers the construction peak while exposing later chunks to compressed history. Activation partition-ing and offloading reduce prefill residency but may retain the uncompressed decode cache or move KV to the CPU. TideKV combines layer-major execution with delayed layer-end eviction: full-prompt KV is confined to one active layer, temporary activations to one chunk, and selection observes the complete prompt. Construction stays on the GPU.

## 4. The TideKV framework 

Compressed-cache construction requires an execution schedule that bounds the live working set 𝑀 live and compres-sion workspace Temp without sacrificing the full-prompt visibility needed for accurate selection. TideKV enforces a layer-major residency discipline : it streams the complete prompt through one layer before advancing and delays evic-tion until the layer boundary. This schedule is governed by the single-active-layer residency invariant :At every instant of prefill, full-prompt KV is resident for at most one layer (the active layer), temporary attention/MLP activations are limited to one chunk alongside a prompt-wide hidden-state bridge, and every completed layer holds only its compressed cache. This invariant confines uncompressed KV to one active layer and temporary activations to one chunk, while the hidden-state bridge and completed layers’ compressed caches re-main on the GPU. Delaying eviction until the layer boundary preserves full-prompt visibility for selection. The framework rests on three mechanisms, detailed below and illustrated in Figs. 2 and 3: layer-major chunked prefill that gives each layer full causal visibility (4.1), delayed layer-end eviction that confines full KV to the active layer (4.1), and a memory-controlled compression step that keeps the eviction tempo-raries bounded (4.2). 

4.1. Layer-major delayed eviction 

As shown in Fig. 2, TideKV recasts prefill as a layer-sequential execution schedule: a standard forward pass prop-agates each chunk through all 𝑁 layers, whereas TideKV advances a single layer over all chunks, moving to the next layer only after the current one has consumed the entire prompt. During prefill it maintains three classes of state: completed layers hold compressed caches, the active layer holds full prompt KV for the chunks processed so far (the only full prompt KV resident anywhere), and future layers hold none . ## 5. System implementation 

We implement TideKV as an on-GPU prefill subsys-tem in Hugging Face Transformers. It reuses the pretrained weights and configured Transformer operators, but replaces the standard whole-model prompt traversal with a layer-by-chunk loop. Figure 4 summarizes the four logical compo-nents and the cross-cutting memory accountant. 

Layer-major scheduler and hidden-state bridge. At layer 𝑙 , TideKV stores output chunks 𝐻 𝑙 = { ℎ𝑙 

> 1

, … , ℎ 𝑙 𝑚 }

as the hidden-state bridge to layer 𝑙 + 1 and reuses the same chunk slots as execution advances. The bridge contains 

𝑂 (𝐵𝑆𝑑 model ) elements, whereas temporary attention and MLP activations remain bounded by one chunk. The active layer separately accumulates its uncompressed KV. Causal masks and absolute token positions are maintained for every chunk. 

Layer-end compression and cache management. Af-ter the last chunk, the compressor scores the complete layer-local history, gathers the retained K/V entries and their origi-nal positions, and commits the compressed cache. The cross-layer cache manager then releases the full active-layer KV. It supports rectangular per-layer caches and a variable-length layout for head-adaptive budgets. The layer-end commit is the synchronization point before the scheduler advances to layer 𝑙 + 1 .

Decode adapter and accounting. The decode adapter exposes the compressed initial cache in the structure ex-pected by generation and resumes from true absolute po-sitions rather than the shortened cache length. Throughout cache construction, the memory accountant tracks active allocation, allocator-reserved memory, final physical-cache bytes, and process-level device memory. These signals con-nect the component lifetimes in Fig. 4 to the end-to-end memory behavior evaluated in Section 6. The layer-major order changes orchestration rather than the numerical definition of attention, normalization, or MLP operators, and therefore remains compatible with intra-layer fused kernels such as FlashAttention-2. Its overhead includes chunk dispatch, blockwise scoring, hidden-state bridge traffic, KV gathering and packing, and layer-boundary synchronization; these costs are included in the measured TTFT and quantified in Section 6.6. The components interact at each layer boundary: after the complete prompt is processed, the scheduler triggers compression, the cache manager commits retained KV and releases the full active-layer KV, and the next layer receives the hidden-state bridge. The memory accountant tracks these lifetimes. This coordination preserves full-prompt selection while limiting uncompressed KV residency to one active layer.

6.2. Selector-matched quality and memory 

We first examine whether TideKV lowers the memory required to construct a cache without changing its utility or final size. Each selector is paired with its TideKV counter-part at physical KV budgets of 256, 1,024, and 4,096 tokens and evaluated on LongBench and RULER. Across both benchmarks, the paired variants remain close. Table 3 shows that TideKV preserves the selector-specific LongBench quality profile. Table 4 reports the cor-responding A100 RULER results from 4K to 128K. Across the 12 selector–budget pairs, the five-length mean score changes by −0 .46 to +1 .14 points under TideKV. Differ-ences at individual lengths range from −2 .41 to +2 .61 

points. At 64K and 128K, all four selector families remain close to their matched baselines, with differences of −0 .41 

to +2 .61 points across 24 comparisons. At budget 1,024, the mean absolute difference over these two lengths is 0.19 points. Thus, the agreement between each selector and its TideKV counterpart persists across both cache budgets and context lengths. The matched memory accounting in Fig. 5 identifies where the saving occurs. After prefill, both methods con-verge to the same 15.466-GiB steady allocation, which com-prises the loaded model, the identical 512-MiB compact cache, and the remaining persistent runtime tensors; it is not the model-weight footprint alone. During cache construc-tion, TideKV-Snap lowers peak allocation from 22.748 to 16.639 GiB and the NVML process peak from 24.096 to 17.283 GiB. Subtracting the common steady state isolates a transient footprint of 7.281 GiB for SnapKV and 1.173 GiB for TideKV-Snap, an 83.89% reduction. TideKV therefore reduces the temporary memory required to build the same final cache rather than shrinking the cache used for decoding.

## 7. Conclusion 

TideKV constructs a compressed initial KV cache by streaming prompt chunks within each layer and delaying eviction until the layer has processed the complete prompt. This layer-major schedule preserves full-prompt-aware cache selection while limiting full-prompt KV residency to one active layer and transient activations to one chunk. Matched experiments show that TideKV preserves the underlying selector’s quality profile and final cache size while reducing the memory required to construct that cache. TideKV-Snap cuts the 64K transient construction footprint by 83.89% on A100 and completes 128K inference on both an RTX 4090 and a Jetson AGX Orin; its RTX 4090 RULER score is 65.93. The allocator, backend, and persistent work-load results further show that the active-memory reduction holds across the tested runtime configurations. These results 

Wang et al.: Preprint submitted to Elsevier Page 13 of 15 Delayed KV Eviction via Layer-Wise Chunked Prefill 

make layer-major delayed eviction a practical way to lower the prefill construction peak and extend feasible context length without reducing the final decode-cache budget. The remaining linear bridge and active-layer KV costs warrant further evaluation at larger batch sizes and beyond 128K. Future work will integrate the layer-aware scheduler and layer-end cache transformation with continuous batching, prefix reuse, graph execution, and distributed serving, while exploring adaptive chunk sizing and backend-aware memory management.
