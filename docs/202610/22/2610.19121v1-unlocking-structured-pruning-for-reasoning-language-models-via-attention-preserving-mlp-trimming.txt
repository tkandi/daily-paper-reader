Abstract 

Structured pruning reduces LLM inference costs by removing model components to pro-duce smaller dense models. However, existing methods can cause reasoning performance to collapse on long-form reasoning tasks such as AIME. We propose LayerTrim , a training-free structured pruning method that identifies redun-dant decoder layers and selectively trims their MLP features while preserving attention and decoder depth. LayerTrim is the first training-free structured pruning method designed to pre-serve long-form reasoning without gradients or recovery training. Across three reasoning language models and five benchmarks, Layer-Trim outperforms existing structured pruning methods in most evaluated settings, improv-ing average accuracy by up to 21.4 percent-age points over RESP. On Qwen3-14B , Layer-Trim achieves 1.24 × faster prefill and 19.7% lower peak GPU memory than the dense model, while better preserving reasoning ability. It also achieves the shortest average generation length among evaluated pruned models, while retain-ing the highest average accuracy. These results demonstrate that LayerTrim improves reason-ing efficiency through both structural compres-sion and reduced token generation.

2 Related Work 

Structured pruning of LLMs. Unstructured pruning methods such as SparseGPT (Frantar and Alistarh, 2023) and Wanda (Sun et al., 2024) re-move individual weights, often requiring sparse kernels for practical acceleration. In contrast, struc-tured pruning removes computational units to pro-duce smaller dense models (Kim et al., 2026). LLM-Pruner (Ma et al., 2023) and HFPrune (Zhu et al., 2026) use gradient- or Taylor-based impor-tance criteria, while FLAP (An et al., 2024) com-pensates for pruning errors. Sheared LLaMA (Xia et al., 2024) incorporates additional training, and CoCurve (Gong et al., 2026) considers interactions between structured units. Depth pruning methods such as ShortGPT (Men et al., 2025) identify redun-dant decoder layers using Block Influence, while LaCo (Yang et al., 2024) and GRASP (Liu et al., 2025) reduce model depth through layer merging or replacement. LoRP (Yun et al., 2026) exploits inter-layer redundancy and architectural locality to identify layers for training-free depth pruning. However, these methods do not explicitly consider long-form CoT reasoning, and removing entire lay-ers can degrade reasoning performance. 

Pruning RLMs. Pruning methods developed for non-reasoning LLMs can degrade reasoning per-formance (Ding et al., 2026). RAC (Lucas et al., 2026) uses on-policy reasoning traces for activa-tion reconstruction, while OBC-Prune (Nguyen et al., 2026) extends reasoning-aware calibration through outcome-based token weighting. Both rely on unstructured pruning, requiring sparse kernel support for practical acceleration. RESP (Wang et al., 2025) uses self-generated reasoning traces, gradient-based importance, and progressive recal-ibration for structured pruning, but retains lower reasoning accuracy than dense models across the evaluated benchmarks. 2Preserving long-form reasoning remains a chal-lenge for existing structured pruning approaches. LayerTrim addresses this challenge by selectively trimming MLP features while preserving attention and decoder depth. 

3 Method 

3.1 Motivation 

We first investigate three structural pruning deci-sions for RLMs: (1) which components to prune, (2) which MLP features to retain, and (3) how to allocate pruning across layers. Using Qwen3-14B 

and AIME reasoning traces generated by the dense model, we characterize MLP feature contributions and compare representation errors across pruning settings. 

Pruning targets. Methods such as RESP prune attention and MLPs jointly. We separately compare attention and MLP removal, attention and MLP trimming, and joint trimming of both. Removal deletes modules selected by low Block Influence, whereas trimming reduces internal width across all 40 decoder layers. Across all tested budgets, MLP-only trimming produces lower final-hidden representation error than module removal, attention trimming, or joint trimming of attention and MLPs (Figure 2(b)). These results motivate preserving attention and de-coder depth while reducing MLP width.

3.2 LayerTrim 

Guided by these observations, LayerTrim reduces MLP width while preserving attention and decoder depth. It retains high-importance features and con-centrates pruning in less influential layers. Figure 3 summarizes five stages: reasoning-trace calibra-tion, decoder-layer selection, MLP feature ranking, structured MLP trimming, and the resulting com-pressed model. Algorithm 1 in Appendix A gives the complete procedure. 

Reasoning-trace calibration. Following prior work on pruning RLMs (Lucas et al., 2026; Wang et al., 2025), we collect statistics through teacher-forced forward passes over reasoning traces gener-ated by the dense model. For each layer, we record decoder-block inputs and outputs and MLP inter-mediate activations. These statistics support layer selection and feature ranking without gradients.

4.2 Main Results 

Table 1 compares LayerTrim with existing pruning methods under matched parameter budgets. Layer-Trim achieves the highest average benchmark score among the pruning methods for all three models at both budgets. Its lead over the strongest baseline grows as the budget increases from N = 7 to N =9. At N = 9 , LayerTrim exceeds the strongest baseline average by 6.8, 14.3, and 21.4 percentage points on Qwen3-14B , Phi-4-reasoning-plus ,and Magistral-Small-2506 , respectively. Although calibration uses only AIME 2024 rea-soning traces, LayerTrim’s advantages extend to science and coding. Compared with the strongest baseline on each benchmark, its gains reach up to 20.2 percentage points on GPQA-Diamond, 48.4 on HumanEval, and 35.0 on MBPP+.

Pruning targets. Figure 2(b) shows that MLP trimming produces the lowest final-hidden NMSE. The accuracy results in Table 2 show the same pattern: MLP-only trimming preserves substan-tially higher average accuracy than whole-module removal or attention pruning. It also outperforms joint attention–MLP trimming, which allocates 25% of the pruning budget to attention. These results show that MLP-only trimming minimizes pruning damage among the tested choices in both representation error and task accuracy. 

Feature-Importance score. We compare alter-native criteria for selecting MLP features dur-ing width reduction. Scores based on activations achieve higher average accuracy than weight-only ranking. Our feature-importance score achieves the highest average accuracy among the evaluated criteria, outperforming activation-only ranking and FLAP’s variance-based score. 

Layer selection and distribution. The accuracy results in Table 2 support the BI-based allocation in Figure 2(d): selecting low-BI layers outperforms random selection and all-layer trimming in average accuracy. Block BI also achieves higher average ac-curacy than MLP-only BI, which measures changes in the residual stream before and after the MLP up-date. This supports measuring redundancy across the full decoder block rather than the MLP update alone. 

Number of selected MLPs. Under a fixed bud-get, K = 1 .5N achieves the highest AIME25 accu-racy, while K = 3 N achieves the highest GPQA-Diamond accuracy. The default K = 2 N gives the highest average accuracy by a small margin, pro-viding a practical balance between the two tasks. 

4.4 Efficiency Measurement Measurement settings. We measure prefill la-tency, decode latency, and peak GPU memory in bfloat16 at batch size 1 on a single NVIDIA RTX 6000 Ada (48 GB). Prefill latency is measured on a 2,048-token prompt, and decode latency is aver-aged over 128 greedy decoding steps with a static KV cache. Each configuration runs two warm-up iterations followed by ten timed runs, synchro-nized using torch.cuda.synchronize() . We re-port median latency and peak GPU memory dur-ing inference, excluding model loading and prun-ing overhead. All methods are evaluated under matched parameter budgets. 

Efficiency results. Table 3 compares inference efficiency across three RLMs at two pruning bud-gets. At the higher pruning budget, LayerTrim achieves prefill speedups of 1.24 ×, 1.22 ×, and 1.27 ×, and decode speedups of 1.21 ×, 1.22 ×, and 1.24 × on Qwen3-14B , Phi-4-reasoning-plus ,and Magistral-Small-2506 , respectively. Peak GPU memory is reduced by 19.7%, 20.3%, and 20.8% on the corresponding models compared with their dense counterparts. 6 Conclusion 

LayerTrim reduces the inference cost of reasoning language models by selectively trimming MLP fea-tures while preserving attention and decoder depth. It uses dense-model reasoning traces to identify re-dundant layers and retain high-importance features, without gradients or recovery training. Across three models and five benchmarks, LayerTrim achieves higher average accuracy than the evaluated struc-tured pruning baselines at both pruning budgets, while achieving comparable inference speedups. LayerTrim offers a step toward more efficient de-ployment of reasoning language models through training-free structured pruning. 8Limitations 

Our evaluation focuses on three reasoning language models and five benchmarks covering mathemati-cal reasoning, scientific reasoning, and code gener-ation. Although LayerTrim outperforms the eval-uated pruning baselines in most settings, experi-ments on additional model architectures, scales, and reasoning tasks would help assess its generaliz-ability. We also evaluate fixed pruning budgets and layer allocation settings. Adapting these choices to individual models and tasks may further improve the trade-off between model compression and rea-soning accuracy. 

Ethical considerations 

Structured pruning modifies the internal architec-ture of language models and may affect their rea-soning behavior. Although LayerTrim aims to pre-serve reasoning accuracy, pruned models may still produce incorrect answers, incomplete reasoning traces, or unexpected outputs. These risks should be considered when deploying compressed models in applications where reasoning accuracy is critical. Our experiments use publicly available models and benchmarks and do not involve human participants or the collection of personal information.

B Main Evaluation Implementation Details 

Pruning budgets. For each model, we set the pruning budget to BN = N P layer , where Player is the number of attention and MLP projection param-eters in one original decoder layer and N ∈ { 7, 9}.All methods use the same target budget, with small differences in actual removal counts because heads and channels are removed in whole units. 

LayerTrim allocation. LayerTrim selects K =2N MLPs using Block Influence and retains the same width m in each selected MLP. Removing one gated-MLP feature affects a gate row, an up row, and a down-projection column, totaling 3C

parameters. The realized budget is 3CK (I − m),with m set by Equation 3. 

Calibration settings. All methods use the same 24 AIME 2024 reasoning traces generated by the corresponding dense model at temperature 0.6, top-

p 0.95 , and seed 0. LayerTrim uses the complete prompt and up to the first 2,048 generated tokens from each trace for statistics collection. 

Baseline implementations. For all baselines ex-cept RESP, we use the authors’ official imple-mentations, adapted to our models and matched-budget. We reimplement RESP using the public GISP (Wang et al., 2026) repository, following the GISP-based structural pruning procedure de-scribed in the RESP paper (Wang et al., 2025), with decode-only scoring and calibration regenera-tion. All baselines use the shared calibration data described above. 

Generation settings. Dense and pruned models use the corresponding native reasoning-enabled chat template. Magistral uses its native Tekken tokenizer and official system prompt. Sampling uses temperature 0.6, top-p 0.95 , and seeds 0, 1, and 2. Each seed produces one response per prob-lem. We set the maximum output length to 32K tokens. Inference uses BF16 in vLLM. 

Answer and code scoring. We evaluate AIME and GPQA-Diamond by exact matching of the ex-tracted final answers. For coding benchmarks, we report pass@1 using HumanEval’s original tests and MBPP+’s extended tests.
