MOSAIC: Multi-Objective Search for Allocating Inference Cache Across
LLM Decoder Layers

Abstract
The Key-Value (KV) cache is the main mem-
ory bottleneck of long-context LLM inference.
Token eviction methods such as SnapKV, H2O,
AdaKV and L2Norm shrink it, but they give
every transformer layer the same budget, al-
though layers differ in which tokens they need.
We present MOSAIC, a multi-objective neural
architecture search that learns per-layer KV-
cache budgets for any eviction method. One
search maps the trade-off between average bud-
get and task score; its best allocation transfers
to every target budget without further search,
and an optional budget-constrained search re-
fines it.
Across four eviction methods on
Llama-3-8B-Instruct and Mistral-7B-Instruct-
v0.2, MOSAIC beats uniform allocation in 146
of 154 (task, method, budget) settings, by up
to +48 points on RULER and +11.9 on Long-
Bench (LCC). It reaches the score of uniform
allocation with up to 4× less KV cache (75%
smaller), and with half the cache or less in
17 Llama settings. The transferred allocation
alone beats uniform in 75 of 87 Llama settings,
so a single 9–40 GPU-hour search serves
every budget.
Against EvolKV, MOSAIC
explores a ∼1040× larger search space with
4× fewer evaluations and 18% fewer GPU-
hours per budget, and scores higher in 5 of 6
settings. The learned allocations consistently
favour a small set of middle layers.

Introduction
Long-context inference with large language models
(LLMs) is limited by the memory of the key-value
(KV) cache, which grows linearly with sequence
length and batch size (Kwon et al., 2023): a 30B-
parameter model with batch size 128 and sequence
length 1024 already needs 180 GB of KV cache
(Zhang et al., 2023). Token eviction methods like
H2O (Zhang et al., 2023), SnapKV (Li et al., 2024)
and L2Norm (Devoto et al., 2024) address this by
selectively dropping cache entries based on token
importance, and AdaKV (Feng et al., 2025) builds
on them by distributing a layer’s budget adaptively
across its attention heads. However, these meth-
ods apply the same memory budget to every trans-
former layer. Layer-wise allocation schemes exist,
but they either fix the shape of the allocation in
advance (Cai et al., 2025), derive it from atten-
tion statistics (Qin et al., 2025), or optimize layer
budgets one group at a time at one budget and
rescale the result to others (Yu and Chai, 2025).
These schemes already exploit layer differences;
MOSAIC instead searches all layers jointly once
and transfers the result to every budget. In our
searches, a few middle layers consistently receive
more than their uniform share, so a uniform alloca-
tion spends cache on layers that need little while
starving the ones that need more.
This paper introduces MOSAIC, a method that
automatically optimizes per-layer KV-cache bud-
gets under a target memory constraint using multi-
objective neural architecture search. Rather than
hand-tuning layer-specific heuristics or optimizing
layers group by group, MOSAIC searches the per-
layer budget space jointly, one budget per decoder
layer (32 for Llama-3-8B, up to 1027 configurations
on its search grid), using Bayesian optimization
guided by a surrogate MLP (Figure 1). MOSAIC
is to KV-cache allocation what static quantization
is to model quantization: just as post-training quan-
tization calibrates offline on a small calibration
set (Frantar et al., 2023; Xiao et al., 2023), MO-
SAIC fixes each layer’s budget offline on calibra-
tion data, so inference adds no per-prompt alloca-
tion step. Methods such as CAKE and Ada-KV in-
stead adapt the budget to each prompt at inference
time, as dynamic quantization computes its ranges
at run time. We evaluate MOSAIC across four evic-
tion methods (SnapKV, H2O, AdaKV, L2Norm)
on Llama-3-8B-Instruct and Mistral-7B-Instruct-
v0.2 (all four methods; on LongBench Summa-

MOSAIC versus EvolKV. The closest prior
work, EvolKV (Yu and Chai, 2025), searches per-
layer budgets with CMA-ES (Hansen and Oster-
meier, 2001) group by group, eight layers at a
time, at a target budget fixed in advance. MO-
SAIC instead searches all layer budgets jointly, so
one search spans about 1040 times more allocations
than one EvolKV group search, across a budget–
score Pareto front, selects a reusable anchor, and
optionally refines it at each deployment budget;
on Code it beats EvolKV at every budget, both
searching once (+1.3 to +2.1) and per budget at
EvolKV’s compute (+0.8 to +1.7, Appendix D),
and even searched once, MOSAIC’s winner out-
performs EvolKV’s per-budget searches at every
budget where both ran (Section 6).
Our contributions are: (i) MOSAIC, a four-stage
workflow (joint per-layer search, budget–score ex-
ploration, winner rescaling, optional per-budget
refinement) whose single search yields a winner
that transfers across budgets without further search;
(ii) an evaluation across four eviction methods, two
models and two benchmarks, where MOSAIC im-
proves over uniform allocation for every method,
with gains of up to +48 points on RULER; and (iii)
an analysis of the learned allocations, which favour
a small set of middle layers.

Related Work
Token eviction.
Eviction methods reduce KV-
cache memory by retaining only the tokens judged
important. H2O (Zhang et al., 2023) keeps “heavy
hitters”, tokens with high accumulated attention,
together with a window of recent tokens, as do
StreamingLLM (Xiao et al., 2024), Scissorhands
(Liu et al., 2023) and FastGen (Ge et al., 2024)
with sink, persistent and per-head criteria. SnapKV
(Li et al., 2024) selects, for each attention head,
the prompt positions that receive the most atten-
tion from an observation window at the end of
the prompt. L2Norm (Devoto et al., 2024) keeps
the tokens whose keys have the lowest L2 norm,
which correlates with high attention, without com-
puting attention scores. KeyDiff (Park et al., 2025)
also avoids attention scores, keeping keys that are
geometrically distinctive from the others, which
makes it compatible with FlashAttention (Dao,
2024). QUOKA (Jones et al., 2026) selects key-
value pairs for prefill from the keys aligned with
a subset of representative queries. These methods
decide which tokens to keep; how much cache each
layer should receive is a separate question, which
MOSAIC addresses.
Static and dynamic budget allocation. A sec-
ond line of work allocates a fixed total budget
non-uniformly instead of changing how tokens are
scored. Dynamic methods recompute the allocation
for every prompt, as dynamic quantization com-
2


putes its ranges at run time: Ada-KV (Feng et al.,
2025) allocates budget adaptively across the heads
of a layer, CAKE (Qin et al., 2025) derives per-
layer budgets from layer preferences measured on
each prompt’s attention patterns, and SqueezeAt-
tention (Wang et al., 2025) shifts budget between
two layer groups. Static methods fix the allocation
before inference: PyramidKV (Cai et al., 2025)
assigns layer budgets following a hand-designed
pyramidal shape, larger in lower layers and smaller
in higher ones; PyramidInfer (Yang et al., 2024)
keeps per layer the context attention consistently
selects, less with depth; HeadKV (Fu et al., 2025)
and DuoAttention (Xiao et al., 2025) fix head-level
allocations offline. MOSAIC is static in the sense
of static quantization, calibrating the allocation of-
fline for each model and eviction method. Closest
to our work, EvolKV (Yu and Chai, 2025) treats
per-layer budgets as optimization variables, par-
titions layers into groups, and runs evolutionary
search on one group at a time against downstream
task score at one target budget; its main results
then extend that allocation to larger budgets by pro-
portional rescaling, without further optimization.
MOSAIC shares this rescaling step but finds the
allocation to rescale differently, searching all lay-
ers jointly across budgets rather than at one target
budget (Section 6).
Neural architecture search. Multi-objective
NAS trades off competing goals such as accuracy
and latency along a Pareto front (Elsken et al.,
2019) (more related work in Appendix G). MO-
SAIC adopts this multi-objective formulation for
KV-cache allocation but uses its own search proce-
dure (Section 3): a classifier-guided optimizer built
for this problem, which needs only a few hundred
evaluations per search.

search at B128 (Appendix H). A search evaluates at
most 200 of them in Stage 1 and 150 in Stage 4 (Ap-
pendix H), so every layer budget must be chosen
jointly from a vanishing fraction of the space.
Search step. All stages share one classifier-
guided Bayesian optimization procedure (cf. Tiao
et al., 2021). After each evaluation, the archive is
non-dominated sorted (Deb et al., 2002), an MLP
classifier (two hidden layers of 32 units) is trained
to separate the rank-1 configurations from the rest,
and differential evolution (Storn and Price, 1997)
maximizes the classifier’s probability of rank 1 over
[0, 1]L to propose the next configuration, one eval-
uation per iteration. We call these BO proposals;
stopping rules are in Appendix H.
3.2
Search Procedure (MOSAIC —
Four-Stage Pipeline)
Why four stages. An unconstrained search returns
configurations at arbitrary average budgets, so a
configuration it finds cannot be compared directly
with uniform allocation at a fixed budget B. MO-
SAIC therefore selects one winner shape from the
search (Stages 1–2) and rescales it to each target
budget (Stage 3). This already gives a configura-
tion at every budget without further search, and
the pipeline can stop here. Stage 4 is optional: it
searches at a fixed budget for a configuration better
than the rescaled winner (Figure 1).
Tasks. MOSAIC searches separately for each
task and eviction method.

Re-evaluate every configuration on the Stage 1
Pareto front (typically 10–20 configurations) on
the full test data, and keep the winner shape:
the shaped configuration with the highest full-data
score. This winner becomes a universal anchor for
all subsequent budget-constrained searches.

Setup

Task and Method Patterns
Gains are largest on RULER. Within LongBench
they are largest on Code, smaller on the two QA cat-
egories and smallest on Summarization, an order-
ing that holds for every method (Table 1). Across
methods, H2O shows the largest RULER gains
(+18 to +33 at B1024–B2048). AdaKV, which
already allocates budget adaptively across heads
within a layer, still gains from reallocation across
layers: +4.1 to +8.3 on RULER and up to +1.98
on LongBench. L2Norm shows the largest Long-
Bench gains (Code +4.9 to +9.5), but from a weak
baseline: at B128 its uniform Single-Doc QA score
is 10.2, against 33.0 for SnapKV.

Conclusion
One MOSAIC search per task learns per-layer KV-
cache budgets that transfer to every budget, beating
uniform allocation in 146 of 154 settings with up
to 4× less KV cache.

Limitations and Future Work
• Scope: we evaluate two dense decoder mod-
els; on Mistral-7B-Instruct-v0.2, LongBench
Summarization has only Stage 1 for SnapKV,
H2O and AdaKV, and we will add Stages 2–4
for it in a future version of this paper.
• Future work: we plan to extend MOSAIC
to other model families, such as mixture-of-
experts models and hybrid architectures that
combine attention with convolutional or state-
space layers (e.g., LFM and Mamba-based
models), and to more recent eviction meth-
ods such as KeyDiff (Park et al., 2025) and
QUOKA (Jones et al., 2026).

a case study.
Table 11
rescores the 24 configurations of one SnapKV
Stage 4 search (Code, B512) on a 30% subsam-

data. In this cell the larger subsample reduces the
optimism (+1.37 against +5.10 points), ranks the
configurations closer to the full data (τ 0.75 against

subsample does not. This is a single cell, chosen be-

subsample also costs about three times as much per
evaluation. A larger subsample reduces the noise
but does not remove it: on the Stage 1 fronts, which

configuration from the calibration-top one in 4 of

points; Figure 6d). MOSAIC therefore re-evaluates
its candidates on full data at either ratio.

Further Related Work
Complementary cache compression. Other tech-
niques shrink the KV cache along axes that per-
layer allocation leaves untouched and can be com-
bined with it: Quest (Tang et al., 2024) keeps the
full cache but loads only the pages relevant to
each query, KIVI (Liu et al., 2024b) and KVQuant
(Hooper et al., 2024) quantize keys and values to a
few bits, and MiniCache (Liu et al., 2024a) merges
the caches of adjacent layers.
Searching once for many budgets. Once-for-
All (Cai et al., 2020) trains one network and spe-
cializes it to many hardware budgets; MOSAIC
similarly searches once and rescales the result to
many cache budgets. Gradient-based NAS such
as DARTS (Liu et al., 2019) does not apply here,
because the task score is not differentiable in the
per-layer token budgets.

Per-layer floor and cap.

LongBench runs and 4096 for RULER; Stages 3

Stopping rules.

calibration score stopped improving, so run lengths
