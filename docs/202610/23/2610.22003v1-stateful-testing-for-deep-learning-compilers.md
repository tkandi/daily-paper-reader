## 摘要
现代深度学习编译器会以惰性方式编译模型，并在多次调用之间缓存产物。即使某次后续调用在孤立执行时是正确的，保留的编译器状态也可能使其产生错误。我们对 PyTorch、JAX 和 TensorFlow 中公开报告的 26 个问题进行分析后发现，检测此类缺陷需要构造调用序列：先建立编译器状态，再暴露故障。我们提出 Rondo，一种有状态测试方法，将每个测试用例表示为一个模型及其对应的调用序列。Rondo 对调用序列进行变异，并采用由编译行为引导的马尔可夫链蒙特卡洛采样器，以优先探索较少观察到的行为。其三路差分预言机比较未编译执行、重置编译器状态下的编译执行，以及保留编译器状态下的编译执行。Rondo 通过在保留和重置状态的条件下重放同一次调用，同时保持输入和程序状态不变，来确认有状态缺陷；随后在保留原始缺陷的前提下缩短调用序列。我们在四个深度学习框架上、使用 24 种常见模型架构对 Rondo 进行了评估。Rondo 检测到 117 个缺陷，其中包括 35 个有状态缺陷。我们提交了 39 份缺陷报告，其中 18 份涉及有状态缺陷；开发者确认了 35 份报告，其中 16 份涉及有状态缺陷，并修复了 18 个缺陷，其中包括 11 个有状态缺陷。在所比较的方法中，Rondo 实现了最高的行为覆盖率和编译器 Python 源代码行覆盖率，告警精确率达 99.26%。它缩短了 117 个调用序列中的 44 个，使这 44 个序列的长度平均减少 83.34%。

## Abstract
Modern deep learning compilers compile models lazily and cache artifacts across invocations. Retained compiler state can make a later invocation incorrect even when it is correct in isolation. An analysis of 26 publicly reported issues in PyTorch, JAX, and TensorFlow shows that detecting such bugs requires sequences that first establish compiler state and then expose a failure. We present Rondo, a stateful testing method that represents each test case as a model paired with an invocation sequence. Rondo mutates invocation sequences and uses a Markov chain Monte Carlo sampler guided by compilation behavior to favor rarely observed behaviors. Its three-way differential oracle compares execution without compilation, compiled execution with compiler state reset, and compiled execution with state retained. It confirms stateful bugs by replaying the same invocation with state retained and reset while preserving inputs and program state, then shortens sequences while preserving the original bug. We evaluate Rondo on four deep learning frameworks using 24 common model architectures. Rondo detects 117 bugs, including 35 stateful bugs. We submit 39 bug reports, including 18 for stateful bugs; developers confirm 35 reports, including 16 for stateful bugs, and fix 18 bugs, including 11 stateful bugs. Rondo achieves the highest behavior coverage and compiler Python source-line coverage among the compared methods, with 99.26% alarm precision. It shortens 44 of 117 invocation sequences, reducing the lengths of these 44 sequences by 83.34% on average.
