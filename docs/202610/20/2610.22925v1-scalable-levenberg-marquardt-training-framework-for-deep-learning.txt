Abstract—The Levenberg-Marquardt (LMA) algorithm is a
widely used nonlinear least-squares solver in scientific computing,
known for its rapid convergence. Recent studies show that for
small-scale neural networks, LMA provides better convergence
and architectural robustness than first-order optimizers like
Adam. However, as a second-order method, LMA imposes
prohibitive memory and computational costs. These costs are
primarily from the Jacobian matrix, whose dimensions scale with
both the number of samples and parameters. This bottleneck
limits LMA in its traditional applications and prevents its use in
large-scale neural networks.
Recent efforts scale LMA using preconditioned conjugate
gradient (PCG) solvers to avoid materializing the Jacobian.
However, PCG only approximates the solution, and an accurate
approximation requires many network propagations and a task-
specific preconditioner. Other studies optimize LMA to reduce
costs, but they restrict their methods to specific tasks or network
architectures. As a result, LMA remains impractical for training
general large-scale neural networks.
In this paper, we propose LeMA, a distributed LMA algorithm
for large-scale neural network training on multi-GPU platforms.
The contributions of LeMA are twofold. First, an exact dual
formulation of LMA removes the memory dependence on the
parameter dimension. Second, a Jacobian sharding strategy
computes Jacobian shards on the fly and in parallel to avoid
materializing the full Jacobian.
For large-scale neural networks, LeMA reduces the memory
footprint of LMA from quadratic in the number of parameters
to quadratic in the batch size. This advancement makes exact
LMA steps feasible for billion-parameter models without approx-
imate PCG solves. Furthermore, for a convolutional neural net-
work with 1,000,022,632 parameters on an 8-GPU node, LeMA
achieves a 7.97× speedup over a single GPU, corresponding to
a 99.7% strong scaling efficiency.

I. INTRODUCTION
The Levenberg-Marquardt (LMA) algorithm [1], [2] is a
standard solver for nonlinear least-squares problems in sci-
entific computing [3], [4]. Each LMA step solves a damped
Gauss-Newton system. A damping factor λ moves the step
between the Gauss-Newton method and gradient descent,
allowing LMA to converge quickly near a minimum while
remaining robust far from it. Since Hagan and Menhaj [5]
applied LMA to neural networks, many studies have used
it to train small models containing up to several thousand
parameters [6]–[13].
Despite its fast convergence, LMA is difficult to scale to
large neural networks. The bottleneck lies in the linear system
solved at each step, which involves an M × M coefficient
matrix JT J+λ diag(JT J) and an N ×M Jacobian matrix J,
where N is the batch size and M is the number of parameters.
This formulation creates an O(MN +M 2) memory footprint.
For a model with only one million parameters, the coefficient
matrix alone contains a trillion elements. The computational
cost is equally high. Evaluating J requires N backward
propagations, computing the coefficient matrix takes O(M 2N)
time, and solving the linear system takes O(M 3) time. These
extreme memory and computation demands prevent the exten-
sion of LMA to large-scale training.
To address these memory bottlenecks, several studies and li-
braries [14]–[18] use preconditioned conjugate gradient (PCG)
solvers [19] to avoid materializing the large matrices. PCG
computes an approximate solution to the linear system Ax =
b using only matrix-vector products Av, without explicitly
constructing A. For instance, both the optimization toolkit
PETSc [17] and the Python library JAXopt [14] provide
LMA implementations with a PCG option. However, applying
PCG to LMA requires numerous network propagations to
ensure a robust approximation. Additionally, PCG relies on a
suitable preconditioner matrix, and selecting an effective one
is highly task-specific [20].
As an exact alternative to PCG, Bilski et al. [21] decompose
LMA into independent tasks where each neuron computes its
own Jacobian and weight updates. However, this approach
assumes each neuron produces a single output. It is therefore
incompatible with convolutional layers, which share parame-
ters to generate multiple spatial outputs.
Our goal is to design an exact LMA framework for general
deep learning tasks, without relying on PCG approximations or
specific network architectures. We focus strictly on the systems
engineering challenges to make each exact LMA step feasible
and fast at scale, as the numerical convergence properties of
LMA fall beyond the scope of this work. Di Marco [12],
[13] utilizes a dual form of the simpler Levenberg method,
which applies λI as the damping term. This approach suc-
cessfully reduces the memory footprint from O(MN + M 2)
to O(MN + N 2), making it feasible to train large neural
networks where M ≫N. Inspired by this, we derive and
arXiv:2610.22925v1  [cs.LG]  16 Oct 2026


implement an exact dual formulation specifically for LMA. To
further reduce memory consumption, we design a partitioning
strategy that avoids storing the full Jacobian J. This design
allows us to parallelize LMA and accelerate training across
multiple GPUs.
We present LeMA, a multi-GPU Levenberg-Marquardt train-
ing framework for neural networks. We summarize our main
contributions as follows:
• We derive an exact dual formulation for LMA, which
shifts the linear system from the parameter dimension to
the batch dimension (Section III-A).
• We provide guidelines for designing robust residual func-
tions tailored for LMA (Section III-B).
• We design a partitioning and parallelization strategy to
further reduce the memory footprint and accelerate com-
putation (Sections IV-B and IV-C).
In addition to these core contributions, we introduce several
supplementary optimizations detailed in Sections III and IV.
We evaluate LeMA on image classification tasks across
various neural networks. LeMA scales LMA to models with
up to 1,000,022,632 parameters and achieves a 99.7% strong
scaling efficiency on 8 GPUs. For LeNet-5, which is small
enough for the standard LMA form to fit in GPU memory,
LeMA achieves an 8.3× speedup and a 33× reduction in
memory footprint on a single GPU compared to a standard
LMA implementation. When running on 8 GPUs, it delivers a
37.8× speedup and a 41× memory reduction over a standard
multi-GPU LMA baseline.
The rest of this paper is organized as follows. Section II
reviews LMA and Jacobian computation within deep learning
frameworks. Section III derives the exact dual formulation and
provides residual representations for common loss functions.
Section IV details the distributed implementation of LeMA
and analyzes its associated costs. Finally, Section V evaluates
the performance of LeMA.

Our framework assumes that each sample in a batch is

C. The LeMA Algorithm
Algorithm 2 presents the complete LeMA procedure. We
collectively refer to JT J in the standard form (1) and JD−1JT
in the dual form (4) as the Gram matrix G. LeMA se-
lects the dual form when M > N and the standard form
otherwise, so G has min(M, N)2 elements. The memory
footprint thus drops from O(MN + M 2) in Algorithm 1 to
O(MN + min(M, N)2), and Section IV-B further eliminates
the O(MN) term of the Jacobian. In addition, LeMA forms
G once per iteration and reuses it across rejected steps, which
only change λ, and carries the residuals of an accepted step
over to the next iteration.
IV. LEMA IMPLEMENTATION
This section describes how LeMA executes Algorithm 2
on P GPUs. Section IV-A covers the distributed setup, Sec-
tion IV-B the partitioned computation of both forms, Sec-
tion IV-C the evaluation of Jacobian shards, and Section IV-D
the resulting cost.
A. Distributed Setup
LeMA runs P processes in the Single Program, Multiple
Data (SPMD) model [25], one per NVIDIA GPU, and commu-
nicates through torch.distributed [22]. Each process
belongs to two communication groups. Large tensors move
between GPUs over NCCL [26], NVIDIA’s collective com-
munication library, and small scalars such as local loss values
move between hosts over Meta’s Gloo library [27]. Keeping
the scalars on the host avoids many small host-to-device and
device-to-host copies that would otherwise interrupt the GPU
streams.
All parameters are stored in one flat tensor, and the weights
of each layer are mapped to their positions in it. A VJP
therefore returns a single M-dimensional gradient, and no per-
layer gradients need to be concatenated.
Each process loads its own mini-batch of N/P samples
instead of receiving part of a scattered global batch, and the
P mini-batches together form the global batch. PyTorch’s
DistributedSampler [22] keeps the mini-batches dis-
joint. The dual form also needs the global batch on every
process (Section IV-B2).

of a shard come from S single-sample VJPs. Running them
one after another sends a single sample through the network at
a time and leaves most of the GPU idle. JAC instead vectorizes
the VJPs of a slice of L samples with vmap [22] and obtains
an L×M Jacobian slice per call (Algorithm 5). The per-sample
function also returns the residual as an auxiliary output, so
the residuals need no extra forward pass. Vectorizing L VJPs,
however, also stores L times as many activations, so the slice
size L trades execution speed against memory.
We slice the computation of JT v in the dual form in
the same way. One VJP over all N/P local samples would
compute it, but its forward pass would keep the activations
of all of them at once. VJP therefore handles one slice of L
samples per call, and Algorithm 4 sums the results. Unlike

V. EVALUATION
LeMA changes how an LMA step is computed, not which
step is taken. As long as it computes the same update as
LMA, it inherits the convergence behavior of LMA, which
prior work has studied for neural networks [5], [6], [12]. We
therefore evaluate correctness and performance rather than
training accuracy. We first verify numerically that the dual
form matches an FP64 reference update (Section V-B). We
then measure how far LeMA extends the model size on one
GPU (Section V-C), compare the two forms (Section V-D), and
evaluate strong scaling (Section V-E). Finally, we study the
shard and slice sizes (Section V-F) and split-K (Section V-G).
Although LeMA implements both the standard and dual
forms of LMA, we treat the standard form as the baseline for
most experiments because the number of parameters typically
exceeds the batch size in practice.
A. Experiment Setup
1) Hardware and Software: All experiments are conducted
on a server equipped with two Intel Xeon Platinum 8275CL
CPUs and eight NVIDIA A100-SXM4 GPUs. Each GPU
features 80 GB of memory, a peak memory bandwidth of
2,039 GB/s, and a peak FP32 performance of 19.5 TFLOPS.
The GPUs are fully connected via NVLink 3.0, providing
600 GB/s of bidirectional bandwidth per GPU.
We implement LeMA in Python 3.14 using PyTorch 2.14,
CUDA 12.6, and NCCL 2.29. All computations are performed
in single precision (FP32).
2) Datasets and Models: We use MNIST [29], which has
60,000 training and 10,000 test images of 28 × 28 pixels. The
whole dataset is pinned in host memory [30].
To reach the billion-parameter scale on MNIST, we take a
convolutional neural network (CNN) with two 3 × 3 convo-
lutional layers of 32 and 64 channels, a 2 × 2 max pooling,
and two fully connected layers, with ReLU after each hidden
layer, and widen its hidden fully connected layer to h neurons.
The model has M = 18,826+9,227h parameters. We call the
models with h = 10,836 and 108,378 CNN-100M and CNN-
1B, with 100,002,598 and 1,000,022,632 parameters. Experi-
ments that need the standard LMA form use smaller models:
LeNet-5 [31] with ReLU and max pooling (M = 61,706)
and a 784-16-10 MLP (M = 12,730). All models use the CE
residual in (5) with ϵ = 10−9.
3) Measurements: We split the step time into four phases:
Jacobian shard evaluation (JAC), the Gram block products

for the slowest process, and the rest, such as VJP, the linear

Section III-A proves that the dual form yields the same

batch sizes N = 1,024 and 8,192 (both smaller than M), and
an MLP with N = 4,096 < M and N = 16,384 > M. For

G. Split-K of the Gram Block Products
We evaluate split-K (Section IV-B2) on a single block
product and on a full step. The baseline computes each block
product with one torch.mm call, which uses cuBLAS. In
the microbenchmark, we multiply two random S × M shards
with M ≈108 or 109, matching CNN-100M and CNN-
1B, and S from 1 to 64, skipping shapes that do not fit in
memory. Both variants write into a strided block of a larger
matrix, as in Algorithm 4, and split-K uses its default of 16
chunks per SM (1,728 chunks on an A100). After two warm-
up runs, we repeat each product for at least 0.5 s and report the
mean time from CUDA events. A block product reads 8SM
bytes in FP32, so a bandwidth-bound kernel should take time
proportional to S.
A plain GEMM does not (Figure 5(a)). From S = 2 to 8,
the time of torch.mm stays at 12.9–13.6 ms for M ≈108
and 130–135 ms for M ≈109 while the data grow 4×, so
the GEMM is limited by its parallelism. Split-K follows the
data volume and is 1.27–11.0× faster for S ≤8. For the
CNN-1B shards with S = 4, it cuts the time from 131.3 ms to
22.9 ms (5.7×), which corresponds to 1.40 TB/s, or 69% of the
peak memory bandwidth. For S ≥16, the GEMM already has
enough parallelism and split-K is up to 9.8× slower, so LeMA
applies split-K only for S ≤8. The result is not sensitive to the
chunk count, which changes the time by at most 12% beyond
8 chunks per SM. Split-K changes the products by a relative
difference of at most 4.5×10−5 because of the different FP32
summation order.
For the full step, we train CNN-1B on 8 GPUs with the con-
figuration of Section V-E. Each GPU computes N 2/(PS2) =
512 block products per step. Without split-K, they take 66.9 s,
70% of the 95.0 s step, which matches 512 products of 131 ms
each in the microbenchmark. Split-K reduces them by 5.7× to
11.8 s and speeds up the step by 2.39× to 39.8 s (Figure 5(b)).
The peak memory stays at 60.0 GB per GPU.
VI. CONCLUSION AND FUTURE WORK
We presented LeMA, a multi-GPU neural network train-
ing framework based on the Levenberg-Marquardt (LMA)
algorithm. By utilizing an exact dual formulation that shifts
the linear system from the parameter dimension to the batch


dimension, alongside efficient partitioning strategies and Split-
K optimizations, we successfully scale LMA to train models
with billions of parameters. Consequently, LeMA achieves
significant speedups over standard LMA implementations.
We identify several limitations in the current design of
LeMA, which direct our future work. First, our assumption
that each input sample is processed independently prohibits
the use of intra-batch operations like Batch Normalization. We
plan to extend LeMA to support these layers without intro-
ducing significant overhead. Second, the dual form repeatedly
evaluates all global Jacobian shards for each local block of
the Gram matrix JD−1JT . This re-evaluation makes Jacobian
computation a primary bottleneck. Since inter-process commu-
nication time is currently negligible, future implementations
could exchange evaluated shards across GPUs via fast NVLink
to avoid this redundant computation. Third, LeMA gathers the
full coefficient matrix on every GPU and solves the linear
system redundantly. Integrating a distributed solver, such as
NVIDIA cuSOLVERMp [32], would allow us to partition the
coefficient matrix and solve the system in parallel, yielding
further memory and speed improvements. Finally, this work
focuses strictly on systems engineering to optimize memory
and execution time. We use a basic damping strategy and
acceptance criterion, and leave refining them and evaluating
convergence on practical deep learning tasks to future work.
