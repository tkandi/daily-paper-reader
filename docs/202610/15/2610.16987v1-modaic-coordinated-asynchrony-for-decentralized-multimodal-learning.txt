1 Introduction 

Modern edge applications increasingly rely on data from multiple modalities, such as audio, video, and text, to improve performance and robustness [21, 33]. At the same time, privacy concerns and data-governance requirements motivate collaborative learning that keeps raw data local [1, 27, 29]. Geographically distributed deployments can additionally benefit from avoiding traffic concentration at a single model-aggregation server. These considerations motivate multimodal decentralized learning : agents collaboratively train modality-specific components of a shared task model by exchanging updates directly with peers, even though each agent may observe only a subset of modalities. Agents sharing a modality form a modality-specific exchange overlay, while

agents with multiple modalities additionally optimize cross-modal alignment to couple their local representations. Beyond conventional client-side resource heterogeneity, differences in available modalities introduce a structured source of computation and communication imbalance. Multimodal agents enable cross-modal knowledge transfer, but they also train more model components and participate in multiple modality overlays. The same modality memberships therefore link an agent’s role in cross-modal learning to its resource demands. These “bridge” agents connect modality-specific learning through local alignment, yet can become slower update producers and communication hot spots under shared resource budgets. Preserving their contribution is important because delays can limit the propagation of cross-modal information as well as the progress of individual agents. 

What breaks under modality heterogeneity. Cooperative multimodal learning introduces both intra-agent and inter-agent couplings. First, cross-modal alignment and fusion couple modality-specific encoders during training. On multimodal agents, synchronization between modalities can create bursty compute phases and idle gaps, slowing the production of sharable same-modality updates (Challenge 1). Second, multimodal agents must serve and fetch updates for multiple model components through the same bandwidth budget. Concurrent exchanges across overlapping modal-ity groups can create communication hot spots and cause transfers to miss local aggregation windows (Challenge 2). Third, under asynchronous aggregation, each agent must choose which peers to contact and which available updates to incorporate under a limited exchange budget. Con-tacting more peers can improve information diffusion but increase contention, whereas contacting too few can slow diffusion and concentrate contributions among a small set of agents (Challenge 3). Together, these effects influence both the age of incorporated updates and whose updates participate in learning, potentially widening accuracy disparities across agents. Section 2 characterizes these effects through controlled microbenchmarks and end-to-end experiments. 

Why existing and simpler approaches fall short. Prior designs address different parts of this problem. Server-coordinated multimodal training [34, 40, 48] addresses modality and representation heterogeneity, but its model exchange relies on centralized aggregation and coordination. Asyn-chronous decentralized schemes [3, 22, 23] reduce synchronization overhead and accommodate heterogeneous participants, but do not directly address reciprocal cross-modal interaction within agents together with contention across overlapping modality groups. Peer selection also faces a practical constraint: active probing [23] adds control messages and can delay scheduling decisions on high-latency links, while random or fixed-topology exchanges do not explicitly account for changing update availability and serving load. Common systems mechanisms address distinct decisions within this setting. Load balancing reduces transfer contention, delayed aggregation reuses late updates, and peer selection determines which updates to request. Their effectiveness also depends on local modality progress: accelerating one modality changes the availability of its updates, while contention determines whether those updates arrive in time to be incorporated. Network-level scheduling must also coexist with the matched, bidirectional feature exchange needed for local cross-modal learning. These dependencies motivate a runtime that coordinates local modality progress, peer-update delivery, and aggregation under shared resource constraints . Our evaluation examines how much of the resulting benefit can be recovered by simpler load-balancing and delayed-aggregation variants. 

Design requirements. The runtime should allow modalities to progress independently while preserving reciprocal cross-modal interaction. It should manage contention and reuse useful late arrivals without blocking local training, and guide peer exchange using lightweight information about update availability and participant state. We therefore ask: MODAIC : Coordinated Asynchrony for Decentralized Multimodal Learning 3

How can we coordinate local cross-modal interaction and peer-update exchange to im-prove learning under heterogeneous compute and limited bandwidth, without imposing global synchronization? 

Our approach: MODAIC . We answer this question with MODAIC (MOdality-Decoupled Asynchrony with Interleaved Coordination), a wait-free training runtime for multimodal decen-tralized learning. Here, wait-free means that local training proceeds without waiting for partner features or remote model transfers. MODAIC follows one principle: decouple modality progress while coordinating reciprocal local interaction and bandwidth-limited peer-update exchange . It realizes this principle through three mechanisms. (1) Hierarchical Asynchronous Collaboration lets modal-ities train and aggregate independently, while enforcing matched, contribute-before-consume feature exchange to preserve bidirectional cross-modal interaction (Section 3.1). (2) Load-Aware Update Fetching overlaps communication with computation, limits concurrent serving load through lightweight admission control, and retains late arrivals in per-modality caches for subsequent ag-gregation (Section 3.2). (3) Consensus-Aware Peer Selection uses lightweight metadata about update availability, sampling history, and loss similarity to guide peer exchange without active probing (Section 3.3). A centralized metadata tracker supports admission control and peer selection, while all model states are exchanged directly between agents, without centralized aggregation or model-data relaying. 

Results. We implement MODAIC as a containerized multi-agent training framework and evaluate it on AVE and KU-HAR using controlled local and cross-region cloud testbeds. On AVE at 1000s with a per-agent bandwidth budget of 200Mbps, MODAIC achieves unimodal and multimodal worst-agent accuracies of 35.16% and 56.28%, improving the best corresponding baseline results by 2.99 and 11.01 percentage points, respectively. Relative to AsyDFL, the multimodal average-worst accuracy gap decreases from 7.35 to 3.46 percentage points. On the cross-region cloud testbed, MODAIC reduces time-to-accuracy by up to 30%. Additional experiments show that the tested load-balancing and delayed-aggregation variants retain a worst-agent accuracy gap, and examine the contributions of the runtime components. We also quantify tracker overhead and show that performance gains persist under the evaluated WAN-like RTT variation and packet loss, with graceful degradation under tracker delay and partial unavailability. Our main contributions are summarized as follows: 

• We characterize how modality heterogeneity couples local training delays with competition for shared bandwidth across overlapping modality groups, and examine the resulting effects on update exchange and worst-agent performance. 

• We design MODAIC , a runtime that coordinates asynchronous local cross-modal interaction, load-aware update fetching, and metadata-guided peer selection while preserving reciprocal feature exchange and allowing local training to proceed without waiting for remote updates. 

• We build an end-to-end implementation and demonstrate improvements in learning quality at fixed resource budgets and in time-to-accuracy, while evaluating component contributions and sensitivity to stragglers, WAN dynamics, and tracker availability.

Problem setting. We study multimodal decentralized learning , where agents hold heterogeneous modality sets (e.g., audio, video, or audio+video) and exchange locally updated model parameters in

Key systems intuition. Efficient decentralized optimization depends on local updates diffusing through the network quickly and broadly . Two system-level factors shape this process: (1) staleness ,the age of an update when it is incorporated [7], and (2) mixing , how rapidly information diffuses across agents through successive exchanges [12]. 2.1 Computation Heterogeneity 

A fundamental obstacle in multimodal decentralized learning is that agents with more modalities can take longer to produce updated model components, even under the same hardware budget. This affects how frequently other agents can obtain new same-modality contributions from them. 

Modality-dependent training creates unequal update rates. Figure 1(a) isolates computation heterogeneity by constructing three groups with different modality sets (audio-only, video-only, and audio+video), using encoders with matched parameter size on identical GPUs. Even in this controlled setting, multimodal agents incur substantially longer per-step training time. As a result, within a same-modality overlay, unimodal agents (e.g., video-only) can receive new video updates from unimodal peers much more frequently than from multimodal peers. At a fixed wall-clock aggregation cadence, the longer refresh intervals of multimodal agents can leave peers with older available updates, even before transfer delay is considered. In realistic deployments where modality encoders are not size-matched, the gap can be larger [14].

In the synchronized multimodal execution shown, backward computation for the joint alignment/fusion loss waits until all required modalities complete their FWD passes [17, 35]. This creates modality-level idle gaps: a faster modality finishes its FWD but waits for its partner’s features before proceeding with BWD. These dependencies delay the production of shareable same-modality updates. Making peer exchange asynchronous does not, by itself, remove this within-agent synchronization. 

Implication: compute skew translates into stale same-modality exchanges. Many de-centralized designs implicitly rely on comparable progress rates within an overlay so exchanged updates remain reasonably fresh. Under modality-induced compute lag, multimodal agents produce shareable same-modality updates less frequently. When peers aggregate the latest available states, these longer refresh intervals can increase update age and slow effective convergence within the modality group [7, 18]. Figure 2 illustrates this age skew in the GPU setting: from the perspective of a video-only agent, updates from multimodal peers are older than those from video-only peers. Crucially, simply dropping slow contributors can sacrifice useful cross-modal information: these contributors are often the multimodal agents that connect modality-specific learning through local alignment. Under-utilizing their updates can therefore hurt both unimodal and multimodal learning. The challenge is to improve update freshness while preserving these cross-modal contributions. 

Why we cannot simply remove cross-modal coupling. Cross-modal interaction contributes to predictive performance in our evaluated setting. With the same model architecture, data split, and synchronous aggregation schedule, bidirectional interaction achieves 64.5% multimodal accuracy, compared with 61.8% for unidirectional interaction and 59.3% without interaction (Appendix A.1). This motivates preserving the benefit of bidirectional interaction while reducing synchronization-induced waiting. 

Challenge 1: independent progress with reciprocal interaction. Therefore, the computation-level challenge is to reduce synchronization-induced delays and the resulting update staleness under modality heterogeneity, while preserving bidirectional cross-modal interaction. 

2.2 Load-Imbalanced Communication 

Decentralized learning performance depends on who exchanges with whom, how often, and under what bandwidth budget [15, 31]. Under modality heterogeneity , this pattern becomes intrinsically imbalanced: multimodal agents exchange multiple modality-specific components and participate in multiple overlays, while unimodal agents participate in only one. With comparable exchange rates per overlay and a shared per-agent bandwidth budget, multimodal agents can therefore face higher aggregate communication demand. 6 Shi et al.

Equal bandwidth does not imply equal delay. Figure 3 isolates this effect with equal 100Mbps full-duplex budgets and the same ring topology for each modality overlay. Multimodal agents participate in both overlays, so their audio and video exchanges share the same per-agent commu-nication resources. Their reported receive delay is higher in both modalities: 0.375s versus 0.170s for audio (2 .2×), and 0.276s versus 0.152s for video (1 .8×). Thus, equal per-agent bandwidth budgets can yield substantially different exchange delays when modality memberships differ. 

Overlapping modality exchanges create contention. The delay gap reflects differences in communication load: a multimodal agent concurrently serves and fetches updates across multiple modality overlays, whose transfers share its fixed uplink and downlink budgets. Even with identical per-agent bandwidth limits, these overlapping exchanges compete for the same communication resources. As Figure 3(right) shows, most recorded per-exchange completion time falls in the combined waiting/serialization interval, while the measured transfer interval is smaller. These observations motivate coordinating concurrent exchanges across overlays to control the load placed on multimodal agents. 

Why both sync and wait-free protocols suffer. In synchronous decentralized training, heav-ily loaded multimodal agents can become bottlenecks and delay aggregation rounds. Wait-free asynchronous training allows local training to continue without waiting for these transfers [3], but the underlying load imbalance remains. Delayed updates can miss local aggregation windows and be incorporated less promptly or less frequently. Thus, asynchrony changes the failure mode rather than removing it: communication delays that previously stalled training can instead leave multimodal contributors underrepresented in aggregation. Because these agents support cross-modal knowledge transfer, reduced participation can weaken information propagation and widen accuracy disparities across agents. 

Challenge 2: timely exchange under shared bandwidth. We therefore need load-aware exchange mechanisms that manage communication load across modality overlays to reduce hot spots and preserve useful contributions from multimodal agents , while allowing local training to continue and keeping coordination overhead low under tight bandwidth budgets. 

2.3 Mixing-Staleness-Contention Tension 

The preceding computation and communication imbalances create a coupled peer-selection problem: agents must balance update freshness with broad information mixing under shared bandwidth constraints. Favoring recent updates can reduce staleness, but repeatedly selecting the same fast peers can underrepresent slower multimodal contributors. Increasing exchange frequency or fan-out to improve mixing, in turn, increases demand on shared links. MODAIC : Coordinated Asynchrony for Decentralized Multimodal Learning 7

Why heterogeneity makes the tradeoff dynamic. Under modality heterogeneity, the “best” peers are neither static nor cheaply observable. Compute skew (Section 2.1) changes who can produce fresh updates, and multi-overlay load (Section 2.2) changes who can deliver them on time. A peer that is fresh at one moment can become a hot spot the next due to concurrent requests, while multimodal agents may remain systematically slower. Consequently, fixed schedules that ignore these changes can repeatedly request stale updates or overload popular peers, delaying information diffusion and skewing participation. 

Why standard aggregation patterns fall short. Random peer selection spreads requests across peers in expectation, but does not account for which updates are recent or likely to arrive within the aggregation window. Fixed peer sets or exchange frequencies likewise do not, by themselves, adapt to changes in update availability and serving load. Simple load balancing reduces contention but does not determine which available updates should be mixed. Delayed aggregation reuses late arrivals but does not decide which peers should be contacted next. These mechanisms leave open how to allocate scarce exchanges while preserving both update freshness and the participation of slower multimodal contributors. 

The practical barrier: contention and probing overhead. Even when agents can contact any peer, choosing “good” peers is difficult in a wait-free system. If many agents simultaneously target the same high-quality peer, they compete for its limited uplink/downlink, increasing queuing delay and causing transfers to miss aggregation deadlines. Probing peers for current queue occupancy or training progress adds control messages and can delay selection on high-latency links. This motivates using lightweight shared progress and load metadata to guide peer selection without repeated per-peer probing. 

Challenge 3: fresh and broad mixing under contention. We therefore need a lightweight scheduling mechanism that balances update freshness with broad participation within a limited exchange budget , while accounting for serving load and keeping coordination overhead low without active peer probing. 

Summary of requirements. These challenges imply three system requirements for multimodal decentralized learning: 

• (i) modality-decoupled progress without global blocking, while preserving reciprocal cross-modal interaction to avoid one-sided alignment (Challenge 1); 

• (ii) load-aware update exchange that manages concurrent communication demand across modality overlays and retains useful late arrivals for subsequent aggregation (Challenge 2); 

• (iii) contention-aware peer selection that balances freshness and broad participation within the available exchange budget, with low control overhead (Challenge 3). These requirements are coupled: local modality progress determines which updates are available, communication contention affects which arrive in time, and peer selection determines whose information enters aggregation. MODAIC coordinates these decisions within a single runtime.

3.1 Hierarchical Asynchronous Collaboration 

This component addresses Challenge 1 (Section 2.1): reduce compute-induced staleness by allow-ing each modality to progress without global blocking, while still preserving the bidirectional 

cross-modal interaction required for multimodal accuracy. MODAIC coordinates asynchrony at two levels: (i) local asynchronous interaction between modalities within an agent, and (ii) cross-device 

asynchronous aggregation within each modality overlay. 

❶ Local asynchronous interaction: preserving reciprocity under asynchrony. A naive design is to run modalities independently and exchange features whenever they become available. Under modality heterogeneity and without coordination, this quickly becomes imbalanced: the faster modality repeatedly reaches interaction points first and mostly consumes the partner’s cached features, while the slower modality mostly produces them. Moreover, if both modalities draw from a single shared data stream, cached features may correspond to a different data sample than the partner input used later for interaction, biasing alignment, as illustrated in Figure 5 (left). ❷ Cross-device asynchronous aggregation: per-modality progress without global barri-ers. Beyond local interaction, MODAIC supports wait-free, modality-level sharing across agents. Each modality 𝑚 runs an independent aggregation loop: it issues asynchronous pulls for same-modality updates, continues local training, and at each aggregation deadline mixes the arrived or cached updates for modality 𝑚 . Neither cross-device aggregation nor local feature exchange requires modalities to reach a common training step. This allows each modality to refresh its parameters as its local computation and available peer updates permit, without waiting for slower modalities or remote transfers. The runtime abstraction is not hard-coded to two modalities. For an agent with modality set 

M𝑖 , MODAIC instantiates one train/pull/serve pipeline per modality and one sharing overlay per modality. Local interaction can be pairwise or fusion-based, with the contribute-before-consume rule requiring that consumed features come only from modalities that have contributed in the current interaction window. Thus, the control/data-plane separation and load-aware fetching design remain unchanged, although local interaction state and overlay membership grow with |M 𝑖 |.

❶ Communication-computation concurrency. As shown in Figure 6, each agent runs a per-modality, wait-free pipeline with three concurrent routines. Train continuously advances local parameters via SGD. Serve replies to inbound pull requests with the latest locally available same-modality state. Pull asynchronously requests peer updates for the next aggregation event. Aggregation executes at a configurable cadence, such as after a local training window, and mixes whichever updates have arrived by the deadline; training is never blocked by communication. Because these routines are modality-isolated, a fast modality can continue training and exchanging updates without waiting for slower modalities on the same agent. 

❷ Load-balanced admission control. Unrestricted pulling can create many-to-one contention when agents target the same peer. To limit concurrent serving load without active peer probing, the tracker maintains a count 𝑎 𝑚 𝑗 of reserved or active serving slots and a configured capacity 𝑐 𝑚 𝑗

Before a pull starts, one slot must be atomically reserved by incrementing 𝑎 𝑚 𝑗 , and the slot is released when the transfer completes or is terminated. An aggregation deadline alone does not terminate a pending transfer, since its result may still be useful in a later window. This admission mechanism limits the concentration of concurrent requests at individual peers. It complements peer selection: selection identifies desirable contributions, while admission controls whether the corresponding transfers can proceed. Per-modality capacities bound serving concur-rency, while their configuration must account for the bandwidth shared by an agent’s modality overlays. 

❸ Caching late arrivals. Aggregation does not wait for in-flight transfers: at each deadline, an agent mixes the updates that have arrived. Unlike designs that cancel or discard late transfers, 

MODAIC stores completed arrivals in a small per-modality receive cache B𝑚 𝑖 . Late updates that miss the current window remain eligible for the next aggregation event, turning deadlines into a soft boundary that determines when an update is applied rather than whether transmitted bytes are discarded. Cached entries are versioned and later filtered/reweighted by the selection policy, so caching salvages bandwidth without forcing the agent to apply every late update. without active peer probing. Given the admissible peers and locally available (possibly cached) updates, MODAIC uses a lightweight selection policy that balances freshness , participation fairness ,and loss similarity . The fetching layer controls concurrent serving load, while the selection policy determines which admissible peers to contact and which available updates to incorporate.

4 System Implementation 

We implement MODAIC as a containerized multi-agent training framework in Python3 (about 3.2K lines of code) on top of PyTorch . MODAIC exposes a small set of APIs for (de)serializing modality-specific model states and for scheduling per-modality training and communication pipelines. This design enables cross-agent modality sharing over commodity IP networks using TCP connections, without requiring dedicated links or a centralized model-data relay. 

Containerized agents. Each agent runs in an isolated Docker container built from a PyTorch CUDA runtime image. Containers encapsulate the full training stack, including model components, optimizer, dataloaders, caches, and communication workers, and provide fault isolation. Each agent maintains modality-specific components (encoders and task heads) and executes MODAIC 

via per-modality pipelines that overlap local training with communication, consistent with the design in Section 3.2. For each exchange, we serialize only the required modality-specific state together with small metadata (peer id, modality, version, timestamp, and loss/progress signal). This keeps P2P model-transfer payloads scoped to the relevant modality and avoids device-wide synchronization across unrelated modalities. 

GPU sharing and isolation. To support many concurrent agents on a single GPU server while limiting interference, we enable NVIDIA Multi-Process Service (MPS) to partition GPU execution across containers. Each container is assigned a controlled GPU share (e.g., via MPS active-thread percentage), preventing any single agent from monopolizing the device. Within each container, 

MODAIC implements the per-modality pull , serve , and train routines as concurrent workers, so communication proceeds while local SGD continues and no global barrier is introduced across modalities. To avoid unintended cross-modality blocking on shared accelerators, each modality executes forward/backward kernels on its own CUDA stream, while a lightweight mutex guards only optimizer steps and parameter serialization to prevent concurrent writes to shared tensors. Received peer updates are stored in per-modality caches to tolerate stragglers and bursty links, and to enable communication-free reuse of late arrivals in subsequent aggregation windows. MODAIC : Coordinated Asynchrony for Decentralized Multimodal Learning 13 

Control plane and peer-to-peer data path. Consistent with Sections 3.2 and 3.3, each agent maintains a control-plane connection to a lightweight tracker service that records only small status metadata for admission control and log-guided peer selection. The tracker is not on the model-data path (i.e., it is not a parameter server): all model updates are transmitted directly between peers over the data plane. All tracker measurements use the same single-process Python tracker used in the training experiments. If the tracker is temporarily unreachable, agents continue wait-free training and aggregation using their most recent admissible-peer snapshot and locally cached updates until connectivity resumes. The tracker can be replicated or sharded by modality for availability; we quantify its overhead and failure behavior in Section 5.5. 

Network emulation and deployment. For controlled local experiments, we construct virtual overlay networks among containers using Mininet [20]. Mininet instantiates virtual links and allows us to configure per-agent bandwidth and latency. We attach all agent containers to a virtual switching fabric, assign each container a static IP address for stable addressing, and enforce heterogeneous link budgets matching our experimental settings. Unless stated otherwise, local experiments do not inject random packet loss; WAN-style RTT variation and loss stress tests, as well as the cross-region cloud deployment, are evaluated separately in Section 5. 

5 Evaluation 

We evaluate MODAIC on a controlled local testbed and a cross-region cloud deployment. Building on the resource effects characterized in Section 2, we examine whether coordinating local cross-modal interaction and peer-update exchange improves learning under heterogeneous compute and limited bandwidth. We emphasize both average and worst-agent accuracy, then examine the contributions of the runtime components and the cost of coordination. Concretely, our evaluation answers: 

• End-to-end benefit: Does MODAIC improve both average and worst-agent accuracy for unimodal and multimodal agents, and does it reduce the bandwidth needed to reach a target worst-agent accuracy (Section 5.2)? 

• Are simpler fixes enough? How much of the benefit can load-balanced random selection and delayed-update reuse recover (Section 5.3)? 

• Where do the gains come from? How do reciprocal local interaction, load-aware update fetch-ing, and consensus-aware peer selection contribute, individually and in the tested combinations (Section 5.4)? 

• Control-plane practicality: What overhead does the metadata tracker incur, and how does training behave under delayed or partially unavailable tracker access (Section 5.5)? 

• Robustness under heterogeneity: How do bandwidth, stragglers, system scale, and WAN-like network conditions affect performance (Section 5.6)? 

• Wide-area deployment: Do the same trends hold in a real cross-region cloud testbed, and does MODAIC reduce time-to-accuracy under CPU-driven training and heterogeneous wide-area links (Section 5.7)? 

5.1 Experimental Setup 

Our evaluation includes both a controlled local testbed and cloud-based experiments. Both use the same containerized MODAIC implementation and differ only in their network configuration. The local testbed provides GPU-based training and controlled network conditions, whereas the cloud deployment uses CPU-only training over cross-region links. We present the main results and most controlled analyses on the local testbed, and in Section 5.7 we reproduce a subset of the results in the cloud to demonstrate practicality under real wide-area links. Importantly, the local experiments 14 Shi et al. 

are not simulations of training: all methods run as containerized PyTorch agents, while Mininet controls communication among containers. 

Testbed and default configuration. All local testbed experiments run on a server with an AMD Ryzen Threadripper PRO 7955WX CPU and three NVIDIA RTX PRO 5000 GPUs. GPU execution is shared across containers using NVIDIA MPS, as described in Section 4. The default configuration has 30 agents: 10 hold both modalities, and 20 hold exactly one modality, split evenly between the two modalities. Unless otherwise stated, the configured bandwidth budget is 200Mbps per agent, and we measure local-testbed accuracy at 1000s. 

Datasets and Non-IID setting. We evaluate on two multimodal benchmarks that cover both lightweight sensor modalities and compute-heavier audio-visual encoders. (1) KU-HAR [36] is a human activity recognition dataset with two sensor modalities, accelerometer and gyroscope. We use an 8-class subset (walking, walking upstairs, walking downstairs, sitting, standing, laying, jumping, and running), and adopt ResNet-9 [8] as the backbone for both modalities. (2) AVE [38] (Audio-Visual Event) contains 10-second video clips from 28 event categories, with synchronized audio and visual streams. We use ResNet-18 [8] to encode audio and MobileNetV3-Large [10] to encode visual inputs. To model non-IID data, we assign each agent a label distribution sampled from a Dirichlet distribution with concentration parameter 𝛼 [11]. Unless otherwise noted, we report results with 𝛼 = 0.5, and we vary 𝛼 in additional studies (Appendix D). 

Training configuration. We use SGD with learning rate 10 −3, momentum 0.9, weight decay 5 × 10 −4, and batch size 32. The local training window contains one SGD step. Model and method-specific configuration details are given in Appendix C. 

Baselines. We compare against four asynchronous decentralized learning baselines: AD-PSGD [22], AsyDFL [23], Swift [3], and DivShare [2]. AD-PSGD assigns nodes to active/passive roles, and active nodes push updates to passive ones to avoid synchronization deadlocks. Swift performs peer-to-peer exchanges with a consensus-based neighbor rule. AsyDFL combines asynchronous update pushing with resource-aware peer selection. DivShare improves communication efficiency by slicing model parameters and sharing only subsets in each exchange. In addition, we include representative synchronous baselines in our main results: Harmony [34], DMML-KD [44], and FedLay [13]. Harmony is a two-stage multimodal federated learning scheme, DMML-KD enables cross-modality transfer via feature generation and distillation, and FedLay couples a practical overlay topology with a model-exchange protocol to mitigate data and client heterogeneity. We adapt Harmony to our peer-to-peer setting by replacing server aggregation with overlay-based peer exchange while keeping its core interaction mechanisms unchanged; detailed adaptations and hyperparameter matching are provided in Appendix C. 

Metrics. We report both average and worst-agent accuracy. For agents with a single modality, U-Avg and U-Worst denote the average and worst accuracy among unimodal agents. For agents with multiple modalities, M-Avg and M-Worst denote the average and worst accuracy among multimodal agents. Worst-agent metrics are central because modality heterogeneity first harms agents that are slow, overloaded, or under-aggregated. We also report the average-worst gap to characterize within-group accuracy disparity, and use wall-clock learning curves and time-to-accuracy to assess training efficiency. Accuracy differences are reported in percentage points.

5.3 Are Simpler Fixes Enough? 

A key question is whether MODAIC ’s gains require the full joint design, or whether simpler fixes recover most of the benefit. We evaluate two variants on AVE under the default configuration. B1 

uses load-balanced random selection: agents request updates only from non-saturated peers, but peer choice is uniform and the system lacks MODAIC ’s reciprocal modality-decoupled interaction. 

B1+B2 further retains delayed peer updates for future aggregation, but still lacks consensus-aware scoring and reciprocal asynchronous interaction. Both variants use the same training budget, model architecture, bandwidth cap, and aggregation cadence as MODAIC , isolating whether simple load filtering and delayed reuse are sufficient. Figure 7(left) shows that these fixes help but do not close the gap. B1 trails MODAIC by 8.4 points in M-Avg and 11.9 points in M-Worst. Adding delayed aggregation improves both metrics, but B1+B2 still trails by 6.7 points in M-Avg and 8.7 points in M-Worst. Thus, the failure is not simply overloaded peers or wasted late transfers: load balancing reduces hot spots and delayed aggregation salvages bytes, but neither preserves reciprocal cross-modal interaction nor selects fresh, pace-compatible peers under deadline pressure.

6 Related Work 

Decentralized learning. Compared with server-based collaboration [4, 9, 26, 37, 49], decentralized learning exchanges updates directly among peers, avoiding centralized model aggregation and supporting geographically distributed deployments [24, 46]. Prior work develops asynchronous protocols and convergence analyses under heterogeneous progress and update delays [2, 3, 7, 22]. Other work studies communication topology [6, 31, 32] and resource-aware neighbor selection [23]. Related FL work optimizes participant selection [16, 19] and resource allocation across learn-ing jobs [25]. MODAIC targets modality-structured imbalance: agents essential for cross-modal knowledge transfer also carry heavier computation and communication workloads across multiple modality overlays. 

Multimodal learning systems. Multimodal learning combines complementary signals (e.g., audio and video) for robustness and accuracy [5, 30, 38, 41, 45]. Fusion and cross-modal alignment objectives couple modality-specific encoders through cross-modal representations [17, 35, 42]. Recent systems improve distributed training throughput through heterogeneity-aware parallelism, placement, and scheduling [14, 47]. These systems optimize distributed execution of multimodal models; MODAIC addresses decentralized agents with different modality subsets, where independent local progress must preserve reciprocal cross-modal interaction. 

Multimodal federated/decentralized learning under heterogeneity. Under modality hetero-geneity , agents hold different modality subsets, introducing learning imbalance and uneven resource demands. Multimodal FL frameworks address this heterogeneity through server-mediated training and aggregation [40, 43]. Harmony [34] disentangles encoder and fusion training and coordinates modalities with different training delays. Recent multimodal FL work also addresses incomplete MODAIC : Coordinated Asynchrony for Decentralized Multimodal Learning 21 

modalities through server-coordinated learning [28, 39]. In decentralized settings, DMML-KD [44] combines knowledge distillation with modality-dependent local iteration control to balance train-ing. MODAIC differs by jointly coordinating reciprocal cross-modal interaction and wait-free update exchange under shared bandwidth. It combines load-aware admission control, late-arrival reuse, and metadata-guided peer selection without active probing. Model exchange remains peer-to-peer, while a lightweight tracker handles coordination metadata. 

7 Conclusions 

We presented MODAIC , a wait-free runtime that coordinates reciprocal cross-modal interaction, load-aware update exchange, and peer selection without active probing under modality heterogeneity. Experiments on AVE and KU-HAR across local and cross-region testbeds show higher average and multimodal worst-agent accuracy and shorter time-to-accuracy. Ablations show that load balancing and delayed aggregation leave a worst-agent gap, while tracker experiments demonstrate modest processing overhead and tolerance to partial unavailability. 22 Shi et al.

A Additional Motivation Results A.1 Cross-modal Interaction Ablation 

Setup. We compare three interaction designs while keeping the same model architecture, data split, and aggregation schedule. The only difference is how cross-modal features are exchanged and used to form the interaction/alignment loss: (i) no interaction, (ii) uni-directional interaction, and (iii) bi-directional (reciprocal) interaction. 

Result and implication. Figure 15 shows that removing interaction degrades multimodal accuracy, and uni-directional alignment recovers only part of the gap. Bi-directional interaction consistently performs best, indicating that reciprocal exchange is important for stable cross-modal alignment in our setting. This supports the design goal in Challenge 1: rather than eliminating cross-modal coupling, the system must preserve reciprocal interaction while avoiding the synchronization-induced stalls that make multimodal agents straggle.

A.3 Additional discussion: scheduling limits under heterogeneity 

Under modality heterogeneity, the feasible set of timely peers changes over time due to compute skew and multi-overlay contention. Random selection wastes limited exchanges on late/stale updates, while fixed topologies cannot react to transient hot spots and stragglers. Although probing peers for queue occupancy or pace could inform better selection, active probing adds control traffic and RTTs and can itself create contention, motivating lightweight shared progress signals and late-update reuse.

Baseline Fairness. For asynchronous decentralized baselines (AD-PSGD [22], AsyDFL [23], Swift [3], and DivShare [2]), we follow the original push/pull protocols. To avoid confounding effects from topology and pairwise contention, we run them on a fully connected overlay with MODAIC : Coordinated Asynchrony for Decentralized Multimodal Learning 27

dedicated per-pair links (i.e., no link-level contention). For AD-PSGD, we use its standard random bipartite active–passive graph, so active agents can always communicate with passive agents. For synchronous baselines, we use the default settings in the original papers. FedLay [13] operates on per-modality overlays; in each round, an agent selects 𝐾 neighbors within each overlay to exchange the corresponding modality parameters. For DMML-KD [44], all agents participate in a single fully connected overlay, and the multimodal fusion module follows the method design. Harmony [34] is originally centralized; we adapt it by replacing the server with a lightweight tracker for stage coordination, while updates are exchanged via random gossip within per-modality overlays. In Harmony’s second stage, unimodal agents communicate only with same-modality peers, and multimodal agents communicate only with multimodal peers. Unless otherwise specified, all baselines (except DMML-KD) use the same modality-grouping rule as MODAIC : agents sharing a modality join the same overlay, and multimodal training uses the same aligned fusion objective (contrastive feature alignment [35]). 

Training Setting. All trainable modules, including the feature extractors and classifiers, are optimized with SGD (learning rate 10 −3, momentum 0.9, weight decay 5 × 10 −4) using a batch size of 32 in all experiments. In each communication round, every agent performs a single local SGD update step.

Data heterogeneity. Using the default bandwidth budget, we evaluate different methods on AVE under varying data heterogeneity levels (Dirichlet parameter 𝛼 ) in Table 3. D.4 Details on Cloud-based Experiments 

Cloud setting. We deploy a cross-region cloud testbed on AWS using three EC2 instances lo-cated in Virginia (US), London (UK) and Singapore, each provisioned with 64 vCPUs and 256 GB RAM, and run all agents as Docker containers (CPU-only). To enable container-to-container IP connectivity across regions, we build an encrypted host overlay using WireGuard in a full-mesh configuration; each host advertises a unique Docker bridge subnet and forwards remote container subnets through the WireGuard interface, yielding stable private container IPs for end-to-end TCP communication. We orchestrate experiments from an external controller (a local server) via SSH, which launches/stops containers on each host, assigns roles (tracker vs. worker), and collects logs from host-mounted volumes, while we also allocate CPU shares to worker containers using cgroup quotas and apply per-container bandwidth caps with Linux traffic control (HTB/ netem ) on each container interface to emulate heterogeneous wide-area links. 

D.5 Additional Wide-Area Cloud Deployment 

Bandwidth sweep. Figure 22 reports unimodal and multimodal average/worst accuracy under different bandwidth budgets. Unlike our GPU-based local testbed, cloud runs are CPU-bound, so reducing bandwidth from 200Mbps to 50Mbps causes a smaller accuracy drop. The average-worst gap is more pronounced because limited CPU parallelism amplifies compute-time skew across agents. Despite this shift in the bottleneck, MODAIC consistently achieves the best average and worst-agent accuracy for both unimodal and multimodal groups.
