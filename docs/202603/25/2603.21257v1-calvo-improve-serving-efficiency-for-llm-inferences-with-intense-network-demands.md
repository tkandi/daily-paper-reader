## 摘要
分布式前缀缓存已成为高效大语言模型（LLM）服务的核心技术。然而，对于具有高缓存命中率的长上下文请求，从远程服务器检索可重用的 KV 缓存（KVCache）块已成为新的性能瓶颈。随着智能体 AI（agentic AI）工作负载的持续增长，这种网络密集型 LLM 推理预计将变得越来越普遍。然而，现有的 LLM 推理引擎在很大程度上仍是以计算为中心的：它们将 KVCache 加载视为 GPU 执行的附属阶段，且通常在调度过程中未能明确考虑其延迟。我们提出了 CALVO，一种将 KVCache 加载视为核心关注点（first-class concern）的 LLM 服务引擎。CALVO 将 KVCache 加载与 GPU 计算解耦为独立管理、异步进行的阶段，从而能够更好地利用网络、PCIe 和计算资源。此外，CALVO 将 KVCache 加载延迟作为单次请求服务成本的明确组成部分，从而实现了更准确的调度决策。在具有多种长上下文工作负载的真实测试平台上的实验表明，CALVO 显著提高了网络密集型 LLM 推理的效率，与基准方案相比，SLO 达成率提高了高达 61.67%。

## Abstract
Distributed prefix caching has become a core technique for efficient LLM serving. However, for long-context requests with high cache hit ratios, retrieving reusable KVCache blocks from remote servers has emerged as a new performance bottleneck. Such network-intensive LLM inference is expected to become increasingly common as agentic AI workloads continue to grow. However, existing LLM inference engines remain largely compute-centric: they treat KVCache loading as a subordinate phase to GPU execution and often fail to account for its delay explicitly during scheduling.   We present CALVO, an LLM serving engine that treats KVCache loading as a first-class concern. CALVO decouples KVCache loading and GPU computation into independently managed, asynchronously progressing stages, enabling better utilization of network, PCIe, and computation resources. In addition, CALVO incorporates KVCache loading delay as an explicit component of per-request service cost, leading to more accurate scheduling decisions. Experiments on a real testbed with diverse long-context workloads show that CALVO substantially improves the efficiency of network-intensive LLM inference, achieving up to 61.67% higher SLO attainment than the baseline.

### 1. 核心问题与研究动机
*   **背景**：随着长文本（Long-context）LLM应用（如文档QA、代码补全、AI Agent）的普及，**前缀缓存（Prefix Caching）**成为减少重复计算、降低首字延迟（TTFT）的关键技术。
*   **核心问题**：在分布式缓存场景下，KVCache 需要从远程服务器（L3）加载到本地内存（L2）再到 GPU 显存（L1）。对于“长上下文、短查询”的请求，**KVCache 的网络加载时间往往超过了 GPU 计算时间**（文中称为“网络密集型推理”）。
*   **现有缺陷**：主流引擎（如 vLLM）是“以计算为中心”的，将加载视为计算的附属阶段。这导致两个问题：
    1.  **资源利用率低**：各阶段（网络、PCIe、计算）串行执行，无法充分流水化。
    2.  **调度不准确**：调度器（如 FIFO）不考虑加载延迟，导致排队策略并非最优。

### 2. 方法论
CALVO 的核心思想是将 KVCache 加载视为与计算同等地位的“一等公民”，通过解耦和成本感知进行优化：
*   **跨阶段工作流解耦**：
    *   **独立调度器-执行器**：为 L3→L2 和 L2→L1 加载阶段分别设立独立的 Dispatcher 和 Executor，使其能够异步并行。
    *   **主动空间分配**：低层级阶段主动触发高层级的空间分配（例如 L3→L2 阶段主动请求分配 GPU 显存），打破了传统“计算触发加载”的被动模式，实现细粒度的加载重叠。
*   **跨请求调度优化**：
    *   **二元线性成本模型**：通过系统分析，将服务成本建模为 $T_{load}$（加载延迟，与上下文长度线性相关）和 $T_{comp}$（计算延迟，与查询长度线性相关）之和。
    *   **感知成本的调度算法**：
        *   **SJF（最短作业优先）**：利用建模的成本预测，优先处理总耗时最短的请求，以最小化平均 TTFT。
        *   **LSTF（最小松弛时间优先）**：针对 SLO 目标，计算 $LST = DDL - (T_{load} + T_{comp})$，优先处理紧急请求。

### 6. 主要结论与发现
*   **性能提升**：在网络密集型负载下，CALVO 相比基准方案可将平均 TTFT 降低高达 **81.3%**。
*   **SLO 优化**：在相同负载下，CALVO 的 SLO 达成率比 vLLM-LMCache 高出 **61.67%**。
*   **调度关键性**：单纯增加加载带宽而不优化调度算法（如仅使用 FIFO）无法达到最优性能，必须显式考虑加载成本。
*   **成本模型有效性**：基于二元线性函数的成本预测比单纯基于 Token 数量的预测更准确，能显著提升调度质量。

### 7. 优点
*   **架构前瞻性**：敏锐捕捉到 Agent 时代“长上下文、短查询”导致的网络瓶颈问题。
*   **系统级解耦**：通过 Dispatcher-Executor 机制实现了真正的异步流水化，解决了计算资源在等待网络传输时的闲置问题。
*   **实用性强**：基于主流框架 vLLM 和 LMCache 实现，易于集成到现有生产系统。

### 8. 不足与局限
*   **显存压力**：主动空间分配机制虽然提升了速度，但在高并发下可能导致 GPU 显存过早被占用，论文虽提到极端情况下会退化为被动分配，但未深入探讨显存碎片化或 OOM 的风险管理。
*   **场景局限**：主要针对 Prefill（预填充）阶段的 TTFT 优化，对于 Decode（解码）阶段的吞吐量优化涉及较少。
*   **多节点扩展性**：实验主要在双节点（一计算一存储）环境下完成，在更大规模、网络拓扑更复杂的集群中的表现（如网络竞争、多路径干扰）有待进一步验证。
