## 摘要
大语言模型（LLM）推理日益依赖多 GPU 执行，然而现有的推理并行化策略需要逐层的 rank 间同步，使得端到端性能对工作负载不平衡非常敏感。我们提出了 DWDP（分布式权重数据并行），这是一种推理并行化策略，它在保持数据并行执行的同时，将 MoE 权重卸载到对等 GPU 上，并根据需要获取缺失的专家。通过消除集合通信的 rank 间同步，DWDP 允许每个 GPU 独立运行。我们通过针对分割权重管理和异步远程权重预取的两项优化，进一步解决了该设计的实际开销。在 TensorRT-LLM 中实现并在 GB200 NVL72 上使用 DeepSeek-R1 进行评估，在 8K 输入序列长度和 1K 输出序列长度下，在 20-100 TPS/user 的服务范围内，DWDP 在相当的 TPS/user 下将端到端输出 TPS/GPU 提高了 8.8%。

## Abstract
Large language model (LLM) inference increasingly depends on multi-GPU execution, yet existing inference parallelization strategies require layer-wise inter-rank synchronization, making end-to-end performance sensitive to workload imbalance. We present DWDP (Distributed Weight Data Parallelism), an inference parallelization strategy that preserves data-parallel execution while offloading MoE weights across peer GPUs and fetching missing experts on demand. By removing collective inter-rank synchronization, DWDP allows each GPU to progress independently. We further address the practical overheads of this design with two optimizations for split-weight management and asynchronous remote-weight prefetch. Implemented in TensorRT-LLM and evaluated with DeepSeek-R1 on GB200 NVL72, DWDP improves end-to-end output TPS/GPU by 8.8% at comparable TPS/user in the 20-100 TPS/user serving range under 8K input sequence length and 1K output sequence length.

### 1. 核心问题与整体含义
*   **研究动机**：随着大语言模型（LLM）规模的扩大，推理必须依赖多GPU并行。现有的并行策略（如张量并行TP、专家并行EP、流水线并行PP）都存在**层级同步（Layer-wise Synchronization）**的问题。
*   **核心痛点**：在实际生产环境中，由于输入序列长度不同、KV缓存命中率差异以及MoE模型中专家路由的不均衡，各GPU（Rank）之间的负载极少能达到完美平衡。传统的同步机制会导致“木桶效应”，即所有GPU必须等待最慢的一个，从而产生显著的同步开销（实验显示在典型负载下开销可达12%）。
*   **研究目标**：提出一种消除集体同步、允许各GPU独立推进推理进程的并行策略。

### 2. 方法论
*   **核心思想（DWDP）**：结合了数据并行（DP）的执行模式和基于GPU的权重卸载（Offloading）。
    *   **权重分布**：Attention权重在各Rank间完全复制；MoE权重（专家）则分布存储在DWDP组内的对等GPU上。
    *   **异步预取**：每个Rank在执行当前层时，通过异步点对点（P2P）通信从其他GPU“拉取”下一层所需的远程专家权重。
    *   **消除同步**：使用 `cudaMemcpyAsync` 代替 NCCL 集合通信（如 All-to-All），使通信不占用计算资源（SM），且各Rank无需相互等待。
*   **关键技术优化**：
    1.  **分割权重管理（Split-Weight Management）**：修改 MoE GroupedGEMM 内核，使其直接支持 TensorList 输入（即同时读取本地和远程缓冲区），消除了将权重合并到连续内存所需的显式拷贝开销。
    2.  **异步通信抗争缓解（TDM 调度）**：针对多个GPU同时向同一个源GPU请求权重导致的“多对一”冲突，引入了**时间分片多路复用（TDM）**。将传输切分为小块（Slice）并采用轮询（Round-Robin）调度，利用拷贝引擎的流水线特性缓解阻塞。

### 3. 实验设计
*   **模型与场景**：使用 **DeepSeek-R1** 模型（NVFP4 权重，FP8 KV缓存）。主要针对**分离式推理（Disaggregated Serving）**架构中的 Context（Prefill）阶段。
*   **Benchmark**：
    *   **数据集**：Artificial Analysis 数据集（用于消融实验）和 SemiAnalysis 数据集（用于端到端评估）。
    *   **对比方法**：传统的 **DEP**（Data Parallelism + Expert Parallelism）策略。
*   **评估指标**：每秒处理 Token 数（TPS/GPU）、每用户吞吐量（TPS/user）、首字延迟（TTFT）以及 Pareto 前沿曲线。

### 4. 资源与算力
*   **硬件平台**：NVIDIA **GB200 NVL72**。
*   **关键特性**：利用了第五代 NVLink（1.8 TB/s 聚合带宽）和 Blackwell 架构的 HBM3e 内存（8 TB/s 带宽）。
*   **实现框架**：基于 **TensorRT-LLM** 推理框架实现。

### 5. 实验数量与充分性
*   **实验规模**：
    *   **消融实验**：涵盖了不同输入序列长度（1K-32K）、不同最大 Token 预算（MNT）、不同负载不平衡度（标准差 0-4096）以及不同 DWDP 组大小（DWDP3, DWDP4）。
    *   **优化验证**：分别验证了权重合并消除和 TDM 调度的增益。
    *   **端到端测试**：在 20-200 TPS/user 的广泛范围内进行了 Pareto 前沿对比。
*   **充分性评价**：实验设计非常充分且具有高度的工业实战价值。作者不仅展示了性能提升，还深入分析了硬件层面的干扰（如功率诱发的频率降频），体现了客观、严谨的工程态度。

### 6. 主要结论与发现
*   **性能提升**：在典型的 8K 输入/1K 输出场景下，DWDP 在 20-100 TPS/user 范围内将端到端输出 **TPS/GPU 提升了 8.8%**。
*   **负载鲁棒性**：随着工作负载不平衡度的增加，DWDP 相比 DEP 的优势更加明显（同步开销被完全消除）。
*   **硬件干扰发现**：研究发现通信与计算重叠时的主要干扰并非内存带宽竞争，而是**功率限制导致的频率降低（DVFS）**。当高强度计算与通信重叠时，GPU 会因触及功耗墙而降频。

### 7. 优点
*   **架构创新**：打破了层级同步的思维定式，将推理任务从“集体行动”转变为“个体独立运行”。
*   **灵活性高**：DWDP 不要求 GPU 数量必须是 2 的幂次，也不要求专家数量能被 GPU 整除，支持更精细的资源分配。
*   **软硬协同**：针对 Blackwell 架构特性（如拷贝引擎、NVLink 5）进行了深度优化。

### 8. 不足与局限
*   **硬件依赖**：该策略高度依赖极高带宽的机架级互联（如 NVL72），在带宽较低的集群（如传统 InfiniBand 连接的 H100 集群）上效果可能受限。
*   **TTFT 权衡**：实验显示，虽然 TPS/GPU 提升了，但在某些配置下 TTFT（首字延迟）会有所增加，这主要是因为 DWDP 允许用更少的 Context GPU 支撑相同的吞吐量，导致排队延迟增加。
*   **适用阶段**：目前主要针对 Context（Prefill）阶段，对于计算强度较低、通信占比更高的 Decoding 阶段，其收益尚待进一步验证。
