## 摘要
在混合专家（Mixture-of-Experts，MoE）模型训练中，分片数据并行会将每个专家的参数划分到多个 GPU 上，因此在每一层执行之前都需要通过 Allgather 操作重构完整的权重矩阵。这类通信通常占据迭代时间的主要部分。以往工作通常采用有损压缩方法来降低这一开销，但会牺牲数值保真度；现有无损方法则未能利用跨迭代的指数稳定性。本文提出跨迭代指数复用 Allgather（Cross-Iteration Exponent Reuse Allgather，CIERA），这是一种面向系统的无损通信方法，用于分片式 MoE 训练。我们观察到，在经过短暂的预热阶段后，大多数权重的指数值在不同迭代之间保持不变。基于这一观察，我们在本地缓存指数值，并在指数未发生变化时仅传输符号位和尾数。接收端通过将缓存的指数值与接收到的数据相结合，能够精确重构原始权重。由于不同层的参数矩阵形状各异，只有在压缩能够带来净时间收益时才会应用压缩。此外，压缩操作与 Allgather 通信及计算过程均以重叠方式执行。真实实验和大规模基于轨迹的模拟器结果表明，在 16 个 GPU 上运行 OLMoE-1B-7B 时，与无损基线相比，CIERA 可实现 3.70 倍加速；与有损基线相比，可实现 3.68 倍加速。预计在 128 个 GPU 上，这两个加速比分别可达到 4.28 倍和 4.42 倍，同时在所有评估运行中均保持参数重构逐位精确。

## Abstract
In training Mixture-of-Experts (MoE) models, sharded data parallelism partitions each expert's parameters across GPUs, requiring an Allgather operation to reconstruct the full weight matrix before each layer executes. This communication often dominates iteration time. Prior work often reduces this overhead using lossy compression methods that sacrifice numerical fidelity, while existing lossless methods do not exploit cross-iteration exponent stability. In this paper, we propose Cross-Iteration Exponent Reuse Allgather (CIERA), a lossless, system-aware communication method for sharded MoE training. We observe that after a brief warmup phase, the exponent values of most weights remain unchanged across iterations. Based on this, we cache exponents locally and transmit only the sign and mantissa when exponents are unchanged. The receiver reconstructs the original weights exactly by combining the cached exponents with the received data. Since parameter matrices vary in shape across layers, compression is applied only when it yields net time savings. Moreover, the compression operation is overlapped with both Allgather communication and computation. Our real experiments and large-scale trace-driven simulator show that on OLMoE-1B-7B at 16 GPUs, CIERA achieves a 3.70x speedup over the lossless baseline and 3.68x over the lossy baseline, projected to reach 4.28x and 4.42x respectively at 128 GPUs, while preserving bitwise-exact parameter reconstruction in all evaluated runs.

### 1.1 研究背景

- 混合专家模型（MoE）通过只激活部分专家来降低单个 token 的计算量，但其参数规模仍然很大。

- MoE 模型的计算与通信比例较低，因此 Allgather 难以被计算过程完全隐藏，逐渐成为训练迭代中的主要通信瓶颈。
- 论文测得，在四种 MoE 模型中，Allgather 占总通信时间的 **51.8%～69.0%**。

### 1.2 现有方法的问题

- **有损压缩方法**，如 ZeRO++，可以减少通信数据量，但会对权重进行量化或近似重构，引入数值误差。
- **传统无损压缩方法**虽然不改变数值，但压缩与解压缩操作可能位于通信关键路径上，额外计算开销可能抵消通信收益。
- 现有方法通常没有充分利用一个重要现象：在训练预热阶段之后，绝大多数浮点权重的**指数位（exponent）在相邻迭代之间保持不变**。

### 1.3 论文的核心含义

CIERA 的基本思想是：

> 对浮点权重进行字段级拆分，将指数、符号位和尾数分开处理；对于跨迭代未变化的指数，在 GPU 本地缓存并复用，仅传输符号位、尾数以及发生变化的指数，从而在不改变权重数值的前提下减少 Allgather 流量。

论文进一步将这一思想与：

1. **块级指数复用**；
2. **基于收益的选择性压缩**；
3. **压缩、通信与计算重叠**

结合起来，形成面向分片式 MoE 训练的系统级无损 Allgather 优化方案。

## 2. 提出的方法论

## 2.1 核心思想：跨迭代复用浮点指数

对于 FP16 或 BF16 权重，每个数值可以拆分为：

- 符号位（sign）；
- 指数位（exponent）；
- 尾数位（mantissa）。

权重数值发生微小变化时，通常只改变尾数，而只有当绝对值跨越某个二的幂边界时，指数才会变化。因此，经过预热后：

- 至少约 **99% 的指数值在相邻迭代之间保持不变**；
- 在不同学习率和数据集下，指数变化率通常低于 1%。

CIERA 将上一迭代的指数保存在本地，在当前迭代中只传输必要部分。

---

## 2.2 块级而非整分片级复用

### 整分片复用的问题

一个分片可能包含约 \(10^6\) 个权重。即使单个权重的指数变化率只有约 \(0.3\%\)，只要分片中有一个指数发生变化，整个分片就必须被视为“发生变化”。

如果假设权重变化相互独立，则整个分片保持不变的概率近似为：

\[
(1-c)^n \approx e^{-cn}
\]

其中：

- \(c\) 是单个指数的变化率；
- \(n\) 是分片中的权重数量。

当 \(c=0.003\)、\(n\approx 10^6\) 时，整分片完全不变的概率几乎为零。因此，整分片级复用收益有限。

### 块级复用

CIERA 将每个分片划分为固定大小的块，每个块包含 \(B\) 个权重。论文最终使用：

\[
B=512
\]

作为默认块大小。

块级复用带来的好处是：

- 只要某个块内的指数没有变化，该块的指数就可以复用；
- 不需要因为一个权重变化而重新发送整个分片的指数；
- 在 \(B=512\) 时，不同模型的块复用率仍具有较大差异，但总体上明显优于整分片复用。

---

## 2.3 基于哈希的指数变化检测

发送端为每个分片中的每个块维护一个持久化的 `HashCache`。

每次 Allgather 前：

1. 提取权重的指数部分；
2. 对每个块的指数计算 128 位哈希；
3. 将当前哈希与上一迭代的缓存哈希比较；
4. 如果哈希不同，则认为该块的指数发生变化；
5. 使用一个 bitmap 标记发生变化的块；
6. 更新对应的哈希缓存。

论文使用两个独立的 64 位 SplitMix64 哈希组合成 128 位哈希，并将单次比较的碰撞概率近似视为：

\[
2^{-128}
\]

论文报告在所有实验中没有观察到哈希碰撞。

需要注意的是，严格来说，这种检测机制依赖哈希不碰撞，因此其工程实现具有极高概率的正确性，而不是形式上完全不依赖随机碰撞假设的确定性判断。

---

## 2.4 通信数据格式

对于一个分片，CIERA 发送：

- 所有权重的符号位和尾数；
- 表示哪些块发生指数变化的 bitmap；
- 发生变化的块对应的指数；
- 对变化指数进一步使用 ANS 进行压缩。

如果某个块的指数未变化，则：

- 不再发送该块的指数；
- 接收端直接从本地 `ExpCache` 中读取上一迭代缓存的指数。

如果指数发生变化，则：

- 发送端发送新的指数；
- 接收端解码后更新对应缓存。

因此，单个分片在某次迭代中的期望传输量可表示为：

\[
S_i^{s+m}+S_i^{bm}+q_iS_i^e
\]

其中：

- \(S_i^{s+m}\)：符号位和尾数部分大小；
- \(S_i^{bm}\)：块级 bitmap 大小；
- \(S_i^e\)：指数部分大小；
- \(q_i\)：该分片的块指数变化率。

接收端通过以下步骤重构权重：

1. 接收 bitmap、符号位和尾数、压缩后的变化指数；
2. 对变化指数进行 ANS 解码；
3. 根据 bitmap 找到变化块；
4. 更新 `ExpCache`；
5. 将缓存中的完整指数与收到的符号位和尾数组合；
6. 恢复原始浮点权重。

只要指数数据正确，重构结果即可与未压缩参数逐位一致。

---

## 2.5 基于收益的选择性压缩（BSC）

CIERA 并不压缩所有参数分片，而是根据预计收益决定是否启用压缩。

论文定义分片 \(i\) 的收益为：

\[
g_i =
\operatorname{Comm}(S_i)
-
\left[
\operatorname{Comm}
\left(
S_i^{s+m}+S_i^{bm}+q_iS_i^e
\right)
+
T_i^{hash}
+
T_i^{cmp}
+
T_i^{decmp}
\right]
\]

其中：

- \(\operatorname{Comm}(\cdot)\)：根据通信数据量估算的 Allgather 延迟；
- \(T_i^{hash}\)：哈希计算时间；
- \(T_i^{cmp}\)：发送端压缩和打包时间；
- \(T_i^{decmp}\)：接收端解压缩和重构时间。

如果 \(g_i\leq 0\)，则该分片不进行压缩。

此外，指数缓存会占用额外显存。世界大小为 \(W\) 时，每个 GPU 的缓存开销约为：

\[
M_i=(W-1)S_i^e
\]

论文按照：

\[
\frac{g_i}{M_i}
\]

对分片进行排序，并在缓存预算限制下优先选择单位缓存空间收益最高的分片。

这种策略能够自动跳过：

- 指数变化频繁的注意力分片；
- 路由门控分片；
- 在当前硬件互联条件下通信收益不足的分片。

通常会优先选择：

- LayerNorm 分片；
- 某些模型中变化率较低的专家 FFN 分片。

## 2.6 计算—通信流水线（CCP）

如果压缩和哈希检查串行执行，额外开销可能达到迭代时间的 **25%～30%**。因此，CIERA 使用 PyTorch FX 对执行图进行重写，并插入以下操作：

1. `Hash`：检查块指数是否变化；
2. `PreDecmp`：提前准备接收端缓存；
3. `Cmp`：构建压缩后的 Allgather 载荷；
4. `Allgather`：传输压缩数据；
5. `Decmp`：解压缩变化指数并重构权重；
6. `Compute`：执行当前层计算。

调度策略是：

- 将哈希和发送端压缩提前到前一层计算或通信期间；
- 将接收端的预处理提前执行；
- Allgather 传输压缩数据；
- 只将最终的 `Decmp` 和权重重构保留在当前层计算之前的关键路径上。

因此，CIERA 的目标不是完全消除压缩成本，而是尽可能把压缩和预处理成本隐藏在已有的计算与通信过程中。

- 32～128 GPU 的结果主要是模拟或外推，并非完整的真实多节点训练测量。
- 某些 FP16 对比结果，尤其是除 OLMoE 外的 ZeRO++ 结果，主要依赖模拟。
- 论文重点关注通信受限的 MoE 训练场景，对通信不敏感或计算占主导的场景覆盖有限。
- 实验没有报告完整的收敛指标、最终任务精度或大规模预训练质量变化，仅主要验证了逐位重构和训练损失一致性。
- 没有提供不同网络拓扑、不同 GPU 型号、不同通信库实现下的广泛结果。
- 性能收益对模型分片结构、互联带宽和指数变化率较敏感，因此不能简单推广到所有模型。

从总体上看，实验设计对论文核心主张——“跨迭代指数复用可以实现高效无损 Allgather”——是较为充分的；但对于大规模部署泛化性和实际生产环境稳定性的论证仍不完整。

## 6. 主要结论与发现

### 6.1 关键经验发现

- Allgather 是分片式 MoE 训练中最重要的通信瓶颈之一，占总通信时间约 **51.8%～69.0%**。
- 预热后大多数权重指数稳定：
  - 在 AG News 上，学习率 \(10^{-5}\) 时平均指数变化率约为 **0.04%～0.11%**；
  - 学习率 \(10^{-4}\) 时约为 **0.30%～0.51%**；
  - OpenWebText 上的变化率约为 **0.44%～0.93%**。
- 整分片级复用效果有限，因为一个分片中只要有少数权重变化，就必须整体标记为变化。
- 块级复用更有效，尤其适合变化集中在部分参数区域的 MoE 模型。
- 不同分片类型的稳定性差异明显：
  - LayerNorm 通常最稳定；
  - 注意力和路由门控分片变化率较高；
  - 专家 FFN 在 OLMoE 上较稳定，但在 DeepSeek 和 MiniCPM 上不一定稳定。

### 6.2 性能结果

- 在 OLMoE-1B-7B、16 GPU、BF16 配置下：
  - 相比 ZeRO-3，CIERA 加速 **3.70 倍**；
  - 相比 ZeRO++，CIERA 加速 **3.68 倍**。
- 在 128 GPU 的模拟结果中：
  - 相比 ZeRO-3，最高达到 **4.28 倍**；
  - 相比 ZeRO++，最高达到 **4.42 倍**。
- 在六个模型上，CIERA 的收益取决于通信是否成为主要瓶颈：
  - OLMoE、DeepSeek、Qwen2 的收益较高；
  - MiniCPM 和 Mixtral 的收益中等；
  - Scout 在 4 GPU NVLink 环境下因为没有任何分片具有正收益，基本不加速；
  - Scout 在更大规模、跨节点通信占主导时才出现收益。

### 6.3 正确性结果

- 在 OLMoE-1B-7B 的 20,000 次训练迭代中：
  - CIERA 和 ZeRO-3 的训练损失曲线完全重合；
  - 最大绝对损失差异为 0；
  - 所有 Allgather 后的参数均实现逐位一致重构。
- 因此，CIERA 的主要优势是同时实现：
  - 较低通信量；
  - 无需牺牲权重数值精度；
  - 较低的关键路径解压缩成本。

## 7. 优点

### 7.1 方法设计亮点

- **利用了浮点表示的结构特性**：不是对完整数值进行近似量化，而是针对指数、符号和尾数进行字段级处理。
- **跨迭代复用具有较强直觉和可解释性**：指数只有在权重幅值跨越二的幂边界时才变化，因此相比完整权重更加稳定。
- **块级复用比整分片复用更合理**：避免少量变化导致整个分片失去压缩机会。
- **无损重构**：目标是恢复原始 BF16/FP16 参数，而不是允许误差范围内的近似参数。
- **系统级优化较完整**：不仅提出编码方式，还考虑了缓存、通信载荷、块选择、GPU stream 和执行图调度。
- **收益驱动选择机制**：避免对变化率高、通信收益低的分片强行压缩，降低了“压缩反而变慢”的风险。
- **适应硬件和通信环境**：通过通信代价模型决定压缩是否值得，在 NVLink 和跨节点网络环境下可作出不同选择。

### 7.2 实验设计亮点

- 覆盖六种 MoE 模型，能够体现模型结构差异带来的影响。
- 同时与 ZeRO-3、FSDP 和 ZeRO++ 比较，兼顾无损和有损基线。
- 消融实验清晰显示三个组件的作用：
  - ER 提供基本通信压缩；
  - BSC 消除不划算分片；
  - CCP 进一步隐藏压缩开销。
- 对层数、序列长度和块大小进行敏感性分析，增强了结论的可解释性。
- 通过长时间逐位正确性测试验证了方法的数值可靠性。

## 8. 不足与局限

### 8.1 实验覆盖范围有限

- 真实硬件测量最多覆盖 16 GPU，64～128 GPU 的结果主要依赖模拟和外推。
- 大规模多节点实验仍缺乏直接验证，尤其是复杂网络拥塞、通信竞争和实际任务负载下的效果。
- 使用的 GPU 主要是 A100，尚未充分验证 H100、H200、B100 等新一代硬件。
- 网络拓扑相对固定，对不同 InfiniBand、以太网、RoCE 或其他互联结构的适应性尚未系统评估。

### 8.2 适用范围受限

- 论文明确指出，CIERA 主要适合稀疏 MoE 训练。
- 对于 dense LLM，由于可压缩分片较少，选择策略可能会跳过大部分分片，整体加速收益显著下降。
- 如果模型权重更新幅度较大、学习率较高或训练阶段指数变化频繁，指数复用的收益会降低。
- 当计算时间远大于通信时间时，减少 Allgather 数据量对总迭代时间的影响有限。
- 在高速节点内互联（如 NVLink）环境中，压缩编码本身可能抵消通信节省，正如 Scout 在 4 GPU 上没有获得收益。

### 8.3 运行时决策仍较静态

- BSC 使用初始化阶段或离线测得的块变化率 \(q_i\)。
- 被选中的分片集合在整个训练过程中固定不变。
- 但训练过程中指数变化率可能随阶段、学习率调度、数据分布和优化器状态变化。
- 因此，静态选择可能无法始终保持最优，论文也将在线 BSC 控制器列为未来工作。

### 8.4 正确性保障存在工程假设

- 块变化检测依赖 128 位哈希。
- \(2^{-128}\) 的碰撞概率极低，且实验中未发现碰撞，但它仍属于概率性检测机制。
- 如果极端情况下发生哈希碰撞，可能导致接收端错误复用旧指数。
- 论文没有进一步讨论哈希校验失败恢复、周期性完整校验或错误检测机制。

### 8.5 基线比较仍有不完全公平之处

- 部分 ZeRO++ 对比，特别是 FP16 下除 OLMoE 外的结果，主要来自模拟而非实测。
- ZeRO++ 的通信设计包含参数量化和梯度通信优化，而 CIERA 主要优化参数 Allgather；两者优化对象并不完全相同。
- 论文指出 ZeRO++ 在节点内 NVLink 环境下量化开销可能抵消通信收益，而跨节点环境中其优势会增强，因此不同硬件规模下的相对结果受基线实现和拓扑影响较大。
- FSDP、ZeRO-3 和 CIERA 的具体实现路径、调度策略和优化程度可能存在差异，实际比较需要结合实现细节解读。

### 8.6 训练质量评估不够全面

- 论文重点验证了参数逐位重构和训练损失一致性。
- 但没有系统报告：
  - 下游任务准确率；
  - 最终验证损失；
  - 不同随机种子下的结果；
  - 不同优化器、学习率调度和训练阶段下的稳定性；
  - 端到端完整预训练的质量指标。
- 因此，数值无损性已经得到较强支持，但对所有训练设置下的通用性仍需更多实验。

## 总体评价

CIERA 的核心贡献在于将“跨迭代指数稳定性”转化为一种面向 MoE 分片训练的无损通信优化机制，并通过块级检测、收益驱动选择和计算—通信流水线解决了传统无损压缩中“压缩开销可能抵消通信收益”的问题。论文的实验证明，在通信受限的 MoE 场景中，该方法能够在保持逐位精确重构的同时获得显著加速，尤其适合大规模、跨节点的分片式训练。不过，其收益依赖于模型的指数稳定性、分片类型、网络带宽和计算通信比例，大规模结果中仍有较多模拟外推成分，因而在更广泛硬件和真实生产环境中的有效性仍需进一步验证。
