## Abstract
Large language model (LLM) inference is constrained by the quadratic scaling of self-attention and the linear scaling of the KV cache, increasing latency, energy consumption, and GPU memory demand as context length scales. Existing soft-compression methods either lack query-guided memory selection at inference time, train without answer-targeted supervision, or couple compression tightly to a specific decoder architecture. We propose a Context-to-Answer-Aligned Memory Compression (CMC) framework, which compresses long input contexts into compact Context Memory Embeddings (CMEs) aligned to any frozen decoder's embedding space, reducing inference costs without modifying decoder weights. CMC introduces a two-tier KV cache that combines question-guided CME selection with a local context window, and trains the compressor with answer-targeted distillation from a frozen LLM. Experiments across nine encoder-decoder combinations and four QA benchmarks show that CMC consistently outperforms the baseline, achieving up to 7.3 EM and 4.0 F1 point gains on SQuAD, while reducing inference time and energy consumption by up to 20% and peak reserved GPU memory by up to 50% at 3,000 generation tokens. Ablation studies confirm that each architectural component and training objective contributes to the performance.

## 1. 核心问题与整体含义

### 1.1 研究背景

长上下文大语言模型在多文档问答、多轮对话和长文档理解中具有重要价值，但其推理成本随上下文长度快速增长：

- Transformer 自注意力的计算复杂度通常随序列长度呈平方增长；
- 自回归生成过程中的 KV Cache 随上下文和生成长度线性增长；
- 长上下文会带来更高的推理延迟、能源消耗和 GPU 显存占用；
- 直接扩展模型上下文窗口或修改注意力结构，往往需要重新预训练或改造已经部署的模型。

现有上下文压缩方法主要存在三类不足：

1. **缺少问题引导的记忆选择**：许多软压缩方法将所有压缩后的记忆向量均匀传给解码器，无法根据当前问题筛选最相关的信息。
2. **缺乏答案导向的训练监督**：部分方法只使用重构损失，优化目标是恢复原始文本，而不是直接提升最终问答质量。
3. **与特定解码器耦合较强**：压缩器输出的表示往往只能被特定模型或特定维度的解码器使用，跨模型部署能力有限。

### 1.2 论文的整体含义

论文提出 **Context-to-Answer-Aligned Memory Compression（CMC）** 框架，将长上下文压缩成紧凑的 **Context Memory Embeddings（CMEs）**，并将这些记忆向量投影到任意冻结解码器的嵌入空间中。

> 不再让冻结的大语言模型直接关注完整长文本，而是先用独立的上下文压缩器生成少量、与问题和答案相关的记忆向量，再结合一个短的局部原文窗口供解码器推理。

CMC试图同时实现：

- 长上下文压缩；
- 跨编码器—解码器架构适配；
- 问题引导的记忆选择；
- 答案导向的压缩训练；
- 限制 KV Cache 长度；
- 在不修改解码器参数的情况下减少推理成本。

## 2. 论文提出的方法论

## 2.1 整体架构

CMC由三个主要模块组成：

1. **ContextEncoder**
   - 对原始长上下文进行去噪、分段和压缩；
   - 使用固定的占位记忆 token 将每个文本片段压缩为若干 CME。

2. **MemoryBridge**
   - 将 ContextEncoder 输出的隐藏向量映射到冻结 DecoderLLM 的输入嵌入空间；
   - 解决编码器和解码器隐藏维度、模型架构不同的问题。

3. **冻结 DecoderLLM**
   - 不更新解码器参数；
   - 接收问题引导筛选后的 CME，以及一个局部原文窗口；
   - 通过两级 KV Cache 进行推理。

最终生成过程可以概括为：

\[
\hat{a}=f_{\theta_d}(\cdot \mid M^*, C_{\text{local}}, q)
\]

其中：

- \(q\) 是问题；
- \(C_{\text{local}}\) 是局部原文窗口；
- \(M^*\) 是根据问题筛选出的 CME；
- \(f_{\theta_d}\) 是冻结的解码器；
- 只有 ContextEncoder 和 MemoryBridge 参与训练。

## 2.2 上下文去噪与分段压缩

### 图结构去噪

论文首先对上下文 token 进行图结构去噪。对于每个 token，计算它与后续若干邻居 token 的余弦相似度：

\[
\cos(e_i,e_j)=
\frac{e_i\cdot e_j}{\|e_i\|\|e_j\|}
\]

如果某个 token 与指定邻域内至少一个后续 token 的相似度达到阈值 \(\tau\)，则保留该 token；否则将其视为低显著性 token 并删除。

该步骤的目的不是简单减少 token 数量，而是：

- 去除语义上孤立或冗余的 token；
- 降低压缩器输入噪声；
- 提高后续 CME 的信息密度。

实验中的主要参数包括：

- 去噪阈值 \(\tau=0.05\)；
- 邻域大小约为 3；
- 每隔一定 token 强制保留 token，以避免上下文被过度删除。

### 分块与记忆 token

去噪后的上下文被切分为固定长度的片段。论文主要使用：

- 每个 chunk 长度 \(t=256\) token；
- 每个 chunk 添加若干个固定的占位记忆 token；
- 压缩率 \(r=t/m^{(c)}\)，其中 \(m^{(c)}\) 是每个 chunk 产生的记忆向量数量；
- 实验考察 \(r\in\{2,4,8\}\)。

每个分段的形式大致为：

```text
原始文本片段 + <MEM> + 若干占位记忆 token + </MEM>
```

占位 token 位于文本之后，因此在因果注意力机制下，它们可以关注前面的文本，并将整段内容压缩到自身隐藏状态中。

## 2.3 CME提取

ContextEncoder是一个可训练的 decoder-only语言模型。对每个文本片段独立处理后，提取最后一层中占位记忆 token 的隐藏状态：

\[
H_i^{(c)}
=
f_{\theta_c}(\tilde{s}_i)
[\text{placeholder positions}]
\]

其中：

- \(H_i^{(c)}\in\mathbb{R}^{m^{(c)}\times H_c}\)；
- \(H_c\) 是 ContextEncoder 的隐藏维度；
- 每个隐藏向量对应一个 CME。

所有分段的 CME 连接起来形成完整记忆矩阵：

\[
H^{(c)}
=
[H_1^{(c)};H_2^{(c)};\ldots;H_{n_s}^{(c)}]
\]

相比硬提示压缩，CMC不是直接删除信息后把剩余 token 输入解码器，而是将上下文编码成连续向量，因此理论上可以保留更丰富的语义信息。

---

## 2.4 MemoryBridge跨架构投影

由于 ContextEncoder 和 DecoderLLM 可能来自不同模型家族，它们的隐藏维度通常不同。因此，CMC使用一个两层 MLP 作为 MemoryBridge，将 CME从 \(H_c\) 维映射到 DecoderLLM 的 \(H_d\) 维：

\[
M^{(i)}=g_\phi(H_i^{(c)})
\]

最终得到解码器可直接接收的记忆表示：

\[
M\in\mathbb{R}^{M_b\times H_d}
\]

### 范数校准

论文还对投影结果进行 LayerNorm、tanh 和范数约束，使 CME 的尺度与冻结解码器的词嵌入尺度相近。

其核心约束是：

\[
\|\tilde{m}\|_2\leq 2\nu
\]

其中 \(\nu\) 与冻结解码器输入 token 嵌入的平均范数相关。

这样做的目的包括：

- 避免投影后的 CME 数值过大；
- 减少连续记忆向量与解码器原生 token embedding 之间的分布偏差；
- 提高跨架构输入的稳定性。

## 2.5 两阶段训练目标

### 阶段一：解码器对齐

第一阶段主要让压缩后的 CME 能够被冻结解码器理解。训练目标包括：

1. **自编码重构损失 \(L_{\text{AE}}\)**  
   使用 CME 让解码器重构完整原始上下文。

2. **自回归重构损失 \(L_{\text{AR}}\)**  
   使用同样的 CME，重点重构上下文前半部分。

总体损失为：

\[
L_1=L_{\text{AE}}+\lambda_{\text{AR}}L_{\text{AR}}
\]

这一阶段的目标是使 CME 包含足够的信息，并与解码器的输入表示空间对齐。

### 阶段二：答案对齐

第二阶段进一步利用问答任务监督，使记忆向量更加关注答案相关信息。

该阶段包含三个损失：

1. **答案交叉熵损失 \(L_{\text{CE}}\)**  
   直接监督解码器生成正确答案。

2. **知识蒸馏损失 \(L_{\text{KL}}\)**  
   将使用压缩记忆的“学生”解码器输出分布，对齐到使用局部文本的“教师”解码器输出分布。

3. **对比学习损失 \(L_{\text{CL}}\)**  
   将所有 CME 的平均表示拉近到教师解码器在答案 span 位置的隐藏状态，使压缩记忆更接近答案语义空间。

总体损失为：

\[
L_2
=
L_{\text{CE}}
+
\lambda_{\text{KL}}L_{\text{KL}}
+
\lambda_{\text{CL}}L_{\text{CL}}
\]

训练过程中：

- ContextEncoder 和 MemoryBridge更新；
- DecoderLLM始终冻结；
- 教师和学生使用同一个冻结解码器，只是输入不同。

## 2.6 两级 KV Cache 推理策略

### Tier-1：问题引导的 CME 选择

首先将问题 token 通过冻结解码器的 embedding 层转化为向量，并进行平均池化，得到问题向量 \(q_{\text{vec}}\)。

对每个 CME 计算余弦相似度：

\[
\text{score}_j
=
\frac{\tilde{m}_j\cdot q_{\text{vec}}}
{\|\tilde{m}_j\|\|q_{\text{vec}}\|}
\]

然后选出得分最高的 Top-\(K\) 个 CME，并按照原始文档位置重新排序，形成 \(M^*\)。

这一步实现了：

- 按问题筛选全局信息；
- 避免将所有 CME 都放入解码器；
- 保留远距离、多段文本中的相关证据。

实验中 \(K\) 通常取 30 或 40。

### Tier-2：局部原文窗口

仅依靠 CME 可能无法准确恢复细粒度答案，例如时间、数字或短语边界。因此，CMC额外保留一个局部原文窗口：

\[
C_{\text{local}}
=
C[\text{start}:\text{start}+W]
\]

窗口大小 \(W\) 的实验值主要为 130 或 256 token。

Tier-2主要负责：

- 提供答案 span 的精确文本；
- 弥补连续向量压缩带来的细粒度信息损失；
- 支持抽取式 QA 中的精确答案生成。

最终预填充输入为：

\[
[\ M^*\ \Vert\ C_{\text{local}}\ \Vert\ q\ ]
\]

因此，生成过程中 KV Cache 长度被限制为：

\[
K+W+|q|
\]

与原始文档长度和生成长度相比，这一缓存规模更加稳定。

- Gemma在四个数据集上均取得改进；
- Mistral在大多数数据集上有所提升，但表现不稳定；
- 在SQuAD、AdversarialQA、HotpotQA和CovidQA中，CMC展示了较好的跨任务适应性。

在 full-data setting下：

- CMC在Llama和Gemma上继续获得性能提升；
- 相比公开软压缩基线，CMC在三个数据集上取得最佳F1；
- 在HotpotQA上，CMC相对PCC-large取得显著提升，说明答案对齐和全局记忆对多跳推理可能有帮助；
- 但在SQuAD和AdversarialQA的EM上，CMC低于PCC-large。

## 6.2 压缩率

压缩率 \(r=4\) 通常是最好的折中：

- \(r=2\)：CME数量过多，可能引入噪声并稀释相关信息；
- \(r=8\)：CME数量过少，可能丢失关键上下文；
- \(r=4\)：在9种编码器—解码器组合中多数情况下取得最好或并列最好结果。

## 6.3 推理效率

在生成3,000 token时，论文报告：

- 推理时间最多降低约20%；
- 能耗最多降低约20%；
- 峰值 reserved GPU memory 最多降低约50%，附录中Mistral实验最高约62.5%；
- 注意力MAC平均降低约27%，不同组合约为6.6%—51.3%。

效率提升主要来自：

- 压缩后输入长度更短；
- KV Cache长度由固定的 \(K+W+|q|\) 控制；
- 随着生成长度增加，基线 KV Cache持续增长，而CMC的缓存规模基本保持稳定。

## 6.4 组件作用

消融结果表明：

- 图结构去噪不是单纯的计算优化，而是会直接影响 CME质量；
- 问题引导的 Top-K选择比随机选择更有效；
- Tier-2 局部窗口对抽取式QA尤其关键；
- Phase-2中的CE、KL和对比学习损失具有互补作用；
- CME负责全局语义覆盖，局部窗口负责精细答案抽取。

## 7. 方法与实验设计的优点

### 7.1 方法层面的优点

- **不修改冻结解码器参数**  
  适合已经部署的LLM，不需要对大型解码器进行重新训练。

- **具备跨架构能力**  
  MemoryBridge使不同ContextEncoder和DecoderLLM可以组合，论文通过9种组合进行了验证。

- **融合全局和局部信息**  
  CME提供全局语义覆盖，局部窗口提供答案span级别的精确文本，这一设计较适合抽取式问答。

- **引入答案导向训练**  
  相比只进行文本重构，Phase-2直接使用答案交叉熵、KL蒸馏和对比损失优化最终问答表现。

- **KV Cache长度有明确上界**  
  通过两级缓存将缓存长度限制在 \(K+W+|q|\)，理论上能够缓解长生成中的显存增长。

- **加入嵌入范数校准**  
  通过MemoryBridge的归一化和范数约束，降低跨模型表示分布不一致的风险。

### 7.2 实验层面的优点

- 模型组合较丰富；
- 同时评估准确率和系统效率；
- 同时报告时间、能耗、MACs和GPU显存；
- 包含较系统的结构和损失函数消融；
- 对压缩率、局部窗口、去噪阈值进行了敏感性分析；
- 通过BM25、CME定位和中点启发式测试了非 oracle部署场景；
- 提供定性案例，展示CMC在重复数字、长答案片段和细粒度时间信息上的优势与不足。

## 8. 不足与局限

### 8.1 任务覆盖不足

论文仅在英文抽取式 QA 上进行验证，尚未覆盖：

- 摘要；
- 开放式问答；
- 长文本生成；
- 多文档生成；
- RAG；
- 多轮对话；
- 多语言或跨语言场景。

因此，CMC是否适用于需要自由生成或复杂规划的任务仍不明确。

### 8.2 对答案位置的依赖

主实验中局部窗口以 gold answer offset 为中心，这会带来一定的 oracle 信息：

- 实际部署中通常无法直接获得答案位置；
- Tier-2的效果可能因此被高估；
- 非 oracle定位实验显示，AdversarialQA上的性能下降较明显。

尽管作者补充了BM25等方法，但完整的端到端答案定位与压缩推理流程仍需要进一步研究。

### 8.3 训练目标和推理流程之间存在任务耦合

Phase-2使用答案 span的教师隐藏状态进行对比学习，因此方法明显依赖：

- 已知答案；
- 已知答案位置；
- 抽取式问答监督。

这使其更适合有标注答案的任务，不一定能直接推广到无答案标注的通用长上下文推理。

### 8.4 部分结果不稳定

Mistral在full-data setting下的SQuAD和HotpotQA表现明显下降，说明：

- 两阶段训练的步数分配仍需针对不同解码器调节；
- 固定的Phase-2 KD预算可能不适合所有数据规模；
- CMC并非对所有解码器都稳定优于基线。

### 8.5 压缩带来的细粒度信息损失

案例分析表明，CMC可能：

- 丢失月份、数字或限定词；
- 将“June 1979”压缩成“1979”；
- 在答案边界识别上不如直接使用局部文本。

这也是Tier-2局部窗口不可或缺的原因，但同时削弱了系统完全依赖软记忆压缩的能力。

### 8.6 计算收益受场景影响

CMC需要额外执行：

- 上下文去噪；
- 分块编码；
- CME生成；
- MemoryBridge投影；
- 问题相关性打分。

在生成较短、上下文较短或请求量较小的场景中，压缩开销可能抵消部分推理收益。论文也显示，压缩成本近似与样本数量相关，但与生成长度基本无关，因此收益更适合长生成场景。

### 8.7 算力报告不完整

论文说明使用单张A100 80GB、4-bit量化和1个epoch训练，但没有完整报告：

- 总训练时间；
- 每个模型组合的训练时长；
- 总GPU小时；
- 训练阶段能耗；
- 多次运行的方差和置信区间。

因此，资源可复现性和成本评估仍不够完整。

### 8.8 基线比较存在架构差异

CMC与PCC等已发表方法的比较中，部分方法采用了不同规模的编码器、解码器或训练配置。因此：

- CMC的性能差异未必完全来自压缩策略；
- 模型规模、解码器能力和数据规模可能同时影响结果；
- 对公开基线的结论应更谨慎解释。

---

总体而言，CMC提出了一种较完整的长上下文软压缩方案，将**跨架构记忆投影、问题引导选择、答案导向蒸馏和两级KV Cache**结合起来。在抽取式问答和长生成场景下，它在保持或提升任务性能的同时，展示了较明显的时间、能耗和显存优势。不过，该方法对局部答案窗口、答案标注和特定QA训练流程仍有依赖，且在不同解码器上的稳定性、非 oracle 部署能力以及向开放式生成任务的泛化能力仍需进一步验证。
