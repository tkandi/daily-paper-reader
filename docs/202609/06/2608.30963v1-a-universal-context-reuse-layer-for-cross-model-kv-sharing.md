## 摘要
现代大语言模型（LLM）服务系统越来越多地处理重复或共享的上下文，但即使其他模型已经处理过相同输入，每个模型通常仍需独立执行预填充（prefill）计算。现有的 KV 缓存复用机制能够显著减少单个模型内部的冗余计算，但通常假设缓存的生产者与消费者是同一模型。本文研究跨模型 KV 共享（cross-model KV sharing）问题：将源模型生成的 KV 状态转换为可供不同目标模型使用的表示，其中源模型与目标模型可以在规模、架构、注意力配置、分词器和模型系列等方面存在差异。我们在同系列模型和跨系列模型两种设置下评估了该方法。对于 Qwen2.5-7B → Qwen2.5-1.5B，转换后的 KV 状态将 LongBench2 准确率从 27.59% 提升至 34.48%，相较于原生 1.5B 基线提高了 6.89 个百分点，同时与目标模型原生预填充相比降低了交接成本。在跨系列的 Qwen2.5-1.5B → Gemma-2-2B 设置下，KV 交接在 4K 上下文长度时最多可将目标侧预填充成本降低 67.05%，同时使解码困惑度保持在接近原生模型基线的水平。在更加异构的 Llama3.1-70B → Qwen2.5-7B 设置下，跨系列交接取得了 44.0% 的准确率，而 Qwen2.5-7B 原生推理的准确率为 45.7%；与此同时，实测延迟从 899ms 降至 138ms。这些结果初步表明，KV 状态可以作为可迁移的计算表示，而不必严格局限于特定模型的本地缓存，并促使我们将“上下文迁移性”（context mobility）视为一种系统抽象，以减少异构 LLM 和多智能体推理工作流中的冗余预填充计算。

## Abstract
Modern large language model (LLM) serving systems increasingly operate over repeated or shared context, yet each model typically performs its own prefill computation even when another model has already processed the same input. Existing KV-cache reuse mechanisms substantially reduce redundant computation within a single model, but generally assume that the producer and consumer of a cache are identical. We study \emph{cross-model KV sharing}, which translates the KV state produced by a source model into a representation that can be consumed by a different target model, including models that differ in scale, architecture, attention configuration, tokenizer, and model family. We evaluate the approach in both within-family and cross-family settings. For Qwen2.5-7B $\rightarrow$ Qwen2.5-1.5B, translated KV states improve LongBench2 accuracy from 27.59\% to 34.48\%, a gain of 6.89 percentage points over the native 1.5B baseline, while reducing handoff cost relative to native target prefill. For the cross-family Qwen2.5-1.5B $\rightarrow$ Gemma-2-2B setting, KV handoff reduces target-side prefill cost by up to 67.05\% at 4K context length while maintaining decoding perplexity close to native-model baselines. In a more heterogeneous Llama3.1-70B $\rightarrow$ Qwen2.5-7B setting, cross-family handoff achieves 44.0\% accuracy compared with 45.7\% for native Qwen2.5-7B inference, while reducing measured latency from 899ms to 138ms. These results provide initial evidence that KV states can serve as transferable computational representations rather than strictly model-local caches, and motivate \emph{context mobility} as a systems abstraction for reducing redundant prefill across heterogeneous LLM and multi-agent inference workflows.

# 1. 核心问题与整体含义

## 研究动机

现代 LLM 服务逐渐从“单模型、单轮请求”转向由多个模型协作的异构工作流，例如：

- **模型路由与级联（routing/cascading）**：先让小模型处理简单问题，再将复杂问题升级给大模型；
- **多智能体系统**：多个不同模型共享对话历史、检索文档、工具输出或任务状态；
- **生成—验证流水线**：一个模型生成答案，另一个模型复核或批评；
- **多模型部署环境**：不同模型承担成本、延迟、能力或专业领域上的不同角色。

这些工作流中，多个模型常常需要理解同一段长上下文。然而，现有推理系统中，每个模型通常都要从原始 token 重新执行完整的 **prefill（预填充）**，构建自身的 KV Cache。即便前一个模型已经处理过完全相同的上下文，后一个模型仍无法直接使用其缓存。

因此，重复 prefill 会带来：

- 长上下文下显著的 GPU 计算冗余；
- 首 token 延迟增加；
- 显存访问、跨设备传输和服务成本增加；
- 多模型、多智能体场景中随模型数增长而累积的重复计算。

## 核心问题

论文提出的问题是：

> 能否将源模型已经计算出的 KV 状态，转换为另一个、可能架构完全不同的目标模型可直接消费的表示，从而避免目标模型重新进行完整 prefill？

传统 KV Cache 被视为**严格模型私有**的运行时状态；本文挑战这一假设，将其重新定义为一种可能跨模型迁移的“上下文计算结果”。

## 整体含义：Context Mobility

论文将这一思想概括为 **context mobility（上下文迁移性 / 上下文流动）**：

- 上下文经过一个模型处理后，其计算价值不应随该模型调用结束而消失；
- 已经完成的上下文理解可以被保存、传输、翻译，并由其他模型继续利用；
- KV Cache 不只是模型内部缓存，也可以成为异构模型之间流动的计算资产。

这对长上下文、多模型服务和多智能体系统具有潜在系统意义：系统可以不再让每一个新模型调用都从原始文本开始计算。

# 2. 方法论：跨模型 KV 共享层

## 核心思想

设共享上下文为：

\[
C=(x_1,x_2,\ldots,x_L)
\]

对于源模型 \(A\)，预填充后生成层级 KV 状态：

\[
KV_A(C)=\{(K_A^{(1)},V_A^{(1)}),\ldots,(K_A^{(N)},V_A^{(N)})\}
\]

传统做法中，目标模型 \(B\) 仍需独立计算：

\[
KV_B(C)=\text{Prefill}(B,C)
\]

本文引入一个可学习的**传输 / 翻译层（transport / translation layer）** \(T_{A\rightarrow B}\)，将源模型缓存映射为目标模型可使用的状态：

\[
\widehat{KV}_B(C)=T_{A\rightarrow B}(KV_A(C))
\]

随后，冻结的目标模型直接基于 \(\widehat{KV}_B(C)\) 进行解码，而不再对完整 prompt 执行自身的 prefill。

## 关键认识：不是简单张量变形

论文强调，跨模型 KV 转换并不是简单的：

- 改变张量 shape；
- 截断或填充维度；
- 不同设备之间复制缓存；
- 将某层缓存机械对应到另一层。

原因在于源、目标模型可能在以下方面不同：

- 参数规模；
- Transformer 层数；
- 隐藏层维度；
- 注意力头数与 KV heads 配置；
- 注意力机制；
- tokenizer；
- 模型家族及训练分布；
- 内部表示空间。

源模型 KV 反映的是其特定的上下文编码方式；目标模型能否从转换后状态中继续解码，取决于转换器能否保留对目标预测有用的上下文信息。

## 训练目标

论文给出了一个基础的表征对齐目标：

\[
\mathcal{L}_{KV}
=
D\big(T_{\theta}(KV_A(C)),KV_B(C)\big)
\]

其中：

- \(T_\theta\)：带参数 \(\theta\) 的 KV 翻译模块；
- \(D(\cdot,\cdot)\)：源—目标 KV 状态间的某种距离函数；
- \(KV_B(C)\)：目标模型原生 prefill 得到的缓存，用作训练时的监督信号。

不过，论文也指出，直接最小化 KV 数值距离不一定是最优目标。更实际的目标可以是让翻译后的缓存保持：

- 相近的目标模型 logits；
- 相近的注意力行为；
- 更低的解码 perplexity；
- 更高的下游任务准确率。

换言之，所需的并非严格满足：

\[
\widehat{KV}_B(C)=KV_B(C)
\]

而是使得 \(\widehat{KV}_B(C)\) 足以支持目标模型后续以可接受质量完成推理。

## 系统执行流程

论文中的交接流程可以概括为：

1. **源模型 prefill**：源模型 \(A\) 对上下文 \(C\) 执行 prefill，生成 \(KV_A(C)\)。
2. **KV 翻译**：传输模块 \(T_{A\rightarrow B}\) 将源 KV 映射为目标兼容状态 \(\widehat{KV}_B(C)\)。
3. **缓存传输与组装**：将翻译后的 KV 经由设备间复制、缓存组装等过程部署至目标推理环境。
4. **目标模型直接解码**：目标模型 \(B\) 跳过完整 prompt prefill，直接从翻译后的 KV 状态开始生成。
5. **回退机制**：当翻译路径在质量或效率上不满足要求时，系统可退回目标模型原生 prefill。

其经济性条件可表述为：

\[
C_{\text{trans}}+C_{\text{overhead}}<C_{\text{prefill}}
\]

即：翻译、传输、组装等额外成本之和，必须小于目标模型重新 prefill 的成本，同时还要满足应用对输出质量的约束。

# 6. 主要结论与发现

## 1）同家族 KV 迁移可以为小模型带来额外上下文能力

在 Qwen2.5-7B → Qwen2.5-1.5B 上：

- Qwen2.5-7B 原生准确率：**45.69%**；
- Qwen2.5-1.5B 原生准确率：**27.59%**；
- 7B KV 转换后由 1.5B 解码：**34.48%**。

即，translated KV handoff 相较原生 1.5B 带来：

\[
34.48\%-27.59\%=6.89\text{ 个百分点}
\]

论文认为，这说明即使目标模型参数完全冻结，源模型 KV 中也确实携带了可迁移的上下文信息。

相对于 1.5B 与 7B 的性能差距，handoff 恢复了约 **38.1%** 的准确率缺口。

## 2）长上下文下，交接的效率优势更明显

Qwen2.5-7B → Qwen2.5-1.5B 的延迟结果为：

| 上下文长度 | 1.5B 原生 prefill | Handoff | 相对目标 prefill 加速 |
|---|---:|---:|---:|
| 8K–16K | 158.7 ms | 34.5 ms | 约 4.6× |
| 16K–32K | 288.3 ms | 53.8 ms | 约 5.4× |

相较源端 7B 的原生 prefill，handoff 分别约快：

- **14.5×**；
- **16.7×**。

随着上下文变长，避免重复 prefill 的价值更突出。

## 3）跨家族、近似规模模型之间也能够实现有效迁移

在 Qwen2.5-1.5B → Gemma-2-2B 中，相比 Gemma 原生 prefill：

| Prompt 长度 | Gemma 原生 prefill | Handoff 延迟 | 延迟降低 |
|---|---:|---:|---:|
| 128 | 5.492 ms | 3.007 ms | 45.25% |
| 1K | 40.105 ms | 16.081 ms | 59.90% |
| 4K | 181.706 ms | 59.897 ms | 67.04% |

主要发现是：**上下文越长，跨模型 handoff 的相对收益越高。**

在解码质量上，handoff 的 perplexity 与 Gemma 原生推理总体接近：

- 在 \(H=1\) 时，handoff perplexity 为 **14.086**，优于 Qwen native 的 14.721 和 Gemma native 的 14.384；
- 在 \(H=32\)、\(H=128\) 时，也略优于 Gemma native；
- 但在 \(H=16\)、\(H=512\) 时较 Gemma native 更差；
- \(H=512\) 时 handoff 为 14.037，Gemma native 为 13.574。

这说明翻译状态在初始解码及部分中短 horizon 上有较强可用性，但其效果并不在所有生成长度上稳定占优。

## 4）在高异构、大到小设置中，可接近目标模型原生准确率

在 Llama3.1-70B → Qwen2.5-7B 中：

| 推理模式 | 准确率 | 延迟 |
|---|---:|---:|
| Llama3.1-70B 原生 | 44.0% | 7,328 ms |
| Qwen2.5-7B 原生 | 45.7% | 899 ms |
| Llama → Qwen KV handoff | 44.0% | 138 ms |

Handoff：

- 与 Llama3.1-70B 原生准确率相同；
- 仅比 Qwen2.5-7B 原生低 **1.7 个百分点**；
- 保留约 **96.3%** 的目标模型原生准确率；
- 相对 Qwen2.5-7B 原生推理约快 **6.5×**；
- 相对 Llama3.1-70B 原生推理约快 **53.1×**。

这为“跨模型 KV 可以承载可迁移上下文计算”提供了最有代表性的结果之一。

# 7. 优点与亮点

## 方法层面的亮点

- **重新定义 KV Cache 的系统角色**  
  将 KV 从模型私有、短暂的推理缓存，提升为可跨模型传输的计算表示，具有明确的系统抽象价值。

- **问题重要且契合现实工作流**  
  模型路由、级联、多智能体、RAG、验证流水线都天然存在共享上下文，论文针对的是现实服务系统中的重复 prefill 痛点。

- **不要求目标模型重新 prefill**  
  目标模型能够直接从翻译后的状态解码，是比单纯缓存搬运更强的跨模型复用形式。

- **支持异构性较强的模型组合**  
  实验涉及 Qwen、Gemma、Llama，覆盖同家族、跨家族及显著规模差异，说明方法并非仅限于相同架构的微调变体。

- **将质量与效率共同作为目标**  
  不只展示延迟降低，也报告准确率和 perplexity，避免将系统加速与模型可用性割裂开来。

## 实验层面的亮点

- **覆盖长上下文**：测试到 32K context，符合 KV Cache 优化最有价值的使用条件。
- **延迟收益随长度增长而增强**：实验结果与理论预期一致，增强了论证的可信度。
- **展示组件级成本**：报告 translation、P2P copy、cache assembly 的部分时间，为后续系统优化提供了切入点。
- **指出长上下文质量退化现象**：没有完全回避问题；例如 16K–32K 的 handoff 准确率显著低于 8K–16K，说明作者至少呈现了不利结果。
- **强调增量成本口径**：明确 handoff 延迟不包含源 prefill，避免将其直接包装成无条件端到端加速，表述相对谨慎。

# 8. 不足与局限

## 方法细节不足

论文对最关键的 translator 实现描述较抽象，缺少可复现所需的细节，例如：

- translator 的具体网络结构；
- 是否逐层、逐 head 或跨层映射；
- 源、目标层数不同如何对应；
- KV 维度和 attention head 数不同时如何处理；
- 是否分别翻译 K 与 V；
- 是否使用线性层、MLP、低秩适配器、注意力模块或 mixture-of-translators；
- 使用何种损失函数及各损失项权重；
- 训练数据规模、训练过程和超参数；
- 不同 tokenizer 下，源、目标 token 序列如何对齐；
- 如何处理 RoPE、位置编码、GQA/MQA 等结构差异。

这些信息的缺失使得该工作更像是一个可行性报告，而不是完全可复现、可部署的方法论文。

## “通用性”证据仍有限

标题中的 “Universal” 较强，但现有实验不足以完全支撑这一结论：

- 仅有 3 组模型对；
- 模型家族仅覆盖 Qwen、Gemma、Llama；
- 没有覆盖更多参数档位、更多层数配置和注意力模式；
- 没有验证 encoder-decoder、MoE、视觉语言模型、长上下文专门模型等；
- 未研究多个源模型向一个目标模型、或一个源模型向多个目标模型的扩展性；
- 未展示新模型对是否需要重新训练 translator，以及训练成本如何随模型数量增长。

实际上，每增加一个模型对，是否都需要一个独立 \(T_{A\rightarrow B}\)，是影响该方案真正“通用性”的关键问题。

## 缺少重要基线比较

尽管相关工作部分列举了 DroidSpeak、MoT、同家族线性映射等工作，实验中未进行直接比较。因此无法回答：

- 本文的 translator 相比简单线性映射提升多少；
- 相比 MoT 等跨异构翻译方法有何优势；
- 是否优于仅复用某些层、部分重算或混合 prefill 的策略；
- 是否可以通过更简单的缓存压缩、传输或部分 token 重算达到接近收益；
- 相比传统 prefix cache、CacheBlend、KVCOMM，在真实多智能体工作流中总体成本如何。

## 延迟结论依赖于“源 KV 已存在”

本文最重要的性能优势建立在一个必要前提上：

> 源模型已经因为自身业务需求执行过 prefill，并且 KV Cache 可以获得。

如果没有这一前提，而是单纯为了给目标模型提供 translated KV 而运行源模型，则应比较：

\[
C_{\text{source prefill}}
+
C_{\text{translation}}
+
C_{\text{transfer}}
\]

与：

\[
C_{\text{target prefill}}
\]

在源模型比目标模型大得多时，前者可能明显更昂贵。因此，该方法最适合：

- 先前模型本来就要处理该上下文；
- 后续确实会调用另一个模型；
- 上下文足够长；
- KV 可在可接受时间和带宽成本下保存与传输；
- translator 的质量满足任务要求。

它不是对所有单模型请求都天然有效的优化。

## 长上下文与长解码稳定性仍有挑战

实验已经显示出一定质量下降：

- Qwen 同家族 handoff 在 8K–16K 为 40.74%，在 16K–32K 降至 32.58%，下降 **8.16 个百分点**；
- Qwen → Gemma 在 \(H=512\) 时的 perplexity 明显高于 Gemma 原生状态。

这意味着：

- 翻译误差可能随上下文长度累积；
- 初始 KV 表示偏差会在多步自回归生成中逐步传播；
- 跨模型映射可能更擅长保留局部或短期上下文信息，而难以稳定保持超长范围依赖。

## 系统部署因素尚未充分评估

实际部署还会受到以下因素影响，而论文尚未系统验证：

- KV Cache 的显存占用及长期持久化成本；
- 跨 GPU、跨节点、跨机房传输带宽与网络延迟；
- 多租户并发下的缓存竞争和调度；
- 不同请求之间的 KV 生命周期管理；
- 源模型和目标模型不在同一硬件节点时的通信代价；
- translator 推理开销随 context length、batch size 和模型规模的增长规律；
- 缓存安全、隔离、隐私和租户边界问题；
- 任务失败时从 translated KV 回退到原生 prefill 的额外代价。

## 评测统计有限

- LongBench2 仅评估 116 个样本；
- 延迟测量仅提到每个长度 bucket 3 个样本；
- 未报告均值之外的方差、P50/P95/P99、置信区间或显著性；
- 未展示不同随机种子下 translator 训练和推理结果的稳定性；
- 没有在开放式生成、代码、数学、RAG、多轮对话等更多任务类型上系统检验输出质量。

因此，现有结果足以说明方法的潜力，但仍不足以充分证明其在生产级、多负载环境中的可靠性与普适性。
