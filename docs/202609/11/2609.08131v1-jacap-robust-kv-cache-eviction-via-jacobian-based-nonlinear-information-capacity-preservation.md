## 摘要
KV 缓存淘汰对于扩展大语言模型的长上下文推理至关重要。然而，现有策略主要依赖经验启发式方法，缺乏对固有非线性 softmax 注意力机制下 token 效用的严格刻画。在本文中，我们从局部信息几何的视角重新审视 KV 缓存淘汰问题，将注意力过程建模为非线性高斯通信信道。通过对注意力映射进行一阶泰勒展开，我们推导出雅可比信息容量（Jacobian Information Capacity）这一新目标函数，该目标显式刻画了查询相关性、softmax 敏感性和结构多样性。在该理论的指导下，我们提出 Jacap，一种感知容量的淘汰方法，利用 softmax 感知的重要性加权和统计杠杆分数进行子集选择。在不同架构和基准上的大量实验表明，Jacap 在多数场景下均能取得更优性能，尤其是在高压缩率条件下。

## Abstract
Key-value (KV) cache eviction is essential for scaling long-context inference in Large Language Models. However, existing policies predominantly rely on empirical heuristics, lacking a rigorous characterization of token utility under the inherently nonlinear softmax attention mechanism. In this work, we rethink KV cache eviction through the lens of local information geometry, modeling the attention process as a nonlinear Gaussian communication channel. By performing a first-order Taylor expansion of the attention mapping, we derive the Jacobian Information Capacity, a novel objective that explicitly captures query relevance, softmax sensitivity, and structural diversity. Guided by this theory, we introduce Jacap, a capacity-aware eviction method that utilizes softmax-aware importance weighting and statistical leverage scores for subset selection. Extensive experiments across diverse architectures and benchmarks demonstrate that \textsc{Jacap} delivers superior performance in most scenarios, particularly in high-compression regimes.

# 2. 方法论：Jacobian Information Capacity 与 Jacap

## 2.1 将注意力建模为非线性信息通道

对于一个候选 KV 子集 \(C\)，论文将保留后的注意力映射写为：

\[
f_C(q)=U_C\,\mathrm{softmax}\left(\frac{K_Cq}{\sqrt{d_k}}\right)
\]

其中：

- \(q\)：未来查询向量；
- \(K_C\)：保留 token 的 Key 矩阵；
- \(U_C\)：由 Value 经过输出投影后得到的输出方向矩阵；
- \(d_k\)：Key/Query 的维度。

为了描述推理过程中的不确定性，论文进一步加入高斯噪声：

\[
Y_C=f_C(q)+\epsilon,\qquad 
\epsilon\sim\mathcal{N}(0,\Sigma_{\text{noise}})
\]

并将保留缓存的效用定义为查询与注意力输出之间的互信息：

\[
L_C=I(q;Y_C\mid Z_C)
\]

这意味着缓存的重要性不再只是“当前是否被关注”，而是“未来查询能够从该缓存输出中获得多少信息”。

## 2.2 一阶泰勒展开与局部雅可比矩阵

论文假设未来查询集中在某个中心 \(\mu_Q\) 附近：

\[
q=\mu_Q+\delta q,\qquad 
\delta q\sim\mathcal{N}(0,\Lambda_Q)
\]

其中：

- \(\mu_Q\)：未来查询的均值或代表性中心；
- \(\Lambda_Q\)：未来查询的协方差，表示查询变化方向和不确定性。

在 \(\mu_Q\) 附近对非线性注意力映射做一阶泰勒展开：

\[
f_C(q)\approx f_C(\mu_Q)+J_C\delta q
\]

其中 \(J_C\) 是注意力映射关于查询 \(q\) 的雅可比矩阵。通过 Softmax 的导数，可以得到：

\[
J_C=\frac{1}{\sqrt{d_k}}U_CS_CK_C
\]

这里的 Softmax 竞争矩阵为：

\[
S_C=\mathrm{Diag}(\alpha_C^\star)
-\alpha_C^\star(\alpha_C^\star)^\top
\]

\[
\alpha_C^\star=
\mathrm{softmax}\left(\frac{K_C\mu_Q}{\sqrt{d_k}}\right)
\]

该分解具有明确的解释：

- \(K_C\)：描述 token 对查询的可访问性和匹配程度；
- \(U_C\)：描述 token 在输出空间中的信息方向；
- \(S_C\)：描述 Softmax 的局部敏感性及 token 间竞争；
- \(\Lambda_Q\)：描述未来查询的统计分布；
- \(\Sigma_{\text{noise}}\)：描述模型输出中的不确定性或噪声。

## 2.3 雅可比信息容量

在局部线性化后，非线性通道近似为线性高斯通道，其信息容量可以写成：

\[
L_C^{\text{Jac}}
\approx
\frac{1}{2}
\log\det\left(
I+
\Sigma_{\text{noise}}^{-1}
J_C\Lambda_QJ_C^\top
\right)
\]

代入雅可比矩阵后得到：

\[
L_C^{\text{Jac}}
\approx
\frac{1}{2}
\log\det\left(
I+
\frac{1}{d_k}
\Sigma_{\text{noise}}^{-1}
U_CS_CK_C\Lambda_QK_C^\top
S_CU_C^\top
\right)
\]

与先前的线性容量目标相比，核心新增项是 \(S_C\)。它显式保留了 Softmax 的非线性局部性质：

- 当某个 token 的注意力权重接近 0 或 1 时，其局部敏感度趋近于 0；
- 当注意力权重处于中等范围时，Softmax 对查询扰动更敏感；
- 一个 token 的 logit 增大，会通过归一化机制降低其他 token 的注意力权重，因此 token 之间存在竞争关系。

这使得 Jacap 不再简单地认为“注意力越高，token 越重要”，而是试图寻找在未来查询扰动下仍能产生有效变化、且输出方向彼此互补的 token。

## 2.4 从理论目标到高效评分规则

直接最大化依赖子集 \(C\) 的 log-determinant 目标计算代价较高，因此论文进行了三步近似。

### （1）Softmax 竞争矩阵对角化

将完整的 \(S_C\) 近似为对角矩阵：

\[
S_C\approx\mathrm{Diag}(\rho_i)
\]

其中：

\[
\rho_i=\bar{\alpha}_i(1-\bar{\alpha}_i)
\]

\(\bar{\alpha}_i\) 是在全部候选 token 上，以 \(\mu_Q\) 为中心计算得到的局部注意力权重。

该项体现 Softmax 的“敏感性—饱和度”权衡：

- \(\bar{\alpha}_i\) 太小：token 几乎不参与注意力；
- \(\bar{\alpha}_i\) 太大：token 可能处于饱和状态；
- 中等注意力权重：局部响应能力更强。

### （2）查询响应协方差对角化

将：

\[
K_C\Lambda_QK_C^\top
\]

近似为对角矩阵，其第 \(i\) 个对角元素为：

\[
\kappa_i=k_i^\top\Lambda_Qk_i
\]

\(\kappa_i\) 表示未来查询变化时，第 \(i\) 个 Key 的 logit 响应方差。

### （3）构造非线性重要性权重

综合 Softmax 敏感度和查询响应方差，得到：

\[
w_i=\frac{1}{d_k}
\left[\bar{\alpha}_i(1-\bar{\alpha}_i)\right]^2
\left(k_i^\top\Lambda_Qk_i\right)
\]

该权重同时考虑：

- 查询相关性：\(\bar{\alpha}_i\)；
- Softmax 局部敏感性：\(\bar{\alpha}_i(1-\bar{\alpha}_i)\)；
- 查询空间中的变化潜力：\(k_i^\top\Lambda_Qk_i\)。

## 2.5 统计杠杆分数与算法流程

论文进一步构造候选池的容量矩阵：

\[
A_{\text{Jac}}
=
I+\sum_{j\in H_t}w_ju_ju_j^\top
\]

其中 \(u_i\) 是 token 的输出方向。如果不希望额外执行输出投影 \(W_O\)，则可以直接使用 \(v_i\) 作为轻量级近似。

每个 token 的最终评分为：

\[
r_i^{\text{Jac}}
=
w_i\,u_i^\top A_{\text{Jac}}^{-1}u_i
\]

该分数包含两部分：

- \(w_i\)：token 的局部非线性信息权重；
- \(u_i^\top A_{\text{Jac}}^{-1}u_i\)：统计杠杆分数，衡量该 token 是否提供了当前候选集合中尚未充分覆盖的新输出方向。

算法流程可以概括为：

1. 根据历史查询估计 \(\mu_Q\) 和 \(\Lambda_Q\)；
2. 在候选 KV 池上计算以 \(\mu_Q\) 为中心的 Softmax 权重；
3. 计算每个 token 的 Softmax 敏感度和查询响应方差；
4. 得到非线性重要性权重 \(w_i\)；
5. 构造输出空间容量矩阵 \(A_{\text{Jac}}\)；
6. 计算每个 token 的杠杆分数；
7. 选择得分最高的 \(B\) 个 token 保留。

在复杂度方面，论文给出的单次、单层淘汰复杂度约为：

\[
O(Nd_h^2+d_h^3)
\]

其中 \(N\) 是候选 token 数量，\(d_h\) 是注意力头维度。相比仅做逐 token 打分的启发式方法，Jacap 需要额外的矩阵构造、求逆和杠杆分数计算，但与同类容量感知方法相比属于相近复杂度。

# 3. 实验设计

## 3.1 LongBench 长上下文理解

- **数据集**：LongBench。
- **模型**：
  - Qwen3-8B；
  - Qwen3-14B；
  - Llama 3.1-8B。
- **压缩率**：0.25、0.5、0.75、0.9。
- **评测任务**：涵盖单文档问答、多文档问答、摘要、少样本学习、合成任务和代码任务等。
- **对比方法**：
  - CAPKV；
  - SnapKV；
  - KeyDiff；
  - Expected Attention（EA）；
  - KNorm。
- **主要观察**：
  - 在压缩率为 0.75 时，Jacap 通常与 CAPKV 相当或略优；
  - 在压缩率为 0.9 的极端压缩场景下，Jacap 的平均得分通常领先下一名基线约 5 分；
  - Jacap 在单文档问答和多文档问答上表现较稳健；
  - 在摘要和少样本任务中，随着压缩加剧，其性能下降相对平缓。

## 3.2 Needle-in-a-Haystack（NIAH）

- **数据集 / 场景**：Needle-in-a-Haystack。
- **模型**：Qwen3-8B。
- **上下文长度**：约 10k–120k tokens。
- **针的位置**：覆盖不同 Needle Depth，从较浅位置到接近上下文末端的深层位置。
- **压缩率**：
  - 主实验：0.75；
  - 附加实验：0.5。
- **比较方法**：
  - SnapKV；
  - KeyDiff；
  - KNorm；
  - CAPKV；
  - EA。
- **目的**：
  - 测试缓存淘汰后是否仍能找回稀疏、远距离、深层位置的信息；
  - 检验方法在极长上下文和动态淘汰下的鲁棒性。
- **主要观察**：
  - Jacap 在长上下文、深层 needle 场景中表现更稳定；
  - 纯结构方法 KeyDiff 和 KNorm 在极长上下文中退化明显；
  - 注意力类方法在超过约 100k tokens 或较深 needle 位置时也会出现性能下降；
  - Jacap 在不同上下文长度和 needle 深度范围内保持较强检索能力。

## 3.3 解码阶段淘汰与 AIME25

- **数据集**：AIME25。
- **模型**：Nemotron-7B。
- **场景**：自回归解码过程中动态进行 KV Cache 淘汰。
- **缓存预算**：保留 token 数量为：
  - 2048；
  - 4096；
  - 8192；
  - 16384。
- **对比方法**：
  - EA；
  - KeyDiff；
  - KNorm；
  - CAPKV；
  - Jacap。
- **结果概况**：
  - 2048 tokens 时，Jacap 得分最高，为 0.30；
  - 4096 tokens 时，Jacap 与 CAPKV 均为 0.50；
  - 8192 tokens 时，CAPKV 高于 Jacap；
  - 16384 tokens 时，Jacap 重新取得最高分，为 0.73。
- **意义**：说明 Jacap 不仅适用于离线或一次性缓存压缩，也可以用于在线解码过程中的动态淘汰，但其优势会随缓存预算变化而波动。

## 3.4 温度参数消融

- **模型与数据集**：Qwen3-8B、LongBench。
- **变量**：Softmax 温度参数 \(\tau\)。
- **压缩率**：0.25、0.5、0.75、0.9。
- **结论**：
  - 当 \(\tau\) 约为 10 时，整体性能最好；
  - 温度过小会使注意力先验过于尖锐，过度偏向少数高匹配 token；
  - 温度过大会削弱查询相关性，使方法更偏向纯多样性选择。

  - 注意力启发式方法；
  - Key/Value 结构方法；
  - 未来查询估计方法；
  - 线性信息容量方法。
- 在多个模型架构上验证了方法，降低了只针对单一模型结构有效的风险。
- 同时报告低、中、高压缩率，特别关注极端压缩场景，符合 KV Cache 淘汰的实际应用需求。
- 包含温度参数消融和运行时间实验，说明作者不仅关注精度，也考虑超参数和部署成本。

### 仍然存在的不足

- 实验中的模型数量仍然有限，主要集中于 Qwen、Llama 和 Nemotron 系列，尚未覆盖更多架构，例如不同注意力机制、MoE 模型、采用特殊 KV 共享策略的模型等。
- AIME25 只使用一个模型和一个数据集，且样本规模相对有限，不足以完全代表复杂推理任务。
- 温度参数 \(\tau\) 的最佳值约为 10，但论文没有充分说明该超参数是否基于验证集调优，以及是否在所有模型和任务上保持一致，存在一定调参偏差风险。
- 缺少更加系统的组件级消融，例如分别去除：
  - Softmax 敏感度；
  - 查询协方差；
  - 输出空间杠杆分数；
  - Value 投影；
  - 历史查询统计。  
  因此难以精确判断每个设计组件的独立贡献。
- 没有报告不同随机种子下的均值、标准差或显著性检验，部分性能提升是否稳定仍需进一步验证。
- 论文主要展示平均分和热力图，但对于不同任务类别、不同层、不同注意力头的具体收益分析还不够充分。
- 运行时间实验规模较小，仅测试生成 100 个 token 和有限的上下文长度，尚不足以全面反映长期在线服务中的吞吐、显存峰值和频繁淘汰成本。

# 6. 主要结论与发现

- **理论层面**  
  KV Cache 淘汰可以被视为在有限缓存预算下保持未来查询信息容量的问题。将注意力视为非线性通道，比简单的线性通道假设更能表达 Softmax 的归一化和 token 竞争效应。

- **方法层面**  
  Jacap 的重要性不仅由注意力权重决定，还取决于：
  - token 对未来查询的响应；
  - Softmax 的局部敏感度；
  - token 在输出空间中的独特性；
  - 候选集合中已有的信息覆盖情况。

- **经验层面**  
  Jacap 在多数实验中优于或匹配现有方法，尤其是在高压缩率场景下表现更好。其优势主要体现在：
  - 远距离信息检索；
  - 深层 needle 保留；
  - 严格缓存预算下的长上下文理解；
  - 部分动态解码任务。

- **效率层面**  
  尽管 Jacap 的理论复杂度高于简单启发式方法，但由于注意力头维度通常较小，且矩阵计算可以由 GPU 并行处理，其端到端推理时间在实验中与基线相近。

# 7. 方法与实验的优点

## 7.1 方法设计亮点

- **具有较强的理论动机**  
  论文不是简单提出新的经验分数，而是从互信息和局部信息几何出发，建立了从非线性注意力到缓存淘汰策略的推导链条。

- **显式处理 Softmax 非线性**  
  通过 Softmax 雅可比矩阵 \(S_C\)，方法能够描述注意力饱和和 token 间竞争，这是纯注意力权重或线性模型难以反映的。

- **结合相关性与多样性**  
  Jacap 的杠杆分数可以避免选择大量输出方向相似的 token，在保留相关信息的同时降低缓存冗余。

- **能够解释“高注意力不一定高价值”**  
  当某个 token 的注意力权重接近 1 时，Softmax 可能已经饱和，其局部敏感度反而较低。这一解释为传统“重视高注意力 token”的策略提供了修正。

- **无需额外模型训练**  
  Jacap 使用历史查询统计和缓存中的 Key/Value 即可工作，具有较好的模型无关性和即插即用特征。

- **与其他缓存优化技术互补**  
  论文指出 Jacap 可以与量化、PagedAttention、系统级内存管理等技术结合，而不与这些方法冲突。

## 7.2 实验设计亮点

- 覆盖多种任务类型，而非只测试单一检索任务。
- 同时测试静态缓存选择和解码阶段动态淘汰。
- 特别关注高压缩率，这是实际部署中最有挑战、也最能区分方法能力的场景。
- 加入运行效率评估，避免只报告精度而忽视部署代价。
- 在不同模型规模和架构上验证，初步体现出方法的泛化性。

# 8. 不足与局限

## 8.1 理论与算法近似

- **局部一阶近似具有适用范围**  
  雅可比信息容量只描述 \(\mu_Q\) 附近的局部行为。当未来查询分布较宽、强烈偏离中心，或解码过程中的查询分布快速变化时，一阶泰勒展开可能无法准确刻画真实注意力映射。

- **忽略了完整的 Softmax 竞争项**  
  理论目标包含完整的竞争矩阵 \(S_C\)，但实际 Jacap 将其对角化，舍弃了 token 间的负相关和耦合关系。因此最终算法并没有完全优化论文提出的非线性容量目标。

- **忽略 Key 响应协方差的非对角项**  
  \(K_C\Lambda_QK_C^\top\) 被近似为对角矩阵，相当于假设不同 token 的查询响应相互独立。现实中不同 Key 的响应可能高度相关，这会影响容量估计和多样性选择。

- **候选池权重与最终子集权重不完全一致**  
  实际算法使用全候选池上的注意力分布 \(\bar{\alpha}_i\) 近似未知保留子集上的 \(\alpha_C^\star\)。当候选池很大或淘汰比例很高时，这种近似可能产生偏差。

- **依赖未来查询统计估计**  
  Jacap 需要估计 \(\mu_Q\) 和 \(\Lambda_Q\)。如果历史查询不能代表未来查询，或者任务发生分布漂移，缓存评分可能失真。

## 8.2 实验覆盖不足

- 只评估了有限模型系列，尚未证明对更广泛架构、不同层数、不同注意力头配置以及多查询注意力、分组查询注意力的普适性。
- 没有系统分析跨层缓存淘汰策略。论文当前主要以 token 级方法为主，而不同层、不同头的重要性可能差异很大。
- 没有充分考察不同解码阶段的行为，例如提示处理阶段、早期生成阶段和长时间生成阶段是否应采用不同策略。
- 缺少更多真实生产场景，例如多轮对话、工具调用、代码代理、长时间任务执行和批量服务。
- 对超长上下文的测试主要集中在 NIAH 等检索型任务，复杂的跨段推理、信息整合和多跳推理仍需更多验证。

## 8.3 公平性与偏差风险

- 论文强调 Jacap 在高压缩率下的优势，但不同方法的超参数、保留策略和实现细节是否完全采用相同调优预算，给定内容中没有充分展开。
- 温度参数的选择可能影响 Jacap 的结果，若该参数通过测试集或特定模型调优，可能造成性能估计偏乐观。
- 缺少多次运行的方差和显著性分析，部分方法之间的细小差异可能并不具有统计稳定性。
- 论文使用 \(u_i=v_i\) 作为输出投影近似时，实际效果是否与完整 \(W_Ov_i\) 一致，尚未进行充分对比。
- 复杂度虽然在 RTX Pro 6000 上表现可接受，但在边缘 GPU、CPU 推理、低延迟服务或超大候选池场景下，矩阵求逆和容量矩阵维护可能成为额外瓶颈。

## 8.4 应用限制

- Jacap 更适合需要较强长上下文能力、且可以接受一定淘汰计算开销的推理系统。
- 对实时性极端敏感、缓存频繁更新或查询分布变化快速的场景，历史统计和矩阵计算可能带来额外延迟。
- 当压缩率较低、缓存预算充足时，Jacap 相比 CAPKV 等容量方法的优势并不总是明显。
- AIME25 实验中不同预算下的排名并不完全一致，例如 8192 tokens 时 CAPKV 优于 Jacap，说明 Jacap 并非在所有缓存规模和任务条件下都占优。
- 论文提出的完整雅可比容量具有较强表达能力，但实际部署的近似算法与理论目标之间仍存在明显差距，未来还需要更严格的近似误差分析和自适应机制。
