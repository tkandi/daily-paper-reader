## 摘要
Kolmogorov-Arnold 网络（KAN）以网络边上的可学习一元函数替代多层感知机（MLP）中的固定激活函数和线性权重，从而提高了可解释性，并在某些情况下实现了具有竞争力的参数效率。尽管 KAN 的逼近性质已受到广泛关注，但其在分布式、多 GPU 训练环境下的表现尚未得到系统刻画。本文针对多节点、多 GPU 高性能计算（HPC）基础设施上的数据并行 KAN 训练开展实证可扩展性研究，从强扩展、弱扩展、通信开销和模型规模扩展四个维度进行评估。实验在 FinisTerrae III 超级计算机上进行，使用 PyTorch 分布式数据并行（DDP），最多跨越 4 个节点的 8 块 NVIDIA A100 GPU。KAN 训练在使用 8 块 GPU 时实现了 74.7% 的并行效率和 5.97 倍的加速比，与传统深度学习工作负载的表现一致。弱扩展实验显示，吞吐量在从单 GPU 扩展到多 GPU 时出现初始下降，随后保持较强的稳定性。通信开销呈现非单调变化模式（1.3%–6.1%），其主要受 All-Reduce 算法选择和节点间延迟驱动，而非 KAN 的边级梯度结构。尽管训练时间呈不利的扩展趋势，参数与内存的比率却随着模型规模增大而提高。这些结果表明，面向算子级别的优化与数据并行优化对于 KAN 具有互补性。本文给出了 GPU 拓扑结构和模型规模选择方面的部署指南，并讨论了采用合成回归任务进行评估的局限性。

## Abstract
Kolmogorov-Arnold Networks (KANs) replace the fixed activation functions and linear weights of Multi-Layer Perceptrons (MLPs) with learnable univariate functions on network edges, offering improved interpretability and, in some settings, competitive parameter efficiency. While the approximation properties of KANs have received considerable attention, their behavior under distributed, multi-GPU training has not been systematically characterized. This paper presents an empirical scalability study of data-parallel KAN training on multi-node, multi-GPU high-performance computing (HPC) infrastructure, evaluated along four dimensions: strong scaling, weak scaling, communication overhead, and model-size scaling.   Experiments were conducted on the FinisTerrae III supercomputer using up to 8 NVIDIA A100 GPUs across 4 nodes with PyTorch Distributed Data Parallel (DDP). KAN training reaches 74.7% parallel efficiency at 8 GPUs with a 5.97x speedup, consistent with conventional deep learning workloads. Weak scaling shows an initial single-to-multi-GPU throughput drop followed by strong stability. Communication overhead follows a non-monotonic pattern (1.3%-6.1%), driven primarily by All-Reduce algorithm selection and inter-node latency rather than KAN's edge-wise gradient structure. The parameter-to-memory ratio improves with model size even as training time scales unfavorably.   These results indicate that operator-level and data-parallel optimizations for KAN are complementary. We provide deployment guidelines for GPU topology and model-size selection, and discuss the limitations of a synthetic-regression evaluation.

## 1. 核心问题与整体含义

### 研究背景

- **Kolmogorov-Arnold Network（KAN）**以边上的可学习一元函数（通常由 B-spline 参数化）替代传统 MLP 中的线性权重与固定激活函数。其潜在优势是：
  - 更好的可解释性；
  - 在部分任务中具备较高参数效率；
  - 适合科学计算、函数逼近和 PDE 代理建模等场景。
- 但 KAN 的每条边都需要进行样条基函数的计算与梯度更新，单卡训练相较普通 MLP 可能具有更高算子开销。
- 现有 KAN 加速研究主要聚焦于**单设备/算子层**优化，例如将 B-spline 计算转成矩阵运算的 MatrixKAN；而 KAN 在多节点、多 GPU 的常规数据并行训练中，是否会表现出特殊的通信、内存或扩展性问题，缺乏系统性实测。

### 核心研究问题

本文聚焦于：

> 在 PyTorch Distributed Data Parallel（DDP）框架下，KAN 在多节点、多 GPU HPC 集群上的训练可扩展性如何？其通信开销、GPU 拓扑敏感性及模型规模增长规律，是否与普通深度学习模型有所不同？

### 整体含义

- 论文并未提出新的 KAN 结构或新的分布式训练算法，而是进行了一项**系统性能测量与分析研究**。
- 其核心结论是：在本文的实验规模和场景下，KAN 可以采用标准 DDP 进行有效的数据并行训练，且其扩展性总体上与常规 DDP 深度学习任务一致。
- KAN 的样条边函数没有显著引入额外同步点；性能瓶颈主要仍来自通用的分布式系统因素，如 NCCL All-Reduce、跨节点延迟及混合通信拓扑。
- 因此，KAN 的**算子级优化**与**系统级数据并行优化**不是替代关系，而是互补关系。

## 2. 方法论：核心思想、技术细节与度量方式

### 核心思想

论文通过控制变量实验，从四个维度评估 KAN 的 DDP 训练性能：

1. **强扩展（Strong Scaling）**
   - 固定总数据量；
   - 增加 GPU 数量；
   - 观察训练时间是否接近按 GPU 数量线性下降。

2. **弱扩展（Weak Scaling）**
   - 固定每张 GPU 的数据量；
   - 随 GPU 数量同比增加总数据量；
   - 观察每 GPU 的吞吐是否稳定。

3. **通信开销分析**
   - 对比单节点、跨节点以及混合节点拓扑；
   - 测量梯度同步占单步时间的比例；
   - 讨论 NCCL All-Reduce 算法和 PCIe / InfiniBand 拓扑的影响。

4. **模型规模扩展**
   - 改变 KAN 隐层宽度；
   - 分析参数量、吞吐、训练时间、显存峰值及“参数量/显存”比值的变化。

### KAN 模型与计算特点

- 模型为一个较简单的 KAN：
  - 输入维度：2；
  - 一个可变宽度的隐藏层；
  - 标量输出。
- 样条相关设置：
  - spline order：`k = 3`，即三次 B-spline；
  - grid size：10；
  - 使用 PyKAN 的参考实现；
  - 使用递归式 Cox-de Boor B-spline 求值路径，**未采用 MatrixKAN 等算子级加速**。
- KAN 的每个边函数包含可学习样条参数，因此每条边都涉及样条基函数前向计算和反向梯度计算。

### 分布式训练机制

- 使用 PyTorch DDP：
  - 每张 GPU 保留完整模型副本；
  - 各 GPU 处理不同数据分片；
  - 反向传播期间对梯度执行 All-Reduce 同步；
  - 使用 NCCL 作为集合通信后端。
- 论文认为，KAN 的边级可学习函数虽然增加了参数和计算量，但本质上仍可沿用标准 DDP 的梯度同步模式，并不会天然引入额外跨 GPU 同步阶段。

### 主要性能指标与公式

- **加速比**：

\[
S_p = \frac{T_1}{T_p}
\]

其中，\(T_1\) 为单 GPU 时间，\(T_p\) 为使用 \(p\) 张 GPU 的训练时间。

- **并行效率**：

\[
E_p = \frac{S_p}{p} \times 100\%
\]

- **吞吐量**：
  - 每秒处理的样本数（samples/s）；
  - 同时报告每 GPU 吞吐，用于识别每设备利用率下降。

- **通信开销**：
  - 梯度同步时间占总 step 时间的百分比。

- **参数-显存比**：

\[
\text{Parameter-to-Memory Ratio}
=
\frac{\text{模型参数量}}{\text{峰值 GPU 显存占用}}
\]

该指标衡量参数存储密度，不等价于通常意义上的显存利用率。

## 3. 实验设计：数据、场景、Benchmark 与对比对象

### 数据集与任务场景

- 使用人工构造的二维回归任务：

\[
f(x,y) = x^2 + y^2
\]

- 输入从均匀分布采样；
- 输出加入受控高斯噪声；
- 各 worker 的数据划分是确定性的，且每张 GPU 获得等量样本；
- 使用固定随机种子以保障可复现性。

### 采用合成任务的原因

作者选择合成回归任务，主要为了：

- 严格控制数据集规模；
- 固定每样本计算成本；
- 在不同 GPU 规模、模型规模和拓扑配置之间保持较高可比性；
- 避免真实数据加载、复杂预处理、数据分布变化等因素干扰系统性能测量。

### Benchmark 类型

论文没有采用 MLPerf、ImageNet 或标准科学计算数据集，而是构建了面向 KAN-DDP 的四类内部性能 benchmark：

| Benchmark 类别 | 控制变量 | 主要观察指标 |
|---|---|---|
| 强扩展 | 总样本数固定为 100,000 | 时间、吞吐、加速比、并行效率 |
| 弱扩展 | 每 GPU 固定 25,000 个样本 | 每 GPU 吞吐、总训练时间 |
| 通信分析 | GPU 总数和节点分布变化 | 通信开销比例、通信拓扑影响 |
| 模型扩展 | 隐层宽度从 32 至 256 | 参数量、吞吐、训练时间、显存 |

### 对比了哪些方法

严格来说，本文**没有进行模型算法层面的横向基线比较**，例如：

- 没有将 KAN 与参数量匹配的 MLP 直接比较；
- 没有对比 CNN、Transformer 或其他函数逼近网络；
- 没有实现并比较 MatrixKAN；
- 没有比较不同 DDP 优化技术，如梯度压缩、ZeRO、FSDP 或参数服务器。

本文的核心比较对象是不同的**资源配置与 GPU 拓扑**：

- `1G1N`：1 GPU、1 节点；
- `2G1N`：2 GPU、1 节点；
- `2G2N`：2 GPU、2 节点，每节点 1 GPU；
- `4G2N`：4 GPU、2 节点，每节点 2 GPU；
- `4G4N`：4 GPU、4 节点，每节点 1 GPU；
- `8G4N`：8 GPU、4 节点，每节点 2 GPU。

其中，`2G1N vs. 2G2N` 用来比较同节点和跨节点双卡通信；`4G2N vs. 4G4N` 用来分析混合拓扑与纯跨节点拓扑的差异。

- 同时覆盖强扩展、弱扩展、通信和模型规模四个关键维度；
- 有意识地区分了：
  - 节点内 PCIe；

- 固定多项变量，保证同一维度下的对比清晰；

### 公平性与客观性评价

- **内部公平性较好**：
  - 使用相同 KAN 结构基础、同一 PyKAN 实现、相同样条阶数和网格大小；
  - 合成任务和数据划分可控；
  - 资源独占以减少共置任务干扰；
  - 每次尽量只改变一个变量。

- **外部公平性不足**：
  - 缺少参数量、层数和训练设定匹配的 MLP 对照；
  - 因而无法实证地确认“通信模式主要是 DDP 通用现象而非 KAN 特性”；
  - 没有与 MatrixKAN 等 KAN 优化实现进行端到端对比；
  - 没有独立重复运行多次，不能评估 run-to-run 方差；
  - 没有将数据加载、优化器、前向计算、反向计算、All-Reduce 等时间进行细粒度剖析。

总体而言，这是一份**内部控制较严谨但外部验证不够充分**的系统性能研究。

## 6. 主要结论与发现

### 6.1 强扩展结果

固定总数据集为 100,000 样本时：

| 配置 | 时间 | 吞吐量 | 加速比 | 并行效率 |
|---|---:|---:|---:|---:|
| 1G1N | 900.59 s | 4,442 samples/s | 1.00× | 100.0% |
| 2G1N | 563.58 s | 7,099 samples/s | 1.60× | 79.9% |
| 2G2N | 571.73 s | 6,998 samples/s | 1.58× | 78.8% |
| 4G2N | 289.73 s | 13,819 samples/s | 3.11× | 77.7% |
| 4G4N | 291.50 s | 13,734 samples/s | 3.09× | 77.2% |
| 8G4N | 150.80 s | 26,618 samples/s | 5.97× | 74.7% |

主要发现：

- 8 张 A100 GPU 相比 1 张 GPU 获得 **5.97× 加速**；
- 8 GPU 并行效率为 **74.7%**；
- 总吞吐从 4,442 提升到 26,618 samples/s；
- 每 GPU 吞吐从 4,442 降至 3,327 samples/s/GPU，下降约 25.1%；
- 随 GPU 数增长，并行效率逐步下降，但没有出现异常恶化；
- 估算得到的 Amdahl 等效非并行部分约为 4.9%，代表通信、同步和潜在负载不均衡等综合开销，而非真正的串行代码比例。

### 6.2 弱扩展结果

固定每张 GPU 处理 25,000 样本时：

- 单 GPU 的每 GPU 吞吐约为 4,390 samples/s/GPU；
- 分布式配置下，每 GPU 吞吐稳定在约 3,440–3,463 samples/s/GPU；
- 所有 6 种配置的变异系数为 9.7%；
- 排除单 GPU 后，5 个分布式配置的变异系数低于 **0.3%**；
- 从 2 GPU 扩展到 8 GPU 时，训练总时间基本维持在约 **290 秒**。

结论：

- 单 GPU 到多 GPU 存在约 21% 的初始吞吐下降；
- 这是进入 DDP 后产生的相对固定的同步、初始化及通信开销；
- 但在 2 至 8 GPU 之间，该额外开销没有继续显著放大；
- 因此，KAN 在该场景下展现出良好的弱扩展稳定性。

### 6.3 通信开销与拓扑发现

| 配置 | 通信类型 | 通信开销 | 通信效率 |
|---|---|---:|---:|
| 2G1N | 节点内 | 1.3% | 98.7% |
| 2G2N | 跨节点 | 6.1% | 93.9% |
| 4G4N | 纯跨节点 | 1.4% | 98.6% |
| 4G2N | 混合拓扑 | 3.0% | 97.0% |
| 8G4N | 混合拓扑 | 4.6% | 95.4% |

关键结论：

- 通信开销并不随 GPU 数量单调增加，而是在 **1.3%–6.1%** 间非单调变化。
- 最差情况是 `2G2N`：
  - 两张 GPU 分别位于两个节点；
  - 通信开销达 6.1%；
  - 作者推测原因是两 rank 的跨节点 All-Reduce 可能类似成对交换，固定跨节点延迟难以被流水化隐藏。
- `4G4N` 的通信开销只有 1.4%：
  - 虽然完全跨节点，但可能可利用 ring 或 tree 型 All-Reduce；
  - 多段数据通信能够实现更好的流水化和链路利用。
- 混合拓扑 `4G2N` 和 `8G4N` 开销更高：
  - 可能需要处理节点内 PCIe 聚合与节点间 InfiniBand 聚合两个层级；
  - 两层通信的协调成本可能抵消了节点内高速链路的收益。

### 6.4 模型规模扩展结果

| 模型规模 | 隐层宽度 | 参数量 | 吞吐量 | 显存 |
|---|---:|---:|---:|---:|
| Small | 32 | 2,726 | 24,624 samples/s | 0.04 GB |
| Medium | 64 | 5,414 | 13,344 samples/s | 0.06 GB |
| Large | 128 | 10,790 | 6,867 samples/s | 0.10 GB |
| X-Large | 256 | 21,542 | 3,469 samples/s | 0.18 GB |

主要发现：

- 隐层宽度增长 8 倍时：
  - 训练时间由 81.5 秒增至 577.0 秒；
  - 增长约 **7.08 倍**；
  - 吞吐由 24,624 降至 3,469 samples/s，约下降 7.1 倍。
- 每参数吞吐降低约 **56 倍**：
  - 从 9.033 samples/s/parameter 降至 0.161。
- 训练损失从 0.100 降至 0.080：
  - 模型变大带来一定拟合改善；
  - 但精度提升相对于计算成本增长较小，呈现明显边际收益递减。
- 参数/显存比随模型增大而提高：
  - 从约 74,268 parameters/GB 增至 118,066 parameters/GB；
  - 作者推测固定 CUDA context、NCCL buffer、缓存分配器和 DDP 进程开销被较大模型摊薄。

## 7. 优点与亮点

### 7.1 明确区分系统级和算子级优化

- 论文清晰指出：
  - MatrixKAN 等工作优化的是单设备上的 B-spline 算子计算；
  - 本文研究的是模型复制到多 GPU 后的 DDP 扩展性和通信行为。
- 这种分层视角是合理的：
  - 算子优化降低 \(T_{\text{compute}}\)；
  - DDP 与通信优化影响 \(T_{\text{comm}}\)；
  - 二者联合使用才可能形成高效的大规模 KAN 训练系统。

### 7.2 拓扑感知的实验设计较有价值

- 不仅简单比较 1、2、4、8 GPU，还专门比较：
  - 2G1N 与 2G2N；
  - 4G2N 与 4G4N。
- 这种设计使论文能够讨论 GPU 是否共置于同一节点、是否存在混合 PCIe / InfiniBand 通信层次对性能的影响。
- 对实际 HPC 用户有直接参考价值。

### 7.3 多维度性能评估较完整

- 覆盖强扩展、弱扩展、通信开销、模型规模四个方面；
- 同时报告时间、吞吐、加速比、并行效率、通信占比、显存和参数密度；
- 比单独报告一个 speedup 更完整，也更符合 HPC benchmark 的常见范式。

### 7.4 对结论边界保持相对谨慎

- 作者多次强调：
  - All-Reduce 的具体算法选择没有通过 NCCL_DEBUG trace 直接验证；
  - 部分通信机理属于基于测量模式和系统原理的推断；
  - 参数/显存比的解释是合理假设，尚未被拆分实验严格证实；
  - 结果不能直接推广到大模型、真实数据集和其他集群。
- 这种主动限制结论范围的做法提升了论文的客观性。

### 7.5 代码和实验材料公开

- 作者提供了实验脚本、日志和分析代码仓库：
  - `https://github.com/anhushow/KAN_Scalability_DDP`
- 有助于复现、检验以及补充 MLP 对照实验。

## 8. 不足、局限与潜在偏差风险

### 8.1 缺少与 MLP 的匹配对照，是最关键不足

- 论文核心判断是：KAN 的通信行为主要反映一般 DDP/NCCL 机制，而非 KAN 特有问题。
- 但这一判断没有由直接实验支撑，因为没有构建：
  - 参数量匹配的 MLP；
  - 相同层数、输入输出维度、训练任务和 DDP 配置下的 MLP；
  - 与 KAN 的通信开销、强扩展与弱扩展曲线对照。
- 因此，当前结论更准确的表述应为：
  - “观察到的模式与一般 DDP 机制相一致”，
  - 而不能严格证明“这些模式与 KAN 无关”。

### 8.2 任务过于简单，现实代表性有限

- 仅使用二维函数 \(x^2+y^2\) 的合成回归任务；
- 输入维度极低，模型仅有一个隐藏层；
- 真实 KAN 应用中的复杂情况未被覆盖，例如：
  - 高维科学数据；
  - PDE 解算器代理；
  - 多变量非线性建模；
  - 图像、时序或工程传感数据；
  - 稀疏输入、复杂边界条件和不均衡数据分布。
- 在真实任务中，数据加载、输入维度、网格大小、batch size、网络深度和模型精度要求都可能改变计算通信比。

### 8.3 模型规模非常小，难以外推至大规模训练

- 最大模型仅有 21,542 个参数；
- 相比现代深度学习模型，甚至相比许多科学计算中的 KAN，规模都非常小；
- 小模型下：
  - 固定进程开销、CUDA context、NCCL buffer 和 allocator 开销的比例更高；
  - All-Reduce 的延迟主导效应可能更明显；
  - 大模型下的带宽瓶颈、显存压力、通信重叠和 bucket 行为可能完全不同。
- 因而参数/显存比随模型增长的趋势是否会持续、饱和或反转，尚不明确。

### 8.4 最大仅测试到 8 GPU / 4 节点

- 实验最多使用 8 张 A100 和 4 个节点；
- 未覆盖几十到数百 GPU 的扩展区间；
- 在更大集群中可能出现：
  - 更复杂的 NCCL ring/tree 构造；
  - fat-tree 网络拥塞；
  - 跨交换机层级通信；
  - straggler；
  - 节点性能波动；
  - 梯度 bucket 调优敏感性；
  - 更严重的同步和负载均衡问题。
- 因此，论文只能说明小规模至中低规模多节点训练的趋势。

### 8.5 每种配置仅执行一次完整训练

- 每个设置仅训练一次、40 个 epoch；
- 虽然有报告 epoch 内标准差，但它不能替代多次独立实验重复；
- 无法统计：
  - 节点分配随机性；
  - 网络短期波动；
  - 调度与系统状态变化；
  - 随机初始化或数据随机性；
  - 不同 run 的置信区间。
- 这可能导致报告的单点数值存在一定偶然性。

### 8.6 通信机制主要为推断，缺乏直接 profiling 证据

- 作者推测：
  - 2G2N 的高开销来自两 rank 跨节点的成对交换；
  - 4G4N 的低开销来自 ring/tree 流水化优势；
  - 混合拓扑开销来自分层协调成本。
- 但没有提供：
  - NCCL_DEBUG 日志；
  - NCCL 拓扑图；
  - Nsight Systems / PyTorch Profiler trace；
  - All-Reduce 算法与协议的实测记录；
  - 通信时间与前向、反向、优化器时间的详细分解。
- 所以这些解释具有合理性，但仍属于未完全验证的系统推断。

### 8.7 未评估重要的分布式优化策略

论文只评估标准同步、非量化 DDP，未测试：

- 梯度压缩或量化；
- 通信与反向传播重叠策略的调优；
- DDP bucket size；
- FSDP、ZeRO、tensor parallel、pipeline parallel；
- 不同 batch size、学习率缩放和 gradient accumulation；
- 不同 NCCL 参数、通信算法和网络配置；
- 不同 spline grid size、spline order、网络深度。

因此，其“部署建议”更适合作为当前硬件与当前工作负载下的初步经验，而非普适配置规则。

### 8.8 个别表述存在轻微不严谨之处

- 结论部分有一句称“训练时间随宽度增长快于固定成本模型预期”，但实验结果中宽度增加 8 倍、训练时间增加 7.08 倍，实际上略低于严格线性增长。
- 正文对此已较谨慎地解释为“近似线性”，但结论中的措辞可能引起歧义。
- 此外，强扩展和弱扩展的吞吐数值在排版提取中存在个别格式混乱，需要结合原始表格或代码日志确认精确数值。

## 总体评价

这是一篇定位清晰的 KAN 系统性能实证研究。其价值不在于提出新的神经网络算法，而在于首次较系统地展示了参考 PyKAN 实现经过 DDP 分布式训练时，在多节点 A100 集群上的扩展趋势、通信拓扑敏感性和小规模模型的资源规律。

其最有实践意义的发现是：**KAN 不会因为边级样条参数化而天然遭遇特殊的多 GPU 数据并行障碍；在当前实验范围内，其性能规律主要仍由通用 DDP 通信机制、NCCL All-Reduce 行为和 GPU/节点拓扑决定。** 不过，该结论尚需通过参数量匹配 MLP 对照、真实科学任务、更大模型和更大规模集群实验加以验证。

（完）
