## 摘要
在负载、模型驻留状态和资源可用性随时间变化的异构 GPU 资源池上运行时，并发多智能体工作流会暴露出未来依赖关系和服务状态需求。逻辑工作流定义了所需的计算，而其物理调度单元、模型生命周期操作、资源排序和部署位置则必须根据观测到的资源池状态进行选择。我们提出了一种预测引导的运行时系统，利用工作流预测结果构建并优化物理执行图。预测器估计面向特定设备的激活延迟、峰值内存和模型加载开销，并沿工作流依赖传播这些预测结果，以预测激活就绪时间和未来模型需求。构造器生成保持语义的融合方案和模型生命周期方案；调度器则基于资源池的实时状态，联合优化方案选择、部署位置和执行顺序。在涵盖三种工作流场景的异构 GPU 资源池工作负载上，与当前最先进的工作流调度器相比，在突发到达情况下，我们的系统可将端到端完成时间和整体 p95 完成延迟分别降低最高 36.8% 和 25.9%，并且每个完成会话最多节省 24.63 个 GPU·秒。

## Abstract
Concurrent multi-agent workflows expose future dependencies and serving-state requirements while running on heterogeneous GPU pools with time-varying load, model residency, and resource availability. The logical workflow defines the required computation, whereas its physical scheduling units, model-lifecycle actions, resource ordering, and placement must be selected according to the observed pool state. We present a prediction-guided runtime that uses workflow forecasts to construct and optimize a physical execution graph. Predictor estimates device-specific activation latency, peak memory, and model-loading cost, then propagates these predictions through workflow dependencies to forecast activation readiness and future model demand. Constructor builds semantics-preserving fusion and model-lifecycle alternatives, while Scheduler jointly optimizes their selection, placement, and execution order based on the live pool state. Across a workload spanning three workflow scenarios on a heterogeneous GPU pool, our system reduces end-to-end makespan and overall p95 completion latency under burst arrivals by up to 36.8% and 25.9%, respectively, over state-of-the-art workflow schedulers. It also saves up to 24.63 GPU-s per completed session.

## 2. 论文提出的方法论

## 2.1 方法核心思想

论文采用“**预测—构造—联合调度**”的总体框架：

```text
逻辑工作流
    ↓
预测设备和模型相关执行代价
    ↓
沿依赖传播，预测未来任务就绪时间和模型需求
    ↓
生成多种语义保持的物理执行方案
    ↓
结合实时 GPU 状态进行方案选择、设备放置和执行排序
    ↓
执行物理工作流并持续根据运行状态调整
```

其关键在于将工作流调度从“仅基于已就绪任务的局部调度”，扩展为“考虑未来依赖、模型状态和资源变化的预测性调度”。

## 2.2 预测器：估计设备相关执行代价

预测器针对具体 GPU 和模型，估计至少三类成本：

### （1）激活延迟

激活延迟可以理解为模型或任务从非活跃状态转为可执行状态所需的时间。它可能受到以下因素影响：

- 模型是否已经驻留在 GPU 上；
- GPU 当前是否被其他任务占用；
- 模型加载或恢复过程；
- 设备间资源竞争。

### （2）峰值显存

系统需要预测任务或模型运行期间的峰值显存需求，以判断：

- 某个模型能否放置到指定 GPU；
- 多个模型能否同时驻留；
- 是否需要提前卸载其他模型；
- 模型切换是否会引起额外开销。

### （3）模型加载成本

模型加载成本反映模型从存储或其他层级进入目标 GPU 的时间和资源消耗。该成本对于多模型、多智能体工作流尤其重要，因为频繁加载和卸载可能成为主要瓶颈。

## 2.3 沿工作流依赖传播预测结果

论文不仅估计单个任务的局部执行代价，还将预测结果沿工作流依赖关系传播，从而预测：

- 某个激活何时可以就绪；
- 后续任务大致何时能够启动；
- 未来将需要哪些模型；
- 某些模型是否值得提前加载或保持驻留；
- 不同分支的潜在关键路径。

从文字上看，该过程相当于在逻辑工作流图上进行带有设备和模型状态信息的时间推演。

若将工作流表示为有向无环图 \(G=(V,E)\)，每个节点表示一个任务或智能体操作，边表示数据依赖，那么某节点的预计就绪时间可以概念性地表示为：

\[
T_{\text{ready}}(v)
=
\max_{u\in pred(v)}
\left(
T_{\text{ready}}(u)

T_{\text{exec}}(u)

其中：

- \(T_{\text{ready}}(v)\)：任务 \(v\) 的预计就绪时间；
- \(T_{\text{exec}}(u)\)：前驱任务 \(u\) 的执行时间；
- \(T_{\text{transfer}}(u,v)\)：中间结果传输或状态准备成本；
- 实际计算中还需要加入模型激活和加载等额外成本。

## 2.4 构造器：生成物理执行方案

构造器根据逻辑工作流生成多种保持语义一致的物理执行图。其主要操作包括：

### （1）任务融合

将多个相关操作合并为更大的执行单元，可能带来以下收益：

- 减少任务调度开销；
- 减少中间结果传递；
- 减少模型重复激活；
- 降低 GPU 上下文切换次数；
- 提高单次执行的连续性。

但融合也可能降低并行度，或增加单个执行单元的显存需求。因此，论文不是固定采用融合，而是生成多个候选方案后交由调度器选择。

### （2）模型生命周期优化

系统显式考虑模型的生命周期操作，包括：

- 模型加载；
- 模型激活；
- 模型驻留；
- 模型卸载；
- 模型切换。

其核心目标是在显存有限的情况下，平衡两类成本：

- 保持模型驻留带来的显存占用；
- 反复加载和激活模型带来的时间开销。

### （3）语义保持

候选物理执行方案必须保持原始工作流的计算语义和依赖约束。也就是说，任务融合、模型生命周期调整和执行顺序变化不能改变最终结果所依赖的逻辑关系。

## 2.5 调度器：联合优化物理执行决策

调度器根据 GPU 资源池的实时状态，联合做出三类决策：

1. **方案选择**：选择哪一种任务融合和模型生命周期方案；
2. **设备放置**：将任务部署到哪一块 GPU；
3. **执行排序**：在多个可执行任务之间确定优先级和顺序。

调度器需要同时考虑：

- 当前 GPU 负载；
- GPU 是否具备足够显存；
- 模型是否已经驻留；
- 模型加载和激活开销；
- 工作流依赖；
- 未来任务需求；
- 并发会话之间的资源竞争；
- 对关键路径和尾延迟的影响。

其优化目标并非单纯降低单个任务的执行时间，而是尽量降低：

- 工作流端到端完成时间；
- 整体 p95 完成延迟；
- GPU 资源消耗；
- 模型加载和切换带来的额外开销。

## 2.6 方法的主要创新点

从现有摘要来看，论文的方法创新主要体现在以下几个方面：

- 将逻辑工作流与物理执行图分离；
- 将模型驻留和生命周期作为一等调度对象；
- 使用未来工作流依赖预测模型需求；
- 联合考虑任务融合、模型生命周期、设备放置和执行顺序；
- 面向异构 GPU 和动态负载，而不是静态同构集群；
- 同时关注平均完成时间、p95 尾延迟和 GPU 资源效率。

## 6. 主要结论与发现

论文的主要结论可以概括为以下几点：

### 6.1 逻辑工作流调度不足以解决物理执行问题

仅根据工作流逻辑依赖进行调度，无法充分处理：

- 模型加载和卸载；
- 模型驻留；
- GPU 显存约束；
- GPU 异构性；
- 动态资源变化；
- 并发会话之间的竞争。

### 6.2 预测未来需求有助于降低关键路径延迟

通过沿依赖关系传播预测结果，系统能够提前估计：

- 任务何时就绪；
- 模型何时被需要；
- 哪些模型应该提前准备；
- 哪些资源安排可能影响未来关键路径。

这使调度从被动响应转向一定程度的主动准备。

### 6.3 联合优化比单点优化更有效

任务融合、模型生命周期管理、设备放置和执行顺序之间存在相互影响。例如：

- 融合任务可能减少切换，但降低并行性；
- 模型驻留可能减少加载延迟，但占用显存；
- 选择空闲 GPU 可能避免排队，但需要重新加载模型；
- 提前加载模型可能改善未来延迟，但也会增加当前资源压力。

因此，论文认为需要对这些因素进行联合决策，而不是分别独立优化。

### 6.4 方法能够同时改善时延和资源效率

论文报告的结果表明，该系统不仅降低端到端完成时间和 p95 延迟，也减少了每个会话的 GPU 时间消耗。这说明其收益不完全来自“使用更多 GPU”或“牺牲资源换取时延”，而可能来自：

- 减少不必要的模型切换；
- 减少等待和排队；
- 改善任务放置；
- 提高模型驻留利用率；
- 减少物理执行图中的冗余开销。

不过，具体收益来源仍需要完整的消融实验加以验证。

## 7. 优点

## 7.1 方法设计上的优点

- **问题定义贴近实际部署**：同时考虑异构 GPU、动态负载、模型状态和并发工作流。
- **从逻辑层扩展到物理层**：不仅决定任务是否可执行，还决定实际如何执行。
- **显式建模模型生命周期**：把加载、激活、驻留和卸载纳入调度，而不是将其视为系统黑盒开销。
- **考虑未来依赖关系**：能够根据后续任务需求提前准备资源和模型。
- **联合优化多个决策变量**：避免任务融合、设备放置和模型驻留之间的局部最优冲突。
- **具有语义保持约束**：在优化物理执行方式的同时，保持原始工作流的计算语义。
- **面向尾延迟优化**：报告 p95 完成延迟，对在线服务具有较高实用价值。

## 7.2 实验设计上的优点

- 覆盖三类工作流场景；
- 使用异构 GPU 资源池，而非理想化的同构环境；
- 考察突发到达，能够反映高并发服务中的资源压力；
- 同时使用端到端时延、p95 延迟和 GPU·秒三个指标；
- 与当前先进工作流调度器进行比较；
- 报告了相对明确的性能收益，便于理解系统价值。

- 激活延迟；

- 预测收益下降。

因此，论文还应充分报告预测准确率及其对最终系统收益的敏感性。

## 8.4 调度开销可能成为新的瓶颈

该系统需要持续生成候选物理执行方案，并联合优化：

- 融合方式；

- 设备选择；

## 8.8 应用限制

该方法更适用于：

- 工作流结构相对明确；

对于高度动态、依赖不可预测、模型调用路径完全由运行时生成的智能体系统，其预测和构造效果可能下降。
