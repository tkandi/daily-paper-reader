## 摘要
对于大语言模型（LLM）而言，长上下文推理正变得日益重要，但由于巨大的内存和通信需求，长序列训练仍然面临挑战。序列并行已成为解决长序列大语言模型训练瓶颈的一项关键技术。然而，我们观察到，现有的序列并行方法与批次大小无关，会对所有批次大小采用统一的序列划分方式，从而导致通信效率低下。本文提出批次感知序列并行（Batch-Aware Sequence Parallelism，BASP），一种利用批次结构降低通信开销的序列并行方法。BASP 根据微批次大小将 GPU 划分为相互不重叠的序列并行组，从而利用批次结构。该设计减小了全对全通信组的规模，进而实现通信局部化并提升训练效率。在 NVIDIA A100 集群上的实验结果表明，与标准序列并行基线相比，BASP 在 Llama 和 Qwen 模型上的端到端训练时间最多可提升至原来的 1.17–1.31 倍，同时保持相同的模型精度和内存使用量。

## Abstract
Long-context reasoning for large language models (LLMs) is becoming increasingly important, but training over long sequences remains challenging due to massive memory and communication requirements. Sequence parallelism has emerged as an essential technique for addressing bottlenecks in long sequence LLM training. However, we observe that existing sequence parallelism methods are batch-agnostic and apply uniform sequence partitioning across all batch sizes, resulting in inefficient communication. In this paper, we introduce Batch- Aware Sequence Parallelism (BASP), a sequence parallelism approach that leverages batch structure to reduce communication overhead. BASP exploits batch structure by partitioning GPUs into disjoint sequence-parallel groups according to the micro- batch size. This design reduces the all-to-all communication group size, thereby localizing communication and improving training efficiency. Experimental results on an NVIDIA A100 cluster show that BASP improves end-to-end training time by up to 1.17 - 1.31x in Llama and Qwen models compared to standard sequence parallel baselines, while preserving identical model accuracy and memory usage.

## 2. 论文提出的方法论

## 2.1 核心思想

BASP，即 **Batch-Aware Sequence Parallelism（批次感知序列并行）**，主要包含两个步骤：

1. 根据微批次大小分析当前训练任务中的批次结构；
2. 将全部 GPU 划分为多个**相互不重叠的序列并行组**，每个组只负责对应的一部分微批次或批次数据。

与标准序列并行相比，BASP 的关键变化不是“是否进行序列切分”，而是：

- 标准方法往往在较大的 GPU 集合上执行统一通信；
- BASP 将 GPU 划分为多个更小的通信组；
- 每个通信组内部独立完成序列并行所需的 all-to-all 通信。

因此，BASP 试图将全局通信转化为多个局部通信。

## 2.2 关键技术细节

根据已提供内容，BASP 的技术机制可以概括为：

- 设系统中有若干 GPU；
- 根据微批次大小，将这些 GPU 划分为若干个不重叠的序列并行组；
- 每个组内部包含固定数量的 GPU；
- 一个微批次被分配到某个序列并行组后，其序列切分、数据交换和同步主要在该组内完成；
- 不同组之间尽量避免不必要的 all-to-all 通信；
- 通过缩小通信组规模，降低通信参与者数量和通信距离。

其直接目标是减少以下开销：

- all-to-all 通信的参与 GPU 数量；
- 跨节点通信；
- 通信竞争和网络拥塞；
- 因全局同步导致的等待时间。

| 通信范围 | 较大的全互连通信域 | 较小的局部通信域 |

所提供材料中没有给出正式数学公式或伪代码，但其算法流程可以用文字表示如下：

1. **输入训练配置**  
   获取 GPU 总数、微批次大小、序列长度以及序列并行配置。

2. **确定并行组结构**  
   根据微批次大小和 GPU 资源，将 GPU 划分为若干互不重叠的序列并行组。

3. **批次分配**  
   将不同微批次分配给对应的序列并行组，每个微批次在所属组内进行序列切分。

4. **局部序列并行计算**  
   组内 GPU 分别处理序列的不同分片，并在需要时进行组内 all-to-all 通信。

5. **组间结果衔接**  
   不同序列并行组之间尽量不进行与序列切分相关的全局通信，从而减少通信范围。

6. **继续训练流程**  
   完成前向传播、反向传播和参数更新，保持原有训练语义。

从方法设计上看，BASP 的正确性依赖于以下条件：

- GPU 分组不能造成数据遗漏或重复计算；
- 分组后的计算结果必须与标准序列并行等价或数值上可接受；
- 微批次与序列并行组之间的映射需要保持稳定；
- 通信局部化不能破坏梯度同步和整体训练流程。

  - H100、H200 等新一代 GPU；
  - 不同显存规格的 GPU；
  - GPU 间互联较弱的环境；
  - 云端异构集群。

## 8.2 基线可能不够全面

- 目前明确的基线只有标准序列并行。
- 如果没有与其他序列并行、混合并行或通信优化方法进行比较，则无法充分证明 BASP 在更广泛技术谱系中的优势。
- 还需要与以下方案进行对比：
  - 不同序列并行实现；
  - 张量并行与序列并行组合；
  - 流水线并行与序列并行组合；
  - 其他通信分组或拓扑感知方法。

## 8.3 对微批次配置的依赖

BASP 的核心依据是微批次大小，因此其效果可能依赖于：

- 微批次数量；
- GPU 数量；
- 序列并行组大小；
- 全局 batch size 与微批次大小之间的比例；
- 训练任务是否能够形成足够均衡的批次分组。

当微批次较少、GPU 数量较多，或者批次结构无法均匀映射到 GPU 组时，BASP 的收益可能下降，甚至可能带来负载不均衡。

## 8.4 负载均衡风险

将 GPU 划分为多个不重叠组可能引发：

- 不同组之间的计算量不均衡；
- 某些组提前完成计算而等待其他组；
- 微批次分配不均导致 GPU 利用率下降；
- 通信减少收益被额外调度开销抵消。

因此，需要进一步报告：

- 各组 GPU 利用率；
- 组间负载方差；
- 调度开销；
- 通信与计算重叠效果。

## 8.5 对整体训练通信的影响尚不清楚

BASP 主要优化的是序列并行相关通信，但完整的大模型训练还可能包含：

- 梯度 all-reduce；
- 参数同步；
- 张量并行通信；
- 流水线并行通信；
- 优化器状态同步。

如果其他通信占据主要时间，序列并行通信优化对整体训练的加速上限可能受到限制。论文需要进一步给出通信时间分解，以说明端到端加速主要来自哪些环节。

## 8.6 缺少详细可复现信息

当前提供内容未说明：

- GPU 数量；
- 具体模型配置；
- 数据集；
- 序列长度；
- batch size；
- 微批次大小；
- 软件版本；
- 网络配置；
- 训练步数；
- 重复实验次数；
- 统计误差。

这些信息不足会影响：

- 实验复现；
- 对结果稳定性的判断；
- 对不同场景下适用性的评估；
- 对加速比是否具有统计显著性的判断。

## 8.7 精度保持结论仍需更细化

摘要称模型精度保持一致，但还需要明确：

- 使用何种精度指标；
- 是训练损失一致，还是下游任务指标一致；
- 是否进行了足够多的训练步；
- 是否比较了最终 checkpoint；
- 是否存在数值误差累积；
- 是否在不同随机种子下重复验证。

对于通信重排类方法，通常还应报告数值一致性和收敛曲线，而不仅是最终精度结论。

## 8.8 应用范围可能有限

BASP 更适合以下场景：

- 长序列训练；
- 存在多个微批次；
- 序列并行通信占比较高；
- GPU 间存在明显通信层次差异；
- 能够将微批次较均匀地映射到多个并行组。

对于以下场景，其收益可能有限：

- 短序列训练；
- 微批次数量很少；
- 单 GPU 或小规模多 GPU 训练；
- 通信不是主要瓶颈；
- batch 结构动态变化频繁；
- 需要高度动态负载调度的训练任务。

总体而言，BASP 的主要贡献在于提出了一个清晰的系统优化方向：**根据微批次结构缩小序列并行通信域**。现有结果说明该方法在 Llama 和 Qwen 的 A100 长序列训练环境中具有实际加速效果，但要充分证明其普适性，还需要更全面的硬件、模型、数据规模、并行配置、基线和消融实验。
