## 摘要
基于 GPU 的具身智能（Embodied AI）仿真环境在单个设备上交替进行物理仿真（CUDA）和照片级渲染（Vulkan）。我们观察到，仿真数据生成和强化学习（RL）训练这两个基础场景可以自然地调整为并发执行仿真和渲染阶段，这为通过空间复用提高 GPU 利用率提供了重要机会。然而，一个被称为“执行隔离”的根本障碍阻碍了这一点：CUDA 和 Vulkan 创建了独立的 GPU 上下文，其通道绑定到不同的调度组，从而将计算和图形限制在互斥的时间片中。现有的空间共享技术仅限于 CUDA 生态系统，而时间共享方法则导致可用资源利用不足。本文提出了 VUDA，一个打破执行隔离以实现 CUDA 计算和 Vulkan 图形负载之间空间并行性的系统。VUDA 基于两个关键观察：尽管 CUDA 和 Vulkan 提供了不同的编程抽象，但它们的执行路径在驱动程序和硬件层面汇聚到共同的通道原语；同时，它们的虚拟地址空间本质上是不相交的，这使得在无需重映射的情况下进行安全的页表合并成为可能。VUDA 为开发人员提供了一个轻量级 API 来标注可协同调度的 CUDA 流，并通过将通道重定向到 Vulkan 的调度域以及通过页表嫁接统一地址空间来实现空间共享，从而消除了关键路径上的所有数据复制。在代表性具身智能工作负载上的实验表明，VUDA 的吞吐量比时间共享基准高出多达 85%，同时提高了 GPU 利用率并降低了端到端延迟。

## Abstract
GPU-based simulation environments for embodied AI interleave physics simulation (CUDA) and photorealistic rendering (Vulkan) on a single device. We observe that two foundational scenarios -- simulation data generation and RL training -- can be naturally adapted to execute their simulation and rendering phases concurrently, presenting a significant opportunity to improve GPU utilization through spatial multiplexing. However, a fundamental obstacle we term execution isolation prevents this: CUDA and Vulkan create separate GPU contexts whose channels are bound to different scheduling groups, confining compute and graphics to mutually exclusive time slices. Existing spatial-sharing techniques are limited to the CUDA ecosystem, while temporal-sharing approaches underutilize available resources.   This paper presents VUDA, a system that breaks execution isolation to enable spatial parallelism between CUDA compute and Vulkan graphics workloads. VUDA is built on two key observations: although CUDA and Vulkan expose different programming abstractions, their execution paths converge to a common channel primitive at the driver and hardware level; meanwhile, their virtual-address spaces are inherently disjoint, making safe page-table merging feasible without remapping. VUDA exposes a thin API for developers to annotate co-schedulable CUDA streams, and realizes spatial sharing through channel redirection into Vulkan's scheduling domain and page-table grafting to unify address spaces, eliminating all data copying on the critical path. Experiments on representative embodied-AI workloads show that VUDA delivers up to 85% higher throughput than temporal-sharing baselines, while improving GPU utilization and reducing end-to-end latency.

### 1. 核心问题与整体含义（研究动机和背景）
*   **背景**：具身智能（Embodied AI）的训练高度依赖 GPU 加速的仿真环境。这类环境通常交替执行两个阶段：基于 **CUDA** 的物理仿真（计算密集型）和基于 **Vulkan** 的照片级渲染（图形密集型）。
*   **核心问题**：现有的 GPU 软件栈存在“执行隔离”障碍。CUDA 和 Vulkan 拥有独立的 GPU 上下文和调度组（TSG），导致两者只能在时间片上轮转（时间共享），而不能同时占据 GPU 资源。
*   **后果**：在物理仿真阶段，图形硬件闲置；在渲染阶段，计算单元（SM）利用率不足。这种阶段性的资源浪费限制了仿真数据生成和强化学习（RL）训练的整体吞吐量。

### 2. 方法论
VUDA 的核心思想是打破 CUDA 和 Vulkan 的上下文壁垒，使计算和图形任务在同一个硬件调度域内并行执行。
*   **通道重定向 (Channel Redirection)**：
    *   **原理**：尽管 API 不同，CUDA 和 Vulkan 在底层都通过“通道（Channel）”提交任务。
    *   **实现**：VUDA 通过逆向工程获取 CUDA 驱动内部的函数指针，将 CUDA 流（Stream）底层的硬件通道重定向到 Vulkan 上下文预留的“转发通道”中。这样，CUDA 的任务会被直接推送到 Vulkan 的调度组（TSG）内，实现空间并行。
*   **页表嫁接 (Page-Table Grafting)**：
    *   **原理**：CUDA 和 Vulkan 拥有独立的虚拟地址空间。VUDA 观察到两者的地址布局天然不重叠（CUDA 在高位，Vulkan 在低位）。
    *   **实现**：在 GPU 内核驱动层，VUDA 将 CUDA 的页目录条目（PDE）递归地合并到 Vulkan 的页表中。这种“嫁接”方式使得 Vulkan 上下文能直接识别 CUDA 的虚拟地址，从而消除了跨库通信时昂贵的数据拷贝。
*   **轻量级 API**：
    *   VUDA 提供了简单的接口（如 `CUstream_bind`），开发者只需标注哪些 CUDA 流需要与 Vulkan 协同调度，并使用异步包装函数（`step_async`, `render_async`）即可实现流水线并行。

### 6. 主要结论与发现
*   **吞吐量大幅提升**：在数据生成场景下，吞吐量提升高达 **1.80x**；在 RL 训练场景下，提升高达 **1.85x**。

*   **高性能**：通过底层通道重定向和页表嫁接，实现了极低的运行时开销和零拷贝数据访问。
*   **易用性**：对现有仿真引擎的改动极小（仅需几行代码），且支持闭源的 CUDA 库（如 cuBLAS, cuDNN）。

### 8. 不足与局限
*   **平台依赖性**：该方案深度依赖 NVIDIA GPU 的底层硬件特性和驱动实现，需要修改内核模块（UVM 和 RM），难以直接移植到其他厂商的 GPU。
*   **维护成本**：由于涉及对驱动内部偏移量的逆向工程，当 NVIDIA 发布重大驱动更新时，可能需要重新适配偏移量表。
*   **边际效应**：当 Batch Size 极大导致 GPU 已经完全满载时，空间共享带来的额外收益会因资源竞争而减小。
*   **应用限制**：目前主要针对具身智能仿真场景，对于其他不涉及频繁计算/图形切换的任务，其收益可能不明显。
