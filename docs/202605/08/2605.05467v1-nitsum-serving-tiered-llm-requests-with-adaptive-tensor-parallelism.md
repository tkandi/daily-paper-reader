## 摘要
LLM 推理服务日益趋向多租户化：在固定的 GPU 预算下，同一部署必须同时处理对延迟敏感的交互式请求和要求较低的后台工作负载。这产生了一种分层服务水平目标（SLO）场景，由于工作负载组合、请求长度和负载强度随时间变化，最大化整体有效吞吐量（goodput，即同时满足 TTFT 和 TPOT 目标的请求数）具有挑战性。现有系统主要优化请求级控制（如排队和批处理），而执行配置在很大程度上保持静态，这限制了在多层竞争下的自适应能力。我们提出了 Nitsum，这是一个分布式 LLM 推理系统，它将张量并行（TP）视为一等公民的运行时控制面，而非静态的部署选择。Nitsum 联合优化了 TP 等级、预填充/解码（prefill/decode）GPU 划分以及请求调度。为了使频繁的 TP 自适应变得可行，Nitsum 引入了 TP 感知的权重重用和快速 KV 迁移。在真实轨迹和针对性微基准测试上的实验表明，Nitsum 相比现有最先进技术（SoTA），将符合 SLO 的有效吞吐量提升了高达 5.3 倍。

## Abstract
LLM serving is increasingly multi-tenant: the same deployment must handle latency-critical interactive requests and more relaxed background workloads under a fixed GPU budget. This creates a tiered-SLO setting where maximizing overall goodput (requests that satisfy both TTFT and TPOT targets) is challenging because workload mix, request lengths, and load intensity vary over time. Existing systems mainly optimize request-level controls (e.g., queuing and batching) while keeping execution configuration largely static, which limits adaptation under multi-tier contention.   We present Nitsum, a distributed LLM serving system that treats tensor parallelism (TP) as a first-class runtime control surface rather than a static deployment choice. Nitsum jointly optimizes TP level, prefill/decode GPU split, and request scheduling. To make frequent TP adaptation practical, Nitsum introduces TP-aware weight reuse and fast KV migration. Experiments on real traces and targeted microbenchmarks show that Nitsum improves SLO-compliant goodput over SoTA by up to 5.3 times.

#### 1. 核心问题与整体含义（研究动机和背景）
随着 LLM 应用的普及，推理服务呈现出**多租户（Multi-tenant）**和**分层服务水平目标（Tiered SLO）**的特征。同一套 GPU 资源需要同时处理延迟敏感的交互式请求（如聊天、编程助手）和高吞吐导向的后台任务（如数据分析、批处理）。
*   **研究动机**：现有的 SLO 感知系统（如 Llumnix, Chiron）主要在请求层面进行调度（如排队、迁移、批处理控制），但其**执行配置（尤其是张量并行 TP 级别）通常是静态的**。
*   **核心发现**：作者观察到 TP 级别不仅影响模型是否能装入显存，还直接影响 TTFT（首字延迟）和 TPOT（每字延迟）。高 TP 级别能显著降低长 Prompt 的 TTFT，并在小 Batch 场景下通过提高 L2 缓存命中率来提升解码吞吐。因此，将 TP 视为动态可调的“运行时控制变量”是提升系统整体有效吞吐量（Goodput）的关键。

#### 2. 方法论：核心思想与关键技术
Nitsum 的核心思想是将 TP 级别、预填充/解码（Prefill/Decode）资源比例以及请求调度进行**联合动态优化**。

*   **零开销 TP 权重切换（Zero-Overhead Weight Switching）**：
    *   为了避免切换 TP 时重新加载权重的秒级延迟，Nitsum 在每个 GPU 上存储一份完整的模型权重。
    *   通过自定义内核在运行时根据当前的 TP 级别选择对应的权重分片（Shard）。
    *   **预热进程**：为所有可能的 TP 级别预先启动并保持“热”执行进程，完成 CUDA Graph 捕获和编译，切换时仅需激活对应进程。
*   **聚合流水线 KV 迁移（Aggregated and Pipelined KV Migration）**：
    *   TP 级别改变时，KV Cache 需要在 GPU 间重新分布。Nitsum 弃用了传统的碎片化迁移，采用**双缓冲聚合机制**：先将碎片化的 KV 拷贝到连续缓冲区，再利用流水线并行化内存拷贝与网络传输，将迁移延迟从秒级降低至毫秒级（3.6ms - 24.8ms）。
*   **自适应配置算法**：
    *   **全局调度器**：每秒执行一次控制循环。基于离线性能 Profile、近期请求到达率和各层 SLO 目标，使用**加权贪心算法**决定 GPU 集群的配置（哪些 GPU 跑 Prefill，哪些跑 Decode，各自的 TP 级别是多少）。
    *   **局部调度器**：在 GPU 层面执行迭代级调度，优先保证“可行”请求的 SLO，余力处理“尽力而为”的请求。

*   **应用限制**：在负载极其稳定或 SLO 极度宽松的场景下，动态 TP 的收益会收敛，系统复杂度带来的维护成本可能超过性能收益。
