## 摘要
随着边缘计算的扩展，在单个共享 GPU 上提供多个深度神经网络（DNN）模型服务已成为一种常见但具有挑战性的场景，其中每个调度决策都会影响所有并发队列的尾部延迟。现有的调度器依赖于局部启发式方法，无法捕捉这种全局影响，而 GPU 空间共享方法则牺牲了延迟的可预测性。在本文中，我们提出了 EdgeServing，一种用于边缘设备的截止时间感知多 DNN 服务系统。EdgeServing 采用带有早退（early-exit）推理的分时 GPU 共享，以实现高推理可预测性，并引入了稳定性评分来量化每个候选调度决策对未来队列状态的影响。在运行时，它协同选择模型、退出点和批处理大小，以最小化预测的全系统 SLO 影响。在多个硬件平台上的实验结果表明，EdgeServing 在 SLO 违规率和 P95 延迟方面均始终优于代表性基准，这得益于早退机制，该机制在严格的延迟约束下扩展了调度动作空间。

## Abstract
As edge computing expands, serving multiple deep neural network (DNN) models on a single shared GPU has become a common yet challenging scenario, where each scheduling decision affects the tail latency of all concurrent queues. Existing schedulers rely on local heuristics and fail to capture this global impact, while GPU spatial-sharing approaches sacrifice latency predictability. In this paper, we propose EdgeServing, a deadline-aware multi-DNN serving system for edge devices. EdgeServing adopts time-division GPU sharing with early-exit inference for high inference predictability, and introduces a stability score to quantify how each candidate scheduling decision impacts the future queue status. At runtime, it cohesively selects the model, exit point, and batch size to minimize predicted system-wide SLO impact. Experimental results on multiple hardware platforms show that EdgeServing consistently outperforms representative baselines in both SLO violation ratio and P95 latency, enabled by early-exit mechanism, which expands the scheduling action space under tight latency constraints.

### 1. 核心问题与研究动机
*   **核心问题**：在边缘计算场景下，单个 GPU 需要同时为多个深度神经网络（DNN）模型提供服务。如何在保证每个请求的延迟截止时间（SLO）的同时，最大化系统吞吐量和推理准确度？
*   **研究动机**：
    *   **现有方案缺陷**：空间共享（如 NVIDIA MPS）会导致缓存和带宽竞争，使延迟不可预测；时间共享（分时）虽然延迟确定，但资源利用率低。
    *   **调度局限性**：现有的调度器（如最长队列优先）多依赖局部启发式规则，忽略了当前决策对其他模型队列未来状态的全局影响。
    *   **早退机制潜力**：虽然“早期退出”（Early-exit）能降低延迟，但现有研究多针对单模型，缺乏在多模型并发环境下的系统级协同优化。

### 2. 方法论
EdgeServing 结合了**分时 GPU 共享**和**动态早退机制**，核心思想是“预测未来影响并最小化系统不稳定性”。
*   **离线分析（Offline Profiling）**：在部署前，对所有模型在不同退出点（Exit Point）和批处理大小（Batch Size）下的延迟和准确率进行详尽测试，生成查找表。
*   **稳定性评分（Stability Score）**：引入一个非线性函数来量化任务的紧迫性。公式采用指数形式 $f(w) = \min(\exp(w/\tau - 1), C)$，其中 $w$ 是排队时间，$\tau$ 是 SLO 阈值。该评分能放大接近截止时间的任务权重。
*   **在线调度算法**：
    1.  **批处理与退出点选择**：针对每个队列，根据当前排队最久的任务，选择能满足 SLO 的最深（准确率最高）退出点和最大批处理大小。
    2.  **状态预测**：模拟如果执行当前决策，所有队列在下一时刻的排队状态。
    3.  **全局决策**：计算所有候选决策后的系统总稳定性评分，选择使系统最“稳定”（评分最低）的模型进行调度。

### 6. 主要结论与发现
*   **SLO 达标率极高**：在重负载下，EdgeServing 的 SLO 违规率保持在 1% 以下，而 All-Final 基准在相同条件下违规率超过 15%。
*   **自适应权衡**：系统能根据负载自动切换退出点。低负载时使用全模型保证准确率，高负载时牺牲部分准确率以换取系统不崩溃。
*   **全局优化的必要性**：仅靠早退机制或仅靠截止时间优先调度是不够的，必须协同优化模型选择、批处理和退出点才能应对边缘侧的资源受限环境。

### 7. 优点
*   **高可预测性**：通过分时共享和离线 Profile，规避了 GPU 空间竞争带来的延迟抖动。
*   **全局视野**：稳定性评分机制考虑了“当前决策对其他队列的负面影响”，有效防止了某个模型队列因长时间占用 GPU 而导致其他模型集体违规。
*   **硬件友好**：算法逻辑简单（线性搜索查找表），调度开销极低，适合在 CPU 算力也有限的边缘设备上运行。

### 8. 不足与局限
*   **离线依赖**：系统高度依赖预先测量的 Profile 数据。如果 GPU 环境发生变化（如温度过高导致降频）或模型更新，需要重新进行耗时的离线测试。
*   **模型限制**：仅适用于可以修改架构并添加早退分支的 CNN 类模型，对于某些难以添加中间分类器的复杂模型或生成式模型（如 Transformer）的适用性未讨论。
*   **准确率损失**：在极端高负载下，为了保住 SLO，系统会频繁选择最早退出点，导致推理准确率大幅下降（实验中甚至降至 10% 左右），这在某些安全敏感场景下可能不可接受。
