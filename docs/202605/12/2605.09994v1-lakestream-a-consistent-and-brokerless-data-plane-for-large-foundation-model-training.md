## 摘要
现代大型基础模型（LFM）训练已将数据流水线从静态摄取层转变为必须与训练过程共同演进的动态组件。现有系统对此准备不足：同机部署的数据加载器（dataloader）无法提供故障隔离，而基于消息队列的解耦式数据加载器则运行在记录/偏移量（record/offset）抽象之上，无法表达分布式训练所需的批次级语义。我们提出了 Lakestream，这是一个无代理、原生支持对象存储的训练数据平面，具有三个关键特性。首先，它引入了事务性全局批次（Transactional Global Batch, TGB），该技术基于湖仓一体（lakehouse-style）的 ACID 存储语义，并将其扩展到训练特定的连贯性，包括原子化的全 rank 批次可见性、全局有序的步进序列、与检查点对齐的生命周期管理以及端到端的精确一次（exactly-once）恢复。其次，它通过在清单（manifest）中内联生产者状态，并将回收与分布式检查点状态绑定，直接在存储层实现恢复和保留。第三，其去中心化自适应提交（Decentralized Adaptive Commit, DAC）算法在清单增长时仍能维持稳定的摄取吞吐量，且无需任何生产者间的通信。在 64 个 GPU 上进行的大规模多模态预训练和 SFT 工作负载评估表明，Lakestream 在提供完整故障隔离的同时，吞吐量超过了同机部署的数据加载器，在摄取吞吐量上优于 Apache Kafka，并且实现了比 Kafka 更低的消费者读取延迟。

## Abstract
Modern Large Foundation Model (LFM) training has transformed the data pipeline from a static ingestion layer into a dynamic component that must co-evolve with the training process. Existing systems are ill-equipped: colocated dataloaders offer no failure isolation, while message queue-based disaggregated dataloaders operate on a record/offset abstraction that cannot express the batch-level semantics required by distributed training.   We present Lakestream, a brokerless, object-store-native training data plane with three key properties. First, it introduces the Transactional Global Batch (TGB), which builds on lakehouse-style ACID storage semantics and extends them with training-specific consistency, including atomic all-rank batch visibility, a globally ordered step sequence, checkpoint-aligned lifecycle management, and end-to-end exactly-once recovery. Second, it realizes recovery and retention directly in the storage layer, by inlining producer state in the manifest and tying reclamation to distributed checkpoint state. Third, its Decentralized Adaptive Commit (DAC) algorithm sustains stable ingestion throughput as the manifest grows, without any inter-producer communication.   Evaluations on large-scale multimodal pre-training and SFT workloads using 64 GPUs show that Lakestream outperforms colocated dataloader throughput while providing full failure isolation, outperforms Apache Kafka in ingestion throughput, and achieves lower consumer read latency than Kafka.

*   **核心挑战**：
    *   **数据膨胀**：运行时预处理（如视频解码、Token 打包）会导致数据量激增（文中提到可达 62x 至 9000x 的膨胀），静态分配资源不可行。
    *   **批次语义缺失**：分布式训练需要“全局批次”（Global Batch）的原子可见性和严格顺序，而现有的消息队列（如 Kafka）基于记录/偏移量，难以表达批次边界。
    *   **缺乏故障隔离与对齐**：同机部署（Colocated）的加载器缺乏隔离，一旦预处理崩溃则训练停止；而解耦系统往往无法与训练检查点（Checkpoint）实现精确一致的恢复。
*   **研究目的**：构建一个无代理（Brokerless）、原生支持对象存储、具备事务一致性且能与训练进度同步的数据平面。

### 2. 方法论与关键技术
Lakestream 采用纯客户端库实现，将对象存储作为唯一的协调媒介。
*   **事务性全局批次（TGB）**：将每个训练批次视为持久化的第一类实体。通过版本化的清单（Manifest）管理可见性，只有当清单记录了 TGB 及其在全局序列中的位置时，该批次才对所有训练 Rank 可见。
*   **去中心化自适应提交（DAC）算法**：
    *   **核心思想**：在无生产者间通信的情况下，动态调整提交频率。
    *   **机制**：基于泊松过程模型，通过在线估计清单 I/O 时间（脆弱窗口 $\tau_v$）和冲突率，计算最优等待间隔 $T^*$。它平衡了“提交开销”和“冲突概率”，确保在清单文件随时间增长时，摄取吞吐量依然稳定。
*   **检查点对齐的生命周期管理**：
    *   **水位线（Watermark）机制**：将数据保留策略与分布式检查点绑定。只有当所有 Rank 都越过某个水位线后，旧数据才会被回收。
    *   **精确一次（Exactly-once）语义**：将生产者状态直接内联在清单中，实现端到端的故障恢复。
*   **数据布局优化**：采用 N 维并行感知的布局，支持 Rank 级别的范围读取（Range Read），避免了传统方案中的读取放大问题。

### 5. 实验数量与充分性
*   **实验规模**：涵盖了从微观基准测试（生产者/消费者性能）到端到端大规模训练的完整链路。

### 6. 主要结论与发现
*   **端到端性能**：在 GR00T、视频 SFT 和 VLA 任务中，Lakestream 的吞吐量分别比 Local 方案高出 **2.68x、7.73x 和 5.17x**。
*   **摄取能力**：在 128 个生产者并发时，Lakestream 达到了最高 **16.0 GB/s** 的摄取吞吐量，远超 Kafka。
*   **读取效率**：由于消除了读取放大，Lakestream 在 128 个 Rank 规模下的读取延迟比传统方案降低了数个数量级（P95 延迟从 31.4s 降至 3.21s）。
*   **稳定性**：DAC 算法成功将提交成功率维持在 95% 以上，而固定间隔策略在运行后期会因冲突剧增而崩溃。

### 7. 优点与亮点
*   **架构极简**：Brokerless 设计消除了中心化代理的单点故障和性能瓶颈，降低了运维成本。
*   **语义对齐**：首次将湖仓一体（Lakehouse）的事务语义引入训练数据流，解决了分布式训练中极其痛苦的“批次一致性”和“检查点回滚”问题。
*   **自适应性强**：DAC 算法能够根据清单文件的物理增长自动调整行为，具有很强的工程实用性。

### 8. 不足与局限
*   **对象存储依赖**：系统性能高度依赖底层对象存储的 `If-None-Match`（条件写）性能和响应延迟。
*   **元数据开销**：虽然文中提到内联状态开销会随时间摊薄，但在极小批次、极高频率提交的极端场景下，清单文件的膨胀速度可能成为潜在瓶颈。
*   **适用范围**：主要针对重预处理（计算密集型）的 LFM 任务，对于数据预处理极轻、IO 极其密集的传统小模型任务，其优势可能不明显。
