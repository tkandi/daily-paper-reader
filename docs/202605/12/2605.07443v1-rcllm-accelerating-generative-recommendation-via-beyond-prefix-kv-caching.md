## 摘要
大语言模型（LLMs）正在将推荐系统从排序任务转变为生成式任务，但由于处理长且个性化的提示词（prompts）存在高延迟，其工业部署仍受到限制。标准的前缀缓存（prefix caching）带来的收益有限，因为推荐工作负载中的重用在用户历史和物品上下文中通常是非连续的。我们提出了 RcLLM，这是一个具有“超越前缀 KV 缓存”（Beyond-Prefix KV Caching）功能的生成式推荐分布式推理系统。RcLLM 将提示词分解为可重用的块，并通过分层分布式存储设计支持大规模物品目录：紧凑的用户历史缓存被复制以实现零延迟检索，而海量的物品缓存则使用相似性感知放置进行分片。为了减少冗余的二次方复杂度注意力计算，RcLLM 结合了提高数据局部性的基于亲和力的全局调度器，以及纠正近似误差的选择性注意力机制。在真实数据集上的实验表明，与最先进的前缀缓存系统相比，RcLLM 将首字延迟（TTFT）降低了 1.31 倍至 9.51 倍，在对推荐准确性影响微乎其微的情况下实现了实时服务。

## Abstract
Large Language Models (LLMs) are transforming recommendation from ranking into a generative task, but industrial deployment remains limited by the high latency of processing long, personalized prompts. Standard prefix caching provides limited benefit because reuse in recommendation workloads is often non-contiguous across user histories and item contexts. We present RcLLM, a distributed inference system for generative recommendation with Beyond-Prefix KV Caching. RcLLM decomposes prompts into reusable blocks and supports large item catalogs with a stratified distributed storage design: compact user-history caches are replicated for zero-latency retrieval, while massive item caches are sharded using similarity-aware placement. To reduce redundant quadratic attention computation, RcLLM combines an affinity-based global scheduler that improves data locality with a selective attention mechanism that corrects approximation errors. Experiments on real-world datasets show that RcLLM reduces Time-To-First-Token (TTFT) by 1.31x-9.51x compared with state-of-the-art prefix caching systems, enabling real-time serving with negligible impact on recommendation accuracy.

### 1. 核心问题与整体含义（研究动机和背景）
*   **核心问题**：大语言模型（LLM）在推荐任务中表现优异，但其**推理延迟（尤其是首字延迟 TTFT）**极高，难以满足工业级实时服务（通常要求 <100ms）的要求。
*   **研究动机**：
    *   **前缀缓存失效**：传统推理引擎（如 vLLM）依赖“前缀缓存”，要求请求开头必须完全一致。但在推荐场景中，虽然物品描述和用户历史是重复的，但它们在提示词（Prompt）中的位置经常变动（位于唯一的个性化前缀之后），导致缓存命中率几乎为零。
    *   **计算冗余**：推荐 Prompt 通常包含数千个 Token（长历史+多物品描述），其中大部分内容是静态或语义重复的，每次请求都重新计算 KV Cache 造成了巨大的算力浪费。

### 2. 方法论
RcLLM 的核心思想是**“超越前缀的块级复用”**，将 Prompt 分解为可独立缓存和拼接的语义块。
*   **分层分布式存储（Stratified Storage）**：
    *   **语义历史库（Replicated）**：针对用户评论等语义重复但位置多变的内容，利用 LSH（局部敏感哈希）进行聚类，构建紧凑的语义原型库，并**全量复制**到所有节点，实现零延迟本地检索。
    *   **物品 KV 分片（Sharded）**：针对海量物品目录（可达 TB 级），采用**相似性感知放置算法**。将高频物品全局复制，长尾物品根据共现关系进行图划分（METIS 算法）并分片存储在不同节点。
*   **在线推理优化**：
    *   **亲和性感知调度（Affinity Scheduling）**：全局调度器根据请求中的物品与节点缓存的匹配度（Locality）以及节点负载（Load）进行加权打分，将请求路由至最优节点。
    *   **选择性注意力（Selective Attention）**：为了解决非连续块拼接导致的精度损失，RcLLM 识别并重新计算少量的“重锤（Heavy Hitter）”Token（对注意力贡献大的关键 Token），其余部分直接复用缓存。
    *   **零拷贝检索**：在本地节点通过零拷贝路径将 KV 块从 CPU 内存快速传输至 GPU。

### 6. 主要结论与发现
*   **显著加速**：RcLLM 相比前缀缓存系统，在 TTFT 上实现了 **1.31x 至 9.51x** 的加速。

### 7. 优点
*   **针对性强**：精准捕捉了推荐系统 Prompt “预填充重、解码轻”且“非连续重复”的结构特征。
*   **架构优雅**：通过分层存储（复制+分片）平衡了存储容量与访问延迟的矛盾。
*   **实用性高**：通过选择性重计算机制，在不牺牲（甚至提升）推荐质量的前提下大幅降低了延迟，使 LLM 推荐进入 100ms 响应圈。

### 8. 不足与局限
*   **模拟环境限制**：系统层面的性能数据主要来自 Vidur 模拟器，虽然 Vidur 具有高保真度，但在真实复杂网络环境下的抖动表现仍需实测。

*   **模型架构依赖**：主要针对标准的 Transformer 架构，对于 MoE（混合专家模型）等更复杂的变体架构，其 KV 缓存管理可能面临新的挑战。
