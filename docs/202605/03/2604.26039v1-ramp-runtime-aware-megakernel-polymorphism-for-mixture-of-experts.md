## 摘要
混合专家模型（MoE）推理的最佳算子配置取决于批大小和专家路由分布，然而生产系统仅依据批大小进行调度，导致 10-70% 的算子吞吐量未能实现。我们提出了 RaMP，一个路由感知的调度框架。性能区域分析仅通过硬件常量即可推导出各项优化的适用时机，并准确预测了所有 8 种测试架构（包括 3 种未知架构）。一个四参数的波次成本模型从运行时专家直方图中选择最快配置，与穷举搜索相比，平均遗憾值仅为 0.93%，且每个模型仅需 10-24 分钟的一次性分析拟合。由于该模型仅依赖于 CTA 网格几何结构，因此具有算子无关性：应用于 Alpha-MoE 时，在无需修改源码的情况下实现了 1.14 倍的提升。配合共同设计的、提供 134-268 种多态配置的 CuTe DSL 算子，RaMP 相比静态调度实现了 1.22 倍的算子加速，在 vLLM 服务中相比 Triton 实现了 1.30 倍的端到端加速，相比 DeepGEMM 提升 1.41 倍，相比 FlashInfer CUTLASS 提升 1.13 倍。

## Abstract
The optimal kernel configuration for Mixture-of-Experts (MoE) inference depends on both batch size and the expert routing distribution, yet production systems dispatch from batch size alone, leaving 10-70% of kernel throughput unrealized. We present RaMP, a routing-aware dispatch framework. A performance-region analysis derives, from hardware constants alone, when each optimization helps, correctly predicting all 8 tested architectures, including 3 unseen. A four-parameter wave cost model selects the fastest configuration from the runtime expert histogram, achieving 0.93% mean regret versus exhaustive search, fitted from just 10-24 minutes of one-time profiling per model. Because the model depends only on CTA grid geometry, it is kernel-agnostic: applied to Alpha-MoE, it delivers 1.14x with no source modification. Paired with a co-designed CuTe DSL kernel exposing 134-268 polymorphic configurations, RaMP delivers 1.22x kernel speedup over static dispatch and 1.30x end-to-end speedup in vLLM serving over Triton, 1.41x over DeepGEMM, and 1.13x over FlashInfer CUTLASS.

#### 1. 核心问题与整体含义
混合专家模型（MoE）在推理时仅激活部分参数，其性能高度依赖于**专家路由分布（Routing Distribution）**。然而，现有的生产系统（如 vLLM、DeepGEMM 等）在调度算子内核（Kernel Dispatch）时，仅依据批大小（Batch Size）进行静态选择，完全忽略了路由分布的倾斜。
*   **研究动机**：在实际生产中，专家路由通常极度倾斜（仅 8-14% 的专家处于活跃状态），静态调度会导致严重的 GPU 波次（Wave）利用率不足和填充浪费（Padding Waste），损失 10-70% 的潜在吞吐量。
*   **核心目标**：开发一种能够感知运行时路由分布、动态选择最优内核配置的调度框架。

#### 2. 方法论
RaMP 框架由三个核心组件组成：
*   **性能区域分析（Performance-Region Analysis）**：
    *   通过四个基于硬件常量的变量来划分性能区间：**计算密度 ($\rho$)**、**L2 缓存压力 ($\lambda$)**、**波次利用率 ($\omega$)** 和 **K 维度归约深度 ($\kappa$)**。
    *   这些变量决定了何时启用特定优化（如 Group M 变换、Split-K 归约等）。
*   **四参数波次成本模型（Wave Cost Model）**：
    *   将内核执行时间建模为：$T = a(\text{启动开销}) + b(\text{波次调度}) + c(\text{每 CTA 流量}) + d(\text{子波次非线性})$。

*   **多态 CuTe DSL 内核**：
    *   使用 NVIDIA CuTe 共同设计的融合内核，支持 134-268 种多态配置（涵盖不同的 Tile 大小、流水线深度等）。
    *   运行时通过一个轻量级 Triton 内核（耗时约 38μs）计算专家直方图并评估成本模型，从而选择最优配置。

*   **内核无关性**：调度框架与具体算子实现解耦，能够轻松集成到现有的各类 MoE 推理引擎中。
*   **极低开销**：通过运行时缓存和向量化评估，解决了动态调度可能带来的延迟瓶颈。

#### 8. 不足与局限
*   **硬件局限性**：目前主要针对 NVIDIA Hopper 架构（H200）进行了验证，虽然理论可扩展，但迁移到 Blackwell 或其他厂商硬件（如 AMD Instinct）可能需要重新推导部分硬件常量。

*   **极端情况收敛**：在批大小极小（S=1）或路由完全均匀的情况下，动态调度的收益会收敛至与静态调度持平。
