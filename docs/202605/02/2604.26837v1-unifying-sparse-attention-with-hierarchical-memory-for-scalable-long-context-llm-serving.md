## 摘要
长上下文大语言模型（LLM）推理服务的瓶颈在于处理不断增长的 KV 缓存（KV cache）的注意力计算开销。动态稀疏注意力通过在每个解码步骤中仅访问 KV 状态中一小部分与查询相关的子集，并将 KV 存储扩展到 CPU 内存，有望缓解这一问题。然而在实践中，这些算法上的节省很少能转化为端到端的系统级收益，因为稀疏方法通常在不同的粒度上运行，因此依赖于针对特定算法的临时实现。同时，分级 KV 存储引入了新的系统瓶颈：跨 GPU-CPU 边界检索细粒度、不规则的 KV 子集很容易抵消稀疏性带来的好处。我们提出了 SPIN，这是一个感知稀疏注意力的推理框架，通过三种技术协同设计执行流水线与分级 KV 存储：(1) 统一的分区抽象，将不同的稀疏粒度映射到共享的基于页面的 KV 基座上；(2) 局部性感知的 KV 缓存管理器，动态调整每个请求的 HBM 预算，并使用 GPU 友好的分桶 LRU 策略来减少 PCIe 往返次数；(3) 两级分层元数据布局，其大小根据活动工作集而非最坏情况下的地址空间确定。SPIN 基于 vLLM 构建，并集成了三种代表性的稀疏注意力算法。与 vLLM 相比，SPIN 的端到端吞吐量提高了 1.66-5.66 倍，首字延迟（TTFT）降低了 7-9 倍，且与原始稀疏注意力实现相比，逐词生成延迟（TPOT）降低了高达 58%。

## Abstract
Long-context LLM serving is bottlenecked by the cost of attending over ever-growing KV caches. Dynamic sparse attention promises relief by accessing only a small, query-dependent subset of the KV state per decoding step and extending the KV storage to CPU memory. In practice, however, these algorithmic savings rarely translate into end-to-end system-level gains because sparse methods typically operate at different granularities and thus rely on ad hoc, per-algorithm implementations. At the same time, hierarchical KV storage introduces a new systems bottleneck: retrieving fine-grained, irregular KV subsets across the GPU-CPU boundary can easily erase the benefits of sparsity.   We present SPIN, a sparse-attention-aware inference framework that co-designs the execution pipeline with hierarchical KV storage through three techniques: (1) a unified partition abstraction that maps different sparsity granularities onto a shared page-based KV substrate; (2) a locality-aware KV cache manager that dynamically sizes per-request HBM budgets and uses a GPU-friendly bucketed LRU policy to cut PCIe round-trips; and (3) a two-level hierarchical metadata layout sized to the active working set rather than the worst-case address space. Built on vLLM with three representative sparse attention algorithms, SPIN delivers 1.66-5.66x higher end-to-end throughput and 7-9x lower TTFT than vLLM, and reduces TPOT by up to 58% over the original sparse-attention implementations.

### 1. 核心问题与研究动机
*   **核心问题**：长上下文 LLM 推理受限于 KV 缓存的线性增长，导致 GPU 显存容量不足（Capacity-bound）和显存带宽受限（Bandwidth-bound）。
*   **研究动机**：
    *   **算法与系统的脱节**：虽然动态稀疏注意力算法（如 ShadowKV）能减少计算量，但不同算法的稀疏粒度（块、聚类、单 Token）不一，缺乏统一的系统抽象。
    *   **数据传输开销**：将 KV 缓存存放在 CPU 内存中虽然解决了容量问题，但跨 GPU-CPU 边界（PCIe）检索细粒度、不规则的 KV 数据会产生巨大的延迟，抵消了稀疏性带来的收益。
    *   **元数据膨胀**：在长上下文和头级（Head-wise）稀疏模式下，管理 KV 页面的元数据本身就会占用大量显存。

### 2. 方法论与关键技术
SPIN 提出了一个感知稀疏注意力的推理框架，通过软硬件协同设计优化执行流水线：
*   **统一分区抽象（Unified Partition Abstraction）**：
    *   引入“分区（Partition）”作为逻辑单位，将不同算法的稀疏粒度映射到统一的、基于页面的 KV 基座上。
    *   定义了五阶段流水线：**Index**（构建索引/摘要）、**Select**（选择关键分区）、**Offload**（异步卸载）、**Retrieve**（按需检索）、**Attention**（稀疏计算）。
*   **局部性感知 KV 管理器（Locality-aware KV Manager）**：
    *   **弹性预算**：根据系统负载动态调整每个请求的 GPU 缓存大小。
    *   **分桶 LRU（Bucketed LRU）**：一种 GPU 友好的缓存替换策略。它不进行全局排序，而是将时间戳映射到有限的桶中，利用 GPU 并行性快速识别并剔除冷数据，减少 PCIe 传输。
*   **分级元数据布局（Hierarchical Metadata Layout）**：
    *   采用类似操作系统的**两级索引结构**，使元数据开销随实际物理工作集（Active Working Set）缩放，而非随最坏情况的逻辑地址空间缩放。
    *   **层级拆分**：将延迟敏感的元数据放在 GPU，容量敏感的（如 CPU 页面映射表）放在 CPU 钉住内存（Pinned Memory）。
