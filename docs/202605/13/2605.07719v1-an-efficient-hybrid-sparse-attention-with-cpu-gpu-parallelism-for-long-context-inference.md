## 摘要
长上下文推理越来越多地在驻留 CPU 的 KV 缓存上运行，这要么是因为解码时的 KV 状态超过了 GPU 显存容量，要么是因为解耦的预填充-解码系统将 KV 数据放置在主机内存中。尽管在这种情况下块稀疏注意力降低了注意力计算开销，但仅靠稀疏性不足以实现端到端的效率。仅 GPU 的设计仍受限于 PCIe 带宽和元数据内存开销，而 CPU-GPU 混合设计仍面临严重的 GPU 空闲时间以及 CPU 端 top-k 选择和稀疏注意力计算的瓶颈。Fluxion 基于三个关键见解：输出感知的 KV 预算分配、特定于头且感知粒度的稀疏配置，以及针对驻留 CPU 的 KV 缓存的跨设备协同执行稀疏注意力。在这些见解的指导下，Fluxion 结合了一个轻量级的头属性预测器、一个粒度-预算选择器和一个基于优先级的调度器，以共同优化预算分配、稀疏配置和 CPU-GPU 执行重叠。这种协同设计使混合稀疏注意力在长上下文推理中能够同时实现准确性和系统效率。在 2 个模型、3 个基准测试和 40 个任务中，Fluxion 很好地保持了质量——相对于全量注意力（FULL），最差的平均性能下降仅为 -0.26，同时比最强的固定稀疏混合基线（其 KV 预算仅为 0.05）实现了 1.5 倍至 3.7 倍的加速。

## Abstract
Long-context inference increasingly operates over CPU-resident KV caches, either because decoding-time KV states exceed GPU memory capacity or because disaggregated prefill-decode systems place KV data in host memory. Although block-sparse attention reduces attention cost in this setting, sparsity alone is insufficient for end-to-end efficiency. GPU-only designs remain constrained by PCIe bandwidth and metadata memory overhead, while CPU-GPU hybrid designs still suffer from substantial GPU idle time and bottlenecks in CPU-side top-k selection and sparse attention computation.   Fluxion is built on three key insights: output-aware KV budgeting, head-specific and granularity-aware sparse configuration, and cross-device coordinated execution for sparse attention over CPU-resident KV caches. Guided by these insights, Fluxion combines a lightweight head-property predictor, a granularity-budget selector, and a priority-based scheduler to jointly optimize budget allocation, sparse configuration, and CPU-GPU execution overlap. This co-design enables hybrid sparse attention to achieve both accuracy and system efficiency in long-context inference. Across 2 models, 3 benchmarks, and 40 tasks, Fluxion preserves quality well -- the worst average degradation is only -0.26 relative to FULL, while delivering 1.5$\times$-3.7$\times$ speedup over the strongest fixed sparse hybrid baseline, whose KV budget is only 0.05.

### 1. 核心问题与研究动机
*   **核心问题**：在长上下文推理中，KV 缓存规模巨大，通常需要卸载（Offload）到 CPU 内存。现有的稀疏注意力方案（如仅 GPU 方案或简单的 CPU-GPU 混合方案）在处理驻留在 CPU 的 KV 缓存时，存在 **PCIe 带宽受限、GPU 严重空闲、以及 CPU 端 Top-K 选择和计算效率低下** 的问题。
*   **研究动机**：作者发现，仅仅将计算移动到 CPU 是不够的。现有的预算分配（Budgeting）大多基于注意力分数（Score-based），忽略了不同头（Heads）对最终输出贡献的差异；同时，Top-K 选择的粒度（块大小）与计算开销及精度之间存在未被充分利用的耦合关系。

### 2. 方法论
Fluxion 的核心思想是通过**软硬件协同设计**，实现输出感知的预算分配和跨设备的并行调度。其关键技术包括：
*   **输出贡献感知的 KV 预算分配**：
    *   **见解**：注意力分数高并不代表输出贡献大（受 Attention Sink 现象影响）。
    *   **做法**：不仅关注注意力分数的覆盖率，还考虑每个头对最终输出的偏差影响及其相对贡献度，从而实现非均匀的误差分配。
*   **特定于头的稀疏配置（头属性预测器）**：
    *   **分类**：将注意力头分为“流式头”（Streaming Head，仅需少量最近/初始 Token）和“检索头”（Retrieval Head，需要全局 Top-K 检索）。
    *   **建模**：针对检索头，建立 KV 预算与选择粒度（Block Size）之间的线性关系模型（在 $log_2$ 空间内）。
    *   **预测器**：使用一个轻量级 MLP（0.112M 参数）在线预测每个头的属性和最优配置。
*   **粒度-预算选择器**：
    *   在满足精度约束的前提下，联合优化 Top-K 选择的块大小和 KV 预算，以最小化 CPU 端的总数据访问量。
*   **基于优先级的并行调度器**：
    *   将稀疏注意力任务抽象为优先级队列，根据任务的数据量（计算开销预测）进行排序。
    *   CPU 和 GPU 作为独立的工作单元，动态从队列中提取任务并行执行，最大化设备重叠（Overlap）。

*   **实验规模**：涵盖了 2 个主流模型、3 个大型基准测试、共计 40 个子任务。

### 6. 主要结论与发现
*   **效率提升**：相比于最强的固定稀疏基线，Fluxion 实现了 **1.5x 至 3.7x** 的解码速度（TPOT）提升。
*   **精度保持**：在 LongBench 上，相对于 FULL 的平均得分变动仅为 -0.13/+0.02；在 L-Eval 上下降约 0.24-0.26，几乎实现了无损压缩。
*   **资源利用**：显著降低了 GPU 空闲率（例如在 Qwen-32K 场景下，空闲比例从 70.65% 降至 45.78%）。
*   **关键发现**：Top-K 选择的粒度是 CPU 端计算的关键瓶颈，且该粒度与所需预算之间存在可预测的耦合关系。

### 7. 优点
*   **首创性**：首次提出将 KV 预算分配与注意力输出贡献挂钩，而非单纯依赖分数。
*   **系统协同**：不仅是算法优化，还深入到了 CPU-GPU 任务调度层面，解决了异构计算中的负载均衡问题。
*   **轻量化**：预测器开销极低（仅占总执行时间的 1.9%-8.2%），且随着 Batch Size 增加而进一步摊薄。

### 8. 不足与局限
*   **硬件依赖**：实验基于 PCIe 4.0 和特定的 CPU/GPU 组合，在 PCIe 3.0 或带宽更高的环境（如 NVLink 卸载）下，性能增益可能有所不同。
*   **任务敏感性**：在代码任务（如 LCC）和某些需要极高局部精确度的任务上，仍存在约 2% 的性能下降。
*   **预测器泛化性**：预测器需要在特定模型上进行离线数据收集和训练，对于新模型可能需要重新适配。
*   **应用限制**：主要针对解码阶段（Decoding），对于预填充阶段（Prefill）的优化提及较少。
