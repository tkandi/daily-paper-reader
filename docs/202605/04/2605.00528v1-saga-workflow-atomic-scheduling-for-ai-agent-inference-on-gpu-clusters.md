## 摘要
AI Agent 在每个任务中执行数十到数百个链式 LLM 调用，然而 GPU 调度器将每个调用视为独立的，导致步骤之间丢弃了数 GB 的中间状态，并将端到端延迟放大了 3-8 倍。我们认为这种请求级抽象与复合 AI 工作负载根本不匹配，并提出转向程序级调度：将整个 Agent 工作流（而非单个推理调用）视为第一类可调度单元。我们提出了 SAGA，这是一种通过三种机制实现该抽象的分布式调度器：(1) Agent 执行图，捕获工作流结构以预测跨工具调用边界的 KV 缓存重用，达到 Bélády 最优离线策略的 1.31 倍以内；(2) 带有工作窃取（work stealing）的会话亲和性批处理，在保持全局负载均衡的同时协同定位相关请求；(3) Agent 公平份额（Agent Fair Share），一种具有可证明的有界偏差保证的任务完成时间公平性指标。在服务于 SWE-bench 编码 Agent 和 WebArena 浏览器任务的 64-GPU 集群上，相比于具有前缀缓存和亲和性路由的 vLLM v0.15.1，SAGA 将任务完成时间缩短了 1.64 倍（几何平均值，p < 0.001），同时将 GPU 显存利用率提高了 1.22 倍，并在多租户干扰下实现了 99.2% 的 SLO 达成率。这些延迟收益伴随着量化的成本：峰值吞吐量比吞吐量最优的批处理调度低约 30%，这种权衡适用于主导复合 AI 使用的延迟敏感型交互式部署。我们的结果表明，工作流感知调度对于高效的复合 AI 服务至关重要。

## Abstract
AI agents execute tens to hundreds of chained LLM calls per task, yet GPU schedulers treat each call as independent, discarding gigabytes of intermediate state between steps and inflating end-to-end latency by 3-8x. We argue that this request-level abstraction is fundamentally mismatched to compound AI workloads, and propose a shift to program-level scheduling: treating the entire agent workflow (not individual inference calls) as the first-class schedulable unit. We present SAGA, a distributed scheduler that implements this abstraction through three mechanisms: (1) Agent Execution Graphs that capture workflow structure to predict KV cache reuse across tool-call boundaries, achieving within 1.31x of Bélády's optimal offline policy; (2) session-affinity batching with work stealing that co-locates correlated requests while maintaining global load balance; and (3) Agent Fair Share, a task-completion-time fairness metric with provable bounded-deviation guarantees. On a 64-GPU cluster serving SWE-bench coding agents and WebArena browser tasks, SAGA reduces task completion time by 1.64x (geometric mean, p < 0.001) over vLLM v0.15.1 with prefix caching and affinity routing, while improving GPU memory utilization by 1.22x and achieving 99.2% SLO attainment under multi-tenant interference. These latency gains come at a quantified cost: approximately 30% lower peak throughput than throughput-optimal batch scheduling, a tradeoff appropriate for the latency-sensitive interactive deployments that dominate compound AI usage. Our results demonstrate that workflow-aware scheduling is essential for efficient compound AI serving.

### 1. 核心问题与整体含义（研究动机和背景）
*   **核心问题**：当前的 GPU 推理调度器（如 vLLM、Orca）采用“请求级”抽象，将 AI Agent 的每一次 LLM 调用视为独立请求。
*   **研究背景**：AI Agent（如编码助手、网页浏览器智能体）通常涉及数十到数百步的链式调用（Thought-Action-Observation 循环）。在步骤之间，Agent 往往需要调用外部工具（如执行代码、查询数据库），这会导致长达数秒甚至数分钟的停顿。
*   **痛点**：由于调度器不感知工作流，在工具调用期间，宝贵的 KV 缓存（Key-Value Cache）常被驱逐，导致下一步骤必须重新生成缓存（Prefill），这使得端到端延迟增加了 3-8 倍，并造成了巨大的计算资源浪费。

### 2. 方法论：核心思想与关键技术
SAGA 提出将调度单位从“请求级”提升到“程序级”（工作流原子调度），核心技术包括：
*   **Agent 执行图 (AEG)**：通过框架提供的提示或模式推理，构建 Agent 的执行拓扑图，预测未来步骤对 KV 缓存的重用概率。
*   **工作流感知驱逐策略 (WA-LRU)**：改进传统的 LRU 算法，结合归一化的访问近期性、AEG 预测的重用概率以及缓存大小来决定驱逐优先级。其效果接近理论最优的 Bélády 算法。
*   **工具调用感知的 TTL (Time-to-Live)**：根据不同工具（如代码执行 vs 网页 API）的历史延迟分布，动态设定缓存保留时间。在显存压力大时，自动缩短 TTL。
*   **会话亲和性批处理与工作窃取**：全局调度器将同一 Agent 会话的请求路由到同一工作节点以复用缓存；当负载不均时，通过“随机工作窃取”机制和 KV 缓存迁移技术实现集群平衡。
*   **Agent 公平份额 (AFS)**：提出一种基于“任务完成时间（TCT）”紧急程度的公平性指标，并利用 Lyapunov 漂移分析证明了其在多租户环境下的有界偏差保证。

### 3. 实验设计
*   **数据集/场景**：
    *   **SWE-bench**：500 个真实的 GitHub 问题解决任务（编码 Agent）。
    *   **WebArena**：812 个浏览器交互任务（网页 Agent）。
    *   **BurstGPT 衍生负载**：基于真实生产轨迹合成的多租户并发工作负载。
*   **对比方法 (Baselines)**：

*   **模型**：主要使用 **Llama-3-70B-Instruct**，采用 4 路张量并行（Tensor Parallelism）。

### 5. 实验数量与充分性
*   **实验规模**：所有实验均重复 10 次并取平均值，标注了标准差和统计显著性（p < 0.001）。
*   **维度覆盖**：涵盖了端到端性能对比、消融实验（验证各组件贡献）、模式推理准确性、多租户公平性、系统开销分析以及参数敏感性分析。
*   **客观性**：实验对比了当前工业界最先进的 vLLM 版本，并量化了 SAGA 在提升延迟性能时付出的吞吐量代价，评价较为客观、全面。

### 6. 主要结论与发现
*   **延迟缩短**：在 SWE-bench 和 WebArena 上，SAGA 相比 vLLM+APC 分别实现了 **1.73x** 和 **1.55x** 的任务完成时间（TCT）加速（几何平均 1.64x）。
*   **显存优化**：显存利用率提升了 **1.22x**，有效减少了因缓存丢失导致的重复计算。
*   **公平性**：在多租户干扰下，SLO 达成率高达 **99.2%**，远超基准系统的 67.3%。
*   **性能上限**：证明了在感知工作流的情况下，在线缓存管理可以达到离线最优策略（Bélády）的 **1.31x** 以内。
*   **吞吐量权衡**：为了优化延迟，SAGA 的峰值吞吐量比纯吞吐量优化调度器低约 **30%**。

### 7. 优点
*   **范式转移**：从请求级调度转向程序级调度，精准捕捉了复合 AI 系统的本质特征。
*   **理论支撑**：不仅有系统实现，还提供了关于公平性和竞争比（Competitive Ratio）的正式数学证明。
*   **即插即用**：作为 vLLM 的扩展实现，能够兼容现有的 Agent 框架（如 LangChain, AutoGen），且在无标注时支持自动模式推理。

### 8. 不足与局限
*   **吞吐量损失**：不适用于对延迟不敏感、只追求极致吞吐量的批处理任务。
*   **工作流可见性依赖**：虽然支持模式推理，但在完全动态、不可预测的多智能体辩论等场景下，AEG 的预测准确性会下降。
*   **工具延迟长尾风险**：如果工具调用出现极端的黑天鹅事件（延迟超过 P99 很多），缓存仍会被驱逐。
*   **模型覆盖**：实验主要集中在 Llama-3 系列，对于混合专家模型（MoE）或超大规模模型（如 405B）的分布式路由细节讨论较少。
