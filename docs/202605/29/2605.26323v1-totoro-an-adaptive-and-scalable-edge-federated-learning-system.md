## 摘要
联邦学习（FL）是一种新兴的分布式机器学习（ML）技术，能够在去中心化的边缘设备上进行原位模型训练和推理。我们提出Totoro+，一种新颖的可扩展FL系统，使大量FL应用能够在边缘网络上同时运行。其关键思想是利用基于分布式哈希表（DHT）的对等（P2P）模型，将集中式FL系统架构重新设计为完全去中心化的系统。与先前研究中多个FL应用共享一个集中式参数服务器不同，Totoro+为每个应用分配一个专用参数服务器。任何边缘节点都可以充当任何应用的协调者、聚合器、客户端选择器、工作者（参与设备）或上述角色的任意组合，从而从根本上提高了可扩展性和自适应性。Totoro+引入了三项创新来实现其设计：一种位置感知的P2P多环结构、基于发布/订阅的森林抽象，以及一个有保证的ε-近似纳什均衡的博弈论路径规划模型。在500个Amazon EC2服务器上的真实实验表明，Totoro+能够随着FL应用数量优雅地扩展，N个边缘节点将总训练时间加速了1.2倍至14.0倍，在拥有数百万节点的情况下实现模型传播和梯度聚合的O(log N)跳数，并能高效适应实际的边缘网络和动态变化。

## Abstract
Federated Learning (FL) is an emerging distributed machine learning (ML) technique that enables in-situ model training and inference on decentralized edge devices. We propose Totoro$^+$, a novel scalable FL system that enables massive FL applications to run simultaneously on edge networks. The key insight is to explore a distributed hash table (DHT)-based peer-to-peer (P2P) model to re-architect the centralized FL system design into a fully decentralized one. In contrast to previous studies where many FL applications shared one centralized parameter server, Totoro$^+$ assigns a dedicated parameter server to each application. Any edge node can act as any application's coordinator, aggregator, client selector, worker (participant device), or any combination of the above, thereby radically improving scalability and adaptivity. Totoro$^+$ introduces three innovations to realize its design: a locality-aware P2P multi-ring structure, a publish/subscribe-based forest abstraction, and a game-theoretic path planning model with a guarantee of an $ε$-approximate Nash equilibrium. Real-world experiments on 500 Amazon EC2 servers show that Totoro$^+$ scales gracefully with the number of FL applications and $N$ edge nodes speeds up the total training time by $1.2\times-14.0\times$, achieves $\mathcal{O}(\log N)$ hops for model dissemination and gradient aggregation with millions of nodes, and efficiently adapts to the practical edge networks and churns.

- **核心问题**：现有主流FL系统（如Google FL框架, Meta的PAPAYA）普遍采用集中式或层级化的“单主/多从”架构。
    - **可扩展性差**：单个逻辑协调器处理所有应用的任务分配、客户端选择，在百万级节点和数千并发应用的边缘场景中成为瓶颈。不同边缘供应商之间缺乏全局视图，任务分配不均。
    - **适应性不足**：固定、静态的参数服务器分配方式无法快速适应边缘网络的动态变化，如不可靠链路、带宽波动、节点频繁加入/退出等，且边缘节点资源有限，无法通过过度配置来应对。
- **整体含义**：`Totoro+` 旨在完全打破中心化架构，提出一个原生去中心化的FL引擎，使系统能够优雅、高效地扩展，以支持大规模并发FL应用，并自主适应边缘网络的内在动态性。

### 2. 方法论

论文提出了一种基于分布式哈希表的完全去中心化对等架构，核心思想是“**多主/多从**”，其设计包含三个层次结构和三个关键创新：

- **第一层：位置感知的P2P多环结构**
    - 所有边缘节点通过DHT（Pastry）自组织成P2P覆盖网络。每个节点有唯一128位ID，保证任意数据在`O(log N)`跳内路由。
    - **多环划分**：为防止单环过大，基于网络往返时间将一个大环逻辑划分为多个更小的、位置感知的“多环”，每个环代表一个“边缘区域”。
    - **管理隔离**：节点ID的设计包含区域前缀和区域内后缀。路由表被分成两级，使管理员能基于区域ID前缀控制数据流，防止特定FL任务的数据流出指定边缘站点，保证隐私和合规性。

- **第二层：基于发布/订阅的森林抽象**
    - **应用级数据流树**：为每个FL应用动态构建独立的数据流树（Dataflow Tree）。使用应用名的哈希值`AppId`作为DHT键，路由`JOIN`消息。消息最终汇聚到的节点即为该应用树的根节点（主节点），消息路径的并集构成树的结构。不同应用分布在不同树上，实现负载均衡。
    - **角色动态化**：任何边缘节点都可以成为一个或多个FL应用的协调器、聚合器、客户端选择器或工作者，职责根据其位置是根、内部还是叶节点来分配。
    - **发布/订阅协议**：主节点是发布者，工作者是订阅者。模型通过树从根发布到叶，梯度从叶逐级聚合到根。由于DHT特性，此过程保证`O(log N)`跳内完成。
    - **广告-发现树**：引入一个独立的AD树（AD Tree）。所有应用的主节点向此树订阅并发布其`AppId`，为新加入或需要切换应用的节点提供应用目录服务。

- **第三层：博弈论路径规划模型**
    - **问题建模**：将数据流树中多节点选择下一跳路径的问题，形式化为**带有强盗反馈的拥堵博弈**。`N`个节点竞争`P`条路径，奖励（数据率/成功率）随选择同一条路径的节点数量增加而降低。
    - **算法**：提出一种去中心化的逐跳路由算法。每个节点独立维护一个对路径选择的策略。算法在每个episode内，使用当前策略发送`τ`个数据包以观察奖励，然后利用线性回归估计从策略到“潜力函数”的梯度，结合弗兰克-沃尔夫方法更新策略，并混合一个探索性策略以平衡探索和利用。
    - **理论保证**：证明了该算法在`T`个数据包总传输时间下的**纳什遗憾**是`Õ(N²T⁵/⁶ log N)`的次线性关系，并能达到**ε-近似纳什均衡**。时间复杂度为每个节点每episode的`O(τ log³ N + |Δ(Pn)| log³ N)`。
    - **故障恢复**：工作者节点故障由其子节点通过绕开故障父节点来恢复；主节点故障则通过复制训练状态到邻近节点，由子节点发现故障后定位新的主节点并从副本恢复。

- **架构创新性强**：基于DHT实现了原生的去中心化FL架构，从根本上解决了中心化瓶颈，设计思路清晰且具开创性。
- **理论与系统结合紧密**：不仅给出了完整的系统实现，还对核心的路径规划问题提供了严谨的博弈论建模和理论证明（纳什均衡、遗憾界、时间复杂度），具有很高的学术价值。
- **实验评估极其全面**：评估体系覆盖了可扩展性、效率、自适应性、容错和异构资源支持，实验规模大（500台服务器），对比了有监督和无监督的多种方法，结论极具说服力。
- **考虑了现实约束**：位置感知多环和管理隔离的设计，使其更能适应现实中多方运营商和隐私法规的要求。

### 8. 不足与局限

- **实验环境限制**：虽然模拟了10万节点，但仍在500台物理服务器上通过多JVM模拟，缺乏在真实数十万级异构物理设备（如手机、IoT设备）上的部署验证。
- **拜占庭容错缺失**：论文的故障恢复主要针对掉线/崩溃故障，未深入讨论如何处理恶意节点（如投毒攻击），在开放的P2P网络中这是一个潜在风险。
- **AD树安全问题**：文中在讨论部分提到广告-发现树可能被恶意节点攻击，并提议使用证书颁发机构进行验证，但这套安全机制并未被实现和评估。
- **非IID数据处理依赖应用层**：系统不直接处理非独立同分布数据的问题，而是将自定义机制（如客户端选择、个性化算法）的决策权交给应用开发者，虽然灵活但对开发者能力要求较高。
- **组播支持缺失**：当前的路径规划算法按单播设计，虽然论文在讨论中给出了组播扩展的算法草案，但未评估其性能和理论界。
