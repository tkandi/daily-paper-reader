## 摘要
流水线并行对于大规模模型训练至关重要，但现有的异步方法常因前向和后向传播之间的参数不匹配而损害收敛性。我们提出异步多向流水线并行（AMDP）以缓解此问题，同时保持高利用率。AMDP限制每个流水线的第一阶段在反向传播前最多处理两个小批量，从而限制了前向和后向传播之间的参数更新次数。为了缓解由此产生的流水线气泡，AMDP启动多个并发流水线，并根据流水线深度调整其数量。此外，AMDP在多个小批量上累积梯度，并在单次更新中应用它们，确保只有有限数量的小批量经历参数不匹配，且限制在一个优化步之内。在GPT和BERT风格模型上的实验表明，AMDP显著加速训练，同时保持收敛性。

## Abstract
Pipeline parallelism is essential for large-scale model training, but existing asynchronous approaches often degrade convergence due to parameter mismatch between forward and backward passes. We propose Asynchronous Multi-Directional Pipeline parallelism (AMDP) to mitigate this issue while sustaining high utilization. AMDP limits the first stage of each pipeline to process at most two minibatches before backpropagation, bounding the number of parameter updates between forward and backward passes. To alleviate the resulting pipeline bubbles, AMDP launches multiple concurrent pipelines and adapts their number according to pipeline depth. In addition, AMDP accumulates gradients across minibatches and applies them in a single update, ensuring that only a bounded number of minibatches experience parameter mismatch, limited to within one optimization step. Experiments on GPT- and BERT-style models demonstrate that AMDP significantly accelerates training while preserving convergence.

### 1. 论文的核心问题与整体含义（研究动机和背景）
- 流水线并行是训练大规模模型（如GPT-3）的必要手段，但传统的同步流水线并行存在流水线气泡，导致GPU利用率低。
- 异步流水线并行能消除气泡，却因前向传播与反向传播之间发生参数更新而引入“参数不匹配”，严重损害模型收敛性。
- 现有异步方法（如PipeDream的参数暂存、XPipe的参数预测）虽试图缓解不匹配，但要么引入延迟梯度，要么预测精度有限，且不匹配程度随流水线深度增加而加剧。
- **核心问题**：如何在保持高硬件利用率（消除气泡）的前提下，有效控制异步流水线并行中的参数不匹配，以维持近乎同步优化的收敛稳定性。

### 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程
AMDP 通过四个相互关联的组件系统性地解决上述问题：

- **参数不匹配结构控制（核心理论保证）**
  - 限制每个流水线的**第一阶段（Stage 0）最多读取 2 个微批次（minibatch）**，然后立即启动反向传播。
  - 通过**引理 3.1** 证明：在所有流水线阶段，参数不匹配（前向与反向之间发生的参数更新次数）≤ 1（即最多一个优化步）。
  - 配套提出 **定理 3.2**，证明在 `τ(t) ≤ 1` 的严格界限下，AMDP 的收敛行为与同步 SGD 仅差一个二阶扰动项 `O(η^2)`，从而在理论上保证收敛稳定性。

- **多向流水线调度（消除气泡）**
  - 为弥补 “Stage 0 仅读 2 个微批次” 带来的气泡，AMDP 启动多个**方向互补的并发流水线**，其数量设为 `d/2`（`d` 为流水线深度），使活跃槽位重叠以填充空闲。
  - 采用类似 Chimera 的方向映射规则：偶数编号流水线正向遍历 GPU，奇数编号则反向遍历。
  - 通过 FIFO 规则解决多流水线在同一 GPU 上因前 / 反向计算耗时不对称造成的冲突。
  - 利用**预加载微批次**的方式，消除在每个 `d` 个小批次边界处产生的头尾气泡。

- **梯度累积更新策略（降低通信并收紧不匹配窗口）**
  - 不在每次反向传播后立即进行全局规约（all-reduce）及参数更新，而是**累积多个微批次的梯度，待达到预设阈值后再执行一次统一更新**。
  - 该策略将参数更新的影响限制在积累窗口内：只有窗口内的前 `d` 个微批次会经历≤1 步的参数不匹配，后续微批次使用完全一致的参数。
  - 实际阈值通常远大于 `d`，使得不匹配的影响可忽略不计，同时大幅降低了通信频率。

- **零冗余优化器（ZeRO）集成**
  - 针对多流水线部署导致的内存冗余，将优化器状态（如 Adam 的动量和方差）**仅存储于各阶段对应的“所有者” GPU 上**。
  - 更新时，各副本 GPU 将梯度发送给所有者 GPU 进行规约和参数更新，然后将新参数广播回副本。这消除了多流水线复制优化器状态带来的内存压力，且通信模式（reduce + broadcast）总开销与 all-reduce 等同。
