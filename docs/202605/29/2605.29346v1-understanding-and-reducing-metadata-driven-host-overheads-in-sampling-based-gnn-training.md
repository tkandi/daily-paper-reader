## 摘要
现代深度学习工作负载越来越表现出动态、元数据驱动的执行特征，其中运行时生成的信息决定内存供应和内核启动决策。在基于采样的图神经网络（GNN）训练中，这种行为将CPU置于关键路径上，引入持续的主机-设备协调开销和频繁的GPU-CPU同步，当GPU计算量较小时，这些开销主导了端到端运行时间。现有方法，包括CUDA图和GPU动态并行，无法解决此问题，因为元数据驱动的控制环路仍由主机中介，且执行结构在不同迭代间变化。我们提出ZEROGNN，该系统将主机从元数据驱动的控制环路中移除，并实现在动态行为下的完全GPU驻留执行。ZEROGNN将运行时元数据保留在设备上，在固定的启动结构中调解动态执行，并提供一个保守但紧凑的执行范围以恢复CUDA图的可重放性。在基于采样的GNN工作负载上的实验表明，ZEROGNN实现了高达5.28倍的端到端加速、接近100%的GPU执行比例，以及与理想元数据知情分配相当的内存效率，同时通过消除主机侧瓶颈实现强大的多GPU扩展。

## Abstract
Modern deep learning workloads increasingly exhibit dynamic, metadata-driven execution, where runtime-generated information determines memory provisioning and kernel launch decisions. In sampling-based graph neural network (GNN) training, this behavior places the CPU on the critical path, introducing persistent host-device orchestration overhead and frequent GPU-CPU synchronization, which dominate end-to-end runtime when GPU computation is small. Existing approaches, including CUDA Graphs and GPU dynamic parallelism, fail to address this problem because the metadata-driven control loop remains host-mediated, and execution structure varies across iterations. We present ZEROGNN, a system that removes the host from the metadata-driven control loop and enables fully GPU-resident execution under dynamic behavior. ZEROGNN keeps runtime metadata on-device, mediates dynamic execution within a fixed launch structure, and provisions a conservative yet tight execution envelope to restore CUDA Graph replayability. Experiments on sampling-based GNN workloads show that ZEROGNN achieves up to 5.28 x end-to-end speedup, near 100% GPU execution fraction, and memory efficiency comparable to ideal metadata-informed allocation, while enabling strong multi-GPU scaling by eliminating host-side bottlenecks.

### 1. 论文的核心问题与整体含义（研究动机和背景）

现代深度学习工作负载，特别是基于采样的图神经网络（GNN）训练，其执行过程表现出显著的动态性和元数据驱动特征。每次迭代中，GPU生成的运行时元数据（如采样子图的顶点/边数量）需要立即传回CPU，以决定后续的内存分配和内核启动参数。该过程导致了两个核心瓶颈：

*   **主机-设备协调开销**：CPU频繁介入GPU的执行环路，在关键路径上引入了大量的内核启动、同步和内存供应决策开销。
*   **主机中介的依赖屏障**：GPU必须等待CPU根据元数据做出决策后，才能执行后续步骤，反之亦然。这破坏了计算与通信的重叠机会，使得GPU执行无法连续，利用率低下。

当GPU计算量较小时（例如小批量或小图上），这些主机侧开销成为端到端性能的绝对主导，使得传统GPU优化和CUDA图技术失效。因此，本文的核心问题是：**如何完全消除元数据驱动动态工作负载中的主机-设备协调开销和依赖屏障，实现纯粹的GPU端自主执行**。

### 2. 论文提出的方法论：核心思想、关键技术细节

ZEROGNN的核心思想是**将主机从元数据驱动的控制环路中完全移除**，通过三项关键技术将动态执行过程封装在一个可由GPU独立、可重复执行的静态结构中。

*   **设备驻留元数据缓冲区**：
    *   **核心思想**：通过内存间接寻址，将运行时产生的元数据（如`|V|`, `|E|`）保存在GPU预分配的固定地址中，供下游内核直接通过设备指针读取。
    *   **效果**：将元数据依赖从“GPU→CPU→GPU”的往返，转变为纯粹的“GPU→GPU”依赖，从根本上消除了主机中介的依赖屏障。

*   **设备侧启动中介**：
    *   **核心问题**：由于元数据不再传回CPU，主机无法获得精确的运行时尺寸来决定内核的启动网格大小或调用次数。
    *   **解决方案**：
        1.  **统一机制**：主机始终使用一个由分发器提供的**保守上界**来启动内核，形成一个**可捕获的固定启动骨架**。
        2.  **设备侧特化**：内核执行时，直接从DRMB读取真实的运行时尺寸。对于超量配置的线程块，通过边界检查和提前退出来实现空操作，不影响功能。
            *   **对于动态内核调用次数**（如循环/递归原语）：DLM将主机侧调度固定，由GPU内部状态决定是否需要继续执行，避免元数据导出。
    *   **效果**：在设备侧调解了内核启动的动态性，同时保持了主机启动结构的静态性和可重放性。

*   **无元数据分发器**：
    *   **核心问题**：如何在主机不知道精确大小时，为采样子图等动态数据结构安全且高效地预分配内存。
    *   **核心思想**：利用“去重后的采样子图大小在多次迭代中高度稳定”这一统计特性。
    *   **理论依据（Lemma 4.1）**：证明去重后的采样大小`|V_d|`近似服从泊松-二项分布，并可进一步近似为正态分布，其波动范围（变异系数）非常小。
    *   **技术实现**：
        1.  **分发执行包络**：基于该统计上界，MFD在初始化时一次性分配一个**保守但紧凑**的固定执行包络，规定好所有动态缓冲区的内存容量上限和内核启动的资源上限。
        2.  **确定性安全兜底**：对于极少数超越包络上限的迭代，ZERO GNN会**重放一个预缓存的“安全图”**（这等同于再次执行相同批次的计算），以确保内存绝对安全，且不影响训练正确性。
    *   **效果**：在没有主机介入和极大内存浪费的条件下，实现了静态、可重放的内存供应，恢复了CUDA图的地址稳定性要求。

最终，这三项技术共同作用，使得ZEROGNN可以将一次典型的训练迭代（预热后）捕获进CUDA图，并在后续迭代中直接重放，从而彻底消除重复的主机侧协调开销。
