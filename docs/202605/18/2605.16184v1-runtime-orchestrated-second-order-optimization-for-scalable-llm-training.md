## 摘要
二阶方法为实现更高样本效率的大语言模型（LLM）训练提供了一条极具吸引力的路径，但其实际应用往往受限于维护和更新大型基于矩阵的优化器状态所带来的系统开销。我们推出了 Asteria，这是一个旨在通过将二阶优化逻辑从关键 GPU 训练路径中分离出来，从而消除这一瓶颈的运行时系统。Asteria 并非将所有预处理器状态都保留在加速器上，而是根据架构限制和运行时压力，将优化器状态动态分布在 GPU 显存、CPU 内存和可选的 NVMe 存储中。它还利用训练钩子提前准备影子状态，允许昂贵的逆平方根计算在主机上异步进行，而 GPU 计算则继续执行。对于分布式训练，Asteria 采用了一种有界陈旧度协议，在限制同步频率的同时，通过拓扑感知协调来保持优化器的有效性。我们在内存受限和分布式训练设置下对 Asteria 进行了评估。在配备单个 GB10 GPU 和 128GB 统一内存的 DGX Spark 平台上，Asteria 支持对 10 亿参数语言模型进行二阶训练。在多节点 GH200 系统上，它降低了可见的优化器开销，减少了周期性的延迟峰值，加速了实际时间（wall-clock time）收敛，并在 70 亿参数语言模型中保持了 SOAP 和 KL-Shampoo 的优化优势。我们的结果表明，要使二阶 LLM 训练变得实用，不仅需要简化优化器本身，更需要从运行时层面重新思考如何管理优化器状态、后台计算和分布式同步。

## Abstract
Second-order methods offer an attractive path toward more sample-efficient LLM training, but their practical use is often blocked by the systems cost of maintaining and updating large matrix-based optimizer states. We introduce \textbf{Asteria}, a runtime system designed to remove this bottleneck by separating second-order optimization logic from the critical GPU training path. Rather than keeping all preconditioner state on the accelerator, Asteria dynamically distributes optimizer state across GPU memory, CPU memory, and optional NVMe storage according to architectural constraints and runtime pressure. It further uses training hooks to prepare shadow states in advance, allowing expensive inverse-root computations to proceed asynchronously on the host while GPU computation continues. For distributed training, Asteria employs a bounded-staleness protocol that limits synchronization frequency while preserving optimizer effectiveness through topology-aware coordination.   We evaluate Asteria on both memory-constrained and distributed training settings. On a DGX Spark platform with a single GB10 GPU and 128GB unified memory, Asteria supports second-order training for a 1B-parameter language model. On multi-node GH200 systems, it lowers visible optimizer overhead, reduces recurring latency spikes, accelerates convergence in wall-clock time, and maintains the optimization advantages of SOAP and KL-Shampoo in a 7B-parameter language model. Our results suggest that second-order LLM training can be made practical not by simplifying the optimizer alone, but by rethinking how optimizer state, background computation, and distributed synchronization are managed at the runtime level.

### 1. 核心问题与研究动机
*   **背景：** 当前 LLM 训练主流使用 AdamW 等一阶优化器，虽然扩展性好，但统计效率低，需要消耗海量 Token 才能收敛。二阶优化方法通过利用损失函数的曲率信息（如海森矩阵的近似），能显著加快收敛速度。
*   **核心瓶颈（“三道墙”）：**
    1.  **垂直容量墙：** 二阶优化器状态（协方差矩阵及其逆平方根）极其庞大（$O(N^2)$ 空间复杂度），极易导致显存溢出（OOM），尤其在单卡或资源受限环境下。
    2.  **重叠中断墙：** 矩阵逆平方根计算具有 $O(d^3)$ 的高计算复杂度，会产生周期性的延迟峰值，中断 GPU 的计算-通信流水线。
    3.  **全局共识墙：** 现有的分布式二阶方法要求所有节点严格同步状态，无法利用异构网络拓扑或容忍一定的陈旧度。

### 2. 方法论：Asteria 核心技术
Asteria 的核心思想是将二阶优化的逻辑从 GPU 训练的关键路径中解耦，通过运行时编排实现高效管理：
*   **架构自适应的非对称内存分层：** 将优化器状态按生命周期分布。Kronecker 因子（更新频繁）保留在 GPU；逆因子状态存放在 CPU 内存或 NVMe 存储中。利用统一虚拟内存（UVM）技术减少冗余的数据拷贝。
*   **钩子编排的影子状态流水线（Hook-Orchestrated Pipeline）：** 利用 PyTorch FSDP 的前向/后向钩子（Hooks）作为调度信号。当 GPU 进行正常的计算时，Asteria 在后台 CPU 线程池中异步执行昂贵的矩阵逆平方根运算，并通过影子流（Shadow Stream）提前预取状态。
*   **拓扑感知的有界陈旧度一致性协议：** 放弃全局强一致性同步，改为跟踪每个块的“新鲜度”。只有当陈旧度超过预设阈值时，才通过主机侧（Host-side）通信组进行分层同步（先节点内再节点间），大幅减少通信量。

*   **客观性：** 实验不仅关注收敛速度，还引入了硬件层面的能量消耗分析，对比了二阶方法带来的额外开销与收益，评估较为全面、公平。

### 6. 主要结论与发现
*   **消除延迟峰值：** Asteria 成功抹平了原生二阶优化器每隔 10 步出现的巨大延迟峰值，使训练节奏接近一阶优化器。
*   **提升收敛效率：** 在相同的时间内，Asteria 变体比 AdamW 和原生二阶方法达到更低的损失值。
*   **能量效率优势：** 尽管 CPU 异步计算增加了主机功耗，但由于缩短了 GPU 的空闲等待时间，Asteria 在“单位能量损失减少量”这一指标上优于 AdamW。
*   **内存突破：** 在仅有 128GB 内存的单卡系统上，Asteria 成功支持了 1B 参数模型的二阶训练，而原生方法会因 OOM 失败。

### 7. 优点
*   **系统级解耦：** 这种不改变优化器数学逻辑、仅通过运行时编排优化的思路具有很强的通用性。
*   **硬件协同设计：** 充分利用了现代架构（如 GH200/GB10）的统一内存特性和 NVMe 存储。
*   **端到端优化：** 实验不仅停留在算法层面，还深入到了内核驱动、内存回收（madvise）和 I/O 调度（io_uring）。

### 8. 不足与局限
*   **硬件依赖：** 实验高度依赖具有高速 NVLink 或统一内存架构的 NVIDIA 平台（如 GH200），在 PCIe 带宽受限的普通消费级 GPU 集群上的表现尚未充分验证。
*   **并行模式覆盖：** 目前主要针对 FSDP（数据并行），对于张量并行（TP）或流水线并行（PP）等更复杂的混合并行模式，其钩子调度逻辑可能需要进一步适配。
*   **陈旧度风险：** 虽然实验显示陈旧度对 OLMo 模型影响较小，但对于极大规模或对曲率极其敏感的任务，异步更新可能引入潜在的不稳定性。
