## 摘要
静态图大语言模型（LLM）解码器提供了可预测的启动、固定的张量形状以及较低的提交开销，但在线解码表现出高度不规则的 KV 缓存行为：请求长度各异、EOS 事件异步到达，且逻辑历史记录随时间而碎片化。动态运行时通过分页 KV 管理和步级调度恢复了灵活性，而静态图执行器通常会过度预留内存，并面临突发性的延迟离群值。本文研究了是否可以在固定的解码接口之下吸收大部分这种变异性。我们提出了 KV-RM，这是一种在静态图 LLM 解码器之下规范化 KV 缓存移动的运行时设计。KV-RM 将逻辑 KV 历史记录与物理存储解耦，通过块分页器跟踪活跃的 KV 状态，并通过单个提交描述符实现每个解码步骤。在固定形状的注意力内核消耗数据之前，合并阶段传输路径将非连续的 KV 映射合并为少量的大型传输组。在同一接口下可以启用可选的有界远期历史摘要，但核心设计并不依赖于它们。在双 GPU NVIDIA A100 节点上，相对于静态图基准，KV-RM 提高了混合长度解码的吞吐量并降低了尾部延迟，减少了各类工作负载中的预留 KV 内存，并消除了生产轨迹回放下的严重突发延迟峰值。这些结果表明，KV 缓存移动而非内核形状，可以作为在静态图 LLM 推理中恢复运行时灵活性的有效边界。

## Abstract
Static-graph LLM decoders provide predictable launches, fixed tensor shapes, and low submission overhead, but online decoding exposes highly irregular KV-cache behavior: request lengths differ, EOS events arrive asynchronously, and logical histories fragment over time. Dynamic runtimes recover flexibility through paged KV management and step-level scheduling, while static-graph executors often over-reserve memory and suffer burst-time latency outliers. This paper studies whether much of this variability can be absorbed below a fixed decode interface. We present KV-RM, a runtime design that regularizes KV-cache movement beneath a static-graph LLM decoder. KV-RM decouples logical KV histories from physical storage, tracks active KV state through a block pager, and materializes each decode step through a single committed descriptor. A merge-staged transport path coalesces non-contiguous KV mappings into a small number of large transfer groups before a fixed-shape attention kernel consumes them. Optional bounded far-history summaries can be enabled under the same interface, but the core design does not depend on them. On a 2-GPU NVIDIA A100 node, KV-RM improves mixed-length decoding throughput and tail latency relative to a static-graph baseline, reduces reserved KV memory across workload families, and removes severe burst-time latency spikes under production-trace replay. These results suggest that KV-cache movement, rather than kernel shape, can be an effective boundary for recovering runtime flexibility in static-graph LLM serving.

#### 1. 核心问题与整体含义（研究动机和背景）
现代 GPU 推理栈在处理在线解码时面临结构性矛盾：
*   **静态图执行器（如 TensorRT-LLM）：** 提供可预测的启动、固定张量形状和低提交开销，但在处理长度不一、异步结束（EOS）的请求时，往往需要过度预留内存（Idle Memory Floor），且在处理混合长度请求时容易出现延迟抖动和吞吐量下降。
*   **动态运行时（如 vLLM）：** 通过分页 KV 管理和步级调度恢复了灵活性，但代价是访问碎片化以及更复杂的宿主机/运行时交互。
*   **核心问题：** 能否在保持静态图解码接口（固定形状、低开销）的同时，吸收在线解码的不规则性？论文提出了 **KV-RM**，旨在通过规范化内核下层的 KV 缓存移动来解决这一矛盾。

#### 2. 论文提出的方法论
KV-RM 的核心思想是**将灵活性从内核形状转移到描述符传输接口（Descriptor Transport Interface）**。

*   **核心机制：**
    1.  **静态滑动内核（Static Sliding Kernel）：** 编译一次，具有固定的近窗宽度 $W^*$，不随运行时改变形状。
    2.  **KV 分页器（KV Pager）：** 将逻辑 KV 历史与物理存储解耦。提供四种原语：`Reserve`（分配）、`Alias`（前缀共享）、`Trim`（回收 EOS 或冷块）、`Frame`（原子提交映射修改）。
    3.  **合并阶段传输（Merge-Staged Transport）：** 针对分页导致的非连续映射，在 DMA 传输前将碎片化的描述符合并为少量的大型传输组（DMA Trains），确保传输效率。
    4.  **可选的远景摘要（Far-View Summarization）：** 在固定预算内，通过对远期历史进行均匀聚合，提供长文本支持，而无需改变内核接口。
*   **系统不变性：** 保持固定执行形状、每步仅单次描述符提交、有界的控制面开销。

#### 7. 优点
*   **接口优雅：** 在不改变底层计算内核和编译器逻辑的前提下，通过运行时映射管理解决了静态图的僵化问题。
*   **传输正则化：** 敏锐地捕捉到分页带来的 DMA 碎片化问题，并提出合并策略，这在以往研究中常被忽视。
*   **高兼容性：** 能够无缝集成到现有的静态图执行栈（如 TensorRT-LLM 或 IPU 栈）中。

#### 8. 不足与局限
*   **单节点限制：** 实验主要集中在单节点双 GPU 环境，未深入探讨多节点分布式推理或远程 KV 缓存卸载的影响。
*   **质量权衡：** 可选的远景摘要虽然节省了带宽，但本质上是有损压缩，对于极度依赖长程精确信息的任务可能存在精度风险。
*   **应用范围：** 如果部署环境已经完全转向动态运行时且对控制面开销不敏感，KV-RM 的边际收益会减小。
