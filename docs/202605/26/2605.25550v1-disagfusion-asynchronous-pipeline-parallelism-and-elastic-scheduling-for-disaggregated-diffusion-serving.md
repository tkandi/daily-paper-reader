## 摘要
基于扩散的生成正日益支撑生产内容管线，然而大规模部署这些模型仍是一个重大挑战。模型权重常常超出商品GPU的内存容量，而编码器、扩散变换器（DiT）和解码器阶段的计算与内存占用高度不平衡。一种自然的解决方案是解聚服务——在异构GPU上将各阶段作为单独服务运行——但这引入了新的瓶颈，包括阶段交接开销和快速变化的工作负载，使得跨阶段供应和调度变得脆弱。本文提出DisagFusion，为解聚扩散服务实现异步流水线并行和弹性调度。首先，DisagFusion引入异步流水线并行，通过重叠计算与阶段间通信来减少流水线气泡并缓解网络抖动。其次，DisagFusion采用混合实例调度策略，结合轻量级性能预测与运行时反馈，在工作负载变化下持续重新平衡各阶段的实例比例。我们实现了DisagFusion并用现代扩散模型对其进行了评估。与单体基线相比，DisagFusion将吞吐量提高了3.4倍至20.5倍，将端到端延迟降低了18.5倍，同时能够跨异构GPU实现灵活且成本高效的部署。

## Abstract
Diffusion-based generation is increasingly powering production content pipelines; however, deploying these models at scale remains a significant challenge. Model weights frequently exceed the memory capacity of commodity GPUs, while the encoder, diffusion transformer (DiT), and decoder stages exhibit highly imbalanced computational and memory footprints. A natural remedy is disaggregated serving-running stages as separate services on heterogeneous GPUs-yet this introduces new bottlenecks, including stage handoff overheads and fast-changing workloads that make cross-stage provisioning and scheduling brittle.   This paper presents DisagFusion, enabling asynchronous pipeline parallelism and elastic scheduling for disaggregated diffusion serving. First, DisagFusion introduces asynchronous pipeline parallelism that overlaps computation and stage-to-stage communication to reduce pipeline bubbles and mitigate network jitter. Second, DisagFusion employs a hybrid instance scheduling strategy that combines lightweight performance prediction with runtime feedback to continuously rebalance instance ratio across stages under workload shifts. We implement DisagFusion and evaluate it with modern diffusion models. Compared to a monolithic baseline, DisagFusion improves throughput by 3.4x-20.5x and reduces end-to-end latency by 18.5x, while enabling flexible, cost-efficient deployment across heterogeneous GPUs.

### 1. 核心问题与整体含义 (研究动机和背景)

*   **核心问题**：当前扩散模型（如Stable Diffusion, Wan等）在部署时面临两大挑战：
    *   **模型权重过大**：模型参数量（如Qwen-2512达58.1GB）远超单张消费级甚至专业级GPU的显存容量（如24GB, 80GB），导致无法完整加载，需要频繁在主存和显存间进行数据交换，严重拖慢推理速度。
    *   **阶段负载高度不平衡**：扩散模型天然包含编码器（Encoder）、去噪变换器（DiT）、解码器（Decoder）三个阶段。它们的计算密度和内存占用差异巨大，DiT是计算瓶颈，而编码器和解码器则相对轻量。在单卡上串行执行导致计算资源（GPU）利用率低下。

*   **解决思路与整体含义**：一种自然的解决思路是“解聚服务（Disaggregated Serving）”，即将三个阶段拆分为独立的服务，并部署在不同（可能异构的）GPU上。
*   **解聚带来的新挑战**：
    1.  **网络成为瓶颈**：阶段间需要传输大规模中间张量，网络延迟和抖动会导致GPU空等，产生“流水线气泡”，显著降低吞吐量。
    2.  **工作负载动态变化**：请求量（峰谷比可达2.2倍）、请求参数（如去噪步数、输出分辨率）随时变化，导致各阶段的执行时间比例动态改变。例如，50步推理下DiT占主导，而1步推理下各阶段耗时比例完全不同。固定的阶段实例配比无法在所有负载下保持最优吞吐。

*   **整体含义**：本文提出的DisagFusion旨在解决解聚架构带来的上述新瓶颈，通过异步流水线并行和弹性调度，实现扩散模型服务的高吞吐、低延迟和成本效益。

### 2. 方法论 (核心思想、关键技术细节、算法流程)

DisagFusion系统从两个层面协同设计以解决解聚服务的核心挑战。

*   **异步流水线并行 (Asynchronous Pipeline Parallelism)**
    *   **核心思想**：通过解耦各阶段的计算与通信，实现两者的并发执行，从而消除因同步等待通信完成而产生的“流水线气泡”。
    *   **技术细节**：
        *   **生产者-消费者模型**：每个阶段既是上游的消费者，也是下游的生产者。阶段间通过异步队列（基于RDMA的环形缓冲区）传递任务元数据，而大规模张量数据则通过专用的高性能传输引擎（Mooncake Transfer Engine）直接传输。
        *   **去中心化调度**：请求通过在各个阶段间流转的元数据进行协调，无需中心节点介入，避免了单点瓶颈和全局锁争用。
        *   **计算-通信重叠**：当一个请求正在某个阶段（如编码器）执行计算时，它可以将已完成请求的结果异步发送给下一个阶段（如Transformer），同时开始处理新请求。这样，通信延迟被隐藏在计算时间之后。
        *   **抗网络抖动**：当网络出现短暂延迟时，异步队列可以起到缓冲作用，避免上游阶段立刻停摆，因此吞吐量受网络抖动的影响远小于同步模式。

*   **混合策略实例调度 (Hybrid-Strategy Instance Scheduling)**
    *   **核心思想**：结合基于模型的**主动式性能预测**和基于监测的**被动式运行时反馈**，动态调整三个阶段（Encoder, Transformer, Decoder）的实例数量配比，以适应动态变化的工作负载。
    *   **性能模型**：系统维护一个公式模型 `QPS = min(g_E/T_E, g_T/T_T, g_D/T_D)`，表明端到端吞吐取决于最慢（瓶颈）阶段的服务速率。调度的目标是使得 `g_E/T_E ≈ g_T/T_T ≈ g_D/T_D`，避免任何一个阶段成为瓶颈。
    *   **算法流程 (Algorithm 1)**：
        1.  **监测**：以一个固定的时间间隔（默认2秒）持续收集各阶段服务的GPU利用率、队列长度和平均排队延迟。
        2.  **主动预测**：当检测到工作负载模式发生显著变化时（例如，请求参数变化），利用一个预先训练的预测器 `ĝ(·)` 根据近期负载特征直接估算出最佳的实例配比 `(ˆn_E, ˆn_T, ˆn_D)`，并主动调整。
        3.  **被动反馈**：如果没有检测到明显的模式变化，则根据实时监控指标进行**响应式调整**。
            *   **缩容 (Scale-In)**：当某个服务的GPU利用率低于阈值（默认20%）且队列为空时，回收空闲实例。
            *   **扩容 (Scale-Out)**：当某个服务的GPU利用率饱和（>80%）、队列持续增长、且排队延迟上升时，为该阶段增加实例。
