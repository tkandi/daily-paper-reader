## 摘要
在大规模 GPU 集群上预训练大语言模型已使硬件故障成为常态而非罕见现象，这推动了对弹性训练系统的需求。然而，现有框架要么专注于特定的并行方案，要么面临偏离无故障训练轨迹的风险。我们提出了 ReCoVer，一个弹性大语言模型预训练系统，它遵循一个单一的不变量：每次迭代保持微批次（microbatch）数量恒定，确保每次迭代的梯度在随机性上等同于无故障运行。该框架由三个解耦的协议层组成：（1）容错集合通信，隔离故障以防其在副本间传播；（2）步内细粒度恢复，保留迭代内的进度并防止梯度损坏；（3）多变负载策略，在存活节点间动态重新分配微批次配额。该设计与并行方式无关，可作为底层基座直接与 3D 并行和混合分片数据并行（HSDP）集成。我们在多达 512 个 GPU 的端到端预训练任务上评估了我们的实现，尽管在运行过程中损失了分布在各处的 256 个 GPU，ReCoVer 仍成功保持了与无故障参考一致的训练轨迹。与检查点重启（checkpoint-and-restart）基准相比，ReCoVer 在连续故障后的有效吞吐量提高了 2.23 倍。这一优势使得 ReCoVer 在 234 个 GPU 小时内处理的 token 数量增加了 74.9%，且随着训练时间的延长，这一差距还会进一步扩大。

## Abstract
Pre-training large language models on massive GPU clusters has made hardware faults routine rather than rare, driving the need for resilient training systems. Yet existing frameworks either focus on specific parallelism schemes or risk drifting away from a failure-free training trajectory. We propose ReCoVer, a resilient LLM pre-training system that upholds a single invariant: each iteration keeps the number of microbatches constant, ensuring per-iteration gradients remain stochastically equivalent to a failure-free run. The framework is organized as three decoupled protocol layers: (1) Fault-tolerant collectives that isolate faults from propagating across replicas; (2) in-step fine-grained recovery that preserves intra-iteration progress and prevents gradient corruption; (3) versatile-workload policy that dynamically redistributes microbatch quotas across the survivors. The design is parallelism-agnostic, integrating directly with both 3D parallelism and Hybrid Sharded Data Parallel (HSDP) as a drop-in substrate. We evaluate our implementation on end-to-end pre-training tasks for up to 512 GPUs, ReCoVer successfully preserves the training trajectory from a failure-free reference despite of 256 GPUs lost spread across the run. For comparison with checkpoint-and-restart baselines, ReCoVer demonstrates $2.23\times$ higher effective throughput after successive failures. This advantage results in ReCoVer processing 74.9% more tokens at 234 GPU-hours, with the gap widening as the training prolongs.

### 论文总结：ReCoVer 弹性大语言模型预训练系统

#### 1. 核心问题与整体含义（研究动机和背景）
随着大语言模型（LLM）预训练规模扩展至 10 万级 GPU 集群，硬件故障已从“偶然”变为“常态”。在如此规模下，平均故障间隔时间（MTBF）缩短至分钟级，而传统的“检查点-重启”（Checkpoint-Restart）机制由于重新初始化、加载状态和重算丢失进度的开销巨大，导致超过 50% 的算力被浪费。
论文的核心问题在于：现有的前向恢复（Forward Recovery）方法要么与特定的并行策略（如流水线并行）深度耦合，缺乏通用性；要么在故障后减少微批次数量，导致梯度噪声尺度变化，进而引发 Loss 震荡，偏离原始训练轨迹。ReCoVer 旨在构建一个**并行无关**且能**保持训练轨迹随机等效性**的弹性预训练系统。

#### 2. 论文提出的方法论
ReCoVer 提出了一个三层解耦协议，其核心思想是维持**“迭代不变性”**：无论发生何种故障，每轮迭代提交的微批次（Microbatch）总数保持恒定。

*   **底层：容错集合通信（Fault-Tolerant Collectives）**
    基于用户级故障缓解（ULFM）原语，扩展了 PyTorch 的通信后端。它实现了 `ULFM_ALLREDUCE` 和 `ULFM_CONSENSUS`，能够在检测到 Rank 丢失时原地修复通信器并形成新的存活视图，避免整个作业崩溃。
*   **中层：步内细粒度恢复（In-Step Fine-Grained Recovery）**
    利用梯度桶（Gradient-bucket）快照机制。在梯度同步期间，如果发生故障，系统会根据“世界纪元”（World Epoch）标签识别受损梯度，并将其恢复到规约前的状态，从而保留迭代内的计算进度，无需回滚到上一个检查点。
*   **顶层：多变负载策略（Versatile-Workload Policy）**
    这是保证轨迹一致性的关键。系统将存活副本动态划分为四种角色：主要副本（Major）、次要副本（Minor）以及对应的备用副本（Spare）。当故障发生时，系统会自动重新分配微批次配额，让存活副本承担更多计算任务，以补偿丢失的算力，确保全局 Batch Size 始终不变。

*   **轨迹保真度**：ReCoVer 能够完美保持训练轨迹，即使损失了一半的 GPU，其 Loss 曲线也无明显尖峰或偏移。

#### 7. 优点
*   **数学严谨性**：通过保持全局 Batch Size 恒定，从根本上解决了前向恢复导致的训练漂移问题。
*   **通用性强**：作为解耦的协议层，可以作为“掉入式”（Drop-in）组件集成到现有的 3D 并行或 HSDP 框架中。
*   **零冗余开销**：不需要像“热备”（Hot-spare）方法那样预留空闲 GPU，所有存活资源都在进行有效计算。

#### 8. 不足与局限
*   **资源回收不完全**：目前当一个副本中的某个 Rank 故障时，该副本的其他存活 Rank 会被丢弃，未来仍有进一步回收这些“碎片算力”的空间。

*   **动态加入限制**：目前主要关注如何“活下去”，对于新节点如何动态加入（Rejoin）并恢复到初始算力规模的讨论较少。
