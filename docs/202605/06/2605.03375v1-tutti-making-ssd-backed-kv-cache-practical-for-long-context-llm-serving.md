## 摘要
LLM 服务依赖前缀缓存（prefix caching）来提高推理性能。随着上下文长度的增加，键值（KV）缓存的占用空间远超 GPU HBM 和 CPU DRAM 的容量，因此 KV 缓存越来越多地被卸载到 NVMe SSD。然而，从 SSD 恢复 KV 缓存面临 I/O 性能差和严重的 GPU 停顿问题。这主要是因为碎片化的 GPU 内存布局导致了大量微小的随机 I/O，使得低并行度的 CPU 成为严重瓶颈，即使使用 GPU Direct Storage (GDS) 也是如此，因为 GDS 仍依赖 CPU 干预来发起每次 I/O，本质上仍是以 CPU 为中心的。本文提出了 Tutti，一种高效的基于 SSD 的 KV 缓存解决方案，它消除了 HBM 与 SSD 之间关键数据和 I/O 控制路径上的 CPU 干预。Tutti 的核心是一个以 GPU 为中心的 KV 缓存对象存储，其中 CPU 仅负责每层异步加载一次 I/O 内核到 GPU。Tutti 通过以下设计使 NVMe SSD 带宽达到饱和，并将 GPU 停顿降至接近零：(i) 提供 GPU 原生对象抽象，实现批量 KV 缓存传输和管理；(ii) 通过引入 GPU io_uring 重新构建 GPU 存储栈，以支持异步 GPU 直接对象 I/O；(iii) 提出松弛感知（slack-aware）的 I/O 调度，以避免 GPU 资源竞争。我们实现了 Tutti 并将其集成到 vLLM 中。广泛的评估表明，与最先进的启用 GDS 的基于 SSD 的 LMCache 相比，Tutti 在严格的 SLO 约束下将首字延迟（TTFT）降低了 78.3%，并将可实现的请求率提高了 2 倍。服务成本降低了 27%。Tutti 实现了与基于 DRAM 的 LMCache 几乎相同的推理性能，同时提供了几乎无限的容量。

## Abstract
LLM serving relies on prefix caching to improve inference performance. As growing contexts push key-value (KV) cache footprint far beyond GPU HBM and CPU DRAM capacity, KV cache is increasingly offloaded to NVMe SSDs. Unfortunately, restoring KV cache from SSDs suffers from poor I/O performance and incurs significant GPU stalls. This is primarily because the fragmented GPU memory layout results in a massive number of tiny random I/Os, rendering the low-parallelism CPU a severe bottleneck even with GPU Direct Storage (GDS), which still relies on CPU intervention to initiate each I/O and thus remains CPU-centric. This paper presents Tutti, an efficient SSD-backed KV caching solution that eliminates CPU intervention from the critical data and I/O control paths between HBM and SSDs. At the core of Tutti is a GPU-centric KV cache object store, in which the CPU is only responsible for asynchronously loading I/O kernels once per layer to the GPU. Tutti saturates NVMe SSD bandwidth and reduces GPU stalls to near zero through the following designs: (i) we provide a GPU-native object abstraction that enables bulk KV cache transfers and management; (ii) we re-architect the GPU storage stack by introducing GPU io_uring to support asynchronous GPU direct object I/O; and (iii) we propose slack-aware I/O scheduling to avoid GPU resource contention. We have implemented Tutti and integrated it to vLLM. Extensive evaluation shows that compared to the state-of-the-art GDS-enabled, SSD-backed LMCache, Tutti reduces TTFT by 78.3% under strict SLO constraints and improves the achievable request rate by 2x. The serving cost is reduced by 27%. Tutti achieves nearly the same inference performance as DRAM-backed LMCache, while providing almost infinite capacity.

### 1. 论文的核心问题与整体含义
随着大语言模型（LLM）上下文窗口的不断扩大，KV Cache（键值缓存）的体积迅速增长，远超 GPU 显存（HBM）和系统内存（DRAM）的承载能力。虽然 NVMe SSD 提供了海量容量，但现有的 SSD 卸载方案存在严重瓶颈：
*   **CPU 中心化瓶颈：** 即使使用 NVIDIA GDS（GPU Direct Storage），I/O 的发起和控制仍依赖 CPU。在处理碎片化的 GPU 内存布局时，会产生大量微小的随机 I/O，导致 CPU 介入开销巨大。
*   **GPU 停顿（Stalls）：** 频繁的 I/O 等待导致 GPU 计算资源闲置，使得从 SSD 恢复缓存甚至比重新计算（Recomputation）还要慢。
**Tutti 的核心目标**是构建一个**以 GPU 为中心**的存储架构，彻底消除数据传输和控制路径上的 CPU 干预，使 SSD 备份的 KV 缓存性能接近 DRAM。

### 2. 论文提出的方法论
Tutti 重新设计了 GPU 存储栈，主要包含以下三个关键技术：

*   **GPU 原生对象抽象（GPU-Centric Object Store）：**
    *   将 KV 缓存管理与底层存储解耦。CPU 仅负责非关键路径上的元数据管理（如哈希索引），而将数据传输路径完全交给 GPU。
    *   引入 **P2P 内存映射表**，使用 **SGL（分散-聚集列表）** 代替传统的 PRP（物理区域页），显著减少了描述大块连续内存所需的元数据开销，提升了中等规模 KV 块的传输效率。
*   **GPU io_uring (gio_uring)：**
    *   借鉴 Linux 的 io_uring 机制，在 GPU HBM 中实现异步 I/O 环形缓冲区。
    *   **SM 分区技术：** 通过 NVIDIA Green Context 将 GPU 资源划分为“计算域”和“I/O 控制域”，确保 I/O 内核与计算内核并行执行，互不干扰。
*   **松弛感知 I/O 调度（Slack-Aware I/O Scheduler）：**
    *   **离线分析：** 预先分析模型各层的计算负载，识别出 SM 利用率较低的“松弛窗口（Slack Windows）”。
    *   **读写解耦：** 针对 SSD 在并发读写时带宽骤降的问题，调度器会根据分析结果，在计算任务的间隙交替安排读/写操作，最大化计算与 I/O 的重叠。

### 6. 论文的主要结论与发现
*   **性能飞跃：** 在严格的 SLO 约束下，Tutti 相比 LMCache-GDS 将 **TTFT 降低了 78.3%**，并将系统可承载的**请求率提升了 2 倍**。
*   **零停顿：** 通过松弛感知调度，Tutti 成功将 GPU 停顿时间降至接近零，使 SSD 方案的推理曲线几乎与 DRAM 方案重合。
*   **成本优势：** 相比基于 DRAM 的方案，Tutti 利用廉价 SSD 实现了极高的缓存命中率，使**服务成本降低了约 27%**。
*   **突破限制：** 在超长上下文（640K tokens）测试中，Tutti 避免了 GDS 方案常见的 OOM（显存溢出）错误，展现了更好的架构鲁棒性。

### 7. 优点
*   **架构创新：** 首次在 KV Cache 场景下实现了真正的“以 GPU 为中心”的存储控制，消除了 CPU 这一长期存在的瓶颈。
*   **深度集成：** 并非简单的插件，而是深入到 GPU 硬件调度（SM 分区）和 NVMe 协议优化（SGL），技术硬核。
*   **实用性强：** 直接集成到主流框架 vLLM 中，且在长文本趋势下具有极高的商业应用价值。
