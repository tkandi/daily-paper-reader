## 摘要
注意力机制的高效 CUDA 实现对现代深度学习系统至关重要，但支持多样化且不断演进的注意力变体仍具挑战。现有框架和编译器在性能与灵活性之间进行权衡，而专家编写的算子虽然效率极高，但难以适配。近期的研究探索了利用大语言模型（LLMs）生成 GPU 算子，但先前的研究表明，对于注意力机制等复杂算子，其正确性不稳定且存在显著的性能差距。我们提出了 CuBridge，这是一个基于 LLM 的框架，通过结构化的“提升-转换-降低”（lift-transfer-lower）工作流来适配专家编写的注意力算子。CuBridge 从专家编写的 CUDA 注意力算子出发，将其提升为一种可执行的中间表示（IR），使执行编排显式化，同时抽象掉底层的 CUDA 语法。给定用户提供的 PyTorch 规范，CuBridge 生成并验证目标 IR 程序，然后通过参考引导的降低过程重构优化的 CUDA 代码。在多种注意力变体和 GPU 平台上，CuBridge 始终能生成正确的算子，且性能大幅优于通用框架、基于编译器的方法以及先前的基于 LLM 的方法。

## Abstract
Efficient CUDA implementations of attention mechanisms are critical to modern deep learning systems, yet supporting diverse and evolving attention variants remains challenging. Existing frameworks and compilers trade performance for flexibility, while expert-written kernels achieve high efficiency but are difficult to adapt. Recent work explores large language models (LLMs) for GPU kernel generation, but prior studies report unstable correctness and significant performance gaps for complex operators such as attention.   We present CuBridge, an LLM-based framework that adapts expert-written attention kernels through a structured lift-transfer-lower workflow. CuBridge starts from expert-written CUDA attention kernels and lifts them into an executable intermediate representation that makes execution orchestration explicit while abstracting low-level CUDA syntax. Given a user-provided PyTorch specification, CuBridge generates and verifies a target IR program, then reconstructs optimized CUDA code via reference-guided lowering. Across diverse attention variants and GPU platforms, CuBridge consistently produces correct kernels and substantially outperforms general frameworks, compiler-based approaches, and prior LLM-based methods.

#### 1. 核心问题与整体含义
*   **研究背景**：注意力机制（Attention）是现代深度学习的核心，随着模型演进，出现了大量变体（如不同的掩码、缩放或归一化规则）。
*   **核心痛点**：
    1.  **性能与灵活性的矛盾**：PyTorch 等高层框架灵活但性能差；FlashAttention 等专家库性能极高但代码极其复杂，难以手动修改以适配新变体。
    2.  **LLM 生成的局限性**：直接让 LLM 从零编写 CUDA 算子（Scratch-generation）在处理复杂逻辑时，正确性极不稳定，且性能往往远低于专家优化水平。
*   **研究目标**：开发一个框架，利用 LLM 自动将“专家编写的高性能算子”适配到“新的注意力变体”上，同时保持原有的极致性能。

#### 2. 方法论
CuBridge 采用了 **“提升-转换-降低”（Lift-Transfer-Lower）** 的结构化工作流，其核心是 **CuIR（一种可执行的中间表示）**。
*   **核心思想**：不让 LLM 直接改 CUDA 源码，而是先抽象成易于理解的 IR，修改 IR 后再映射回源码。
*   **关键技术细节**：
    *   **CuIR 设计**：一种 Pythonic 的中间表示，它抽象掉了繁琐的线程索引和底层语法，但显式保留了**执行编排（Execution Orchestration）**信息（如内存层级、异步拷贝 `copy_async`、计算指令 `gemm_async` 和同步屏障 `barrier`）。
    *   **语义提升（Lifting）**：利用 LLM 将原始 CUDA 代码转化为 CuIR。通过 Chain-of-Thought 提示词，识别代码中的工作单元（Worker）及其同步逻辑。
    *   **语义转换（Transfer）**：根据用户提供的 PyTorch 参考实现，LLM 在 CuIR 层面进行逻辑修改（如插入 Mask 逻辑或更改激活函数）。
    *   **参考引导的重构（Lowering）**：通过对比原始 CuIR 和目标 CuIR 的差异，LLM 以原始 CUDA 代码为参考，通过“打补丁”（局部代码编辑）的方式生成目标 CUDA 代码。
    *   **闭环验证**：由于 CuIR 是可执行的，框架会在每一步通过执行器验证数值正确性，若失败则触发 LLM 自我修复。

#### 5. 实验数量与充分性
*   **实验规模**：进行了 96 个测试用例的系统性评估（8 种变体 × 12 种序列长度/模型配置）。
*   **充分性分析**：
    *   **多维度验证**：涵盖了不同 GPU 架构（A100/H100）、不同 LLM 后端、不同序列长度（1k 到 8k）。
    *   **消融实验**：专门对比了 Vanilla LLM、ReAct 模式与 CuBridge 流程的差异，证明了 CuIR 的必要性。
    *   **客观性**：采用了 Pass@k 等标准指标，并与当前工业界最强的编译器（FlexAttention）和专家库（FlashInfer）直接对标，实验设计客观且具有说服力。

#### 6. 主要结论与发现
*   **性能卓越**：CuBridge 生成的算子性能显著优于现有方案。在 H100 上，平均比 PyTorch 快 **19.82x**，比 FlexAttention 快 **1.62x**，比之前的 LLM 方法快 **4.35x**。
*   **正确性高**：在所有测试变体中达到了 **100% 的正确率**，解决了 LLM 直接写 CUDA 代码时逻辑易出错的问题。
*   **架构适配性**：CuBridge 能够很好地利用 H100 的新特性（如 Warp-specialization 和 TMA），而这些特性是通用编译器难以自动优化的。
*   **能力阈值**：实验发现 LLM 的基础推理能力至关重要，较小的模型（如 Qwen-3-32B）无法完成复杂的算子重构任务。

#### 7. 优点
*   **创新的抽象层**：CuIR 成功找到了“人类可读、LLM 可理解、硬件性能相关”的平衡点。
*   **补丁式重构**：通过局部修改而非全量生成，最大限度保留了专家代码中的手工优化技巧。
*   **端到端自动化**：从高层 PyTorch 规范到低层高性能 CUDA 代码的自动化路径非常完整。

#### 8. 不足与局限
*   **依赖专家参考**：该方法的前提是必须有一个现成的、高性能的“源算子”作为参考。如果面对全新的硬件架构或完全没有参考代码的算子，该框架无法发挥作用。
*   **LLM 成本与延迟**：虽然比人工开发快，但多次调用 LLM 进行迭代验证仍存在一定的计算成本和生成延迟。
*   **应用范围**：目前主要集中在注意力机制和 GEMM 类算子，对于非规则数据访问或非张量计算类算子的适用性尚未验证。
