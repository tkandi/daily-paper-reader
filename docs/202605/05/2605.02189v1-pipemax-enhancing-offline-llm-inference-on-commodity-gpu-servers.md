## 摘要
离线大语言模型（LLM）推理旨在固定预算下最大化请求处理量，这使得通用 GPU 服务器成为一个极具前景的选择。然而，先前的工作通常孤立地考虑卸载（offloading）和并行化，导致性能不佳。在本文中，我们提出了 PipeMax，这是一个高吞吐量的 LLM 推理系统，它将流水线并行与卸载相结合，以克服 GPU 服务器上的互连和内存限制。特别地，流水线并行自然地产生较低的通信开销，并且每次在每个 GPU 上仅保持一个批次处于活跃状态，从而能够卸载非活跃批次的 KV 缓存。通过协调计算与卸载数据移动，PipeMax 有效地扩展了 GPU 内存容量并支持大批次执行。实验表明，在 8-GPU 节点上，PipeMax 的吞吐量比 vLLM 高出多达 2.51 倍，比最先进的高吞吐量 LLM 系统分别高出多达 1.42 倍和 1.38 倍。

## Abstract
Offline LLM inference seeks to maximize request processing under fixed budgets, making commodity GPU servers a promising choice. However, prior work typically considers offloading and parallelism in isolation, resulting in suboptimal performance. In this paper, we propose PipeMax, a high-throughput LLM inference system that integrates pipeline parallelism with offloading to overcome interconnect and memory constraints on GPU servers. Particularly, pipeline parallelism naturally incurs low communication overhead and keeps only one batch active on each GPU at a time, which enables offloading the KV cache of inactive batches. By coordinating computation with offloading data movement, PipeMax effectively expands GPU memory capacity and sustains large-batch execution. Experiments show that PipeMax achieves up to 2.51x higher throughput than vLLM, and up to 1.42x and 1.38x higher throughput than state-of-the-art high-throughput LLM systems, respectively, on an 8-GPU node.

### 1. 核心问题与研究动机
*   **核心问题**：如何在预算有限的**商用 GPU 服务器**（如 RTX 5090、L20 等缺乏高带宽 NVLink 互连的设备）上，实现大语言模型（LLM）的**高吞吐量离线推理**。
*   **研究动机**：
    *   **显存瓶颈**：LLM 推理（尤其是 Decode 阶段）受限于 KV Cache 占用的巨大显存。
    *   **现有技术局限**：纯“卸载（Offloading）”技术受限于 PCIe 带宽；“张量并行（TP）”在无 NVLink 的服务器上通信开销巨大；“流水线并行（PP）”虽然通信开销低，但在 Decode 阶段显存利用率低（每个 GPU 只有当前处理的 Batch 是活跃的，其他 Batch 的 KV Cache 闲置在显存中）。
    *   **研究目标**：打破卸载与并行的孤立状态，通过深度集成流水线并行与 KV Cache 卸载，扩展有效显存容量。

### 2. 方法论
PipeMax 的核心思想是利用流水线并行的结构特性，将非活跃批次的 KV Cache 卸载到 CPU，从而腾出显存支持更大的 Batch Size。
*   **核心技术细节**：
    *   **预填-解码解耦（Prefill-Decode Decoupling）**：在时间上分离两个阶段，预填阶段连续执行以填满流水线，生成的 KV Cache 异步卸载至 CPU。
    *   **预取感知调度器（Prefetch-aware Scheduler）**：
        *   **执行时间预测**：利用公式 $\alpha \cdot b + \beta \cdot L + \delta$（$b$ 为 Batch Size，$L$ 为总序列长度）预测 Decode 耗时。
        *   **动态预取**：根据预测的计算时间确定预取预算，确保 KV Cache 的传输能被计算时间完全掩盖（Overlap）。
        *   **两阶段调度**：分为“热身阶段”（优先处理短请求以快速扩大 Batch）和“稳定阶段”（平衡各 Batch 负载以减少流水线气泡）。
    *   **传输高效型 KV 引擎**：
        *   **块优先布局（Block-First Layout）**：改变 PagedAttention 的存储方式，将同一 Block 内所有层的 KV Cache 连续存储，使 PCIe 传输从碎片化变为连续化，带宽利用率从 30% 提升至 90%。
        *   **优先级编排**：在 PCIe 链路上优先保证激活值（Activation）传输，利用空闲带宽进行 KV Cache 的预取和卸载。

### 6. 主要结论与发现
*   **吞吐量提升**：在 8 卡节点上，PipeMax 的吞吐量比 vLLM 高出 **2.51 倍**，比 TD-Pipe 和 Seesaw 分别高出 **1.42 倍**和 **1.38 倍**。
*   **显存扩展**：通过预取机制，PipeMax 实际上在 GPU 物理显存之外，利用 CPU 内存支撑了远超单机容量的 KV Cache。
*   **通信效率**：块优先布局是提升商用 GPU 推理性能的关键，它解决了 PagedAttention 在跨设备传输时的碎片化问题。

### 7. 优点
*   **针对性强**：精准捕捉到了流水线并行在 Decode 阶段的“显存闲置”机会。
*   **工程实现优雅**：提出的“块优先布局”不改变 PagedAttention 的计算逻辑，仅改变存储布局，兼容性好。
*   **软硬结合**：充分考虑了 PCIe 全双工特性和计算/通信的重叠，将商用硬件的性能压榨到了极致。

### 8. 不足与局限
*   **应用场景限制**：主要针对**离线（Offline）**高吞吐场景。由于引入了频繁的 CPU-GPU 换入换出，其首字延迟（TTFT）或单请求延迟可能不适合对实时性要求极高的在线服务。
*   **硬件依赖**：虽然针对商用 GPU，但仍依赖于较大的 CPU 内存来存放卸载的 KV Cache。
*   **模型规模上限**：虽然通过 PP 扩展了显存，但如果模型权重本身大到无法在 N 张卡的显存中分片放下，该系统仍需结合权重卸载，而本文主要关注 KV Cache 卸载。
