## 摘要
出于成本和隐私方面的考虑，在 CPU-GPU 节点上本地部署基于 MoE 的大语言模型颇具吸引力；然而，有限的 GPU 内存迫使大多数专家模型驻留在 CPU 内存中。此时，预填充阶段受计算限制，因而受益于激进的 GPU 加载；而解码阶段受 I/O 限制，则需要谨慎控制 PCIe 传输。在本地助手和文档工具中常见的低批处理规模下，这些需求无法被摊销，迫使与阶段无关的调度器陷入跷跷板困境：偏向预填充阶段的激进加载会引入无法掩盖的 I/O，进而阻塞解码；而偏向解码阶段的保守传输则会使预填充阶段的 GPU 缺乏工作负载。我们观察到，专家路由在不同阶段具有可预测的特性，因此能够将两个阶段解耦，并分别独立优化其预测、调度和执行。PDScope 预测专家激活情况以指导放置和预取，并通过跨层成本建模使这些策略适应各阶段的瓶颈；随后利用静态计算图、缓存预取和零拷贝异步 I/O，将决策编译为无额外开销的流水线。在主流 MoE 模型上，相较于现有系统，PDScope 实现了 2.5–10.3 倍更高的预填充吞吐量和 2.1–6.1 倍更高的解码吞吐量，表明具备阶段感知能力的协同设计能够在内存约束下实现高效的 MoE 推理，并可自然扩展至多批次场景。

## Abstract
Local deployment of MoE-based LLMs on CPU-GPU nodes is attractive for cost and privacy reasons, yet limited GPU memory forces most experts into CPU memory. Prefill is then compute-bound and benefits from aggressive GPU loading, while decode is I/O-bound and requires conservative PCIe transfers. These demands cannot be amortized under low batching---typical of local assistants and document tools---forcing phase-agnostic schedulers into a seesaw: favoring prefill's aggressive loading injects unmaskable I/O that stalls decode, while favoring decode's conservative transfers starves prefill's GPU of work. We observe that expert routing is predictable in phase-specific ways, allowing us to decouple the two phases and optimize prediction, scheduling, and execution independently for each phase. PDScope predicts expert activations to guide placement and prefetching, adapts these policies to each phase's bottleneck via cross-layer cost modeling, and compiles decisions into overhead-free pipelines using a static computation graph, cache prefetching, and zero-copy asynchronous I/O. On mainstream MoE models, PDScope achieves 2.5-10.3x higher prefill throughput and 2.1-6.1x higher decode throughput than existing systems, showing that phase-aware co-design unlocks efficient MoE inference under memory constraints and extends naturally to multi-batch settings.
