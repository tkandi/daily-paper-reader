LSTM-Style Looped Transformers with Shared KV Caches
Andreas Kirsch
blackhc@gmail.com
Abstract
Recurrent transformers reuse weights to perform deep computation with fewer parameters.
We study an LSTM-style transformer that also shares one key–value cache across its recurrent
core. At width 1024, it uses 40.4% fewer parameters than an untied control at nearly matched
forward FLOPs, and reduces persistent cache sets from fifteen to four. Parallel training
supplies cache entries from a standard-attention pass, whereas continuation reads entries
produced recursively using shared attention. We address this mismatch by aligning the
two training passes’ cache entries with a consistency loss during the final 10% of a fixed
training-token budget. Across three model widths on FineWeb, this removes 81–89% of the
continuation-loss penalty relative to full-cache evaluation. The improvement replicates on
disjoint documents for two training seeds. Across four widths and 1.05–4.19B training tokens,
the loss cost of weight tying is smallest at lower token budgets, suggesting an opportunity to
use recurrent computation when data and model storage are limited.

Introduction
Applying the same transformer blocks repeatedly separates parameter count from computational depth.
Universal Transformers, ALBERT, and recurrent language models use this principle to share parameters
across layers or iterations (Dehghani et al., 2019; Lan et al., 2020; Geiping et al., 2025). The corresponding
attention caches are usually not shared: at each iteration, a token attends to representations of earlier tokens
from that same iteration. A direct decoder therefore stores keys and values for every block application, even
when its weights are reused.
Shared attention memories already reduce this storage in both untied and looped models (Wu & Tu, 2024;
Sun et al., 2024; Conchello Vendrell et al., 2026; O’Neill & Reid, 2026). We study the loss and computation
costs of combining weight tying with one cache for the entire recurrent core. The central question is whether
a parallel training objective prepares the model to reuse entries produced recursively during inference.
Our default model places four distinct transformer blocks between one untied prologue block and two epilogue
blocks. An LSTM-style update (Hochreiter & Schmidhuber, 1997; Gers et al., 2000) combines each core
application with a carried state through input and forget gates, then normalizes the state before its next use.
Three iterations give fifteen block applications but only seven sets of block weights. All core blocks read the
final block’s final-iteration cache for preceding tokens (Figure 1).
We use a common framework derived from modded-nanogpt (Jordan et al., 2024a)1 to compare untied,
standard-cache recurrent, and shared-cache recurrent models across four widths and three token budgets. Each
width has a 15-layer untied control that approximately matches the recurrent model’s forward computation.
Weight tying reduces parameters at this fixed computational depth, with higher loss under the tested recipe.
A separate comparison pairs recurrent width 1024 with untied width 768 to approximately match parameter
count; the wider recurrent model achieves lower continuation loss using more forward and training computation
(Figure 1, Table 1).
Cache sharing introduces a second tradeoff. A two-pass objective can train all core blocks to read a common
cache, but its parallel second pass reads caches produced by standard attention. During continuation,
newly appended entries are themselves produced using shared attention. We measure the total penalty of

Method
2.1
Backbone and gated recurrence
An untied prologue P produces a seed representation, a core of K distinct transformer blocks F = FK ◦· · ·◦F1
is applied R times, and an untied epilogue E produces the final representation. We write PiEj for i prologue
and j epilogue blocks. Our default is P1E2 with K = 4 and R = 3: seven sets of block weights and fifteen
block applications. A slot denotes a block position in the core; weights are shared across iterations, not across
slots.
Each block uses pre-RMSNorm with learned gains (Zhang & Sennrich, 2019), rotary positions (Su et al.,
2021), grouped-query attention (Ainslie et al., 2023), and a SwiGLU feedforward layer (Shazeer, 2020). We
use an RMS variant of query/key normalization (Henry et al., 2020): gain-free RMS normalization within
each head, with fixed attention-logit scale d−1/2
head . Head dimension is 64, with two query heads per KV head.
Long and short attention windows contain 2,048 and 1,024 tokens. The prologue uses a long window, the
core repeats long/short/short/short, and the epilogue uses short/long. The 15-layer untied control has five
long-window layers, at zero-based indices 0, 4, 7, 10, and 14, and ten short ones. Both models therefore have
the same counts of long and short block applications. Input embeddings and the output projection share
weights. Appendix B gives remaining dimensions and initialization details.
Let N denote gain-free RMS normalization, and Ng the core’s learned-gain candidate normalization. For
token embeddings x, initialize s = N(P(x)) and c0 = h0 = s. One iteration computes

The gates act per token and coordinate. This is an LSTM-style update over depth, without a tanh or output
gate. The carry cr accumulates information; its normalized read hr supplies the next core application, gates,
and eventually the epilogue. A separate learned-gain normalization precedes the output projection. The
candidate’s learned gain can change its magnitude, while normalization of the carry read controls the input
scale of the next iteration.

Gate matrices start at zero, with bf = 1 and bi = 0. The initial gates are therefore approximately 0.7311
and 0.5. With identity-initialized blocks, unit candidate gain, and idealized exact normalization, the first
update gives c1 = 1.2311s and h1 = h0. This preserves direction at initialization; the forget bias specifies
initial carry retention, not contraction of the complete state-dependent recurrence.
2.2
One cache for all core blocks
Standard attention uses preceding-token keys and values from the same block and iteration. A direct decoder
stores P + KR + E cache sets. Our shared-cache policy uses one donor for the entire core: the own keys and
values computed by the final core block on its final iteration. Every core block, on every iteration, reads
this donor for preceding positions and its own key and value at the current position. Attention still respects
each block’s window and document boundaries. Prologue and epilogue blocks retain separate caches, giving
P + 1 + E sets: four instead of fifteen for the default model. Keys are stored after query/key normalization
and rotary positions. This adapts final-layer KV sharing (Wu & Tu, 2024) to a tied core while retaining each
block’s own current-token KV.
The two-pass objective trains these reads in parallel over token positions. First, run standard attention,
obtain cross-entropy CE1, and retain the donor. Second, restart the recurrence from the same prologue seed,
use the retained donor for shared-cache attention, and recompute the epilogue and CE2. We minimize
L2p = 1

Both terms are mean next-token cross-entropies. The donor remains in the computation graph, so the second

This construction does not make the second pass identical to autoregressive continuation. In training, the
donor for every preceding position was computed by standard attention. During continuation, a newly
processed token reads shared past caches and appends its own final donor entry; subsequent tokens then read
that entry. Epilogue caches also develop recursively. Ground-truth token inputs do not remove this difference
in hidden-state histories. Comparing full-cache and shared-cache continuations on identical targets measures
the total effect of changing cache policy, including both the read layout and the histories supplying it.

whole-run consistency appear in Appendix G. The loss encourages local agreement under first-pass histories;
it does not enforce agreement under every recursively generated history.
2.4
Variable depth and stopping
For variable-depth training, each update draws one rank-synchronized R ∼U{3, . . . , 6}. At inference a token
may stop when consecutive read states point in similar directions. With the same gain-free normalization as

qr,t > 0.98, or at the six-pass cap. Its selected stopping iteration supplies its donor entry. Read-state direction,
carry magnitude, and prediction loss need not converge together.
The batched decoder freezes stopped states but continues computing until all rows have stopped. We report
each token’s selected depth, not executed FLOPs or latency savings. Parallel chunk probes instead use a
global state statistic and a common stopping depth. The adaptive consistency branch repeats the last 1,000
of 8,000 updates (12.5%): 200 constant-rate updates followed by 800 decay updates.
3
Experimental setup
Training and comparisons.
We train on FineWeb (Penedo et al., 2024) using a common framework
derived from modded-nanogpt (Jordan et al., 2024a). Tied and untied models use the same block components,
data loader, and optimizer implementation. We simplify the architecture to support controlled recurrence
experiments. We distinguish four trained variants: an untied 15-layer control; a standard cell trained with
single-pass cross-entropy and separate caches; a two-pass cell trained with Equation 5; and its repaired branch
trained with Equation 7 near the end. The standard cell is a separate model, not the first pass of the two-pass
cell.
The main ladder uses widths 384, 512, 768, and 1024 and fixed depth three. Endpoints of 4,000, 8,000, and
16,000 updates contain 1.048576B, 2.097152B, and 4.194304B training tokens. Each update processes 262,144
tokens in 32 chunks of 8,192, with attention confined to chunks and documents. Training uses BF16 on eight
H100s, global gradient clipping at norm 1, Muon for hidden matrices (Jordan et al., 2024b), and AdamW
(Loshchilov & Hutter, 2019) for embeddings, normalization gains, and biases. The selected learning rates
are 0.01 and 3 × 10−4, respectively. After an 80-update warmup, a constant-rate trunk supports branches
with linear decay over the last 10% of each budget (Appendix B). Common named tensors share initial
values in paired controls. Training data order is fixed across seeds. The repository maps models to recorded
configurations and results.
Chunk validation.
All losses are next-token cross-entropy in nats. Standard and parallel shared-cache
validation score the same 1,280 chunks of 8,192 targets (10,485,760 targets total). Standard validation uses
each block and iteration’s own past representations. For the main two-pass models, parallel shared-cache
validation is the second-pass computation of Section 2.2. These provide the model-size ladder and update-rule
comparisons. They do not measure a cache that is updated recursively during continuation.
Prompt-prefill continuation.
Our primary continuation evaluation uses 1,280 document-contained spans,
each with 2,048 prompt tokens followed by 512 scored targets (655,360 targets total). Ordinary prefill
computes the prompt with standard attention. The full-cache reference retains all block-iteration caches; the
shared-cache continuation retains the final donor and prologue/epilogue caches. Subsequent token processing
updates the respective caches recursively. Both score the same targets and always receive ground-truth token
inputs. The first target uses the final prompt logits, followed by 511 decoding steps. We call the shared-cache
result served loss; it measures teacher-forced continuation, not sampled generation quality.
A 512-prompt/2,048-target diagnostic changes both continuation length and target positions. A two-pass-
prefill diagnostic retains first-pass donor entries but second-pass epilogue entries and logits. Cold evaluation
processes both prompt and continuation sequentially from empty caches under the shared policy; it is reported
separately. After selecting the repair, we evaluate it on the next 1,280 eligible documents disjoint from the
original spans and chunk set; this is fresh same-source evaluation, not a new training replicate (Appendix C).
The appendix’s update-rule and cache-producer pilots use separate held-out documents and state their
evaluation policy alongside each result.

Resources and uncertainty.
Parameter counts include tied embeddings once and all used weights.
Reference forward FLOPs count dense projections and attention products for one pass at the stated depth,
using mean attended lengths in an 8,192-token chunk with 2,048/1,024 windows. They omit elementwise
operations and are not measured serving latency. We also report estimated training FLOPs because two-pass
and single-pass objectives differ substantially in cost (Appendix D). KV storage counts persistent BF16 keys
and values, excluding scratch space.
Width-768 untied and two-pass ladders have three training seeds; repair confirmation uses two of them.
Other widths and update-rule/deep-depth experiments use one seed. Paired continuation errors use a block
bootstrap over ordered document spans, with blocks of eight and 2,000 resamples. These conditional standard
errors describe variation over evaluation documents, not over training runs. We report training-seed variation
separately (Appendix F); the compact prespecification summary is in Appendix K.
4
Results
4.1
Model size and computation
The primary controls match width, training tokens, and the number of block applications. Their reference
forward FLOPs differ by only 1.5–2.4%, from the recurrent gates. Untied models have lower loss at each
width (Figure 2). We also compare models of different widths with approximately equal parameter counts
(Figure 1).
4.1.1
Fixed width and training tokens
At 4.19B tokens, both recurrent families have higher loss than the untied control at every width, with smaller
gaps for wider models (Figure 2). At width 1024 and 1.05B tokens, single-pass standard and two-pass parallel
shared losses are within 0.0002 nats of the untied control with 40.4% fewer parameters (seed 0; Table 7).
All model families improve from 1.05B to 4.19B tokens, while both recurrent families’ gaps to the untied
controls increase at every tested width, despite nearly matched forward computation (Figure 5). The loss
6


cost of reducing parameters through recurrence is therefore smaller at the lower token budgets. Across three
training seeds at width 768, the two-pass model’s shared-minus-untied gap grows from 0.0115 to 0.0209 to
0.0309, with seed standard deviations 0.0009, 0.0014 and 0.0025, respectively. This supports the budget
trend at that width; the other widths and the single-pass cells have one seed each. These observations do not
identify an asymptotic capacity limit or a width at which parity would be reached.
Matching estimated training compute instead pairs the two-pass models at 2.10B tokens with untied controls
at 4.19B. Their parallel shared-cache losses are higher by 0.0957–0.1439 nats across the four widths (Table 6).
These comparisons precede consistency repair and do not measure recursive continuation quality.
4.1.2
Cross-width comparison at approximately matched parameter count
After donor-consistency training, the width-1024 recurrent model has 136.202M parameters, close to the width-
768 untied model’s 135.978M. On the same primary continuation spans their losses are 3.1953 and 3.2393: a
paired difference of −0.0441 nats (block-bootstrap SE 0.0014). The recurrent model uses 545.5M rather than
328.9M reference forward FLOPs per token, a factor of 1.66. Its estimated training computation is 3.22 times
larger at the same token budget, excluding consistency-loss overhead. This cross-width comparison matches
parameters, not forward computation. The width-1024 untied compute control has 228.49M parameters and
uses 532.9M reference forward FLOPs per token; its loss is 3.1515, compared with the recurrent model’s 3.1953
(Table 1). The cross-width comparison uses seed 0 on the original spans; it has not received the held-out
confirmation used for the width-768 repair in Section 4.3. Detailed parameter and compute accounting is in
Appendix D.
4.2
Update-rule controls and a Huginn-style baseline
We compare the gated-carry update with a plain update that removes the carry and gates and overwrites the
hidden state with the normalized candidate, hr = N(gr). For each update, we also test input injection: a
learned linear adapter projects the concatenation of the current hidden state and the prologue state s, giving
core input A[hr−1; s] at every iteration. The four factorial arms in Table 2 share the backbone, initialization of
common parameters, data order, three-iteration depth, single-pass objective and training schedule. Removing
the cell also removes carry accumulation, so this control does not isolate learned gates from the carried
residual state.
We additionally test a Huginn-style baseline, adapting the input-injection recurrence of Geiping et al. (2025)
to our common backbone. It uses the same adapter at every iteration, starts from a normalized Gaussian
hidden state, and sets hr = gr: the core’s learned-gain candidate becomes the next hidden state directly,
without a cell carry or gates. This differs from the plain adapter arm, which starts from s and applies
gain-free normalization to the candidate. The fixed-depth comparison uses three iterations; Section 4.2.1
separately tests variable-depth training and gradient truncation. These controls use standard caches. A
separate width-512 shared-cache pilot tests the repair across update rules (Appendix G).

4.2.1
Gradient truncation and additional depth
At fixed depth three, the Huginn-style baseline remains 0.022–0.025 nats above the single-pass cell as training
increases from 1.05B to 4.19B tokens (Table 18). The other three update-rule ablations were trained only
to 1.05B tokens. For a separate comparison at greater depth, we train both updates at width 512 over
R ∼U{4, . . . , 32} on 1.05B tokens, with standard caches and either full gradients or gradients through only
the last eight iterations. Token budgets and sampled depths are matched; training computation differs
between gradient treatments. At evaluation depth 32, full-gradient losses are 3.6065 for the cell and 3.6036
for injection, a difference of −0.0029 (SE 0.0003). This small gap concerns these checkpoints, not statistical
equivalence across runs.
Truncation changes the comparison substantially: it raises the cell’s loss by 0.0757 and lowers injection’s by
0.0140, producing a 0.0926 gap. When the depth exceeds eight, truncation cuts the cell’s only gradient path
to its prologue, while injection retains a path through the adapter on later iterations. The controls establish
an architecture-dependent effect of truncation, not a general ranking of update rules. At depth 64, injection’s
loss is almost unchanged while the full-gradient cell’s rises by 0.0222. The best deep arm reaches 3.5896 at
depth 32, compared with 3.5941 for the fixed-depth-three cell at the same width and token budget, using 6.5
times its forward FLOPs. Full curves are in Appendix H.
All these update-rule comparisons have one training seed. They adapt Huginn’s recurrent structure to a
common smaller-scale language-model setting (Geiping et al., 2025); they do not reproduce its scale, training
recipe or reasoning evaluations. The results therefore do not resolve whether its reported benefits from
additional inference depth transfer to this regime.
4.3
Shared-cache continuation and donor consistency
A low parallel shared-cache loss does not ensure accurate continuation through a recursively updated cache.
At width 768, the two-pass model’s shared loss on chunks is 3.2675, below its standard loss of 3.2728. On
the primary continuation spans, however, its full-cache loss is 3.2827 and its shared-cache continuation loss
is 3.3347: a penalty of 0.0520 (SE 0.0013). These are different evaluation sets, so the penalty is computed
within the continuation protocol, on identical targets. Token inputs remain ground truth; the recursively
produced quantities are cache entries, not sampled tokens.
The two-pass objective exposes each token to donor entries from a standard first pass. During continuation,
it instead reads entries written by earlier shared-cache forwards. The continuation contrast changes both
read layout and cache history. Figure 3 shows how this total penalty varies with continuation position. The
shorter-prompt, longer-continuation diagnostic has a larger average penalty: 0.0826 at width 768. That
comparison changes both conditioning and scored positions, so it does not isolate continuation length alone.
A separate diagnostic holds the shared-read policy fixed and repeatedly recomputes donors on the same 64
chunks. From the second to third iterate, the parent’s loss rises from 3.2510 to 3.2994; after repair it rises
from 3.2515 to 3.2596. This supports a cache-history contribution, but does not decompose the prompt-prefill
continuation penalty (Appendix G).
4.3.1
Late consistency training
Applying donor consistency during the final 10% of training reduces the continuation penalty at all three
evaluated widths (Table 3). Across both continuation settings, 81–93% of the within-model penalty is
removed. The continuation’s full-cache loss increases by 0.0011–0.0025. The separate prespecified guard on
chunk-standard degradation also passes its 0.005 tolerance. The repaired models still trail their width-matched
untied controls by 0.0891, 0.0545 and 0.0438 nats at widths 512, 768 and 1024 (Table 1).

0 and 1; their full-cache costs are 0.0010 and 0.0014. The corresponding penalty reductions are 80% and 75%.
This confirms the selected repair on fresh same-source documents, with different effect sizes across the two
seeds; it does not establish cross-domain generalization.
Loss variants.
At width 768, increasing donor weight from γ = 0.1 to 0.3 to 1.0 lowers continuation
loss from 3.3001 to 3.2938 to 3.2902, while full-cache costs relative to the rerun control rise from 0.0005 to
0.0012 to 0.0057. We select 0.3 using the chunk-standard quality guard: its cost is 0.0013, whereas weight
1.0 costs 0.0052, just outside the 0.005 tolerance. Adding output distillation to combined donor/epilogue
consistency almost eliminates the penalty but costs 0.0112 in chunk-standard loss. Donor-only supervision
achieves the improvement; its slight advantage over combined supervision does not isolate epilogue effects,
because the combined loss halves the donor coefficient. Applying consistency throughout training also
changes its normalization from fixed to tracked scales; those comparisons do not isolate the effect of timing.
Appendix G reports the variants and both continuation settings. A separate width-512 pilot also finds that
donor consistency improves plain and input-injection updates, so the repair does not require the gated carry
at this setting (Appendix G).

Related work
Cache sharing and consistency.
Layer-Condensed KV Cache (LCKV) shares final-layer keys and values
across layers and handles their sequential dependency through iterative parallel cache refinement (Wu &
Tu, 2024). Its Appendix C.3 also tests an MSE loss between successive cache iterates, with lower perplexity
in one configuration and higher perplexity in others. We adapt this idea to an LSTM-style tied core using
normalized donor matching late in training. Our two-pass objective starts with standard attention, and each
block retains its own current-token K/V; LCKV masks that position. Our two- and four-sweep controls vary
refinement within this recipe, with full gradients (Appendix G).
Feedback Transformer uses one shared memory of past-token layer representations and shared K/V projections
(Fan et al., 2020). Cross-Layer Attention reuses earlier layers’ KVs (Brandon et al., 2024), and YOCO’s
cross-decoder shares caches produced by its self-decoder (Sun et al., 2024). Wu et al. (2025) compare lower-
and upper-layer donors, including their training and prefill costs. Our early-donor ablation tests this choice in
a tied core (Appendix G). Huginn tests zero-shot sharing across iterations (Geiping et al., 2025, Section 6.2),
and a Mixture-of-Recursions variant reuses first-recursion KVs (Bae et al., 2025b). Our final donor is shared
across both iterations and distinct core blocks.2
MELT adapts pretrained Ouro models using gated cache-writing states, chunk-wise training, and distillation
at every loop (Conchello Vendrell et al., 2026). It shares a global cache across loops for each layer while
retaining small per-loop sliding-window caches. Our gates update the recurrent carry, and all core blocks share
one donor. Looped Latent Attention compresses loop trajectories and reconstructs loop-specific KVs using
a distilled codec (O’Neill & Reid, 2026). Its unsuccessful final-loop-reuse control leaves the original model
frozen; our shared-cache models are trained for that policy. FlashLoop uses sparse updates and quantized
cross-loop KV residuals without retraining (Yang & Liu, 2026). These methods adapt pretrained models; we
study training from scratch and subsequent consistency repair.
Depth recurrence and gating.
Universal Transformers apply shared updates with adaptive computation
(Dehghani et al., 2019), ALBERT shares layer parameters (Lan et al., 2020), and deep equilibrium models
formulate prediction through a fixed point of a tied transformation (Bai et al., 2019). Our finite recurrence
uses an LSTM-style carry (Hochreiter & Schmidhuber, 1997; Gers et al., 2000), with independent input and
forget gates and a normalized read. The controls test the combined carry/gate update.
Huginn combines a prelude/core/coda architecture with input injection, randomized depth, and truncated
backpropagation (Geiping et al., 2025). Our Huginn-style arm adapts these mechanisms to a common
backbone. Its full- and truncated-gradient controls use standard caches; shared-cache update controls appear
separately in Appendix G. Neither reproduces Huginn’s scale or full recipe. Relaxed Recursive Transformers
convert pretrained models using layer-specific low-rank adapters (Bae et al., 2025a). Mixture-of-Recursions
learns token-level depth routing (Bae et al., 2025b), and Ouro uses an entropy-regularized exit policy (Zhu
et al., 2025). Our stopping rule uses state agreement without learned routing.
Scaling recurrence.
Parcae studies allocation between training tokens and loop depth at fixed parameter
count (Prairie et al., 2026). At matched executed depth, Schwethelm et al. (2026) find that their baseline
recurrence saves parameters but increases loss at matched training computation. SMELT estimates training-
compute savings at matched loss for a tuned looped mixture-of-experts recipe with closely matched per-token
FLOPs, parameters, and cache storage (Wang et al., 2026). Chen et al. (2026) distinguish weight sharing,

boundary operators, and model growth, finding gains from more recurrence when training repeatedly on
limited data.
Distillation and adaptive computation.
MiniLM matches attention distributions and value relations
(Wang et al., 2020); our auxiliary target is the stored donor itself. Adaptive computation time and PonderNet
learn stopping policies (Graves, 2016; Banino et al., 2021). CALM addresses early exits and missing deeper

verification and is evaluated against fixed-depth controls under the same cache policy.
6
Discussion and limitations
The loss penalty for tying grows with the training-token budget at nearly matched forward computation,
suggesting more scope for parameter savings when data are limited. Our depth-three ladder extends the
training stream as the budget grows. On a 100M-token corpus reused over ten epochs, Chen et al. (2026) find
that increasing recurrence can outperform adding parameters. Whether shared-cache models retain those
multi-epoch gains is open. Our grid neither optimizes width/depth nor fits scaling exponents. All families
improve through 4.19B tokens; we observe no capacity floor or compute-optimal training endpoint.
When training is amortized over many predictions, loss at a given inference and cache budget may justify
more training. The cache-producer comparisons illustrate the distinction: early production wins the pilot at
equal training compute, while an existing late-producer checkpoint has lower loss on fresh documents after
about four times as much estimated training compute, at nearly equal inference cost (Appendix G). Neither
result establishes a generally better producer or attributes the gap to recurrently refined memory alone.
Donor consistency reduces the shared-cache continuation penalty. The repeated-donor diagnostic supports a
contribution from cache histories, without decomposing the full penalty. The improvement requires no direct
epilogue supervision, but does not exclude epilogue effects or guarantee agreement on other histories. The
confounds in the loss-variant controls remain (Appendix G). Two seeds confirm the selected repair on fresh
same-source documents, without establishing a generally optimal coefficient or zero quality cost.
The repair also helps plain and injection updates in a single-seed pilot; the tested LSTM-style carry is
not necessary for that improvement. Four refinement sweeps provide no advantage over two sweeps with
late consistency at matched estimated training compute (Appendix G); their equal-token ranking depends
on prompt history. These pilots do not establish a best update rule or producer across scales. Holding
normalization fixed would separately test the value of applying consistency late.
Evaluation covers FineWeb language-model loss with ground-truth inputs. Sampled generation, longer
contexts, downstream tasks, and larger models may behave differently. Most configurations have one run;
document-level uncertainty excludes training variability. Our small-scale Huginn-style experiments leave open
how architecture, data, and optimization affect the value of additional depth.
Cache storage and selected depth do not determine latency. Uniform cache rings overstate savings relative to
window-sized allocations; our implementation slows at width 1024 with large batches. The adaptive decoder
computes stopped rows until the batch completes. A quality–latency improvement over fixed depth remains
to be demonstrated.
7
Conclusion
An LSTM-style weight-tied transformer reduces parameter count at fixed computational depth and shares
one persistent cache across its recurrent core. Two-pass training leaves a shared-cache continuation penalty;
late donor-KV consistency substantially reduces it, with a small full-cache loss cost and confirmation on
disjoint documents. At matched width and approximately matched forward computation, untied controls
retain lower loss. Simpler updates also benefit from consistency in a pilot, and adaptive stopping does not
improve on fixed depth. The evidence supports cache sharing with a measured quality and computation
tradeoff, rather than a general advantage for gated recurrence.

B
Architecture and training recipe
All models use the same transformer block: a learned-gain RMS normalization before attention and before
the MLP, rotary positional embeddings, gain-free per-head query/key normalization, and a SwiGLU MLP.
Attention has 64-dimensional heads and two query heads per key/value head. For model width d, the MLP
hidden width is 8d/3 rounded up to a multiple of 128. The tokenizer has 50,257 entries; input and output
embeddings share one matrix padded to 50,304 rows. There are no value-embedding tables, raw-embedding
residual skips, learned residual-mixing scalars, or FP8 output projection in these experiments.
The recurrent model has one prologue block, four distinct core blocks, and two epilogue blocks (P1E2). The
core weights are reused at each iteration. Its prologue, first core slot, and last epilogue use a 2,048-token
attention window; other blocks use 1,024 tokens. At three iterations this gives five long-window and ten
short-window block applications. The untied comparator has 15 blocks, with long windows at zero-based
indices 0, 4, 7, 10, and 14. Thus the models match the counts of long and short applications, while placing
them differently in the stack. Causal attention is also restricted to the current document and logical chunk.
The maximum attention window and the 8,192-token logical chunk length are distinct quantities.
Attention and MLP output projections start at zero, so each transformer block initially acts as the identity.
Other projection matrices use a uniform distribution with standard deviation 0.5/√fan_in; embeddings have
independent Gaussian entries with standard deviation 0.02. Normalization gains start at one. Gate matrices
start at zero, with forget and input biases 1 and 0. The initial forget coefficient σ(1) ≃0.731 describes carry
retention, not contraction of the full recurrent map. The cell starts with hidden state and carry equal to the
gain-free-normalized prologue output. Its carry read is gain-free RMS normalization; the candidate and final
output normalizations have learned gains. There is no additive latent noise in the cell. The Huginn-style
comparator instead starts from a unit-RMS Gaussian hidden state, uses the prologue adapter on every pass,
and reads the normalized candidate directly.
Data and optimization.
The global batch contains 262,144 tokens, arranged as 32 logical chunks of 8,192
tokens. All paired models see the same ordered FineWeb training stream. An update’s chunk indices are
determined by its step, independently of microbatching. Training uses eight H100 GPUs with four chunks per
rank per update. Memory-intensive runs split these into two or four microbatches; accumulation preserves the
global batch. Attention does not cross logical chunk boundaries. Training does not cycle over exhausted data.
Hidden matrices use Muon with learning rate 0.01, momentum 0.95, five Newton–Schulz iterations, weight
decay 0.1, and update scaling
p
max(1, rows/columns). The tied embedding and remaining parameters use
AdamW at learning rate 3 × 10−4, with β = (0.9, 0.95) and ϵ = 10−8. Embeddings have weight decay 0.1;
normalization gains and biases have none. Gradients are accumulated and synchronized before global norm
clipping at 1.0. The recipe is common across model widths, rather than separately tuned to each architecture.
Models compute in BF16 with FP32 normalization and loss reductions. Optimization states and complete

Evaluation protocols and uncertainty
Chunk validation.
Standard and parallel shared-cache validation each score 10,485,760 targets in the same
1,280 chunks of 8,192 tokens. Standard attention reads the cache for its own block and iteration. In the main
two-pass models’ parallel shared pass, every core block reads older-token entries from the last core slot’s final
iteration in the first pass; its current token uses its own key and value. The two passes share the prologue
computation but run separate core and epilogue computations. Appendix G specifies the early-producer and
additional-sweep variants. Ground-truth token inputs are used throughout.
Prompt-prefill continuation.
The primary continuation evaluation uses 1,280 documents, each at least
2,561 tokens long. Each example starts at a document boundary and supplies 2,048 prompt tokens, followed
by 512 scored next-token targets: 655,360 targets in total. The full-cache reference evaluates the ordinary
model on the same document prefix and scores precisely those targets. The shared-cache evaluation prefills the
prompt with ordinary attention, keeps the first pass’s final donor and the prologue/epilogue caches, and then
appends new donor entries after each input token. The final prompt logit scores the first continuation target;
processing that target as the next ground-truth input produces the prediction for the following target. Thus
512 targets require 511 new token updates after prefill. No model samples its next token in this evaluation.
The diagnostic split uses a 512-token prompt and 2,048 targets on the same documents, for 2,621,440 targets.
It changes both prompt length and scored positions, so its aggregate difference is not a controlled effect
of continuation length alone. Positionwise loss differences within either setting show how errors change as
recursively generated cache entries replace prompt entries. A second prefill diagnostic retains the first-pass
core donor but takes epilogue history and final prompt logits from the parallel second pass. It still does not
replace subsequent donor entries with first-pass entries.
Cold sequential evaluation.
A separate diagnostic processes complete validation chunks token by token
from empty caches, with caches reset at document boundaries. For example, at width 768 and 4.19B training
tokens, the untreated two-pass model has cold shared-cache loss 3.3426 and parallel shared-cache loss 3.2675.
Their difference, 0.0751, describes that cold protocol; it is not a correction to prompt-prefill continuation.
Cold decoding and the prefill protocols both use ground-truth inputs, despite their different cache histories.
Selection and confirmation.
The original continuation documents lie beyond the chunk-validation prefix
in the validation shard. They were reused to compare objectives and regularization weights. A further 1,280
eligible documents, disjoint from both earlier sets, were reserved for confirmation of the selected width-768
donor-only recipe at γ = 0.3. The two training seeds were evaluated on this same confirmation set; they
17


are not two new independent text sets. The confirmation supports transfer to fresh documents from the
same source, not to another corpus. Cross-width parameter matching uses the original spans and has no
corresponding held-out confirmation.
All paired differences are computed before rounding from per-example loss sums on identical targets. Unless
stated otherwise, reported standard errors use 2,000 moving-block bootstrap resamples of eight adjacent
chunks or spans. Blocks preserve some dependence between nearby chunks; spans themselves are document-
contained. These errors condition on the trained checkpoint pair. They do not include training seed variation
or uncertainty from selecting a recipe on the reused set. Seed standard deviations are reported separately
where independent training seeds exist.

Persistent cache storage.
For S cache sets, BF16 storage per cached token is 2 × 2 × HKV × 64 × S bytes.
At P1E2, K = 4, and R = 3, standard caching needs 1 + 4 · 3 + 2 = 15 sets; full sharing needs 1 + 1 + 2 = 4.
Uniform 2,048-position rings therefore reduce allocated KV storage by 15/4 = 3.75. Sizing each set to its
longest read window instead gives five long and ten short sets for standard caching, versus three long and one
short set for full sharing: (5 · 2 + 10)/(3 · 2 + 1) = 20/7 ≃2.86. The shared donor must retain a long window
because the first core slot reads it, although the last core slot produces it. These formulas exclude scratch
tensors and model weights; measured peaks appear in Appendix J.

An early cache producer.
An alternative forms each token’s shared core K/V directly from its prologue
representation, using the first core block’s existing projections. This entry is independent of the recurrent
computation, so parallel shared attention and cold sequential serving use the same past-token entries. A
single shared-pass training objective suffices; a standard producer pass is unnecessary. Producer depth is also
a design choice in cross-layer and decoder-sharing architectures (Brandon et al., 2024; Sun et al., 2024; Wu
et al., 2025).
This removes a path for communicating refined representations between tokens. Later recurrent passes can
change the current token’s queries, carry and prediction, but cannot change the entry read by future core
blocks. Their output still reaches the epilogue, whose separate caches retain projections of recurrently refined
states for future epilogue attention. Thus recurrence can improve computation over a fixed memory; it cannot
enrich that memory for future recurrent computation. The early producer and its prologue remain trainable
end to end.
