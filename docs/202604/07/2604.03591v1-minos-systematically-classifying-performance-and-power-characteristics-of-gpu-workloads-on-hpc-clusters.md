## 摘要
随着大规模高性能计算（HPC）集群越来越多地采用 GPU 等加速器来满足现代工作负载的巨大需求，这些集群正日益受到功耗限制。不幸的是，现代应用程序往往会暂时超过加速器的额定功率（即“功率峰值”）。因此，当前和未来的 HPC 系统必须同时对功耗和性能进行协同优化。然而，日益多样化的应用程序使得这一目标变得困难，因为这些程序通常需要定制化的优化才能在每个集群上高效运行。传统上，研究人员通过在特定集群上对应用程序进行性能分析（profiling）并进行优化来解决这一问题，但规模、算法多样性以及缺乏有效工具使得这项工作极具挑战性。为了克服这些低效问题，我们提出了 Minos，这是一种系统的分类机制，通过低成本的功耗和性能分析来识别相似的应用程序特征。这使我们能够将行为相似的工作负载归入有限数量的类别中，并减少对新工作负载进行广泛分析的开销。例如，在预测先前未见过的应用程序的频率限制（frequency capping）行为时，Minos 将分析时间缩短了 89%。此外，在 18 种流行的图分析、HPC、HPC+ML 和 ML 工作负载中，Minos 的功耗预测平均误差为 4%，性能预测平均误差为 3%，相比现有最先进的方法，预测精度显著提高了 10%。

## Abstract
As large-scale HPC compute clusters increasingly adopt accelerators such as GPUs to meet the voracious demands of modern workloads, these clusters are increasingly becoming power constrained. Unfortunately, modern applications can often temporarily exceed the power ratings of the accelerators ("power spikes"). Thus, current and future HPC systems must optimize for both power and performance together. However, this is made difficult by increasingly diverse applications, which often require bespoke optimizations to run efficiently on each cluster. Traditionally researchers overcome this problem by profiling applications on specific clusters and optimizing, but the scale, algorithmic diversity, and lack of effective tools make this challenging. To overcome these inefficiencies, we propose Minos, a systematic classification mechanism that identifies similar application characteristics via low-cost profiling for power and performance. This allows us to group similarly behaving workloads into a finite number of distinct classes and reduce the overhead of extensively profiling new workloads. For example, when predicting frequency capping behavior for a previously unseen application, Minos reduces profiling time by 89%. Moreover, across 18 popular graph analytics, HPC, HPC+ML, and ML workloads, Minos achieves a mean error of 4% for power predictions and 3% for performance predictions, significantly improving predictions over state-of-the-art approaches by 10%.

### Minos：HPC 集群 GPU 工作负载性能与功耗特征系统分类研究总结

#### 1. 核心问题与研究动机
*   **研究背景**：现代高性能计算（HPC）集群正大规模采用 GPU 加速器，但面临严峻的功耗约束。新一代 GPU（如 AMD MI300X, NVIDIA H100/B100）的 TDP（热设计功耗）已飙升至 700W-1400W 以上。
*   **核心问题**：现代应用在运行中经常出现瞬时突破 TDP 的“功耗峰值”（Power Spikes），这给系统稳定性、散热和电力分配带来挑战。
*   **动机**：由于应用极其多样（涵盖图分析、传统科学计算、机器学习及二者结合），为每个应用在每个集群上进行详尽的性能分析（Profiling）以寻找最优频率限制（Frequency Capping）设置是不切实际的。因此，需要一种低成本、系统化的分类机制来预测未知负载的行为。

#### 2. 方法论
Minos 提出了一种双重分类框架，结合了功耗动态和资源利用率特征：
*   **基于功耗的分类（Power-based）**：
    *   **特征提取**：不使用单一的平均功耗，而是提取“功耗峰值分布向量”。通过 1-2ms 粒度的采样，识别 $P \ge 0.5 \times TDP$ 的样本，计算其相对于 TDP 的幅度，并将其归入预设的 Bin（如 0.5 到 2.0 倍 TDP 之间）。
    *   **聚类**：使用层次聚类（Hierarchical Clustering）和余弦距离（Cosine Distance）来识别具有相似功耗波动模式的应用。
*   **基于利用率的分类（Utilization-based）**：
    *   **特征提取**：收集 GPU 内核粒度的硬件计数器，重点关注 SM 利用率（计算强度）和 DRAM 利用率（内存带宽强度）。
    *   **加权平均**：根据内核运行时间对利用率进行加权，生成应用级的二维特征点。
    *   **聚类**：使用 K-Means 将应用分为计算密集型、内存密集型和混合型。
*   **预测算法**：对于新负载，仅需在默认频率下进行一次低成本分析，通过寻找分类库中的“最近邻”（Nearest Neighbor），利用邻居的频率缩放数据来预测新负载在不同频率限制下的功耗峰值和性能损失。

#### 3. 实验设计
*   **数据集与负载**：涵盖 18 种代表性工作负载，包括：
    *   **图分析**：PageRank, BFS, SSSP, BC（基于 Gunrock 和 Pannotia）。
    *   **HPC 模拟**：LULESH, LSMS, LAMMPS, MILC, M-PSDNS。
    *   **机器学习（ML）**：LLaMA2/3 推理与微调、Stable Diffusion (SD-XL)、ResNet50、GNN。
    *   **HPC+ML 混合**：DeePMD（分子动力学+AI）、OpenFold（蛋白质折叠）。
*   **对比方法**：主要对比了 Guerreiro 等人的最先进方法（SOTA），该方法主要依赖平均功耗进行分类。
*   **验证方式**：采用“留一法”（Hold-one-out）交叉验证，并针对 FAISS 和 Qwen1.5-MoE 进行了案例研究。

#### 4. 资源与算力
*   **硬件平台**：
    *   **AMD 集群**：使用 AMD HPC Fund 集群，配备 MI300X GPU（每节点 8 个，192GB HBM3）。
    *   **NVIDIA 集群**：使用 TACC 的 Lonestar6 集群，配备 A100 PCIe GPU（40GB HBM2）。
*   **软件工具**：使用 AMD ROCm SMI API 获取功耗数据，使用 NVIDIA Nsight Compute 获取利用率计数器。
*   **算力消耗**：文中未明确给出总训练/运行小时数，但强调了 Minos 仅需单次运行即可完成分类，相比全频率扫描减少了约 90% 的分析时间。

#### 5. 实验数量与充分性
*   **实验规模**：测试了 18 种应用，涵盖了不同的输入规模（如 Batch Size 变化）和算法实现，总计产生了数十组对比数据。
*   **充分性**：实验设计较为全面，不仅验证了分类的准确性，还进行了敏感性分析（如 Bin 大小的影响）和跨应用泛化测试。
*   **公平性**：通过在不同厂商（AMD/NVIDIA）的 GPU 上分别测试，证明了方法的通用逻辑，对比 SOTA 时使用了相同的评估指标（p90 功耗误差和性能损失误差）。

#### 6. 主要结论与发现
*   **高精度预测**：Minos 对功耗峰值的预测平均误差仅为 4%，性能预测误差为 3%，比现有 SOTA 方法提升了 10%。
*   **大幅减开销**：对于未知负载，Minos 可减少 89%-90% 的性能分析时间。
*   **关键洞察**：
    1.  单一的平均功耗指标无法捕捉现代 GPU 的动态功耗行为，必须考虑功耗峰值的分布。
    2.  同一应用在不同输入规模或不同算法实现下，可能属于完全不同的功耗/性能类别。
    3.  频率限制（Capping）在抑制功耗峰值方面通常比频率锁定（Pinning）更有效且性能损失更小。

#### 7. 优点
*   **多维度视角**：首次同时考虑了功耗、性能和瞬时功耗峰值三个维度进行 GPU 负载分类。
*   **低成本且实用**：仅需利用厂商提供的标准 API 和计数器，无需修改内核或使用昂贵的外部电力测量设备。
*   **泛化能力强**：在从未见过的 MoE 模型（Qwen1.5）和向量检索（FAISS）上表现出极高的预测准确度。

#### 8. 不足与局限
*   **跨厂商限制**：虽然方法论通用，但由于 AMD 和 NVIDIA 的分析工具对“利用率”的定义不同，目前无法直接进行跨厂商的特征点对比。
*   **参考库依赖**：预测精度高度依赖于参考工作负载库的丰富程度。如果新负载在特征空间中距离所有已知负载都很远，预测误差会增大。
*   **静态分析局限**：目前的分类基于应用的整体或代表性阶段，对于运行过程中行为剧烈波动的长时任务，可能需要更动态的在线分类机制。
