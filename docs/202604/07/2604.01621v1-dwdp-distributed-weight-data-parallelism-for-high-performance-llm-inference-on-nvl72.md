## 摘要
大语言模型 (LLM) 推理日益依赖多 GPU 执行，然而现有的推理并行化策略需要逐层的 rank 间同步，使得端到端性能对工作负载不平衡非常敏感。我们提出了 DWDP（分布式权重数据并行），这是一种推理并行化策略，它在保持数据并行执行的同时，将 MoE 权重卸载到对等 GPU 上，并根据需要获取缺失的专家。通过消除集合式的 rank 间同步，DWDP 允许每个 GPU 独立运行。我们通过针对切分权重管理和异步远程权重预取的两项优化，进一步解决了该设计的实际开销。在 TensorRT-LLM 中实现并在 GB200 NVL72 上使用 DeepSeek-R1 进行评估，在 8K 输入序列长度和 1K 输出序列长度下，在 20-100 TPS/用户的服务范围内，DWDP 在相当的 TPS/用户水平下将端到端输出 TPS/GPU 提升了 8.8%。

## Abstract
Large language model (LLM) inference increasingly depends on multi-GPU execution, yet existing inference parallelization strategies require layer-wise inter-rank synchronization, making end-to-end performance sensitive to workload imbalance. We present DWDP (Distributed Weight Data Parallelism), an inference parallelization strategy that preserves data-parallel execution while offloading MoE weights across peer GPUs and fetching missing experts on demand. By removing collective inter-rank synchronization, DWDP allows each GPU to progress independently. We further address the practical overheads of this design with two optimizations for split-weight management and asynchronous remote-weight prefetch. Implemented in TensorRT-LLM and evaluated with DeepSeek-R1 on GB200 NVL72, DWDP improves end-to-end output TPS/GPU by 8.8% at comparable TPS/user in the 20-100 TPS/user serving range under 8K input sequence length and 1K output sequence length.

### DWDP：面向 NVL72 高性能大语言模型推理的分布式权重数据并行

#### 1. 核心问题与整体含义（研究动机和背景）
随着大语言模型（LLM）规模的扩大，推理过程通常需要多 GPU 协作。现有的并行策略（如张量并行 TP、专家并行 EP、流水线并行 PP）都存在一个共同的根本属性：**层级间的集体同步**。
*   **痛点**：在实际生产环境中，由于输入序列长度不同、KV 缓存命中率差异以及 MoE（混合专家模型）路由倾斜，各 GPU 的负载往往是不平衡的。
*   **后果**：层级同步（如 All-to-All 通信）会将局部延迟放大为全局等待，导致整体吞吐量受限于最慢的 GPU（长尾效应）。
*   **目标**：本文提出 **DWDP**，旨在通过消除推理路径上的集体同步，允许各 GPU 独立推进，从而解决负载不均衡导致的性能损失。

#### 2. 方法论：核心思想与关键技术
DWDP 的核心是将**数据并行（DP）**与**基于 GPU 的权重卸载/预取**相结合：
*   **分布式权重存储**：Attention 权重在各 GPU 间完全复制，而 MoE 专家权重则分布存储在 DWDP 组内的对等 GPU 上。
*   **异步按需预取**：每个 GPU 在执行当前层计算时，通过异步方式从其他 GPU “拉取”（Pull）下一层所需的专家权重。
*   **消除集体同步**：弃用基于 NCCL 的集体通信（如 All-to-All），改用基于 **Copy Engine (CE)** 的 `cudaMemcpyAsync` 进行点对点数据传输。这种方式不占用 SM（流式多处理器）资源，且各 Rank 无需互相等待。
*   **关键优化**：
    1.  **切分权重管理**：扩展 MoE GroupedGEMM 内核，使其能直接处理非连续的权重缓冲区（本地+远程），消除合并权重带来的显存拷贝开销。
    2.  **时分复用（TDM）预取**：针对多个 GPU 同时向同一源 GPU 请求权重导致的“多对一”竞争，将传输切分为小块（Slice）并采用轮询调度，利用流水线化执行缓解拥塞。

#### 3. 实验设计
*   **模型与框架**：使用 **DeepSeek-R1** 模型（NVFP4 权重，FP8 KV 缓存），集成在 **TensorRT-LLM** 推理框架中。
*   **测试场景**：
    *   **Context-Only（首字生成/预填充阶段）**：评估不同序列长度（ISL）、最大 Token 数（MNT）和负载不平衡度下的性能。
    *   **End-to-End（端到端服务）**：模拟真实的分离式推理（Disaggregated Serving）场景。
*   **Benchmark 与对比方法**：
    *   基准线为 **DEP**（数据并行 + 专家并行），这是目前主流的 MoE 推理并行方案。

*   **硬件平台**：NVIDIA **GB200 NVL72**（Blackwell 架构）。
*   **算力配置**：实验主要在 DWDP 组大小为 3 或 4 的配置下进行（即 3-GPU 或 4-GPU 作为一个权重共享组）。
*   **训练/推理时长**：论文侧重于推理性能评估，未涉及模型训练时长。

#### 5. 实验数量与充分性
*   **实验维度**：涵盖了消融实验（验证切分权重管理和 TDM 优化的有效性）、工作负载敏感度分析（ISL 从 1K 到 32K）、负载不平衡度分析（标准差变化）以及端到端 Pareto 前沿对比。
*   **充分性**：实验设计较为全面，不仅提供了宏观的吞吐量数据，还深入到了内核级别的延迟分解（Kernel Breakdown）和硬件层面的干扰分析（如功率诱导的频率降频），论证具有较强的说服力和客观性。

#### 6. 主要结论与发现
*   **吞吐量提升**：在 8K 输入/1K 输出的典型场景下，DWDP 在 20-100 TPS/用户的范围内，将单 GPU 的输出吞吐量（TPS/GPU）平均提升了 **8.8%**。
*   **抗失衡能力**：随着工作负载不平衡度的增加，DWDP 相比 DEP 的加速比进一步扩大（从 1.09x 提升至 1.15x）。
*   **资源灵活性**：DWDP 支持非整数倍的专家分配和更灵活的 GPU 组配置（如 DWDP3），有利于分离式推理中的精细化资源调度。
*   **硬件干扰发现**：附录指出，异步预取与计算重叠时的主要干扰源并非显存带宽，而是**功率限制诱导的频率降低**（DVFS 机制）。

#### 7. 优点
*   **架构创新**：打破了传统的层级同步范式，将“推”（Push/All-to-All）模式转变为“拉”（Pull/Async Prefetch）模式。
*   **实用性强**：针对 Blackwell 架构（NVL72）的高带宽特性进行了深度定制，解决了 MoE 模型显存占用巨大的痛点。
*   **内核级优化**：通过改进 GroupedGEMM 避免了显存拷贝，体现了软硬件协同设计的思路。

#### 8. 不足与局限
*   **TTFT 权衡**：在某些高吞吐配置下，为了换取更高的 TPS/GPU，DWDP 可能会导致首字延迟（TTFT）有所增加（主要是由于减少了 Context GPU 数量导致的排队延迟）。
*   **硬件依赖**：该方案高度依赖极高的点对点通信带宽（如 NVLink 5），在带宽较低的集群（如 PCIe 连接）上效果可能大打折扣。
*   **计算窗口要求**：DWDP 需要足够的计算任务来掩盖权重预取的通信时间，对于极短序列或极小 Batch Size 的场景，性能增益有限。
