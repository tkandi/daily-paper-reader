## 摘要
大语言模型（LLM）推理正迅速成为核心数据中心服务，然而当前的推理服务栈仍将主机 CPU 置于编排和 Token 级控制的关键路径上。这使得 LLM 性能对 CPU 干扰非常敏感，损害了应用的混合部署能力，并迫使运营商预留 CPU 余量，导致大量计算能力无法得到充分利用。我们提出了 Blink，这是一种端到端的推理服务架构，通过在 SmartNIC 和 GPU 之间重新分配职责，将主机 CPU 从稳态推理路径中移除。Blink 将请求处理卸载到 SmartNIC，由其通过 RDMA 将输入直接传输到 GPU 显存中，并使用持久化 GPU 内核取代主机驱动的调度，在无需 CPU 参与的情况下执行批处理、调度和 KV 缓存管理。实验评估表明，与 TensorRT-LLM、vLLM 和 SGLang 相比，即使在隔离环境下，Blink 的表现也优于所有基准系统，将预饱和 P99 TTFT 降低了高达 8.47 倍，P99 TPOT 降低了高达 3.40 倍，解码吞吐量提高了高达 2.1 倍，并将每个 Token 的能耗降低了高达 48.6%。在存在 CPU 干扰的情况下，Blink 能够保持稳定的性能，而现有系统的性能下降幅度高达两个数量级。

## Abstract
Large Language Model (LLM) inference is rapidly becoming a core datacenter service, yet current serving stacks keep the host CPU on the critical path for orchestration and token-level control. This makes LLM performance sensitive to CPU interference, undermining application colocation and forcing operators to reserve CPU headroom, leaving substantial capacity unutilized.   We introduce Blink, an end-to-end serving architecture that removes the host CPU from the steady-state inference path by redistributing responsibilities across a SmartNIC and a GPU. Blink offloads request handling to the SmartNIC, which delivers inputs directly into GPU memory via RDMA, and replaces host-driven scheduling with a persistent GPU kernel that performs batching, scheduling, and KV-cache management without CPU involvement.   Evaluated against TensorRT-LLM, vLLM, and SGLang, Blink outperforms all baselines even in isolation, reducing pre-saturation P99 TTFT by up to 8.47$\times$ and P99 TPOT by up to 3.40$\times$, improving decode throughput by up to 2.1$\times$, and reducing energy per token by up to 48.6$\%$. Under CPU interference, Blink maintains stable performance, while existing systems degrade by up to two orders of magnitude.

#### 1. 核心问题与整体含义（研究动机和背景）
当前主流的大语言模型（LLM）推理系统（如 vLLM、TensorRT-LLM、SGLang）虽然利用 GPU 进行张量计算，但其**控制平面（调度、批处理、KV 缓存管理）仍高度依赖主机 CPU**。
*   **研究动机**：由于 LLM 采用自回归解码，每生成一个 Token 都需要 CPU 进行一次调度决策。这种“主机-设备”的紧耦合导致推理性能极易受到 CPU 干扰（如数据中心内其他混合部署的任务），产生严重的尾部延迟（TTFT 和 TPOT 飙升），并迫使运营商预留大量闲置 CPU 资源以保证服务质量（SLO）。
*   **核心目标**：将主机 CPU 从稳态推理路径中彻底移除，实现“无 CPU（CPU-Free）”推理，提高系统的鲁棒性、吞吐量和能效。

#### 2. 核心思想与关键技术细节
Blink 的核心思想是将推理栈的职责重新分配给 **SmartNIC (DPU)** 和 **GPU**，使主机 CPU 仅负责一次性的初始化工作。

*   **前端（DPU 侧）**：
    *   **请求处理与分发**：在 DPU 的 ARM 核上运行轻量级 API 服务器，处理 HTTP 请求。
    *   **高效分词（Tokenization）**：在 DPU 上实现针对 ARM 优化的分词器，速度比传统 Python 实现快 8-20 倍。
    *   **零拷贝数据传输**：利用 **单边 RDMA** 技术，将分词后的输入直接写入 GPU 显存中的环形缓冲区（Ring Buffer），完全绕过主机内存和 CPU。
*   **后端（GPU 侧）**：
    *   **持久化调度内核（Persistent Scheduler）**：在 GPU 上运行一个永不退出的 CUDA 内核，负责扫描环形缓冲区、管理连续批处理（Continuous Batching）和 Paged KV-cache。
    *   **设备端图启动（Device-side Graph Launch）**：利用 CUDA Graph，由调度内核直接在 GPU 内部启动推理任务，消除主机端的内核启动开销。
    *   **窗口化尾部启动恢复机制**：针对 CUDA 硬件 120 次连续启动的限制，设计了自动重置机制，确保推理可以无限持续进行。

#### 3. 实验设计
*   **数据集**：使用 **ShareGPT v3** 真实对话数据集。
*   **测试模型**：涵盖不同规模和架构，包括 **Llama-3 8B**（稠密）、**Phi-4 15B**（稠密）、**Qwen-3 32B**（稠密）以及 **Qwen-3 30B-A3B**（混合专家模型 MoE）。
*   **对比基准（Benchmarks）**：
    *   **TensorRT-LLM**（NVIDIA 官方高性能框架）。
    *   **vLLM**（广泛使用的开源推理系统）。
    *   **SGLang**（以调度优化著称的高性能框架）。
*   **测试场景**：
    1.  **隔离环境**：推理任务独占服务器资源。
    2.  **干扰环境**：在主机 CPU 上运行高负载任务（如 `pbzip2` 压缩和 `Ninja` 编译 LLVM 源码），模拟多租户干扰。

#### 4. 资源与算力
*   **GPU**：单张 **NVIDIA H100 (96GB HBM3)**。
*   **DPU**：**NVIDIA BlueField-3** (16 个 ARM Cortex-A78 核，32GB 内存)。
*   **主机 CPU**：双路 Intel Xeon Gold 6336Y (共 96 核)。

*   **训练/运行**：论文侧重于推理服务，未涉及模型训练时长。

#### 5. 实验数量与充分性
*   **实验规模**：针对 4 种模型，在 13 种不同的请求负载（1 到 32 req/s）下进行了详尽的测试。
*   **维度覆盖**：涵盖了 TTFT（首字延迟）、TPOT（逐字延迟）、吞吐量、能效（每 Token 焦耳数）以及微架构层面的硬件计数器分析（LLC miss, TLB walk 等）。
*   **充分性评价**：实验设计非常充分且客观。作者不仅对比了应用层指标，还深入分析了操作系统层面的缓解措施（如核心隔离、缓存分区 CAT、大页内存）为何无法解决 CPU 瓶颈，从而证明了 Blink 架构的必要性。

#### 6. 主要结论与发现
*   **性能领先**：在隔离环境下，Blink 的 P99 TTFT 降低了高达 **8.47 倍**，解码吞吐量提升了 **2.1 倍**。
*   **极强的抗干扰能力**：在 CPU 受到严重干扰时，现有系统性能下降 1-2 个数量级，而 Blink 的性能几乎**完全不受影响**（波动在实验误差范围内）。
*   **能效显著**：由于消除了 CPU 调度开销并提升了 GPU 利用率，Blink 在隔离环境下节省了 **48.6%** 的能效，干扰环境下节省高达 **70.7%**。
*   **MoE 模型收益最大**：由于 MoE 模型计算量相对较小但调度频繁，Blink 移除 CPU 调度后的性能提升最为显著。

#### 7. 优点
*   **架构创新**：首次实现了端到端的“无 CPU”LLM 推理栈，打破了传统的 CPU 中心化控制逻辑。
*   **确定性性能**：通过硬件级隔离（DPU+GPU），为延迟敏感型应用提供了极高的性能确定性。
*   **兼容性强**：基于 TensorRT 引擎，无需修改模型权重即可支持多种主流 Transformer 架构。
*   **经济效益**：允许数据中心在不影响 LLM 推理的前提下，将主机 CPU 资源完全售卖给其他计算任务。

#### 8. 不足与局限
*   **硬件依赖**：需要配备高性能 SmartNIC/DPU（如 BlueField-3），增加了硬件部署成本和复杂度。
*   **单机限制**：目前原型主要针对单 GPU 场景，虽然文中讨论了多 GPU 扩展路径，但尚未在分布式/多卡并行环境下进行大规模验证。
*   **功能完备性**：尚未集成一些最新的软件优化技术，如分块预填充（Chunked Prefill）或前缀缓存（Prefix Caching），尽管架构上支持扩展。
*   **应用范围**：主要针对模型能完全装入显存的场景，对于需要 CPU/DRAM 卸载（Offloading）的超大规模模型，CPU 仍会回到路径中。
