## 摘要
LoRA 实现了大语言模型（LLM）的高效定制，并广泛应用于多租户和多任务服务场景。然而，诸如 MoE 等新兴模型架构显著增加了 LoRA 的显存开销，使得现有的耦合式 LoRA 服务设计扩展性较差，且容易导致尾部延迟激增。我们提出了 InfiniLoRA，这是一种将 LoRA 执行与基础模型推理相解耦的解耦式 LoRA 服务系统。InfiniLoRA 引入了一个共享的 LoRA 服务器，具有感知并行性的执行、SLO 驱动的资源配置以及关键路径优化，包括 GPU 发起的通信和硬件定制化的 LoRA 算子。实验表明，在严格的延迟 SLO 约束下，InfiniLoRA 可实现平均 3.05 倍的可服务请求率提升，并将满足 SLO 要求的 LoRA 适配器比例提高 54.0%。

## Abstract
LoRA enables efficient customization of LLMs and is widely used in multi-tenant and multi-task serving. However, emerging model architectures such as MoE significantly increase LoRA memory cost, making existing coupled LoRA serving designs poorly scalable and prone to tail-latency inflation. We present InfiniLoRA, a disaggregated LoRA serving system that decouples LoRA execution from base-model inference. InfiniLoRA introduces a shared LoRA Server with parallelism-aware execution, SLO-driven provisioning, and critical-path optimizations, including GPU-initiated communication and hardware-specialized LoRA kernels. Experiments show that InfiniLoRA can achieve an average $3.05\times$ increase in serviceable request rate under strict latency SLOs, and improve the percentage of LoRA adapters satisfying the SLO requirement by 54.0\%.

### 1. 核心问题与研究动机
*   **核心问题**：在多租户大语言模型（LLM）服务中，如何高效处理海量的 LoRA 适配器（Adapters）。
*   **研究背景**：
    *   **内存瓶颈**：随着 MoE（混合专家模型）架构的普及，LoRA 适配器的参数量剧增（因为每个专家都需要对应的 LoRA 权重），导致显存压力巨大。
    *   **耦合架构的局限**：现有的系统（如 S-LoRA）将 LoRA 执行与基础模型推理耦合在同一块 GPU 上。这种设计导致 LoRA 缓存空间受限，频繁的换入换出（Swapping）引发严重的尾部延迟（P95 Latency）。
    *   **扩展性差**：增加 GPU 数量（Scale-out）并不能线性增加可容纳的 LoRA 数量，因为基础模型在每块 GPU 上都要占用大量空间。

### 2. 核心方法论
InfiniLoRA 提出了**解耦式 LoRA 服务架构**，其核心思想是将 LoRA 的计算从基础模型推理中分离出来。

*   **解耦架构（Disaggregated Architecture）**：
    *   **Client GPU**：仅负责基础模型的推理（Attention 和 MLP 的基础权重计算）。
    *   **Server GPU**：组成共享的 LoRA 服务器池，专门存储和执行 LoRA 相关的矩阵乘法（$h = xA \cdot B$）。
*   **感知并行性的执行策略**：针对不同的模型并行模式（TP 张量并行、EP 专家并行），提出了三种 LoRA 放置策略（Adapter-wise, Layer-wise, Expert-wise），以最小化跨节点的通信开销。
*   **SLO 驱动的资源配置**：建立延迟解析模型，根据用户定义的延迟服务等级协议（SLO），动态决定需要多少台 LoRA 服务器以及如何分配计算任务。
*   **关键路径优化**：
    *   **GPU 发起的通信**：利用 NVSHMEM 等技术，让 GPU 直接触发网络传输，绕过 CPU 调度开销，降低微秒级延迟。
    *   **硬件定制内核**：开发了针对解耦场景优化的 BMM（批量矩阵乘法）算子，提升计算吞吐。

### 6. 主要结论与发现
*   **性能提升**：在严格的延迟约束下，InfiniLoRA 的**可服务请求率平均提升了 3.05 倍**。
*   **SLO 优化**：相比 S-LoRA，能够满足延迟要求的 LoRA 适配器比例提升了 **54.0%**。
*   **内存解耦的优势**：通过将 LoRA 移至专用服务器，系统能够支持比耦合架构多出数倍的适配器数量，且不会因为频繁的磁盘/内存交换导致系统卡顿。
*   **扩展性**：InfiniLoRA 证明了通过增加廉价的计算节点（专门做 LoRA 计算）可以有效缓解昂贵推理节点的内存压力。

### 7. 优点
*   **架构创新**：首次在 LoRA 服务领域引入解耦思想，解决了 MoE 模型带来的“内存墙”问题。
*   **系统级优化**：不仅是算法改进，还深入到 GPU 通信底层（NVSHMEM）和算子优化，具有很高的工程实践价值。
*   **灵活性**：支持动态资源调整，能够根据实时负载和 SLO 要求灵活分配算力。

### 8. 不足与局限
*   **网络依赖**：解耦架构对节点间的通信带宽（如 NVLink 或 RoCE）有较高要求，在低带宽环境下性能可能会受限。
*   **小模型开销**：对于参数量极小、显存压力不大的场景，解耦带来的通信开销可能会抵消其内存节省的收益。
*   **复杂性增加**：相比单体架构，解耦系统的部署、监控和故障处理复杂度更高。
