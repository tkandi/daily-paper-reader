## 摘要
现代 GPU 工作负载，特别是大语言模型（LLM）推理，受到算子启动开销和粗粒度同步的困扰，这限制了算子间的并行性。近期的巨核（megakernel）技术通过将多个算子融合进单个持久化内核中，以消除启动间隙并挖掘算子间并行性，但在处理实际工作负载中的动态形状和数据依赖计算时面临挑战。我们提出了 Event Tensor，一种用于动态巨核的统一编译器抽象。Event Tensor 编码了分块任务之间的依赖关系，并实现了对形状和数据依赖动态性的原生支持。基于此抽象，我们的 Event Tensor 编译器（ETC）应用静态和动态调度变换来生成高性能的持久化内核。评估结果表明，ETC 在实现最先进的 LLM 服务延迟的同时，显著降低了系统预热开销。

## Abstract
Modern GPU workloads, especially large language model (LLM) inference, suffer from kernel launch overheads and coarse synchronization that limit inter-kernel parallelism. Recent megakernel techniques fuse multiple operators into a single persistent kernel to eliminate launch gaps and expose inter-kernel parallelism, but struggle to handle dynamic shapes and data-dependent computation in real workloads. We present Event Tensor, a unified compiler abstraction for dynamic megakernels. Event Tensor encodes dependencies between tiled tasks, and enables first-class support for both shape and data-dependent dynamism. Built atop this abstraction, our Event Tensor Compiler (ETC) applies static and dynamic scheduling transformations to generate high-performance persistent kernels. Evaluations show that ETC achieves state-of-the-art LLM serving latency while significantly reducing system warmup overhead.

*   **研究动机**：现代 GPU 工作负载（尤其是大语言模型 LLM 推理）面临两大瓶颈：
    1.  **内核启动开销**：每个算子（Kernel）启动需 5-10μs，在 LLM 解码阶段，大量细粒度算子使得启动开销占据主导。
    2.  **粗粒度同步**：传统的算子间同步（Kernel Boundary）强制所有任务完成后再开始下一个算子，阻碍了算子间的并行（Inter-kernel Parallelism）。
*   **现有技术局限**：现有的“巨核”（Megakernel）技术试图将多个算子融合为一个持久化内核，但难以处理**动态形状（Dynamic Shapes）**和**数据依赖（Data-dependent）**的计算（如 MoE 架构中的动态路由），且编程复杂度极高。
*   **核心目标**：提出一种统一的编译器抽象，使巨核能够高效支持动态性，并简化其开发流程。

### 2. 方法论：Event Tensor 抽象与 ETC 编译器
*   **核心思想**：将同步原语（Event）提升为编译器中的“一等公民”，并以多维张量（Event Tensor）的形式组织，从而利用现有的符号形状（Symbolic Shape）编译器技术来处理动态性。
*   **关键技术细节**：
    *   **Event Tensor 抽象**：将算子拆分为分块任务（Tiles/Tasks），任务间的依赖关系通过 Event Tensor 编码。它支持符号维度（如 `Batch Size B`），允许在不重新编译的情况下处理不同形状。
    *   **数据依赖支持**：通过索引表达式（如 MoE 中的 `topk` 结果）动态映射任务坐标到事件坐标，实现运行时的动态任务触发和更新。
    *   **ETC 编译器变换**：
        *   **静态调度（Static Scheduling）**：在编译时预先分配任务到 SM 的队列，开销极低，适用于规律性强的负载。
        *   **动态调度（Dynamic Scheduling）**：在 GPU 上实现轻量级调度器，任务完成后动态推送到就绪队列，实现负载均衡，适用于 MoE 等不规则负载。
    *   **最小化运行时**：将调度逻辑直接编译进内核，避免了传统任务图在内存中的显式实例化。

*   **通用性**：Event Tensor 抽象不依赖于特定的 DSL（如 Triton 或 TVM），具有普适性。

*   **算子调优依赖**：ETC 生成的 GEMM 分块在某些特定形状下可能仍略逊于高度手工优化的 cuBLAS。

*   **应用限制**：主要针对延迟敏感的低 Batch 推理优化明显，在吞吐量导向的大 Batch 场景下，由于 GPU 已经饱和，巨核带来的边际收益会递减。
