## 摘要
低秩自适应（LoRA）目前是大语言模型参数高效微调的主流方法，但由于 LoRA 的性能对配置选择高度敏感，获得高质量的适配器（adapter）通常需要进行系统的超参数调优。在实践中，这导致了许多并发的 LoRA 任务，这些任务通常跨越了多租户环境中的异构任务。现有系统在很大程度上独立处理这些任务，这既浪费了在表现较差的候选配置上的计算资源，又导致 GPU 利用率不足。我们提出了 ALTO（自适应 LoRA 调优与编排），这是一个协同设计的训练系统，它在加速 LoRA 超参数调优的同时，实现了异构任务间高效的集群共享。ALTO 的核心见解是，当多个调优任务在共享的冻结主干网络（backbone）上并发运行时，它们会暴露出单任务设计无法利用的优化机会。基于此，ALTO 监控损失轨迹以提前终止没有前景的配置，使用融合分组 GEMM 结合一种新的秩局部适配器并行（rank-local adapter parallelism）来协同部署剩余的适配器并回收释放的 GPU 容量，并结合任务内和任务间调度，利用 LoRA 任务可预测的时长来改进多任务放置。广泛的评估表明，在不牺牲适配器质量的情况下，ALTO 与现有最先进技术相比实现了高达 13.8 倍的加速。

## Abstract
Low-Rank Adaptation (LoRA) is now the dominant method for parameter-efficient fine-tuning of large language models, but achieving a high-quality adapter often requires systematic hyperparameter tuning because LoRA performance is highly sensitive to configuration choices. In practice, this leads to many concurrent LoRA jobs, often spanning heterogeneous tasks in multi-tenant environments. Existing systems largely handle these jobs independently, which both wastes computation on weak candidates and leaves GPUs underutilized. We present ALTO (Adaptive LoRA Tuning and Orchestration), a co-designed training system that accelerates LoRA hyperparameter tuning while enabling efficient cluster sharing across heterogeneous tasks. The central insight behind ALTO is that when multiple tuning jobs run concurrently over a shared frozen backbone, they expose optimization opportunities that single-job designs cannot exploit. Building on this, ALTO monitors loss trajectories to terminate unpromising configurations early, uses fused grouped GEMM together with a new rank-local adapter parallelism to co-locate surviving adapters and reclaim freed GPU capacity, and combines intra-task and inter-task scheduling to improve multi-task placement by leveraging the predictable duration of LoRA jobs. Extensive evaluation shows that ALTO achieves up to $13.8\times$ speedup over state-of-the-art without sacrificing adapter quality.

### 1. 核心问题与整体含义（研究动机和背景）
LoRA（低秩自适应）已成为微调大语言模型（LLM）的主流方法，但其性能对超参数（如学习率、Batch Size、秩）高度敏感。为了获得高质量适配器，用户通常需要运行大量并发的调优任务。
*   **现有痛点**：目前的框架（如 PEFT、Unsloth）通常独立处理这些任务，导致：
    1.  **计算浪费**：在注定失败或表现不佳的候选配置上消耗了完整训练预算。
    2.  **资源利用率低**：单个 LoRA 任务计算量小，难以填满高性能 GPU（如 H100）的算力。
    3.  **调度低效**：在多租户、多任务环境下，缺乏对异构任务（不同模型、不同数据集）的有效编排。
*   **研究目标**：设计一个协同优化的系统，通过提前终止差配置、高效批处理执行和智能调度，加速 LoRA 超参数搜索过程。

### 2. 方法论：核心思想与关键技术
ALTO 提出了一个三层协同设计的架构：
*   **损失感知早期退出（Loss-Aware Early Exit）**：
    *   **热身阶段**：先运行一小部分步数，根据验证集损失剔除排名靠后的配置。
    *   **模式检测**：实时监控损失曲线，识别并终止“发散”（Divergence）和“过拟合”（Overfitting）的任务。
*   **动态批处理执行器（Dynamically Batched Executor）**：
    *   **解耦执行**：将冻结的主干网络（Base Model）计算与 LoRA 分支计算分离。主干网络使用高性能 cuBLAS，LoRA 分支使用自定义的 **Triton 融合分组 GEMM 内核**，实现 O(1) 次内核启动处理多个适配器。
    *   **秩局部适配器并行（Rank-Local Adapter Parallelism, AP）**：在多 GPU 场景下，主干网络权重被切分（类似 FSDP），但每个 GPU 独立负责不同的适配器计算。这消除了适配器梯度的跨卡通信，并支持极小的 Batch Size。
*   **分层调度（Hierarchical Scheduling）**：
    *   **任务内调度**：基于内存分析模型，贪婪地将适配器打包进执行器。
    *   **任务间调度**：利用 LoRA 任务时长可预测的特性，将其建模为约束规划问题（CP-SAT 求解），最小化集群的总完工时间（Makespan）。

### 6. 主要结论与发现

*   **质量保持**：早期退出机制能够准确保留最优配置，最终得到的适配器质量与全量搜索一致，甚至优于专家推荐的超参数。
