## 摘要
我们提出了 MegaTrain，这是一个以内存为中心的系统，能够在单 GPU 上高效地进行 100B+ 参数大语言模型的全精度训练。与传统的以 GPU 为中心的系统不同，MegaTrain 将参数和优化器状态存储在主机内存（CPU 内存）中，并将 GPU 视为瞬态计算引擎。对于每一层，我们流式输入参数并输出计算出的梯度，从而最大限度地减少持久化的设备状态。为了克服 CPU-GPU 带宽瓶颈，我们采用了两项关键优化：1) 引入了流水线双缓冲执行引擎，通过在多个 CUDA 流中重叠参数预取、计算和梯度卸载，实现了持续的 GPU 执行；2) 用无状态层模板替换了持久化的自动求导（autograd）图，在权重流式输入时进行动态绑定，在消除持久化图元数据的同时提供了调度灵活性。在配备 1.5TB 主机内存的单台 H200 GPU 上，MegaTrain 能够可靠地训练高达 120B 参数的模型。在训练 14B 模型时，其训练吞吐量达到了开启 CPU 卸载的 DeepSpeed ZeRO-3 的 1.84 倍。此外，MegaTrain 还支持在单台 GH200 上进行具有 512k token 上下文的 7B 模型训练。

## Abstract
We present MegaTrain, a memory-centric system that efficiently trains 100B+ parameter large language models at full precision on a single GPU. Unlike traditional GPU-centric systems, MegaTrain stores parameters and optimizer states in host memory (CPU memory) and treats GPUs as transient compute engines. For each layer, we stream parameters in and compute gradients out, minimizing persistent device state. To battle the CPU-GPU bandwidth bottleneck, we adopt two key optimizations. 1) We introduce a pipelined double-buffered execution engine that overlaps parameter prefetching, computation, and gradient offloading across multiple CUDA streams, enabling continuous GPU execution. 2) We replace persistent autograd graphs with stateless layer templates, binding weights dynamically as they stream in, eliminating persistent graph metadata while providing flexibility in scheduling. On a single H200 GPU with 1.5TB host memory, MegaTrain reliably trains models up to 120B parameters. It also achieves 1.84$\times$ the training throughput of DeepSpeed ZeRO-3 with CPU offloading when training 14B models. MegaTrain also enables 7B model training with 512k token context on a single GH200.

### 1. 核心问题与研究动机
*   **核心问题**：随着大语言模型（LLM）规模突破千亿参数，其训练和微调所需的显存（GPU HBM）远超单卡容量。即使是后训练阶段（如指令微调、对齐），也需要加载完整的模型参数、梯度和优化器状态。
*   **研究动机**：
    *   **显存墙限制**：现有的 GPU 显存增长速度远不及模型参数增长速度。
    *   **资源稀缺性**：高性能 GPU（如 H100）在学术界和中小型机构中极度稀缺。
    *   **现有方案不足**：现有的卸载技术（如 ZeRO-Offload）仍将 GPU 视为主要存储，仅将 CPU 内存作为溢出缓冲区，且受限于 CPU-GPU 带宽瓶颈，导致吞吐量低下。

### 2. 方法论
MegaTrain 采用了**以内存为中心（Memory-centric）**的设计理念，将 GPU 视为瞬时计算引擎，而将 CPU 内存视为主要存储。
*   **核心思想**：将所有持久化状态（参数、优化器状态）保留在主机内存中，仅在计算时将当前层所需的参数流式传输（Streaming）到 GPU，计算完成后立即释放。
*   **关键技术细节**：
    *   **流水线双缓冲执行引擎**：通过三个并发的 CUDA 流（计算流、权重传输流、梯度传输流）实现“预取-计算-卸载”的重叠。当 GPU 计算第 $i$ 层时，系统已在预取第 $i+1$ 层的权重，并同时将第 $i-1$ 层的梯度传回 CPU。
    *   **无状态层模板（Stateless Layer Templates）**：摒弃了 PyTorch 传统的全局静态计算图，改用无状态的层模板。在权重流进时动态绑定（Bind），消除了持久化图元数据和中间张量的显存占用，使显存占用仅取决于单层大小。
    *   **块状重计算（Block-wise Recomputation）**：每 $K$ 层存储一个激活检查点，在反向传播时按块重计算，使激活显存的增长与模型深度解耦。
    *   **CPU 端优化器更新**：利用 CPU（支持 AVX-512）处理计算密集度低但 I/O 密集度高的 Adam 优化器更新，避免了优化器状态在 CPU 和 GPU 之间的无效往返。

*   **极高的显存效率**：通过将显存占用限制在“单层”级别，彻底解耦了模型规模与 GPU 显存容量。

*   **普适性强**：不仅适用于高端服务器，也能让拥有 RTX 3090 等消费级显卡的开发者训练 14B 级别的模型。
