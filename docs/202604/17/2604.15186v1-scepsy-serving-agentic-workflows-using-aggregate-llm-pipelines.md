## 摘要
智能体工作流通过编排多个大语言模型（LLM）和工具来执行复杂任务。在保证低延迟的同时以目标吞吐量服务此类工作流具有挑战性，因为它们可以使用任意智能体框架定义，且表现出不可预测的执行时间：执行过程可能以依赖数据的方式进行分支、扇出或递归。由于工作流中的 LLM 数量通常超过可用 GPU 的数量，其执行还会导致 GPU 超额订阅。我们介绍了 Scepsy，这是一种新型智能体服务系统，能够高效地将任意多 LLM 智能体工作流调度到 GPU 集群上。Scepsy 利用了这样一个洞察：虽然智能体工作流具有不可预测的端到端延迟，但每个 LLM 在总执行时间中所占的份额在不同执行过程中相对稳定。Scepsy 根据这些聚合份额决定 GPU 分配：首先，它在不同的并行度下对 LLM 进行性能分析。然后，它利用这些统计数据构建聚合 LLM 流水线，这是一种用于分配方案的轻量级延迟/吞吐量预测器。为了找到在达到目标吞吐量的同时最小化延迟的 GPU 分配方案，Scepsy 使用聚合 LLM 流水线在分数级 GPU 份额、张量并行度和副本数量的搜索空间中进行探索。它使用分层启发式算法将最佳分配方案部署到 GPU 集群上，在遵守网络拓扑约束的同时最小化碎片化。我们在真实智能体工作流上的评估表明，与独立优化 LLM 或依赖用户指定分配的系统相比，Scepsy 实现了高达 2.4 倍的吞吐量提升和 27 倍的延迟降低。

## Abstract
Agentic workflows carry out complex tasks by orchestrating multiple large language models (LLMs) and tools. Serving such workflows at a target throughput with low latency is challenging because they can be defined using arbitrary agentic frameworks and exhibit unpredictable execution times: execution may branch, fan-out, or recur in data-dependent ways. Since LLMs in workflows often outnumber available GPUs, their execution also leads to GPU oversubscription.   We describe Scepsy, a new agentic serving system that efficiently schedules arbitrary multi-LLM agentic workflows onto a GPU cluster. Scepsy exploits the insight that, while agentic workflows have unpredictable end-to-end latencies, the shares of each LLM's total execution times are comparatively stable across executions. Scepsy decides on GPU allocations based on these aggregate shares: first, it profiles the LLMs under different parallelism degrees. It then uses these statistics to construct an Aggregate LLM Pipeline, which is a lightweight latency/throughput predictor for allocations. To find a GPU allocation that minimizes latency while achieving a target throughput, Scepsy uses the Aggregate LLM Pipeline to explore a search space over fractional GPU shares, tensor parallelism degrees, and replica counts. It uses a hierarchical heuristic to place the best allocation onto the GPU cluster, minimizing fragmentation, while respecting network topology constraints. Our evaluation on realistic agentic workflows shows that Scepsy achieves up to 2.4x higher throughput and 27x lower latency compared to systems that optimize LLMs independently or rely on user-specified allocations.

### Scepsy：基于聚合流水线的高效智能体工作流服务系统总结

#### 1. 核心问题与整体含义（研究动机和背景）
随着大语言模型（LLM）应用从单一对话转向**智能体工作流（Agentic Workflows）**，系统面临严峻的服务挑战。这类工作流通常编排多个不同规模的 LLM 和外部工具，具有以下特性：
*   **执行不可预测性**：受数据驱动，工作流会产生动态分支、循环和扇出，导致端到端延迟波动剧烈。
*   **资源超额认购**：工作流中的模型数量往往超过可用 GPU 数量，简单的“一模型一 GPU”分配会导致严重的资源浪费或性能瓶颈。
*   **优化目标冲突**：在有限的 GPU 预算下，增加副本（数据并行）提升吞吐量，与增加张量并行（TP）降低延迟之间存在复杂的权衡。
现有系统（如 K8s 自动扩缩容或单一模型优化器）缺乏对工作流整体结构的感知，导致资源分配效率低下。

#### 2. 方法论：核心思想与关键技术
Scepsy 的核心思想是：**虽然工作流的绝对执行时间不可预测，但各 LLM 在总执行时间中的“聚合占比”在统计上是稳定的。**

*   **聚合 LLM 流水线 (Aggregate LLM Pipeline, ALP)**：
    *   **追踪与聚合**：通过代理拦截 LLM 调用，提取每个模型的平均调用次数 ($n_m$) 和平均请求并行度 ($p_m$)。
    *   **性能建模**：在不同 TP 程度下对模型进行离线 Profile，将 LLM 级别的指标转化为工作流级别的延迟贡献和吞吐量瓶颈。
*   **联合 GPU 调度**：
    *   **搜索空间**：调度器在“分数级 GPU 份额（Fractional GPU）”、“张量并行度（TP）”和“副本数（Replicas）”三个维度进行搜索。
    *   **剪枝策略**：利用延迟比例进行剪枝，优先给高延迟模型分配更多资源，确保搜索在秒级完成。
*   **拓扑感知的分数级放置**：
    *   **层次化启发式算法**：首先进行节点间分配（优先放置大 TP 模型以利用 NVLink），然后进行节点内打包。
    *   **资源隔离**：利用 NVIDIA MPS（多进程服务）强制执行分数级 GPU 限制（如 0.66 个 GPU），提高利用率。

*   **实验规模**：涵盖了 4、8、16 张 GPU 的扩展性测试。

*   **调度开销测试**：测试了在不同模型数量（最高 5 个）和 GPU 数量（最高 128 个）下的调度搜索时间，证明了算法的可扩展性。
*   **客观性**：对比实验均在相同硬件和底层推理引擎版本下进行，使用了真实的智能体框架（如 LangChain, AutoGen）生成的负载，实验设计较为客观公平。

#### 6. 主要结论与发现
*   **性能提升**：相比 Kubernetes HPA，Scepsy 在相同 GPU 预算下实现了高达 **2.4 倍的吞吐量提升**和 **27 倍的延迟降低**。
*   **超越前沿系统**：相比 Ayo，Scepsy 在高负载下表现出更强的鲁棒性，吞吐量提升达 2.1x-8.2x。
*   **稳定性洞察**：实验证实了相对执行时间占比的稳定性（比绝对时间稳定约 4 倍），验证了 ALP 建模的有效性。
*   **资源利用**：分数级 GPU 分配能有效解决小模型（如 Embedding）占用整块 GPU 导致的浪费问题。

#### 7. 优点（亮点）
*   **框架无关性**：不绑定特定的编程模型（如 LangGraph），通过底层 API 追踪即可支持任何智能体框架。
*   **多维度联合优化**：首次在智能体场景下将分数级 GPU 分配与张量并行、副本管理结合。
*   **拓扑感知**：考虑了 NVLink 等硬件约束，避免了在跨节点通信上的性能损失。

#### 8. 不足与局限
*   **跨 LLM 并行建模简化**：ALP 目前将工作流简化为串行流水线，对于复杂的跨模型并行（Fan-out 到不同模型）可能存在建模偏差。
*   **工具执行时间假设**：假设外部工具（如数据库查询）执行时间极短。如果工具执行耗时极长（如运行物理实验），ALP 的预测准确度会下降。
*   **冷启动与动态变化**：虽然能处理请求内的动态性，但如果工作流结构发生根本性变化（如模型热切换），可能需要重新 Profile。
