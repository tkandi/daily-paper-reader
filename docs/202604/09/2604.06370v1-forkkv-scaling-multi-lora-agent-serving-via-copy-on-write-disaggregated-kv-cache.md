## 摘要
大语言模型（LLM）的推理范式正迅速转向复杂的多智能体工作流，其中专业化智能体在海量共享上下文上进行协作。虽然低秩自适应（LoRA）能够让这些专业化智能体高效地共存于单个基础模型上，但它在推理过程中引入了关键的内存占用瓶颈。具体而言，独特的 LoRA 激活导致不同智能体之间的键值（KV）缓存出现分歧，使得传统的针对共享上下文的前缀缓存（prefix caching）失效。这迫使系统进行冗余的 KV 缓存维护，迅速饱和 GPU 容量并降低吞吐量。为了应对这一挑战，我们推出了 ForkKV，这是一个针对多 LoRA 智能体工作流的推理系统，其核心是借鉴自操作系统中一种新颖的内存管理范式：带有写时复制（CoW）的 fork。通过利用 LoRA 的结构特性，ForkKV 在物理上将 KV 缓存解耦为一个海量的共享组件（类似于父进程的内存页）和轻量级的智能体特定组件（子进程的页面）。为了支持这一机制，我们提出了一种 DualRadixTree 架构，允许新 fork 的智能体继承海量共享缓存，并对其轻量级的独特缓存应用 CoW 语义。此外，为了保证高效执行，我们设计了 ResidualAttention，这是一种专门的算子（kernel），可直接在片上 SRAM 中重构解耦的 KV 缓存。在多种语言模型和不同任务的实际数据集上的全面评估表明，ForkKV 的吞吐量达到了最先进的多 LoRA 推理系统的 3.0 倍，且对生成质量的影响微乎其微。

## Abstract
The serving paradigm of large language models (LLMs) is rapidly shifting towards complex multi-agent workflows where specialized agents collaborate over massive shared contexts. While Low-Rank Adaptation (LoRA) enables the efficient co-hosting of these specialized agents on a single base model, it introduces a critical memory footprint bottleneck during serving. Specifically, unique LoRA activations cause Key-Value (KV) cache divergence across agents, rendering traditional prefix caching ineffective for shared contexts. This forces redundant KV cache maintenance, rapidly saturating GPU capacity and degrading throughput.   To address this challenge, we introduce ForkKV, a serving system for multi-LoRA agent workflows centered around a novel memory management paradigm in OS: fork with copy-on-write (CoW). By exploiting the structural properties of LoRA, ForkKV physically decouples the KV cache into a massive shared component (analogous to the parent process's memory pages) and lightweight agent-specific components (the child process's pages). To support this mechanism, we propose a DualRadixTree architecture that allows newly forked agents to inherit the massive shared cache and apply CoW semantics for their lightweight unique cache. Furthermore, to guarantee efficient execution, we design ResidualAttention, a specialized kernel that reconstructs the disaggregated KV cache directly within on-chip SRAM. Comprehensive evaluations across diverse language models and practical datasets of different tasks demonstrate that ForkKV achieves up to 3.0x the throughput of state-of-the-art multi-LoRA serving systems with a negligible impact on generation quality.

### 1. 核心问题与整体含义（研究动机和背景）
随着大语言模型（LLM）应用从简单对话转向复杂的多智能体工作流（如 ReAct、MapReduce），系统通常需要在共享的大规模上下文（如代码库、长文档）上运行多个专业化的 LoRA 智能体。
*   **核心矛盾**：虽然 LoRA 权重本身很轻量，但不同 LoRA 适配器产生的激活值不同，导致即使输入文本相同，其生成的 KV Cache 也会发生分歧。
*   **瓶颈**：这使得传统的高效技术“前缀缓存（Prefix Caching）”失效，系统必须为每个智能体维护独立的、冗余的 KV Cache，导致 GPU 显存迅速耗尽，严重限制了并发处理能力和吞吐量。

### 2. 方法论
ForkKV 借鉴了操作系统中进程创建的 **Fork 与写时复制（Copy-on-Write, CoW）** 机制，提出了一种解耦的 KV 缓存管理范式。
*   **核心思想**：将 KV Cache 物理上解耦为两部分：
    1.  **基础缓存 (bCache)**：由基础模型权重 $W$ 生成（$xW$），体积巨大且在不同智能体间共享。
    2.  **残差缓存 (rCache)**：由 LoRA 的下投影矩阵 $A$ 生成（$xA$），体积微小（通常仅为 bCache 的 1/64），为智能体私有。
*   **关键技术**：
    *   **DualRadixTree 架构**：使用两个基数树分别管理共享的 bCache（按 Token 索引）和私有的 rCache（按 Token+智能体 ID 索引）。新智能体启动时，通过 Fork 语义继承父辈的 bCache，并仅为自己的 rCache 分配空间。
    *   **解耦驱逐策略**：为两棵树分配独立的 LRU 状态，允许在显存压力下灵活置换，提高缓存命中率。
    *   **ResidualAttention 内核**：为了避免在显存（HBM）中重构完整 KV Cache 带来的开销，设计了定制化 Triton 算子。该算子在片上 SRAM 中实时重构 Key，并利用矩阵结合律（Matrix Associativity）将 Value 的 LoRA 上投影操作推迟到注意力计算的最后阶段，从而保持高并行度。

### 3. 实验设计
*   **数据集/场景**：
    *   **ReAct**：模拟顺序推理工作流，使用 LooGLE（长文档问答）、NarrativeQA（阅读理解）和 APIGen（工具调用）数据集。
    *   **MapReduce**：模拟并行处理工作流，使用上述相同数据集。
*   **Benchmark 模型**：Llama3-8B、Qwen2.5-7B、Qwen2.5-14B。

### 5. 实验数量与充分性
*   **实验规模**：涵盖了 3 种不同规模的模型、3 个不同领域的长上下文数据集、2 种典型智能体工作流。
*   **维度**：包括端到端吞吐量测试、请求到达率敏感性分析、LoRA Rank 敏感性分析、输出长度敏感性分析，以及关键的生成质量（F1-Score）验证。

### 6. 主要结论与发现
*   **吞吐量提升**：在 ReAct 工作流中，ForkKV 实现了 **1.25x 至 3.04x** 的吞吐量提升；在 MapReduce 工作流中提升了 **1.68x 至 2.60x**。
*   **显存效率**：相比传统前缀缓存，ForkKV 将每个智能体的平均显存占用降低了约 **12.7 倍**，从而允许更大的 Batch Size（提升约 12 倍）。
*   **质量保持**：尽管解耦 KV Cache 在数学上对后续层是近似的，但实验证明其精度损失极小（平均 F1 分数仅下降 **0.71%**），远优于完全共享策略。

### 7. 优点
*   **跨学科创新**：巧妙地将操作系统的经典内存管理概念（Fork/CoW）引入 LLM 推理系统。
*   **软硬协同设计**：不仅有高层的数据结构创新（DualRadixTree），还有底层的硬件感知内核优化（ResidualAttention），解决了重构开销问题。
*   **实用性强**：直接针对当前热门的多智能体协作场景，解决了实际部署中的显存瓶颈。

### 8. 不足与局限
*   **低负载开销**：在并发量极低、显存充足的情况下，由于 ResidualAttention 涉及额外的计算逻辑，其性能可能略低于标准算子（文中提到可通过自适应调度缓解）。
*   **近似计算风险**：虽然在测试数据集上表现良好，但在某些对激活值极其敏感的特定任务中，跨层累积的微小误差是否会演变成严重的幻觉仍需更广泛的验证。
*   **LoRA 依赖**：该系统专门针对 LoRA 架构设计，对于全参数微调或其他非线性适配器结构的适用性有限。
