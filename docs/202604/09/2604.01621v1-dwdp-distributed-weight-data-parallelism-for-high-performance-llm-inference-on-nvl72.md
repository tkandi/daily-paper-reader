## 摘要
大语言模型（LLM）推理日益依赖多 GPU 执行，然而现有的推理并行化策略需要逐层的 rank 间同步，使得端到端性能对工作负载不平衡非常敏感。我们提出了 DWDP（分布式权重数据并行），这是一种推理并行化策略，它在保持数据并行执行的同时，将 MoE 权重卸载到对等 GPU 上，并根据需要获取缺失的专家。通过消除集合通信的 rank 间同步，DWDP 允许每个 GPU 独立运行。我们通过针对分割权重管理和异步远程权重预取的两项优化，进一步解决了该设计的实际开销。在 TensorRT-LLM 中实现并在 GB200 NVL72 上使用 DeepSeek-R1 进行评估，在 8K 输入序列长度和 1K 输出序列长度下，在 20-100 TPS/user 的服务范围内，DWDP 在相当的 TPS/user 下将端到端输出 TPS/GPU 提高了 8.8%。

## Abstract
Large language model (LLM) inference increasingly depends on multi-GPU execution, yet existing inference parallelization strategies require layer-wise inter-rank synchronization, making end-to-end performance sensitive to workload imbalance. We present DWDP (Distributed Weight Data Parallelism), an inference parallelization strategy that preserves data-parallel execution while offloading MoE weights across peer GPUs and fetching missing experts on demand. By removing collective inter-rank synchronization, DWDP allows each GPU to progress independently. We further address the practical overheads of this design with two optimizations for split-weight management and asynchronous remote-weight prefetch. Implemented in TensorRT-LLM and evaluated with DeepSeek-R1 on GB200 NVL72, DWDP improves end-to-end output TPS/GPU by 8.8% at comparable TPS/user in the 20-100 TPS/user serving range under 8K input sequence length and 1K output sequence length.

*   **整体含义**：本文提出了一种名为 **DWDP** 的新策略，旨在通过消除层间集体同步，让每个GPU能够独立、异步地执行推理任务，从而解决负载不平衡带来的效率损失。

#### 2. 论文提出的方法论
*   **核心思想**：保持数据并行（DP）的执行模式，但将MoE层的专家权重分布式存储在组内对等GPU上。在推理时，GPU根据需要异步“拉取”（Pull）缺失的专家权重，而不是通过集合通信进行同步交换。
*   **关键技术细节**：
    *   **异步预取流水线**：利用当前层的计算时间（MoE块）和下一层的注意力计算时间作为窗口，提前异步预取下一层所需的远程专家权重。
    *   **P2P 权重拉取**：放弃基于NCCL的集合通信，改用基于拷贝引擎（Copy Engine）的 `cudaMemcpyAsync` 进行点对点拉取，不占用SM（流式多处理器）资源。

    *   **时分复用（TDM）调度**：为了解决多个GPU同时向同一个源GPU请求权重导致的“多对一”竞争，将传输切分为固定大小的切片（Slice），并采用轮询（Round-robin）调度，提高通信流水线的利用率。

#### 7. 优点
*   **架构创新**：打破了传统并行策略必须同步的思维定式，利用 Blackwell 架构的高带宽 NVLink 实现了“以通信换异步”。
*   **工程落地性强**：在 TensorRT-LLM 中实现，并针对内存布局和通信竞争进行了深度优化，具有实际部署价值。

#### 8. 不足与局限
*   **TTFT 权衡**：实验显示，虽然吞吐量提升，但在某些配置下首字延迟（TTFT）会有所增加，这可能影响对延迟极度敏感的应用。
*   **硬件依赖**：该策略高度依赖极高带宽的对等通信（如 NVLink 5），在带宽较低的集群（如仅有 PCIe 或低速以太网）上可能无法掩盖权重预取的开销。
*   **适用场景限制**：主要针对 Context（Prefill）阶段优化，在计算量较小的 Decoding 阶段，计算窗口可能不足以掩盖权重预取延迟。
