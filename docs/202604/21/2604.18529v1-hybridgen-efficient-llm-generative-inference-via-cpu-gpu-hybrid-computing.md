## 摘要
随着现代大语言模型（LLM）支持数千到数百万个 token，KV 缓存（KV cache）增长到数百 GB，给内存容量和带宽带来了巨大压力。现有的解决方案（如 KV 缓存剪枝和卸载）虽然缓解了这些问题，但由于仅依赖 GPU 或 CPU 进行注意力计算，且仅考虑有限的 CPU 本地内存用于 KV 缓存存储，导致硬件利用率不足。我们提出了 HybridGen，这是一个用于长上下文 LLM 推理的高效混合注意力框架。HybridGen 在具有扩展分级内存（如 CXL 内存）的系统上实现了 CPU-GPU 协同注意力计算，解决了三个关键挑战：(1) 多维注意力依赖关系，(2) 随序列长度增加而加剧的 CPU-GPU 负载不平衡，以及 (3) 分级内存的 NUMA 惩罚。HybridGen 通过引入注意力 Logit 并行（attention logit parallelism）、反馈驱动的调度器以及语义感知的 KV 缓存映射来解决这些问题。在三个配备 CXL 扩展内存的 GPU 平台上，针对三种 LLM 模型、十一种不同规模进行的实验表明，HybridGen 在保持卓越准确性的同时，平均性能优于六种最先进的 KV 缓存管理方法 1.41 倍至 3.2 倍。

## Abstract
As modern LLMs support thousands to millions of tokens, KV caches grow to hundreds of gigabytes, stressing memory capacity and bandwidth. Existing solutions, such as KV cache pruning and offloading, alleviate these but underutilize hardware by relying solely on either GPU or CPU for attention computing, and considering yet limited CPU local memory for KV cache storage. We propose HybridGen, an efficient hybrid attention framework for long-context LLM inference. HybridGen enables CPU-GPU collaborative attention on systems with expanded tiered memory (e.g., CXL memory), addressing three key challenges: (1) multi-dimensional attention dependencies, (2) intensifying CPU-GPU load imbalance with longer sequences, and (3) NUMA penalty of tiered memories. HybridGen tackles these by introducing attention logit parallelism, a feedback-driven scheduler, and semantic-aware KV cache mapping. Experiments with three LLM models with eleven different sizes on three GPU platforms with a CXL-expanded memory show that HybridGen outperforms six state-of-the-art KV cache management methods by 1.41x--3.2x on average while maintaining superior accuracy.

### 1. 核心问题与研究动机
*   **核心问题**：现代 LLM 支持的上下文长度已达百万级，导致 KV 缓存（KV Cache）体积激增（可达数百 GB），远超 GPU 显存容量。
*   **研究动机**：
    *   **现有方案的局限**：传统的“卸载（Offloading）”方案将 KV 缓存存放在 CPU 内存，但计算仍依赖 GPU，导致海量数据传输开销；“剪枝（Pruning）”方案虽然减少了内存占用，但会显著降低模型精度。
    *   **硬件利用率低**：现有的卸载框架通常只利用 GPU 或只利用 CPU 进行注意力计算，导致另一方处于闲置状态。
    *   **新型硬件挑战**：新兴的分层内存（如 CXL 内存）虽然扩展了容量，但其非一致性内存访问（NUMA）延迟会严重拖慢推理速度。

### 2. 方法论：HybridGen 核心技术
HybridGen 的核心思想是实现 **CPU 与 GPU 的协同注意力计算**，并利用分层内存扩展存储。

*   **注意力 Logit 并行（Attention Logit Parallelism）**：
    *   将注意力计算解耦：CPU 负责计算其本地内存中（旧 token）的注意力 Logit（$Q \cdot K^T$），GPU 负责计算显存中（新 token）的 Logit。
    *   **跨层流水线**：利用相邻 Transformer 层输入之间的高度相似性，让 CPU 在 GPU 处理第 $i$ 层时，提前使用第 $i$ 层的输入预计算第 $i+1$ 层的 Logit，从而掩盖计算延迟。
*   **反馈驱动调度器（Feedback-driven Scheduler）**：
    *   动态调整 CPU 的工作负载：根据运行时延迟反馈，自动调整 CPU 处理的 token 数量（$K$ 值）。
    *   **策略切换**：在“精度优先”（计算所有卸载 token 的 Logit 后选 Top-K）和“性能优先”（仅计算预测的重要 token 的 Logit）之间动态切换，确保 CPU 不会成为流水线瓶颈。
*   **语义感知 KV 缓存映射（Semantic-aware KV Mapping）**：
    *   针对 CXL 内存优化：由于 CPU 计算 Logit 只需访问 Key（K）向量，而 Value（V）向量仅需传输给 GPU。
    *   **策略**：将 K 向量保留在较快的 CPU 本地 DRAM 中，将 V 向量存放在较慢的 CXL 内存中，从而将 CXL 的高延迟从计算关键路径中移除。
