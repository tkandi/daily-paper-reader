## 摘要
未来分布式机器学习系统的设计空间探索面临着缺乏现成工作负载表示的问题，而这种表示应能支持跨技术栈的灵活探索。我们提出了 Flint，这是一个通过利用机器学习框架编译器的中间表示（IR）来填补这一空白的框架。编译器承担了理解并保留原始模型代码行为的繁重工作。由于 Flint 在硬件执行之前与编译器进行交互，因此它可以收集任意集群规模的工作负载表示。我们通过执行后的追踪记录验证了工作负载图，并通过一个设计空间探索案例研究展示了 Flint 的灵活性。

## Abstract
Design space exploration for future distributed Machine Learning systems suffers from a lack of readily available workload representation that enables flexible exploration across the stack. We present Flint, a framework that bridges this gap by leveraging the Intermediate Representation of Machine Learning framework compilers. The compiler does the heavy weight lifting of understanding and preserving the behavior of the original model code. Flint can collect the workload representation of arbitrary cluster size because it interfaces with the compiler before hardware execution. We validate the workload graph against post-execution traces and show the flexibility of Flint through a design space exploration case study.

*   **核心思想**：利用机器学习框架（如 PyTorch）编译器的**中间表示（IR）**。编译器在执行前已经理解了模型的计算逻辑和数据依赖，Flint 通过接入编译器后端来捕获这些信息。

    *   **真实依赖保留**：与截获 CUDA API 的方法不同，Flint 保留了原始的数据依赖关系，允许研究人员探索算子重排序和通信掩盖（Overlap）等调度优化。

### 6. 主要结论
*   **高保真度**：Flint 生成的工作负载图在算子分布和端到端性能预测上与真实执行追踪高度吻合。

### 7. 优点
*   **低门槛**：极大地降低了学术界和工业界进行大规模分布式系统研究的硬件门槛。

*   **标准化**：采用 Chakra 标准格式，能够无缝对接现有的分布式系统模拟生态。
*   **深度优化支持**：由于保留了数据依赖，支持对编译器级别的调度优化进行深入探索。

### 8. 不足与局限
*   **编译器依赖**：目前主要针对 PyTorch 的 FX Graph，对其他框架（如 JAX）的支持尚在构想阶段。
*   **图断裂问题（Graph Breaks）**：受限于 `torch.compile` 的成熟度，如果模型代码中包含大量不支持的 Python 特性（如复杂控制流），可能会导致图捕获不完整。
*   **算子库差异**：某些底层算子的分解（Decomposition）可能与特定硬件厂商的闭源库（如 cuBLAS）存在微小差异，影响极高精度下的模拟。
*   **手动适配**：对于某些特殊的算子（如 SDPA），仍需要对 PyTorch API 进行少量的手动修改以确保其在 Meta Device 上正确分发。
