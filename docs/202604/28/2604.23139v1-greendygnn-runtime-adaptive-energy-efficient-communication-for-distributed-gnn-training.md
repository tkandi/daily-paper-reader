## 摘要
分布式 GNN 训练主要受限于远程特征获取，其成本可能非常高昂。多跳邻居采样跨越了分区边界，并触发了细粒度的远程过程调用（RPC），其固定的启动成本和 GPU 停顿延迟会浪费能源。先前的系统尝试通过预采样和静态缓存来减少这种开销，但缓存策略无法应对运行时的网络变化。我们展示了在随时间变化的拥塞情况下，由于固定的重建计划不足，静态缓存可能会使能耗增加高达 45%。我们提出了 GreenDyGNN，它将缓存窗口管理建模为一个序列决策问题。GreenDyGNN 执行周期内（intra-epoch）缓存重建，并使用一个在具有领域随机化拥塞的校准模拟器中训练的 Double-DQN 智能体，在每个边界处自适应调整重建窗口大小和每个所有者的缓存分配。异步双缓冲流水线使得这种自适应几乎不产生额外开销。在拥塞情况下，GreenDyGNN 相比默认的 DGL 可降低高达 43% 的总能耗，相比最佳静态策略可降低 4-24%，同时在无拥塞条件下能紧密匹配最优性能。

## Abstract
Distributed GNN training is dominated by remote feature fetching, which can be very costly. Multi-hop neighborhood sampling crosses partition boundaries and triggers fine-grained RPCs whose fixed initiation cost and GPU-stall latency waste energy. Prior systems try to reduce this overhead with presampling and static caching, but cache policies cannot react to runtime network variation. We show that under time-varying congestion, static caching can increase energy by up to 45% because a fixed rebuild schedule is insufficient. We present GreenDyGNN, which formulates cache window management as a sequential decision problem. GreenDyGNN performs intra-epoch cache rebuilds and uses a Double-DQN agent, trained in a calibrated simulator with domain-randomized congestion, to adapt rebuild window size and per-owner cache allocation at each boundary. An asynchronous double-buffered pipeline makes adaptation effectively free. Under congestion, GreenDyGNN cuts total energy by up to 43% over Default DGL and 4-24% over the best static policy, while closely matching the optimum under clean conditions.

#### 1. 核心问题与研究动机
分布式图神经网络（GNN）训练的性能和能效主要受限于**远程特征获取（Remote Feature Fetching）**。
*   **高昂的启动成本**：GNN 的多跳邻居采样会触发大量细粒度的 RPC 调用。实验表明，在典型的采样规模下，RPC 的启动开销（中断处理、协议栈延迟等）占总能耗的 90%–99%。
*   **GPU 能源浪费**：当 CPU 线程等待远程特征返回时，GPU 处于近乎闲置状态但仍消耗大量功率（40W–80W），形成“能耗空洞”。
*   **静态策略的局限性**：现有的缓存策略（如 RapidGNN）通常在每个 Epoch 开始前固定缓存内容和重建频率。然而，共享集群中的网络拥塞是动态变化的，静态策略无法在运行时调整，导致在拥塞时能耗增加高达 45%–60%。

#### 2. 方法论
GreenDyGNN 将缓存窗口管理建模为一个**马尔可夫决策过程（MDP）**，通过强化学习实现运行时自适应控制。
*   **核心思想**：在训练过程中动态调整两个关键参数：**缓存重建窗口大小 $W$**（决定了摊销启动成本与缓存新鲜度之间的平衡）和**按所有者分配的缓存比例**（将更多缓存空间分配给网络延迟高的节点）。
*   **关键技术细节**：
    *   **Double-DQN 智能体**：观测当前网络拥塞倍率、缓存命中率、系统负载比等状态，输出最优的窗口大小和分配模板。
    *   **校准模拟器与领域随机化**：为了避免在真实集群上进行昂贵的 RL 训练，作者开发了一个基于真实 RPC 延迟和功率数据校准的轻量级模拟器，并利用领域随机化（Domain Randomization）模拟各种复杂的拥塞模式，实现“从模拟到现实（Sim-to-Real）”的策略迁移。
    *   **异步双缓冲流水线**：设计了三阶段流水线（采样、缓存构建、特征解析），通过双缓冲区（Active/Pending）实现缓存重建与 GPU 训练的解耦，使得 RL 决策和数据预取对训练主路径几乎零开销。

#### 3. 实验设计
*   **数据集**：Reddit（社交网络）、OGBN-Products（亚马逊商品图）、OGBN-Papers100M（超大规模论文引用图）。
*   **对比方法（Benchmarks）**：
    *   **Default DGL**：原生分布式 DGL，采用按需获取特征。
    *   **BGL**：优化了 GPU I/O 和预取的系统。
    *   **RapidGNN**：目前最先进的静态缓存策略（Epoch 级别缓存）。
*   **实验场景**：分为“清洁网络（Clean）”和“动态拥塞（Congested）”两种环境。拥塞通过 Linux `tc netem` 注入，模拟 15-25ms 的随机链路延迟。

#### 4. 资源与算力
*   **硬件环境**：4 节点的 Chameleon Cloud 集群。每节点配备 Intel Xeon CPU、**2 块 NVIDIA P100 GPU** 以及 25 Gbps 以太网。
*   **训练时长**：
    *   **模拟器校准**：约 15 分钟收集数据。
    *   **RL 智能体训练**：在单核 CPU 上约 20 分钟即可完成 50,000 个 Episode 的训练。
    *   **推理开销**：RL 策略模型仅 400 KB，推理延迟在微秒级，相对于毫秒级的 RPC 延迟可忽略不计。

#### 5. 实验数量与充分性
*   **实验规模**：涵盖了 3 个不同规模的数据集、3 种 Batch Size（1000, 2000, 3000）以及多种网络条件，共计几十组完整的训练运行。
*   **消融实验**：专门设计了实验验证“无 RL 适应”和“无成本权重分配”的情况，证明了动态窗口调整是节能的主要贡献者。
*   **客观性**：实验不仅测量了总能耗，还细分了 CPU 和 GPU 的能耗占比，并验证了模型准确率未受影响，确保了对比的公平性。

#### 6. 主要结论与发现
*   **显著节能**：在拥塞环境下，GreenDyGNN 相比 Default DGL 降低了 **28%–43%** 的总能耗；相比最强的静态策略 RapidGNN，节能 **4%–24%**。
*   **吸收拥塞开销**：在最大规模的 Papers100M 数据集上，GreenDyGNN 吸收了静态策略无法处理的 26 个百分点的拥塞能耗增量。
*   **性能保持**：在无拥塞的理想网络下，GreenDyGNN 的表现与最优静态策略持平，证明其自适应机制不会引入负面扰动。
*   **收敛加速**：由于减少了远程等待时间，GreenDyGNN 在相同时间内达到了更高的模型准确率。

#### 7. 优点
*   **运行时自适应**：首次将分布式 GNN 的通信优化从静态配置提升到动态闭环控制。
*   **能效导向**：不同于以往仅关注吞吐量的系统，该方法直接针对 GPU 闲置能耗和 RPC 启动能耗进行优化。
*   **低部署门槛**：通过 Sim-to-Real 技术，用户无需在真实集群上长时间训练 RL 模型，校准过程简单快速。

#### 8. 不足与局限
*   **硬件覆盖有限**：实验主要基于较旧的 NVIDIA P100 GPU 和 25Gbps 网络，未测试最新的 H100/A100 GPU 或 100Gbps+ 的 RDMA 网络，在极高性能互联环境下的增益可能收窄。
*   **分区依赖性**：虽然 GreenDyGNN 在 METIS 分区上表现良好，但未深入探讨不同分区算法（如随机分区或高度不平衡分区）对 RL 策略收敛性的影响。
*   **多租户复杂性**：实验中的拥塞是人工注入的，真实数据中心中多作业竞争导致的复杂网络抖动可能比模拟的模式更难预测。
