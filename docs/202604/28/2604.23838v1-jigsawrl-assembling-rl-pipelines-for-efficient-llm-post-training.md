## Abstract
We present JigsawRL, a cost-efficient framework that explores Pipeline Multiplexing as a new dimension of RL parallelism. JigsawRL decomposes each pipeline into a Sub-Stage Graph that exposes the intra-stage and inter-worker imbalance hidden by stage-level systems. On this abstraction, JigsawRL resolves multiplexing interference through dynamic resource allocation, eliminates fragmented utilization by migrating long-tail rollouts across workers, and formulates their coordination as a graph scheduling problem solved with a look-ahead heuristic. On 4-64 H100/A100 GPUs across different agentic RL pipelines and models, JigsawRL achieves up to 1.85x throughput over Verl on synchronous RL, 1.54x over StreamRL and AReaL on asynchronous RL, and supports heterogeneous pipelines with moderate latency trade-off.

### 1. 核心问题与整体含义（研究动机和背景）
*   **核心问题**：现有的 RL 训练框架（如 Verl, OpenRLHF）主要关注时间效率，而忽视了**成本效率**。
*   **研究动机**：作者发现，由于 RL 训练中的“生成（Rollout）”阶段存在严重的负载不均衡（长尾序列、多轮对话、工具调用导致的 GPU 空闲），GPU 的平均利用率（MFU）通常低于 10%。随着 GPU 规模扩大，这种不均衡进一步加剧，导致极高的计算成本和资源浪费。
*   **整体含义**：JigsawRL 提出了一种新的并行维度——**流水线复用（Pipeline Multiplexing）**，通过在同一组 GPU 上并发执行多个 RL 任务，利用不同阶段的资源互补性来填补利用率低谷。

### 2. 方法论：核心思想与关键技术
JigsawRL 将 RL 流水线建模为**子阶段执行图（Sub-Stage Execution Graph）**，并实施以下核心技术：
*   **子阶段图抽象**：将粗粒度的阶段（如 Rollout, Training）分解为细粒度的子阶段（如 Prefill, Decoding, Tool-calling）。这揭示了阶段内部和工作节点（Worker）之间的不平衡。
*   **子阶段复用（Sub-stage Multiplexing）**：
    *   **动态资源分配**：利用 NVIDIA MPS 或 Green Context 对计算资源（SM）进行切分。
    *   **互补调度**：将计算密集型（如 Training）与内存绑定型（如长尾 Decoding）子阶段配对执行，减少资源竞争。
*   **子阶段合并（Sub-stage Merging）**：
    *   **长尾样本迁移**：当部分 Worker 进入低利用率的长尾生成阶段时，将样本迁移到少数 Worker 上合并执行，释放其余 Worker 的资源供其他流水线使用。
*   **前瞻性调度（Look-ahead Scheduling）**：使用启发式算法预测未来几个步骤的资源需求，在关键路径上优化子阶段的组合和资源分配，以最小化总完成时间。

### 6. 主要结论与发现
*   **吞吐量提升**：相比同步基准 Verl，JigsawRL 实现了高达 **1.85倍** 的吞吐量提升；相比异步基准 StreamRL/AReaL，提升达 **1.54倍**。
*   **成本效率**：通过提高 MFU（利用率提升约 1.5-1.7倍），显著降低了单位 Token 的训练成本。
*   **延迟权衡**：虽然吞吐量大幅提升，但单步延迟仅增加 1.14x-1.48x，远优于串行执行两个任务（2x 延迟）。
*   **扩展性**：在 64 块 GPU 规模下依然保持显著优势，证明了其在大规模生产环境中的潜力。

### 7. 优点
*   **创新维度**：开辟了“流水线复用”这一新的 RL 并行优化方向，打破了单流水线优化的瓶颈。
*   **精细化管理**：子阶段图的抽象比传统的阶段级调度更贴合 RL 任务的动态特性。
*   **灵活性**：支持异构模型并发，且能与现有的数据并行（DP）、张量并行（TP）等技术无缝集成。

### 8. 不足与局限
*   **模型架构限制**：目前主要针对稠密（Dense）模型进行了优化，尚未深入探讨混合专家模型（MoE）在复用时的专家负载不均问题。
*   **离线分析依赖**：虽然有步间一致性假设，但仍需要一定的初始分析（Profiling）成本来构建资源消耗模型。
*   **延迟敏感性**：对于极度追求单次迭代延迟（而非总吞吐量）的科研场景，复用带来的延迟增加可能是一个负面因素。
