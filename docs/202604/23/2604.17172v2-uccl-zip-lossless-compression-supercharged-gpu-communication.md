## 摘要
大语言模型（LLM）的快速增长使 GPU 通信成为关键瓶颈。虽然先前的工作通过量化或有损压缩来减少通信量，但这些方法引入了数值误差，可能会降低收敛性、准确性和稳定性。我们提出了 UCCL-Zip，这是一种将无损压缩直接集成到 GPU 通信原语中的统一设计。UCCL-Zip 支持点对点（P2P）和集合通信，且无需修改面向用户的 API 或牺牲数值正确性。对于 P2P 通信，Uzip-P2P 采用了一种拆分发送流水线，能够尽早暴露可传输数据，并将压缩与通信重叠，同时通过在大数据块上操作来保持高 GPU 效率。对于集合通信，Uzip-NCCL 通过融合执行将压缩集成到 NCCL 的持久内核模型中，消除了冗余的内存流量和内核启动。在实际工作负载中，UCCL-Zip 将强化学习（RL）权重同步加速了高达 47.5%，并将 vLLM 端到端推理延迟降低了高达 10%，且无需对应用程序进行任何更改。

## Abstract
The rapid growth of large language models (LLMs) has made GPU communication a critical bottleneck. While prior work reduces communication volume via quantization or lossy compression, these approaches introduce numerical errors that can degrade convergence, accuracy, and stability. We present UCCL-Zip, a unified design that integrates lossless compression directly into GPU communication primitives. UCCL-Zip supports both point-to-point (P2P) and collective communication without modifying user-facing APIs or compromising numerical correctness. For P2P communication, Uzip-P2P employs a split-send pipeline that exposes transmissible data early and overlaps compression with communication, while preserving high GPU efficiency by operating on large data blocks. For collective communication, Uzip-NCCL integrates compression into NCCL's persistent kernel model via fused execution, eliminating redundant memory traffic and kernel launches. In real workloads, UCCL-Zip accelerates RL weight synchronization by up to 47.5% and reduces vLLM end-to-end inference latency by up to 10%, all without application changes.

随着大语言模型（LLM）规模和上下文长度的激增，多节点、多 GPU 间的通信（如梯度交换、KV Cache 传输、权重同步）已成为系统性能的关键瓶颈。
*   **现有方案的缺陷**：目前的通信优化多采用量化或有损压缩，这会引入数值误差，导致模型收敛变慢、精度下降或推理不稳定。
*   **无损压缩的挑战**：虽然无损压缩能保证数值正确性，但在 GPU 上实现时面临两大难题：
    1.  **延迟抵消增益**：GPU 压缩延迟随数据量减小的缩放并不线性，小块压缩效率极低，导致压缩时间往往抵消了节省的传输时间。
    2.  **架构不兼容**：主流通信库（如 NCCL）采用持久内核和细粒度流水线，而传统压缩算法需要全局统计信息和多次内存读写，难以高效集成。

### 2. 方法论：核心思想与关键技术
UCCL-Zip 提出了一个统一框架，将基于 ANS（非对称数字系统）的无损压缩直接嵌入 GPU 通信原语中。

*   **Uzip-P2P（点对点通信优化）**：
    *   **拆分发送流水线（Split-Send Pipeline）**：利用浮点数结构特性，将张量拆分为“不压缩部分”（符号和尾数）和“待压缩部分”（指数）。
    *   **早期数据暴露**：在压缩的第一阶段完成后，立即发送占比较大的不压缩部分，使网络传输与后续耗时的压缩计算（Step 2 & 3）实现重叠，最大化带宽利用率。
*   **Uzip-NCCL（集合通信优化）**：
    *   **局部频率表（Localized Frequency Tables）**：放弃构建全局频率表，改为每个线程块（CTA）通过局部采样构建自己的频率表。这消除了跨块同步，允许将压缩逻辑融合进单个内核。
    *   **内核融合（Kernel Fusion）**：将压缩/解压逻辑直接嵌入 NCCL 的数据处理层（如 `CopyReducePacks`），减少了全局内存访问次数（从 3 次降至 1 次），并消除了额外的内核启动开销。
*   **多格式支持**：扩展了 DietGPU 算法，支持 BF16、FP16、FP32 以及最新的 FP8（E4M3/E5M2）格式。
