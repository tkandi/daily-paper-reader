## 摘要
混合专家（MoE）架构在现代大语言模型和多模态模型中得到了广泛应用。然而，推理效率往往受到不同模态间高度动态且倾斜的专家工作负载的限制。在大批量预填充阶段，视觉 token 经常在输入序列中占据主导地位。在专家并行（EP）模式下，这会导致严重的负载不均衡，部分设备会过载，从而降低整体系统吞吐量。我们提出了 ReaLB，一种用于多模态 MoE（MMoE）推理的实时负载均衡方法，该方法引入了零调度开销。ReaLB 在运行时根据每个 EP 秩（rank）动态调整 MoE 专家的计算精度。对于由视觉密集型专家主导的秩，ReaLB 通过利用 FP4 Tensor Core 分配低精度计算以提高执行效率。ReaLB 不需要冗余专家或额外的内存分配。相反，它在运行时执行逐层专家精度转换，并将相关开销隐藏在 MoE 计算前的分发（dispatch）阶段。在代表性 MMoE 模型上的实验表明，ReaLB 实现了 1.29 倍的层级加速，同时将精度损失限制在 1.2% 以内。

## Abstract
Mixture-of-Experts (MoE) architectures are widely used in modern large language models and multimodal models. However, inference efficiency is often limited by highly dynamic and skewed expert workloads across different modalities. During the prefill stage with large batch sizes, vision tokens frequently dominate the input sequences. Under expert parallelism (EP), this leads to severe load imbalance, where a subset of devices becomes overloaded, reducing overall system throughput.   We propose ReaLB, a real-time load balancing method for multimodal MoE (MMoE) inference that introduces zero scheduling overhead. ReaLB dynamically adjusts the computation precision of MoE experts at runtime on a per-EP-rank basis. For ranks dominated by vision-heavy experts, ReaLB assigns lower-precision computation to improve execution efficiency by exploiting FP4 Tensor Cores. ReaLB does not require redundant experts or additional memory allocation. Instead, it performs layer-wise expert precision transformation on the fly and hides the associated overhead within the dispatch phase before MoE computation. Experiments on representative MMoE models show that ReaLB achieves 1.29x layer-level speedup while limiting accuracy loss to within 1.2%.

混合专家模型（MoE）在多模态大模型（MMoE）中应用广泛，但在专家并行（Expert Parallelism, EP）推理时面临严重的**负载失衡**问题。
*   **研究动机**：在多模态任务（如图像理解）的预填充阶段，视觉 Token 数量远超文本 Token，且路由分布极度倾斜，导致某些 GPU（Rank）成为性能瓶颈（Stragglers）。
*   **现有局限**：传统的负载均衡方法（如 EPLB）依赖历史预测来迁移专家，但 MMoE 的路由模式具有高度动态性，预测往往滞后且准确度低，同时专家迁移会带来额外的内存和通信开销。

#### 2. 论文提出的方法论：ReaLB
ReaLB 提出了一种**实时、模态感知且零开销**的负载均衡机制，核心思想是通过动态调整计算精度来平衡执行时间。
*   **实时模态感知调度**：在每一层 MoE 计算前，系统实时统计各 Rank 的 Token 负载。若某 Rank 负载超过平均值且视觉 Token 占比高（视觉 Token 对精度相对不敏感），则将其标记为“热点”。
*   **动态精度缩放**：针对热点 Rank，ReaLB 在运行时将其计算精度从 BF16 降低到 **FP4**，利用 Blackwell 架构（如 RTX 5090）的 FP4 Tensor Core 实现约 4 倍的理论算力提升，从而加速慢速节点。
*   **流水线编排（Pipeline Orchestration）**：为了消除精度转换（BF16 到 FP4）的开销，ReaLB 将**权重转换操作**与 MoE 的 **All-to-All Dispatch 通信阶段**进行重叠（Overlap），从而在关键路径上实现零延迟。
*   **自适应激活**：仅在计算密集型（大 Batch Size）场景下激活 ReaLB，避免在通信密集型的小 Batch 场景下引入不必要的调度逻辑。

#### 3. 实验设计
*   **实验模型**：选取了三个代表性的开源 MMoE 模型：Kimi-VL-A3B、Qwen3-VL-30B 和 ERNIE-4.5-VL-27B。
*   **数据集/评测集**：涵盖了 RealWorldQA、AI2D、InfoVQA、TextVQA、MMMU、MMBench 等 6 个主流视觉语言基准测试，以及 DynaMath 和 MathVista 用于敏感度分析。
*   **对比方法（Baselines）**：
    *   **Baseline**：全 BF16 精度执行。
    *   **FP4-All**：所有专家统一使用 FP4 精度。
    *   **EPLB / Async EPLB**：基于预测和专家复制/迁移的传统负载均衡方法。
    *   **ReaLB-seq**：不使用流水线重叠的 ReaLB 变体。

#### 5. 实验数量与充分性
*   **实验规模**：作者在 3 个不同架构的模型上进行了测试，涵盖了模态融合（Modality-fused）和模态隔离（Modality-isolated）两种 MoE 设计。
*   **维度覆盖**：实验包括了层级延迟分析、端到端吞吐量对比、不同任务下的精度损失评估，以及针对模态阈值（$M_d$）的敏感度消融实验。
*   **充分性评价**：实验设计较为全面，不仅验证了性能提升，还深入探讨了精度与效率的权衡（Trade-off），对比了多种 SOTA 方法，结果具有较强的说服力和客观性。

#### 6. 论文的主要结论与发现
*   **性能提升**：ReaLB 实现了平均 **1.29 倍**的 MoE 层级加速，端到端吞吐量提升最高达 **1.53 倍**。
*   **精度保持**：相比于全量 FP4 导致的显著精度下降，ReaLB 通过仅对视觉密集型热点进行降精度，将平均精度损失控制在 **1.2%** 以内，部分任务甚至无损。
*   **实时性优势**：ReaLB 能够完美追踪 MMoE 剧烈波动的路由变化，而基于预测的 EPLB 在动态场景下表现不佳，甚至可能因调度开销导致性能下降。

#### 7. 优点
*   **零内存开销**：不需要像专家复制方法那样占用额外的显存来存储冗余专家。
*   **零调度开销**：通过巧妙的流水线设计隐藏了量化延迟。
*   **硬件友好**：充分利用了新一代 GPU 的低精度硬件加速特性。
*   **模态感知**：利用了视觉 Token 的冗余性，实现了比通用量化更精细的控制。

#### 8. 不足与局限
*   **硬件依赖**：该方法高度依赖支持 FP4 加速的硬件（如 NVIDIA Blackwell 架构），在旧款 GPU 上无法发挥作用。
*   **精度风险**：虽然平均损失小，但在某些对数值极其敏感的任务（如 RealWorldQA）中仍有约 3% 的精度波动。
*   **阈值调优**：模态阈值 $M_d$ 目前仍需手动配置，虽然实验证明其相对稳定，但未来若能实现全自动自适应调整会更具鲁棒性。
