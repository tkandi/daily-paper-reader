## 摘要
集合通信在 LLM 工作负载中产生了显著开销。尽管在应用层将通信与计算重叠是一种常用策略，但它通常需要大量的代码修改，且对于许多工作负载（如张量并行和专家并行）而言并不切实际。我们提出了 CCCL，这是一个内置的基于压缩的集合通信库，支持 allreduce、alltoall 和 send/recv 等操作，无需用户侧进行任何更改，从而能够在现有应用中实现无缝采用。CCCL 紧密融合了压缩算子以最小化内存访问，并与 NCCL 集成以消除数据合并阶段，使其速度足够快（最高可达 NVLink 带宽的 3 倍）以维持通信。我们的评估表明，CCCL 在 vLLM PD 解耦工作负载中将端到端吞吐量提高了多达 10.1%，在微基准测试中将吞吐量提高了多达 30%。

## Abstract
Collective communication incurs significant overhead in LLM workloads. Although overlapping communication with computation in application-level is a common strategy, it often requires substantial code modifications and is impractical for many workloads (e.g., tensor and expert parallelism). We present CCCL, a built-in compression-based collective communication library that supports operations such as allreduce, alltoall, and send/recv without requiring any user-side changes, thereby enabling seamless adoption in existing applications. CCCL tightly fuses compression kernels to minimize memory accesses and integrates with NCCL to eliminate the data coalescing stage, making it fast enough (up to 3x NVLink bandwidth) to sustain communication. Our evaluation shows that CCCL improves end-to-end throughput in vLLM PD disaggregation workloads by up to 10.1% and microbenchmark throughput by up to 30%.

*   **通信瓶颈：** 随着 LLM 规模扩大，跨 GPU 通信（如张量并行、专家并行）成为主要性能瓶颈。
*   **重叠困难：** 现有的通信与计算重叠技术（Overlap）在实际应用中效果不佳（平均重叠率仅约 20%），且往往需要侵入性地修改模型代码。
*   **带宽差距：** 现代 GPU 的显存带宽（HBM，数 TB/s）远高于互连带宽（NVLink/NIC，数百 GB/s）。这为利用“过剩”的显存带宽进行数据压缩以换取通信效率提供了机会。
*   **易用性缺失：** 现有的压缩通信方案要么性能不足（压缩太慢），要么与标准库（如 NCCL）集成困难。

### 2. 方法论
CCCL 的核心思想是将轻量级压缩引擎直接嵌入到 NCCL 的数据路径中，实现透明且高效的集合通信。
*   **CCCL-CORE（压缩引擎）：**
    *   **原理：** 针对浮点数（bf16/fp16）的指数位（Exponent）进行熵编码。指数位分布通常高度倾斜，具有高达 70% 的压缩潜力。
    *   **单阶段内存访问：** 传统的 GPU 压缩（如 DietGPU）需要三轮全局内存访问。CCCL-CORE 通过**局部频率表（Localized Frequency Tables）**估计，将访问次数减少到一轮，显著提升了吞吐量。
*   **系统集成与协同设计：**
    *   **NCCL 深度融合：** 将压缩/解压缩内核嵌入 NCCL 的 `CopyReducePacks` 函数中，消除冗余的数据合并阶段。
    *   **Warp 级执行：** 压缩与通信在 Warp 级别并行，利用通信时闲置的 SM 资源。
    *   **选择性压缩策略：** 仅对跨节点/跨 GPU 路径进行压缩，本地传输则绕过压缩以降低开销。
    *   **透明采用：** 通过 `LD_PRELOAD` 替换 NCCL，用户无需修改任何应用代码。

### 7. 优点
*   **无缝集成：** 最大的亮点是无需修改用户代码，通过 `LD_PRELOAD` 即可实现透明加速。
*   **极致性能：** 通过将三轮内存访问优化为一轮，使压缩速度能够匹配甚至超过高速互连带宽。
*   **资源利用：** 巧妙利用了 HBM 与互连带宽之间的巨大差距，以及通信时闲置的 SM 算力。

### 8. 不足与局限
*   **AllReduce 瓶颈：** 在 `AllReduce` 操作中，由于需要多次压缩/解压缩步骤，目前 CCCL 的表现略逊于原生 NCCL。
*   **小消息开销：** 对于小于 32MB 的小消息，压缩带来的计算开销可能超过通信节省的时间。
*   **硬件依赖：** 虽然支持多代 GPU，但其性能增益高度依赖于特定硬件的 HBM 与网络带宽比值。
*   **压缩算法局限：** 目前主要针对浮点数指数位，对于已经过量化或高度压缩的数据，增益可能有限。
