## Abstract
Large Language Models (LLMs) based on Mixture-of-Experts (MoE) are pivotal in industrial applications for their ability to scale performance efficiently. However, standard MoEs enforce uniform expert sizes,creating a rigidity that fails to align computational costs with varying token-level complexity. While heterogeneous expert architectures attempt to address this by diversifying expert sizes, they often suffer from significant system-level challenges, specifically unbalanced GPU utilization and inefficient parameter utilization, which hinder practical deployment. To bridge the gap between theoretical heterogeneity and robust industrial application, we propose Mixture of Heterogeneous Grouped Experts (MoHGE) which introduces a two-level routing mechanism to enable flexible, resource-aware expert combinations. To optimize inference efficiency, we propose a Group-Wise Auxiliary Loss, which dynamically steers tokens to the most parameter-efficient expert groups based on task difficulty. To address the critical deployment challenge of GPU load balancing, we introduce an All-size Group-decoupling Allocation strategy coupled with an Intra-Group Experts Auxiliary Loss. These mechanisms collectively ensure uniform computation distribution across GPUs. Extensive evaluations demonstrate that MoHGE matches the performance of MoE architectures while reducing the total parameters by approximately 20% and maintaining balanced GPU utilization. Our work establishes a scalable paradigm for resource-efficient MoE design, offering a practical solution for optimizing inference costs in real-world scenarios. The code is publicly available at https://github.com/UnicomAI/MoHGE.

以下是对该论文的结构化总结：

### 1. 核心问题与研究动机
*   **背景**：基于 MoE 的大语言模型通过稀疏激活实现了高效扩展，但标准 MoE 的专家大小是统一的（同质化），无法根据 Token 的难易程度动态调整计算成本。
*   **核心问题**：现有的异构 MoE（专家大小不等）虽然在理论上能匹配计算复杂度，但在实际部署中存在两大痛点：
    1.  **GPU 负载不均衡**：不同大小的专家分布在不同 GPU 上，导致显存占用和计算耗时差异巨大，产生系统瓶颈。
    2.  **参数利用率低**：缺乏有效的路由引导，导致模型倾向于只使用大专家，忽略了小专家的潜力。
*   **目标**：设计一种既能实现异构计算、又能保证 GPU 负载平衡且参数利用率高的工业级 MoE 架构。

### 2. 方法论
MoHGE 引入了以下核心技术：
*   **分组异构专家结构**：将专家分为多个组（Groups），同一组内专家大小相同，不同组之间大小不同（按预设比例递增）。
*   **两级路由机制（Two-level Routing）**：
    1.  **组门控（Group Gating）**：首先选择最相关的 $K_g$ 个专家组。
    2.  **专家门控（Expert Gating）**：在选定组内计算专家得分，并进行全局 Top-$K_e$ 筛选和归一化。这种设计增加了专家组合的灵活性。
*   **组级辅助损失（Group-Wise Auxiliary Loss）**：对参数量较大的专家组施加轻微惩罚，迫使模型在处理简单任务时优先选择参数效率更高的专家组。
*   **全尺寸组解耦分配策略（All-size Group-decoupling Allocation）**：这是解决 GPU 平衡的关键。将来自**每个**不同大小组的一个专家分配到同一个 GPU 上。这样，无论路由如何选择组，每个 GPU 承载的总参数量和计算负载在统计上是趋于一致的。
*   **组内专家辅助损失（Intra-Group Experts Auxiliary Loss）**：借鉴 DeepSeekV2，但在组内实施，确保同一组内的专家被调用的频率均衡。

### 3. 实验设计
*   **模型规模**：涵盖了 1B、3B 和 14B 三个参数量级。
*   **数据集**：在 0.58 万亿（0.58T）Token 的混合语料（DataComp-LM, FineWeb, The Pile）上进行预训练。
*   **Benchmark**：使用了 MMLU（综合知识）、SIQA/PIQA（常识推理）、GSM8K/MATH（数学能力）、LAMBADA（语言建模）和 TriviaQA（问答）。

*   **硬件设施**：使用了一个包含 **16 个节点**的 GPU 集群，每个节点配备 **8 张 NVIDIA GPU**（共 128 张 GPU，具体型号未明确说明，推测为 A100 或 H800 等级）。
*   **训练细节**：采用 Megatron-LM 框架，序列长度 4096，每个模型训练 2 个 Epoch。

### 5. 实验数量与充分性
*   **实验覆盖面**：论文在三个不同量级的模型上验证了性能，并针对 14B 模型详细分析了 GPU 负载情况。
*   **消融实验**：对辅助损失系数（$\alpha_{Exp}, \alpha_{Grp}$）进行了详细的网格搜索实验，验证了各组件对性能和激活参数量的影响。
*   **客观性**：通过 Token 出现频率和困惑度（Perplexity）两种维度定义 Token 难度，并统计其路由分布，客观证明了“简单 Token 走小专家，难 Token 走大专家”的假设。

### 6. 主要结论
*   **性能卓越**：MoHGE 在总参数量减少约 **20%**、激活参数量减少约 **25%** 的情况下，性能达到甚至超过了标准同质 MoE。
*   **负载平衡**：通过分配策略和辅助损失，各 GPU 间的 Token 处理频率标准差极小，实现了真正的负载均衡。
*   **推理效率**：在保持高精度的同时，MoHGE 的推理速度通常快于标准 MoE，且远优于 Dense 模型。

### 7. 优点
*   **系统友好性**：不同于以往只关注算法指标的论文，MoHGE 重点解决了异构模型在多 GPU 环境下的**部署瓶颈**。
*   **参数高效**：通过组级损失引导，实现了更精细的计算资源分配。
*   **开源贡献**：提供了代码实现，增强了研究的可复现性。

### 8. 不足与局限
*   **复杂任务耗时**：在 GSM8K 等复杂数学任务上，由于模型倾向于调用大专家，推理耗时会略有增加（虽然准确率更高）。
*   **超参数敏感性**：辅助损失的系数需要针对不同规模的模型进行微调，以达到性能与效率的最佳平衡。
*   **模型规模上限**：实验最高只做到 14B，尚未在千亿级（100B+）超大规模模型上验证其分配策略的极端稳定性。
