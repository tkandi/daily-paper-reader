## 摘要
有效的节点内 GPU 通信对于优化基于 MPI 的高性能计算（HPC）应用程序的性能至关重要，尤其是在利用多条通信路径时。在本研究中，我们提出了一种将 CUDA Graphs 集成到 UCX 框架中的新方法，以增强节点内多路径点对点 GPU 通信。通过并发利用包括 NVLink 和经由主机的 PCIe 在内的多条路径，并使用 CUDA Graph 优化通信工作流，我们显著降低了通信开销并提高了执行效率。据我们所知，我们提出的方法是首次将 CUDA Graphs 无缝集成到 UCX 中。通过在四 GPU 节点上进行的广泛实验，我们提出的基于 CUDA Graph 的多路径通信方法在利用主机路径和另外两条 GPU 路径时，在消息大小高达 512MB 的 GPU 到 GPU OMB 带宽测试中，与单路径 UCX (UCT::CUDA-IPC) 相比，实现了高达 2.95 倍的带宽提升。

## Abstract
Effective intra-node GPU communication is essential for optimizing performance in MPI-based HPC applications, especially when leveraging multiple communication paths. In this study, we propose a novel approach that integrates CUDA Graphs into the UCX framework to enhance intra-node multi-path point-to-point GPU communication. By concurrently leveraging multiple paths, including NVLink and PCIe through the host, and optimizing communication workflows using CUDA Graph, we achieve significant reductions in communication overhead and improve execution efficiency. To the best of our knowledge, our proposed approach is the first to seamlessly integrate CUDA Graphs into UCX. Through extensive experiments on a four-GPU node, our proposed CUDA Graph-based multi-path communication approach achieves up to a 2.95x bandwidth improvement, compared to the single-path UCX (UCT::CUDA-IPC), in GPU-to-GPU OMB bandwidth test when utilizing the host path and two other GPU paths, at message sizes up to 512MB.

在高性能计算（HPC）和人工智能领域，节点内 GPU 间的通信效率是系统性能的关键瓶颈。传统的点对点（P2P）通信通常仅依赖单一路径（如 NVLink 或 PCIe），无法充分利用硬件拓扑中的冗余带宽。虽然之前的研究尝试过通过多路径条带化（Message Striping）来提升带宽，但往往面临较高的 CPU 调度开销和复杂的同步问题。
**研究动机：** 本文旨在通过将 **CUDA Graphs** 集成到 **UCX（Unified Communication X）** 框架中，利用其“捕获并重放”的特性来降低多路径通信的启动开销和同步成本，从而实现更高效的节点内 GPU 通信。

### 2. 论文提出的方法论
核心思想是构建一个统一的多路径通信框架，包含静态运行时流水线引擎和动态 CUDA Graph 执行机制。
*   **2D 流水线引擎：** 
    *   **水平拆分：** 将大消息根据可用路径（如多条 NVLink、经由主机的 PCIe）进行划分。
    *   **垂直拆分：** 将每条路径上的数据进一步细分为小块（Chunks），通过多个 CUDA 流实现流水线传输。
*   **CUDA Graph 集成：** 
    *   **动态构建：** 将复杂的流水线工作流（包括内存拷贝节点和依赖关系）封装进一个有向无环图（DAG）。
    *   **缓存与重用：** 在 UCX 传输层实现 CUDA Graph 缓存，根据消息大小和缓冲区地址匹配已实例化的图，避免重复构建开销。
*   **关键技术细节：** 
    *   使用 CUDA Driver API 显式构建图节点。
    *   引入代理实体连接 UCX 的基础模块与 CUDA IPC 模块。
    *   通过离线拓扑微调（Offline Tuning）确定不同消息大小下的最优路径组合和分块数量。

### 6. 论文的主要结论与发现
*   **带宽提升：** 在 512MB 大消息下，相比单路径 UCX，该方法实现了高达 **2.95 倍** 的带宽提升。
*   **应用加速：** 在 Jacobi 求解器中，整体执行时间缩短了高达 **1.28 倍**。
*   **CUDA Graph 收益：** 
    *   CUDA Graph 在消息较大（>8MB）且窗口大小较高时收益最明显，因为它能有效分摊启动开销。
    *   对于小消息，CUDA Graph 的启动开销（Launch Overhead）可能抵消其带来的性能增益。
*   **路径选择：** 增加主机路径（PCIe）对带宽的贡献相对较小（约 15%），且在双向通信中可能因 PCIe 争用导致性能下降。

### 7. 优点
*   **首创性：** 据称是首次将 CUDA Graphs 无缝集成到 UCX 传输层中。
*   **透明性：** 该优化位于传输层，对上层 MPI 应用透明，无需修改应用代码即可获益。
*   **深入的开销剖析：** 对 CUDA Graph 生命周期的量化分析为未来在通信库中应用该技术提供了宝贵的参考。

### 8. 不足与局限
*   **小消息开销：** 在处理小消息时，CUDA Graph 的实例化和管理成本仍然较高，缺乏动态切换机制。
*   **硬件局限：** 实验仅限于单节点内的 4 GPU 环境，尚未验证在 8 GPU（如 DGX 系统）或跨节点环境下的扩展性。
*   **路径争用：** 在双向通信模式下，PCIe 路径的竞争处理尚不够优化。
*   **静态配置：** 目前路径选择和分块参数部分依赖离线微调，缺乏完全动态的实时自适应能力。
