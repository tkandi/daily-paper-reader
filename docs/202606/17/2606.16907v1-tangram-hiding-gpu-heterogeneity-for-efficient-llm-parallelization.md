## 摘要
大语言模型训练任务的规模要求在大规模 GPU 集群上进行并行化规划。由于不同 GPU 类型和互连随时间的增加，这些 GPU 集群变得越来越异构。自动 LLM 并行器可以搜索并行化方案，但在异构 GPU 上面临着搜索空间的爆炸。为了使搜索在异构 GPU 集群中可行，并行器通常省略一些并行类型（例如专家并行）或内存节省技术（例如 ZeRO），这会导致更差的方案。我们描述了 Tangram，一个通过将并行化规划与 GPU 异构性解耦，使得现有不了解异构性的 LLM 并行器能够在异构 GPU 集群中使用的系统。为此，Tangram 利用了两种见解：（1）由于批量采购导致具有相似计算、内存和连接性的 GPU 集合，Tangram 可以将这种同构 GPU 岛屿暴露给现有并行器；（2）并行器通常首先划分模型，然后对划分进行并行化。Tangram 可以将这样的模型切片分配给 GPU 岛屿，并将它们组合成工作负载平衡的流水线以获得高吞吐量。Tangram 通过一个狭窄的 API 与现有并行器集成，该 API 依赖于模型切片/岛屿对的枚举。Tangram 的训练吞吐量比当前的异构并行器（Metis 和 Sailor）高出 2.3 倍，并通过剪枝枚举的方案扩展到大型 GPU 集群。

## Abstract
The scale of LLM training jobs requires parallelization planning over large GPU clusters. Due to different GPU types and interconnects added over time, these GPU clusters are increasingly heterogeneous. Automatic LLM parallelizers can search for parallelization plans but face an exploding search space with heterogeneous GPUs. To make search tractable in heterogeneous GPU clusters, parallelizers often omit types of parallelism (e.g., expert parallelism) or memory-saving techniques (e.g., ZeRO), which results in worse plans.   We describe Tangram, a system that enables the use of existing heterogeneity-unaware LLM parallelizers in heterogeneous GPU clusters by decoupling parallelization planning from GPU heterogeneity. For this, Tangram exploits two insights: (1) since bulk purchases result in sets of GPUs with similar compute, memory, and connectivity, Tangram can expose such homogeneous GPU islands to existing parallelizers; and (2) parallelizers commonly first partition models and then parallelize partitions. Tangram can compose such model slices, assigned to GPU islands, into work-balanced pipelines for high throughput. Tangram integrates with existing parallelizers through a narrow API, which relies on the enumeration of model-slice/island pairs. Tangram achieves up to 2.3x higher training throughput than current heterogeneous parallelizers (Metis and Sailor) and scales to large GPU clusters by pruning enumerated plans.

### **2. 方法论：Tangram 系统设计**

Tangram 采用“**解耦**”的思想，将并行规划与 GPU 异构性分离，其核心流程如下：

*   **核心思想**：
    1.  **GPU 同构孤岛**：利用批量采购导致集群内存在性能相近的 GPU 组这一观察，将异构集群划分为多个内部同构的 **“GPU 岛”**。
    2.  **模型切片**：利用并行器自身的模型划分能力，将模型分解为连续的 **“模型切片”**。
    3.  **组合规划**：为每个“模型切片-孤岛”对调用现有同构并行器生成局部最优计划，最后通过一个负载均衡的流水线将这些局部计划组合成全局异构并行方案。

*   **关键技术细节**：
    1.  **GPU 岛构建（§4.1）**：
        *   **定义**：GPU 岛是满足计算、内存、机内互连差异在容忍阈值（\(\epsilon\)）内，且机间互连带宽高于外部连接的 GPU 集合。
        *   **方法**：通过性能剖析，使用**凝聚层次聚类**算法，将 GPU 节点基于计算、内存、网络指标贪婪地合并，形成数量可控的同构岛。
    2.  **通用并行器接口（§4.2）**：
        *   Tangram 定义了一个狭窄、通用的 API，包含 `slice_model()`、`concatenate()`、`profile()`和 `parallelize()` 四个核心函数。
        *   该接口封装了模型切片（获取最小划分单元“模型原子”）和岛内并行化查询，使得集成 Alpa、Aceso 等不同并行器只需少量工作。
    3.  **模型切片枚举与剪枝（§5.1）**：
        *   为找到最佳的“模型切片-孤岛”对，Tangram 枚举所有可能组合，但为防止搜索爆炸，应用了三层剪枝策略：
            *   **冗余剪枝**：利用 Transformer 层的重复结构，对相同组成的模型切片仅查询一次。
            *   **不平衡剪枝**：估算孤岛计算能力和切片需求，剔除计算需求严重不匹配的组合。
            *   **不可行剪枝**：基于内存开销，提前剔除因显存不足而无法执行的组合。
    4.  **面向异构的流水线组合（§5.2）**：
        *   **组合策略**：采用 1F1B 流水线并行为框架，将属于不同模型切片和 GPU 岛的局部计划组合成一个全局流水线。
        *   **算法流程**：使用**动态规划**算法，在“**最慢流水线阶段决定整体吞吐量**”的约束下，贪婪地构建能覆盖完整模型的“模型切片-孤岛”计划序列。算法会自动识别并剔除会引入严重硬件瓶颈的资源受限 GPU 岛。

### **7. 优点**

*   **巧妙的问题解耦**：The core insight of decoupling parallelization planning from hardware heterogeneity is elegant and effective. 这使得能立即复用所有现有及未来同构并行器的先进特性。
*   **系统设计通用且实用**：

*   **全面的剪枝与搜索优化**：设计了多层、异构感知的剪枝策略，有效控制了搜索空间，并通过动态规划找到了负载均衡的流水线组合，提升了规划质量和速度。

### **8. 不足与局限**

*   **依赖于同构子集群**：The method’s effectiveness hinges on the presence of sufficiently large "homogeneous islands," which may be non-trivial if an organization’s GPU purchases are highly fragmented or incremental.
*   **跨岛通信限制**：仅考虑使用流水线并行（PP）连接各 GPU 岛，这要求跨岛通信仅限于激活传输。如果最佳全局方案更需要跨岛的、通信密集的张量并行（TP），Tangram 可能无法实现。
*   **规划时间与岛屿数量相关**：虽然通过剪枝优化，规划时间已大幅降低，但实验显示，随着 GPU 岛数量从 1 增加到 4，规划时间仍增加了 20 倍（从 31 秒到 659 秒）。在极其大规模且型号繁杂的集群中，规划开销仍可能构成挑战。
*   **对网络动态的适应性有限**：GPU 岛的定义基于静态的、预先剖析的性能指标（如带宽）。但在共享云或网络竞争频繁的环境下，这种静态划分可能并非最优。
