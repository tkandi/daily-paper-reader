## 摘要
分解式大语言模型推理强制KV缓存在解码开始前穿越数据中心网络，因此传输时间直接计入首Token时间（TTFT）预算。当前的调度器仅根据计算负载和前缀缓存局部性进行路由，忽略了预填充与解码实例之间的拓扑距离和动态拥塞。我们通过一个精简的操作者-调度器接口——网络成本预言机——来弥补这一差距，并证明忽略网络项会使得仅缓存感知的调度在上下文长度增加时任意次优。NetKV，一种消耗该预言机的每个请求O(|D|)贪心算法，具有可证明对陈旧遥测数据鲁棒的层级排名。在由Mooncake轨迹驱动的64-GPU四层胖树模拟器上，NetKV相比轮询调度将平均TTFT最多降低21.2%，相比调谐过的缓存+负载感知调度器降低17.6%，将SLO达成率提升最多20.1个百分点，并在所有测试条件下将令牌间时间开销保持在0.5毫秒以下，无需更改传输、推理引擎或硬件。

## Abstract
Disaggregated LLM inference forces the KV cache to traverse the datacenter network before decoding begins, so transfer time enters directly into the Time to First Token (TTFT) budget. Current schedulers route on compute load and prefix-cache locality alone, ignoring the topological distance and dynamic congestion between prefill and decode instances. We close this gap with a thin operator-to-scheduler interface, the network cost oracle, and we prove that ignoring the network term renders cache-aware-only scheduling arbitrarily suboptimal as context length grows. NetKV, the O(|D|) per-request greedy that consumes this oracle, has tier rankings that are provably robust to stale telemetry. On a 64-GPU four-tier fat-tree simulator driven by Mooncake traces, NetKV reduces mean TTFT by up to 21.2% over round-robin and 17.6% over a tuned cache+load-aware scheduler, lifts SLO attainment by up to 20.1 percentage points, and keeps the Time Between Tokens overhead below 0.5 ms in every condition tested, with no changes to the transport, inference engine, or hardware.

## 1. 核心问题与研究背景
- **核心问题**：当前分解式大语言模型（LLM）推理系统中，KV 缓存必须在预填充阶段结束后穿越数据中心网络传输到解码实例，传输延迟直接计入首 Token 时间（TTFT）预算。然而现有调度器仅基于计算负载和前缀缓存局部性进行路由决策，完全忽略预填充实例与解码实例之间的**网络拓扑距离**与**动态拥塞**，导致 TTFT 上升、服务等级协议（SLO）达成率下降。
- **研究意义**：随着上下文长度增长，KV 缓存体积变大，网络传输时间占比显著增加，若不将网络成本纳入调度决策，仅基于缓存的调度策略会任意次优（provably arbitrarily suboptimal）。论文提出一种轻量级的网络感知调度方案，无需修改传输层、推理引擎或硬件，即可改善分解式推理的性能。

## 2. 方法论
- **核心思想**：引入一个精简的操作者与调度器之间的接口——“网络成本预言机”（network cost oracle），该预言机为每个（预填充节点，解码节点）对提供一个抽象的传输成本值。调度器在决策时同时考虑缓存命中收益与该网络成本，选择总代价最小的解码实例。
- **NetKV 贪心算法**：
  - **输入**：请求的预填充实例、候选解码实例集合 \(D\)、缓存感知的成本函数、网络成本预言机。
  - **流程**：对每个候选解码实例，计算“缓存命中带来的节省”减去“网络传输成本”的净收益，按照净收益从高到低排序，选择排第一位的实例。
  - **复杂度**：每个请求仅需线性扫描候选集一次，时间复杂度为 \(O(|D|)\)。
  - **鲁棒性**：算法仅依赖各实例的**相对排名**，而非精确数值，因此对陈旧遥测数据具有可证明的鲁棒性（即使网络状态信息略有滞后，只要排名顺序大致正确，决策仍接近最优）。
- **关键细节**：
  - 网络成本预言机可通过测量往返时间、链路利用率或来自交换机的拥塞通知等实现，论文使用基于链路利用率和传播延迟的复合指标。
  - 将缓存命中的收益量化为“避免重新计算 KV 缓存的时间”，并与网络成本统一在同一个时间单位下比较。

- **对比方法（Benchmark）**：

  2. **仅缓存感知调度（Cache-Aware-Only）**：仅根据前缀缓存命中率选择解码实例，完全忽略网络因素。

  - 令牌间时间（TBT）开销，标识调度决策对后续解码阶段的附加延迟。
