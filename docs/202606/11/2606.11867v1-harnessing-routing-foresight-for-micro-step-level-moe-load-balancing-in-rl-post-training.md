## 摘要
混合专家（MoE）与强化学习（RL）后训练如今主导着大语言模型（LLM）的发展，然而专家负载不均衡仍是一大关键挑战。现有负载均衡系统面向预训练，依赖历史步级统计数据。但这些方法在RL后训练独特的工作负载动态下失效：步级负载稳定，但微步期间处理的极小批量大小会导致剧烈的高频负载波动。我们提出ForeMoE，一个面向MoE RL后训练的微步级负载均衡系统。ForeMoE不依赖历史统计数据，而是利用多阶段RL流水线（推演、重新计算、策略更新），通过使用来自推演阶段的可预见路由信息，主动指导其余阶段的负载均衡。为支持频繁的每微步重配置，ForeMoE采用分层规划器，将NP难负载均衡问题分解为可处理的子组件，同时配备一个传输引擎，利用互补硬件路径（CPU辅助和GPU直连）实现重叠的专家传输。在64个GPU上的评估表明，ForeMoE相较于最先进的RL后训练系统，可实现高达1.45$\times$的加速。

## Abstract
Mixture-of-Experts (MoE) and reinforcement learning (RL) post-training now dominate large language model (LLM) development, yet expert load imbalance remains a critical challenge. Existing load-balancing systems target pre-training by relying on historical step-level statistics. However, these methods fail under the unique workload dynamics of RL post-training: the step-level load is stable, but the tiny batch sizes processed during micro-steps cause severe, high-frequency load fluctuations.   We introduce ForeMoE, a micro-step-level load balancing system for MoE RL post-training. Instead of relying on historical statistics, ForeMoE exploits the multi-stage RL pipeline (rollout, recompute, policy update) by using foreseeable routing information from the rollout stage to proactively guide load balancing in the remaining stages. To support frequent per-micro-step reconfiguration, ForeMoE employs a hierarchical planner that decomposes the NP-hard load balancing problem into tractable sub-components, alongside a transfer engine that leverages complementary hardware paths (CPU-assisted and GPU-direct) for overlapped expert transfer. Evaluations on 64 GPUs demonstrate that ForeMoE achieves up to a 1.45$\times$ speedup over state-of-the-art RL post-training systems.

## 方法论
### 核心思想
- **利用路由预见性**：RL后训练包含推演（rollout）、重计算（recompute）、策略更新（policy update）三个阶段。推演阶段记录的路由信息在后续阶段被重新使用，因此路由信息是可预见的。ForeMoE以推演阶段的路由信息作为精确信号，主动制定微步级负载均衡计划。
- **分层规划**：将NP难的负载均衡问题分解为四个阶段，减少求解开销。
- **互补传输路径**：在不同RL阶段采用最优的专家传输路径（CPU辅助传输用于重计算阶段，GPU直连传输用于策略更新阶段），实现传输与计算重叠。

### 关键技术细节
- **四阶段规划器**（Four-stage Planner）：
  1. **基底专家放置**（Stage 1）：基于跨步的聚合负载，用贪婪算法确定长期稳定的专家到插槽的映射，最小化计算和跨机通信成本。
  2. **专家重定位**（Stage 2）：对每个微步，通过交换重载与轻载专家，快速修正负载偏斜，迭代终止于目标函数不再改善。
  3. **专家复制**（Stage 3）：利用冗余插槽，贪心地放置热门专家的副本，采用局部感知的令牌分配启发式。
  4. **令牌分配**（Stage 4）：在专家放置固定后，将问题简化为线性规划（LP），通过求解器获得最优令牌分配，并用稀疏矩阵、向量化和并行加速。
- **专家传输引擎**（Expert Transfer Engine）：
  - CPU辅助路径：机器CPU内存持有全部专家参数，GPU通过PCIe预取所需专家，用于重计算阶段。
  - GPU直连路径：专家在GPU间通过NVLink直接传输，用于策略更新阶段（需同步梯度）。
  - 微步级重配置：通过逐层传输与CUDA流重叠隐藏通信开销，并管理前向/后向通道的重配置计划恢复。

### 理论建模
- 建立MoE层执行时间模型，计算时间由最大秩负载决定，通信时间由最大跨机流量决定。
- 联合放置与令牌分配问题被建模为混合整数线性规划（MILP），目标是最小化单层时间，约束包括插槽容量、专家覆盖、令牌守恒等。因NP难，故采用分层分解。

## 实验设计
### 数据集与场景
- **数据集**：DAPO-Math-17k（数学推理）、CodeForces（代码生成）。
- **模型**：Qwen3-30B-A3B（128专家）、Qwen3.5-35B-A3B（256专家）。
- **配置**：三种专家并行规模（EP16、EP32）及相应的数据/张量并行组合；每步512样本，提示长度2K，回答长度8K；每个秩2个冗余专家插槽。

### 基线方法
- **veRL**：最先进的RL后训练系统（固定专家布局，无运行时均衡）。
- **veRL+EPLB**：veRL基础上集成面向预训练的步级负载均衡器EPLB。
- **Oracle**：理想化均衡（每秩负载完全相同）作为理论上界。

### 实验指标
- 端到端每步延迟（重计算阶段+策略更新阶段）。

## 主要结论与发现
- ForeMoE在所有配置上均实现端到端加速，最高达1.45倍（对比veRL），以及对比步级均衡的1.12–1.22倍。
- 微步级负载均衡是关键，使重计算和策略更新阶段分别接近Oracle的95–97%和90–95%性能。
- 各规划阶段（基底放置、重定位、复制、分配）均可叠加产生非重叠收益；不同RL阶段选择适配传输路径至关重要。
- 规划与传输开销均可完全隐藏，随GPU数增加而保持低占比。
