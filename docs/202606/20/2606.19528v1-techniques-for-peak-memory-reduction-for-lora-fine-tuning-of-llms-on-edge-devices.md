## 摘要
使用低秩适应(LoRA)在最终用户数据上微调大型语言模型(LLMs)可在保持数据隐私的同时提供个性化体验，但在消费级硬件上面临严重的内存限制。微调期间的峰值内存通常超出设备限制，特别是对于参数达数十亿的模型和长上下文训练数据。本文介绍了一套在不牺牲模型质量的情况下减少内存占用的互补技术：(1) 带有即时反量化的基础模型量化，(2) 结合选择性激活缓存和磁盘卸载的内存高效检查点，(3) 使用语义相关令牌子集的softmax近似，以及(4) logits屏蔽。在Llama-3.2 3B和Qwen-2.5 3B上的实验表明峰值内存减少高达26倍和28倍，从而能在资源受限的设备上进行微调。

## Abstract
Fine-tuning of Large Language Models (LLMs) using Low-Rank Adaptation (LoRA) on an end-user's data offers personalized experiences while keeping data private, but faces severe memory constraints on consumer hardware. Peak memory during fine-tuning often exceeds device limits, especially for models with billions of parameters and long-context training data. This paper introduces a suite of complementary techniques to reduce memory footprint without sacrificing model quality: (1) base model quantization with on-the-fly dequantization, (2) memory-efficient checkpointing combining selective activation caching and disk offloading, (3) softmax approximation using semantically relevant token subsets, and (4) logits masking. Experiments on Llama-3.2 3B and Qwen-2.5 3B demonstrate up to $26\times$ and $28\times$ reduction in peak memory, enabling fine-tuning on resource-constrained devices.

### 1. 论文的核心问题与整体含义

本论文旨在解决**在资源受限的边缘设备（如智能手机、IoT 设备）上，使用 LoRA （低秩适应） 对大型语言模型 （LLM） 进行个性化微调时所面临的严峻的峰值内存 （Peak Memory）瓶颈问题**。

- **研究动机与背景**：
    -   在端侧直接微调 LLM 能满足用户对**数据隐私、低延迟和个性化体验**的需求。
    -   虽然 LoRA 通过仅更新少量参数显著降低了可训练参数量，但在反向传播过程中仍需存储大量前向传播的激活值 （Activations），导致**峰值内存极易超出消费级硬件的物理限制**（例如处理长上下文数据时）。
    -   现有的内存优化方案（如混合服务器-端侧训练、零阶优化等）在隐私、精度或通用性上存在妥协。因此，需要一套能在不牺牲模型质量的前提下，大幅削减端侧微调峰值内存的方法。

### 2. 论文提出的方法论

论文的核心思想是通过一套**互补协同的技术组合**，从不同维度共同削减峰值内存。其主要技术包括以下四点：

- **基础模型量化与即时反量化 （Base Model Quantization with On-the-Fly Dequantization）**：
    -   **核心操作**：将冻结的基座模型权重离线压缩为 INT4 等低精度格式（词嵌入层和输出头保留更高精度如 INT16/INT8），从而将模型存储占用从 5.98 GB 降至 2.59 GB。
    -   **即时反量化**：在计算前向和反向传播时，临时将所需的权重块反量化为 FP32，完成矩阵乘法后立即从片上内存中释放，从而避免常驻完整精度的权重，消除了这部分参数带来的峰值内存。

- **内存高效检查点 （Memory-Efficient Checkpointing）**：
    -   **核心操作**：将一个 Transformer 层分解为多个计算节点。在前向传播中，仅缓存每个节点边界处的激活值到离片存储（如 SSD）；在反向传播时，动态加载所需的节点权重和边界激活值，并**重新计算**节点内部中间的激活值。
    -   **策略**：通过最大化最后一个计算节点（通常是内存瓶颈所在的 LM Head），使其无需重计算，以此来平衡重计算开销与内存节省。

- **基于语义的 Softmax 近似 （Softmax Approximation）**：
    -   **核心思想**：预训练模型的词嵌入空间具有语义几何特性（相似令牌的嵌入向量接近）。传统的 Softmax 需要计算整个词表（如 128k）的 Logits，内存消耗巨大。
    -   **实现方式**：
        1.  离线预计算整个词嵌入矩阵的余弦相似度矩阵。
        2.  微调时，对于序列中的目标令牌，检索一个语义最相关的前 $k$ 个令牌子集 $\mathcal{J}$。
        3.  $\mathcal{J}$ 由序列中所有目标令牌的 top-$k$ 索引的并集构成（$\mathcal{J} = \cup_{t=1}^{T} \mathcal{I}(y_t, k)$），从而保证目标令牌本身一定包含在内。
        4.  仅加载 $\mathcal{J}$ 对应的、大幅缩减的嵌入矩阵来计算近似 Softmax 和损失。这显著降低了 I/O 传输、片上 Logits 存储和计算量。

- **Logits 掩码 （Logits Masking）**：
    -   **核心思想**：在指令微调场景中，输入序列的大部分（如系统提示、用户问题）是**不可训练的固定令牌**。标准做法是在计算损失时屏蔽它们，但依然会为其计算 Logits 和 Softmax。
    -   **实现方式**：**直接跳过**不可训练令牌在 LM Head 中的 Logits 计算，等效于缩短了 LM Head 处理的有效上下文长度，从而在前后向传播中均能降低峰值内存占用量。

**算法流程概述**：
整体流程将上述方法有机结合。首先使用量化权重，并采用内存高效检查点策略执行前向后向传播，其中在 LM Head 节点，应用基于语义的 Softmax 近似，并仅对可训练令牌执行 Logits 掩码计算。
