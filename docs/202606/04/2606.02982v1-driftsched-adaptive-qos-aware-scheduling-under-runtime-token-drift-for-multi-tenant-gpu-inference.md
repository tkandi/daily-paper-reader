## 摘要
大语言模型（LLM）推理服务的快速增长，增加了对高效多租户GPU调度的需求。尽管vLLM等现代推理运行时通过连续批处理和优化的内存管理提高了吞吐量，但准确估计异构推理请求的运行时成本仍然是一个重大挑战。在实践中，观察到的输出长度常常偏离准入时的估计值，造成运行时令牌漂移，可能导致工作负载误分类、队列不平衡、尾延迟增加以及服务质量（QoS）下降。本文提出DriftSched，一个在NVIDIA L4 GPU上服务于多租户LLM推理的自适应QoS感知调度框架。DriftSched结合了工作负载分类、令牌预算估计、租户感知队列管理和运行时反馈驱动的漂移补偿，以改进准入时的调度决策。该框架在异构多租户工作负载下评估了FIFO、优先级、加权、最短作业优先（SJF）和老化优先级调度策略。实验结果表明，不同工作负载类别中存在可测量的运行时令牌漂移。自适应偏差校正将工作负载估计误差平均降低了38.8%（MAE）和40.5%（RMSE），提高了工作负载分类的稳定性和调度准确性。在所有评估的调度器中，SJF实现了最佳整体性能，在持续的GPU争用下，相对于FIFO，将中位端到端延迟降低了约42%，P99延迟降低了约16%。这项工作贡献了一个自适应漂移感知调度架构、一个运行时令牌漂移补偿机制，以及一个可复现的基准测试框架，用于评估共享GPU基础设施上QoS感知的LLM推理调度。

## Abstract
The rapid growth of large language model (LLM) inference services has increased the demand for efficient multi-tenant GPU scheduling. While modern inference runtimes such as vLLM improve throughput through continuous batching and optimized memory management, accurately estimating the runtime cost of heterogeneous inference requests remains a significant challenge. In practice, observed output lengths often deviate from admission-time estimates, creating runtime token drift that can lead to workload misclassification, queue imbalance, increased tail latency, and degraded Quality-of-Service (QoS).   This paper presents DriftSched, an adaptive QoS-aware scheduling framework for multi-tenant LLM inference serving on NVIDIA L4 GPUs. DriftSched combines workload classification, token-budget estimation, tenant-aware queue management, and runtime feedback-driven drift compensation to improve admission-time scheduling decisions. The framework evaluates FIFO, Priority, Weighted, Shortest-Job-First (SJF), and Aging Priority scheduling policies under heterogeneous multi-tenant workloads.   Experimental results demonstrate measurable runtime token drift across workload categories. Adaptive bias correction reduces workload estimation error by an average of 38.8% (MAE) and 40.5% (RMSE), improving workload classification stability and scheduling accuracy. Among all evaluated schedulers, SJF achieves the best overall performance, reducing median end-to-end latency by approximately 42% and P99 latency by approximately 16% relative to FIFO under sustained GPU contention.   The work contributes an adaptive drift-aware scheduling architecture, a runtime token-drift compensation mechanism, and a reproducible benchmarking framework for evaluating QoS-aware LLM inference scheduling on shared GPU infrastructure.

## 1. 论文的核心问题与整体含义

- **核心问题**：多租户GPU上运行大语言模型（LLM）推理时，请求的实际输出长度与调度准入时的估计值之间存在显著偏差，即“运行时令牌漂移”（runtime token drift）。
- **影响**：这种估计误差会导致工作负载误分类、队列失衡、尾延迟增加、租户服务质量（QoS）下降，尤其是在GPU资源争用严重的场景下。
- **研究动机**：现有推理调度系统（如vLLM）主要优化吞吐与内存，调度决策多依赖静态的 `max_tokens` 或用户预设，难以适应动态变化的真实推理输出，因此需要一种能自适应补偿漂移、同时兼顾多租户QoS的调度框架。

## 2. 论文提出的方法论

- **整体架构**：DriftSched 由工作负载生成、工作负载分析、租户感知队列管理、调度引擎、GPU推理执行、运行时指标采集和**自适应反馈驱动的漂移补偿**共七个模块组成。
- **自适应令牌预算估计**：
  - 估计输出令牌数 \( T_{\text{estimated output}} = T_{\text{base}} \times B_{\text{runtime}} \times S_{\text{tenant}} \times F_{\text{input}} \)
  - \( T_{\text{base}} \)：工作负载基线令牌估计。
  - \( B_{\text{runtime}} \)：自适应运行时漂移校正因子，根据历史观测动态更新。
  - \( S_{\text{tenant}} \)：租户安全缩放因子。
  - \( F_{\text{input}} \)：提示复杂度缩放因子。
- **漂移补偿更新规则**：
  - 使用指数移动平均（EMA）更新偏差：\( B_{\text{new}} = (1 - \alpha) \times B_{\text{old}} + \alpha \times B_{\text{measured}} \)
  - \( B_{\text{measured}} = T_{\text{actual}} / T_{\text{base}} \)，即实际输出长度与基线估计之比。
- **工作负载分类**：基于自适应估计的令牌预算，将请求分为 `short`、`medium`、`long` 三类调度作业，而非仅依赖语义类别（如 `short_qa`、`summary` 等）。
- **调度算法**：实现并评估了五种策略：FIFO、优先级调度（Premium/Standard/Batch）、加权调度（50:30:20 分配）、最短作业优先（SJF，基于自适应预算）和老化优先级调度。
- **运行流程**：请求进入后先经过自适应分析层分类并分配至租户队列，调度器根据策略选择请求送入vLLM推理，执行完成后实际输出长度用于更新漂移校正因子，形成闭环。

## 3. 实验设计

- **测试平台**：NVIDIA L4 GPU + vLLM 推理运行时，模型为 Qwen1.5-1.8B-Chat (FP16)，API网关采用 FastAPI，队列基于 Redis。
- **工作负载**：生成四种语义类别的提示（短问答、摘要、技术解释、长报告），并赋给三个租户等级（Premium、Standard、Batch），模拟多租户竞争。总提示库约 1180 个独特提示。
- **实验配置**：
  - 总请求数 3000，前 1000 作为校准阶段（学习偏差），后 2000 为压力评估阶段。
  - 并发客户端 50，GPU 批大小 32，批等待间隔 0.01s。
  - 对比“BIAS=OFF”（静态基线，无反馈）与“BIAS=ON”（自适应补偿）两种模式。
- **评估指标**：端到端延迟（P50/P95/P99）、队列等待时间、令牌估计误差（MAE / RMSE）、GPU 利用率与内存占用、偏差收敛过程、不同租户与作业类别的延迟分布。

- **硬件**：单块 NVIDIA L4 GPU（24 GB GDDR6，PCIe Gen4 x16），搭配 Intel Xeon 6 处理器、32 GB DDR5 内存。未使用多GPU或分布式训练。
- **推理执行**：所有实验均为**在线推理**，不涉及模型训练；整个实验过程消耗的算力主要用于 GPU 推理和少量 CPU 逻辑调度，文中未报告总运行时长或能耗。

## 5. 实验数量与充分性

- **实验规模**：针对五种调度策略 × 两种偏差模式（BIAS OFF/ON）的主要对比，每组实验重复3次独立运行，标准差较小。
- **分析维度**：从多角度分析了偏差收敛曲线、队列深度演化、租户级延迟、负载分类分布、估计误差缩减、GPU利用率等，覆盖较为全面。
- **数据充分性**：使用约1180个独特提示，减少了提示记忆效应；但只测试了单个模型与单块GPU，且工作负载为合成构建，虽能体现多租户竞争，但与真实生产环境的分布可能存在差异。总体而言，实验设计能支撑主要结论，但在多样性与规模上仍有扩展空间。

## 6. 论文的主要结论与发现

- **运行时令牌漂移真实存在**：静态估计持续高估实际输出长度，自适应机制能有效学习并补偿漂移，偏差因子收敛至 0.79~0.84 附近。
- **估计误差大幅下降**：开启自适应补偿后，MAE 平均降低约 39%，RMSE 平均降低约 40%，在所有五种调度策略下均表现一致。
- **调度策略对性能影响显著**：
  - **SJF 整体延迟最优**：相比 FIFO，中位延迟降低约 42%，P99 降低约 16%，P95 降低约 17%，但代价是牺牲了租户级 QoS——Batch 用户受益最大，Premium 租户延迟反而升高。
  - **优先级与老化策略保障租户 QoS**：Premium 租户延迟可降至约 76~77秒，但 Batch 租户延迟飙升至 400秒以上。
  - **加权策略**在公平性与QoS差异化之间取得较好平衡。
- **性能提升源于调度与队列管理**：不同策略下 GPU 执行延迟（约 10.5s）基本不变，GPU 利用率稳定在 85%~92%，说明延迟改善主要来自更优的请求排序和等待时间管理，而非硬件执行效率变化。

## 7. 优点

- **创新性漂移补偿**：提出并实现了运行时反馈驱动的自适应偏差校正，使调度器能持续适应动态输出分布，优于静态生硬的令牌限制。
- **分离语义与调度类别**：将提示语义分类与运行时作业大小分类解耦，使得调度决策基于实际计算成本，提升了灵活性。
- **系统化对比**：在同一框架下对五种经典调度策略进行了公平比较，揭示了延迟优化与租户公平性之间的权衡。
- **可复现与开放**：提供了完整的开源基准测试框架（GitHub仓库），包括自动化实验与指标采集，便于后续研究验证和扩展。

## 8. 不足与局限

- **硬件与模型单一**：实验仅使用一块 NVIDIA L4 和一个较小的 1.8B 模型，结论在不同 GPU 架构、更大模型或多GPU部署下的泛化性有待验证。
- **令牌计量粒度**：输出长度使用空格分隔词计数而非精确的 Tokenizer 计数，虽保持一致性但可能引入偏差，未来需改用精确令牌计数。
- **工作负载合成**：虽包含多种语义类型，但提示集和请求分布仍为静态合成，未覆盖真实生产环境中用户行为的动态漂移和概念漂移。
- **调度策略较基础**：未与更先进的智能调度或基于强化学习的方法对比，也未深度研究批处理策略、KV缓存抢占等高级优化对漂移的影响。
- **校准与评估阶段划分**：采用固定的 1:2 划分，可能无法适应在线系统中工作负载特征的非平稳性，其鲁棒性仍需检验。
