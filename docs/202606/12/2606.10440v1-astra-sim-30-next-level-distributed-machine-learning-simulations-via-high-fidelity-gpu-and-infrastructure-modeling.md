## 摘要
分布式机器学习（ML）是当今大规模人工智能应用的关键范式。随着模型推理成为一个重要的用例，对延迟敏感的集合通信的忠实建模变得前所未有的重要。因此，如今以高保真度捕获设备架构并对控制和数据路径进行建模是必需的。拥有一个通用的、详细的分布式ML基础设施表示也至关重要。我们重新审视了有前景的开源、社区驱动的模拟器：ASTRA-sim。在这项工作中，我们指出了当前ASTRA-sim模拟器的局限性，并用新功能对其进行了增强。为此，我们通过标准化的基础设施表示实现了细粒度、高保真度的模拟，从而开启了新的设计空间探索机会。我们提出了以缓存行大小的加载-存储粒度进行模拟，并采用详细的图形处理单元（GPU）执行模型，以平衡模拟的可扩展性和保真度。我们还引入了InfraGraph，这是一种标准化的表示方法，用于详细捕获分布式ML网络基础设施。使用更新后的ASTRA-sim 3.0模拟器，我们展示了有趣的设计空间探索，用于设计优化的集合算法、网络需求和GPU架构。

## Abstract
Distributed machine learning (ML) is a key paradigm for today's large-scale artificial intelligence applications. As model inference arises as an important use case, faithful modeling of latency-sensitive collective communication has never been more important. Capturing the device architecture and modeling control and data paths at high fidelity is therefore a necessity today. Having a common, detailed representation for distributed ML infrastructure is also crucial. We revisit the promising open-source, community-driven simulator: ASTRA-sim. In this work, we identify limitations of the current ASTRA-sim simulator and augment it with new features. To this end, we enable fine-grained, high-fidelity simulation with a standardized infrastructure representation, opening new design space exploration opportunities. We propose the simulation at cache-line-sized load-store granularity, with a detailed graphics processing unit (GPU) execution model, to balance simulation scalability and fidelity. We also introduce InfraGraph, a standardized representation to capture distributed ML network infrastructure in detail. Using the updated ASTRA-sim 3.0 simulator, we showcase interesting design space explorations for designing optimized collective algorithms, network requirements, and GPU architectures.

- **核心问题**：当前分布式机器学习（尤其是大模型推理）对集合通信的延迟高度敏感，但主流开源模拟器 ASTRA-sim 2.0 存在三大局限：
  - **不支持自定义集合算法**：仅内置少数经典算法（环形、二叉树等），无法评估学术界最新的集合通信研究成果。
  - **缺乏细粒度设备建模**：忽略 GPU 内部的控制通路、资源竞争及缓存行级的数据搬移，导致延迟估计严重失真。
  - **缺少标准化基础设施表示**：不同网络后端需各自描述拓扑，难以复用和共享，影响社区协作与结果复现。
- **研究意义**：以高保真度捕捉设备架构和控制/数据通路，并提供统一的分布式 ML 集群表示，对下一代 AI 基础设施的协同设计至关重要。

## 2. 方法论：核心思想与关键技术
### 2.1 细粒度负载表示：**Load-Store 粒度模拟**
- 将 GPU 内核分解为缓存行大小（如 128 B）的加载/存储指令序列，定义三类原语：
  - **数据指令**：`Load`、`Store`
  - **控制指令**：`SemaphoreAcquire`、`SemaphoreRelease`
  - **其他指令**：`Reduce`、`Waitcnt`
- 进一步封装为有意义的 **GPU 操作**（如 `MemcpyOp`、`BarrierOp`），逐波前（wavefront）、工作项组（workgroup）组织，最终形成完整的内核执行迹。

### 2.2 自定义集合通信支持：**MSCCL++ 绑定**
- 通过解析 MSCCL++ 的 JSON 表示，将自定义的 `put`/`get`/`signal`/`wait` 等语义自动翻译为 ASTRA-sim 3.0 的细粒度 GPU 操作。
- 实现任意集合算法的一键仿真，无需手动编码。

### 2.3 详细 GPU 执行模型
- **GPU 模型**：抽象为多个计算单元（CU），以轮询方式将工作项组映射到空闲 CU，模拟资源竞争。
- **计算单元**：维护波前调度，当某波前因控制操作停滞时，切换到其他就绪波前，体现波前级并行。
- **波前请求**：每次发起一条缓存行大小的网络交换，并为不同操作生成不同数量的请求。
- **循环展开**：可配置的展开因子，模拟一条波前同时发起多条内存请求的指令级并行。

### 2.4 升级的 Simple 网络模型
- 将原有以 GPU 为最小粒度的 Simple 模型升级为 **NoC 级** 表示，内部包含 CU、HBM 通道、I/O 端口等细节。
- 与细粒度波前请求对接，可同时仿真片上与片间网络传输，兼顾精度和速度。

### 2.5 InfraGraph：标准化基础设施图表示
- 将集群拓扑抽象为带属性的有向图：顶点表示 GPU、NIC 等物理组件，边表示连接，属性标注带宽/延迟。
- 提供可组合的 Device 蓝图和 Fabric 蓝图，支持参数化自动展开（如 Clos 胖树）。
- 翻译器可将同一 InfraGraph 转换为 Simple、ns-3、HTSim 等后端格式，并内建可视化工具。

## 3. 实验设计
- **目标平台**：通用 GPU 架构（128 CU，2D Mesh NoC，32 个内存通道，16 个 I/O 端口，总带宽 4 TiB/s，片间链路延迟 1 μs）。
- **案例Ⅰ – 集合算法设计**：对比基于 `get` 与 `put` 的 Reduce-Scatter（32 GPU，32 工作项组/GPU）和 All-Gather（16 GPU，60 工作项组/GPU），观测不同缓冲区大小下集合带宽，并分析控制消息仲裁的影响。
- **案例Ⅱ – GPU 架构探索**：
  - 测试不同循环展开因子（2~32）对 All-to-All 性能的影响。

## 6. 主要结论与发现
- **细粒度建模至关重要**：控制消息（信号、等待）与数据消息的竞争会显著影响集合带宽，仲裁策略可缓解阻塞，揭示了过去粗粒度仿真无法捕捉的性能瓶颈。
- **架构参数显著影响集合性能**：提高循环展开因子或最大并发波前请求数可提升带宽型集合的吞吐，但收益很快饱和，且对延迟敏感的小消息无效。
- **仿真可扩展性良好**：即使模拟 128 GPU、每个 GPU 含 448 端点的极细粒度场景，仿真时间随消息量线性增长，吞吐量基本稳定。
- **InfraGraph 切实可用**：同一拓扑描述可跨多个后端复用，且成功驱动了 ns-3 下的无损 Clos 网络仿真，证明了标准化表示的可行性。

## 7. 优点
- **高保真与可扩展的平衡**：以缓存行级 Load-Store 模拟控制/数据通路，兼顾精度与仿真速度。
- **首个支持 MSCCL++ 的公开模拟器**：天然兼容任意自定义集合算法，直接推动集合通信研究。
- **标准化基础设施图**：InfraGraph 的设计理念、蓝图机制和自动翻译器极大提升了多后端协同与社区共享的效率。
- **开源社区驱动**：延续 ASTRA-sim 生态，提供完整工具链，利于复现和扩展。

## 8. 不足与局限
- **缺乏真实硬件检验**：所有性能趋势均基于内部模型，未与实测数据对比，仿真结论的可信度有待实际系统验证。
- **场景覆盖有限**：仅展示了单节点多 GPU 和特定集合算法，未涉及异构网络、多机多卡推理流水线、存储/计算重叠等更复杂的工作负载。
- **建模假设理想化**：如固定缓存行大小、简单仲裁策略、无竞争的内存通道数等，可能偏离某些商业 GPU 的微架构。
- **无与其他模拟器的定量对比**：未提供与同类仿真工具（如 SimAI、TrioSim 等）的精度或速度对比，难以评估相对优势。
