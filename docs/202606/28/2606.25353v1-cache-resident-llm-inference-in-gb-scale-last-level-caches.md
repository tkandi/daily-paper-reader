## 摘要
大语言模型（LLM）推理日益受限于内存层次结构间的数据移动。近期三维堆叠缓存技术使现代服务器CPU能配备GB级末级缓存，从而可将可复用的模型权重保留在芯片上，并利用缓存带宽与延迟。达成这一状态并非易事：为实现权重驻留而加深流水线会增加在途请求与KV缓存占用，同时缓存驻留算子使得算子边界处的同步成为显著瓶颈。本文针对分层内存集群系统提出一种缓存驻留式推理执行模型。该模型将权重中心型算子与注意力机制及KV缓存管理分离，置于专用资源域中，使可复用权重驻留于缓存，同时使KV容量独立于流水线深度进行扩展。它还将同步从算子边界放宽至真正的子算子依赖，从而降低缓存驻留情境下的协调开销。我们在多路CPU集群上实例化了该模型，采用权重-注意力解耦架构、局部性感知的布局以及专用静态运行时。原型相比同等配置的llama.cpp性能大幅提升。在已部署的Llama-3.2-3B和Llama-2-7B配置上，其每输出令牌时间（TPOT）加速达2.04至11.51倍。在经验证的解析模型下，进一步在模型规模、上下文长度及批次大小维度上实现最高13.9倍的TPOT加速。这些结果表明，当执行围绕缓存驻留、解耦状态管理及依赖感知协调进行组织时，配备GB级末级缓存的商用CPU能够支持高效的大语言模型推理。

## Abstract
Large language model (LLM) inference is increasingly dominated by data movement across the memory hierarchy. Recent 3D-stacked cache technologies have enabled GB-scale last-level caches in modern server CPUs, making it possible to keep reusable model weights on chip and exploit cache bandwidth and latency. Achieving this regime is not straightforward: deeper pipelining for weight residency increases in-flight requests and KV-cache footprint, while cache-resident operators make operator-boundary synchronization a visible bottleneck.   We present a cache-resident execution model for inference on hierarchical-memory clustered systems. The model separates weight-centric operators from attention and KV-cache management into dedicated resource domains, keeping reusable weights cache-resident while scaling KV capacity independently of pipeline depth. It also relaxes synchronization from operator boundaries to true sub-operator dependencies, reducing coordination overhead in the cache-resident regime.   We instantiate this model on a multi-socket CPU cluster with a weight-attention decoupled architecture, locality-aware placement, and a specialized static runtime. The prototype substantially outperforms equally provisioned llama.cpp. On deployed Llama-3.2-3B and Llama-2-7B configurations, it achieves 2.04x-11.51x speedup on time-per-output-token (TPOT). Under a validated analytical model, it further reaches up to 13.9x TPOT speedup across model sizes, context lengths, and batch sizes. These results show that commodity CPUs with GB-scale last-level caches can support efficient LLM inference when execution is organized around cache residency, decoupled state management, and dependency-aware coordination.

## 1. 论文核心问题与研究背景

- **核心问题**：大语言模型推理的性能瓶颈已从计算转向数据移动，尤其是模型权重和KV缓存数据在内存层次结构中的搬运。随着模型扩大，访存带宽成为限制吞吐与延迟的关键。
- **研究背景**：
  - 现代服务器CPU通过3D堆叠缓存技术可配备GB级末级缓存（LLC），理论上可将LLM权重驻留在芯片上，利用高带宽和低延迟。
  - 但是，简单用流水线并行（PP）将模型层分片以实现缓存驻留会导致KV缓存压力随流水线深度增加而增大，因为每节点需维护更多在途请求的KV状态，与权重争抢缓存容量。
  - 同时，当算子因缓存驻留而变快后，算子边界的全局同步开销不可忽略，传统的算子中心执行成为新瓶颈。
- **整体目标**：提出一种缓存驻留执行模型，在商用多路CPU集群中实现LLM权重和KV缓存的高效驻留，降低同步开销，显著提升推理性能。

## 2. 方法论

### 2.1 核心思想：权重–注意力（WA）解耦与子算子同步
- **权重–注意力解耦**：将Transformer解码路径划分为两类操作：① 权重中心算子（QKV投影、FFN），仅依赖静态模型权重；② 注意力算子，仅依赖动态KV缓存。将它们部署到独立的资源域（CPU socket上），使权重节点无需维护KV缓存，注意力节点专注KV状态管理，消除二者在缓存容量上的相互干扰。
- **子算子异步同步**：突破算子边界全局同步，将同步粒度细化为多头注意力的头级完成信号和FFN的树形归约，减少全局屏障导致的缓存一致性和锁争用开销。

### 2.2 关键技术实现
- **并行化资源映射**：
  - 集群间采用流水线并行（PP），将连续的Transformer层分配到不同服务器节点，仅传递激活张量。
  - 单节点内双路CPU采用WA解耦：一个socket作为权重节点（执行QKV投影、FFN），另一个socket作为注意力节点（执行注意力并维护KV缓存）。
  - socket内部通过张量并行（TP）将输出通道分片到各物理核心，利用私有缓存实现高复用。
- **缓存驻留计算内核**：
  - GEMV内核：激活向量驻留L1，权重和KV缓存从LLC流式访问，并通过首次触触摸（first-touch）策略将权重分片绑定到邻近的LLC bank。
  - 注意力内核：采用flash风格分块计算，减少中间结果；FFN采用树形归约同步来避免重复从LLC流式权重数据。
- **专用静态线程池运行时**：替代OpenMP，将线程永久绑定到核心，实现固定的分片-核心映射和层次化同步（CCD内局部同步，再CCD间同步），避免通用调度器的原子操作争用和缓存行弹跳。
- **节点间通信**：使用InfiniBand RDMA传输激活张量，通信延迟占端到端解码时间的比例极低（如LLaMA-3B上约0.5%）。

### 2.3 性能模型
- 采用解析模型刻画延迟与吞吐：

## 6. 主要结论与发现

- 商用CPU通过GB级末级缓存，结合缓存驻留执行设计，可实现高效LLM推理。
- **实测加速**：LSMA-3.2-3B上TPOT加速2.83–11.51倍，LSMA-2-7B上加速2.04–10.43倍，小批次优势最显著。
- **消除KV缓存压力悖论**：WA解耦使权重和KV缓存不再争抢同一片高速缓存，扩展KV容量无需加深权重节点的流水线。
- **同步开销可观**：线程池消融显示，专用静态运行时在算子延迟几百微秒时，能减少数十微秒同步开销，小批次下相对加速比可达1.56倍。
- **WA分离的收益与代价**：当KV缓存压力大时（大模型、长上下文），WA分离带来明显加速（70B上最高1.30倍）；但会消耗额外socket，提高单位socket成本。
- **一致性**：LSMA-3.2-3B和LSMA-2-7B生成结果与原模型输出完全一致，未牺牲正确性。
