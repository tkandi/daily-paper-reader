## 摘要
混合专家（MoE）模型已成为扩展大型语言模型的事实标准。为保持计算效率，现代 MoE 服务系统通常采用混合并行策略，将注意力阶段的数据并行（DP）与 MoE 阶段的专家并行（EP）相结合。然而，这种设计需要在注意力 DP 组和专家之间频繁设置全局同步屏障。在线服务中，请求到达速率和序列长度的固有大差异会导致 DP 不平衡，引发严重的同步停滞，从而延长首个令牌生成时间（TTFT）并降低系统吞吐量。本文提出 ASAP，一个专为加速 MoE 模型预填充阶段而设计的异步推理系统。ASAP 将注意力阶段与 MoE 阶段解耦，并实现完全异步的执行流水线。通过一套专用的异步通信原语以及针对请求调度和模型执行的四项协同优化，该系统彻底消除了全局同步屏障。我们在 CloudMatrix384 超级节点上实现并评估了 ASAP，结果表明，相比最先进的同步服务方案，其满足服务等级目标（SLO）的预填充吞吐量提升了 90%。

## Abstract
Mixture-of-Experts (MoE) models have become the de facto standard for scaling large language models. To maintain computational efficiency, modern MoE serving systems typically employ a hybrid parallelism strategy, combining Data Parallelism (DP) for attention stages with Expert Parallelism (EP) for MoE stages. However, this design necessitates frequent global synchronization barriers between attention DP groups and experts. In online serving, significant variance in request arrival rates and sequence lengths inherently leads to DP imbalance, causing severe synchronization stalls that degrade Time-to-First-Token (TTFT) and system throughput. We present ASAP, an asynchronous inference system specifically designed to accelerate the prefill phase of MoE models. ASAP disaggregates the attention and MoE stages and implements a fully asynchronous execution pipeline. This is achieved through a suite of specialized asynchronous communication primitives and four coordinated optimizations across request scheduling and model execution, which collectively dismantle global synchronization barriers. We implement and evaluate ASAP on CloudMatrix384 super-nodes, demonstrating that it improves SLO-compliant prefill throughput by 90% compared to state-of-the-art synchronous serving solutions.

### 一、论文的核心问题与整体含义

现代大规模 MoE 模型（如 DeepSeek-V3）在线推理服务普遍采用“注意力阶段的数据并行 + MoE 阶段的专家并行”混合策略。注意力 DP 之间的请求批次需频繁进行全局同步，以便后续 MoE 阶段对共享专家池进行统一计算。然而在实际生产环境中，请求到达速率、序列长度、前缀缓存命中率等因素高度随机，导致各 DP 组工作负载显著不均衡（所谓 “DP 不平衡”）。这种不平衡与刚性同步屏障耦合，会形成严重的**掉队效应**：快速完成的 DP 组必须等待最慢的 DP 组，从而导致大量计算资源空转、首个令牌生成时间（TTFT）延长、系统吞吐量严重下降。

论文提出 **ASAP**，是首个面向 MoE 预填充阶段的**完全异步推理系统**，通过彻底消除全局同步屏障，使异构请求批次能真正以各自速度“流动”，从而有效将空闲的同步时间转化为有效的计算时间。

### 二、论文提出的方法论

ASAP 的核心在于将注意力阶段与 MoE 阶段**物理解耦**，并构建一个全异步执行流水线。方法论由以下 4 个层次构成：

#### 2.1 解耦设计与异步通信原语

- **物理解耦**：将注意力设备（共 `D×T` 个 NPU）与 MoE 设备（共 `E` 个 NPU）从硬件上分离。系统为每个设备静态分配一块对所有其他设备可见的**分布式共享内存缓冲区**（充当“超级通信枢纽”）。
- **异步通信原语**：
  - **异步分发**：发送方（注意力设备）通过 `async-dispatch-send` 将 token 直接写入目标 MoE 设备缓冲区的指定区域并置位标志位，**不等待接收方确认**即返回继续计算。MoE 设备通过 `async-dispatch-recv` 轮询标志位，当某个 DP 组的所有 TP 片段数据就绪后，将数据拷贝至私有内存并清除标志位。
  - **异步合并**：MoE 设备完成专家计算后，通过 `async-combine-send` 将结果写回对应注意力设备缓冲区。注意力设备通过 `async-combine-recv` 检查所有所需专家的结果是否到齐，拷贝后清除标志位。
- **背压机制**：若目标缓冲区标志位未清，发送方会阻塞写入，以保证数据完整性。

#### 2.2 请求调度优化

- **长度感知批量聚合**：保证送往 MoE 设备的批次 token 总量超过 MoE 阶段的“拐点”（如论文中的 2k tokens），使 MoE 计算突破内存带宽瓶颈，进入高效的线性计算区间。由于各 DP 组异步独立执行，调度器无需再为跨 DP 负载均衡做复杂优化。
- **双批次交错**：当等待队列中请求数量满足条件后，一次性向同一个空闲 DP 组提交成对的两个请求批次。当其中一个批次的数据被卸载到 MoE 进行计算时，注意力设备立即开始处理同层另一个批次的注意力计算，以避免注意力设备空转。对于长序列（注意力延迟远大于 MoE 延迟），系统会禁用交错以避免排队延迟。

#### 2.3 模型执行优化

- **通信-计算重叠之三流设计**：在每张 NPU 上分别创建 1 个主计算流和 2 个独立通信流。计算流处理正常的模型前向传递；通信流独立执行异步数据搬运，将通信开销隐藏在计算过程中。
- **无气泡核函数下发之 MoE 超级核**：
  - **问题**：异步乱序执行下，MoE 设备下一层要执行的层 ID 只能在运行时动态确定，导致 CPU 无法“提前”下发 NPU 计算核，每次下发的开销（约 220 µs/层）直接暴露在关键路径上。
  - **方案**：将所有层的专家权重在 HBM 中连续存放，设计一个**层无关**的 MoE 超级核。该核接受“层 ID”作为设备端动态参数，从预先计算好的地址数组中通过常量时间索引直接找到对应层的权重，然后执行分组矩阵乘法。
  - **效果**：CPU 可以提前一次性下发该超级核，从根本上消除了层间的 CPU 下发气泡。

### 三、实验设计

- **部署环境**：华为 CloudMatrix384 超级节点，由 384 张昇腾 910 NPU 经统一总线互联组成（任意 NPU 间带宽 400 GB/s）。
- **模型与并行配置**：DeepSeek-V3.2（671B 参数、256 专家、每 token 激活 8 专家 + 1 共享专家）。ASAP 配置为 `D=4`（注意力 DP）、`T=4`（注意力 TP）、`E=16`（专家 EP），共 32 张 NPU，与基线 32 张 NPU 相同，保证公平。
- **工作负载**：
  - 请求到达间隔遵循**泊松分布**，以请求每秒（RPS）作为负载强度表征。
  - 序列长度采样自**华为云生产环境真实轨迹数据集**（分布极不均衡：均值 5K，尾部长达约 100K）。
  - 预填充 TTFT 的 SLO 设为 **5 秒**。
- **基准方法（Baselines）**：
  - **Default**：类似 vLLM 的标准同步调度逻辑，按总 token 数相近原则组批次并分发给 DP 组。
  - **ChunkedPrefill**：将长序列切分为 8K token 的块顺序处理，以降低序列长度方差来缓解 DP 不平衡。

### 六、论文的主要结论与发现

- **性能提升显著**：在 5 秒 TTFT 的 SLO 下，ASAP 的预填充吞吐量相比 Default 和 ChunkedPrefill 分别提升 **194% 和 90%**（20 vs. 6.8 vs. 10.5 RPS）。低负载下 TTFT 缩短 34%，高负载下缩短超 50%。
- **根本症结得到解决**：延迟分解显示，同步系统中短请求的非核函数开销（同步等待 + 排队）占 TTFT 比例可高达 85%，而 ASAP 通过异步化将这部分开销**削减了 80%**。
- **关键技术有效**：
  - 异步通信原语延迟仅为同步点对点方案的 1/5 至 1/6（8K tokens 下）。
  - 双批次交错将吞吐量绝对上限提升 14.3%。
  - 通信-计算重叠和 MoE 超级核分别带来 12.4% 和 6% 的吞吐量增益。

### 七、优点

- **问题定义精准**：首次系统性地指出并量化了 MoE 预填充场景下的 DP 不平衡问题，而非笼统地谈负载不均。
- **系统设计完整且精巧**：从硬件拓扑利用（超级节点分布式共享内存）到底层通信原语，再到调度与执行优化，形成了一套从通信到计算的“全栈异步”方案。

- **评估扎实**：结合真实生产轨迹、严格消融实验、微观性能拆解，证据链清晰，说服力强。

### 八、不足与局限

- **评估维度较保守**：主要测定了纯预填充阶段的吞吐量与延时，对并发预填充-解码实例间的资源干扰、KV 缓存带宽争抢等未做探讨。
