## 摘要
高性能GPU核函数对于降低大型语言模型（LLM）指数级增长的计算成本至关重要，但其开发严重依赖领域专家的人工调优。尽管近期基于LLM的方法在自动化核函数生成方面展现出前景，但它们仍难以同时实现正确性和高性能。这一限制主要源于缺乏领域特定的优化指导，阻碍了对优化空间的有效探索。我们提出EGG，一个面向核函数生成的专家引导型智能体框架，它融合了专家优化原则来指导LLM的决策。受专家工作流程启发，我们将核函数生成分解为两个层级阶段：1）算法结构设计，为高质量的计算结构奠定基础；2）硬件特定调优，通过并行映射、张量分块和内存优化进行针对性调整。这种分阶段分解定义了明确的优化目标，构建了设计空间以实现渐进式优化。为此，我们设计了一种阶段感知的多智能体协作机制，用于阶段间和阶段内的上下文管理，确保优化轨迹的稳定性。在KernelBench和真实世界工作负载上的实验表明，EGG相比PyTorch平均实现了2.13倍的加速，优于现有的基于智能体和基于强化学习的方法。

## Abstract
High-performance GPU kernels are critical for reducing the exponentially growing computational costs of large language models (LLMs), but their development heavily relies on manual tuning by domain experts. While recent advances in LLM-based approaches show promise for automating kernel generation, they still struggle to achieve both correctness and high performance. This limitation primarily arises from the lack of domain-specific optimization guidance, hindering effective exploration of the optimization space. We propose EGG, an Expert-Guided Agent Framework for Kernel Generation, which incorporates expert optimization principles to guide LLMs' decisions. Inspired by expert workflows, we decompose kernel generation into two hierarchical stages: 1) algorithmic structure design, which establishes a high-quality computational structure foundation; 2) hardware-specific tuning, which performs targeted adjustments through parallel mapping, tensor tiling, and memory optimization. This staged decomposition defines explicit optimization objectives, structuring the design space to achieve progressive refinement. To this end, a stage-aware multi-agent collaboration mechanism is designed for inter and intra-stage context management, ensuring stable optimization trajectories. Experiments on KernelBench and real-world workloads show that EGG achieves a 2.13x average speedup over PyTorch, outperforming existing agent-based and RL-based approaches.

## 2. 论文提出的方法论
EGG采用**专家引导的分阶段优化**与**阶段感知的多智能体协作**两大核心设计。

### 2.1 专家引导的分阶段优化
- **算法结构设计**（建立性能上界）  
  - *多种子搜索*：为同一算子生成多种算法范式（如直接卷积 vs. im2col + 矩阵乘法），提供多样化起点。  
  - *算法精炼*：对每种子的计算结构进行语义保持的变换（如算子融合、在线 softmax 等），消除结构低效，仅保留性能最佳的候选人进入下一阶段。  
- **硬件特定调优**（逐层实现潜力）  
  在固定算法结构的基础上，依次进行三个子阶段：  
  1. **并行映射**：将算子维度映射到 GPU 执行网格，提高流多处理器利用率。  
  2. **张量分块**：选择合适的块大小（如 BM、BN、BK），平衡数据重用与寄存器/共享内存压力。  
  3. **内存优化**：组织全局内存合并访问，调节多缓冲深度以隐藏访存延迟。  
  各阶段均定义明确的优化目标，后一阶段在前一阶段的决策约束下工作，形成渐进式精化。

### 2.2 阶段感知的多智能体协作
- **智能体角色**

  - *调试智能体*：针对编译错误、运行时异常、数值不一致提供定向修复方案。  
- **上下文管理**  
  - *阶段间上下文传播*：阶段切换时仅保留最终决策与内核实现，丢弃中间探索产物，避免跨阶段干扰。

## 7. 优点
- **专家知识显式引导**：通过分阶段目标与结构化提示，将难以量化的专家经验转化为 LLM 可遵循的优化路径，大幅降低无效探索。  
- **设计空间结构化**：算法结构→硬件调优的层级分解，将巨大的联合优化问题拆解为一系列约束清晰的子问题，提升可控性与生成稳定性。  
- **多智能体分工明确**：分析、生成、调试角色分离，配合上下文过滤，有效避免目标漂移与累积误差。  
- **跨硬件、跨 LLM 泛化**：在多种 GPU 架构和不同后端模型上均表现稳定，展示框架的通用性。  
- **成本效率**：相较纯迭代搜索基线，EGG 在更少的 token 预算内获得更高性能。

## 8. 不足与局限
- **依赖专家先验**：优化路径的设计高度依赖人工总结的规则，可能限制对非传统优化模式的发现；如何自动学习或更新专家原则尚未解决。  
- **缺乏跨阶段联合优化**：顺序决策可能使前期局部最优选择在后期组合时非全局最优，虽有助于控制搜索成本，但在充足算力下可能牺牲部分性能。  
- **搜索预算仍较高**：单个内核生成消耗约 5 万 token、20 分钟，对于需要批量生成大量内核的场景仍构成一定开销。  
- **主要面向 Triton DSL**：实验集中于 Triton 抽象层级，对 CUDA 等更底层、优化空间更大的语言尚待验证。  
- **失败处理与鲁棒性**：虽设计了有限次的重试与修复机制，但若所有种子均无效或修复失败，任务将提前终止，可能漏掉某些复杂算子的可行解。
