## 摘要
机器学习（ML）训练与推理经常需要处理远超 GPU 内存容量的数据集，迫使它们依赖 PCIe 进行按需张量传输，从而产生严重的传输瓶颈。有损压缩已被提议用于缓解此类瓶颈，但会引入依赖于工作负载的精度损失，导致在现有 ML 部署中使用复杂甚至不可行。我们探索无损压缩作为一种避免此部署复杂性的替代方案。我们确定了无损压缩可以集成到 ML 流水线中的位置，同时尽量减少对 GPU 执行的干扰。基于我们的发现，我们提出了不变位打包（IBP），这是一种新颖的无损压缩算法，旨在最小化 ML 的数据传输时间。IBP 识别并消除张量组中的不变位，通过利用 warp 并行性、低开销位操作和异步 PCIe 传输的 GPU 优化解压缩来提高吞吐量。我们提供了易于使用的 API，通过为图神经网络（GNN）训练以及 DLRM 和 LLM 推理框架添加 IBP 支持来展示它们。IBP 平均实现了 74% 的 GNN 训练加速，180% 的 DLRM 嵌入查找加速，以及 24% 的 LLM 推理加速。

## Abstract
Machine learning (ML) training and inference often process data sets far exceeding GPU memory capacity, forcing them to rely on PCIe for on-demand tensor transfers, causing critical transfer bottlenecks. Lossy compression has been proposed to relieve bottlenecks but introduces workload-dependent accuracy loss, making it complex or even prohibitive to use in existing ML deployments. We explore lossless compression as an alternative that avoids this deployment complexity. We identify where lossless compression can be integrated into ML pipelines while minimizing interference with GPU execution. Based on our findings, we introduce Invariant Bit Packing (IBP), a novel lossless compression algorithm designed to minimize data transfer time for ML. IBP identifies and eliminates invariant bits across groups of tensors, improving throughput through GPU-optimized decompression that leverages warp parallelism, low-overhead bit operations, and asynchronous PCIe transfers. We provide easy-to-use APIs, showcasing them by adding IBP support to GNN training, as well as DLRM and LLM inference frameworks. IBP achieves, on average, 74% faster GNN training, 180% faster DLRM embedding lookup, and 24% faster LLM inference.

*   **现有方案不足与本文思路**

### 2. 论文提出的方法论：不变位打包 (Invariant Bit Packing, IBP)

IBP 的核心思想是发现并利用 ML 数据中跨张量的“位不变性”来实现压缩。

*   **核心观察：ML 数据的位不变性**
    *   ML 张量（特征向量、嵌入表、KV 缓存等）在位级别上并非完全随机。由于数据正则化、分布结构化等原因，许多高位（如浮点数的符号位、指数位）在大量张量间保持相同值。
    *   通过仅存储一次这些不变位，并从每个张量中去除，即可实现无损压缩。

*   **IBP 算法流程**
    1.  **预处理（Preprocessing）**：
        *   对整个数据集进行扫描，统计每个比特位为 `1` 的次数。
        *   设定一个阈值 `T`（如 `80% × 张量总数 N`）。若某个比特位的 `1` 计数大于 `T`，则认为该位是值恒为 `1` 的不变位；若 `1` 计数小于 `N - T`，则认为该位是值恒为 `0` 的不变位。其余位为可变位。
        *   据此生成一个**掩码（Mask）**（标记哪些是不变位）和一个**位值（Bitval）**（记录不变位的值）。此元数据（大小仅为 KB 级别）被存入 GPU 显存，全局共享。

    2.  **压缩（Compression）**：
        *   将张量分成固定大小的块（chunk），每个块由一个 GPU 线程处理。
        *   在每个块前添加**参与位（participation bit）**，指示该块是否被压缩。若块中位值与 Mask 和 Bitval 匹配，则可压缩，移除其中的不变位；若不匹配，则保留原始数据。
        *   利用 GPU 的 warp 原语（warp intrinsics）在 warp 内线程间进行通信与扫描，快速计算出每个压缩块在输出缓冲区中的偏移量以执行并行写入。

    3.  **解压缩（Decompression）**：
        *   这是性能关键路径。IBP 采用 **warp 并行迭代解压缩** 来最小化开销。
        *   每个 warp 负责一个张量，warp 内线程协作从 CPU 内存**对齐读取**一段数据到共享内存（workspace）。
        *   线程读取各自的 Mask 块，通过 warp 原语进行**排他性扫描（exclusive scan）**，计算出各自需要读取的数据位在 workspace 中的起始偏移量。
        *   线程独立完成解压缩。同时利用 **异步内存拷贝**，在解压当前数据时预取下一段数据，将计算与数据传输重叠。整个过程确保 CPU 内存只被顺序扫描一次，实现效率最大化。

*   **高效 PCIe 数据传输**
    *   **对齐传输（Aligned Transfers）**：确保从 GPU 发起的数据读取是 128 字节对齐的，符合硬件合并访问要求，以最大化 PCIe 吞吐量。
    *   **有界传输（Bounded Transfers）**：采用基于上下界的动态长度拷贝，保证迭代读取连续缓冲区时始终是 128B 对齐的段。
    *   **GPU 直读**：利用 CUDA 的零拷贝（Zero-Copy）特性，由 GPU 直接访问并解压 CPU 内存中的数据，避免 CPU 侧复杂的 DMA 启动开销。

*   IBP 在所有测试的 ML 数据集上都能实现**无损压缩**，空间节省从 8% 到 27% 不等，在 BF16 类型数据（如现代 LLM）上表现尤为突出。

*   IBP 的设计对上层应用友好，集成到现有框架所需代码修改极少（< 40 行 Python/CUDA 代码）。

### 7. 优点

*   **新颖性与实用性结合**：抓住了 ML 数据跨张量存在位不变性这一被忽视的规律，提出的 IBP 算法简单有效且易于部署，不影响模型精度。
*   **全栈式优化**：不仅是提出一个压缩算法，还深度结合了 GPU 架构特性（warp 并行、共享内存、异步拷贝、内存对齐），对压缩、解压和传输路径进行了系统级优化。

### 8. 不足与局限

*   **硬件依赖性强**：性能优化紧密耦合于特定 GPU 架构特性（如 warp 原语、L1 缓存/共享内存），设计方案和结论在非 NVIDIA GPU 或其他平台上的可迁移性有待验证。
*   **压缩率依赖于可找到的不变性**：IBP 的压缩增益完全取决于数据本身是否存在跨张量的不变位。对于高度随机或已充分打散的数据，压缩效果可能有限。
*   **预处理开销**：虽然是一次性的，但对于首次接触或频繁更新的数据集，预处理会引入一定的启动延迟。
*   **实验覆盖面**：LLM 推理实验中，由于兼容性问题，仅使用 OPT 模型测试了 FP16 的 KV 缓存压缩，虽然使用了 Gemma 测试了 BF16 权重压缩，但未对现代 LLM 中最优潜力场景（BF16 KV 缓存压缩）进行全面端到端评估。
