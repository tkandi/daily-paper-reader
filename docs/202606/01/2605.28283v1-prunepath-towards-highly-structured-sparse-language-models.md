## 摘要
前馈网络（FFNs）占据了现代语言模型的主要参数和计算量，然而现有剪枝方法常常难以将稀疏性转化为硬件友好的推理效率增益。我们提出了 PrunePath，一个针对 FFN 层的预算自适应结构化稀疏化框架。PrunePath 基于 MoEfication，用 softmax 归一化的路由分布替代独立的专家级别阈值，并在累积质量阈值下激活重要专家。这一设计施加了令牌级概率预算，从而实现自适应专家数量，并允许从单一检查点直接调控推理时的稀疏程度。在自然语言理解、自然语言生成和指令微调评估中，与现有静态剪枝和基于 MoEfication 的方法相比，PrunePath 在稀疏性与性能之间实现了更优的权衡。我们进一步实现了用于 KV 缓存解码的 Triton 内核，将所产生的结构化稀疏性转化为实际的内存节省和可测量的解码速度提升。这些结果展示了 PrunePath 在构建高度稀疏、易于部署的大语言模型方面的卓越性能。

## Abstract
Feed-forward networks (FFNs) dominate the parameter count and computation of modern language models, yet existing pruning methods often struggle to convert sparsity into hardware-friendly inference efficiency gains. We introduce \textbf{PrunePath}, a budget-adaptive structured sparsification framework for FFN layers. Built on MoEfication, PrunePath replaces independent expert-wise thresholding with a softmax-normalized routing distribution and activates important experts under a cumulative-mass threshold. This formulation imposes a token-level probability budget, enabling adaptive expert counts and a direct inference-time sparsity knob from a single checkpoint. Across NLU, NLG, and instruction-tuning evaluations, PrunePath achieves a favorable sparsity--performance trade-off compared with existing static pruning and MoEfication-based methods. We further implement Triton kernels for KV-cache decoding to translate the resulting structured sparsity into practical memory savings and measurable decoding-speed improvements. These results demonstrate the superior performance of PrunePath for building highly sparse, deployment-friendly large language models.

- **核心问题**：现代大语言模型（LLM）中，前馈网络（FFN）占据约三分之二的参数量和大部分计算 FLOPs，它们的密集矩阵乘法造成巨大的内存占用和延迟瓶颈。现有的剪枝方法（如非结构化剪枝、N:M 结构化稀疏及基于 MoEfication 的独立阈值路由）要么无法在硬件上高效实现，要么在稀疏性增大时性能劣化严重，难以将稀疏性转化为实际的推理加速。
- **研究动机**：亟需一种**高度结构化、硬件友好的稀疏 FFN 推理方法**，能够在保持任务性能的同时，使模型在资源受限设备上实际减少内存消耗和提升解码速度。论文旨在提出一套预算自适应的结构化稀疏框架，解决从稀疏性到部署效率的转化难题。

## 2. 方法论：PrunePath 的核心思想与技术细节

### 2.1 基础框架与专家分解
- 基于 **MoEfication**：将 FFN 的中间神经元按权重相似性聚类成若干个专家（Expert），保证全专家激活时可精确恢复原 FFN 输出。
- 每个 FFN 层分解为 E 个等宽的专家，对应权重矩阵分别为 \(\tilde{W}_{gate}^{(e)}\)、\(\tilde{W}_{up}^{(e)}\)、\(\tilde{W}_{down}^{(e)}\)。

### 2.2 累积质量专家激活
- **路由机制**：使用轻量线性路由器 \(W_r\) 产生专家 logits \(g = W_r^\top x\)，再经 softmax 得到概率分布 \(\{p_j\}\)。
- **选择规则**：按概率降序排序，**保留累计概率质量小于阈值 τ 的专家**，并始终保留概率最高的专家。具体为：
  \[
  \mathcal{A}_\tau(x) = \{\pi_1\} \cup \left\{\pi_i \;\middle|\; \sum_{r=1}^i p_{\pi_r} < \tau\right\}
  \]
  该设计借鉴核采样（nucleus sampling）的思想，为每个 token 分配一个概率预算，实现 token 级自适应专家数量。
- **输出聚合**：仅激活集合内的专家参与计算，并用 Sigmoid 门控（而非 softmax 权重）缩放各自输出：
  \[
  y_\tau(x) = \sum_{e \in \mathcal{A}_\tau(x)} \text{sigmoid}(g_e) \cdot \text{FFN}_e(x)
  \]
  这样将竞争性选择与输出缩放解耦，避免归一化权重对激活数量产生干扰。

### 2.3 渐进稀疏路径训练
- **训练流程**：
  1. **全专家预热阶段**：设置 \(\tau_{\text{warm}}=1.05\)，激活所有专家。
  2. **递减阈值**：按照线性计划降低 τ 值至目标 \(\tau_{\min}\)：
     \[
     \tau_t = 1.0 - (1.0 - \tau_{\min}) \frac{t}{T}, \quad t=1,\dots ,T
     \]
     让模型逐步适应更稀疏的专家子集。
- **辅助损失**：
  - **熵最小化损失** \(L_{ent}\)：鼓励路由分布变得尖锐，使高概率专家更明确。
  - **负载均衡损失** \(L_{bal}\)：防止路由分布坍缩到个别专家，保证所有专家都能参与训练。
  - 总损失：\(L = L_{task} + \eta L_{ent} + \lambda L_{bal}\)。
- **指令微调适配**：针对 Qwen2-7B 引入 **门控幅度正则化** \(L_{gate}\)，抑制 Sigmoid 门控值过大，减少全专家输出与稀疏输出之间的不匹配。

### 2.4 Triton 加速的稀疏 FFN 推理
- 设计针对 KV‑cache 自回归解码的 Triton 内核，将同属于一个专家的神经元在内存中连续存储，使每个选中专家的计算变为**密集矩阵块运算**。
- 实现稀疏路由、选择执行和结果归约，实测降低峰值 GPU 内存使用并提升解码吞吐量。

## 6. 主要结论与发现

- PrunePath 在 NLU、NLG 和指令微调任务上，相较于 LTE 和 Wanda，在所有稀疏度区间都实现了**更优的性能‑效率权衡**。
- 累积质量路由能学到 **更紧凑的专家排序**：在极低专家预算下（Top‑1 或 Top‑8），重建误差显著低于 LTE。
- **单一检查点即支持多级推理稀疏度**：只需调整累积质量阈值 τ，无需重新训练，模型可实现从低稀疏到 60%+ 稀疏的平滑性能下降，而 LTE 需为每个稀疏度单独训练模型。
- Triton 内核实现将结构化稀疏性转化为**实际内存节省（峰值 VRAM 降低 17.9%）和解码延迟降低 4.4%**，解码吞吐量提升。
- PrunePath 为构建“高度稀疏、易于部署”的大语言模型提供了一条简单且有效的技术路径。

## 7. 优点

- **预算自适应的激活机制**：用累积概率质量替代独立阈值，提供清晰、可预测的推理稀疏度控制。
- **训练稳定且兼容性高**：渐进式训练路径避免直接高稀疏训练的崩溃；可与多种 FFN 结构（如 SwiGLU）结合。
- **部署灵活性**：单一检查点覆盖多级稀疏，节省存储和训练开销。
- **端到端验证**：不仅停留在模型质量指标，还通过 Triton 内核证明了实际推理加速和内存收益。
- **消融实验扎实**：从初始化、排名质量到负载均衡和正则化均有详细分析。

## 8. 不足与局限

- **路由额外开销**：每次前向需计算 softmax 并对专家概率排序、累加，该操作对于极低延迟场景或吞吐优化不够友好，可能抵消部分理论计算减少带来的加速。
- **预填充阶段未充分优化**：当前 Triton 内核主要针对单 token 解码，预填充阶段的多 token 批量路由、分发与归约尚存在效率瓶颈，仅报告了解码速度。
- **模型规模验证受限**：实验仅到 7B 参数规模，10B 以上超大规模模型及生产级服务环境下的效果尚未验证。
- **校准数据依赖性**：指令微调场景中，若路由仅在 SFT 分布上训练，可能在预训练知识密集型任务（如 MMLU）上出现专家使用模式不匹配，文中已讨论这一偏差风险。
- **压缩粒度固定**：FFN 稀疏性仅作用于专家粒度，不能进一步细粒度压缩（如单个神经元），可能错过更高压缩比的机会。
