## 摘要
代理AI应用组合多个模型调用与工具执行，为GPU-CPU集群带来了新的调度挑战。其推理时间和模型调用结构通常依赖于提示语义，使得传统调度方法难以实现低延迟服务。本文提出了SwarmX，一个为低延迟代理应用实现代理调度的系统。SwarmX运用调度专用的神经预测器来捕获提示、设备、运行时以及目标模型特征；将分布性预测暴露给路由器和扩缩器以做出尾部感知的决策；并提供了预测器训练和在线适应的机制。这些预测器和机制被整合到一个调度器-代理框架中，为与现有调度和模型服务基础设施的集成提供了通用基础。我们利用生产环境部署（近千块GPU和一百万个CPU核心）以及在128-GPU测试平台上的受控实验对SwarmX进行了评估。在多代理代码生成、深度研究以及多模态代理工作流中，与最先进的调度器相比，SwarmX最多将尾部延迟降低了61.5%，并在相同SLO下维持高达生产调度器2倍的吞吐量。

## Abstract
Agentic AI applications compose multiple model calls and tool executions, creating new scheduling challenges for GPU-CPU clusters. Their inference time and model-call structure often depend on prompt semantics, making conventional scheduling approaches ineffective for low-latency serving. This paper presents SwarmX, a system that implements agentic scheduling for low-latency agentic applications. SwarmX uses scheduling-specific neural predictors to capture prompt, device, runtime, and target-model features; exposes distributional predictions to routers and scalers for tail-aware decisions; and provides mechanisms for predictor training and online adaptation. These predictors and mechanisms are integrated into a scheduler-agent framework that provides a common substrate for integration with existing scheduling and model-serving infrastructure. We evaluate SwarmX using production deployment (nearly one thousand GPUs and one million CPU cores) and controlled experiments on a 128-GPU testbed. Across multi-agent code generation, deep research, and multimodal agentic workflows, SwarmX reduces tail latency by up to 61.5% compared to state-of-the-art schedulers and sustains up to 2x the throughput of production schedulers under the same SLO.

## 1. 论文的核心问题与整体含义（研究动机和背景）
- **核心问题**：代理AI应用（如多代理代码生成、深度研究、多模态工作流）由多个大模型调用和工具执行组合而成，推理时间和调用结构严重依赖提示语义，传统调度器（轮询、随机、基于点估计或平均延迟）难以处理这种**提示依赖的动态性**，导致GPU-CPU集群上尾部延迟高、资源利用差。
- **整体含义**：需为代理工作负载设计一种**预测驱动、尾部感知且能与现有基础设施无缝集成**的调度方法，即“代理调度”。SwarmX正是通过神经预测器捕获提示语义、设备状态和运行时特征，将路由与扩缩决策从被动响应转为主动预测，从而在低QPS、长请求的代理场景中大幅降低尾部延迟。

## 2. 论文提出的方法论
### 核心思想
将集群中的路由器和扩缩器转化为**轻量级调度器代理**，每个代理观察提示、设备、运行时状态，调用神经预测器估计延迟与模型调用的分布，并通过分布感知决策框架转化为安全、有界的调度动作。

### 关键技术细节
- **神经预测器设计**
  - 解耦为两部分：**语义模型**（目标模型的同构小型变体，如8B模型对应35M参数预测器）负责从提示中提取语义特征；**多层感知机（MLP）** 融合语义特征与设备、运行时、目标模型特征，输出分布预测（分位数）。
  - 路由器预测请求延迟分布；扩缩器预测下游模型调用数量分布。
  - 预测开销极低：35M参数模型在CPU约30 ms，GPU约4 ms；66K参数模型仅需<1 ms。

- **分布感知调度**
  - 用**分位数草图**表示预测分布与队列/需求状态，保留尾部形状。
  - 通用组合模板：对于候选动作，预测其引发的负载分布，与当前状态合成得到候选状态，再由尾部成本评估器（如P99延迟）得到候选成本分布，最后**从成本分布中采样**并选择最优的一个。
  - 路由算法见论文 Algorithm 1；扩缩器采用相同模式，仅替换状态为需求草图。

- **训练与在线适应**
  - 分阶段训练：语义模型预测输出长度等响应属性（MSE等损失）；路由器MLP预测延迟分位数（加权 pinball 损失）；扩缩器MLP预测下游调用数分位数。
  - 在线适应：监控尾部 pinball 误差，按提示/设备分组维护滑动窗口，平均误差超阈值则**异步重训练轻量MLP**（语义模型仅在大模型更新时才重训），可在100秒内从严重资源偏移中恢复。

- **调度器-代理框架**
  - 提供预测器、协调器、内存和基础架构特定的**动作集**（如 Dispatch, Deploy, Drain）。代理仅通过有限动作集与环境交互，实现与Ray、Kubernetes等系统的低侵入集成。
  - 不同代理间通过轻量状态变更通知协调（如扩缩器更新副本集后通知路由器）。
