## 摘要
工业级分布式视觉语言模型（VLM）训练的效率仍远低于单模态大语言模型（LLM）。现有方案要么采用单体设计，为异构模块统一分配并行策略，要么采用分离式部署，将模块分开，但以批次同步流水线的方式执行。本文指出上述方案仍有不足，VLM训练可进一步解耦。为此，我们提出FlowTrain，一个基于流的解耦训练框架，将VLM训练重新表述为通过统一内存池协调的生产者-消费者数据流。编码器和骨干网络可在全局虚拟地址空间上独立推进。由于这种执行解耦从根本上改变了分配与调度的优化目标，FlowTrain进一步引入异构并行分配器，通过求解吞吐匹配问题为各模块分配合适的并行策略。动态打包调度器则根据大语言模型端的实际计算成本，在运行时构建均衡的微批次。在真实工作负载上的大量实验表明，FlowTrain实现了超过50%的模型浮点运算利用率（MFU）和高达1.7倍的吞吐量提升，缩小了与纯LLM训练的效率差距。

## Abstract
Industrial-grade distributed training of vision-language models (VLMs) remains far less efficient than that of unimodal LLMs. Existing solutions either follow a monolithic design that assigns uniform parallelism to heterogeneous modules or adopt a disaggregated deployment that separates modules while executing them as a batch-synchronized pipeline. In this paper, we highlight that the above solutions are still not sufficient, and VLM training can be further decoupled. To this end, we present FlowTrain, a flow-based decoupled training framework that reformulates VLM training as a producer-consumer dataflow coordinated through a unified memory pool. The encoder and backbone can progress independently over a global virtual address space. Since this execution decoupling fundamentally changes the optimization objective of allocation and scheduling, FlowTrain further introduces a heterogeneous parallel allocator that assigns module-specific parallelism strategies by solving a throughput matching problem. The dynamic packing scheduler is used to construct balanced microbatches at runtime according to the actual LLM-side computation cost. Extensive experiments on real-world workloads show that FlowTrain achieves over 50% MFU and up to 1.7x throughput improvement, narrowing the efficiency gap to LLM-only training.

### 1. 论文的核心问题与整体含义
工业级视觉语言模型（VLM）的分布式训练效率远低于单模态大语言模型（LLM），成为大规模模型落地的关键瓶颈。  
- 现有**单体框架**（如 Megatron‑LM）为异构模块（视觉编码器、投影器、LLM 主干）统一分配并行策略，忽略了各模块在算术强度、内存占用、最优并行度上的巨大差异，导致资源利用率和模型浮点运算利用率（MFU）低下。  
- 最新的**分离式框架**（如 DistTrain）虽允许不同模块使用独立的并行策略和资源组，但仍维持**批次级同步流水线**：编码器的所有数据并行副本必须完成整个全局批次，输出才能被点对点传输到 LLM 主干，由此引入同步障碍和空闲等待。  
- 工业多模态样本在分辨率、序列长度上差异显著，批次级同步会放大这种动态不平衡带来的流水线气泡。  

因此，**核心问题是**：分离式部署不足以彻底解耦执行，VLM 训练需要从刚性流水线转变为“生产者-消费者”数据流，以消除同步障碍、匹配吞吐并动态平衡负载。FlowTrain 将训练重构为基于**统一内存池**的连续生产者-消费者过程，实现“部署分离、执行解耦”，从根本上缩小 VLM 与 LLM 训练的效率差距。

### 2. 方法论
FlowTrain 由三个协同组件构成，共同实现解耦的数据流训练。

#### 2.1 统一内存池（Unified Memory Pool）
- **全局虚拟地址（GVA）**：为所有节点上的 HBM 和 DRAM 分配 64 位 GVA，形成连续的全局地址空间。每个进程拥有 `[start + i*max_size, start + (i+1)*max_size)` 的地址段，并将其物理内存绑定到 GVA。  
- **页表映射与透明访问**：每个进程维护页表，将 GVA 映射到本地/远程物理地址。编码器（生产者）将视觉嵌入写入自身 GVA 段，LLM 主干（消费者）直接从 GVA 读取微批次数据，无需感知数据实际物理位置。跨节点或跨存储层级时，自动选择 NVLink、HCCS 或 RDMA 等传输引擎，上层操作与硬件解耦。  
- **效果**：将点对点同步传输转为缓冲式异步交换，打破批次级依赖，允许编码器和主干以各自原生吞吐独立推进。

#### 2.2 异构并行分配器（Heterogeneous Parallel Allocator）
目标：在固定总资源预算 \(R\) 下，最大化全局吞吐并最小化生产者与消费者间的吞吐不平衡。  
- **优化问题**：以字典序优化 `lexmax(G, -F)`，其中 \(G = \min(T_{\text{enc}}, T_{\text{bb}})\)，\(F = |T_{\text{enc}} - T_{\text{bb}}|\)，\(T_{\text{enc}}\) 和 \(T_{\text{bb}}\) 分别为编码器总生产率和主干消费率，取决于各模块选择的并行配置。  
- **三步求解**：  
  1. **候选空间剪枝**：编码器侧仅考虑 DP×TP；主干侧加入 PP，剔除全局批大小不可被 DP 整除或跨节点 TP 等无效配置。  
  2. **吞吐代理建模**：通过少量预热迭代，在固定打包序列长度下对每种配置的吞吐进行轻量级性能建模。  
  3. **MILP 求解**：将代理模型代入上述约束优化问题，使用 Gurobi 等求解器在毫秒内得到模块专属并行策略和资源分区。

#### 2.3 动态打包调度器（Dynamic Packing Scheduler）
- **最佳适配打包**：基于段树维护各候选微批次剩余容量，对每个序列以 \(O(\log L)\) 复杂度查找剩余容量≥序列长度且最小的微批次，若无则新建微批次，最大程度减少填充浪费。  
- **双维负载均衡**：  
  - 执行开销建模：打包后的微批次执行时间近似与 \((\ell_{\max})^2\) 线性相关（注意力二次方）并与总有效 token 数线性相关（MLP），定义统一开销函数 `Cost(Bj) = (∑ ℓ(s))/L + (ℓmax)^2 / L^2`。  
  - **Zig‑zag 分发**：将开销相近的微批次聚类到同一桶，桶内降序排序后，以“正序→逆序”交替方式分配到数据并行（DP）的各 rank，确保高成本的与低成本的微批次配对，平衡不同 rank 的计算量。
