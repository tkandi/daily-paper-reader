## 摘要
深度学习技术提升了点击率（CTR）预测模型学习特征并提高预测准确性的能力。然而，由于串行计算模式与并行模型结构之间存在巨大不匹配，将CTR模型顺利部署在GPU上并高效执行推理具有挑战性。本文提出DPIFrame，首个双并行化框架，用于加速CTR模型推理。在DPIFrame中，a）提出了双并行架构，在模块内和模块间执行并行CTR模型推理；b）通过提前预估整体工作负载，为嵌入操作设计了高效的多表查找算法；c）设计了广度优先的流调度策略，对GPU上的并行计算进行细粒度管理，以进一步支持双并行执行。在两个真实世界数据集上进行了大量实验，结果表明，与PyTorch相比，DPIFrame能够高效地将嵌入延迟降低**23.0倍**。与PyTorch、TorchRec、HugeCTR和OneFlow相比，DPIFrame在GPU上可实现最先进的推理性能，分别达到**5.83倍**、**4.29倍**、**2.15倍**和**2.0倍**的加速。

## Abstract
Deep learning technology has enhanced the ability of Click-through rate (CTR) prediction models to learn features and improve prediction accuracy. However, it is challenging to deploy CTR models on GPU smoothly and perform inference efficiently, because there is a huge mismatch between the serial computational pattern and the parallel model structure. In this paper, we propose DPIFrame, the first dual parallelizable framework to accelerate CTR model inference. In DPIFrame, a) a dual parallelizable architecture is proposed to perform parallel CTR model inference in both intra-module and inter-module; b) an efficient multi-table lookup algorithm is presented for embedding operations through anticipating the whole workload in advance; c) a breadth-first stream scheduling strategy is designed for fine-grained management of parallel computation on GPU to further supporting the dual parallel execution. Extensive experiments are conducted on two real-world datasets, and the results highlight that DPIFrame can reduce the embedding latency efficiently by \textbf{23.0$\times$} compared to PyTorch. Compared with PyTorch, TorchRec, HugeCTR, and OneFlow, DPIFrame can achieve state-of-the-art inference performance on GPU with speedups of \textbf{5.83$\times$}, \textbf{4.29$\times$}, \textbf{2.15$\times$}, and \textbf{2.0$\times$}, respectively.

### 论文核心问题与整体含义
点击率（CTR）预测是现代推荐与广告系统的核心任务。深度CTR模型虽然精度高，但其推理过程存在**串行计算模式与并行模型结构之间的根本性不匹配**，导致在GPU上部署时效率极低。现有深度学习框架（如PyTorch）通常采用粗粒度、序列化的执行方式，使得模型固有的模块内与模块间并行性无法被有效利用，GPU利用率往往低于40%，成为产业落地的核心瓶颈。
**DPIFrame 是首个面向CTR模型推理的双层并行加速框架**，旨在从系统架构层面解决上述不匹配问题，在严格保证模型精度的前提下，实现模块内与模块间的并行执行，从而大幅提升推理效率与硬件利用率。

### 方法论：核心技术思想与关键设计
DPIFrame 的核心方法论围绕 **“双并行架构”、“高效多表查找”与“广度优先细粒度流调度”** 三个层面展开：
- **双并行架构**
  - **模块内并行**：识别嵌入模块中各特征域的查表操作相互独立，以及神经网络模块中大量细粒度向量算子的可并行性。通过将独立的查表操作融合为单一并行操作，或将相邻的非GEMM算子（如逐元素运算、激活函数）融合为一个大算子，实现模块内部的并行执行。
  - **模块间并行**：利用CTR模型中显式交互模块（如交叉网络）与隐式交互模块（如深度网络）天然无数据依赖的特点，使其在不同CUDA流上并行执行，实现模块间的流水线并行。
- **多表查找算法与输出优先负载分配**
  - **算法核心**：将针对不同特征域的多次稀疏查表操作，重构为对**预期输出矩阵的单次、顺序填写过程**。算法通过输入ID与嵌入表配置直接计算输出矩阵中每个元素应填入的值，避免了传统方法中的中间向量拼接与多次数据搬运（详见论文 Algorithm 1）。
  - **输出优先负载分配**：在GPU线程分配任务时，让同一Warp内的线程共同处理**同一个样本**的不同特征，而非让不同线程处理不同样本。此举保证了全局内存的读写地址连续，最大化内存带宽利用率，避免因随机访问导致的性能下降。
- **非GEMM算子融合与广度优先流调度**
  - **算子融合**：通过构建模型计算图，识别并合并所有通过边相连的非GEMM算子（如 ReLU、逐元素乘加）为单个融合算子，从根本上减少GPU内核启动开销（单次查表启动开销约21.92 μs，而实际计算仅需4.75 μs）和冗余显存访问。
  - **广度优先流调度策略**：设计了算子级的CUDA流调度器（详见论文 Algorithm 2）。不同于PyTorch默认的深度优先（先执行完一个流中的所有任务再执行下一个），DPIFrame采用**宽度优先**，将不同模块的算子交替推入启动队列，使得不同CUDA流上的算子能尽早开始执行并最大化任务重叠。实验证明，该方法使双分支并行启动延迟最高可降低 **23.18倍**。
