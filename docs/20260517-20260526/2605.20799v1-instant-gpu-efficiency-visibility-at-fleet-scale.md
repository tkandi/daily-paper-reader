## 摘要
我们提出总体FLOP利用率（OFU），这是一种硬件级、精度无关的GPU效率指标，适用于HPC系统上的AI工作负载，它源自两个片上性能计数器：张量管道活动（Tensor Pipe Activity）和SM时钟频率。OFU无需应用程序插桩，可跨GPU代际和数值精度工作。我们通过在H100和GB200上进行FP16、TF32、FP8和NVFP4的受控GEMM实验，刻画了OFU近似值的五个特性——分片量化、浮点精度缩放、时钟采样噪声、张量核心时钟域和非张量欠计数。经过分片量化校正后，OFU预测应用级MFU的误差在2个百分点以内。针对608个生产训练任务，OFU与应用级MFU的相关性达到r=0.78，并揭示了两处框架级的FLOPs计算错误。在大规模GPU集群部署中，OFU检测到2.5倍的效率退化，并追踪了混合精度预训练中精度依赖的利用率变化。我们的评估和运营经验表明，OFU是对应用级MFU的一种实用、可即刻部署的补充，用于持续的全集群效率监控。

## Abstract
We present Overall FLOP Utilization (OFU), a hardware-level, precision-agnostic GPU efficiency metric for AI workloads on HPC systems, derived from two on-chip performance counters: Tensor Pipe Activity and SM clock frequency. OFU requires no application instrumentation and works across GPU generations and numeric precisions. We characterize five properties of the OFU approximation -- tile quantization, floating-point precision scaling, clock sampling noise, Tensor Core clock domains, and non-tensor undercounting -- through controlled GEMM experiments on H100 and GB200 across FP16, TF32, FP8, and NVFP4. After tile-quantization correction, OFU predicts application-level MFU to within <=2 percentage points. Against 608 production training jobs, OFU achieves r = 0.78 correlation with application-level MFU and surfaces two framework-level FLOPs miscalculations. Deployed across large-scale GPU fleets, OFU has detected a 2.5x efficiency regression and tracked precision-dependent utilization changes in mixed-precision pretraining. Our evaluation and operational experience suggest OFU is a practical, deployment-ready complement to application-level MFU for continuous fleet-wide efficiency monitoring.

### 1. 论文的核心问题与整体含义

- **核心问题**：在大规模 GPU 集群（“舰队”）中，如何实时、精确且无侵入地监控所有 AI 工作负载的 GPU 计算效率（即 MFU，模型 FLOPs 利用率），以支撑资本支出的回报最大化。
- **研究背景与动机**：
  - 大型科技公司在 AI 基础设施上的资本支出正达数万亿美元，每 1% 的 GPU 利用率提升意味着巨大经济价值。
  - **现有方案均存在短板**：
    - **用户级剖析工具**（如 Nsight Compute、PyTorch Profiler）：需逐作业插桩，有开销，无法连续全舰队监控。
    - **框架级 MFU 估算**（如 Megatron-LM 内置）：覆盖碎片化，架构更新（MoE、混合精度）时 FLOPs 公式易出错，难以跟随模型演进。
    - **硬件性能计数器**（如 DCGM）：虽然无侵入，但此前缺乏对其作为 MFU 代理的严格精度验证和可伸缩性研究。
- **整体含义**：提出并验证一个基于硬件计数器、精度无关、可跨 GPU 代际的简单指标 `OFU`，填补全舰队实时效率可见性的空白，并展示其在实际生产中诊断效率回退和框架 FLOPs 计算错误的能力。

### 2. 论文提出的方法论

- **核心思想**：利用现代 AI 工作负载中绝大部份 FLOPs 都流经 Tensor Core 执行流水线的特点，仅用两个无侵入的硬件计数器推导出 MFU 的近似值 `OFU`。
- **关键技术细节与公式**：
  - **基础信号**：
    - `Tensor Pipe Activity (TPA)`：GPU 执行 Tensor Core 浮点指令的周期占比，该计数器为硬件平均，反映真实平均活跃度。
    - `fSM`：SM 时钟频率（瞬时采样），`f_max_SM`：该 GPU 的 Tensor Core 最高加速时钟。
  - **OFU 定义**：
    ```
    OFU = TPA × (fSM / f_max_SM)
    ```
  - **推导逻辑**：  
    `TPA ≈ 实际 FLOPs/周期 ÷ 峰值 FLOPs/周期`，再乘以时钟比 `(fSM/f_max_SM)` 将周期域转换为时间域的吞吐率比，从而近似 MFU。
  - **误差特性刻画**（论文对 OFU 产生偏差的 5 个来源进行了系统分析）：
    1. **分片量化与 cuBLAS 内核选择**：固定分片尺寸导致实际执行 FLOPs 略高于理论值 `2MNK`，且 cuBLAS 对不同精度和矩阵形状选择的内核（nvJet、XMMA、CUTLASS）会影响开销模式。
    2. **浮点精度缩放**：不同精度（FP16、TF32、FP8、NVFP4）具有不同的理论峰值和量化的有效加速比，受分片缩放因子等开销影响，但 OFU 本身精度无关，且实验表明能正确追踪精度相关的吞吐率变化。
    3. **SM 时钟采样噪声**：由于 SM 时钟为瞬时值而非窗口平均，采样间隔会引入误差，但即使 30 秒间隔，95% 置信区间仍低于 ±0.22 个百分点，非主要误差源。
    4. **Tensor Core 时钟域**：Tensor Core 流水线可能运行在不同于 SM 整体最高频率的独立时钟域（如 H100 上 Tensor Core 为 1830 MHz，而 SM 为 1980 MHz），计算峰值时必须使用正确的 Tensor Core 频率。
    5. **非张量欠计数**：OFU 仅监测 Tensor Core，忽略 CUDA core 的少量浮点操作，但矩阵乘占 Transformer 总 FLOPs 的 99.8%，因此影响可以忽略。
  - **分片量化校正**：
    为提升精度，引入 `Adj. OFU = OFU × (2MNK / FLOPs_profiled)`，使用一次 NCU 测量出的实际 FLOPs 对 OFU 进行修正，可将预测误差控制在 2 个百分点内。

### 6. 论文的主要结论与发现

- **OFU 精度**：经过分片量化校正后，OFU 预测应用级 MFU 的误差 ≤ 2 个百分点（在 95% 以上的测试中）。即使未校正，原始 OFU 对纯 GEMM 的预测误差也在 1–3 个百分点。
- **生产相关性**：在 608 个真实训练作业上，OFU 与应用 MFU 的皮尔逊相关系数为 **0.78**（排除已知框架错误后），平均绝对误差 6.2%。
- **框架错误发现**：OFU 成功揭示了两类 Megatron-LM 中的 FLOPs 计算错误（MoE 投影维度未缩减、混合层结构不兼容），导致应用 MFU 被严重高估（最高误差 112%）。
- **运营实效**：
  - 检测到机器人模型训练中因分布式调试环境变量导致的 **2.5 倍** 效率退化。
  - 在 6144 GPU 的混合精度大模型预训练中，OFU 能实时追踪精度切换带来的利用率变化，且任务级与应用 MFU 相关性高达 **0.977**。
- 总体结论：OFU 是一个实用、可部署的补充指标，能以极低代价实现全舰队 GPU 效率的连续性可见性，有效定位低效和框架错误。

### 7. 优点

- **无侵入且易部署**：完全基于 DCGM 硬件计数器，无需修改任何应用或框架代码，可在所有作业上自动运行。
- **跨代与精度无关**：公式仅依赖 TPA 和 SM 频率，适用于 Volta 至 Blackwell 不同架构，以及 FP16/FP8/FP4 等格式。
- **误差刻画系统**：首次对硬件计数器衍生 MFU 的误差来源（分片量化、时钟噪声、时钟域等）进行全面分析和量化，提供了明确的精度边界。
- **生产验证扎实**：在 608 个真实作业和大规模（6144 GPU）长周期训练中验证了相关性和诊断能力，并给出切实的运维案例。
- **具备纠错价值**：不仅能反映真实利用率，还能反向发现框架层 FLOPs 计算的 bug，对用户和框架开发者都具有参考价值。
- **简单透明**：OFU 可直观解释为“Tensor Core 单位时间利用率”，便于集群管理者理解和集成到看板或自动告警系统中。

### 8. 不足与局限

- **CUDA Core 盲区**：忽略小幅非矩阵计算，在非矩阵乘主导的负载中（如某些传统 HPC 应用）会显著低估利用率。
- **依赖硬件计数器准确性**：若硬件计数器本身的设计或定义发生变化（尤其对未来的 Tensor Core 指令混合），OFU 需要重新验证。
- **内核选择的复杂度**：分片量化校正需要基于已知的内核分片尺寸（如 nvJet 可直接推导，但其他内核不易静态预测），完全自动化的精确校正仍有困难。
- **时钟采样噪声**：虽影响小，但在采集间隔过长（>30 秒）或超短时间窗口下，仍会引入误差，论文建议采集间隔不超过 30 秒。
- **生产验证覆盖面**：
  - 仅在一个内部 Megatron-LM 集群上进行了大规模验证，对 PyTorch 原生或其他更广泛的训练框架的普适性未展示。
  - 除 GEMM 外，未专门评估如卷积、自注意力计算等常见操作中的具体误差模式。
  - 部署案例均基于 NVIDIA GPU，且主要是 H100 和 GB200，对其他架构（如 A100）的适配性虽有论证但缺少同等规模的运营数据。
- **需使用正确的峰值频率**：OFU 分母依赖于准确的 Tensor Core 最高频率，而该信息并非在所有 GPU 上公开文档化（如 GB200 目前无独立 Tensor Core 时钟文档），实践中可能需要校准。
- **无法定位性能瓶颈类别**：OFU 只能给出整体利用率，要区分是计算、显存带宽还是通信瓶颈，仍需借助更深层次的剖析工具。
