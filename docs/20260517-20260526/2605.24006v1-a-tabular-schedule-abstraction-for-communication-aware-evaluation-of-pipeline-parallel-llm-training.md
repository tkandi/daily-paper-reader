## 摘要
流水线并行是大语言模型分布式训练的一项关键技术，因为它可以减少每设备的参数和激活内存。然而，比较流水线调度方案是困难的：分析模型揭示了气泡比例等结构量，而端到端的硬件实验成本高昂且依赖特定系统。在本工作中，我们引入了一种表格调度抽象和统一的多抽象方法，将基于公式的推理、理想化调度表以及通信感知的执行模拟连接起来。利用该框架，我们在多个建模的系统配置下，比较了 GPipe、1F1B、Chimera 和处于受限状态的 Hanayo。结果表明，调度方案的排名并非抽象不变的：通信可能会抵消单独由气泡分析所提示的结构性优势。在本文所考虑的假设下，GPipe 和 1F1B 在运行时间上等价，但 1F1B 实现了更低的激活内存峰值。Chimera 主要在微批次数少和通信有利的环境下具有优势，而 Hanayo 在其预期的受限工作点上有效，但仍对网络瓶颈敏感。我们进一步研究了一种非对称的 Chimera 风格放置，它并未降低全局峰值内存需求，但在浅层流水线中展现出了有限的运行时间收益。总体而言，流水线调度方案的质量只有在建模执行环境的上下文中才有意义。

## Abstract
Pipeline parallelism is a key technique for distributed training of large language models because it reduces per-device parameter and activation memory. However, comparing pipeline schedules is difficult: analytical models expose structural quantities such as bubble ratios, while end-to-end hardware experiments are costly and system-specific. In this work, we introduce a tabular schedule abstraction and a unified multi-abstraction methodology that connects formula-based reasoning, idealized schedule tables, and communication-aware execution simulation.   Using this framework, we compare GPipe, 1F1B, Chimera, and Hanayo in its restricted regime across multiple modeled system configurations. Our results show that schedule rankings are not abstraction-invariant: communication can negate structural advantages suggested by bubble analysis alone. Under the assumptions considered here, GPipe and 1F1B are runtime-equivalent, but 1F1B achieves a lower activation-memory peak. Chimera is advantageous mainly at low microbatch counts and in communication-favorable regimes, while Hanayo is effective in its intended restricted operating point but remains sensitive to network bottlenecks. We further study an asymmetric Chimera-style placement, which does not reduce the global peak memory requirement but reveals limited runtime gains in shallow pipelines. Overall, pipeline schedule quality is meaningful only in the context of the modeled execution environment.

### 2. 方法论：统一的多抽象评估框架

论文提出了一种连接三个抽象层次的统一评估方法论，其核心是一项新的**表格调度抽象**，作为连接结构性分析和通信感知模拟的桥梁。

*   **核心思想**：将调度方案的结构（某个 worker 在某个时刻执行什么任务）与硬件执行成本解耦，从而实现跨调度方案的统一表示和可比性。
*   **关键技术细节**：
    1.  **表格调度抽象**：
        *   将调度方案定义为一个二维表格 `S ∈ (M × P ∪ {∅})W × T`。
        *   其中 `W` 代表 Worker（流水线级），`T` 代表离散的时间槽（Slot）。
        *   表格中的每个单元格 `Sw,t` 指定了在时间槽 `t`，Worker `w` 为微批次 `m` 执行的阶段 `p`（如前向传播 `fwd`、激活梯度计算 `agrad` 等）或空闲状态（`∅`）。
        *   该表格是“结构性”的，不包含硬件耗时信息。
    2.  **三层评估级别**：
        *   **公式级**：使用传统的分析公式计算气泡比等结构性指标。
        *   **理想调度表级**：直接在表格抽象上观察气泡、填充/排空行为、激活生命周期等，进行硬件无关的结构分析。
        *   **通信感知模拟级**：基于表格构建精细的执行依赖图，并在图上进行模拟。
    3.  **从表格到执行图的翻译**：
        *   **本地顺序**：同一 Worker 上连续的非空单元格按顺序连接，构成计算任务节点。
        *   **跨 Worker 依赖**：根据阶段语义（如前向传播需要上游的激活，反向传播需要下游的梯度），在相应的计算节点之间插入显式的**通信节点**（`send`/`receive`），构建完整的执行依赖图。
    4.  **模拟执行**：基于 **Graphculon** 平台，采用容量式的系统模型对执行图进行模拟。
        *   **通信时间**：使用 Hockney 模型计算，`t_comm = V_net / BW_net + L_net`, 其中 `V` 是数据量, `BW` 是带宽, `L` 是延迟。
        *   **计算时间**：使用 Roofline 模型计算，`t_comp = max( F/(TP*e_c) + L_c, V_m/(BW_m*e_m) + L_m )`, 综合考量计算吞吐量、内存带宽和各自的效率系数 `e`。

### 6. 论文的主要结论与发现

*   **调度排名非抽象不变**：从公式或理想表格得出的结构性优势（如更低的气泡比）在引入通信模型后可能被削弱甚至逆转。

    *   **Chimera**：其双向结构的优势仅限于**低微批次数和通信友好的环境**。在网络成为瓶颈时，其额外的通信开销会使其比 GPipe/1F1B 更差。
    *   **Hanayo**：在其目标工作点有效，但优势**对网络瓶颈非常敏感**，在网络极差的情况下可能劣于 Chimera。

*   **最终裁决**：没有一种调度方案在所有抽象级别和系统环境下都具有绝对优势，调度方案的质量必须在具体的**建模执行环境上下文**中才有意义。
